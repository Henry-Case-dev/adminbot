# AdminBot — ваш карманный цифровой абьюзер с элементами ИИ

*Решение для тех, кто хочет токсичности в чате, но ленится писать сам. Теперь с памятью слона, терпением снайпера и запасным аэродромом для нейронки.*

**Версия:** v2.51.0 | **Тестов:** 3794 | **Язык:** русский (как сами ответы, так и этот файл)

Бот живёт в Telegram-группе, следит за несколькими героями чата, реагирует на слова-триггеры и умеет пользоваться нейросетью: подслушивает переписку, делает саммари, проверяет факты, гуглит, пересказывает видео и сайты (причём видео бот теперь реально «смотрит» мультимодальными глазами — хоть ссылку на YouTube, хоть прямой `.mp4`, хоть файл в чат, хоть репост; не вышло посмотреть — честно перескажет по субтитрам или звуковой дорожке), считает, сколько раз ты упоминал бензин, расшифровывает голосовые и видосы и даже лечит себя сам. Всё это — с иронией, за которую его и держат.

---

## Быстрый старт

```bash
pip install -r requirements.txt
cp .env.example .env          # впиши API_TOKEN от @BotFather, остальное опционально
mkdir -p media/dead_page media/leha_greeting media/slavik/slavik_random
mkdir -p media/common/otboy media/common/danger media/common/selfdev media/common/work media/common/goodmorning
py bot.py                       # на Linux — python3 bot.py
```

Накидай в папки `media/` файлы (фото/видео/GIF — бот сам разберётся, что куда) — и всё, через три секунды бот готов страдать фигнёй в продакшене.

> Команды запуска даны для Windows (`py`). На Linux замени `py` на `python3`.

## Где живут настройки

**Большая часть настроек — в `.env`.** В коде дефолты, в `.env` — правда жизни. С v2.51.0 появилась и вторая жизнь: почти всё то же самое (промпты, лимиты, кулдауны, ключи, флаги, реакции) можно менять **прямо из Telegram-админки без рестарта** — см. раздел «Админка» ниже. `.env` при этом никуда не делся: инфраструктура (токен бота, DSN БД, порты, пути) живёт там, как и раньше.

- **На сервере:** `nano /var/www/admin_bot/.env` → сохранил → `systemctl restart admin_bot` (либо открой админку и поменяй параметр там — бот подхватит на следующем обращении).
- **Локально:** правь `.env` (создай его из шаблона `cp .env.example .env`). Сам `.env.example` — шаблон: в него добавлены все переменные с дефолтами и комментариями, можно смело переписать его в рабочий `.env`.
- **Перед правкой сделай копию:** `cp .env .env.bak.epic59`. Откатить всегда быстрее, чем вспоминать, что ты там менял в три часа ночи.
- **Секреты (токены, ключи) живут только в `.env` и в базе админки.** В README — ни одного ключа: здесь только имена переменных. В git `.env` не коммитим (для этого есть `.env.example` с плейсхолдерами).

Куда смотреть, если что-то сломалось: в секцию «Мониторинг» ниже.

## Функции бота

### Люди, за которыми бот следит

#### Слава — главный герой этого цирка

- **Возвращение.** Зашёл в чат (покинул → вернулся) → бот пишет **«ДОЛБОЕВ ВЕРНУЛСЯ»**. Каждый раз одно и то же, и каждый раз смешно. Славе — нет.
- **Dead Page.** Слава делает репост из канала **@d_pages** → бот берёт случайный пост из своего приватного канала (где он должен быть админом) и пересылает его в чат. Альбомы пересылаются целиком, без разрывов. Два раза подряд один и тот же пост не шлётся — разнообразие превыше всего. Если приватный канал упал или бота оттуда выгнали — fallback: случайная картинка + случайный текст из папки `media/dead_page/`.
- **Месть за удалённый репост.** Telegram не сообщает боту, что Слава снёс репост. Поэтому бот узнаёт об этом окольным путём: когда кто-то отвечает или цитирует удалённое сообщение. Узнал → удаляет свою dead page. Нет прав на удаление → отправляет одну токсичную фразу из пула (в духе «снёс репост мёртвой страницы? стыдно стало?»). Ровно одно срабатывание на один репост — двойной порции не будет.
- **Чат-реакции** — трёхуровневая система эскалации. На одно сообщение срабатывает ровно один сценарий, в жёстком порядке приоритетов: dead page → гифка → рандом-медиа → mimic → «пошёл нахуй»:
  1. Написал «куча»/«кучи»/«кучу» → **«ДАЛБАЕБ»** (прицельный выстрел по грамматике). Тумблер `reactions.kucha_enabled` (`KUCHA_ENABLED`, дефолт **False**): выключен — грамматический снайпер молчит; Слава с «кучей» спокойно уходит дальше по цепочке (mimic / «пошёл нахуй»), остальных — просто тишина.
  2. Каждое 5-е сообщение **Славы** → **гифка** (`media/slavik/slavic_chlen.mp4`; файл реально так называется). Счётчик тикает строго по `reactions.slavik_user_id` (`SLAVIK_USER_ID`): чужие сообщения гифку не приближают — раньше дотикать Славе до флешбека мог кто угодно, теперь только он сам.
  3. Каждый 10-й ответ «пошёл нахуй» → **случайное медиа** из `media/slavik/slavik_random/` — фото, видео, GIF, аудио, войс или вообще любой файл. Вместо текста, а не вместе с ним.
  4. Длинное сообщение (больше 5 слов) → **шепелявый mimic** (передразнивание, см. ниже).
  5. Всё остальное → **«пошёл нахуй»** (catch-all, потому что Слава всегда заслуживает).
- **Военный оповещатель.** Слава пишет военные слова (дрон, БПЛА, ракета, тревога, убежище и ещё 90+ словоформ) — бот отвечает случайной фразой из пула: «потрясись», «повизжи», «прячься под шконку быстрее» и соседями. Психологическая поддержка наоборот. Слова ловятся в обычных сообщениях, в подписях к медиа и в репостах. Отдельно: репост из каналов «ЧП Пермь» или «Радар БПЛА» (от любого пользователя) — тоже ор.

#### Леха — объект пристального интереса

(В коде до сих пор `ALAN_*`, `handlers/alan.py` и прочие `alan`-идентификаторы — их не переименовывали ради совместимости. Но персонаж в текстах бота, админке и этом README — Леха. Так и запишем.)

- **Приветствие при входе.** Леха зашёл в чат → случайное видео из `media/leha_greeting/` с подписью-тегом из `ALAN_USERNAME` (по умолчанию `@Alan_Z` — старый ник, значение настраивается в `.env`/админке).
- **Приветствие после сна.** Молчал дольше 6 часов и наконец написал → приветственное видео «с возвращением». Бот как будто соскучился. На самом деле — просто фототропизм на движение. Таймер молчания хранится в БД и переживает рестарт бота.
- **Автоответчик.** Каждые 10 сообщений Лехи бот проявляет крайний интерес к его темам: NixOS, продажа SSD по цене трёх таких же, витамины Life Extension, 5-секундные прогулки с гантелями, уличный тренажёр и реванш за колени. Всего в пуле 52 фразы плюс вопросы-подколы («а ты вообще разминался? или как обычно — с дивана сразу к штанге?»). **На проде реплики выключены** рубильником `ALAN_REPLIES_ENABLED=False`: фразы написаны, отрепетированы и пока никому не показаны. Леха страдает молча.

#### Костик — генератор случайных оскорблений

На каждое сообщение Костика — случайное оскорбление из пула. Вероятность настраивается: `1.0` = всегда, `0.0` = никогда (режим «Костик в отпуске»). Костик не выбирал эту жизнь, жизнь выбрала его.

#### Вася / Админ — лингвистическая симметрия

- Написал «вася» (в любых формах) → **«АДМИН»**
- Написал «админ» → **«ВАСЯ»**

Это не баг, это зеркало души чата. С эпика 04.09.2026 зеркало по умолчанию завешено: обе реакции висят на одном тумблере `reactions.vasya_enabled` (`VASYA_ENABLED`, дефолт **False**). Выключен — бот делает вид, что не расслышал ни «васю», ни «админа» (молча, без ошибок). Включается в админке («Реакции и Триггеры» → «Словесные реакции») или в `.env`. Безопасный деплой: старые реакции не выстреливают, пока их явно не попросили.

#### Оля — отдельное внимание за отдельные видео

Оля присылает видео/фото с подписью «Спасибо, что пользуетесь - @SaveAsBot'ом» → бот отвечает случайным медиа из `media/olya/cringe/` (простым сообщением, без цитирования). Триггер срабатывает, если: подпись содержит этот текст (сравнение не придирается к тире, апострофам и регистру), или в подписи упомянут `@SaveAsBot`, или это репост от самого SaveAsBot. Обычные видео Оли игнорируются — точность прежде всего. Хочешь старый беспредел (реакция на всё подряд)? `OLYA_ALWAYS_SEND=True`.

### Общие реакции на слова

Бот слушает весь чат и реагирует на слова-триггеры. Слова ловятся в тексте и в подписях к медиа; регистр не важен («Отбой», «ОТБОЙ», «отбой» — всё сработает); матчится только отдельное слово («отбойный» не сработает). Ответ приходит реплаем на сообщение, и в Telegram подсвечивается именно найденное слово (нативное цитирование).

- **Отбой.** Кто-то пишет «отбой» → случайное медиа из `media/common/otboy/`.
- **Danger.** Danger-слова (118 словоформ: бпла, ракетная, сирена, взрыв, хлопок…) или фразы-связки (17 штук: «ракетная атака», «уйти в бомбоубежище», «атака дронов»…) → случайное медиа из `media/common/danger/`. Одиночные «атака»/«угроза»/«прилёт» больше не будят бота — только в связках: обсуждение игры за «атаку» бота не волнует.
- **Selfdev.** «саморазвитие», «личностный рост», «прокачка» → мотивирующее медиа из `media/common/selfdev/`. Репосты игнорируются: саморазвитие — дело личное.
- **Work.** «устал», «заебался», «запарился», «нет сил» → сочувствующее медиа из `media/common/work/`. Сочувствие — случайный файл. Репосты мимо: чужая усталость — чужая проблема. **На проде выключено** (`COMMON_WORK_MEDIA_ENABLED=False`) — усталые страдают молча.
- **Goodmorning.** Раз в сутки в настроенное время (по умолчанию 07:00) бот будит чат случайным медиа из `media/common/goodmorning/` и случайной подписью из пула («❗️❗️❗️ ПАДЪЕМ НИГЕРЫ…» и ещё пять в том же тоне). По умолчанию рассылка выключена — пока не задан список чатов, будильник молчит, и это правильно.

От спама защищают двухуровневые кулдауны: общий на все common-реакции плюс персональный на danger/selfdev/work. Подробности — в таблице параметров.

#### Mimic — передразнивание

Шуточная трансформация текста «под шепелявость»: «что» → «фе», «учишься» → «учифся», «рука» → «люка». Это чистая замена букв по словарю и правилам, без нейросети. Работает в двух местах:

- Для жертв из списка `MIMIC_VICTIM_USER_IDS` — если сообщение длинное (больше 5 слов) и не репост.
- Для Славика — встроено в его цепочку реакций (см. выше).

Репосты бот не передразнивает — цитирует только первоисточники. Проверить трансформацию можно командой `/mimic [текст]`.

С эпика 04.09.2026 у common-мимикрии (той, что для жертв из `MIMIC_VICTIM_USER_IDS`) появился общий рубильник `flags.mimic_enabled` (`MIMIC_ENABLED`, дефолт **False**): выключен — бот не передразнивает никого из списка жертв. Славячий mimic рубильником не управляется — у него свои `limits.slavik_mimic_min_words` / `limits.slavik_mimic_cooldown` (см. таблицу «Слава»). Мимикрия Лехи — под двумя замками: для него нужны **оба** флага — общий `MIMIC_ENABLED` и персональный `reactions.alan_mimic_enabled` (`ALAN_MIMIC_ENABLED`, дефолт **False**). Остальным жертвам достаточно общего.

Мозг бота — нейросеть через провайдера apinet.cloud (модель `deepseek-v4-flash`).

#### Summary — бот, который подслушивает

Бот слушает **весь** чат и раз в 6 часов (00:00 / 06:00 / 12:00 / 18:00 по Екатеринбургу) выдаёт токсично-ироничное саммари: кто с кем спорил, кто какую хуйню сморозил и кто оказался «самым главным шизом». Или по команде `/summary` — если не спамить (кулдаун на повторный вызов, с фразой-отборкой, где честно указано, сколько ещё ждать: «хули ты дрочишь, подожди 42 секунды»).

Имена в саммари подставляются по каскаду: алиас (из `SUMMARY_ALIASES`) → имя и фамилия → username → ID. Длинный ответ приезжает кусками с паузой, чтобы не упираться в лимиты Telegram.

**Трёхуровневая память — как у слона с амнезией по расписанию:**

| Уровень | Срок | Что это |
|---|---|---|
| L1 — окно генерации | 6 часов | Свежая история, которую бот реально читает (до 500 сообщений / 120 000 символов) |
| L2 — сырая память | 30 дней | Полная переписка для точных цитат из прошлого (поиск по ключевым словам) |
| L3 — векторный архив | 90 дней | Старьё сжимается нейронкой в факты по темам и ищется по смыслу (если векторный поиск не завёлся — ищется текстом, бот не падает) |

**Бот не умеет падать:** упал векторный поиск → текстовый; упала нейронка → честное «не смог сделать саммари потому что упал апи»; упала база данных → «база данных подавилась». Маленькими буквами, без техдеталей. UX-дизайн уровня «прости, я в пролёте».

**Свежие апгрейды:**
- Лимиты контекста теперь считаются **в токенах** (tiktoken), а не в буквах. Точнее, чем «на глаз».
- **Бегущий конспект:** контекст заполнился на 80% → старые сообщения тихо сжимаются в саммари, последние дословно. Нейронка не захлёбывается, история не теряется.
- **Стриминг саммари** (тестовый режим, по умолчанию выключен): длинное саммари «растёт» на глазах вместо ожидания готовой простыни.

#### DirectChat — бот вливается в разговор

Бот отвечает на **прямые обращения** — и только на них. Сам он никогда не начинает диалог (скромный):

- **Реплай** на сообщение бота.
- **Тег** `@username` в сообщении.
- **Слова-триггеры:** «бот», «ботик», «ботяра», «ботина», «ботохуета», «ботохуйня». Матчится только слово целиком: «робот», «работа» и «забота» бота не будят, а вот «ботохуета» — будит. Шаблон настраивается через конфиг (`CHAT_BOTWORD_PATTERN`), а не зашит в код — хочешь другие слова, вперёд. (Выключается флагом `DIRECT_CHAT_BOTWORD_ENABLED`; Леху и Костика эта ветка не касается — их сообщения уходят своим хендлерам.)
- Команды `/…` бот не перехватывает — у них своя жизнь.

При ответе бот держит в голове контекст: последние 100 сообщений чата, цепочку ответов глубиной до 6 и память о прошлых диалогах с тобой. Диалоги запоминаются отдельно и в чужие саммари/фактчеки не подмешиваются. Память о собственных ответах бота (RAG-факты `bot_direct_reply` — стилевые якоря и «я ему уже отвечал») живёт **30 дней**, а не вечно: TTL задаётся `CHAT_DIRECT_REPLY_TTL_DAYS` (пусто = кодовый дефолт 30, `0` = вечно), протухшее подметается само, при старте бот делает идемпотентный backfill старых «вечных» фактов.

**Агентный режим (Tool Calling).** Если для ответа не хватает свежих данных, бот сам, без команды, сходит в инструменты: `execute_web_search` — поиск (каскад Tavily → Exa → DuckDuckGo) и `query_chat_memory` — копание в собственной памяти чата (`time_range`: `last_day` / `last_week` / `last_month` / `all`). До 4 раундов «подумал → сходил → ответил», результаты возвращаются модели как факты и вплетаются в ответ. Провайдер не умеет tool calling → бот молча деградирует в обычный ответ без инструментов (никаких падений). Работает только в direct_chat: ручным «найди», фактчеку и «поясни за ссылку» инструменты не мешают — у них свои хендлеры.

С bugfix-раунда 04.09.2026 системный промпт direct_chat **прямо инструктирует модель** про оба инструмента — когда вопрос про прошлое чата («когда это было», «кто говорил», статистика), `query_chat_memory` надо звать первым; свежие внешние данные — удел `execute_web_search`; цифры бери только из результата инструмента, не выдумывай. Раньше инструменты существовали, но модель о них не знала — теперь знает. А `query_chat_memory` научился считать: «бот, сколько раз в чате упоминался бензин» → «Найдено N упоминаний „бензин" за всё время (с … по …)» — с датами и без гадания на кофейной гуще.

**Защита от «задрочивания» бота:**
- **Token Bucket:** 3 обращения подряд — дальше кулдаун (по умолчанию 5 минут) с фразой, где честно указано оставшееся время.
- **Circuit Breaker (предохранитель):** 3 сбоя нейронки подряд → бот на 5 минут перестаёт дёргать нейросеть и отвечает человечными отмазками из пула («мозги временно ушли на профилактику, скоро вернутся» и ещё три в том же духе). Истёк срок — одна пробная попытка: мозг вернулся с обеда → работаем; снова сбой → ещё пять минут тишины.
- **Фоллбэк-провайдер:** бот ходит в apinet.cloud (модель `deepseek-v4-flash`) через OpenAI-совместимый клиент; при сбое провайдера срабатывает фоллбэк-провайдер, если настроен в .env.

**Ещё слои защиты и вежливости (новое):**
- **Дедуп повторов.** Пишешь «бот бот бот» пять раз подряд — получишь один ответ, остальные из кэша. Модель не дёргается, деньги не тратятся, ты всё равно не услышал ничего нового.
- **Молчание после 5 кулдаунов подряд.** Долбишься в закрытую дверь — бот перестаёт её открывать вообще. Навязчивым собеседникам — тишина, это тоже ответ.
- **Пустой ответ нейронки → реакция 🗿.** Раньше были заглушки, теперь просто истукан. Во всех ИИ-фичах: молчаливое осуждение универсально.
- **Индикатор «печатает…»** у всех фич смарт-модуля: горит, пока нейронка думает. Бот выглядит живым, искусственных пауз нет.
- **Стилевые якоря:** бот видит свои недавние ответы и держит тон — не скатывается из токсичного абьюзера в вежливого консультанта на середине мысли. С раунда 3 — с **анти-залипанием**: если минимум два из последних ответов начинаются с одного и того же слова («сцуко, …» — привет), такие ответы в якоря не попадают, а инструкция прямо запрещает модели начинать каждый ответ с одного и того же слова. Попугайский режим отменяется.
- **Ловля настроения:** лёгкая подстройка тона под твоё состояние через контекст (системный промпт неприкосновенен — канон есть канон).
- **Температура модели пресетами:** точный / сбалансированный / болтливый. Три степени откровенности.
- **Правка ответа ботом** → память цепочки обновляется. Цепочка не врёт даже после редактур.

**Команды прямо в диалоге с ботом:**
- `/clear` — сбросить память текущего разговора. Начали с чистого листа.
- `/persona [имя]` — карточка человека из памяти графа: что бот о тебе (или о нём) накопал. Без аргумента — своя карточка; `/persona <имя>` и `/persona list` — только для админа.
- `/tone` — переключить тон: формально ↔ по-свойски.
- `/forget` — забыть конкретный неверный факт или всё сразу. Важное помечено защищённым: при сжатии памяти и /forget не стирается. Слон забывает выборочно.

**Память-команды словами (раунд 4): «бот, запомни …» / «бот, забудь …».** Прямо в диалоге, без слэшей: написал «бот, запомни, что бензин опять подорожал» — бот сохранит это **вербатим** (без пересказа нейронкой, вес 1.0 — явное «запомни» важнее фоновых сплетен) как факт `user_memory` и подтвердит «запомнил: …». «Бот, забудь про бензин» — сотрёт именно такие явно запомненные факты (по словам запроса, до 5 слов, только `origin=user_memory`): скажет, сколько забыл, или честно признается, что про это не запоминал. Правила игры:
- **Кто может:** админ и модераторы — всегда (их «запомни» идёт в общий фон чата, «забудь» чистит по всему чату). Обычные участники — только когда включён тумблер `flags.memory_commands_user_enabled` (TMA → «Память и RAG»; дефолт **false**); при выключенном тумблере бот вежливо объяснит, что запоминать и забывать — привилегия админов (и не исполнит команду). С включённым тумблером участник запоминает от своего имени и забывает только своё — чужие факты неприкосновенны.
- **«Забудь всё» — нельзя.** Намеренно: команда «забудь» без аргумента, с аргументом «всё» или короче трёх символов — только ехидная подсказка «забудь что именно?», ничего не удаляется. Забывается только конкретика.
- **Забываются только явно запомненные факты** (`запомни`-команды): автопамять из переписки, поиска и видосов «забудь» не трогает — для неё есть свои TTL и `/forget`.
- Срок хранения «запомни» — `limits.memory_commands_remember_ttl_days` (дефолт 365 дней; `0` = вечно). Повторный «запомни» того же самого — «это я уже знал», дубли не плодятся.
- Команды не тратят лимиты диалога: распознанный синтаксис обрабатывается до LLM и не стоит в кулдауне. Всё остальное («бот, а помнишь…», «бот, забудь про эту тему и ответь нормально») — обычный диалог как раньше.

#### SmartCache — не платим за одно и то же дважды

Спросил бота про одно и то же второй раз — зачем дёргать нейронку и платить повторно? SmartCache запоминает ответы на умные запросы: повторный одинаковый вопрос в течение 30 минут (TTL кэша — 1800 секунд) получает готовый ответ из кэша, мгновенно и бесплатно. Кэш держит до 1000 ответов, старые вытесняются. По умолчанию выключен — включается рубильником `SMART_CACHE_ENABLED=True` (подробности в таблице параметров).

#### FactCheck — третейский судья интернет-срачей

Отвечаешь реплаем на чьё-то сообщение и начинаешь ответ со слова **«фактчек»** — бот берёт текст, гоняет его через поисковики (каскад Tavily → Exa → DuckDuckGo), фильтрует мусорную выдачу и выдаёт токсичный вердикт через нейронку, **реплаем на проверяемое сообщение**.

С недавних пор бот — не просто проверялка фактов, а **третейский судья срачей**: ему больше не важно, проверяемое ли утверждение. «Все мужики козлы», философский тейк или чистая эмоция — всё идёт в дело: бот выделит главный тезис, прогонит его через логику и здравый смысл, найдёт когнитивные искажения (или признает «базой») и чётко займёт позицию: автор выдал базу, жидко обосрался, или истина посередине. Поисковая выдача теперь лишь патроны для аргументации — притягивать мусорные ссылки за уши бот откажется принципиально.

- Всё, что написано после слова «фактчек» («фактчек да ты что, это давно опровергли»), уходит нейронке как подсказка.
- Репост тоже можно фактчекнуть (триггер в подписи) — реплай не обязателен.
- Стикер или фото без текста → порция абьюза без поиска. Судить нечего — осуждать всегда есть кого.
- Регистр не важен; «фактчекинг» не матчится — не надо тут терминов.

#### SmartSearch — «загугли за меня, я устал»

Пишешь **«найди/поищи/загугли + запрос»** — бот собирает факты через те же поисковики, выжимает суть через нейронку и присылает токсичную выжимку реплаем на твоё сообщение. Не сарказм ради сарказма — там и факты есть. «Найди» без запроса → порция абьюза, поисковики не беспокоим: они для тех, кто дописал мысль.

#### YouTube — пересказ видосов

Пишешь **«че за видос», «о чем видео», «поясни за видос», «перескажи видос», «че в видосе»** или **«транскрипт»** — и бот разберётся с роликом, откуда бы тот ни приехал: YouTube-ссылка (`youtube.com/watch?v=`, `shorts/`, `youtu.be/`), прямая ссылка на медиа-файл (`.mp4` и прочие), ссылка на соцсеть (TikTok, Instagram, VK и остальные из списка «скачай» — молча скачает в 360p) или просто видео, брошенное в чат (своё, чужое, хоть репост). Ответ — реплаем на сообщение со ссылкой или на сам ролик; ссылку можно прислать и реплаем на чужое сообщение.

**«Че за видос» и братья — режим выжимки, и тут бот уже не читает, а смотрит.** Раньше он умел только добывать субтитры YouTube; теперь ролик сначала уходит «глазастым» мультимодальным моделям через OpenRouter (`video_url` прямо в content): L1 — `models.video_primary_model` (`nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free` — единственная free-модель OpenRouter, которая и видит кадры, и слышит звук), не вышло — L2 — `models.video_fallback_model` (`minimax/minimax-m3:free` — видит кадры, звук не слышит, зато контекст на миллион токенов). Для нативных TG-видео и скачанных по ссылке файлов «глаза» работают через **временную публикацию**: файл копируется под случайным uuid-именем в каталог медиа-шары и раздаётся короткоживущим подписанным URL `/media/{uuid}?e=…&s=…` (HMAC-подпись, TTL по умолчанию 15 минут), модель смотрит ролик по ссылке, файл подметается. Прямые `.mp4`-ссылки L1/L2 пробуют посмотреть сразу по URL — не вышло, скачиваем и публикуем. Free-роуты OpenRouter — ребята ненадёжные: видео им то не доставляется, то они делают вид, что не видят. С раунда 4 такие **отказные ответы ловит маркерный детект** (нормализация текста + словари-маркеры «не вижу видео»/«no access»/… на русском и английском + порог: ответ короче 15 символов выжимкой не считается): «я не вижу видео» больше **не выдаётся за пересказ** — уровень молча считается пустым, каскад уходит на следующую модель, а исчерпал обе — на субтитры или звук. Обе модели отказали (нет ключа OpenRouter, таймаут `VIDEO_TIMEOUT_SECONDS`, пустой или отказной ответ, провайдер не понял видео) — честная деградация на старый добрый L3: YouTube → субтитры (русские → английские → автогенерация), файлы и ссылки → транскрипт звука (STT-каскад Groq → OpenRouter). Сбои уровней наружу не вылезают: бот молча переходит ниже и в итоге всё равно отвечает.

Выжимка теперь **честная**: если разборчивой речи в ролике нет или транскрипт короче `video_summary_min_chars` (100 символов по умолчанию), бот прямо скажет «в ролике почти нет речи, пересказывать нечего» — и не выдумает сюжет по памяти чата: RAG-подмес при видео-выжимке убран принципиально, источник «о чём ролик» — только сам ролик.

**«Транскрипт» — режим текста, и теперь для всех типов видео он выдаёт текст в формате кружков**: «Имя 🗣: *текст*» (у репостов — с пометкой «(переслал …)»). **Изменение поведения:** раньше «транскрипт <ссылка на YouTube>» работал как «че за видос» и давал выжимку; теперь это честные субтитры текстом (кап 20 000 символов), а если субтитров нет — бот скачает ролик, прогонит звук через STT и всё равно отдаст текст. YouTube-выжимка по «че за видос» не изменилась: тот же каскад «смотреть → субтитры», а если YouTube тупит — привычные токсичные ретраи («ютуб опять тупит, пробую выдрать текст еще раз»).

Размерные гейты (проверка до скачивания) на месте: `VIDEO_TRANSCRIBE_MAX_SIZE_MB` (50 МБ) и `VIDEO_TRANSCRIBE_MAX_DURATION_SECONDS` (600 сек). Новые предохранители раунда 3: `VIDEO_STT_TIMEOUT_SECONDS` (120 сек на одну STT-стратегию для видео; голосовые не трогает — у них свои таймауты) и размерные гейты провайдеров `STT_GROQ_MAX_UPLOAD_MB` (25) / `STT_OPENROUTER_MAX_UPLOAD_MB` (20): файл тяжелее лимита провайдера — стратегия пропускается, а не ловит HTTP 400. Нюанс: Groq free реально переваривает ~25 МБ, так что если бот на 40-мегабайтный ролик честно скажет «видос жирный» — это не жадность, а физика: выставь 25 МБ в админке и живи спокойно. Публикация выключена при пустом `MEDIA_SHARE_SECRET`, мультимодалка — при пустом `OPENROUTER_API_KEY`: бот тихо деградирует на STT/субтитры, юзеру — фраза, а не трейсбек. Голосовые, кружочки и аудио фича по-прежнему не трогает — у них свои хендлеры, а видео из YouTube приоритетнее ссылки в тексте, если она есть.

#### Web — пересказ страниц

Пишешь **«поясни за ссылку», «че по ссылке», «о чем статья», «поясни за статью», «выжимка», «че на сайте», «перескажи статью»** плюс любой http(s)-URL — бот читает страницу (локальный парсер, при провале — Tavily/Exa) и пересказывает суть. Сайт сдох или за пейволлом → «сайт сдох или закрылся пейволлом, читать нечего».

#### Скачай — видео из ссылки, без танцев

Пишешь **«скачай»** плюс ссылку на видео (TikTok, YouTube, Twitter/X и всё остальное, что умеет cobalt) — бот скачивает видео и кидает его прямо в чат. Никаких сторонних ботов, никакой рекламы с водяными знаками: свой downloader на self-hosted cobalt + yt-dlp.

С bugfix-раунда 04.09.2026 маршрутизация честная, без самодеятельности: **прямые ссылки на медиа-файл** (`.mp4/.webm/.mkv/…` на обычном хостинге, файл реально лежит по адресу) бот **стримит сразу**, без cobalt, — это осознанно: нечего гонять файл через третью машину ради того, что можно скачать за один заход. А вот ссылки на YouTube и ещё полтора десятка платформ (TikTok, Instagram, Facebook, X/Twitter, VK, Rutube, Vimeo, OK, Twitch, Kick, Dzen, Reddit и прочие — всего 17) прямым стримом больше **не считаются, даже если в URL нарисовано `.mp4`**: там CDN, редиректы и HTML-просмотр, файла по адресу нет. Такие ссылки уходят в yt-dlp/cobalt, как и положено порядочным ссылкам.

- Реплай **«скачай»** на видео-сообщение или видео-документ (своё, чужое, хоть репост — mime `video/*` или имя с расширением) без всяких ссылок → бот качает файл и пересылает его в чат как своё. Голосовые и кружочки не подходят — они не видео, у них своя жизнь.
- Несколько ссылок в одном сообщении → скачает все, по очереди (качалка одна на всех, очередь честная).
- Если у видео несколько версий качества → бот предложит выбрать кнопками; протухшее меню честно скажет «время вышло».
- Пока бот качает — он занят: повторный «скачай» получит вежливое «не жми кнопку, я работаю». Кулдаун на (чат, юзер) — 30 минут.
- Ссылки без видео («скачай», а ссылки нет) → порция абьюза. Качать воздух бот не обязан.
- Скачанные файлы живут во временной папке `media/downloads/` и подметаются после отправки.

Фича выключена рубильником `DOWNLOAD_ENABLED` (по умолчанию выключена — см. раздел Docker-инфраструктура ниже).

#### Расшифровка голосовых и кружочков — лень слушать? Бот послушает

Кинули в чат голосовое или видеокружочек — бот сам расшифрует текст и ответит реплаем: **«Имя 🗣: расшифровка»**. Теперь можно делать вид, что ты прочитал всё, не тратя 47 секунд на чьё-то «короче, слушайте…».

- Каскад распознавания: Groq Whisper (быстрый, основной) → OpenRouter (запасной). Строго одна попытка на каждого — если оба сдохли, бот честно орёт, что уши не работают.
- Кружочки конвертируются как mp4, войсы как ogg — бот разбирается сам.
- Голосовые длиннее `VOICE_MAX_DURATION_SECONDS` (600 сек = 10 минут) не качаются: кто записывает войсы на 15 минут — сам виноват.
- Тишина на записи → фраза про то, что там даже молчание содержательнее. Полный провал сервисов → своя порция цинизма.
- Бонус для памяти: расшифровка **заменяет плейсхолдер** в памяти бота реальным текстом — то есть бот теперь знает, что было в том самом войсе. Пугает? Правильно.

Выключается рубильником `ENABLE_VOICE_TRANSCRIPTION`; ключи — `GROQ_API_KEY` / `OPENROUTER_API_KEY` (только в `.env`).

#### Checkup — бот лезет в свои логи и орёт на тебя оттуда

Спроси в чате **«чекап», «ты в порядке», «живой собака», «пульс бота», «чекни здоровье», «как сервак»** — бот устроит самодиагностику: заберёт логи (из облачного мониторинга Better Stack, а если тот обосрался — из локального `journalctl`) и выдаст токсичный отчёт о своём здоровье реплаем на твой вопрос. Отчёт пишет нейронка в роли токсичного DevOps-инженера, унижающего разработчика за кривой код. «чекапчик» и «живой собакен» пролетают мимо — триггер знает границы слова.

Теперь в тот же чекап входит и **метрики здоровья памяти**: размер базы, свободное место на диске, счётчики записано/протухло/дублей. Да, бот сам себе сдаёт анализы — и озвучивает результаты всё с тем же унижением. В основном тебя.

### Память бота (GraphRAG) — кто кого назвал долбоёбом

Поверх трёх уровней памяти у бота есть **граф знаний** прямо в SQLite: когда старые сообщения сжимаются в факты, бот отдельным вызовом нейронки извлекает связи «кто с кем спорил», «кто кого жёстко оскорбил», «кто на чём фанатеет». Участники и темы становятся узлами, связи — рёбрами, а повторное упоминание одной и той же связи накачивает её **вес**. Да, у ваших конфликтов теперь есть вес. Буквально.

Факты из чата живут вечно; факты из поиска/фактчека/ютуба/веба — 14 дней. Перед генерацией саммари или ответа в DirectChat бот подмешивает в контекст собственные прошлые знания — как настоящий слон, который помнит, что ты наговорил неделю назад. Аварийный выключатель — `GRAPH_RAG_ENABLED=False`, и бот ведёт себя как до появления графа.

С недавних пор память стала умнее и экономнее:

- **Дедуп при записи:** дубль факта не запишется дважды — сравнение по смыслу, а не по буквам. Свежий факт побеждает старый при конфликте.
- **Веса значимости:** у каждого факта вес — «важно» живёт дольше «мемов». Плюс квота на человека: один болтун не забьёт память целиком.
- **TTL+LRU:** факты, которые бот реально использует, живут дольше неиспользуемых. Как шкаф: нужное наверху, хлам на выброс.
- **Уборка по расписанию:** однотипные эпизоды сливаются в общие факты, дубли склеиваются, мусор выбрасывается.
- **Time-decay:** старые связи в графе слабеют, свежие выигрывают. Обиды тускнеют со временем. Немного.
- **MMR:** подбор фактов разнообразный — не три одинаковых карточки подряд, мы не на конвейере.
- **Кэш эмбеддингов + int8-сжатие векторов:** та же память, меньше денег и места.
- **Резервная копия базы раз в день** + экспорт фактов текстом, читаемым глазами (а не только роботами).
- **Даты в RAG-фактах (раунд 4):** когда бот подмешивает в контекст свои прошлые знания, каждый факт несёт дату — префикс `[ГГГГ-ММ-ДД]` (UTC, по времени создания). «Когда это было», «что было N-числа» — нейронка теперь видит числа, а не гадает по косвенным признакам. Работает везде, где рендерится RAG-контекст: и в direct_chat, и в саммари.
- **Research-отчёты (раунд 4):** куда девать многолетнюю историю чатов из `migrate_history/` (~1,27 млн сообщений, три разных чата) — форматы, стоимость и поэтапный план в [`plans/docs/memory-import-research.md`](plans/docs/memory-import-research.md); что сломается при переезде памяти с SQLite на PostgreSQL и как чинить — в [`plans/docs/sqlite-to-pg-research.md`](plans/docs/sqlite-to-pg-research.md) (вход в Epic 86, пока future/planned).

Решение «не переезжать на Mem0/Zep/Letta» зафиксировано: своя схема памяти уже взрослая, подсматриваем только приёмы.

## Docker-инфраструктура (для «скачай» и локального Bot API)

Первое использование Docker в истории этого проекта. Сам бот — хостовой python-процесс (systemd), а в Docker живут два его инфраструктурных слуги:

```bash
docker compose up -d          # поднять telegram-bot-api (:8081) + cobalt (:9000)
docker compose ps             # проверить, что слуги на месте
```

| Контейнер | Порт | Зачем |
|---|---|---|
| `telegram-bot-api` | `127.0.0.1:8081` | Локальный Bot API-сервер: без него Telegram не примет видео больше 20 МБ, а мы качаем не по 5 мегабайт |
| `cobalt` | `127.0.0.1:9000` | Сервис скачивания видео — та самая мышца за командой «скачай <ссылка>» |

Порты публикуются строго на `127.0.0.1` — наружу слуг не выпускаем, они работают только для бота. Папка `./docker/telegram-bot-api` смонтирована по тому же пути, что и в контейнере (`/var/lib/telegram-bot-api`) — так `file_path` от локального Bot API резолвится напрямую с диска, без лишнего скачивания.

**Без этих контейнеров фича «скачай» просто не включается:** рубильник `DOWNLOAD_ENABLED=False` оставляет бота в классическом режиме (облачный Bot API), и все желающие продолжают смотреть видео в оригинальных приложениях как дикари.

| Вкладка | Зачем |

| 📊 Статус | Аптайм, CPU/RAM/диск, карточки LLM-провайдеров с health-пингом, график аптайма и живые логи — со стеками и кнопкой «скопировать» |
| ℹ️ Как это работает | Та самая справка `/info`, но в красивой обёртке; админ может редактировать с предпросмотром |

Вкладки пересобраны в эпике 04.09.2026: «Модели и Провайдеры» и «API Ключи» слились в «LLM Провайдеры», из «Лимитов» выделились «Память и RAG» и «Реакции и Триггеры» — теперь конфиг разложен по полочкам, а не свален в три кучи.

**KV-редактор вместо JSON-простыни.** Алиасы саммари (`limits.summary_aliases`, пары «Telegram ID → имя», например `{"138811255": "Леха"}`) больше не надо править сырым JSON-текстом: в «Лимиты» → «Алиасы людей» встроен Key-Value-редактор — строки «ID → имя», добавил/удалил/сохранил, бот подхватил. Кривой JSON теперь не собрать даже со старанием.

**Динамический RBAC.** Роли задаются правами на секции/отдельные параметры/отдельные ключи/действия. `admin` видит всё (wildcard — флаг «я всё могу»), `moderator` по умолчанию — только лимиты и кнопки рестарта, `user` — только «Статус» и «Как это работает» (статус-дашборд открыт всем валидным пользователям миниаппа — пусть завидуют). Удалить или лишить wildcard последнюю всемогущую роль нельзя — бот бережёт себя от лок-аута.

**Управление жизненным циклом.** Прямо из карточки «Бот»: 🔄 Рестарт / ⏹ Стоп / ▶ Старт (кнопки видны только ролям с правами `control.*`). Команда подтверждается, выполняется через пару секунд, защищена от спама (не чаще раза в 30 секунд). На сервере это `systemctl` через polkit, локально — честный graceful exit с пожеланием перезапустить руками.

- После «Стоп» бот и правда выключен: кнопка «Старт» ему уже не поможет (некому слушать HTTP). Полный старт — по-стариковски: SSH → `systemctl start admin_bot` (при обычном старте бот сам подчистит stop-флаг).
- Остановка оставляет на сервере флаг-файл `.adminbot_keep_stopped` — при ручном запуске бот его увидит, вытрет и аккуратно выйдет с кодом 0. Это не бот обиделся, это защита от бесконечного «перезапустился и умер».

**Быстрый старт админки:**

```bash
# 1. БД: в .env добавь (пароль придумай сам, я за тебя не буду)
#    POSTGRES_DSN=postgresql://adminbot:<pass>@127.0.0.1:5432/adminbot
#    POSTGRES_PASSWORD=<pass>
#    WEB_PORT=8000
docker compose up -d postgres       # ждём, пока healthcheck позеленеет

# 2. Перенос настроек из .env в базу (ДО первого запуска с фичей):
python scripts/migrate_env_to_pg.py --dry-run     # свериться глазами
python scripts/migrate_env_to_pg.py               # перенести по-настоящему

# 3. Рестарт бота — и всё.
```

- Кнопка миниаппа задаётся в BotFather (`/setmenubutton`) на адрес `https://admin-bot.duckdns.org/web/`.
- Секреты в базе хранятся открытым текстом, но PostgreSQL слушает только `127.0.0.1`, в API ключи отдаются только как «configured/last4», а в логи — только факт, никогда значение. Паранойя включена.
- Админка общается с ботом тем же процессом: FastAPI крутится внутри `bot.py` в одном event loop с polling'ом. Никаких лишних сервисов — бот теперь ещё и веб-сервер, примите и смиритесь.

| `OPENROUTER_API_KEY` | *(пусто)* | Ключ OpenRouter (запасной распознаватель). Секрет: только в `.env`. Пусто = остаётся только Groq |
| `GROQ_MAX_CONCURRENCY` | `1` | Очередь для конкурентных запросов (asyncio.Semaphore). 1 = строго последовательно (Free Tier 30 RPM) |
| `GROQ_MIN_INTERVAL` | `2.0` | Минимальный интервал между запросами к Groq, сек (30 RPM = 1 req/2s) |
| `GROQ_MAX_RETRIES` | `3` | Количество retry на 429 (exponential backoff 2s→4s→8s + Retry-After) |

### SmartCache — кэш умных ответов (3)

| Переменная | Дефолт | Что меняет |
|---|---|---|
| `SMART_CACHE_ENABLED` | `False` | Кэш повторных запросов. `True` = повторный вопрос за 30 минут получает мгновенный ответ из кэша, нейронка не дёргается |
| `SMART_CACHE_TTL_SECONDS` | `1800` | Время жизни кэш-строки (30 минут) |
| `SMART_CACHE_MAX_ROWS` | `1000` | Потолок строк кэша (старые вытесняются) |

## Мониторинг

| Компонент | Что делает | Библиотека |
|---|---|---|
| **Sentry** | Ловит исключения со стектрейсами | `sentry-sdk` |
| **Better Stack (свой хендлер)** | Стримит логи в Better Stack в реальном времени | свой `services/betterstack_handler.py` (раунд 4; замена чёрного ящика `logtail-python` 0.4.0, который терял события молча) |
| **Админка → 📊 Статус** | Живые логи последних событий (in-memory ring-buffer, секреты замаскированы ещё до записи), CPU/RAM/диск, health-пинги LLM-провайдеров, график аптайма | свой велосипед |

- **Свой `BetterStackHandler`** вместо logtail-python: буфер на 2000 событий + фоновый поток-флашер (батчами до 500, раз в секунду, POST на `in.logs.betterstack.com/{токен}`), формат фрейма — logtail-совместимый, чтобы панель не заметила подмены. В отличие от старого клиента, **всё видно**: счётчики `sent/failed/dropped`, сбой отправки — явный WARNING в journald (не чаще раза в минуту, чтобы не заорать сам на себя), дроп при полном буфере — тоже WARNING (раньше был тихий `dropcount`), восстановление после серии сбоев — INFO с числом упавших батчей. Диагностика при старте — маркер `[betterstack] attached | token_len=N | handler=own-v1` (и в journald, и в админке «Статус»: первым же событием он уходит и в панель — живая проверка, что хендлер слушает). При остановке — `[betterstack] shutdown flush`: остаток буфера досылается, ничего не пропадает (кроме SIGKILL — против убийств -9 медицина бессильна).
- **aiogram.event-спам заглушён**: aiogram 3.31 логировал **каждый** апдейт на INFO («Update id=… is/not handled») — в панели это было море шума на пустом месте. Теперь логгер `aiogram.event` сидит на WARNING: полезного в нём не было (ошибки и так пишутся в ERROR), зато в Better Stack наконец видно реальную жизнь бота, а не простыню апдейтов.
- Логи смотришь на [betterstack.com](https://betterstack.com/) → Logs & Metrics → Live tail (фильтры по уровню, модулю или тексту) — либо в админке на вкладке «Статус», если лень идти в браузер.
- Ошибки — там же, в разделе Errors: стектрейс, контекст, чат, сообщение. Как чёрный ящик, только полезный.
- Локально и без Better Stack: логи идут в консоль, всё работает.
- На сервере есть ещё `journalctl -u admin_bot` — и бот сам умеет его читать по слову «чекап».
- История аптайма хранится в PostgreSQL (`uptime_events`, heartbeat раз в минуту, хранение 72 часа) — график в админке покажет честный разрыв, когда бота перезапускали.

## Известные нюансы

- **Приватность бота должна быть выключена.** Обязательно: BotFather → `/setprivacy` → **Disable**. Иначе бот в группе видит только команды и упоминания: не услышит ни «отбой», ни Славу, ни саммари-материал. Это настройка Telegram, а не баг.
- Бот должен быть **админом** приватного канала из `DEAD_PAGE_RELAY_CHANNEL_ID` — иначе dead page нечего пересылать.
- `DEAD_PAGE_COOLDOWN=0` → спам на каждый репост. Весело, но чревато баном.
- Приветствие Лехи (F7) срабатывает при **смене статуса**. Если Леха уже в чате на момент старта бота — проверяй через `/alangreet`.
- Таймер молчания Лехи живёт в БД и переживает рестарт: перезапустил бота — бот не «забыл» Леху.
- Слава иногда обижается, но всегда возвращается. Это не баг, это фича личности.
- Костик не понимает, за что. И не поймёт.
- Тумблеры реакций («Вася», «куча», common-мимикрия, мимикрия Лехи) по умолчанию выключены — это сознательный безопасный деплой, а не поломка. Включил в админке («Реакции и Триггеры») или в `.env` — и чат ожил.
- Память-команды для участников — тоже за тумблером (`flags.memory_commands_user_enabled`, дефолт false): пока выключен, «бот, запомни» от не-админа — это вежливый отказ, а не молчание. Админ и модераторы не зависят от тумблера.
- «Забудь всё» — намеренно не работает (только конкретика), а «забудь все» без «ё» бот может принять за обычный диалог: пишите с буквой «ё» или конкретнее — «бот, забудь про бензин».
- Free-видео-модели (`nemotron-omni`, `minimax-m3:free`) не гарантируют доставку ролика — но с раунда 4 их «не вижу видео» больше не выдаётся за пересказ: отказной ответ ловится, каскад честно уходит на запасную модель/субтитры/звук.
- Без интернета уровень токсичности падает до нуля. Техническое ограничение вселенной.
- Геопозиции, контакты и кубики (dice) в память не сохраняются: саммарить кубики нечего. Медиа без подписи попадают в контекст как `[фото]`.
- Если векторный поиск (sqlite-vec) на сервере не завёлся — бот молча переходит на текстовый поиск. В логах WARNING, в чате никто ничего не заметит.
- «Глазастый» просмотр файлов (мультимодалка через `/media/`) работает, только если задан `MEDIA_SHARE_SECRET` и OpenRouter может достучаться до `MEDIA_PUBLIC_BASE_URL` (публичный домен → Caddy → FastAPI). Нет домена/секрета — бот честно перескажет ролик по звуку (STT) либо скажет, что речи нет: мягкая деградация, а не падение.
- Удаление dead page работает через пассивную телепатию: бот узнаёт, что Слава снёс репост, только когда кто-то ответит или отцитирует удалённое сообщение. Удалил молча и без реплаев — бот не заметил. Такая вот слежка.
- `/summary` не удаляется из чата (в отличие от админ-команд): команда — тоже сообщение, а память собирает всё. Свидетелей трогать нельзя.
- `setMyCommands` при старте перезаписывает меню бота: в нём живут `/summary` и `/info`. Если в BotFather было своё меню — оно сменится на это.
