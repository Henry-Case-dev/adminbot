# AdminBot — ваш карманный цифровой абьюзер с элементами искусственного интеллекта

*Решение для тех, кто хочет токсичности в чате, но ленится писать сам. Теперь с памятью слона и терпением снайпера.*

**Версия:** v2.24.0 | **Тестов:** 939 | **Эпиков:** 26 (T-001…T-206)

---

## 🚀 Возможности

### Слава: возвращение блудного долбоёба (F1)
Когда Слава заходит в чат (покинул → вернулся) — бот пишет **«ДОЛБОЕВ ВЕРНУЛСЯ»**. Dead page при входе по умолчанию не шлётся (`DEAD_PAGE_POST_ON_JOIN=False`, Epic 22) — не надо перебивать классику. Каждый раз одно и то же, и каждый раз смешно. Славе — нет.

### Слава: Dead Page (F2 v2)
- Кто-то делает репост из канала **@d_pages** → бот выбирает случайный пост из своего приватного канала и пересылает его в чат. Технология «слышу звон — несу что попало» доведена до совершенства.
- Если приватный канал упал или бот оттуда выгнали → fallback: случайная картинка + текст из папки `media/dead_page/`. Качество контента не гарантируется, но volume присутствует.
- При входе Славы → «ДОЛБОЕВ ВЕРНУЛСЯ». Dead page при входе по умолчанию выключен (`DEAD_PAGE_POST_ON_JOIN=False`, Epic 22) — Слава и так знает, зачем вернулся.

**Исправлено в v2.11.0 (Epic 14):**
- **Альбомы (media groups)**: если в приватном канале лежит пост из нескольких фото (альбом), бот теперь пересылает **весь альбом целиком**, а не одно первое фото. Раньше из трёх фото с подписью пересылалось только одно — теперь все три.
- **Как работает**: бот отслеживает `media_group_id` новых постов в релейном канале и сохраняет в БД (путь 1 — точный, через `forward_messages`). Для старых постов — эвристический поиск соседей по дате (путь 2 — запасной).
- **Дедупликация триггера**: когда кто-то репостит альбом из @d_pages, Telegram шлёт N событий (по одному на фото). Бот теперь обрабатывает только первое — не спамит кулдаун лишними запросами.

**Обновлено в v2.20.0 (Epic 22):**
- **Анти-повтор PostPicker (D54)**: бот запоминает последний отправленный пост (ключ БД `dead_page_last_sent:{chat_id}`) и в следующий раз выбирает ДРУГОЙ. Раньше при sparse-канале sequential scan упорно находил «почти всегда id 3» — теперь Слава видит разнообразие. Если в канале только один пост — осознанный повтор (лучше повториться, чем удариться в ALL RANGES EXHAUSTED).
- **Триггер только для репостов Славы (D53)**: dead page реагирует на репосты из @d_pages исключительно от Славы. Репост от кого-то другого проходит мимо — Слава был и остаётся главным героем.

### Слава: чат-реакции (F3/F4)
Трёхуровневая система эскалации абьюза:
- Просто написал → **«пошёл нахуй»** (catch-all, потому что Слава всегда заслуживает)
- Упомянул «куча»/«кучи»/«кучу» → **«ДАЛБАЕБ»** (F4 — прицельный выстрел по грамматике)
- Каждое 5-е сообщение → **GIF** со славным членом (F3 — визуальное подкрепление)

### Слава: военный оповещатель (F5v2 — Epic 10)
Когда Слава пишет сообщение с военными ключевыми словами (дрон, БПЛА, ракета, опасность, тревога, убежище и т.д.) — бот отвечает случайной фразой из пула: «потрясись», «повизжи», «прячься под шконку быстрее», «закрой ушки и считай до десяти», «поплачь». Психологическая поддержка наоборот.

**Новое в v2 (Epic 10):**
- **Caption support**: теперь бот видит угрозу даже в подписях к медиа. Раньше был слеп как крот — теперь зряч как орёл.
- **Channel reposts**: если **любой пользователь** репостит из каналов «ЧП Пермь» или «Радар БПЛА» — бот тоже орёт. Коллективная паника.
- **Расширенный словарь**: 90+ словоформ. Бот знает о войне больше, чем некоторые военкоры.
- **Настраиваемый пул фраз**: `WAR_REPLIES` в `.env`. Хотите «всё пропало» вместо «потрясись»? Да пожалуйста.
- **Детальное логгирование**: каждый чих пишется в Better Stack. Можно потом пересматривать как сериал.

**Исправлено в v2.9.0 (Epic 12):**
- **Forwarded messages fix**: бот теперь перехватывает военные слова не только в сообщениях, которые Слава пишет сам, но и в его репостах (forwarded messages). Раньше Слава мог репостнуть «БПЛА летит» и бот молчал как партизан. Теперь не молчит.

### Слава: фото-сюрприз (F6 — Epic 12, обновлено в v2.18.0) 🆕
Каждый N-й ответ «пошёл нахуй» (по умолчанию N=10) бот вместо текста отправляет **случайное медиа** из директории `media/slavik/slavik_random/`. Счётчик сбрасывается после отправки — и дальше по кругу.

**Поддерживаемые типы медиа (v2.18.0):**
- 📷 **Photo**: `.jpg`, `.jpeg`, `.png`, `.webp`, `.bmp`
- 🎬 **Video**: `.mp4`, `.mov`, `.webm`
- ✨ **Animation (GIF)**: видеофайлы с `gif` в имени (word-boundary детект — `.gif.`, `_gif`, `gif` в начале)
- 🎵 **Audio**: `.mp3` → `send_audio`
- 🎤 **Voice**: `.ogg` → `send_voice`
- 📄 **Document (fallback)**: всё остальное отправляется как документ. `.pdf`? `.zip`? `.txt`? Да без разницы, Слава примет любой подарок.

**Настройка:**
- `SLAVIC_PHOTO_INTERVAL=10` — каждые сколько ответов слать медиа (в `.env`)
- `SLAVIC_RANDOM_DIR=media/slavik/slavik_random` — директория со случайным медиа всех типов
- `SLAVIC_PHOTO_PATH` — **deprecated**, используется как запасной путь если `SLAVIC_RANDOM_DIR` пуст
- `SLAVIC_PHOTO_INTERVAL=0` — отключает фичу (только текст)
- Счётчик хранится в БД (переживает рестарт)
- **Не зависит от F3** (GIF-счётчик) — разные таблицы, разные интервалы, работают параллельно

### Alan_Z: автоответчик (F6)
Каждые N сообщений Алана бот проявляет **крайний интерес** к темам: тренировки, лонгковид, фьючерсы, нейросети, жим дьявола. Случайная фраза из пула ~40 вариантов. Маскируется под живого собеседника. Алан до сих пор не понял.

### Alan_Z: приветственное видео (F7)
Когда Alan заходит в чат — бот отправляет случайное видео из `media/leha_greeting/` с подписью `@Alan_Z`. Срабатывает через `ChatMemberUpdated` (основной детект) и `new_chat_members` (fallback для параноиков). Кулдаун 10 секунд — чтобы не заддосить чат радостью.

### Common Service: отбой + Danger Detection (F9 — Epic 15) 🆕
**Общий сервис для ВСЕХ пользователей чата.** Два sub-service'а на одном роутере (позиция 4c):

**1. Отбой (F9):** Когда кто-то пишет слово «отбой» — бот отправляет случайное медиа из `media/common/otboy/` с нативным цитированием именно этого слова через Telegram quote API.

**2. Danger Detection (Epic 15):** Когда кто-то пишет danger-слово (бпла, ракетная, опасность, сирена, дрон, взрыв, хлопок и др. — 118 словоформ) или danger-фразу-связку («укрыться в убежище», «уйти в бомбоубежище», «беспилотная атака», «ракетная атака», «атака дронов» и др. — 17 фраз, итого 135 паттернов) — бот отправляет случайное медиа из `media/common/danger/`. Одиночные «атака»/«угроза»/«прилет» больше не в словаре — только в связках, как и положено серьёзному джентльменскому набору.

**Где ловятся слова:**
- Обычные текстовые сообщения
- Подписи к фото/видео (caption)

**Как работает:**
- Regex с Cyrillic word boundary (`(?<![а-яё])...(?![а-яё])`) — «отбойный» не матчится, только отдельное слово
- Фразы-связки (17 шт.) проверяются **перед** одиночными словами: границы только по краям фразы, «в бункер» не сработает внутри «в бункере», зато «ракетная атака» сработает целиком
- Регистронезависимый: «Отбой», «ОТБОЙ», «БПЛА», «бпла» — все сработают
- Quote через нативный `ReplyParameters` — в интерфейсе Telegram подсвечивается именно найденное слово
- Ответ приходит reply-to на исходное сообщение
- Media directory-based: auto-detect photo (jpg/png/webp), video (mp4/mov/webm) или animation (mp4/mov/webm с "gif" в имени). **Обновлено в v2.16.0:** детект GIF использует word-boundary матчинг (`_gif`, `gif_`, `.gif.`) — надёжно определяет анимацию даже при любом расположении слова "gif" в имени файла.
- **Dual cooldown (v2.16.0):** двухуровневая система защиты от спама:
  - `COMMON_COOLDOWN` (глобальный) и `DANGER_COOLDOWN` (только danger). Danger срабатывает только если **оба** кулдауна истекли; otboy проверяет только общий
- **Относительные ко времени значения**: новые кулдауны принимают human-readable форматы: `1h`, `30s`, `5m`, `1d`, или просто число секунд. `0` = отключено.
- Поддержка обратной совместимости: старые plain-integer значения из `.env` работают без изменений.

**Настройка:**

| Переменная | По умолчанию | Что делает |
|-----------|-------------|-----------|
| `COMMON_COOLDOWN` | `0` | Общий кулдаун между отправками в одном чате. `0` = без кулдауна |
| `DANGER_COOLDOWN` | `60s` | Доп. кулдаун только для danger. `0` = без доп. ограничения |
| `COMMON_MEDIA_BASE` | `media/common` | Базовая директория с подпапками otboy/ и danger/ |
| `DANGER_WORDS` | *(118 слов + 17 фраз)* | Danger-слова через запятую. Пусто = встроенные дефолты (118 словоформ + 17 фраз-связок = 135 паттернов; фразы не переопределяются) |

**Масштабируемость:** сервис изолирован в отдельных модулях (`filters/otboy_word.py` + `filters/danger_word.py` → `services/common_relay.py` → `handlers/common.py`). Не зависит от других фич, не использует БД. Добавление новых sub-service'ов — новый filter + handler на том же common_router, новый subdir в media/common/.

**Обновлено в v2.12.1 (Epic 16):** DangerWordFilter расширен с 22 до **187 словоформ** (полная синхронизация с `WarWordFilter.WAR_WORDS` из `filters/war_word.py`). Добавлены все падежные формы, а также новые категории: обстрел, сбитие, падение, эвакуация, отбой.

**Исправлено в v2.14.0 (Epic 18):**
- **Критический фикс `.env.example`**: переменная `DANGER_WORDS` в шаблоне была жёстко прописана как `бпла,ракетная,опасность` (всего 3 слова вместо 135+). Это приводило к тому, что бот на сервере игнорировал 132+ словоформ из `word_lists.py`. Теперь `.env.example` содержит пустое значение — бот автоматически использует полный словарь из кода.
- **Фикс propagation**: все хендлеры в `common_router` и `war_alert_router` возвращают `UNHANDLED` — события больше не блокируются между роутерами.

### Mimic: передразнивание (F11 — Epic 18) 🆕 — обновлён v2.15.0
**Шуточная механика трансформации текста «под шепелявость».** Чистая алгоритмическая (не LLM) замена букв. Алгоритм полностью заменён на новый многослойный:

| Слой | Правило | Пример |
|------|---------|--------|
| WORD_MAP | Целые слова: что→фе, почему→патему, вообще→вафе, хочу→хатю... | «что случилось?» → «фе случилось?» |
| SUBSTR_MAP | Окончания/подстроки: шься→фся, ться→тца, сл→фл... | «учишься» → «учифся» |
| Согласные | р→л, ш/щ→ф, ж→з, ч→т | рука→люка, шум→фум |
| Гласные (после согл.) | у→ю | тут→тют |
| Регистр | Сохраняется | Рыба→Лыба, ЩУКА→ФЮКА |

**Две независимые интеграции:**

**1. Common сервис (жертва):** Реагирует на сообщения от `MIMIC_VICTIM_USER_ID`. Условия: > N слов (по умолчанию 5) и таймаут (по умолчанию 60 сек).

**2. Slavik сервис (мьютекс):** Встроен в `slavik_catchall_handler` с приоритетом: фото > mimic > «пошёл нахуй». Если сообщение Славика > 5 слов и прошёл таймаут — mimic. Иначе — классический ответ. Дублирование исключено через if/elif/else.

**Настройка:**
| Переменная | По умолчанию | Что делает |
|-----------|-------------|-----------|
| `MIMIC_VICTIM_USER_IDS` | `138811255` | ID жертв через запятую. Пусто или "0" = отключено |
| `MIMIC_MIN_WORDS` | `5` | Мин. число слов для mimic |
| `MIMIC_COOLDOWN` | `1h` | Кулдаун между mimic (common) |
| `MIMIC_FORWARDS_ENABLED` | `False` | Передразнивать репосты? `False` = только собственные сообщения (репосты игнорируются), `True` = старый беспредел |
| `SLAVIK_MIMIC_MIN_WORDS` | `5` | Мин. слов для mimic Славика. -1 = отключено |
| `SLAVIK_MIMIC_COOLDOWN` | `60s` | Кулдаун между mimic (Славик) |

**Admin-команда:** `/mimic [текст]` — тест трансформации (DM: любой, группа: только админ).

**Эпик 22 (D52):** mimic больше не передразнивает **репосты** — только собственные сообщения жертвы (`MIMIC_FORWARDS_ENABLED=False`). Раньше бот шепелявил чужие цитаты, теперь цитирует только первоисточники.

### SmartModule: Summary — бот, который подслушивает (Epic 24) 🧠 🆕
**Первый сервис с настоящим ИИ.** Бот подслушивает **весь** чат, а каждые 6 часов (00:00/06:00/12:00/18:00 по Екатеринбургу) выдаёт токсично-ироничное саммари через LLM: кто с кем спорил, кто какую хуйню сморозил и кто в итоге оказался «самым главным шизом». Или по команде `/summary` — если не спамить, конечно (троттлинг 60 секунд на (чат, юзер)).

**Промпт v2 (Epic 27) — бот-абьюзер пошёл учиться печатать:** теперь он имитирует «ленивую печать» живого двушника — регистр в начале предложений скачет случайным образом, а не сидит на маленькой букве, как отличник младших классов. Маркдаун, списки и эмодзи — под строжайшим запретом: за несанкционированную звёздочку в тексте полагается расстрел типографики. А длинные тире и кавычки-ёлочки с Epic 29 промпт уже не воспитывает (v4): их вычищает сам бот на выходе — расстрельная бригада переехала в бэкенд и не промахивается. Сплошной текст с абзацами — потому что читать его стены без абзацев согласны только мазохисты.

**Трёхуровневая память — как у слона с амнезией по расписанию:**
- **L1 — окно генерации (6 часов):** свежая история, которую бот реально читает. По умолчанию последние 500 сообщений, но срезается до 120 000 символов, чтобы LLM не подавился.
- **L2 — сырая память (30 дней):** полная переписка для RAG. Когда бот делает саммари, он вытаскивает из прошлого «точные цитаты» по ключевым словам окна через FTS5 — да, он цитирует то, что вы сказали 3 недели назад. Готовьтесь.
- **L3 — векторный архив (90 дней):** всё старше 30 дней сжимается LLM'ом в факты по темам и ищется по векторам (sqlite-vec KNN). Если векторы недоступны — факты всё равно живут в тексте и ищутся через FTS5.

**Как работает деградация (бот не умеет падать):**
- sqlite-vec не загрузился на Windows/Linux → вся векторная ветка тихо превращается в FTS5-поиск.
- Эмбеддинги упали/таймаут → то же самое, факты ищутся текстом.
- LLM упал → в чат уходит честное «не смог сделать саммари потому что упал апи», в логи — полный стектрейс.

**Осознанные решения (зафиксировано после ревью):**
- **Кап размера ответа — только через промпт.** Жёсткого кода «отрезать по `MAX_SUMMARY_PARTS`» нет: LLM получает `{max_symbols}` в системном промпте, а чанкинг ≤4096 — это защита от лимита Telegram, а не enforcement длины. Если LLM разойдётся — сообщение уйдёт чанками, и бот не будет рубить мысль на полуслове.
- **location/contact/dice и прочие «бестекстовые» сообщения не сохраняются.** Осознанно: саммарить геопозицию и кубики — то ещё развлечение. Текст, подписи и медиа (фото/видео/войс/стикер/файл) — сохраняются; у медиа без подписи в контекст попадает описание вида `[фото]`.
- **`SUMMARY_CHUNK_DELAY=2.0`** — отклонение от дизайна (1.0) в пользу лимитов Telegram: 1 сообщение/сек на чат, 20/мин в группе.
- **`/summary` не удаляется из чата** (в отличие от админ-команд): команда — тоже сообщение, память собирает всё, а свидетелей трогать нельзя.

**Требования к проду (обязательно!):**
- **BotFather → `/setprivacy` → Disable.** С включённой privacy mode бот в группах видит только команды и упоминания — память будет пустой, саммари будет про «ничего».
- **`LLM_API_KEY` в продовом `.env`** — в `.env.example` лежит плейсхолдер `your_key_here`, реальный ключ не коммитим (секреты — не для git'а).

### Dead Page: фикс репостинга Rich Message (Epic 18) 🆕
**Проблема:** бот застрял на старом посте (id=3) и не видел новые Rich Message посты (Telegram Bot API 10.2, июль 2026).

**Исправления:**
- **Forward scan**: при каждом вызове бот сначала сканирует вперёд от последнего известного ID (до 50 ID, увеличено с 20 в v2.15.0), находя свежие посты до старого fallback-а.

- **Resilient error handling**: непредвиденные ошибки форварда больше не обрывают весь поиск — бот логирует и продолжает со следующим диапазоном.
- **Mock-safe checks**: `isinstance` вместо `getattr` для проверки Rich Message — корректно работает в тестах с MagicMock.

### Alan_Z: приветствие после сна (F7 v2 — Epic 11) 🆕
**Самая пассивно-агрессивная фича бота.** Если Алан **молчит** в чате дольше `ALAN_SILENCE_GREETING_HOURS` часов, а потом наконец пишет сообщение — бот встречает его приветственным видео. Как будто соскучился. На самом деле — просто фототропизм на движение.

**Как это работает:**
1. Бот запоминает timestamp каждого сообщения Алана в БД (переживает рестарт — память как у слона).
2. Перед каждым новым сообщением вычисляет `elapsed = сейчас − последнее_сообщение`.
3. Если elapsed ≥ N часов → «С ВОЗВРАЩЕНИЕМ!» через случайное видео.
4. Если Алан пишет слишком часто → таймер сбрасывается без приветствия (не заслужил).
5. Общий anti-spam с join-приветствием: если видео только что отправлено при входе — silence не дублирует.

**Зачем это нужно:** потому что наблюдать за реакцией Алана, когда бот «узнаёт» его после долгого отсутствия — бесценно.

| Переменная | По умолчанию | Что делает |
|-----------|-------------|-----------|
| `ALAN_SILENCE_GREETING_HOURS` | `6.0` | Часы молчания, после которых следующее сообщение триггерит видео. `0.5` = 30 мин, `0.0` = фича отключена. Требует перезапуска бота |

## 🖼 Как работают dead page и fallback

### Основной режим (канал жив)
1. Кто-то репостит из **@d_pages** → бот просыпается
2. Идёт в приватный канал, выбирает случайный пост, форвардит в чат
3. Всё одним сообщением, без разрывов. Магия.

### Fallback (канал мёртв / бота выгнали)
1. Бот берёт случайный `.jpg` и случайный `.txt` из `DEAD_PAGE_DIR`
2. Отправляет фото + подпись (до 1024 символов)
3. Если текста больше — второе сообщение с хвостом

Пополнение: кидай `.jpg` и `.txt` в `media/dead_page/`. Profit.

## 🐛 Исправлено в v2.12.1 (Epic 16)

### Epic 16: Bug Fixes — исправление двух критических багов

**Bug 1: Репостинг альбомов (DeadPageRelay)**
- **До**: для каждого фото в альбоме вызывался отдельный `forward_message`, что приводило к разрыву группы и дублированию.
- **После**: `_forward_with_heuristic()` переписан на **Collect-then-Group** — собирает все `message_id` одного альбома и делает **один** `forward_messages`. Альбомы пересылаются целиком, без разрывов.

**Bug 2: Propagation forwarded-сообщений к common_router**
- **До**: `war_channel_repost_handler` использовал `F.forward_origin` как propagation stopper, что блокировало **все** forwarded-сообщения от попадания в `common_router`. Danger Detection не срабатывал на репосты.
- **После**: **новый `TargetChannelFilter`** — проверяет только целевые каналы (ЧП Пермь, Радар БПЛА). Forwarded-сообщения из других источников свободно проходят к `common_router`, и Danger Detection работает корректно.

**DangerWordFilter: 22 → 187 слов**
- Словарь `DangerWordFilter` синхронизирован с `WarWordFilter.WAR_WORDS` — расширен с 22 до **187 словоформ**. Добавлены: склонения «ракетная/ракетной/ракетную», «обстрел/обстрелы/обстрелов», «сбит/сбита/сбито/сбиты», «падение/упал/упала», «эвакуация», «отбой» и др.

**Тесты: 372 → 387 (+15)**
- 6 тестов на альбомы (heuristic + DB path)
- 6 тестов на DangerWordFilter (caption, forward, no regression)
- 3 теста на propagation (war_alert + common_router interaction)
- Полный прогон: 387 тестов, 0 регрессий

## 🐛 Исправлено в v2.13.0 (Epic 17)

### Epic 17: Danger Word Fix — восстановление реакции на danger-слова

**Root Cause:** `war_alert_router` (позиция 4b) блокировал propagation сообщений от Славы, не давая `common_router` (позиция 4c) обработать danger-слова. `DangerWordFilter` и `WarWordFilter` содержат одинаковый словарь из 135+ слов — когда Слава пишет danger-слово, `war_alert_router` перехватывает сообщение и останавливает цепочку, не доходя до `common_router`.

**Исправления:**

## 🧠 Новое в v2.24.0 (Epic 26)

### GraphRAG: граф знаний — бот теперь помнит, кто кого назвал долбоёбом

Трёхуровневой памяти стало мало, и бот завёл себе **граф знаний** — таблицы `nodes` и `edges` прямо в SQLite. Серьёзные корпорации для этого берут Neo4j, но у нас корпораций нет.

**Как это работает:**
- **Entity extraction при архивации:** когда старые сообщения сжимаются в факты (L3), бот делает ещё один LLM-вызов через `deepseek-v4-flash` и извлекает **триплеты** — «кто с кем спорил», «кто кого жёстко оскорбил», «кто на чём фанатеет». Результат складывается в граф: участники и темы становятся узлами, связи — рёбрами.
- **Вес имеет значение:** повторное упоминание одной и той же связи не плодит дубликаты, а накачивает вес ребра. Да, у ваших конфликтов теперь есть вес. Буквально.
- **Гибридный поиск в `/summary`:** при генерации саммари бот сопоставляет участников и темы окна с узлами графа (без лишних LLM-вызовов, детерминированно) и подмешивает в промпт самые жирные связи в виде `[Историческая справка: Слава (жестко оскорбил) Костика]`. Саммари стало умнее, архив — цитируемее.
- **Граф не ломает ничего:** упал extraction, пустой граф или сущности не сматчились — секция справок просто исчезает из промпта, бот делает вид, что так и было. Узел не найден — fallback на топ рёбер всего чата.

**Настройка:**

| Переменная | По умолчанию | Что делает |
|-----------|-------------|-----------|
| `GRAPH_RAG_ENABLED` | `True` | Главный рубильник графа. `False` = аварийный выключатель: extraction при архивации не вызывается, поведение ровно как до фичи |
| `GRAPH_EDGE_WEIGHT_INCREMENT` | `1` | На сколько толстеет ребро при повторном упоминании связи |
| `GRAPH_TOP_EDGES_LIMIT` | `5` | Сколько рёбер-справок «[Историческая справка: …]» подмешивать в `/summary` |
| `GRAPH_EXTRACT_MAX_TRIPLETS` | `50` | Максимум триплетов, сохраняемых за один extraction-вызов |

**Исправлен P1-баг (T-206, pre-existing с Epic 24):** медиа без подписи не попадали в FTS-индекс (вставка под `if text:`), но FTS-удаление шло безусловно — при чистке старых сообщений SQLite выдавал «database disk image is malformed». Теперь удаление зеркалит условие вставки, и фото без подписи выпиливаются из памяти без членовредительства.

- **SmartModule:** если sqlite-vec на сервере не завёлся — бот молча переходит на FTS5-поиск архива. В логах будет WARNING, в чате никто ничего не заметит.
- **GraphRAG:** `GRAPH_RAG_ENABLED=False` — аварийный выключатель графа: extraction при архивации не вызывается, `/summary` работает ровно как до Epic 26. Справки из графа пропадают, граф остаётся лежать в БД как приятное воспоминание.
