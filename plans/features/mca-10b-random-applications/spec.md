## §1. Контракт ExplorationRequest/ExplorationResult (D1–D2)

**Место:** новый тонкий модуль `services/mca_exploration.py` — dataclasses `ExplorationRequest`/`ExplorationResult` + константы lifecycle/purposes + фасад над `ExplorationPolicy.choose` (10a reuse; `PolicyChoice` `mca_random_source.py:949–965`, `choose` `:987+`). Это контракт внутри текущего приложения: **новый агент, отдельный сервис, второй координатор и второй контракт 10a не создаются** (`:606`). Журнал переходов — `mca_events` (единый словарь); durable-состояние фоновых jobs — `task_jobs` (mca-01); read-only `random_metadata` в Decision — существующие закрытые ключи (`direct_chat_service.py:921–926`).

**Request:** `operation_id, chat_id, purpose, context_version, candidate_ids+versions, primary, eligible_alternatives, admission/exclusion grounds, probability, policy_version, requested_source`. **Result:** `selected, actual_source, draw_ids, fallback(+reason), explanation, outcome`. Поля — R17-safe (ID/коды/числа/refs; без сырого текста/секретов/CoT — прецедент mca-09 `:918`).

**Purposes — санкционированное расширение закрытого набора 10a** (в `EXPLORATION_PROBABILITY_KEYS`, `mca_random_source.py:79–83`; код прямо резервирует: «расширение имён — санкция 10b», `:73`; CA-10B-2):

| purpose | карта вероятности | точка гейта |
|---|---|---|
| `conversation_variant` | `memory.random_exploration_probability` | этап Decision (§3) |
| `memory_recall` | `memory.random_exploration_probability` | draw выбора истории внутри выбранного memory-кандидата (§3/§4) — не probability-гейт |
| `archive_sample` | `memory.random_sleep_exploration_probability` | после пакета сна (§5); draw периода/внутри job |
| `belief_review` | `memory.random_sleep_exploration_probability` | после пакета сна (§6); draw объекта review |
| `association_pair` | `memory.random_sleep_exploration_probability` | после пакета сна (§7); draw пары |

Probability-настроек **новых нет** — гейтов по-прежнему два (разговор / после сна), карта лишь связывает purpose с существующим ключом для валидации `choose()` и разделения статистики по purpose (`:608`). `POLICY_VERSION` потребителей — **`mca10b-v1`** (в журнале; константа 10a `mca_random_source.py:94` не переопределяется).
**`ui_replay` — НЕ purpose**: маркер read-only-режима витрины; в `choose()` отвергается как неизвестный purpose (существующая проверка `:1000–1003`), новых чисел не запрашивает (R5c). **`ui_visualization` — настройка `random.uses.*`, не purpose.**
**OFF-паритет:** до включения применений модуль не вызывается потребителями; `choose()` при существующих гейтах OFF возвращает primary с `disabled` — поведение 2.58.60 не меняется.

## §3. Один выбор в разговоре (`conversation_variant` + `memory_recall`, D3)

На этапе подготовки текущего Decision (mca-09) координатор формирует **общий пул целостных альтернативных кандидатов**: варианты из памяти (§4) + формы участия (§9), каждый — со своими story/episode refs, формой, основаниями допуска/исключения. Далее:

1. **Ровно одна проверка** `memory.random_exploration_probability` на conversation operation — `choose(primary, pool, purpose="conversation_variant")` (A29: не сумма независимых 5%).
2. При успехе — **ровно один целостный альтернативный кандидат**; воспоминание и форма внутри него повторных 5%-проверок не проходят.
3. Если выбранный кандидат — memory-история: **один дополнительный draw** равномерного выбора среди одинаково допустимых старых историй (purpose=`memory_recall`) — это draw корректной выборки, а не вторая probability-проверка и не «перекрутка» неудачного варианта (`:610`, `:616`, `:632`).
4. Пустой пул / нет допустимых альтернатив → primary + `no_eligible_alternative` (без draw); исход — обычный.
5. **LLM для набора альтернатив не вызывается** — только уже найденные материалы текущего этапа подготовки.
6. Проверка уместности/перед отправкой выполняется потребителем поверх выбранного — политика её не подменяет и не отключает (контракт `choose`, `mca_random_source.py:980–982`).

**OFF-паритет:** `MCA_RANDOM_USES_ENABLED=false` или `random.uses.conversation_variant=false` (или per-chat override) → пул не строится, choose не вызывается, реплика по primary-пути — бит-в-бит 2.58.60; в событии честный `disabled`/`not_run`.

## §4. `memory_recall` — неожиданные, но уместные воспоминания (D6)

- Кандидаты — только из MemoryRetrieval/EpisodeService через **`retrieve()`**; отбор **сначала релевантность** (тема/участники/допустимый статус источников), **затем разнообразие**; случайность не поднимает нерелевантную историю (`:630`).
- Признак допуска к разговору — отдельное поле результата, **порог привязан к версии ранжирования** (не универсальный cosine; `ARCHITECTURE.md` §99.4, `:630`).
- Хранить раздельно `last_retrieved_at` (любой retrieval, включая поиск во сне) и `last_used_in_chat_at` (только подтверждённая доставка в чат) — **2 аддитивные колонки v30 на `mca_episodes`** + индекс по `last_used_in_chat_at` (§13). Поиск во сне ≠ рассказ.
- Dedup повторов — по **canonical event ID** (EpisodeService + redirect-резолв): переформулировка того же события не обходит защиту; давность не свидетельство истинности (`:632`).
- Полный кандидат участвует в §3; отдельного триггера отправки нет. **Прямой запрос конкретной истории — обычный поиск** без exploration (измерение `direct_request` недопустимо, `:89–92`).
- Событие выбора: тема, выбранная история, когда последний раз использовали, альтернативы и причины исключения повторов. `delivery_unknown` (существующий код, `mca_events.py:68`) фиксируется отдельно и **подавляет немедленный повторный выбор** той же истории до разрешения статуса (A21-семантика).
- **Приёмка-якоря A30:** фиксированный draw → допустимая старая история; нерелевантная старая исключена; direct не заменён; перефраз распознан; `last_used_in_chat_at` обновляется только после подтверждённой доставки.

## §5. `archive_sample` — исследование забытых периодов (D7)

- Только **существующий resumable archive worker** (`task_jobs`); нового сканера/второй очереди нет. Карта покрытия — **v30 таблица `mca_archive_coverage`** (chat_id, period, msgs_total, verified_unique, episodes, last_explored_at, extractor_version): «нет истории» ≠ «не обработано» (`:646`).
- Выбор: непустые периоды → **нижняя группа по доле `verified_unique/msgs_total`** → **равномерный draw периода** (purpose=`archive_sample`) → допустимый непроверенный поддиапазон **по стабильным ID**, исключая диапазоны, занятые активными jobs (coalesce/unique v14). **Random OFFSET по всей таблице запрещён** (`:648`). Разбиение по календарным месяцам — стартовое; слишком большие периоды — поддиапазоны по стабильным ID.
- Job metadata: причина выбора периода, диапазон, покрытие, флаг «дополнительное исследование»; обычные checkpoint/source refs/версия экстрактора. Пустой результат **отмечает диапазон проверенным** (R7c).
- **Основной cursor не передвигается через непроверенные участки**; покрытие объединяется; пропуск — только подтверждённо выполненных совместимой версией участков (`:650`).
- **FIFO-приоритет основного прохода — by construction:** exploration-job — отдельный kind в `task_jobs`, который основной archive worker никогда не выбирает; он исполняется отдельным шагом после пакета сна и не вытесняет основную очередь (A31/R7d).
- «Всё покрыто» → дополнительное изучение только по установленной причине (пересмотр/новая версия экстрактора); без причины — job не создаётся (`:648`).
- **OFF-паритет:** флаг/настройка OFF → точка после пакета сна не создаёт archive_sample job; основной проход не меняется вообще.

## §6. `belief_review` — проверка убеждений (D8)

- База — DreamWorker + ProvenanceRepository (reuse). **Обязательная перепроверка изменённых источников — существующая обычная очередь, вне random, без изменений** (`:662`).
- Случайный review: активные убеждения с самым старым `last_reviewed_at` (NULLS FIRST), **исключая** уже ожидающие review и настроенное владельцем **ядро личности**; **один draw** объекта (purpose=`belief_review`).
- Книга отзывов — **v30 таблица `mca_belief_reviews`**: belief_id, chat_id, reviewed_at, `material_refs_hash` (хеш первичных материалов), outcome ∈ `kept|narrowed|split|disputed|replaced`, grounds (refs), reason_code.
- После выбора ищутся **и подтверждения, и опровержения**; поиск контрпримера — не задание «обязательно опровергнуть». **Вердикт — детерминированная оценка материалов** (случайность выбрала объект, не вердикт — R8c/A32). Отсутствие найденного контрпримера **не повышает уверенность** (не увеличивает confidence/счётчики).
- Исходы: оставить / сузить применимость / разделить периоды / пометить спорным / заменить новой версией. Пересмотр — **существующим write-путём mca-06** (прежний текст + новые основания + reason_code; коды пересмотра переиспользуются, напр. `superseded` — новых на пересмотр нет).
- **Защита от колебаний:** если `material_refs_hash` совпадает с последним review и нет новых обстоятельств → outcome=`kept`, версия убеждения не растёт, счётчик «улучшений» не увеличивается (reason `belief_review_unchanged`). Явные пользовательские правки — по существующим overrides.
- Событие «Убеждение проверено/уточнено» — в **существующей ленте убеждений** (до/после/исключения/источники). Участнику о каждом внутреннем пересмотре не объявляется.
- **OFF-паритет:** OFF → случайный review не выбирается; обязательная очередь и обычная работа сна — как в 2.58.60.

## §7. `association_pair` — необычные ассоциации (D9)

- EpisodeService предлагает **конечный набор пар (cap ≤ 8 за job)**: сторона A — актуальная тема/эпизод контекста сна (canonical ID), сторона B — из релевантного retrieval-пула (`retrieve()`), тематическая связь + подтверждённые источники + **разные canonical event ID**. **Декартов перебор запрещён; «две произвольные записи + LLM любой ценой» запрещены** (`:678`).
- **Один draw** выбора пары для рассмотрения (purpose=`association_pair`). Проверка связи — LLM-классификация (не random): `analogy|motif|contrast|continuation|insufficient` + короткое основание + **SourceRef обеих сторон**. Сходство не доказывает причинность/родство/тождество/намерение.
- Хранение — **v30 таблица `mca_associations`** (D5/§13): chat_id, link_type, `a_event_id+a_version`, `b_event_id+b_version`, status ∈ `candidate|accepted|rejected|stale`, basis, timestamps; индексы по (chat_id,status) и side-refs (инвалидация). Association — **отдельный тип производной интерпретации**: не в фактическом досье, не усиливает убеждение без отдельной проверки; `continuation` подтверждается **правилами EpisodeService** — автосклейки историй нет (`:682`).
- **Изменение любой стороны → `stale`** (по версиям; R9d/A33). Rejected-пара = кэш попытки по версиям сторон (та же пара на тех же версиях повторно не выбирается). Принятая ассоциация — **кандидат обычному координатору** (§2, CA-10B-3); **прямой отправки из worker нет**.
- Витрина: карточка «Найдена перекличка» (две истории, формулировка, статус, источники); неподтверждённое — гипотеза, не факт.
- **OFF-паритет:** OFF → job не создаётся; существующие истории/склейки не меняются.

## §9. `conversation_variant` — форма участия (D10)

- На этапе подготовки Decision формируются допустимые **communicative intent**: `observation/question/opinion/joke/recall/silence` — **семантика кандидата, не новая action-schema**; `reply/react/silent/tool` сохраняются (read-only reuse `COMMUNICATIVE_INTENTS`, `mca_intents.py:68`; CA-10B-1). Учитываются стиль персонажа, текущий тон, недавние свои формулировки; **не подгонять контекст под случайный тон** — непригодные формы не попадают в пул (напр. шутка при direct/техническом запросе — A34/R10b).
- Кандидат: коммуникативная цель, предполагаемая длина, предмет ответа, источники, ограничения стиля. Выбор — **в общей процедуре §3** (одна probability-проверка на решение; отдельного «стилевого броска» нет — R10d).
- Verbalizer получает выбранный смысл; редактор его сохраняет. Повторяющаяся фраза — обработка как повтор, **без постоянного жёсткого запрета слов** (`:698`).
- Раскрытие решения: «выбран уточняющий вопрос»/«короткое наблюдение» + исключённые с причинами; в чат — только естественная реплика без меток. **Direct-запрос не теряет смысл**; форма не меняет факты/адресата/действующие стилевые запреты.
- **OFF-паритет:** OFF → пул форм не строится, реплика по существующему primary-пути mca-09 — бит-в-бит 2.58.60.

## §10. Живая визуализация (§14.11, D11)

- **Расширение существующего блока «Источник случайности»** на «Статусе» (`status_service.random_source_snapshot:410` — уже read-only, «нет QRNG/LLM в статус-пути»; блок web/app.js UI_STATUS_GRID_V2). **Второго виджета, отдельного маршрута, новых routes нет** (Δ routes = 0; `ROUTES_SHA256_F11` не переутверждается).
- Данные — события exploration-журнала (`mca_events`) + Telemetry: purpose, разрешённый сокращённый контекст, кандидаты, **actual_source** (метка ANU/PRNG — фактический, не запрошенный), выбор, конечный исход **включая отклонение проверкой**. Обновления — **существующий механизм миниаппа** (event cursor/dedup), bounded history (последние 20 событий).
- Анимация **воспроизводит уже произошедшее** (подсветка 2+ вариантов → выбранный), не задерживает отправку; **новые QRNG/LLM-запросы при открытии/кадре/«Повторить» запрещены**; повтор помечен как повтор; при отсутствии событий — «Пока нет событий» (без имитации); если до exploration не дошло — не показывать как квантовый выбор.
- Пауза, reduced motion, мобильная компоновка, сохранение scroll/focus, текстовое представление — обязательны. Отказ визуализации **не влияет на координатор**.
- Права/chat scope: персональные детали кандидатов фильтруются текущими правами; наблюдателю без прав недоступны закрытые источники, ключ, сырой контекст (R17; прецедент snapshot-маскирования 10a).
- **Приёмка-якоря A35:** ID показанного события существует в журнале; source = actual_source; открытие/пауза/повтор — без внешних запросов и без изменения поведения бота; отклонённый кандидат не показан как отправленный ответ.
- **OFF-паритет:** `random.uses.ui_visualization=false` (или master OFF) → живая часть скрыта, остаётся статичный блок 10a; на координатор не влияет.

## §11. Наблюдаемость (D12)

- Процесс **`random.uses` v1** в `mca_process_registry` (code-declared, прецеденты `sleep.deep:167`, `random.source:596`, `intent.initiative:946`); стадии = lifecycle §1; master-гейт по прецеденту `:1044–1048`; widget-ID для строки матрицы **§27.1 `:1355`** («Случайность и её применения»: партия/draw, варианты, выбор, проверка, fallback, конечный результат) — контракт для mca-17c (рендер не здесь).

## §12. Настройки и kill-switches (D13)

- **Каталог (user-facing):** `random.uses.memory_recall / archive_sample / belief_review / association_pair / conversation_variant / ui_visualization` — 6 bool, **все true при первом релизе** (`:620`; §20.2 `:1019`); pg-ключи `memory.random_uses_*` в **существующей группе `memory_random`** (новых групп/вкладок нет); per-chat через `chat_params` (прецедент 10a, `chat_params.py:344`). Это **разрешения видов использования**: выключение одного не ломает остальные (R5e). **Игровой stub §14.12 в список активных потребителей не входит.**
- **Kill-switch (env-only, default ON):** `MCA_RANDOM_USES_ENABLED` — master 10b-поверхности (прецедент naming `MCA_RANDOM_*`/`MCA_INTENTS_ENABLED`); OFF → все применения не выполняются, честный `disabled`/`not_run`, существующие контуры (10a политика, mca-06 сон/dream-выборка, mca-09 Decision) работают как в 2.58.60. Эффективное разрешение применения = каталог AND master AND соответствующий существующий гейт (K1/K4) для probability-веток.
- **Per-purpose env-дубликатов нет** (F8 п.2, `arch-frames.md:171`: инфраструктурный контур — env-only; user-facing разрешения — каталог; mca-16-прецедент «kill-switches в каталоге НЕ дублируются», `param_catalog.py:2062–2063`).

## §13. САНКЦИИ (T-5049, поимённо)

1. **Δ DDL = additive v30 (≠ 0), через реестр mca-14 (`MigrationStep(30)`) + backup-guard fail-closed (прецедент 10a: полка `pre_migration_*.db`, read-back), PG no-op; v29 в проде не трогается:**

   - `CREATE TABLE mca_associations` (+idx `(chat_id,status)`, idx side-a/side-b refs);
   - `CREATE TABLE mca_archive_coverage` (+idx `(chat_id, period)`);

   **Обоснование Δ≠0:** (а) выбор «нижней группы покрытия» и «давно не проверявшихся» требует индексированных min/order-by выборок — на логе `mca_events`/одноразовых `task_jobs` это вырождается в сканы по 2M сообщений; (б) stale-инвалидация ассоциаций требует точечных lookups по side-ref+версии; (в) защита от колебаний требует durable `material_refs_hash` на belief. Контракт §1 и lifecycle в DDL **не** нуждаются: журнал — `mca_events`, jobs — `task_jobs`, conversation-исходы — `random_metadata` v22. **Взаимодействие с mca-22:** ассоциация — доменная v30-запись; всё отправленное, ссылающееся на неё, атрибутируется существующим `mca_bot_outputs` v22 (изменений mca-22 нет).
2. **Δ каталога ≠ 0 (F8 ADR-1026-2 обязателен):** REGISTRY 504→**510** (+6 bool `memory.random_uses_*`, группа `memory_random` — существующая); GROUPS **108** (0), `_TAB_BY_GROUP` **106** (0), TAB_RULES **21 in-place**; Settings +6, screen-map +6; secret-счётчик без изменений. **F8-переиздание полностью:** repin sha256 → regenerate TSV/meta/ScreenMap/widget-map → recount/дельта → обновить `tests/fixtures/round1025/f8_baseline.json` и ассерты (процедура `arch-frames.md:169–173`; инструмент — прецедент `tools/_extra_reissue_f8.py`, AM-4 ADR-1028-14). **Производные счётчики (delta-число) фиксировать по выводу F8-тула, не вручную** (урок errata 10a: ручной подсчёт «32→33» оказался неверным).
3. **Kill-switches — точный список (env-only, default ON, OFF = бит-в-бит 2.58.60):** ровно **один новый** — `MCA_RANDOM_USES_ENABLED`. Остальные гейты уже существуют и не дублируются: `MCA_RANDOM_SOURCE_ENABLED` (K1), `MCA_RANDOM_EXPLORATION_ENABLED` (K4), `MCA_DREAM_RANDOM_EXPLORE_ENABLED`. 4. **reason_code — аддитивно ровно +10 в единый `REASON_CODES` (`mca_events.py:60`), 237→247:** `exploration_accepted`, `exploration_rejected`, `exploration_deferred`, `exploration_failed`, `exploration_used_in_reply`, `exploration_stored_only`, `exploration_not_used`, `exploration_type_unavailable`, `association_stale`, `belief_review_unchanged`. Второго словаря причин нет.
5. **Risk R3 — подтверждён** (мульти-доменная поведенческая интеграция + DDL + F8 + фоновые jobs на большом архиве + UI-витрина); **`threat-failure-analysis.md` создан** (THR-1…THR-14) — обязателен к прочтению Builder'ом.
