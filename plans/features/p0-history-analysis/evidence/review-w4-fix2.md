## Блокеры

### A. При переполнении фона граница врёт: конспект назван дословным хвостом диапазона

- Владелец: Builder.
- Требование: REQ-HA-ISOLATION-SUPPLEMENTARY. Обещание этого фикса: баннер только над конспектом вне диапазона, дословные строки окна — после границы, «не подтверждает события» их не накрывает.
- Где: `services/direct_chat_service.py`, `_build_global_context`. Срез keep-head (около строк 9661–9666) оставляет в `head` только первую метку, всё остальное кладёт в `tail`. Новый блок (около 9674–9680) считает этот `tail` дословным хвостом окна и ставит перед ним `_HA_INRANGE_TAIL_LABEL`.
- Наблюдение: штатный потолок, без подмены лимита. Лог: `direct: global context truncated | tokens=32052 -> 4347`. Тело:

```
ДОПОЛНЕНИЕ ВНЕ ВЫБОРКИ hs_ab12cd34ef56: не подтверждает события внутри запрошенного диапазона.
фон: конспект из 100 сообщений, ниже дословно свежий хвост
фон: ниже — дословные сообщения запрошенного диапазона
CONSPECTUS_ALPHA out-of-range-memory ...
```

Дословной строки окна в блоке нет: её срезал `trim_verbatim_lines`, потому что конспект сам не влез. После границы лежит остаток конспекта. Фраза «не подтверждает события» накрывает только метку объёма.
- Влияние: когда фон длиннее потолка — а это штатная ветка усечения, не лабораторный лимит — модель читает старую память как дословные сообщения запрошенного диапазона. Изоляция переворачивается как раз на длинном конспекте.
- Почему тесты зелёные: `test_banner_on_conspect_only_in_range_lines_unlabeled` берёт короткий конспект, усечение не срабатывает. Порядок на коротком ходе верный. Это не доказательство переполнения.
- Правка: границу ставить только перед строками окна, которые были хвостом до схлопывания. Остаток конспекта остаётся под баннером, до границы. Если дословных строк после усечения не осталось — границы нет, весь остаток под баннером. Короткий ход не менять: баннер → конспект → граница → хвост.
- Перепроверка: тот же вызов `_build_global_context` с конспектом длиннее штатного потолка. Остаток конспекта до границы. Граница есть только если строка окна выжила, и тогда она после границы. Короткий ход, пустой хвост, ход без конспекта и без выборки — как в пробах 1.

### B. Срез короткой даты съедает более длинную дату, которую штамп подтвердил

- Владелец: Builder.
- Требование: REQ-HA-NO-INVENTED-STATS. Прошлая правка: срезать написание, которое нашёл детектор, и не трогать дату, которую подтверждает штамп ref.
- Где: `_ha_strip_invented_claims`, `cleaned.replace(str(value), " ")`. Детектор тут ни при чём: он возвращает точную подстроку и более длинную дату отдельно не помечает. Ломает сырой `replace` без границы токена. «5.10.2024» — хвост «15.10.2024» и «05.10.2024». «5.03.2025» — хвост «15.03.2025».
- Наблюдение: `_ha_guard_event`, штамп строки `15.10.2024`, note `15.10.2024 was real, but 5.10.2024 was not` → `note='1 was real, but was not'`, флаг `invented_date:5.10.2024`. Та же пара `15.03.2025` / `5.03.2025` при штампе 15.03.2025 → `note='1 was real, but was not'`. Если короткая выдуманная стоит раньше длинной выдуманной (`5.10.2024 and 15.10.2024 both invented`), длинная тоже не уходит целиком: `note='and 1 both invented'` при флаге `invented_date:5.10.2024,15.10.2024`.
- Влияние: Writer теряет дату, которую выборка подтвердила, и видит обрывок «1». Флаг говорит только о короткой дате, поэтому обрывок ничем не отменён.
- Почему тесты зелёные: каждая note содержит одну дату. Одиночные `5.10.2024`, `15.3.2025`, `5.3.2025` и прибитая `15.03.2025` срезаются верно. Это не доказательство соседства двух дат.
- Правка: заменять только целый токен даты, не сырую подстроку. Граница по цифре: короткое «5.10.2024» не должно попадать внутрь «15.10.2024» и «05.10.2024». Флаг оставить точным написанием. Одиночные формы не ослаблять.
- Перепроверка: note `15.10.2024 was real, but 5.10.2024 was not` при штампе 15.10.2024 сохраняет `15.10.2024`, теряет `5.10.2024`, флаг `invented_date:5.10.2024`. То же для `15.03.2025` / `5.03.2025`. `5.10.2024 and 15.10.2024 both invented` не оставляет цифру «1». Прежние одиночные пробы остаются зелёными.
