## 2. Источник данных: один, аддитивный

`loadCognitionGraph()` читает `GET /api/memory/cognitive-map` (S1) и
нормализует ответ адаптером (`normalizePayload`). Старый `/api/memory/graph`
виджетом **не запрашивается**; серверный контракт и маршрут `#/status/graph`
не тронуты (retirement — S4). Загрузка висит на существующем cognition-polling
(15 с), нового поллера нет. Данные не уходят в LLM/эмбеддинги: живой прогон
проверяет ДЕЛЬТУ сетевых запросов за показ/зум/фильтры/полный экран (§8).

Поле `cognitionGraphData` теперь хранит нормализованную модель (а не legacy
снимок) — этим же полем пользуется уже существующий каталог «Память»; его
раздел «Связи» адаптирован к `title`/`relation`/`derived` (выдуманных связей
по-прежнему нет).

## 3. Легенда — слова владельца

Источник формулировок — ТЗ, строка 1285: «Цвет/форма ↔ «Факты», «Убеждения»,
«Парадигмы», «Изменения»». Ровно эти четыре строки обязательны и
показываются всегда (`legendEntries().filter(required)`), в этом порядке.
«Эволюция характера» — заголовок секции лент (строка 1257), в легенду не
попадает (проверяется и в node-тесте, и в живом прогоне).

Различие не только цветом (строка 1280): у класса своя форма — круг (факты),
скруглённый квадрат (убеждения), шестиугольник и больший размер (парадигмы),
ромб (изменения). Токены — существующая палитра (topic/user/indigo/event),
новых цветов нет.

Вторичные классы (`Сущности`, `Наблюдения`) показываются отдельными
приглушёнными строками ТОЛЬКО если такие узлы реально есть в модели: иначе
пользователь видел бы необъяснимые серые/янтарные узлы. Обязательные четыре
строки они не подменяют и не переименовывают (помечены `required:false`).

## 4. «Показано X из Y» — нейтрально

Правило одно на узлы и рёбра (правка B1 в S1): строка включается, когда
`totals > shown` (после B1 это нормальное состояние почти любого реального
чата — снапшот берёт окрестность сидов и отбрасывает сирот). Никакой связи с
серверным `state='partial'`: `partial` не рисуется как тревога и вообще не
упоминается в UI.

Вид: серый `text-gray-500` (`rgb(162,176,198)` по замеру), без иконок,
янтарного/красного и слова «ошибка»; текст «показано 11 из 320 узлов · 6 из 40
связей». Формулировка собирается pure-функцией `completeness()` и проверяется
node-тестом (числа из payload, а не из `state`), pytest-ом (класс нейтрален,
нет `state === 'partial'` в разметке/коде) и живым прогоном (цвет + текст).

Обратная сторона правила тоже проверена: при полном наборе (`totals == shown`)
строки нет (e2e, оба вьюпорта).

## 5. Подписи, LOD, камера, раскладка

* **Слой подписей** — собственный (`nodes.font.size = 0` + событие
  `afterDrawing`), аллокатор — из S1 (`allocateLabels`): приоритет
  (выбранный → парадигма → убеждение → факт → сущность → наблюдение →
  изменение), экранное разрешение коллизий, отступ от кромки кадра.
* **Бюджет подписей из геометрии (§9.2)**: `budget = clamp(round(fill·W·H /
  boxArea), 4, cap)`, `boxArea` — средняя подпись через `measureLabel()`,
  `fill` = 0.05 desktop / 0.04 mobile, `cap` = 26/12 (жёсткие потолки). LOD —
  доля бюджета: `overview = min(budget, 6)`, `normal = min(budget, 16)`,
  `detail = budget`. Выбранный узел и парадигмы подписываются всегда (бюджет
  не ниже их числа), но не выше `cap`.
* **Кернинг по DPR**: канвас внутри имеет масштаб устройства, подписи
  рисуются в CSS-пикселях (`setTransform(ratio…)`), координаты — через
  `network.canvasToDOM`.
* **Semantic zoom**: колесо/pinch меняют масштаб, режим зума (far/medium/close,
  гистерезис) переключает детализацию подписей; данные не режутся.
* **Камера**: снимается на кадрах установившейся сцены, на
  `animationFinished` и перед сменой экрана (`_cogCaptureCamera`, защита от
  resize-пересчёта), восстанавливается `moveTo`; если камеры ещё нет (первый
  кадр, появление данных из пустоты) — `fit`. Полный экран и обратный переход
  дают ту же камеру/масштаб, выбор узла сохраняется (проверено на 390 и 1280,
  допуск 3 ед./0.08 — не менялся; сохранённая камера сверяется с установившейся
  отдельно, допуск 1.0 ед.).
* **Стабильная раскладка**: при обновлении данных DataSet обновляется
  локально (инстанс жив), позиции известных узлов переиспользуются, новые
  узлы встают рядом с реальным соседом (детерминированная спираль по хешу id,
  без `Math.random`); при возврате на экран физика не запускается вовсе, а при
  переходе 0 → N сцена пересобирается и подгоняется (`fit`).
* **Mobile-simple** — существующее поведение (`isMobileShell` без полного
  экрана): без перетаскивания узлов, мобильный потолок подписей 12, физика
  сразу off.
* **reduced-motion**: физика выключена, `moveTo`/`focus` без анимации,
  информативность (узлы/подписи/легенда/счётчики) сохраняется — проверено
  живым прогоном с `prefers-reduced-motion: reduce` (камера ставится сразу;
  контрольный прогон без reduced-motion показывает анимацию, т.е. проверка
  чувствительна).

## 6. Кластеры — только реальные связи

`computeClusters(model)` — связные компоненты по ПРИНЯТЫМ рёбрам (union-find,
корень = минимальный id). Никакой близости на экране, похожести названий или
LLM. Изолированный узел — честный кластер из одного узла. Подпись кластера:
«Парадигмы: <название>» при наличии реальной парадигмы, иначе
«<доминирующий класс> · N». Детерминизм: повторный прогон и порядок объектов
дают идентичный результат (node-тест).

Фильтр «Все кластеры» — витринный: сужает набор узлов/рёбер, не меняет данные,
не ходит в сеть и не сбрасывает камеру. На фикстуре: 5 кластеров на 11 узлов,
фильтр даёт 3 узла, камера сохраняется.

## 7. Состояния: две оси + ОДНА видимая строка (§9.1)

Оси раздельные (контракт §4): `state` описывает рендерер, серверный `state` —
факт о данных. Видимая пользователю строка одна: `notice` по «худшему факту»
(`renderer_failed` → `loading`/`not_loaded` → `degraded` → `empty` → `stale` →
`ready`). Поэтому «отказ источника» и «нет фактов» не могут висеть
одновременно.

| `state` (ось рендерера) | `notice.kind` | Что видит пользователь |
|---|---|---|
| `loading` | `loading` | «загрузка карты…» |
| `not_loaded` | `not_loaded` | «визуализация грузится — счётчики уже видны» |
| `renderer_failed` | `renderer_failed` | «визуализация недоступна — данные и счётчики сохранены» + «Открыть в Памяти» |
| `ready` | `degraded` | янтарная «часть источников не прочитана: …» + «Повторить» (рендерер работает) |
| `empty` | `empty` | «в этой области нет фактов и связей» + «Открыть в Памяти» (только при `degraded.active === false`) |
| `stale` | `stale` | «данные на HH:MM» + «Обновить» |
| `ready` | `ready` | строки статуса нет |
| любое (данные есть) | `ready` + пустая витрина | «по выбранному фильтру узлов нет» + «Сбросить фильтры» |

Клиентская ось считается `mapClientState()` — чистой функцией с `now` и
порогом на входе; `degraded` читается из `model.degraded.active`, а не из
строкового `state`. `partial` не является состоянием UI, а полнота
(«показано X из Y») независима от обеих осей.

## 9. Что найдено и исправлено попутно

**vis-инстанс в реактивных данных (реальный дефект старого виджета).**
Vue 3 заворачивает любой объект, прочитанный из экземпляра, в `reactive`-proxy;
методы vis-network обращаются к приватным полям классов, и вызов через proxy
падает с `TypeError: Cannot read private member…`. Воспроизведено на базе
`ba01c082`: в старом «Графе связей» `selectNodes([])`/`selectNodes([id])`
бросали исключение, т.е. кнопки **«Найти» и «Сбросить вид» в проде не
работали** (ошибка не доходила до UI). В S2 экземпляр сети и DataSet
закреплены через `Vue.markRaw` (`cogRaw`) — паритет контролов восстановлен,
а не «перенесён». Это же устраняет риск для карточки S3.

Прочее: подпись «Эволюция характера» к легенде не применялась (решение
Architect в S1-ревью); на телефоне контролы карты перестали занимать столбик
из пяти строк (L01312).

## 11. Исправления по ревью S2 (B1–B4) и их чувствительность

### B1. Переход «пусто → данные» врал и терял узлы

Причины и правки (все — по месту причины, допуски не менялись):

1. **`_cogView` нереактивен.** Введены реактивные поля `cogViewNodes` /
   `cogViewEdges` (`data`), они публикуются в начале и в конце
   `renderCognitionGraph`. Все computed читают только их:
   `cogClientState` (`_cogClientState` → `visibleNodes: this.cogViewNodes`),
   `cogFilterEmpty` (`this.cogViewNodes === 0`), плюс новый `cogViewCounters`
   («видно X из Y» при активном фильтре). `_cogView` остался внутренним слоем
   подписей и в computed не участвует.
2. **Сцена не пересобиралась.** Флаг `emptyToData = prevViewNodes === 0 &&
   view.nodes.length > 0` запрещает инкрементальный путь: сеть пересоздаётся,
   камера пустой сцены сбрасывается (`_cogCamera = null`), и после создания
   выполняется `fit`, а не восстановление несуществующего кадра.
3. **Сеть создавалась в скрытом контейнере.** Пока контейнер не измерен
   (`getBoundingClientRect` < 2 px) или ещё принадлежит прошлому экрану,
   рендер откладывается на следующий тик (не больше 8 попыток), а снимок
   камеры для 0×0 холста запрещён (`_cogDrawLabels` и `_cogInitializing`).
   Раньше «снимок» пустого кадра перекрывал `fit` — отсюда узлы за вьюпортом.
4. **Пустая витрина выдавалась за пустоту данных.** `visibleNodes === 0`
   больше не означает «нет фактов»: пустота данных (`dataEmpty`) отделена от
   пустоты вида (`viewEmpty`). Фильтр, скрывший всё, показывает «по выбранному
   фильтру узлов нет» + «видно 0 из 11 узлов», а не «нет фактов и связей».

Проверки: живой сценарий 0→N (`w15-cog-0-to-n-1280.png`): статус `ready`,
сообщений о пустоте нет, 11/11 узлов в кадре (`inside: 11`), 10 подписей;
живой сценарий «фильтр скрыл всё» (`w15-cog-filter-empty-1280.png`): блок
фильтра есть, блока пустоты нет, `state=ready`, счётчики данных «11 узлов»
и витрины «видно 0 из 11» согласованы; pytest-пины на реактивные поля,
`emptyToData` и разделение `dataEmpty`/`viewEmpty`.
Мутации → красные: «`emptyToData = false`» («0→N: видимых узлов 3 из 11
(fit не выполнен)», «0→N: подписей 2»), «`viewEmpty = false`» («фильтр скрыл
все узлы → отдельный факт вида (viewEmpty)»).

### B2. §9.1: «пусто» при отказе источника

`mapClientState` теперь считает ДВЕ вещи: `state` (ось рендерера) и `notice`
(единая видимая строка по «худшему факту»: `renderer_failed` →
`loading`/`not_loaded` → `degraded` → `empty` → `stale` → `ready`).
`emptyFact` принудительно `false`, пока `degraded.active === true`, поэтому
«нет фактов» не может скрыть непрочитанный источник. `degraded` определяется
по `model.degraded.active` (а не по строке `state`), список источников
отдаётся в `notice.sources`. В UI осталась ОДНА строка статуса
(`cogStatus` → `data-cog-state="<kind>"`, `data-cog-degraded` только у неё);
отдельный янтарный блок удалён.

Проверки: node-пины на приоритет и на `degraded+0`; живой сценарий
`degraded` с нулём узлов (`w15-cog-degraded-empty-1280.png`): видна одна
строка «часть источников не прочитана: memory_cycle», текста пустоты нет,
`data-cog-state="degraded"`, кнопка «Повторить».
Мутации (обе → красные): «убрать ветку degraded» → «§9.1: отказ источника —
видимая заметка, а не «пусто»»; «разрешить empty при отказе» → «§9.1: `empty`
запрещён, пока degraded.active === true».

### B3. §9.2: бюджет подписей из геометрии

`labelBudget()`: `budget = clamp(round(fill·W·H / boxArea), 4, cap)`;
`boxArea` — средняя подпись кандидатов через `measureLabel()` (ширина
`chars·0.55·fontSize`, высота `fontSize + padding`); `fill` = 0.05 desktop /
0.04 mobile; `cap` = 26/12 (значения `DEFAULTS` не менялись). LOD стал долей
бюджета: `overview = min(budget, 6)`, `normal = min(budget, 16)`,
`detail = budget`. Обязательные подписи (выбранный узел и парадигмы) поднимают
бюджет до своего числа — но не выше `cap`. Подпись обязана лежать в кадре с
отступом `padding` (иначе её срезает скругление сцены).

Приёмка в node (все способны упасть, см. мутации): монотонность по площади,
участие длины подписи, `4 ≤ budget ≤ cap`, `mobile < desktop` на одном кадре,
`fill` = 0.04/0.05, LOD-доли, обязательные подписи, отсутствие обрезанных
подписей. Измеренные бюджеты: 320×300 mobile → 4; 1000×400 → 7; 1440×900 → 22
(LOD `normal` → 16).
Мутации: «`raw = 0` (вернуть константу)», «fill = 0.05 всегда», «avgChars = 12
(длина не участвует)», «обязательные не поднимают бюджет» — каждая краснит
свой пункт.

### B4. Нестабильная проверка камеры

Причина проверки и правка: снимок камеры теперь делается и на
`net.on('animationFinished', …)` (в дополнение к кадру/`zoom`), поэтому
сохранённый кадр равен установившемуся. Сама проверка стенда больше не
сравнивает середину анимации с концом: перед переходом она ждёт
УСТАНОВИВШИЙСЯ кадр (`settled_view`), затем сверяет сохранённую приложением
камеру с установившейся (допуск 1.0 ед./0.02 — жёстче прежнего) и живой кадр
до/после полного экрана (допуск 3.0/0.08 — **не менялся**).

Честная оговорка: в Chromium снятие одного лишь `animationFinished`-снимка не
меняет сохранённую камеру (кадры отрисовки успевают снять установившийся вид) —
мутация «без animationFinished» остаётся зелёной. Нестабильность давала именно
гонка чтения «до» (середина 600-мс анимации в тяжёлом полном прогоне); она
устранена ожиданием установившегося кадра, а обработчик оставлен как гарантия
для платформ, где кадры после анимации не приходят (требование Architect).
Чувствительность проверки доказана другой мутацией: «при пересоздании сцены
всегда `fit`» → 4 красных пункта камеры (390 и 1280, вход и выход).

### Сводка мутаций этого прохода (все — красные)

| Мутация | Поймавший пункт |
|---|---|
| убрать ветку `degraded` из `notice` | §9.1: отказ источника — видимая заметка, а не «пусто» |
| разрешить `empty` при `degraded.active` | §9.1: `empty` запрещён при отказе |
| `viewEmpty = false` (фильтр-пусто как пустота данных) | фильтр скрыл все узлы → отдельный факт вида |
| LOD-константа вместо геометрии (`raw = 0`) | бюджет растёт с площадью кадра |
| `fill` без mobile/desktop | мобильная заливка 0.04 |
| длина подписи не участвует (`avgChars = 12`) | длина подписи уменьшает бюджет |
| обязательные не поднимают бюджет | бюджет поднят до числа обязательных |
| не отсекать подпись у кромки | подпись у самой кромки не рисуется |
| `emptyToData = false` | 0→N: видимых узлов 3 из 11 / подписей 2 |
| всегда `fit` вместо восстановления камеры | 4 пункта камеры (390 и 1280, вход и выход) |

Честно: мутация «убрать снимок на `animationFinished`» остаётся зелёной в
Chromium (кадры отрисовки успевают снять установившийся вид) — обработчик
оставлен как требование Architect и гарантия для платформ без кадров после
анимации; стабильность проверки обеспечена ожиданием установившегося кадра.

## 14. Что стоит решить до S3 (не блокирует S2)

1. **`degraded` и клиентское состояние — решено Architect §9.1** (этот проход
   реализует решение): ось рендерера (`state`) остаётся отдельной, видимая
   строка — `notice` по «худшему факту». Матрица сочетаний
   (`degraded+empty`, `degraded+stale`, `degraded+renderer_failed`) — S4.
2. **Плотность прода.** 26/12 остаются жёсткими потолками, а РАБОЧИЙ бюджет
   теперь из геометрии (§9.2): на прод-плотности (≈356 узлов) нужно измерить
   «нарисовано/скрыто» и долю площади — менять при необходимости LOD-доли, а не
   данные.
3. **Кластер как продуктовый фильтр.** Реальные компоненты на проде могут
   дать один большой кластер (связность памяти высокая). Тогда фильтр по
   кластеру будет малополезен — это вопрос S4 (нужен ли второй уровень:
   тема/участник), а не дефект S2.
