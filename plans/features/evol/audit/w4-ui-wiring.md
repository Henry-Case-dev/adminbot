## 3. Экраны и состояния

### 3.1 EVOL-019 — «Проверка распознавания» (модуль «Распознавание», вкладка «Модели»)

- Два РАЗНЫХ действия без дублирующего «Проверить»: существующая кнопка
  карточки подключения для Vision подписана «Проверить подключение»
  (`data-conn-test`; для остальных модулей подпись прежняя — «Проверить»),
  новая — «Проверить распознавание» (`data-vision-recognition-btn`). Подпись
  «платный вызов» видна ДО нажатия, после — «платный вызов выполнен».
- Раздельные шаги (`data-vision-state-step`): конфигурация / провайдер доступен /
  медиа принято / распознавание завершено / содержимое получено (+ символы).
  Плюс факты: причина (RU + код), безопасный образец, модель · провайдер · тип,
  длительность · время, готовность модуля с оговоркой, покрытие типов медиа.
- «Подтверждено» ставится ТОЛЬКО при `content_received && recognition_completed`
  (JS-проекция `visionRecognitionView`). 200 + не-JSON → `schema_invalid`,
  200 + пустой `content` → `content_empty`; оба показывают «не подтверждено» и
  красную/жёлтую рамку шага, а не зелёный статус.
- Результат обновляет ВИДИМЫЕ данные: карточку и живую линию модуля
  (`maybeLoadVisionState(true)` — обход 30-секундного кэша), а не только тост.
- Покрытие медиа честное: фото — «проверено этой проверкой», стикеры/GIF/видео —
  «не проверено» с причиной.
- Секретов в ответе нет (R17): ключ и `base_url` не попадают ни в JSON, ни в DOM
  (проверено и тестом, и живым прогоном).

### 3.2 EVOL-020 — цепочка опыта (Статус → карточка «Опыт»)

- Вместо «голых» чисел окон — компактная воронка из 8 стадий
  (`data-experience-stage`): подпись, серверное состояние
  (`working`/`idle`/`broken`/`disabled`/`stale`/`never_run` → RU-подпись),
  реальные `прогон:`/`успех:`/`всего:` и числа 24ч/7д/30д.
- Подписи состояний приходят С СЕРВЕРА (`state_label`): «Замечено — работает»,
  «Урок предложен — простаивает», «Проверка урока — не запускалось». Локального
  «работает» нет — в вёрстке нет ни одного жёсткого `>работает<`.
- Раскрытие причины — по одной стадии (`expStageOpen`): причины пропусков из
  событий, причины исключения уроков при отборе, ссылки на «Память» ТОЛЬКО при
  подтверждённых счётчиках (`total > 0`).
- Существующая компактная сводка 24ч/7д сохранена ниже (не ломает пины
  `data-experience-windows`), но перестала быть единственным представлением.
- Честность: `enabled=false` → прямая подпись «контур выключен — стадии
  показываются как «выключено», а не как «работает»».

### 3.3 EVOL-021 — эпизоды (Память → «Эпизоды»)

- Компактная лента (`data-episode-feed-items`): заголовок, 1–2 строки «что
  произошло», период события, чат, участники (+N), число связанных сообщений,
  полнота и проверка. Клик открывает карточку РОВНО этого эпизода (запрос по id,
  сервер отсекает чужой чат → 404).
- Карточка: читаемая история, участники, связь с сюжетом, «Технические детали»
  по требованию (`data-episode-tech`), кнопка «Открыть в памяти».
- «Открыть в памяти» ставит адрес `#/memory?episode=<id>` (`pushState` при
  нахождении в «Памяти», `replaceState` после перехода) и раскрывает карточку —
  ссылка копируемая и открывает ТОТ ЖЕ эпизод, а не общий каталог.
- Отдельная СВЁРНУТАЯ группа «Требуют восстановления» (`episodeRecoveryOpen:
  false`): реальная причина + затронутое число + статус
  (`восстановить нечего` / `ждёт пересборки`), грузится только при раскрытии.
- Честное пустое состояние с датой последней сборки; при отсутствии сборки —
  «Сборка эпизодов ещё не выполнялась».
- Старая техническая таблица сохранена под «Расширенный поиск (техническая
  таблица историй)» (`data-stories-advanced`): фильтры, keyset-пагинация и
  карточка истории не удалены.

### 3.4 EVOL-014 — мемы (модуль «Инициатива», вкладка «Основные настройки»)

- Своя ось `flags.meme_initiative_enabled` (тумблер `data-meme-toggle`) отдельно
  от текстовой инициативы; мастер модуля остаётся в каталоге — второго
  мастер-тумблера в блоке нет (в разметке нет `flags.initiative_enabled` и
  `toggleModule`).
- Поля: окно сообщений, квота в сутки (0 = выключено), кулдаун, минимум
  активности, модель выжимки (пусто — общая), тихие часы `HH:MM-HH:MM`, потолок
  длины; сохранение — per-chat override с объяснением, что глобальные значения
  не меняются.
- Квота: «Генерации сегодня: 1 / 3», «Осталось: 2», время сброса, часовой пояс +
  источник, отдельная пометка «схема квоты не применена — счётчик честно
  недоступен» при `schema_absent`.
- Аналитика отдельно от текстовой инициативы: стадии
  (рассмотрено/годно/выжимка/генерация/публикация/ошибка/пропуск), охват
  (журнал/память процесса/схемы нет) и причины пропусков с RU-подписями.
- Шаблон картинки: эффективный текст из реестра, признак «заводской/изменён
  вручную», ревизия; эффективный потолок длины + источник (явное
  переопределение / настройка администратора / возможности модели) + цель
  выжимки (считается ДО выжимки).
- Публикация/перепроверка: объяснение ворот и честный вывод «будет ли отправлено»
  (квота 0 / остаток 0 / функция недоступна / при прохождении ворот будет
  отправлено) + число заблокированных публикаций из журнала.
- Недоступность — конкретная причина (`initiative_disabled`,
  `disabled_by_setting`, `image_provider_not_configured`, `image_module_off`,
  `image_provider_unhealthy`, `schema_absent`), а не «не работает».

- Живой замер: на 390 и 1280 `documentElement.scrollWidth == innerWidth`,
  у всех четырёх блоков `right ≤ viewport` (переполнения нет), `console_errors=0`.

## 7. Остаточные риски и находки

### 7.1 Предсуществующий красный пин (НЕ этой волны)

`tests/test_webapp_api.py::TestParamPermissionFlagsApi::test_param_permissions_matrix_metadata_and_coverage`
падает на `f7a906e2` с `556 != 561`: каталог (`REGISTRY`) содержит 556

и `tests/test_webapp_api.py` в моём диффе отсутствуют; в каноническом репозитории
(более старый коммит) тест зелёный. Файлы вне моего write-scope — пин нужно
реквалифицировать владельцу каталога/пинов.

### 7.2 Грязные файлы другого лейна в рабочем дереве

На момент старта в worktree уже были незакоммиченные изменения НЕ моего лейна:
`services/experience_diagnostics.py` (+74: `selection_not_in_window`,
активация только по событию `activated`), `tests/test_evol020_experience_pipeline.py`

отображается без изменений UI.

### 7.3 Ограничения, зафиксированные честно

- Проверка распознавания — реальный платный вызов; UI это пишет и до, и после.
  В тестах сеть подменена транспортом (сервисный контракт покрыт отдельно).
- Покрытие медиа подтверждает только фото/PNG-фикстуру; остальные типы помечены
  «не проверено» — это не регресс, а честная граница проверки.
- Лента эпизодов и настройки мемов требуют выбранного чата: без него — честное
  «выберите чат» (мемы: 422 на сервере).
- Запись настроек мемов идёт per-chat override; в тестах резолвер значений
  подменён на профиль фейкового PG (в проде — `ChatParamsCache` + NOTIFY).
- `reason_details` в EVOL-020 — причины за 7 дней; окна 24ч/30д видны числами
  по стадиям (второй агрегатор причин не создавался).

## 8. Итог (RU)

Все четыре витрины подключены к уже принятым backend-контрактам, без нового
store и без второго мастера модуля. Главное правило волны соблюдено: нигде не
показывается «работает» без подтверждения — проверка распознавания разделяет
конфигурацию, доступность провайдера, принятие медиа, завершённость и полученное
содержимое (200 с неверной схемой честно показывается как «не подтверждено»),

### 9.2 Нит-1: «тихие часы» принимали несуществующее время

### 9.3 Нит-2: сохранение мемов материализовало ВСЕ поля как override

Было: `saveMemeSettings` слал весь черновик (`enabled`, `summarizer_model`,
`quiet_hours` всегда + все непустые числа), а POST пишет per-chat override —
после первого же сохранения чат терял наследование глобальных значений по этим
ключам.

Стало (`web/app.js`, тривиальная правка): тело собирается сравнением черновика
с фактическими `settings` из последнего GET (`length_limit` ↔ `length_admin`) —
уходят только изменённые поля; если не изменилось ничего, запрос не
отправляется вовсе (пустое тело сервер отклоняет 422 «нет изменений»), вместо
этого нейтральный тост. Снятие непустых `summarizer_model`/`quiet_hours`
по-прежнему выражается явной пустой строкой (пусто = наследовать).

Остаточное ограничение (честно, не блокер): числовые поля нельзя «очистить» —
пустой ввод не отправляется, поэтому снять ранее записанный числовой override
из UI нельзя (поведение не изменилось этой правкой; глобального редактора этих
ключей в продукте нет, практический эффект мал).

Регрессия — новый §6 в `tests/js/evol_w4_diagnostics_ui_test.js`: (а) без
изменений — тело не отправлено (`bodies === []`), (б) изменён один
`daily_limit` — уходит ровно `{daily_limit: 5}`, (в) снятие непустых
`summarizer_model`/`quiet_hours` — уходят явные пустые строки.
RED: против `web/app.js` из `HEAD` §6 падает (`deepStrictEqual`: уходит весь
черновик), PASS на кандидате — `EVOL-W4-UI-OK`.

### 9.4 Нит-3: семантика `activation.total` в EVOL-020 (для следующего лейна)

Не правил: `services/experience_diagnostics.py` вне моего write-scope. Суть для
следующего лейна: `activation.total` считает **активные уроки** (сколько уроков
сейчас в активном состоянии), а `windows.*` — **события активации** за окно
(сколько раз активировали). Это разные классы величин в одном ответе, и на
витрине они стоят рядом (`прогон:/успех:/всего:` + числа 24ч/7д/30д). Нужно
явно назвать класс в определениях серверных полей (`total` → например
`active_lessons`/`activation_events_total`) либо в подписи витрины; UI менять не
придётся, если сервер отдаст однозначное имя/подпись.
