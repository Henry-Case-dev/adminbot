## 2. EVOL-040 — единая модель источников настроек

### 2.1 Реестр (как он устроен)

Реестр не дублирует каталог: он выводится из уже существующих структур и
используется одинаково поиском, шапкой модуля и самими редакторами.

```
setting_id (pg key)
  canonical storage   → PostgreSQL settings ключ каталога (services/param_catalog.py)
  global default      → значение ключа в global scope (configItems[i].value)
  per-chat override   → chat_params.overrides (configItems[i].chat_source = 'chat')
  runtime consumer    → вкладка/группа каталога → модуль-потребитель (TABS.sources)
  UI entrypoint       → _settingDestination(): мастер → каталог, промпт → редактор
                        модуля, остальное → #/modules/<slug>/<tab> + ?focus=<key>
  права               → canViewTab/canEditConfig (сервер уже фильтрует configItems)
  dependencies        → module.toggleKey / parentGate / env-ось (read-only в UI)
```

Реализация: `_tabOfItem`, `_settingDestination`, `_settingRouteOf`, `_modelRouteOf`,
`paletteIndexEntries` (`web/app.js`). Один ключ = одна строка реестра; адрес
редактора вычисляется, а не хардкодится.

### 2.2 Найденное и устранённое дублирование (UI-сторона)

До W12 master-флаг модуля **рисовался дважды**: тумблер в карточке каталога
«Модули» (единственная запись, `toggleModule`) и такой же тумблер в деталях
модуля (`data-cfg-key="flags.*"` → `saveConfigItem`). Это две активные копии
одного ключа (запись шла в один ключ, но пользователь видел два «выключателя»).

Исправлено:
1. `_moduleViewGroup()` помечает master-ключ как `readonly_master` (детали →
   только состояние + ссылка «Управляется из каталога →»); ключи семантических
   групп «Инициативы» в generic-сетке не рендерятся вовсе.
2. Шаблоны модуля получили read-only ветку `item.readonly_master` (модалка
   «Параметры», вкладка «Основные настройки», расширенные настройки).
3. `saveConfigItem` отклоняет запись `readonly_master` с понятным сообщением —
   защита от обхода UI (например, старым обработчиком).
4. Поиск по master-ключу ведёт **в карточку каталога** (`data-focus-id="module-card:<id>"`),
   а не в read-only строку внутри модуля.

Master-ключи (реестр): `flags.summary_enabled`, `flags.direct_chat_botword_enabled`,
`flags.factcheck_enabled`, `flags.search_enabled`, `flags.enable_voice_transcription`,
`flags.video_summary_enabled`, `flags.download_enabled`, `flags.webpage_enabled`,
`flags.checkup_enabled`, `memory.dream_enabled`, `memory.nostalgia_enabled`,
`flags.budgets_enabled`, `flags.image_generation_module_enabled`, `flags.vision_enabled`,
`flags.initiative_enabled` (+ подмодули-персоны `flags.slavik_enabled` и т. п.).

Состояние и источник по-прежнему приходят из существующего store
(`getModuleState` → `configItems`), runtime остаётся единственным источником
истины; UI не пишет ничего нового.

## 3. EVOL-035 — truth table тумблеров «Инициативы»

Ключи (`services/param_catalog.py`, группы `flags_intent` / `limits_intent`)
не менялись; изменена только витрина и исключён второй редактор мастера.

| Ось | Ключ | Где в UI | Влияние |
| --- | --- | --- | --- |
| Мастер модуля | `flags.initiative_enabled` | карточка каталога «Модули» (единственная запись); в деталях — статус + ссылка | модуль работает/нет |
| Per-chat opt-in | `initiative.enabled` | «Инициатива в этом чате» (отдельная подписанная строка) | только выбранный чат |
| Автономная активность | `flags.initiative_observer_enabled`, `flags.intent_decision_enabled` | группа «Автономная активность» | наблюдение в обычных чатах, инициативные решения |
| Планирование | `flags.intent_heartbeat_enabled` | группа «Планирование и расписание» | фоновый тик due-скана |
| Безопасность | `flags.send_recheck_enabled`, `flags.initiative_diagnostics_publish_enabled` | «Дополнительно: предохранители и диагностика» | проверка на границе отправки; разрешение реальной публикации из диагностики |
| Диагностика | — (ссылки) | там же | воронка на «Статусе», журнал решений, «Проверить инициативу» |

Truth table (проверено тестом `tests/js/evol_w12_internals_test.js`, блок 8):
* ни один ключ не управляется двумя тумблерами (`Set(all).size === all.length`);
* master не входит ни в одну группу (только карточка каталога);
* per-chat не смешан с глобальными осями;
* включение «проверки перед отправкой» **не** включает реальную публикацию;
* публикация без мастера невозможна (дополнительно гарантируется бэкендом).

## 4. EVOL-037 — единый поиск/command palette

* Точки входа: desktop topbar (кнопка «Поиск» + `Ctrl/Cmd+K`), drawer (планшет/
  телефон), меню «⋯» (мобильный). Шапка на мобильном не раздувается: кнопка
  скрыта (`v-if="!hasDrawer"`), вход — в навигации/меню.
* Поведение: `Ctrl+K` открывает, `Esc` закрывает первым слоем (до модалок),
  обычный ввод не перехватывается (хоткей требует модификатор), `↑/↓`/`Enter`
  работают, клик/`Enter` открывает результат.
* Реестр: разделы (`TABS`), модули и **их подразделы** (`MODULES[].tabs`),
  области «Речи и характера», настройки/поля (`configItems` с реальным ключом),
  промпты (категория `prompts`), модели/подключения (`PROVIDER_BLOCKS`),
  объекты данных/аналитики (статический список адресов разделов). Новых списков
  названий модулей нет.
* Группы: `Разделы / Модули / Настройки / Промпты / Модели / Данные` — порядок
  фиксирован, внутри — по релевантности.
* Переход: `#/...?focus=<токен>` — общий deep-link. Фокус ищет
  `[data-focus-id="…"]` → `[data-cfg-key="…"]`, раскрывает `<details>`,
  прокручивает к центру, ставит фокус и кратко подсвечивает (`1.6 c`,
  `prefers-reduced-motion` — статичная рамка). Повторный выбор того же адреса
  тоже фокусирует (hashchange молчит).
* RBAC: разделы/модули фильтруются `canViewTab`/kill-switch, «Аналитика» — только
  `isGlobalAdmin`; сервер по-прежнему фильтрует `configItems`. Секреты и ключи
  API (`item.secret`, `category === 'keys'`) **не индексируются**; поиск не
  вызывает ни сервер, ни LLM.
* Мобильный лист: полноэкранный, `env(safe-area-inset-*)`, высота ограничена
  `--vv-h`/`--kb-offset` (клавиатура), непрозрачная поверхность `--surface-1`.

## 5. EVOL-038/039 — промпты и подключения

* Каталог промптов модуля: поиск по названию/ключу/описанию (`promptTreeGroups`),
  всегда **один** выбранный промпт (master-detail), пустая выдача объясняется.
* Мета редактора: `prompt_id`, потребитель (модуль), scope (источник значения),
  активная версия и время последнего изменения (из существующего журнала версий).
* Полноэкранный режим — тот же объект/та же история (никакой второй формы),
  выход по Esc/повторной кнопке.
* Конфликт версий: при `saveState === 'conflict'` редактор показывает остановку
  сохранения и «Обновить и сравнить» (существующая машина состояний 409).
* Подключения: в карточке отдельно «Соединение (HTTP/API): успешно/ошибка + время»
  и «Функция: …». Функциональная проверка показывается только там, где она
  реально существует (vision, генерация изображений, пайплайн Direct), иначе —
  прямо сказано, что её нет (доступность API не равна работающей функции).
  Секреты остаются замаскированными, проверки не отправляют сообщения в Telegram.

## 6. EVOL-041/042 — «Речь и характер» и Effective Prompt Inspector

* Навигация по задачам: `Обзор · Характер · Манера речи · Юмор · Опыт и обучение ·
  Как собирается ответ` — это переходы в существующие секции (не второй набор
  настроек), один экран за раз.
* Второй дубль «Личности» удалён; редактор личности остался один, deep-link
  `#/ai/persona` и палитра фокусируют именно его.
* Инспектор: сегмент «Последний реальный вызов» / «Предпросмотр».
  * реальный режим: только подтверждённый снимок; при его отсутствии — карточка
    «Нет подтверждённого снимка» и кнопка «Предпросмотр (не отправлено)»;
  * режим предпросмотра: жёлтая плашка «НЕ отправлено», сборка локальная;
  * карточка «Полный итоговый промпт»/«Фактически отправленный payload» больше
    не показывается там, где нет подтверждённого снимка.

## 8. Остаточные риски и посторонние находки

1. **Тестовая книга**: `tests/js/round1021_ui_audit_test.js` («28 вкладок» vs 27)
   и `tests/js/round1025_ia_routing_test.js` («Личность осталась в ИИ») падают
   **до** этой волны — проверено на чистом checkout HEAD (`w12-baseline`).
   Каталог/навигация здесь не менялись.
2. `tests/test_soul1_w6_speech_ui.py` (3 теста) падает на HEAD (ожидает старую
   композицию секций речи); W12 её не усугубляет — в живом Chromium все шесть
   областей и редактор на месте.
3. Мастер-флаг, убранный из generic-сетки, теперь доступен только в каталоге —
   это и есть требование EVOL-040; вкладка «Основные настройки» модуля, где не
   осталось других ключей, может не отображаться (пустых вкладок не рисуем).
4. Проверка соединения не заменяет функциональную: для подключений без
   функционального теста интерфейс прямо говорит об этом, а не показывает
   «успех». Это осознанное поведение, а не незакрытая часть.
5. Живые Telegram-сообщения не отправлялись; проверки выполнялись на локальном
   стенде с заглушками API.
