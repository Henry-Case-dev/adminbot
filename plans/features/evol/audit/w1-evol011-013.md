### Разделение исходов (требование «разделить terminal failure / unsupported / pending / cancel / timeout…»)

| Ситуация | outcome | level | reason_code | Носитель детали |
|---|---|---|---|---|
| `ready` / `no_text` | `success` | INFO | — (не ставится) | — (контракт прежний) |
| HTTP 200, payload не JSON | `failed` | WARN | `parse_error` | `error_json.error=""`, honest «нет исключения» |
| HTTP 200, пустой content | `failed` | WARN | `empty_content` | — |
| Транспортный таймаут провайдера | `failed` | WARN | `vision_unavailable` | `error_json.detail="VisionError: timeout"` |
| Исчерпание бюджета адаптива (wait_for) | `failed` | WARN | `timeout` | класс `TimeoutError` |
| 429 / 401/403 / прочие не-2xx | `failed` | WARN | `vision_rate_limited` / `vision_unavailable` / `vision_failed` | `error_json.detail="…http_<status>…"` |
| Отмена (CancelledError) | `cancelled` | INFO | — | `error_json.error="CancelledError"` |
| Иное исключение (например NameError) | `failed` | WARN | — (код НЕ выдумывается) | `error_json.error` = класс, `detail` = класс+сообщение |
| `unreadable`/`unsupported`/`unavailable` через merged-анализ | `failed` | WARN | по существующему `_reason_by_status` | — (в adaptive-пути недостижимы, покрыто defensively) |

Событие `vision_adapt` остаётся в едином контракте `mca_events.build_event`
(outcome из фиксированного набора, `reason_code` через whitelist — новый код
`empty_content` добавлен именно туда, параллельный словарь не заводился).
`pending` в adaptive-пути не возникает (это статус durable-гранулы/джобы выше
по конвейеру) — выдумывать для него исход в `_emit_adapt` не требовалось.
