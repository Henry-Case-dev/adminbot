## 1. EVOL-026 — «Статус» и «Аналитика» разведены по смыслу

**Переносы (ровно один экземпляр каждого виджета):**

| виджет | было | стало |
|---|---|---|
| «Активность по часам» (heatmap) | «Аналитика» → «Обзор» | **«Статус»** (`data-viz-heatmap`, `data-status-activity`) |
| «Живая лента досье» | «Аналитика» → «Обзор» | **«Статус»** (`data-status-dossier`) |
| «Истории памяти» (полный) | «Статус» | **«Аналитика» → «Память и интеллект»** (`data-stories-analytics`, лента `data-stories-feed`) |
| «Истории памяти» (превью) | — | **«Статус»**: счётчики + 3 последних события + «Показать всё →» (`data-stories-preview`) |

**Подача «Статуса» — живой дашборд без неконтролируемой высоты:** heatmap
`max-height: 240px` (200 на ≤480 px), лента досье `max-height: 132px`,
превью историй — список из 3 строк. Данные не «прыгают»: значения берутся из
кэша `/api/analytics/viz/activity` (60 с) и `/api/oversight/dossier_feed` (45 с).

**Heatmap стал интерактивным и читаемым:**
* каждая ячейка — настоящая `<button>` с `aria-label`/`title` полного значения
  (`дддд-мм-дд чч:00 — событий: N (ошибок: M)`), `tabindex=0` только у ячеек с
  данными, `aria-pressed` для выбранной;
* hover + touch + клавиатура: Enter/Space выбирает час, стрелки ←→↑↓ двигают
  выбор (`vizHeatStep`), фокус переходит на новую ячейку;
* **читаемая легенда**: шкала 5 уровней + «точка — были ошибки»;
* **правильная временная зона**: подпись берётся из поля `timezone` ответа
  (`vizHeatTzLabel` → «время сервера»), без догадок о зоне браузера;
* выбранный час разворачивается строкой «дддд-мм-дд, чч:00–чч:00 · событий: N ·
  с ошибками: M» и кнопкой **«Показать события →»**, которая ведёт в
  «Аналитику → Запуски» с подписью выбранного часа (`oversightFocusNote`) —
  серверного фильтра по часу нет, поэтому период не выдумывается.

**Лента досье:** сущность, чат-контекст, excerpt + строка «запись досье ·
дата/время · источник: сообщение N», разворот записи тем же
`openFeedDossier` (клик/Enter/Space). Подпись свежести — **реальное** время
загрузки (`dossierFeedStamp`: «данные от 11:50» / «ещё не загружено» /
«не удалось загрузить · последние данные от …»), фиктивного «обновляется» нет.

**Routing/deeplinks/scope:** новых маршрутов нет. `vizLoadActivity` и
`startDossierFeedPolling` включены на входе в «Статус», на входе в «Аналитику»
досье-поллер останавливается (двойного поллера нет). Полный виджет историй
грузится на суб-вкладке «Память и интеллект» (`oversightTabEnter('memory')`).
Кнопка «Открыть таблицу в «Памяти»» и адресное открытие эпизода не менялись.
Роль-чек прежний: оба экрана — global admin (`canViewTab('oversight')`).

**«Аналитика»:** у списка «Запуски» появилась подпись реальных фильтров
(`data-runs-filter-meta`: статус/компонент/тип/chat_id/период), поля получили
`aria-label`. Технические поля (`trace_ids`, `reason_code`, `pipeline_run_id`)
не удалены — они остаются в детали прогона/стадии.

## 2. EVOL-027 — каталог модулей и карточки (v0.7 + v0.8)

**v0.7 — глобальный тумблер остаётся на карточке.** Карточка каталога теперь
имеет два раздельных, подписанных контрола:
* **«Глобально <включён/выключен/неизвестно>»** — `data-module-global-toggle`,
  немедленно выполняет штатную серверную операцию `setModuleGlobalState(m, on)`
  → `persistItems([{key, value, per_chat:false}])` (глобальный write-path, без
  X-Chat-Id, **без перехода в «Настроить»**). Отдельное пространство операции
  (`moduleGlobalOptimistic/Pending/Error`, ключ `global/null/<id>`), поэтому
  глобальное действие не путается с чатовым override и не подменяет его.
  Есть pending, откат к серверному значению при отказе, сообщение
  «Не удалось изменить глобально», защита от повторного тапа (`skipped: true`)
  и подтверждение сервером через повторное чтение конфигурации.
* **«В этом чате <включён/выключен>»** — `data-module-chat-toggle`, только для
  модулей, у которых локальное значение реально читается runtime
  (`runtimeGate === 'per_chat'`). Для global-only модулей вместо тумблера —
  строка «В этом чате · управляется глобально <состояние>».
* Явно показаны **глобальное состояние, эффективное состояние области и
  источник отличия** (`moduleEffectiveLine`: «Для этой области: включён ·
  источник: своё значение для чата»).
* Когда прав нет — контрол disabled и написано «только чтение (нет прав global
  admin)»; chat-only действие не выдаётся за глобальное.

**v0.8 — убрана тяжёлая KPI-строка** «20 всего / 18 включено / …»
(`.module-counters` удалён). Вместо неё подпись списка
(`data-module-caption`): «Показано N из M · фильтр активен · здоровье
показывается там, где для модуля есть данные». Быстрые фильтры
`Включённые / Выключенные / Проблемы / Избранное` сохранены.

**Дублирующий master-toggle в деталях исключён:**
* модалка `#/modules/<slug>` больше не содержит тумблера — только read-only
  статус (`data-module-readonly-status`) и пояснение «Управляется из каталога»
  (`data-module-managed-hint`);
* шапка страницы модуля — read-only статус + ссылка
  `data-module-managed-link` → «Управляется из каталога →» (возврат в каталог).
  Независимые оси модуля (свои лимиты/предохранители, EVOL-035/040) не тронуты.

**`enabled` ≠ `healthy`:** здоровье показывается отдельной строкой только по
реальным данным подсистем (`moduleHealthView`: Vision / Сон / Опыт через
существующие health-источники), с временем наблюдения; у модулей без health-оси
блока нет — «включён» никогда не выдаётся за «работает».

## 3. EVOL-028 — «ИИ» как рабочая панель; личность переехала в «Речь и характер»

**Панель `#/ai`** (`data-ai-hub`) вместо витрины ссылок:
1. **«Модели и подключение»** (`data-ai-models`) — реальные
   `/api/status.llm` по ролям (`module_title`) с провайдером, моделью и её
   источником, состоянием ключа и **health соединения**; рядом честная подпись
   «проверка соединения · не проверка работы функции» + пояснение, что
   функциональная проверка — в «Моделях и подключениях» (кнопка «Проверить»).
2. **«Речь и характер»** (`data-ai-speech`) — область, чем является раздел, и
   две двери: «Открыть редактор» и **«Личность и характер →»**
   (`data-ai-persona-link`) — deep-link в секцию личности того же редактора.
3. **«Имена и алиасы»** (`data-ai-names`).
4. **«Библиотека промптов»** (`data-ai-prompts`) — число промптов/семейств/с
   версиями из существующего `/api/prompts/catalog` (`aiPromptCountsLabel`,
   честные состояния «каталог загружается/недоступен/пуст»), и подпись, что
   активная ревизия, заводская версия и диффы — в карточке промпта каталога
   (второй библиотеки нет). Плюс честная строка: **кеш готовых ответов выведен
   из эксплуатации, управляющих настроек кеша ответов в интерфейсе нет**
   (`Умный кэш` в навигации отсутствует).

**v0.8 — «Личность и стиль» переехала в «Речь и характер»:**
* карточка «Личность и стиль» удалена из `HUBS_V2['#/ai']` (осталось 3
  страницы: промпты, модели, имена; вход в «Речь и характер» — отдельная строка
  хаба);
* форма личности (имя, биография, характер, «осознаёт себя ИИ») физически
  живёт в `#/ai/speech` как секция **`#speech-persona`** — с теми же полями,
  `personaDraft/savePersona/resetPersona`, scope-бейджами и сбросом override;
  ветка `activeTab === 'persona'` удалена (второго редактора нет);
* `#/ai/persona` остаётся рабочим адресом: `ROUTE_TO_TAB['#/ai/persona'] =
  'speech'`, при переходе секция личности открывается и получает фокус;
  `ROUTE_PARENT` не изменился (назад → `#/ai`);
* при входе в «Речь и характер» догружается `loadPersona()` (данные того же
  scope), поэтому форма не пустая.

## 4. EVOL-029 — «Память» как читаемый каталог знаний

Стартовый экран `#/memory` (`data-memory-catalog`) вместо «приборной панели»:
* **поиск человеческим текстом** (`data-memory-search`) по названию, содержанию
  и метаданным;
* **типы знаний по реальной модели данных**: `Факты` (записи досье,
  `/api/oversight/dossier_feed`), `Люди` (участники чата,
  `/api/chat_lore/{chat}/relations`), `Связи` (рёбра `/api/memory/graph`),
  `Контекст` (убеждения/парадигмы, `/api/memory/dream/beliefs`), `Эпизоды`
  (`/api/episodes/feed`); у каждого типа честный счётчик;
* **карточка записи**: человеческое содержание, тип, когда получено, чат,
  степень подтверждения/полноты, участники/сообщения; клик открывает
  существующее окно записи (`openStatusRecord` — источники, соседние связи,
  изменения, трасса/цепочка) или адресную карточку эпизода (`openEpisodeCard`);
* **«Диагностика / расширенный режим»** (`data-memory-diagnostics`): доступность
  поиска по смыслу (провайдер эмбеддингов/индексы), счётчики памяти и графа,
  ссылки на «Настройки памяти» (фильтры/индексы/технические параметры),
  «Люди и связи» и таблицу историй; сырые ID — в открытом окне записи;
* **никакого выдуманного прошлого**: где данных нет, выводится реальная причина
  («дата записи неизвестна», «краткое описание не восстановлено — причина в
  карточке эпизода»);
* адресное открытие эпизодов в «Памяти» сохранено (это разрешено прямо), второй
  независимый продукт «истории» там не живёт — полный обзор в «Аналитике».

## 5. EVOL-030 — «Доступы», матрица на mobile, аналитика, второстепенные экраны

**«Доступы»** (`data-access-summary` на стартовом `#/access`): вместо трёх
гигантских плиток — краткая **сводка** (роли, администраторы чата, число
параметров матрицы, область, роль, напоминание «права проверяются на сервере
(RBAC)») и **разделы** (`data-access-section`): «Матрица прав»,
«Администраторы чата», «Роли и пользователи» — каждый открывает существующее
route-driven окно (`#/access/roles|local|admins`, deep-link/BackButton целы).
Подмаршруты получили строку «← Все разделы доступов».

**Матрица прав на mobile** — новая модель «сущность → доступные права →
эффективные роли»: у строки появился блок `data-matrix-effective` («Читают: …»,
«Меняют: …», вычисляется из реальных `view_roles`/`edit_roles`; без прав —
«только глобальный админ»), видимый только на узком экране (`.matrix-perm-summary`),
таблица на desktop не менялась. Перед изменениями видны scope, эффект и
наследование; права скрыты/запрещены на сервере, а не только визуально.

**«Аналитика»**: подпись активных фильтров и `aria-label` на полях «Запусков»
(см. §1), технические поля и drilldown/deeplinks сохранены.

**Прочие экраны** (справка, PERMsoc, профили, провайдеры/ключи, подтверждения,
пустые/ошибочные состояния, поповеры, галереи, кнопки, логи, статусные карточки)
— проверены «сквозным» инвентарём вьюпортов и живым осмотром: новых «второсортных»
рамок/кнопок не добавлено, стили идут через существующие токены EVOL-022/033 §A,
пустые состояния остались честными («Бюджет недоступен», «Нет данных»,
«прогонов пока нет»).

## 10. Остаточные риски и честные пробелы

1. **Серверного фильтра по часу нет.** Переход «Показать события» из heatmap
   открывает «Запуски» с периодом и подписью выбранного часа; фильтр по
   конкретному часу — отдельная серверная работа (в UI не имитируется).
2. **`global_value` в чатовой области.** Глобальное состояние на карточке
   читается из `global_value` ответа `/api/config`; если сервер его не отдаёт
   (например, ключ не установлен в глобальном слое), карточка честно пишет
   «неизвестно», а не «выключено». Живой стенд (стабы) показывает «неизвестно»
   именно по этой причине.
3. **Здоровье модулей.** Отдельная строка здоровья есть только там, где у
   подсистемы реально есть health-источник (Vision/Сон/Опыт). Для остальных
   модулей её нет — это осознанно: `enabled` не выдаётся за `healthy`.
4. **WEBP/большие данные памяти.** Каталог памяти строит выборку из уже
   загруженных источников и ограничивает список 60 видимыми записями (с
   подсказкой уточнить запрос); полноценный серверный поиск по знаниям —
   отдельная задача (новых API эта волна не вводила).
5. **Живой Telegram WebView** (Android/iOS, поворот, крупный системный шрифт)
   агенту недоступен; покрытие — детерминированные вьюпорты + реальный Chrome.
6. **Скриншоты живого осмотра.** Часть кадров реального браузера не сохранилась
   из-за таймаутов CDP-хелпера (см. §7); сохранены только проверенные кадры.

## Коротко по-русски

«Статус» и «Аналитика» больше не дублируют друг друга: интерактивная
«Активность по часам» (с легендой, правильной зоной времени, выбором часа
мышью, пальцем и клавиатурой) и «Живая лента досье» (сущность, чат, время,
источник, разворот записи) переехали в «Статус», а полный виджет «Истории
памяти» с лентой, фильтром по проблемным исходам и реальными причинами
невосстановления — в «Аналитику»; в «Статусе» осталось короткое превью с
«Показать всё». Каталог модулей стал ровным: у каждой карточки прямо на месте
есть подписанный глобальный тумблер (сразу выполняет серверную операцию, с
подтверждением, откатом и защитой от двойного клика) и отдельный чатовый
переключатель, видно глобальное и эффективное состояние с источником отличия,
а тяжёлая строка «20/18/1/1» убрана — вместо неё подпись «Показано N из M».
Второй мастер-тумблер из деталей модуля убран: там только статус и ссылка
«Управляется из каталога». «ИИ» стал рабочей панелью: текущие модели по ролям
и состояние соединения (отдельно от функциональной проверки), входы в «Речь и
характер» и «Имена», число промптов с версиями; «Личность и стиль» больше не
отдельный пункт — форма личности живёт секцией в «Речи и характере», а старый
адрес ведёт туда же. «Память» — читаемый каталог знаний: поиск обычным текстом,
типы (факты/люди/связи/контекст/эпизоды) по реальным данным, человеческие
карточки с датой, источником и подтверждением, а ID/индексы/debug — в
«Диагностике». «Доступы» начинаются со сводки и трёх понятных разделов, матрица
прав на телефоне показывает «сущность → права → эффективные роли». Оптика
(жидкое стекло, преломление, полигональный фон) не тронута. Новые 27 тестов
зелёные, сквозной Playwright-прогон по шести экранам и двум размерам — OK, все
обязательные наборы зелёные; пять падающих UI-тестов — предсуществующие и
воспроизводятся на базе. Честные пробелы: нет серверного фильтра по часу у
heatmap, настоящий Telegram WebView и часть кадров живого осмотра — за
пределами доступного агенту.
