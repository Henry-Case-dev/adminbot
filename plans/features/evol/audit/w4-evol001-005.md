## 2. EVOL-001 — одна система строк на четыре источника

Четыре виджета («Новые факты», «Убеждения (Сон)», «Парадигмы (Глубокий сон)»,
«Эволюция характера (Личность)») переведены на один набор классов:

- `.sfeed-viewport` — окно (`--sfeed-h: 168px` для всех четырёх),
  `.sfeed-track` — список, `.sfeed-item` — строка (`height: var(--sfeed-row-h)`
  = 64 px **у всех**, без «прыгающей» высоты), `.sfeed-item__head`,
  `__badge`, `__subject`, `__date`, `__text`, `.sfeed-empty`.
- Общее: фон `rgba(10,14,22,.45)`, hairline `rgba(255,255,255,.08)`,
  радиус `var(--radius-md)`, паддинг `6px 8px`, шрифт `.78rem`,
  затухающие границы окна (маска 8 px), подсветка активности
  (`[data-sfeed-active="1"]` — строка в центре окна, ровно одна на ленту),
  одинаковый transition. Токены ритма — из слоя EVOL-022.
- Различие источников — **только бейдж/подпись раздела** (оттенок:
  факт — teal, убеждение — violet, парадигма — blue, черта — amber) и
  названия разделов сохранены.
- Длинный текст: строка — **одна кнопка** (`<button class="sfeed-item">`),
  кликабельна вся площадь; визуально 2 строки (line-clamp), но полный текст
  открывается в окне записи — обрезанного «кликабельного хвоста» больше нет.
- Стекло не затронуто: в правилах строки нет `backdrop-filter`, `z-index`,
  `position:absolute`, `url(#lg…)` — тест это утверждает.

## 3. EVOL-002 — авто-движение + полноценная ручная прокрутка

Legacy-механизм (`@keyframes ribbon-scroll` + `translateY(-50%)` + дублирование
строк) заменён **реальным скролл-контейнером** и одним JS-контроллером
`SFeed` (`web/app.js`, директива `v-sfeed`):

- чистое ядро `SFeed.step(prev, dtMs)` — один шаг движения: `run` →
  `hold_end` (1.6 с) → `rewind` (плавный возврат, easeOutCubic 0.9 с) →
  `hold_start` (0.6 с) → `run`; `max <= 0` → `idle`, `y = 0`
  (**нет искусственного движения**, если элементов меньше окна);
- ручное управление: `wheel`, `touchstart/touchmove`, `pointerdown`
  (скроллбар), `keydown` (↑/↓/PageUp/PageDown/Home/End/Space), `scroll`
  (сравнение с ожидаемым `scrollTop` — своё движение не считается ручным);
- при ручном действии — пауза `resumeMs = 2600` мс, затем возобновление
  **с текущей позиции** (`y` читается из фактического `scrollTop`, без прыжка);
- пауза на `mouseenter`, `focusin`, открытом окне записи (`setModal`),
  выделении текста (одна `selectionchange`-проверка при `mouseup`/`scroll`);
- `prefers-reduced-motion` → авто-движение не запускается вообще (плюс маска
  и transition снимаются CSS), ручная прокрутка остаётся;
- один экземпляр на контейнер (`el.__sfeed`), слушатели не дублируются,
  `destroy()` снимает всё; изменение списка (`MutationObserver`) и размер
  окна/контейнера (`ResizeObserver`) пересчитывают `max` и обрезают позицию.

## 4. EVOL-003 — окно записи ТОЙ ЖЕ сущности

Одно окно внутри приложения (`role="dialog"`, `aria-modal`, `aria-labelledby`,
`tabindex="-1"`, `data-sfeed-modal`), новое окно браузера не открывается.

Поля (`_statusRecordFrom`, рендер `data-rec-field`): полный текст; тип записи;
чат/область; субъект; связанный Telegram user id; **раздельные даты** —
«Записано (извлечение)» (`graph_facts.created_at`), «Дата события (сообщение)»
(`message_timestamp`), «Подтверждено» (`last_confirmed_at`), «Последнее
обновление» (отдельной колонки нет → «нет данных»); происхождение
(`origin` → «сырое сообщение чата» / «Сон» / «Глубокий сон» / «Личность» …);
статус; источники (TG-сообщение #id · чат); изменения (`supersedes`,
`archived_at`); для убеждений/парадигм — вес и важность.

Отсутствующее поле помечается `rec-missing` → «нет данных» (не подменяется
соседней датой и не выдумывается). Закрытие: явная кнопка, Esc (первым в
`escClose`), клик вне окна; focus trap (Tab по кругу), возврат фокуса на
исходную строку, блокировка фоновой прокрутки
(`.app-shell.sfeed-modal-open main.scroll-area` — та же схема, что у меню
«Ещё»), анимация `sfeed-modal-enter` с reduced-motion-off.

## 5. EVOL-004 — первоисточник и связанные записи

В окне записи: «Показать первоисточники» — **объектные** вызовы существующих
API:
- убеждение/парадигма → `GET /api/memory/dream/chain?fact_id=…&chat_id=…`
  (основания/якоря → факты → сообщения `(chat_id, tg_message_id)`, delta
  «было/стало», число сообщений, флаг усечения);
- факт с адресом сообщения → `GET /api/memory/attribution/trace?chat_id=…&
  tg_message_id=…` (сообщение-триггер, дата отправки, автор, ревизия, число
  фактов из сообщения);
- «Досье субъекта» — существующий `openFeedDossier` (конкретный участник, не
  общий раздел);
- «Связанные записи» — другие факты **того же субъекта** / другие черты;
  переключение внутри окна (контекст списка не теряется).

Кнопок «в общий раздел» нет (`shellNavTo`/`navigateTo` в окне отсутствуют —
проверяется тестом). Если адреса нет — честный текст «у записи нет адреса
исходного сообщения», а причина недоступности внешней ссылки называется
отдельно (`statusRecordTgNote`: username чата этим ответом не передаётся).
Данные не расширяются на другие роли/чаты: роут остаётся
`requires_global_admin()`, окно работает на уже доступных записях.

## 6. EVOL-005 — метки времени, тип и честные пустые состояния

- Строка: `statusRowDateLabel` (сегодня → время, иначе ДД.ММ) — одна форма для
  всех четырёх; точный timestamp — в `title` (`statusRowTitle`) и в окне
  записи; `statusRowAgeLabel` («сейчас / N мин / N ч / N дн») доступен без
  подмены даты события.
- Пустые состояния:
  - «Новые факты»: ошибка → «Не удалось загрузить ленту. Причина: …»
    (`data-sfeed-error`); пусто → `data-sfeed-empty` с причиной по факту:
    «лента ещё не запрашивалась» / реальные счётчики «не подтверждено: N ·
    к переизвлечению: M» / честная фраза, что причину запуска экстракции ответ
    ленты не передаёт (пробел ниже).
  - «Убеждения»: `сон выключен настройкой` (при `cognition.dream.enabled ===
    false`), `задача ещё не наступала` (нет `last_run_at`), иначе — результат
    последней попытки (`lastAttemptLabel`, включая `выключено настройками`).
  - «Парадигмы»/«Эволюция характера»: сохранены прежние честные строки
    (последняя попытка / планировщик / причина / self-фактов за 30 дней).
- Чат/область: `_statusScopeLabel` — «Весь бот (GLOBAL)», название чата из
  `oversightData.chats`/`accessChats`, иначе «Чат <id>»; неизвестный чат —
  «нет данных», а не выдуманный GLOBAL.

### Задокументированные пробелы (не выдумываем)

1. **Конверт пустого состояния ленты фактов не отдаётся HTTP.** Готовый
   `services.memory_diagnostics.new_facts_widget` различает
   `empty/disabled/no_new_results/load_failed/not_yet_run`, но HTTP-роут его
   пока не собирает (это прямо записано в докстринге `dossier_feed` в БД).
   Подключение конверта меняет форму ответа и требует переделки стаба
   `tests/test_dossier_feed_round1024.py` — выходит за рамки «только wiring»
   этого лейна. Сейчас UI показывает причину, доказуемую на клиенте, и честно
   говорит, что причину запуска экстракции ответ не передаёт. **Нужен
   отдельный бэкенд-шаг** (EVOL-007/009-линия).
2. **Telegram deep-link.** Username чата в ответе ленты отсутствует, поэтому
   прямая ссылка `t.me` не строится; показывается внутренняя трасса сообщения
   (id + чат + время + автор) и причина недоступности внешней навигации.
3. Для черт характера «связанные записи» — другие черты (у `dynamic_traits`
   нет собственных source-ссылок в ответе `/api/persona`).

## 12. Итог (кратко, по-русски)

Четыре статусных виджета теперь выглядят и ведут себя одинаково: одна высота
окна и строки, общий фон, шрифт, отступы, границы и подсветка активной строки;
различаются только бейджем типа и названием раздела. Все четыре ленты плавно
двигаются сами и нормально прокручиваются руками (колесо, палец, трекпад,
клавиатура, скроллбар); при ручном действии движение замирает и через короткую
паузу продолжается с того же места, при наведении/фокусе/открытом окне/выделении
текста список не уезжает, а при `prefers-reduced-motion` авто-движения нет
совсем. Клик по строке открывает аккуратное окно той же записи с полным
текстом, раздельными датами (запись, событие, подтверждение, обновление),
происхождением и адресом первоисточника; оттуда можно раскрыть цепочку
вывода/трассу сообщения, связанные записи того же субъекта и досье участника,
а если внешняя ссылка в Telegram невозможна — это сказано прямо с причиной.
В строках появились ненавязчивые даты, а пустые состояния объясняются по
фактической причине; там, где причина действительно не передаётся ответом
ленты фактов, это названо честно и вынесено как отдельный бэкенд-пробел.
Проверки: 28 новых pytest, новый node-тест, 168 + 119 + 40 + 19 регрессионных
зелёных, живой рендер в Chromium и реальная визуальная проверка; известные
4 падения — предсуществующие и к этой работе не относятся.

### Блокер 1 — строки «Новых фактов» сжимались в реальной разметке

Корень: в `web/index.html` (L10803) окно «Новых фактов» — это
`.facts-list.sfeed-viewport` БЕЗ `.sfeed-track`, строки — прямые дети окна.
На этот контейнер действует legacy-правило `.status-facts .facts-list`
(specificity 0,2,0) с `display:flex; flex-direction:column`. Во flex-контейнере
строка получала `flex-shrink:1` (по умолчанию) и сжималась: 168 px окна / 12
строк → 13.33 px вместо 64, `.sfeed-item__text` → высота 0 (текст факта
полностью скрыт), `scrollHeight - clientHeight` = 62 px (движения почти нет).

Правка (`web/static/app.css`):
- `.sfeed-item` — `flex: 0 0 var(--sfeed-row-h)` (строка не сжимается и не
  растягивается ни в одной из четырёх лент);
- legacy-правило `.status-facts .facts-list` больше не задаёт геометрию окна
  (`max-height: 260px` убрано — высоту даёт `--sfeed-h`), шаг строк приведён к
  общему токену `var(--sfeed-gap)`, а правила `.status-facts .facts-list
  .sfeed-item` больше нет.

Замеры на РЕАЛЬНОМ фрагменте `index.html` (предок `.status-facts`, без
`.ribbon-track`, 12 строк, `app.css` — байт-в-байт копия, контроллер `SFeed`
вырезан из `web/app.js`):

| Метрика | HEAD (RED) | после правки |
| --- | --- | --- |
| высота строки (`getBoundingClientRect` / computed) | **13.33 px** | **64 px / 64px** |
| `flex` строки | `0 1 auto` | `0 0 64px` |
| высота `.sfeed-item__text` | **0 px** | 15.8 px (1280) / 31.6 px (390, 2 строки) |
| `scrollHeight - clientHeight` | **62 px** | 666 px |
| активных строк (`[data-sfeed-active="1"]`) | 1 | 1 |
| горизонтальный overflow | нет | нет (`docScrollW` = 390/1280) |

### Блокер 2 — авто-прокрутка «замирала» на узком экране

Корень: `Viewport.tick()` перечитывал `el.scrollTop` каждый кадр и писал туда
дробную цель (16 px/с ÷ 60 ≈ 0.27 px). Браузер квантует `scrollTop`, остаток
терялся каждый кадр → позиция не росла.

Правка (`web/app.js`, `SFeed`):
- дробная позиция теперь живёт ВНУТРИ контроллера между кадрами (`state.y`), в
  DOM пишется целое (`Math.round`), последнее записанное хранится в
  `this.written`;
- из DOM пересинхронизируемся только по внешнему поводу: `refresh()`
  (список/ресайз), `pauseManual()` (ручное действие) и дрейф > 2 px
  (скроллбар/клавиши/обрезка `max`) — тогда остаток уже неактуален.

Замеры (реальная разметка, 3 с окна наблюдения):

| Ширина | HEAD (RED) | после правки |
| --- | --- | --- |
| 390 px | 0.89 px/с (практически стоит) | **16.43 px/с** (49.33 px за 3 с) |
| 1280 px | ~3.25 px/с при `max=62` | **16.0 px/с** (48 px за 3 с) |

Дополнительно проверено, что правка не сломала ручной режим:
колесо → позиция удержана (20 → 20 через 400 мс, `active=false`), затем
возобновление С ТОЙ ЖЕ позиции (20 → 31.33, без прыжка в 0); программная
прокрутка «пользователем» до 300 подхватывается (`state.y` = 300), после паузы
движение продолжается с 300 (315.33); `prefers-reduced-motion: reduce` —
движения нет (`dy=0`, маска `none`); лента с обёрткой `.sfeed-track` (три
«Мониторинга интеллекта») — строка 64 px, текст 15.8 px, `max` 686,
16.4 px/с, одна активная строка — регрессии нет.

### Малое — focus trap окна записи (EVOL-003)

Корень: при открытии фокус ставился на корень окна (`tabindex="-1"`), и
Shift+Tab уводил фокус за пределы окна.

Правка (`web/app.js`):
- `openStatusRecord` → фокус сразу на ПЕРВОМ элементе управления (кнопка ✕);
  корень остаётся фолбэком, если элементов управления нет;
- `statusRecordKeydown` → корень включён в цикл: Tab/Shift+Tab с корня ведут на
  первый/последний элемент, фокус наружу не уходит.
