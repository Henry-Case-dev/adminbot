# ER-65 — проверка «на разрыв» (falsification) снимка сегментов

Снимок считается доказательством только если он **падает** при изменении канона.
Проверено вручную на рабочем дереве (локально, без сети и без прода):

## Что делали

1. Сохранили `services/chat_prompts.py` побайтно (sha256
   `4942cdb1da53961dcb87b0fca4b4c7bcecc06b13ea2172bd6a661e31a2e640f8`).
2. Дописали в конец файла одну строку, меняющую канон канала:
   `CHAT_SYSTEM_PROMPT = CHAT_SYSTEM_PROMPT + "\nФАЛЬСИФИКАЦИЯ-КАНОНА"`.
3. Запустили проверку и тест.
4. Вернули файл из сохранённой копии, сверили sha256 (совпал), перезапустили
   проверку — снова OK.

## Наблюдаемый результат (сломанный канон)

```
FAIL: снимок разошёлся с закоммиченным артефактом
  direct.single.legacy_no_tools[0] system: chars 5961 → 5976,
    sha fa18451557a4 → 309dbc0fcbb4
  direct.tool_phase.model_driven[0] system: chars 5961 → 5976,
    sha fa18451557a4 → 309dbc0fcbb4
```

```
FAILED tests/test_er65_sent_segment_snapshot.py::
  test_snapshot_regenerates_byte_stable_from_code
1 failed, 12 passed
```

## Что это доказывает

* Правка канона **не проходит молча**: диагностика называет стадию, сегмент,
  роль, изменение длины и оба `sha256`.
* Долговременный тест ловит это штатной командой из шапки артефакта, без
  отдельного «ручного» режима.
* Снимок не является тавтологией (сравнение идёт с кодом, а не с самим собой).

## Восстановление после проверки

Файл канона возвращён из копии, `git status` по нему чистый, `--check` снова
проходит: `OK: снимок воспроизводится байт-в-байт (stages=17, segments=34,
two isolated processes identical)`.
