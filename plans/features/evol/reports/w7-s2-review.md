### B2. Решение Architect §9.1 не выполнено: «пусто» объявляется при отказе источника

`web/static/cognitive-map.js:906-913` (нет ветки `degraded`, `empty` при

`12164-12166`.

Сервер реально отдаёт `state='degraded'` при нуле узлов
(`web/api/cognitive_map.py:505-516` и `854-861`: любая упавшая выборка попадает в

Воспроизведение (реальный адаптер в node; payload `state:'degraded'`,
`degraded.active:true`, 0 узлов):
- ожидание по §9.1: `empty` запрещён, пока `degraded.active === true`;
- наблюдение: `mapClientState(...).state = "empty"`, note «в этой области нет
  фактов и связей».

В браузере (стенд, payload `state:"degraded"` с 0 узлов) одновременно видны
янтарная строка «часть источников не прочитана: memory_cycle» **и** пустое

по «худшему факту» нет: при `degraded` с данными клиентское состояние остаётся
`ready` (замер стенда: `degraded -> state=ready`).

Минимальное исправление: в `mapClientState` добавить ветку `degraded` с
приоритетом `renderer_failed -> loading/not_loaded -> degraded -> empty -> stale ->

Матрицу сочетаний (`degraded+empty/stale/renderer_failed`) держать на S4, как решил
Architect.

### B3. Решение Architect §9.2 не выполнено: бюджет подписей негеометрический

`web/static/cognitive-map.js:698-718`: `budget = min(maxLabels, 6|16|26)` -
константа на LOD, площадь вьюпорта и длина подписей не участвуют.

Замер (реальный адаптер, одинаковый набор 12 подписей по 34 символа):
- 320x300, mobile: `maxLabels = 12`;
- 1440x900, desktop: `maxLabels = 16`;
- 1000x400 (плоский кадр), desktop: `maxLabels = 16`.

Ожидание по §9.2: `budget = clamp(round(fill * W * H / boxArea), 4, cap)`, где
`boxArea` считается через `measureLabel()`, `fill` = 0.05 desktop / 0.04 mobile,
потолки 26/12. На 320x300 формула даёт примерно 4 против фактических 12: потолок
не нарушен, но бюджет геометрии не следует.

Смягчающее: реальное число нарисованных подписей дополнительно ограничивают
коллизии и вьюпорт (на 320x300 в замере нарисовано 2), визуального провала нет;
дефект в неисполненном правиле и в том, что `maxLabels` в приёмке перестаёт быть
осмысленной метрикой.

Минимальное исправление: считать бюджет по формуле §9.2 внутри `allocateLabels`,
LOD - долями бюджета (`overview=min(budget,6)`, `normal=min(budget,16)`,
`detail=budget`); добавить в `tests/js/evol_cognitive_map_test.js` приёмку из §9.2
(монотонность по площади и по длине подписи, `budget <= cap`, `budget >= 4` при
4 и более узлах, mobile < desktop, выбранный узел и парадигма подписаны).

### B4. Обязательная живая проверка камеры нестабильна

Полный прогон стенда дал 2 падения: «полный экран сбросил камеру
`{x:-58.59,y:14.22},1.098 -> {x:-61.79,y:14.95},1.1`» и «выход из полного экрана не
сохранил камеру» (допуск `pos_tol=3.0`,
`tools/ui_evol_w15_composition_e2e.py:1587`). Повтор только секции - 0 падений,
камера ровно `{-62,15},1.1` на 390 и 1280.

Причина: `_cogCaptureCamera` снимает камеру на каждом кадре отрисовки
(`web/app.js:28398-28402`) и в обработчике `zoom` (`28316-28323`), но после
завершения анимации `focus()` нового кадра уже нет: сохранённая камера отстаёт на
один кадр (около 3.2 единицы, примерно 3.5 px), и допуск 3.0 иногда пробивается.
Для пользователя сдвиг практически незаметен, но обязательная проверка L01321
воспроизводится через раз, то есть доказательство не годится как «зелёное».

Минимальное исправление: снимать камеру по `net.once('animationFinished', ...)` в
дополнение к кадру, тогда сохранённое значение равно установившемуся виду; допуск
не ослаблять.

Перепроверка: полный стенд дважды подряд, оба прогона `COG-MAP checks=90` без
падений по камере.

  с `state` (`:1050-1058`); `degraded` считается от `model.degraded.active`, не от
  строки `state`.
- `empty` принудительно запрещён при отказе: `var dataEmpty = degradedActive ? false ...`
  (`:1014`), поэтому состояние «нет фактов» не может скрыть непрочитанный источник.
- В шаблоне осталась **одна** строка статуса (`cogStatus`, `web/app.js:7270`):
  `data-cog-state="<kind>"`, `data-cog-degraded` только у неё; прежний отдельный
  янтарный блок удалён из обоих блоков карты (`web/index.html:12196-12212` и
  `13662-13678`). Кнопки: «Обновить» (stale), «Открыть в Памяти»
  (empty/renderer_failed), «Повторить» (degraded). В полном экране пустота и
  `renderer_failed` теперь тоже дают переход в «Память» (моё прежнее сопутствующее
  замечание закрыто).
- Матрица. Node-тесты (`tests/js/evol_cognitive_map_test.js`, §14): `degraded` + 0
  узлов (`notice.kind=degraded`, `empty=false`, текст с именем источника),
  `degraded` + данные (`state=ready`, `notice.kind=degraded`), `degraded` +
  `renderer_failed` (побеждает `renderer_failed`), `not_loaded` выше `degraded`,
  `degraded` + `stale` (побеждает `degraded`), чистая пустота без отказа
  (`notice.kind=empty`), полный набор (`notice.kind=ready`, пустой текст).
- Живой `degraded` с нулём узлов (оба прогона стенда): `data-cog-state=degraded`,
  `empty=false`, ровно **один** элемент `.cog-state[data-cog-state]` на экране,
  текст пустоты отсутствует, имя `memory_cycle` названо. Кадр:
  `evidence/cog-map-s2/w15-cog-degraded-empty-1280.png`.
  Живая матрица `degraded+stale` и `degraded+renderer_failed` остаётся на S4, как
  решил Architect (node-часть уже есть).

## 4. B3 (§9.2): бюджет подписей из геометрии

`labelBudget()` (`web/static/cognitive-map.js:712-780`) реализует
`budget = clamp(round(fill * W * H / boxArea), 4, cap)`; `boxArea` из средней подписи
через `measureLabel()` (ширина `chars*0.55*fontSize + 6`, высота `fontSize + padding`),
`fill` 0.05 / 0.04, `cap` = `DEFAULTS.maxLabels` / `mobileMaxLabels` (26/12, значения не
менялись), LOD стал долей: `overview=min(budget,6)`, `normal=min(budget,16)`,
`detail=budget`; обязательные подписи (выбранный узел, парадигмы) поднимают бюджет до
своего числа, но не выше `cap` (`:752`).

Моя независимая проверка (свои размеры кадра, ожидание посчитано в пробе по формуле
Architect, а не вызовом `labelBudget`): 9 случаев, **0 расхождений**.

| Кадр | budget | raw | cap | ожидание |
|---|---|---|---|---|
| 320x300 mobile | 4 | 3 | 12 | 4 |
| 390x844 mobile | 12 | 12 | 12 | 12 |
| 800x600 desktop | 22 | 22 | 26 | 22 |
| 1000x400 desktop | 18 | 18 | 26 | 18 |
| 1280x900 desktop | 26 | 52 | 26 | 26 |
| 1440x900 desktop | 26 | 59 | 26 | 26 |
| 1920x1080 desktop | 26 | 94 | 26 | 26 |
| 1440x900, подпись 6 симв. | 26 | 109 | 26 | 26 |
| 1440x900, подпись 34 симв. | 22 | 22 | 26 | 22 |

Свойства: рост по площади (18 < 26 на 1000x400 против 1440x900), уменьшение по длине
подписи (22 < 26 при 34 против 6 символов), mobile < desktop на одном кадре
(12 < 22 при 800x600), потолки 26/12 соблюдены, значение больше не константа LOD.
Живые бюджеты стенда: 390 -> 4 (кадр 338x318), 1280 -> 12 (996x318).
Мобильных подписей стало 4 вместо 7 прежних: это правило §9.2 и ТЗ §2.7 «только
приоритетные подписи»; кадр 390 читается без наложений.

## 5. B4: камера снимается после анимации, проверка стабильна

- Снимок камеры добавлен на `net.on('animationFinished', ...)`
  (`web/app.js:28443`, рядом с прежними кадрами и `zoom`), закреплён pytest-пином
  `test_camera_captured_after_animation_finished`.
- Стенд больше не сравнивает середину анимации с концом: перед переходом он ждёт
  установившийся кадр (`settled_view`), сверяет сохранённую камеру с установившейся
  при допуске **1.0 ед. / 0.02** (жёстче прежних 3.0 / 0.08) и живой кадр до/после
  полного экрана при прежних 3.0 / 0.08.
- Два полных прогона подряд: падений ноль, камера полного экрана и выхода совпадает
  бит в бит (`{-62, 15}`, scale `1.1`) на 390 и 1280.
- Честная оговорка (её даёт и Builder): удаление одного только обработчика
  `animationFinished` в Chromium стенд не краснит, потому что кадры отрисовки успевают
  снять установившийся вид. Требование Architect выполнено (обработчик есть), а
  наблюдаемая приёмка (сохранённый кадр равен установившемуся, два прогона) доказана;
  платформа, где после анимации кадры не приходят, не проверялась. Это остаточный
  риск S4/живого прода, не блокер.

## 9. Какие строки EVOL-COG-MAP поддерживает S2 (для PM)

Доказательства S2 теперь покрывают (строки остаются `PENDING` до релиза и до S3/S4):

- §2.3 модель узлов/связей: типизированные ключи, изолированные узлы без выдуманных
  рёбер, изоляция чатов в данных;
- §2.4 визуальная система: цвет и форма по классам, легенда словами владельца,
  различие не только цветом;
- §2.4 подписи: экранное разрешение коллизий, LOD и геометрический бюджет §9.2,
  отсутствие массового наложения;
- §2.4 reduced-motion: живой прогон с `prefers-reduced-motion: reduce` (камера без
  анимации, информативность сохранена) и контрольный прогон, доказывающий
  чувствительность проверки;
- §2.5 витрина: поиск по имени/алиасу с фокусом, фильтр по типу и реальному кластеру,
  сброс вида, «видно X из Y», честные состояния (loading/not_loaded/
  renderer_failed/stale/empty/degraded) одной строкой по худшему факту;
- §2.6 паритет: тот же маршрут и позиция в сетке, pan/zoom, полный экран с сохранением
  узла, масштаба, камеры и фильтров;
- §2.8 нет LLM и эмбеддинг-вызовов при рендере/зуме/фильтрах/полном экране, self-host
  vis-network, ленивый рендер, отсутствие новых зависимостей;
- §4 (в контракте) честность метрик: «показано X из Y» нейтрально и независимо от
  состояния, `partial` не выдаётся за ошибку.

Не поддерживает (ждут S3/S4 и деплой): карточка узла и ребра с provenance и кнопками
(§2.5), мобильная композиция, жесты, BackButton, клавиатура, safe-area (§2.7),
retirement остатков «Граф связей», живые замеры прода (плотность около 356 узлов,
размер payload, `EXPLAIN QUERY PLAN`, Android WebView).

**Границы утверждения.** Approve привязан к `9bd5818f` и к среде прогонов (Chromium
через стенд, фикстура 11 узлов, локальный статический сервер стенда). Любое изменение
`web/**`, тестов или стенда требует повторной проверки затронутых пунктов.
Побочный эффект моих прогонов: `pytest tests/test_webapp_evol_w10_sections.py`
перегенерировал 24 файла `plans/features/evol/audit/evidence/w10-sec-*`; они
