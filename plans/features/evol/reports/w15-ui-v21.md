## 1. Что изменено (наблюдаемый контракт)

### §5 «Модули»: один переключатель, scope = верхний селектор
- Карточка каталога содержит **ровно один** контрол `data-module-scope-toggle`.
  Второй (global+chat) тумблер, а также «всегда глобальный» контрол при
  выбранном чате удалены.
- Метка и состояние берутся из выбранной области: `GLOBAL` → глобальный ключ
  (`per_chat:false`, POST без `X-Chat-Id`), чат → `effective`-значение этой
  области (`per_chat: item.per_chat`, POST с `X-Chat-Id`).
- Модуль без chat-scope при выбранном чате — read-only «В этом чате ·
  управляется глобально» (ложного ON нет).
- Наследование: короткая подпись «наследуется от глобального» /
  «переопределено для этого чата»; возврат к наследованию — компактное
  **действие** `data-module-override-reset` → `DELETE /api/config/chat/<key>`
  только для текущего чата (global не меняется).
- Pending/ошибка привязаны к снимку `scope_id` (`storeKey` = `type/id/module`,
  global = `global/null/<id>`) и epoch: запоздавший ответ A не применяется к B
  или GLOBAL; 403/409/5xx откатывают только свою область.
- Детали модуля: только read-only статус + «Управляется из каталога», второго
  источника правды нет.

### §4.2 «Речь и характер»: пять независимых вкладок
`Личность | Речь и стиль | Мат | Примеры | Правила и источники`
- `Личность` — существующий редактор (`#speech-persona`), без простыни
  effective-правил под формой.
- `Речь и стиль` — style-документ + контролы выражения **без** мата + юмор.
- `Мат` — отдельная вкладка, но **та же** серверная сущность
  (`/api/speech/expression`, `saveSpeechExpression`) и тот же документ: второго
  write-path нет; показан статус передачи в Writer.
- `Примеры` — существующий раздел примеров.
- `Правила и источники` — SelfModel-правила (пауза/возобновление/источники) +
  переходы в канонические «Эффективный промпт», Core, реестр инструкций, опыт,
  возможности.
- Витрина разделов осталась (кнопка «← Назад»), сервисные разделы не потеряны.
- Защита черновиков: точка «не сохранено» на самой вкладке
  (`data-speech-area-dirty`), черновик личности помечается (`personaDirty`) и
  не сбрасывается при переключении; по умолчанию открыт рабочий блок
  «Личность».

### §6.1/§6.2 мобильный каркас
- App-level «…» (меню, дубль аватара/роли, пункт fullscreen) **удалён**.
- На его месте — **одна** кнопка ⛶ (`header-fs-btn`, `data-fs-toggle`), иконка
  по реальному состоянию, tap ≥44 px; на узких телефонах она больше не
  уезжает в меню.
- «Диагностика геометрии» убрана из prod-UI; панель доступна только по
  внутреннему флагу (`?fs_geom_dev=1` / `localStorage adminbot.fs_geom_dev=1`)
  для E2E.
- Drawer начинается ниже фактической системной области:
  `top = max(env(safe-area-inset-top), --tg-safe-area-inset-top)
  + --tg-content-safe-area-inset-top`, `max-height` от `--vv-h`,
  внутренний скролл, `visibility:hidden` в закрытом состоянии (маски нет),
  Esc/пункт/назад закрывают.

### §6.3/§6.4 рамки, плотность, Status
- Единый блок здоровья: одна поверхность `.card ... status-block status-health`
  → компактная строка ошибок/предупреждений с адресным переходом (логи /
  «Открыть в Аналитике») + три сегмента `Бот | Сердцебиение | Сервер` с
  волосяными разделителями из токенов (`--border-hairline`,
  `--surface-border`, `--space-*`).
- Тонировка EVOL-032 — только у виновного сегмента (свой
  `data-health-state`); сам блок нейтрален; второй blur/тень не добавлены.
- Мобильный: три сегмента вертикально в **одной** панели; действия бота —
  компактные кнопки с tap ≥44 px вместо трёх плиток.
- «ИИ»: компактный хаб — карточки по контенту (`align-items:start`,
  `grid-auto-rows:min-content`), широкая карточка моделей + компактные входы и
  deep-links в конкретную вкладку редактора.

### §4.2 «Мат»/«Примеры» и §7 «Избранное»
- «Избранное» удалено как концепция: кнопка-звезда, фильтр `Избранные`,
  `localStorage adminbot.modules_quickpicks.v1`, computeds/methods, CSS-класс.
  Замена другим именем («Закреплено»/«Быстрый доступ») не вводилась.
- Категории, глобальный поиск, локальные фильтры
  `Все/Включённые/Выключенные/Проблемы`, маршруты и RBAC сохранены.

### §2/§3.4 история версий и Test Style
- Панель истории: показывается **дата события активации** из
  `prompt_activations.created_at` (`phActivationNote`), устаревшая сноска
  «таймер активации не отдаётся» удалена.
- `.prompt-history-active`: flex + токенный `gap` + волосяные разделители
  (было «слипание» на 1280 и 390).
- Test Style: время только серверное (`elapsed_ms`/`elapsed_seconds`,
  `queued_at`/`started_at`, `timing_source`); локальный тик — `performance.now`
  относительно серверной базы; `Date.now()`-арифметики нет. В очереди без
  `started_at` — «В очереди» и «—», а не миллионы секунд.
- Автомат: `idle → queued → running(base) → running(edit) →
  succeeded|failed|cancelled|expired`; терминальные состояния снимают спиннер и
  «Обработка…», кнопка снова доступна, 404 job → честный финал
  (`job_not_found`), поздний poll не оживляет job.
- Результат различает `styled` и «стиль не применён (публикации не было)»,
  показывает длительность/ревизию; устаревший пример помечен ревизией и
  «это не успешная проверка текущей версии».

1. **pre-existing**: `ui_soul14_layers_e2e.py` ждёт `DIV` у узлов карты сборки
   (в HEAD это `BUTTON` — контракт U-02), плюс ждёт числовое значение правил

   себе». Мой диф эту разметку не менял (проверено `git show HEAD:web/index.html`).
2. **pre-existing**: `ui_speech_mobile_entry_e2e.py` ожидает generic-карточки
   хаба «ИИ» и `[data-speech-hub-entry]` в отрисованном виде — после EVOL-028
   хаб «ИИ» показывает рабочую панель (`data-ai-hub`), а вход в речь
   реализован секцией `data-ai-speech`. Инструмент не обновлялся вместе с
   EVOL-028.
3. **pre-existing**: `ui_asap3_hint_speech_e2e.py` ждёт
   `[data-speech-inspector-style]` сразу после карточки `inspector`; раздел
   требует загрузки `/api/speech/inspector` и на стабах инструмента не приходит.
4. `hasUnsavedEdits()` на стенде без `/api/persona` считает личность
   «изменённой» (baseline отсутствует) — это артефакт фикстуры матрицы, не
   продукта: реальный backend отдаёт `values`. В собственном e2e я добавил
   стаб `/api/persona` и подтверждение штатного confirm-диалога.
