## 1. Обязательный UI/поведенческий контракт (группировка по слайсам §6)

**Данные и модель.** Единая типизированная модель вместо «узлы = сущности»: `entity` (user/topic/event/fact из `nodes`), `fact`, `belief`, `paradigm`, `observation`, `evolution_event`. Каждый узел: стабильный типизированный `id`, `kind`, `scope`, заголовок + полный текст, статус, раздельные времена (когда произошло / обнаружено / сохранено / обновлено — только реально существующие поля, иначе `null`), `provenance`, и `isolated:true`, если подтверждённой связи нет. Рёбра: только записанные (`edges`) + `derived_from` по реальным ссылкам (`supersedes`, `edges.fact_id`); тип, концы и provenance обязательны.

**Визуал.** «Живое созвездие»: `fact` — голубой/бирюзовый, `belief` — мягкий фиолетовый, `paradigm` — крупный индиго-центр, `evolution_event` — янтарный акцент; различие не только цветом (форма/контур/легенда/подпись). Тонкие рёбра, локальная подсветка при выборе, едва заметные микродвижения, стабильный layout, один клик — фокус. Легенда обязательна и видима без документации, на мобильном — компактная строка. Подписи: **экранное разрешение коллизий**, приоритеты, LOD по масштабу; массовое наложение названий запрещено. `prefers-reduced-motion` отключает движение, информативность сохраняется.

**Карточка узла.** Кликабелен каждый реально показанный узел → аккуратная выдвижная панель (desktop) / bottom sheet (mobile) без потери контекста и без гигантского полупрозрачного окна. Показывает по наличию данных: полный текст, тип/статус, чат/область, три корректно названные даты, источник/сообщение, связанные записи и *почему* связь показана. Кнопки только работающие: «Открыть источник», «История изменений», «Открыть в Памяти», «Показать связи». Клик по ребру — тип, обе сущности, источники, обоснование (нет `fact_id` → «обоснование не записано»).

**Паритет + responsive.** Поиск (имя/алиас), фильтры (тип, scope/чат, кластер/статус), reset, pan, zoom, fullscreen, счётчики, переходы в Память, права — сохраняются. Desktop: карта на всю ширину, side panel; планшет — панель по ширине; телефон — та же сцена, приоритетные подписи, bottom sheet, предсказуемый приоритет жестов «скролл страницы vs карта», keyboard/viewport, safe-area, Telegram BackButton не закрывает Mini App; выход из fullscreen сохраняет узел, масштаб, камеру, фильтры.

**Честность метрик.** `weight`/`importance` — правила извлечения, `edges.weight` — повторяемость; показывать можно, но с названной природой. `confidence`/`strength`/`freshness` **не рассчитываются** → не показываются (строка «не рассчитывается»). Размер узла = тип + degree; легенда это объясняет. Никаких псевдооценок людей и никакого «социального рейтинга».

## 2. Источники данных и запрет второго хранилища

| Что | Источник (единственный) |
|---|---|
| Топология сущностей и рёбра | `db.graph_snapshot` без изменений (`nodes`, `edges`, score/stoplist/сироты — как есть) |
| Provenance рёбер | `edges.fact_id`, `origin`, `last_updated` + `graph_facts` по `fact_id` |
| `fact` / `belief` / `paradigm` | `graph_facts` (`kind`, `status`, `belief_meta.type=paradigm`, `importance`, `weight`, `last_confirmed_at`, `supersedes`, `source_ids`, `tg_message_id`, `forward_from`, `origin`) |
| `observation` | `mca_trait_observations` (`observed_at`, `dimension`, `raw_text`, `source_refs`, `subject_status`) |
| `evolution_event` | только реальные записи изменений: цепочки `graph_facts.supersedes`, `memory_dream_log` (`distilled/resurrect/decay_run/deep_run`), `mca_trait_observations`; `dynamic_traits` (`/api/persona`) — текущее значение, не история |
| Итоги для «показано X из Y» | `db.graph_stats` (facts/beliefs/paradigms/graph_nodes/graph_edges) |

**Запрещено:** второе графовое хранилище, вторая очередь извлечения, новые эмбеддинги, любой LLM-вызов при рендере/зуме/фильтрах/карточке, синтез эволюции сравнением текущего текста с прошлым, вывод «веса»/«уверенности» из похожести слов, `t.me`-ссылки без проверки. Изоляция: ключ узла всегда чат-квалифицирован (`ent:<chat>:<id>`, `fact:<id>`…), узлы разных чатов не сливаются даже при совпадении имени; global — только агрегат глобального админа с явной пометкой области.

## 3. Переиспользование и судьба «Графа связей»

* Рендерер: **vis-network 9.1.9 как есть** (pan/zoom/select, DataSet, `destroy`, mobile-simple, reduced-motion). Подписи — собственный слой: `nodes.font.size=0` + отрисовка в событии `afterDrawing` (подтверждено в вендорном файле: `emitter.emit("afterDrawing", A)`); `ctx.setTransform(1,0,0,1,0,0)` + `network.canvasToDOM()`; DataSet не мутируется (иначе поедет `_graphSignature` `app.js:27835`).

* «Открыть в Памяти» = `navTo('#/memory')` + предзаполнение существующего поиска каталога и типа (никакого нового маршрута/экрана).
* «Открыть источник»: есть `tg_message_id` → существующий просмотр первоисточника/сообщения в админке (с проверкой прав); нет — «ссылка недоступна», без выдуманного пути. «История изменений» — только реальные версии (`supersedes`-цепочка, `expand_chain`), иначе «истории нет».
* **Судьба старого виджета:** тот же маршрут `#/status/graph` и та же позиция в сетке остаются; меняются название («Когнитивная карта» в `app.js:838,13063`), данные, визуал и карточка. Информация не теряется: все прежние взаимодействия перечислены в таблице паритета и закрыты.

## 4. Состояния и честность

| Состояние | Поведение |
|---|---|
`loading` | скелет + «загрузка карты», контролы disabled
`not_loaded` (payload есть, vis-network не загружен) | честная подпись «визуализация грузится», счётчики уже видны
`empty` | «в этой области нет фактов/связей» + переход в Память; нули не рисуются как данные
`partial/truncated` | «показано X из Y» по узлам и рёбрам (`truncated`, `shown_of`) — полнота не обещается
`stale` | «данные на HH:MM» + кнопка обновления; устаревшая карта не выдаётся за текущую
`renderer_failed` | «визуализация недоступна» + счётчики + ссылка в Память (не пустой чёрный прямоугольник)
`reduced-motion` | статичная раскладка, без импульсов и авто-движения
`degraded` | физика off, меньше подписей/эффектов; содержательные взаимодействия остаются

**NOT_APPLICABLE:** `confidence`/`strength`/`freshness` (не рассчитываются), причинное «почему» у рёбер без `fact_id`, реконструкция истории при отсутствии версий, оценка «доказательности» по размеру узла. WebGL-fallback не нужен: рендер Canvas2D.

## 5. Лимиты производительности (только существующие числа)

Бюджет узлов — общий `GRAPH_MAX_NODES=800`, рёбер — `GRAPH_MAX_EDGES=2400`; когнитивные классы запрашиваются с `LIMIT = GRAPH_SEED_NODES (150)` каждый (≤4×150=600), топология сущностей получает остаток, но не меньше своих 150 сидов. Порядок обрезки фиксирован (класс → importance/recency → id), `truncated`/`shown_of` заполняются всегда. Ленивое раскрытие = визуальный LOD/кластеры по загруженному набору, **без** дополнительных запросов на раскрытие узла. Запрещены неограниченные выборки, N+1 запросы, постоянная физика в фоне, отрисовка при скрытой вкладке, `backdrop-filter` на вершинах. Одновременных подписей ≤26 (существующий `maxVisible:26`), на мобильном ≤12 (визуальная константа, не квота данных). Перед релизом: `EXPLAIN QUERY PLAN` на прод-копии; новый индекс не вводится без доказанной деградации (в write_scope его нет).

## 7. Риски и отклонённые варианты

* **R2 — собственный слой подписей.** Экранное разрешение коллизий поверх canvas — единственное место, где возможна визуальная деградация. Отклонение: включить штатные подписи vis-network и «сортировать» их — неуправляемо, это и есть текущий дефект. Митигация: чистый аллокатор + скриншот-приёмка на плотном снимке.
* **R2 — состав «изменений».** Реальных записей эволюции мало → слой будет визуально тонким. Это честный результат, не повод синтезировать события.
* **R2 — производительность при 800 узлах на среднем Android.** Митигация: mobile-simple (уже есть), физика off после стабилизации, LOD, потолок подписей.
* Отклонено: **Cytoscape.js/D3** (второй движок 400+ КБ при работающем vendored vis-network — несовместимо с §2.8 «не закреплять библиотеку без проверки кодовой базы»); **новое графовое хранилище/пайплайн извлечения** (§2.1 запрет); **новый маршрут/экран карты**; **рисование рёбер `mentions` по совпадению имён** (подтверждаемости нет → только текстом в карточке, выключено по умолчанию, счётчики связей не затрагивает); **второй LLM-проход для «красивых» связей**.

**Параллельная безопасность:** `web/static/cognitive-map.js`, `web/api/memory_graph.py`, `tests/**`, `plans/features/evol/audit/w7-cognitive-map.md` — PARALLEL_SAFE (новые файлы). `web/index.html`, `web/app.js`, `web/static/app.css`, `web/app.py` — **SERIALIZE**: писать только после того, как полоса ревью композиции UI освободит эти файлы; SRC-READER-полосу не касаются. Изменения аддитивные, «новое в хвост», старый рендер удаляется в S2 вместе с заголовком.

**Требуемая правка write_scope (ARCHITECT_ADJUSTMENT):** добавить `web/app.py` (одна строка `include_router`). Без неё endpoint не публикуется.

**Риск:** R2 (визуальная деградация подписей и мобильная плотность), R1 по данным (изоляция чатов, отсутствие выдуманных рёбер), R3 (нет роста: только чтение).
