## 1. Жизненный цикл: один владелец, одна сцена, ноль дублей

Оставляем один канонический путь (менять архитектуру не нужно, она уже правильная):

```
loadCognitionGraph  :28754   (данные + нормализация адаптером)
      ↓ $nextTick
renderCognitionGraph :28819  ← ЕДИНСТВЕННЫЙ владелец графа
      ├─ сигнатура изменилась?  нет → _cogRedraw :28881
      ├─ тот же контейнер+режим? да  → _cogApplyData :28942   (инкремент)
      └─ иначе                       → destroyCognitionGraph :29936 → _cogCreateNetwork :29058
```

Внутри сцены вводится ровно один необязательный объект-владелец кадра:

```
this._cogScene = {
  net, nodesDS, edgesDS, el,          // vis и его данные
  fx: { canvas, ctx, dpr, dirty },    // НАШ слой: свечение/импульсы/подписи/агрегаты
  raf: null, running: false,          // ОДИН requestAnimationFrame на карту
  fitScale, bbox, lod, lodPrev,       // геометрия и уровень детализации
  labels: null, labelKey: '',         // кэш подписей
  ro: ResizeObserver|null, io: IntersectionObserver|null,
  sprites: {}, watchdog: null
}
```

Правила (проверяемо):

1. `_cogScene` создаётся **только** в `_cogCreateNetwork` и уничтожается **только** в `destroyCognitionGraph`. Ни один другой метод не создаёт canvas/RAF/наблюдатель.
2. `destroyCognitionGraph` в одном месте снимает: `cancelAnimationFrame(fx.raf)` → `ro.disconnect()` → `io.disconnect()` → `clearTimeout(watchdog)` → `fx.canvas.remove()` → `net.destroy()` → `_cogScene = null`. Порядок фиксирован, частичные «полусносы» запрещены.
3. Обработчики уровня `window`/`document` под граф **не добавляются вообще**: `visibilitychange` уже есть (`:8793`, `onVisibilityChange:30608`), resize — через `ResizeObserver` на `_cogEl`.
4. Переход embedded ↔ fullscreen по-прежнему `destroy` + `create` в новом контейнере (существующие строки `:28916-28923`). Причина: vis жёстко привязывает canvas к контейнеру; перенос живого инстанса требует ручного `setSize`+`redraw` и уже проверенной камеры не даёт. Один инстанс в единицу времени — требование §6.6 спеки выполнено; проверка «после 20 переключений нет роста» — счётчики §10.
5. Состояние, которое **переживает** пересоздание (не сбрасывается в `destroy`): `_cogCamera` (есть), `_cogLodPrev` (новое), `_cogCard`/выбор (есть). Состояние, которое сбрасывается: `fx`, `labels`, `fitScale`.

## 4. LOD: fit-масштаб, отношение `r`, гистерезис (замороженная формула)

### 4.1. `fitScaleRef` — считаем сами

```
W, H              = clientWidth/clientHeight контейнера сцены (CSS px)
bbox              = по позициям узлов: spanX = maxX-minX, spanY = maxY-minY
R0                = 12                        // номинальный радиус-паддинг, CSS-px → сетевые единицы
fitScaleRef       = (spanX <= 0 || spanY <= 0)
                    ? 0.8
                    : min( W / (1.1·(spanX + 2·R0)), H / (1.1·(spanY + 2·R0)) )
```

Множитель `1.1` и структура `min()` взяты из фактического `fit()` 9.1.9, чтобы кадр «обзор» совпадал с тем, что пользователь считает fit-ом. Верхний зажим **не применяется** (нам не нужен vis-овский `maxZoomLevel = 1`): при 10 узлах `fitScaleRef` может быть > 1, тогда «обзор» слегка приближен — это ожидаемо и одинаково для всех графов.

Первый кадр: **не** `net.fit()`, а `moveTo({position: center(bbox), scale: fitScaleRef, animation:false})` — тогда `r === 1` в обзоре по построению (иначе r «плавает» 0.9–1.05 из-за размеров узлов). `graphResetView:29883` и `clearCognitionGraphSearch:29703` переводятся на тот же `_cogApplyFit()`, `fit()` остаётся только как аварийный fallback.

`fitScaleRef` пересчитывается в трёх случаях и только в них: создание сети, `ResizeObserver` контейнера (в т.ч. embedded↔fullscreen, появление/исчезновение колонки инспектора), смена набора узлов (после `_cogApplyData`). Камера при этом **не двигается** (`fit`/`moveTo` не вызываются).

### 4.2. Отношение и уровни

```
r = getScale() / fitScaleRef           // clamp в [0, 10/fitScaleRef]; fitScaleRef <= 0 → r = 1
T1 = 0.85   (L0 ↔ L1)
T2 = 1.80   (L1 ↔ L2)
δ  = 0.12   (полоса гистерезиса, спек §5.1 «10–15 %»)
```

Вход в более высокий уровень — по завышенному порогу, возврат — по заниженному:

```
подняться через T:  r >= T·(1+δ)      T1: 0.952    T2: 2.016
опуститься через T:  r <  T·(1−δ)     T1: 0.748    T2: 1.584
```

```
lodFor(r, prev):
  prev = clamp(prev ?? 0, 0, 2)
  // подъём (можно перескочить уровень за одно движение колеса)
  if (r >= 2.016) return 2
  if (r >= 0.952 && prev === 0) return 1
  // спуск
  if (prev === 2 && r < 1.584) return (r < 0.748 ? 0 : 1)
  if (prev === 1 && r < 0.748) return 0
  return prev
```

Зона нечувствительности на каждой границе — 24 % по `r` (2·δ), поэтому дрожание колеса/пинча около порога не даёт мигания. Формула — чистая функция в `cognitive-map.js` (`lodFor`) и покрывается node-тестом; в `app.js` она вызывается на событиях камеры (`zoom`, `dragEnd`, `animationFinished`, `ResizeObserver`) — не на каждом кадре.

Обратная совместимость с существующим кодом и тестами: `DEFAULTS.overviewScale` → `0.85`, `DEFAULTS.detailScale` → `1.8` (тесты `tests/js/evol_cognitive_map_test.js:365-381`, `:737-745` используют константы от относительных значений и остаются валидными). `GRAPH_ZOOM_FAR/CLOSE` (`app.js:1479-1480`, `_graphZoomModeOf:29780`) **выводятся из обращения**: `graphApplyZoomLevel` остаётся по имени (её дергает `routing_test.js:2163`), но делегирует в `lodFor`.

### 4.3. Что меняет каждый уровень

| Уровень | Подписи | Свечение (fx) | Рёбра | Агрегаты |
|---|---|---|---|---|
| L0 `r<0.952` | `overview`-доля бюджета (§7.3), обязательны выбранный/найденный/парадигмы | ореолы только у центров компонент + top-K по degree (`K = min(40, ⌈nodes/12⌉)`), остальные — только ядро | без изменений | мягкие «потоки» между центрами компонент с реальным числом связей; клик/двойной клик по центру → раскрытие |
| L1 `0.952…2.016` | `normal`-доля | ядро + ближний ореол у всех в кадре; дальний — у ключевых | без изменений | выключены |
| L2 `r ≥ 2.016` | `detail`-доля, приоритет отсечения — по видимости | как L1 + дальний ореол у всех в кадре | без изменений | выключены |

**Почему нет мигания и скачка камеры (инварианты, а не обещание):**

1. LOD меняет только наш слой `fx` и (опционально, при доказанной «белой простыне», см. §10.5) альфу рёбер. `x/y`, `size`, `shape`, `physics` узлов не меняются никогда.
2. LOD не вызывает `fit`, `moveTo`, `focus`, `setOptions({physics})`, `stabilize`, `selectNodes` — камера и симуляция не задействованы.
3. `lodFor` с гистерезисом ⇒ уровень не может колебаться на границе.
4. Подписи детерминированы при данном кадре (сортировка по приоритету + id) ⇒ на смене уровня меняется **состав**, а не положение уже показанных.

## 5. Подписи: экранные координаты, коллизии, пересчёт

Геометрия экрана из позиций без вызова `canvasToDOM()` на каждый узел (то же преобразование, что в 9.1.9: `DOM = canvasX·scale + translation.x`, `translation = W/2 − viewPos·scale`):

```
sx = (nx − viewPos.x)·scale + W/2
sy = (ny − viewPos.y)·scale + H/2
```

1. Позиции узлов кэшируются: `_cogScene.pos = getPositions()` — обновление по `stabilizationIterationsDone`, `dragEnd` (узел), `animationFinished`, `_cogApplyData`, и не чаще одного раза за кадр. На кадре панорамирования `getPositions()` **не вызывается**.
2. Кандидаты отбираются по видимости: узел вне `[−40, W+40]×[−40, H+40]` в разбор коллизий не попадает (§5.4 спеки: не рисовать подписи далеко за кадром). Это же ограничивает `O(n·placed)`.
3. Алгоритм коллизий — существующий жадный боксовый (`allocateLabels` `cognitive-map.js:817`, `boxesOverlap:696`), детерминированный. Сохраняем.
4. Приоритет (первым ставится — первым побеждает): выбранный → совпадения поиска → hover → соседи выбранного → `paradigm`/высокий degree → остальные; тай-брейк по `id`. Расширение `labelPriority:702` полем `search`/`neighbor` (данные передаются из `app.js`, модель не меняется).
5. Выбранный/найденный/hover подписываются **всегда**: они не отбраковываются коллизией; конфликтующие с ними подписи снимаются (спек §4.4, §5.5).
6. Текст: до 2 строк, обрезка с `…` только при отрисовке (`labelText:684` остаётся, полный текст — в инспекторе; данные не режутся).
7. Отрисовка вместо нынешней «плашки» (`app.js:29354-29356`): `strokeText` тёмным контуром `lineWidth 3`, `rgba(8,11,18,.85)` + `fillText` `#E6EDF8`. Никаких чёрных прямоугольников под каждой подписью (§4.4 спеки).
8. Пересчёт — по ключу кадра и с дебаунсом в один кадр (single-flight rAF):

```
labelKey = quantize(viewPos.x,0.5)+':'+quantize(viewPos.y,0.5)+':'+round(scale,3)
           + ':'+lod+':'+selectionRev+':'+viewRev+':'+W+'x'+H
пересчёт, если labelKey изменился; не чаще 1 раза за кадр; при неизменном ключе — переиспользование кэша
```

`selectionRev` инкрементируется в `graphApplySelectionLabels`, `viewRev` — при смене набора/фильтра, `lod` — в `graphApplyZoomLevel`.

## 6. Декор: отдельный Canvas-слой, а не «только CSS/опции»

**Решение: нужен Canvas-слой `fx`.** Чистые vis-опции и CSS физически не дают: трёхслойного свечения, бегущего импульса по реальному ребру, агрегированных «потоков» между компонентами, приоритетного отсечения подписей и внутреннего кольца «убеждений». Дополнительное подтверждение: `shape:'custom'/ctxRenderer` есть (§2), но рисование вернулось бы внутрь vis-кадра и потребовало бы `net.redraw()` на каждый импульс — это удвоение полного кадра (см. §10.2).

Устройство:

```
<div class="cognition-graph" ...>            (существующий контейнер, position:relative)
   [vis создаёт .vis-network > canvas]       — ядро/формы/рёбра рисует vis
   <canvas class="cog-fx" pointer-events="none">   — НАШ слой, z-index выше vis canvas
```

Порядок внутри `fx` (за спека §2.1): дальний ореол → ближний ореол → импульсы по рёбрам → агрегаты → подписи → кольцо/грань/блик активного узла. `pointer-events:none` обязателен; клики остаются у vis, а «Раскрыть» по агрегату обрабатывается в bubble-фазе на контейнере сцены (hit-test по центрам компонент в экранных координатах).

Геометрия слоя: `canvas.width = W·dpr`, `dpr = min(devicePixelRatio, 2)`; `ctx.setTransform(dpr,0,0,dpr,0,0)` — рисуем в CSS-px. Переустановка размера — в `ResizeObserver`, не на кадре.

Спрайты (кэш, никакого `shadowBlur` на 700 узлов):
- ключ `kind:round(screenRadius)`: `screenRadius = radiusNet·scale`; гранулярность 2 px; варианты `idle|hot` (обычный/выбранный-hover);
- бюджет ~`7 kind × 14 бакетов × 2 = 196` канвасов, создаются лениво, живут в `_cogScene.sprites`, сносятся вместе с `_cogScene`;
- ближний ореол — справка-спрайт `α` 0.22, дальний — 0.10; центр спрайта прозрачен (кольцевой градиент), поэтому ядро vis под ним видно;
- hover/выбор не пересоздают спрайт: берётся `hot`-вариант и добавляется один световой импульс.

Двойная отрисовка запрещена: `afterDrawing` используется **как сигнал кадра и источник камеры**, а рисует всегда только `_cogPaintFx(now)`. Точка входа одна: `afterDrawing → _cogPaintFx(t)`, `RAF → _cogPaintFx(t)` (§7). Один и тот же кадр не рисуется дважды — внутри `_cogPaintFx` стоит `if (t === this._cogScene.paintedAt) return`.

## 7. Анимация: живая карта при падающем CPU

1. Импульсы/дыхание обслуживает **только `fx`**. `net.redraw()` для анимации не вызывается ни разу (§6).
2. Постоянная «жизнь» (§7.1 спеки): пульсирует подмножество `P`, `|P| = min(24, ⌈nodes/30⌉, 24)` — центры компонент + top-K по degree + выбранный/соседи; период `T_i ∈ [3000, 5000] ms` по `hash(id)`, фаза `hash(id) mod T_i`. Пульсирует яркость/радиус **дальнего** ореола: `α = α0·(0.82 + 0.18·sin(2π·(t+φ_i)/T_i))`, `Δr ≤ 6 %`. Геометрия ядра не меняется.
3. Одиночный RAF-цикл с частотным потолком (иначе батарея и FPS без выгоды):
   `idle` — 24 fps; при `pan/zoom` (vis сам зовёт `afterDrawing`) наш `fx` рисуется из `afterDrawing`, собственный RAF на этот кадр не дублируется; `reduced-motion` — RAF не запускается вовсе.
4. Реактивные состояния (без новых таймеров): `hover` — 150–200 ms нарастание `α` (CSS-переход невозможен на canvas → интерполируем в `fx` по `performance.now()`); `click` — один импульс 600 ms по инцидентным рёбрам; `search` — 1–2 пульса найденного по 900 ms.
5. Импульс по ребру идёт **только по реальным рёбрам** из `view.edges` (спек §4.3): координаты концов берутся из кэша позиций, никаких «декоративных» линий между несвязанными узлами.
6. `prefers-reduced-motion: reduce` — сохраняем формы, контрасты, ореолы (статичный `α` = среднее), выделение, агрегаты, подписи; убираем RAF, импульсы, плавные `focus`/`moveTo` (`animation:false` — уже так в `:29273`, `:29688`, `:29867`).
7. Приостановка: `document.hidden` → `_cogPauseFx()` (существующий `onVisibilityChange:30608`, две строки); `IntersectionObserver` на `_cogEl` (threshold 0) → пауза при уходе сцены за вьюпорт; `activeTab !== 'status'` → граф уже сносится `:20983`. Возврат — `_cogResumeFx()`, который проверяет `this._cogScene && !fx.raf` (дубль исключён по построению).
8. Наблюдение (для приёмки §10.2 спеки): на `_cogScene` счётчики `netCount`, `rafActive`, `observerCount`, `spriteCount` доступны для проверки в консоли Playwright после 20 переключений.

## 8. Физика и камера

1. Стабилизация обязана завершаться (§6.1 спеки). Число итераций — по размеру набора, а не константа 150 (`GRAPH_PHYSICS_ITERATIONS:1470`):

| узлов | iterations | комментарий |
|---|---|---|
| ≤ 200 | 150 | текущее поведение |
| 201–400 | 90 | |
| > 400 | 60 | 702 узла: синхронная стабилизация не должна блокировать поток на секунды |

Дополнительно: `stabilization.fit = false` (кадр выставляем сами, §4.1), `adaptiveTimestep: true`, `minVelocity: 2.5` (ранний выход), `avoidOverlap: 0.5`, `springLength = 70·U`, `centralGravity: 0.3`, `damping: 0.09`, `barnesHut.gravitationalConstant: -8000`. Точные значения физики доводятся **по замеру** (критерий §10.3), контракт фиксирует структуру и требование «экранный просвет между связанными хабами ≥ 40 px при r = 1, пересечение ядровых кругов запрещено».

2. Терминация: `once('stabilizationIterationsDone')` + `once('stabilized')` (уже есть `:29207-29218`) → `setOptions({physics:{enabled:false}})`. Плюс страх: `watchdog = setTimeout(3000)`; если ни одно событие не пришло — `stopSimulation()` + `physics:false`. Таймер снимается в `destroyCognitionGraph`.
3. Idle CPU: после терминации нет ни физики, ни таймеров, ни RAF при скрытой сцене. Проверка: 60 с простоя → 0 кадров, `performance` без изменений (Playwright).
4. Камера: программный `focus` — `{duration: 420, easingFunction:'easeInOutQuad'}` (полоса 350–500 мс из §6.4 спеки); ручной жест — без анимации (vis сам). Ничего не меняется в существующих `focusGraphNode:29865`, `searchCognitionGraph:29690`.
5.Resize: при любом изменении размера контейнера (fullscreen ↔ embedded, открытие/закрытие колонки инспектора на десктопе) порядок строгий: `_cogCaptureCamera()` → изменение layout → `fitScaleRef` пересчёт → `moveTo({position: cam.position, scale: cam.scale, animation:false})`. `fit` не вызывается, выбор сохраняется по id. Это требование §6.6 спеки «камера пересчитывается к новым размерам без смещения/потери selection».
6. «Сбросить вид» (`graphResetView:29883`): фильтры/поиск **не сбрасываются** (спек §6.5), снимается только выбор и временное раскрытие агрегатов; камера → `_cogApplyFit()`.
7. Кнопка «Снять выбор» (новый явный путь в инспекторе) = `selectNodes([])` + очистка `_cogSelectedId`, камера не двигается.

### 10.2. Обязательные меры (все — в рамках функциональности)

1. `smooth: false` для всех рёбер (прямые линии). Визуально это «сигнальные линии», а не клубок; экономия — основной вклад в 45 FPS.
2. Кэш позиций и экранных координат (§5.1), никакого `canvasToDOM` на кадре.
3. Подписи — по `labelKey` (§5.8), не на каждый кадр.
4. LOD и выбор не трогают DataSet узлов; рёбра — один батч на переход состояния, частичные строки `{id, color:{opacity}, width}`.
5. Свечение — спрайты (§6), `shadowBlur` не используется нигде.
6. Импульсы — только в `fx`, без `net.redraw()` (§7.1).
7. Стабилизация по таблице §8.1 + `watchdog`; позиции чата кэшируются в `this._cogLayoutCache[chatScope]` (обычный объект, не реактивный), чтобы 20 переключений режима не запускали раскладку ни разу (`hasLayout:29078` уже это делает внутри сессии).

### 10.3. Измерение (обязательное, воспроизводимое)

- Наборы: 10 / 100 / 702 узла, рёбра 20 / 300 / 2400 (последний — реальная или семантически обезличенная копия топологии; спека §10.2).

- Обязательные счётчики для §10.2 спеки (после 20 переключений embedded↔fullscreen): `_cogScene.netCount`, `rafActive`, `observerCount`, `spriteCount`, число `listeners` у `net`.

`hideEdgesOnDrag`/`hideEdgesOnZoom`, скрытие узлов по LOD, отключение ореолов/подписей на desktop, второй движок (Three.js/Pixi/D3), `backdrop-filter` на сцене (сейчас корректно выключен через `data-glass="c"` — `app.css:2192-2203`; не менять на `a`/`b`), «деградация без замера».
