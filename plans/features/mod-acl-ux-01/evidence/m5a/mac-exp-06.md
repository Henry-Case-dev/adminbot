# MAC-EXP-06 — живой цикл OFF → ON → OFF без рестарта (прод 2.58.170)

Артефакт закрывает единственную оставшуюся живую строку среза **M5A**:
тик `experience_review_tick` зарегистрирован **всегда** и проверяет effective-гейт
**на каждом заходе**, поэтому пользовательский тумблер применяется без рестарта
процесса, а при OFF тик выходит **до любого SQL** (ноль работы).

Приёмка строки: «Лёгкий `experience_review_tick` регистрируется независимо от
пользовательского hot-тумблера и проверяет effective enablement внутри;
OFF→ON→OFF работает без рестарта».

## 2. Живой цикл (один и тот же процесс, без рестарта)

Метки времени — серверное локальное время дня релиза `2.58.170` (09.11.2026).
Ключ переключения — hot-настройка `memory.experience_learning_enabled`
(глобальная ось; chat-override не использовался). Аварийные env-гейты
`MCA_EXPERIENCE_LESSONS_ENABLED` / `MCA_EXPERIENCE_REVIEW_ENABLED` не заданы,
поэтому effective-значение определяла только UI-настройка.

| 1 | **OFF** (до цикла) | `GET /api/config` → `false`; живая проба: `review_enabled() = False`, статус тика `disabled`, `sql_execute_calls = 0` |
| 2 | **OFF**, штатный тик `22:24:12` | тик отработал и завершился `disabled`: задача не создана, в лог ничего не записано; `task_jobs` осталось **35** |

## 3. Почему это доказывает именно «регистрация всегда, гейт внутри»

Проверено чтением развёрнутого кода (`git show 42f068df:<файл>`), не отчётом Builder:

- `services/memory_maintenance.py` 376–392: `self._scheduler.add_job(self._tick_experience_review, ...)`
  стоит **вне** любого `if` — регистрация не зависит от состояния гейта при старте;
  интервал `_EXPERIENCE_REVIEW_TICK_SECONDS = 900`, `max_instances=1`, `coalesce=True`.
- `_experience_review_tick_enabled()` 182–193 — диагностический резолвер для витрины,
  в докстроке прямо зафиксировано, что он **не** условие регистрации.
- `services/mca_experience_jobs.py` 875–886: `tick_experience_review()` начинается
  с `if not review_enabled(): return "disabled"` — **до** чтения очереди и любых
  `db.execute`, то есть при OFF действительно ноль SQL.
- `review_enabled()` 687–695 = env-K1 (`MCA_EXPERIENCE_LESSONS_ENABLED`) ∧
  env-K3 (`MCA_EXPERIENCE_REVIEW_ENABLED`) ∧ UI `_learning_enabled()`
  (hot `memory.experience_learning_enabled`), fail-closed.

Отсюда наблюдаемое поведение: OFF не «снимает» джобу (она остаётся в планировщике
и тикает), а гасит её работу; ON подхватывается следующим тиком без рестарта
(в прогоне — в пределах одного 15-минутного интервала).

## 4. Границы: что этим артефактом не доказано

1. **Сырые транскрипты команд/запросов не приложены.** Наблюдения исполнены на
   живом проде DevOps/оркестратором; PM их не перепрогонял и дословные логи
   прогона в этот handoff не передавались. Артефакт фиксирует числа и статусы
   из handoff'а, а не заменяет их новым измерением.
2. **Аварийный env-гейт в живом прогоне не выключался.** Доказано только, что
   переменные не заданы и что при их OFF `experience_lessons_enabled()` /
   `experience_review_enabled()` возвращают `False` до любого SQL (код-путь,
   без отдельного живого прогона).
3. **M5C — ограниченный production-proof** (60–90 мин, отчёт §7.3–7.4 исходника)
   этим артефактом не выполнен и не заменяется.
4. **Строки §7/§15 карты** (`MAC-S0-12`, `MAC-S7-390…394`, `MAC-S15-06`,
   `MAC-S15-1-03…05`, `MAC-S7-BOUND-01`, `MAC-S7-LIMIT-01`, `MAC-S7-EDGE-01`,
   `MAC-S7-PROOF-01`) и вопрос `MAC-M5-01` остаются открытыми: по ним нет
   по-строчного вердикта Reviewer, и этот артефакт его не подменяет.
5. **VOICE-контур** (реальное голосовое владельца) к этой строке не относится.
