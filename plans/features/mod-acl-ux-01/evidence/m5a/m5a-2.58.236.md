## 2. Код

`semantic_stage_report(payload, counters)` (R17: только коды/числа):

- `semantic_stage_status`: `completed` / `partial` / `unavailable`;
- `semantic_partial`: bool;
- `semantic_partial_reasons`: `llm_unavailable`, `discover_error`,
  `read_error`, `parse_invalid`, `write_failed`, `budget_exhausted`,
  `truncated` (только непокрытая обрезка), `deferred`.
- `unavailable` — LLM недоступен и ни одна строка не выбрана; иначе
  `partial`.
- Снимок `semantic_progress` теперь отдаёт `stage_status`, `partial`,
  `partial_reasons`.

`completed` у job остаётся статусом выполненного прохода; он больше не
читается как «полное обучение». При `llm_unavailable` cursor не двигается,
durable retry/lag сохраняются; после появления LLM следующий job догоняет.
