# Release 2.58.214 — ограничения и честные пробелы (W2b B3)

Дата: 2026-11-17. Ветка `release/mod-acl-w2b3-2.58.214`, база/откат
`34c25d09` (2.58.213), content tip `2b57443a`. Статус: **REVIEW**, не
деплой и не VERIFIED.

## 1. Cross-chat содержимое журнала (design-ограничение, не дефект сборки)

- `loadModuleRuns` **не передаёт `chat_id`**: используется существующий
  global-admin `GET /api/oversight/runs?pipeline_type=…&limit=20`, который
  серверно не фильтруется по чату.
- Поэтому вкладка «История» у «Сводок» и «Источника случайности» показывает
  **до 20 последних прогонов ВСЕХ чатов**, а не только выбранной области.
- Каждая строка подписана своим `чат <id>` (реальный `chat_id` прогона), так
  что принадлежность видна и не подменяется.
- Сознательное решение: источник — существующий API, RBAC и контракт не
  расширялись; выборка по чату/области — **W2c/W3**, не этот релиз.
- Клиентская изоляция состояния при этом полная: кэш помечен `scope+epoch`,
  поздний ответ чужой области не применяется, строки разных источников не
  смешиваются (проверено node-юнитом и e2e A→B→A).

## 2. Копирайт для не-владельца на Summary/Random (LOW, backlog)

- Условие «Обзор»-блока обобщено с `id === 'mod_factcheck'` на
  `historyNeedsOwner(module)`, поэтому не-владелец на «Сводках»/«Случайности»
  видит существующую подсказку «Журнал проверок с источниками доступен
  владельцу бота…» — формулировка фактчека, не журналов сводок/случайности.
- Поведение честное (никакого запроса, никаких выдуманных строк), неточна
  только фраза. Косметика — LOW/backlog, чинится в W2c-полировке копирайта.

## 3. `available:false` печатается как «503» (LOW, backlog)

- Источник различает причины: `503` — ручка выключена, `available:false/
  enabled:false` — гейты наблюдаемости OFF (`_runs_disabled`). Оба состояния
  дают `off`.
- Текст панели/Обзора для `off` один: «История недоступна: журнал выключен
  (503)». Для `available:false` это неточно (это не HTTP 503), но и не
  «0 событий»: причина названа честно на уровне состояния.
- Расширение словаря причин — LOW/backlog (W2c-полировка состояний).

## 4. Деталь прогона запрашивается дважды (наблюдение, не B3)

- При переходе по ссылке `#/oversight?view=runs&run_id=…` деталь
  запрашивается 2 раза: `oversightApplyDeepLink` вызывается путём
  `applyRoute` и повторно существующим путём (тот же hash обрабатывается до
  выхода из маршрута). Поведение было в продукте до B3, продукт не менялся;
  e2e фиксирует `detail_gets >= 1`.
- Функционально корректно (деталь открывается по `run_id`); оптимизация —
  вне scope B3.

## 5. Изменённая существующая тестовая строка (документировано)

- `tests/js/round1025_f5_workspace_route_test.js` теперь ожидает `history` в
  карте вкладок `mod_summary` и полностью объявленную карту `mod_random`
  (H-2). Без этого полный JS-набор дал бы 116/5 вместо 117/4.
- Прочие pre-existing падения не ослаблялись и не правились.

- `BU_CDP_URL` не задан, `127.0.0.1:9222` и `127.0.0.1:19988` недоступны.
  Живая визуальная проверка этим каналом **не заявляется**; визуальный

  768/390/320, 113 flows, 0 pageerrors). Локальные скриншоты не коммитятся.

## 8. W3 (живые состояния) — вне релиза

- Живые `403/503/stale/disabled/permissions` и серверная доступность
  `oversight` на production не проверялись в этой сборке: это W3 на
  выкаченном SHA. Здесь состояния проверены детерминированно (node-юнит +
  e2e-стабы); `MAC-S10-16` остаётся за W3.

## 9. Прочее

- Cross-scope e2e использует стабы ответов (`B3_ROWS`), потому что серверный
  API не различает чат; проверяется изоляция клиентского состояния/кэша.
- Product content tip — `2b57443a`; evidence-коммит продукт/версию не
  меняет, `deployed_sha` манифеста остаётся `2b57443a`.
- Секретов в evidence нет; production в этой сборке не затрагивался.
- Строки `MAC-S5-TAB-01`, `MAC-S5-TAB-06`, `MAC-S5-EMPTY-01`, `MAC-AC-07`
  закрывает PM после review/deploy — этот релиз их не закрывает и не
  переводит в VERIFIED.
