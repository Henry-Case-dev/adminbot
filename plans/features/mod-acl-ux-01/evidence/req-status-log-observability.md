# Наблюдаемость отказов `/api/*` — контракт и граница (hotfix-meme-publication-initiative)

**Срез:** `web/request_status.py` + подключение в `web/app.py` + reason-коды в
`web/api/deps.py`; тесты `tests/test_webapp_request_status_log.py`.
**Коммит:** `6a5957cc` (ветка `integ/unify-release`), уточнение контракта —
отдельным коммитом вслед за ним.

## Зачем

Прод-инцидент: uvicorn запущен с `log_level="warning"`, Caddy не пишет
access-log, поэтому отказ Mini App нельзя было привязать к пути, статусу и
пользователю. В журнале были только успешные `[tma-auth]`-трейсы и 401 —
ни одного 403 и ни одного пути. Вопрос «какой именно запрос получил отказ»
был недоказуем по серверу.

## Что эмитится

Одна строка на каждый non-2xx ответ под `/api/*`:

```
[api-status] method=GET path=/api/admins status=403 user=5885953495 reason=permission_denied
```

- `path` — шаблон маршрута (`/api/avatar/{kind}/{tid}`), query string не
  входит; числовые id в путь не попадают;
- `user` — `telegram_id` аутентифицированного запроса, `-` если auth не
  проходил (middleware не зависит от auth-зависимости);
- `reason` — только allowlist: `missing_init_data`, `invalid_init_data`,
  `no_user_in_init_data`, `init_data_expired`, `permission_denied`,
  `not_global_admin`; иначе `-`;
- 5xx — та же форма с `exc=<ИмяКласса>`; текст исключения и трейсбек не
  дублируются (трейсбек уже логируется uvicorn);
- 2xx — ни строки, ни форматирования (полный access-log uvicorn не включён).

Никогда не пишутся: initData, заголовки, cookie, тела запросов, токены,
полные payload'ы пользователя, query string, текст `HTTPException.detail`.

## Граница наблюдаемости — правило чтения журнала

Middleware видит **только** HTTP-запросы под `/api/*`, дошедшие до ASGI-
приложения. Отказ, произведённый целиком **на клиенте** (до любого запроса:
UI-гейт маршрута в браузере, скрытая кнопка, локальная проверка прав),
строки **не порождает** — запроса не было.

Следствие, обязательное для диагноза:

- **отсутствие строки НЕ доказывает отсутствие отказа**;
- отсутствие строки означает только, что этот запрос не дошёл до данного
  ASGI middleware/приложения: он мог не быть отправлен, быть остановлен
  клиентом или завершиться на прокси/серверном слое до middleware;
- обратное утверждение верно всегда: строка есть ⇒ middleware видел запрос
  и ответил указанным статусом.

Поэтому при разборе «пользователю отказано» порядок такой:

- **строка есть** — отказ зафиксирован на уровне приложения: видно
  статус/путь/юзера/`reason`;
- **строки нет** — запрос не дошёл до middleware, и это НЕ означает, что
  отказа не было: он мог быть произведён на клиенте (UI-гейт до запроса),
  отклонён reverse proxy / инфраструктурой (Caddy, TLS, лимиты) или упасть
  на серверном слое до приложения. Такой отказ или ошибка этим журналом не
  виден и разбирается отдельно: клиентское поведение Mini App, access-log и
  конфигурация прокси, состояние процесса до старта ASGI.

Почему это не покрыто тестом: утверждение «клиентский отказ не логируется»
описывает событие, которого нет ни в ASGI-scope, ни в логах; тест на него
был бы тавтологией («в отсутствие запроса журнал пуст») и не мог бы упасть
при регрессии серверного кода. Дюрабельные тесты покрывают проверяемую
сторону границы: каждый реальный запрос даёт ровно одну строку, запросы вне
`/api` не логируются вовсе.

## Подтверждённая редакция (независимая проверка Reviewer)

Reviewer подал middleware путь длиной 1000+ символов, содержащий перевод
строки и возврат каретки, вместе с секретом в query string. Наблюдение:
**ровно одна строка длиной 258 символов**, без перевода строки, без секрета,
`reason=-`; `http.response.start` и тело ответа не изменились. Это
подтверждает: log-injection невозможен, ограничение длины работает, query и
служебные символы не утекают.

## Тесты

`pytest -q tests/test_webapp_request_status_log.py tests/test_webapp_deps.py tests/test_webapp_api.py`
— см. свежий прогон в коммите-уточнении; ключевые гейты: 403 с `user=<id>`
и полным набором redaction-проверок (initData/hash/bearer/cookie/query),
401 `missing_init_data` без id, `invalid_init_data`, `not_global_admin`,
тишина на 2xx и вне `/api`, 500 только типом, нормализация шаблона пути,
`root_path` за прокси.
