5. Контрактные уточнения (в рамках H-1…H-7, без новых API):
   - `oversight:summary.window` / `oversight:random.uses` — ОДИН read-API
     `GET /api/oversight/runs?pipeline_type=…&limit=20` (global admin,
     `global:true` без X-Chat-Id), ответ `{available,enabled,runs}`;
     `available:false`/`enabled:false` = off (проверяется ДО массива:
     серверный disabled отдаёт пустой `runs`), битый конверт = error.
   - Строки источника хранятся отдельно (`moduleRuns[source]`) — summary и
     random не делят стор; 30-с кэш помечен scope+epoch, поздний ответ
     чужой области отбрасывается epoch-guard'ом, уходящая область не
     оставляет `loading`-мету.
   - Деталь строки — СУЩЕСТВУЮЩИЙ deep link
     `#/oversight?view=runs&run_id=` (парсер `oversightParseDeepLink`,
     `oversightOpenRun`); без `pipeline_run_id` ссылки нет. Двойной запрос
     детали при переходе (2 вместо 1) — прежнее поведение пути
     applyRoute+oversightApplyDeepLink, не B3; продукт не менялся.
   - RBAC не расширен: для не-владельца `historyStateFor` = denied,
     запросов 0, вкладки нет; «Обзор» показывает прежнюю честную подсказку
     «доступно владельцу» (условие блока обобщено с `id === mod_factcheck`
     на `historyNeedsOwner(module)` — для sleep/nostalgia/experience
     результат тот же).
   - `WS_OVERVIEW_LIVE` не изменён; `history` не может стать дефолтом
     (`_wsDefaultTab`), pending не стирает память (H-4).
