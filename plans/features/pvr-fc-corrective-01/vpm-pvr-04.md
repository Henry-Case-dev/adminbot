# Visual Preservation Map — PVR-04 (новый визуальный язык реестра промптов)

Срез: PVR-FC-CORRECTIVE-01 / PVR-UI / PVR-04.0–04.3.1. Базовый кандидат: `evol/impl` @ `df02ab0c`
(PVR-BACKEND state-контракт d5ee97ef + PVR-UI презентация 9889d6e0 уже влитые).
Карта фиксирует, что сохраняется, что уточняется, что переносится и что перерисовывается —
до правки разметки. Семантика честного контракта не меняется: редизайн меняет визуальный
язык ВОКРУГ проверенных элементов, не их формулировки.

## REFINE — уточняется вокруг сохранённой семантики

- Шапка карточки разгружается: строка заголовка = название + бейдж области + «⋯»;
  состояние, «Сохранено <дата>», индикатор черновика и «История» уходят в ОДНУ компактную
  метанаходящуюся под заголовком строку (PVR-04.0). Слова состояния — из KEEP.
- Строка редакции: вместо кучи бейджей (серверные status_label «активная/неактивная/снята…»)
  — два спокойных ряда: имя «Версия от <дата>» + максимум ОДИН статус («Действует» /
  «Базовая» / «Недоступна») только когда уместен (PVR-04.2.3). Серверный `status_label`
  из строки уходит; источник рендерится по каноничной UI-карте («Вручную», «Из релиза»,
  «Импортирована», «Историческая», «Восстановлена»), серверный `source_label` — fallback.
- «Активная» перестаёт быть ярко-зелёной дважды (фон строки + бейдж): один спокойный
  маркер активной строки + один нейтральный чип статуса (политика оформления §118).
- Панель: ширина clamp(420px, 44vw, 520px) на desktop ≥960px (PVR-04.2.1);
  768–959px — центральный диалог вместо чрезмерного сужения; ≤767px — fullscreen sheet.

## MOVE — переносится без изменения поведения (те же обработчики/подтверждения/атрибуты)

- Кнопка «История версий» → вторичный текстовый пункт «История N» в метной строке карточки
  (`data-prompt-history-toggle` сохранён, ровно один в разметке). N — только честно
  известное число: список ревизий догружен полностью; иначе число не показывается
  (в API нет total — выдумывать нельзя).
- Операции строки («Посмотреть»/«Сравнить»/«Применить»/«Назначить базовой»/
  «Скопировать»/«Скопировать глобально») → экран деталей версии: «Сравнить с текущей» и
  «Скопировать» в футере деталей, primary «Применить» — только если версия отличается от
  действующей, «Назначить базовой» и «Скопировать в глобальные» — в меню «Действия»
  (PVR-04.2.4). data-атрибуты `data-pv-row-*` сохраняются на новых кнопках.
- Указатели панели («действует…»/«исходный из кода…»/«базовый по выбору владельца…») →
  единый блок «Сейчас действует» в неподвижной шапке панели (PVR-04.2.2),
  атрибуты `data-pv-panel-active/factory/baseline` сохранены.
- Переключатель «История действий» → тихая вторичная секция в конце списка (блок и
  формулировки прежние).

## REDESIGN — новое по строкам PVR-04

- Шапка панели: «История версий» (eyebrow) + название промпта + область («Этот чат» /
  «Глобально») + поиск по версиям (`data-pv-search`) + короткая справка о наследовании.
- Экран деталей версии внутри sheet: «Назад» (`data-pv-panel-back`), дословный текст
  (загружается при открытии, без пересохранения), причины недоступных действий, тонкий
  список событий применения выбранной версии, fixed-футер с главным CTA.
- Мобильный sheet: собственная шапка, «Назад» на деталях, нативная прокрутка тела,
  safe-area футера (`--ctl-safe-bottom`), без двухколоночных таблиц и горизонтального
  скролла (PVR-04.3.1).
- Спокойная токен-дисциплина: убираются декоративный backdrop-blur скрима и
  «стеклянное» размытие тела списка; сплошная спокойная поверхность панели, волосяные
  разделители, `tabular-nums` для дат/счётчиков; никаких новых `z-index` (токен
  `--z-panel` сохранён) и самодельных «ревизий act:/fac:» в видимых строках.

## Штампы времени в поясе чата (PVR-04.2.3)

Метки `created_at` в `/versions` приходят в UTC, а пояс чата уже есть в
существующем контракте: `GET /api/config/time` (UR-29.1/29.2) отдаёт `iana` и
`utc_offset`, считает их сервер (zoneinfo). Компонент версий читает этот
контракт при монтировании карточки и заново при открытии панели (кэш по
области чат/глобально + dedupe параллельных запросов) и форматирует метки
через `Intl.DateTimeFormat(timeZone: iana)`: «Версия от 07.11 15:02»,
«Сохранено …», «Сейчас действует», даты baseline. Аддитивных полей бэкенда не
требуется.

Если пояс получить не удалось (сеть/403) или сервер честно деградировал в
`utc_fallback`, UTC-цифры НЕ выдаются за местное время: карточка и блок
«Сейчас действует» показывают «пояс чата недоступен», а строки времени не
рисуются. Это проверяется e2e (основной сценарий +03:00 и отдельный сценарий
с `utc_fallback=true`).
