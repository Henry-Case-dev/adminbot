## Три блокера повторного ревью — что исправлено

### F1 (PVR-04.2.3 + C1.14): время истории — В ПОЯСЕ ЧАТА

- `pvShortWhen(iso, tz)` форматирует метку через
  `Intl.DateTimeFormat('ru-RU', {timeZone: iana, day, month, hour, minute})`.
  Через него идут: имя строки «Версия от …», метаданные событий,
  «Сохранено …», «Сейчас действует», «назначен/снят …».
- Источник пояса — **уже существующий** контракт `GET /api/config/time`
  (UR-29.1/29.2, считает сервер через zoneinfo): `iana`, `utc_offset`,
  `utc_fallback`. Аддитивных полей бэкенда не требуется.
- Загрузка: при монтировании карточки (метанстрока «Сохранено» видна до
  открытия панели) и заново при открытии панели; кэш разделён по области
  (чат/глобально) + dedupe параллельных запросов. На прогоне 11–12 запросов
  `/api/config/time` на ширину при десятках карточек.
- Честная деградация: если пояс не получен (сеть/403) **или сервер сам
  ушёл в `utc_fallback`**, UTC-цифры не выдаются за местное время —
  карточка и блок «Сейчас действует» показывают «пояс чата недоступен»
  (`data-pv-tz-unavailable`, `data-pv-panel-tz-unavailable`), штампы строк
  не рисуются.
- E2E: зона `Europe/Moscow` (+03:00) в стабе `/api/config/time`; строка
  rev-002 (`2026-11-03T12:02:00+00:00`) показывает **15:02**, и отдельный
  assertion «UTC-цифры выданы за время чата» краснеет, если вернуть ISO-цифры.
  Час каждой из первых трёх строк сверяется с `created_at` + 3 ч.
- Отдельный сценарий (390): `utc_fallback=true` → метка недоступности видна,
  «Сохранено …» отсутствует, ни одна строка не печатает время.

### F2 (PVR-04.4.3/04.3.1): 44 px у КАЖДОЙ цели в мобильной панели

- В мобильном блоке `pv-*` добавлено правило:
  `.pv-panel button, input, select, textarea, [role="button"], .more-menu-item
  { min-height: 44px }`. Раньше выпадали «Закрыть» (34 px), «Показать более
  ранние версии» (34 px), «История действий» (34 px) при строках/CTA 44 px.
- E2E измеряет ВСЕ видимые интерактивные узлы внутри `[data-pv-panel]` в трёх
  состояниях (список / «История действий» / экран деталей) на 390/360/320.
  Замер этого прогона: **min_h = 44.0** во всех девяти замерах; «Закрыть»,
  «Показать более ранние версии», «История действий», «Действия…»,
  «Сравнить с текущей», «Скопировать», «Применить», «Назад» — 44 px.
  Горизонтальный скролл 0 px на 1536/1440/1366/768/390/360/320.

### F3 (PVR-04.1.4): read-only статус с причиной — на любой поверхности

- Блок `[data-pv-readonly]` вынесен из `v-if="variant === 'card'"`: он
  рендерится для card/bar/history. Каталог (`variant="history"`,
  `can-edit=false`) — это ровно та поверхность, где промпт из кода раньше
  показывался без честного статуса.
- E2E: в каталоге выбирается промпт, `/versions` отдаёт `manageable=false`
  (`STATE["code_only"]`), проверяется **видимый** `[data-pv-readonly]` с
  текстом «Только чтение: значение задаётся кодом, а не в базе…», отсутствие
  `[data-pv-save]` и отсутствие активного `textarea`.

## Что именно проверяет e2e (ключевые пункты)

- **Selection ≠ active.** Клик по строке (rev-004) → «Назад» → в списке
  `.is-selected` остаётся на rev-004, `.is-active` — на rev-002; строка
  одновременно не бывает и selected, и active.
- **Поиск честно называет область.** На загруженных 50 из 130 версий запрос
  «rev-099» даёт 0 строк, текст про «среди загруженных 50… более ранние ещё
  не загружены», строку области «Найдено 0 из 50 загруженных» и доступную
  догрузку. После догрузки rev-099 находится. Ложной формулировки
  «сохранённых версий нет» в этой ветке нет.
- **«История N» без ложного итога.** Первая страница (`has_more=true`) —
  числа нет; третья (130) — ровно «130» и признак конца истории; после
  перемонтирования из кэша «История 50» не появляется.
- **Время в поясе чата** (см. F1) — заголовок «Сейчас действует», строки,
  «Сохранено …»; честная деградация при `utc_fallback`.
- **После «Применить»** экран деталей закрывается, возвращается список с
  прилипшим подтверждением сервера и новым активным маркером.
- **503 из открытого экрана деталей**: честная метка и «Назад», списочный
  футер под экраном деталей не всплывает.
- **Строки редакций** не печатают сырой Telegram-id чата: область названа
  словами («этот чат · Чат A», «другой чат», «глобально»).
- **Тонкий список событий** при `activations_page.has_more` не утверждает
  «Применений этой версии в журнале нет», а говорит о незагруженных событиях
  и даёт свою догрузку.
- **Консоль/страница**: на каждый прогон навешены `page.on("console")` и
  `page.on("pageerror")`; любая ошибка JS/ресурса — красный результат.
  Исключение только для НАМЕРЕННОГО сценария «журнал недоступен» (503
  `/api/prompts/…/versions`), который сам проверяется отдельными assertions.
- **Ширины**: 1536/1440/1366/768/390/360/320 — 7 ширин × 10 сцен + 2
  спец-снимка (каталог read-only, недоступный пояс) = **72 снимка**.

## Честный контракт — подтверждение сохранности (формулировки не менялись)

- Метки происхождения: «Действует в этом чате» / «Действует глобальная версия»
  (+ «наследуется чатом») / «Исходный из кода» — дословно (`data-pv-state`).
- Unmatched: «Не сопоставлено с историей», `activeLabel` = «не сопоставлено с
  историей», в подробностях «действующая ревизия: не сопоставлена» — дословно.
- Drift-баннер с текстом «ни одна версия не помечена активной…» (`data-pv-drift`,
  `role="alert"`) — дословно; при drift ни одна строка не активна.
- 503: «История временно недоступна: …» (`data-pv-panel-error`), редактор не
  прячется при недоступном журнале — дословно.
- Основной список = только revisions (`revisions_cursor`); события активации —
  вторичная «История действий» (`activations_cursor`), статус «была применена»,
  без кнопок «Применить»/«Назначить базовой».
- Sticky-подтверждение действия первым в теле панели с явным × (B4), переживает
  перечитывание; «Назначить базовой» не активирует и не меняет действующий текст.
- Честные причины недоступных действий (retired / несовместима / code-only /
  нет прав / журнал недоступен) — в деталях версии (`data-pv-row-reason`);
  теперь та же честная причина видна и на read-only поверхностях
  (`data-pv-readonly`, PVR-04.1.4).

## Что изменилось в визуальном языке (до → после)

- Карточка редактора: было — свалка бейджей/кнопок в одной шапке; стало —
  заголовок + область + «⋯», ниже одна метанстрока (честное состояние ·
  «Сохранено <дата в поясе чата>» · черновик · вторичный пункт «История N»).
- Панель: было — 560px, мета-строка с 4 указателями, легенда, кнопки под каждой
  строкой; стало — 420–520px, неподвижная шапка (eyebrow «История версий»,
  название, область, поиск, справка), ОДИН блок «Сейчас действует», спокойные
  строки «Версия от …» с максимум одним статусом, selection ≠ active.
- Детали версии: экран деталей («Назад», дословный текст по GET, причины,
  тонкий список событий, diff) с футером «Сравнить/Скопировать/Применить» и
  меню «Действия».
- Мобильное: fullscreen sheet по `--app-usable-height` с safe-area-футером,
  detail-screen с «Назад», CTA в фиксированном футере; **все** интерактивные
  цели панели ≥44 px (проверено замерами, а не только строками).
- Убраны декоративный backdrop-blur скрима, фиолетовый inset базовой строки,
  дублирующие бейджи, массивы одинаковых кнопок под строками.

Шрифтовая дисциплина: новых микроразмеров в блоке нет — служебные подписи
используют существующие токены `--ctl-font` / `--ctl-font-sm`.

## Поиск по истории (честное ограничение)

Поиск по версиям ищет по ЗАГРУЖЕННОЙ части истории (серверного поиска в
контракте нет): это не скрывается — область поиска названа в интерфейсе, а
догрузка доступна прямо из отфильтрованного списка.
