## Что именно проверяет e2e (ключевые новые пункты)

- **Selection ≠ active.** Клик по строке (rev-004) → «Назад» → в списке
  `.is-selected` остаётся на rev-004, `.is-active` — на rev-002; строка
  одновременно не бывает и selected, и active. При регрессии («Назад» стирает
  выбор») ожидание не наступает и тест краснеет по таймауту.
- **Поиск честно называет область.** На загруженных 50 из 130 версий запрос
  «rev-099» (существует, но лежит на непрочитанной странице) даёт 0 строк,
  текст «Среди загруженных 50 версий совпадений нет… более ранние версии ещё
  не загружены», строку области «Найдено 0 из 50 загруженных» и доступную
  кнопку догрузки. После догрузки (100 из 130) тот же запрос находит rev-099 —
  версия не «теряется». Ложная формулировка «сохранённых версий нет» в ветке
  «страницы не загружены» отсутствует.
- **«История N» без ложного итога.** Первая страница (`has_more=true`) — числа
  нет; вторая (100 из 130) — числа нет; третья (130, `has_more=false`) — ровно
  «130» и признак конца истории. Отдельно: перемонтирование карточки
  (уход/возврат по маршруту в пределах кэша состояния, без нового GET
  `/versions`) не показывает «История 50».
- **После «Применить»** экран деталей закрывается, возвращается список с
  прилипшим подтверждением сервера и новым активным маркером (библиотека и
  раздел «Характер»).
- **503 из открытого экрана деталей**: видна честная метка и «Назад», а
  списочный футер (включая «Вернуть исходную из кода») под экраном деталей не
  всплывает.
- **Строки редакций** не печатают сырой Telegram-id чата (`-100500…`):
  область названа словами («этот чат · Чат A», «другой чат», «глобально»).
- **Тонкий список событий** при `activations_page.has_more` не утверждает
  «Применений этой версии в журнале нет», а говорит о незагруженных более
  ранних событиях и даёт свою кнопку догрузки.

## Честный контракт — подтверждение сохранности (row-verified формулировки не менялись)

- Метки происхождения: «Действует в этом чате» / «Действует глобальная версия»
  (+ «наследуется чатом») / «Исходный из кода» — дословно (`data-pv-state`).
- Unmatched: «Не сопоставлено с историей», `activeLabel` = «не сопоставлено с
  историей», в подробностях «действующая ревизия: не сопоставлена» — дословно.
- Drift-баннер с текстом «ни одна версия не помечена активной…» (`data-pv-drift`,
  `role="alert"`) — дословно; при drift ни одна строка не активна.
- 503: «История временно недоступна: …» (`data-pv-panel-error`), редактор не
  прячется при недоступном журнале — дословно.
- Основной список = только revisions (`revisions_cursor`); события активации —
  вторичная «История действий» (`activations_cursor`), статус «была применена»,
  без кнопок «Применить»/«Назначить базовой».
- Sticky-подтверждение действия первым в теле панели с явным × (B4), переживает
  перечитывание; «Назначить базовой» не активирует и не меняет действующий текст.
- Честные причины недоступных действий (retired / несовместима / code-only /
  нет прав / журнал недоступен) — в деталях версии (`data-pv-row-reason`).

## Что изменилось в визуальном языке (до → после)

- Карточка редактора: было — свалка бейджей/кнопок в одной шапке; стало —
  заголовок + область + «⋯», ниже одна метанстрока (честное состояние ·
  «Сохранено <дата>» · черновик · вторичный пункт «История N», N — только
  честно известное число, пока история не догружена целиком числа нет).
- Панель: было — 560px, мета-строка с 4 указателями, легенда, кнопки под каждой
  строкой (до 6 одинаковых), серверные status_label на каждой строке; стало —
  420–520px (в пределах требуемых 420–540), неподвижная шапка (eyebrow «История
  версий», название, область, поиск по версиям, справка о наследовании), ОДИН
  блок «Сейчас действует», спокойные строки «Версия от …» с максимум одним
  статусом («Действует»/«Базовая»/«Недоступна»), selection ≠ active.
- Детали версии: было — inline-«Посмотреть» + кнопки в строке; стало — экран
  деталей («Назад», дословный текст по GET, причины, тонкий список событий
  применения версии, diff) с футером: «Сравнить с текущей», «Скопировать»,
  primary «Применить» (только если отличается), меню «Действия» (Назначить
  базовой / Скопировать в глобальные).
- Мобильное: было — fullscreen sheet без detail-экрана и safe-area; стало —
  sheet по `--app-usable-height` с safe-area-футером, detail-screen с «Назад»,
  CTA в фиксированном футере (проверено геометрией на 390/320), строки ≥44px.
- Убраны: декоративный backdrop-blur скрима, фиолетовый inset базовой строки,
  дублирующие бейджи, массивы одинаковых кнопок под строками.
- Мобильная шапка панели (найдено визуальным осмотром, ≤767px): eyebrow
  «История версий» и название промпта получали по 2 строки в узкой колонке
  рядом с бейджем области и «Закрыть»; теперь заголовок занимает свою строку,
  область и «Закрыть» — следующую (`.pv-panel__titles { flex: 1 1 100% }`).

Шрифтовая дисциплина: новых микроразмеров в блоке нет — служебные подписи
используют существующие токены `--ctl-font` / `--ctl-font-sm` (0.9rem / 0.8rem).
Прежняя формулировка отчёта про «удалённый микрошрифт 10px» была неточной: в
блоке `pv-*` 10px не применялся ни до, ни после среза.

## Визуальный осмотр настоящей отрисовки (не только ассерты)

Проведён на локальном стенде (`web/` + правдивые ответы `/api/**`, 130 ревизий)
в реальном Chromium: 1440×900 и 390×900/844.
Наблюдено глазами на снимках и подтверждено измерениями DOM:
выбранная строка (14:04) остаётся нейтрально подсвеченной после «Назад», активная
(12:02) несёт бирюзовое ребро и чип «Действует», панель 520 px на 1440 и
полноэкранный sheet на 390, шапка мобильного sheet в одну строку после правки,
футер деталей с «Сравнить/Скопировать/Действия/Применить» целиком во вьюпорте
(CTA 44 px, `elementFromPoint` попадает в кнопку), горизонтального скролла нет.

Честное ограничение канала: Browser Use MCP в этой сессии недоступен (каталог
проверен один раз), встроенный десктопный браузер сессии не подключён, поэтому
осмотр сделан реальным Chromium через Playwright MCP — не вторым независимым
браузером. Детерминированные проверки (геометрия/состояния/ширины) идут в
`tests/ui_prompt_version_card_e2e.py`.

## Ограничение (честно, не маскируем)

PVR-04.2.3 требует «дата/время в TZ чата»; бэкенд-контракт `/versions` отдаёт
`created_at` в UTC без поля TZ чата (сервисы срезом не трогаются по правилам).
UI показывает штампы API как есть, без выдуманной конвертации. Для честной
конвертации нужно аддитивное поле бэкенда — вынесено отдельной задачей.

Поиск по версиям по-прежнему ищет по ЗАГРУЖЕННОЙ части истории (серверного
поиска в контракте нет): это не скрывается — область поиска названа в
интерфейсе, а догрузка доступна прямо из отфильтрованного списка.
