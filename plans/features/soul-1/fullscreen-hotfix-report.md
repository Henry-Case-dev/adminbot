## 2. Что исправлено

**Кнопка (один DOM-узел `.header-fs-btn`, слот — inline/row A).**
- Кнопка видима на ВСЕХ клиентах, где реально есть API (включая Telegram
  Desktop); скрытие — только при настоящем отсутствии API (вне Telegram или
  нет ни `requestFullscreen`, ни `exitFullscreen`). Платформенных запретов нет.
- Стиль «как у нативных»: прозрачный фон, без круга/стекла/`backdrop-filter`,
  иконка 18px, hit-цель ≥44×44 (U07.2/U01).
- Позиция — от РЕАЛЬНОЙ геометрии, без fixed-координат: шапка начинается под
  нативной зоной, посчитанной как `max(env safe-area-top, --tg-safe-area-inset-top)
  + --tg-content-safe-area-inset-top` (сумма «система + Telegram UI»;
  официальные определения insets + рекомендация tma.js#695). При нулевом
  `--tg-content-safe-area-inset-top` формула в точности равна прежней
  max-формуле фикса `d9b7f389` — стандартная мобильная шапка не меняется
  (измерено: 116.2px на 320/360/390, shell-e2e «failed_checks: {}»).
- Fixed-координаты намеренно НЕ используются: реальных координат нативных
  кнопок клиента WebView не знает — официального API для них нет
  (Telegram-Mini-Apps/issues#62, открыт 10.01.2025). Поэтому «рядом с
  нативными» реализовано честно: кнопка вплотную ПОД нативной панелью, у
  того же правого края, с нулевым пересечением зон (проверяется rect-тестом).

**Геометрия по состояниям (измерено, mock-клиент, финальный код; числа
динамических прогонов ±2 px — значения из отчёта и из review-fs сходятся в
пределах этой погрешности):**

| Состояние | header | кнопка | нативная зона | пересечение |
|---|---|---|---|---|
| Android 390 портрет (safe=0, csa=36) | 152px (было 189) | 44×44 @ y=46 | 0..36 | 0 px² |
| Android 390 + safe=24 (реальный Android) | 176–178px | 44×44 @ y=70–72 | 0..60 | 0 px² |
| Android 320 + safe=24 | 176–178px | 44×44 @ y=70–72 | 0..60 | 0 px² |
| Android 667×375 landscape (harness: safe=0, csa=24) | 111px | 44×44 @ y=26 | 0..24 | 0 px² |
| Android 667×375 landscape (live-рендер: safe=24, csa=24) | 134–135px | 44×44 @ y=50 | 0..48 | 0 px² |
| tdesktop 1024×768 | 111px | 44×44, top-right | — | — |

Контент шапки не перекрывается кнопкой в этих состояниях (проверка площадей
пересечений = 0). Полноэкранный режим клиента (`fullscreen-mode`) занимает
видимую область целиком — высота шелла по-прежнему из `--app-usable-height`.

**Android landscape.** Вертикальные отступы шапки срезаны
(`padding: .35rem → .15rem`, `row-gap: .15rem → .1rem`), селектор чата 36→32px;
навигация row B уже была компактной (иконка 16px, min-height 32px). Архитектура
навигации не менялась (Статус / Аналитика / Модули / Ещё). Логотип AdminBot
оставлен: измеренная ширина 667/320 даёт запас (overflow=0), а директива
разрешает его скрывать только «если не хватает ширины» — нехватки нет.

**Landscape-высота честно:** 134px при 375px экрана — это 48px нативной зоны
клиента + 44px hit-цель кнопки ⛶ (U07.2 требует 44×44) + 35px навигации;
собственные «лишние» отступы убраны.

**Windows Desktop.** Восстановлен прежний рабочий переключатель: кнопка в
строке A, `toggleFullscreen()` → политика → `requestFullscreen()` /
`exitFullscreen()` (никаких WinAPI/moveTo/resizeTo/CSS-100vw). Авто-выход из
стартового fullscreen (прежний «мягкий exit» на tdesktop) удалён — политика
больше не выводит клиента из запрошенного владельцем режима; при старте в
Launch Mode=Fullscreen кнопка сразу предлагает ВЫХОД, второго request нет.
Ошибка хоста (`fullscreenFailed`) → тост с причиной, состояние не выдумывается.
