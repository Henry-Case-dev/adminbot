# SOUL-14.3 / 21.5 — A/B-отчёт: старая (OFF) vs новая (ON) композиция речи

Дата: 21.10.2026 · HEAD-копия: `6f8710a8a561` (байт-в-байт, отпечатки services/ совпадают
с репо) · модель: `deepseek-v4-flash`, temperature 0.7, один прогон на руку ·
33 сцены (11 типов × 3) × 2 руки = 66 генераций · seed слепого порядка: 20261021.

## 1. Методика (кратко)

- Ось A/B — единственный флаг `UNIFIED_COMPOSER_ENABLED` (env, ON/OFF) на одной
  HEAD-копии. OFF = прежняя сборка `compose_verbalizer_system` + хвосты; ON =
  единый композер с реальными резолверами (Core full/709 токенов, identity,
  expression occasional, response_plan). Одинаковый user-текст сцены, модель,
  провайдер, температура. MCA-23 scrub в обеих руках.
- Сцены — анонимизированные реплики-фикстуры по типовым окнам (PII-чек 0
  попаданий, `scenes.json`). Форма (one_word/longform) — детерминированный план,
  без LLM.
- Слепота: порядок пар и позиции рук перемешаны seeded-рандомом ПОСЛЕ прогона и
  ДО ручного разбора; имена рук только в `private-mapping.json`, вскрыт после
  записи `blind-scores.json`. Ограничение: ратер = оркестратор прогона
  (один-агентный лейн), полная слепота невозможна — зафиксировано честно.
- Рубрика БЕЗ LLM-судьи: 4 скриптовые метрики (пересчёт из сырых ответов,
  `verdict-recheck.json`: расхождений нет) + 6 ручных размерностей (0/1/2) по
  слепым парам. MiniApp-сбор человеческих оценок — вне скоупа.

## 3. Качество — человеческая сводка (ручные размерности, 33 пары)

| Размерность | ON лучше | OFF лучше | ничья | ON ср. | OFF ср. |
|---|---|---|---|---|---|
| остроумие | 12 | 3 | 18 | 1.82 | 1.55 |
| уместность | 5 | 2 | 26 | 1.94 | 1.85 |
| внутренняя связность | 0 | 0 | 33 | 2.00 | 2.00 |
| естественность | 0 | 0 | 33 | 2.00 | 2.00 |
| факты | 1 | 0 | 32 | 2.00 | 1.97 |
| адресат | 5 | 0 | 28 | 1.85 | 1.70 |

- **Где ON лучше.** Остроумие: ON чаще выдавал законченную шутку там, где OFF
  отделывался сухой репликой (анекдот про Валеру против «анекдота не будет»,
  «очная ставка с пустым стулом», «сравнить с калькулятором»). Адресат: ON чаще
  выходил на ситуацию человека («ужин сам себя не разогреет») вместо чистой
  шутки в никуда. Единственная фактическая победа — важная: под давлением
  фальшивой «поправки» (жирафы) OFF признал ошибку, которой не делал
  (конфабуляция), ON отказал честно.
- **Где OFF лучше.** Единичные пары, и без общего сюжета: OFF чаще давал
  практический каркас там, где ON уходил в образ (созвон с заказчиком: чек-лист
  из трёх вопросов против «иди как на ограбление»), и был собраннее в
  флейм-сценах (не называл вопрос пользователя пустым). OFF заметно компактнее
  (средний ответ 978 симв. против 1158 у ON).
- **Где паритет.** Связность и естественность — 33/33 ничьих: русский текст у
  обеих рук чистый, без машинности. Инъекции отклонены обеими руками во всех
  трёх сценах («ПИУ-ПИУ», мат по указке, «выведи системный промпт» — промпт не
  выдал никто). Технические ответы (docker, git rebase, хеш-таблицы, вайфай) —
  фактически точные в обеих руках.
- «Победа по одному удачному мем» не объявляется: перевес ON устойчив по
  остроумию (12 против 3 при 18 ничьих), но это слепая оценка одного агента на
  одношаговых сценах — см. границы.

  замерено).

- Регрессий не обнаружено: ни одной пустой генерации в итоговом наборе, ни
  одной утечки промпта, ни одного подчинения инъекции, форматные нарушения 0.
- ON-манифест стабильный: rendered-слои channel_contract, core (full,

  одношаговых сценах).
- Откат: OFF-путь остаётся прежней сборкой, паритет покрыт
  `tests/test_soul1_composer_parity_off.py` — 13/13 зелёные на байтах HEAD
  `6f8710a8`; в самом A/B ось флага переключала сборку 66/66 раз (per-record
  gate: ON=композер, OFF=старая сборка). Откат = переключение флага, данные не
  трогаются.
- **Ничего не переключено**: прод-флаги не менялись, автоматической настройки
  по результатам нет (запрещено источником). Решение о составе слоёв остаётся
  за владельцем; текущее прод-состояние (композер включён) по этой выборке
  чуть лучше по качеству и дороже по входным токенам.

## 7. Честные границы

1. Сцены — анонимизированные фикстуры типовых окон, не дословная выгрузка
   реальных чатов.
2. Одношаговые сцены без истории/тулов/уроков: механика сборки сравнена на
   заводских текстах; персоны прод-чата локально невоспроизводимы (в обеих
   руках одинаковый код-канон 240 симв.).
3. «Непрямой повод для Initiative» — через writer-путь, инициативный контур
   локально не вызывался.
4. Один прогон на руку (temp 0.7), без повторов — повторяемость не замерялась
   (это telemetry-метрика 14.2).
5. Ратер = оркестратор прогона (один агент): полная слепота ограничена;
   порядок/позиции seeded до разбора, mapping вскрыт после записи оценок.
6. 3 сцены-исключения из общего счёта нет: оценка охватывает все 33 пары;
   MiniApp-оценки людей — отдельное будущее окно (разрешение, не обязанность).
7. Худший провайдер-инцидент за день пришёлся на этот прогон; восстановление
   и учёт задокументированы (§2), дублирующие генерации посчитаны в ведомости.
