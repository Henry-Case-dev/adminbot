## Наблюдённый дефект (первый прогон 2.58.87)

- `deploy-run.txt` §F2: `RESTART_T0=%Y-%m-%d %H:%M:%S` — литерал вместо таймстампа: строка
  F2 не участвовала в `%`-форматировании Python, поэтому `%%` дошли до shell-`date` и после
  подстановки дали литеральный `%`. Дополнительно `echo RESTART_T0="$T0"` не выводит кавычки,
  а Python-захват ожидал `RESTART_T0="…"` → `t0=""` → F3/F5/J шли с пустым `--since`
  (вакуумный срез: WITHHELD=0/GRACEFUL=0 — `final-verification-firstrun-vacuous-journal.txt`).
- Перепроверка (read-only, корректный T0 вручную) — `final-verification.txt`; изоляция/healthz
  и прод-следы не пострадали (REV-REL-25887 §4).

## Патч

`deploy_25887-t0-hardening.patch` (sha256 `917d60e1…`), 3 хунка, применяется `git apply -p1`
в каталоге скрипта (проверено: `--check` rc=0; применённый файл байт-идентичен эталону).

1. **T0-substitution:** `'+%%Y-%%m-%%d %%H:%%M:%%S'` → `'+%Y-%m-%d %H:%M:%S'`
   (литерал не проходит `%`-форматирование Python — `%%` был багом) и `echo RESTART_T0=$T0`.
2. **fail-fast:** захват `RESTART_T0=(\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2})` (F2 и J);
   пустой `t0` → `_rb("T0 capture failed")` + abort: F3/F4/F5/G/J не выполняются на сломанном
   анкере, прод автоматически возвращается на предыдущую проверенную версию.
3. **канонический F3:** PID-анкерный `soul87_f3.sh` (вместо stale-окна `--since -12min`
   из 2.58.86-нита) — приложен копией; для следующих релизов использовать его же.
