# SOUL-1 / W6 — evidence «Речь и характер» (MiniApp-поверхность)

Что здесь лежит и как это воспроизводится.

## Артефакты

| Файл | Что доказывает | Как получить |
|---|---|---|
| `api-fixture.json` | формы данных, которые реально отдаёт `web/api/speech.py` (витрина, характер, стиль, выражение, юмор, примеры, обучение, возможности, Inspector, блоки, предпросмотр, «Попробовать») | `.venv/Scripts/python.exe plans/features/soul-1/evidence/w6/dump_api_fixture.py` |
| `ui-report.json` | прогоны по 320/360/390/430/768/1024/1440 + landscape: overflow страницы, тач-цели, число колонок, скролл длинных строк внутри компонентов, список POST-вызовов, тексты confirm-диалогов защиты черновиков | `.venv/Scripts/python.exe tools/ui_soul1_w6_speech_e2e.py` |
| `shots/*.png` | витрина раздела, вход внутри «Личности и стиля», каждый раздел, состояния сохранения на каждом viewport | тот же прогон (по умолчанию со скриншотами) |
| `roundtrip-tests.txt` | реальный round-trip правок через API реестра: правка полной/компактной редакции характера, чат-оверрайд без изменения глобального, заводской сброс, откат, стиль/выражение/сбросы, RBAC 403 | `.venv/Scripts/python.exe -m pytest tests/test_soul1_w6_speech_ui.py -q` |
| `glass-and-ui-suites.txt` | существующие стеклянные/UI-сьюты остались зелёными после правок `web/**` | команды внутри файла |

## Живая визуальная проверка

`.venv/Scripts/python.exe tools/ui_soul1_w6_speech_e2e.py --serve-only` поднимает
демо-сервер (`http://127.0.0.1:8815/web/#/ai/speech`) с теми же ответами API
(сервер отдаёт `/api/speech/*` из `api-fixture.json` и базовые стабы матрицы),
чтобы страницу можно было открыть в реальном браузере и посмотреть глазами —
Playwright-скриншоты и живой просмотр дополняют друг друга.

## Границы

* Playwright-прогон использует route-стабы `/api/*` (прецедент
  `tools/ui_asap8_w2_shell_e2e.py`), но формы ответов взяты у настоящего слоя
  (`dump_api_fixture.py`), а не выдуманы в тесте.
* Реальный Telegram-клиент/провайдер в этом слайсе не гоняется: живая отправка
  в чат — гейт владельца (см. отчёт слайса, раздел «что осталось»).
* `character.expression` («Выражение») — owner-документ на существующем
  контуре `bot_settings`/`chat_params`; рендер слоя проверяется композером
  (Inspector/«Попробовать»), а подключение слоя на боевом пути Direct —
  отдельный слайс владельца (в манифесте честная причина `expression_absent`).
