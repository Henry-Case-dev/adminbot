## 4. Сравнение: критерии без LLM-судьи (сверено с директивами)

- L529: никаких вторых LLM-писателей/обязательных постпроцессоров; L882: качество не объявляется баллом судьи; L195: данные не выдумываются, нули видны как нули, честные stale. → **LLM-судья не используется вовсе** (не нужен + экономия ~30–50 вызовов + прецедент AMD.8.2 VERIFIED без него).
- **Скриптовые детерминированные метрики**: соблюдение длины (точный one_word compliance, слова/символы), мат (лексикон проекта), устойчивость к prompt injection (детерминированные маркеры выполнения вброшенной инструкции), разнообразие (межсценовое 3-граммное перекрытие по вариантам), повторяемость.
- **Ручной бинд-разбор аналитиком** (агент): остроумие, уместность, связность, естественность, факты, адресат — по рубрике, по слепым парам; вердикты перевыверяемы из захватов (паттерн `amd82-verdict-recheck.json`).
- MiniApp-сбор человеческих оценок — **вне скоупа** (разрешение, не обязанность; отдельное будущее окно).

## 5. Волны (один Builder-лейн, строгая сериальность; write-scope не пересекается с 14.1/14.2)

- **W1 — харнес + фикстуры сцен.** Скоуп: `plans/features/soul-1/evidence/ab/**` (новое: `scripts/ab_harness.py` — форк amd_probes_harness, `scenes.json` 30–50 анонимизированных сцен, покрытие 11/11 типов проверено скриптом, `README.md`). Свежий `git archive HEAD` + SHA фиксируется при прогоне. Приёмка: харнес dry-run без платных вызовов проходит, сцены анонимизированы (скрипт-чек PII-паттернов), манифест обеих рук рендерится.
- **W2 — прогон + разбор.** Скоуп: тот же `evidence/ab/**` (`results.json`, слепые ответы, `blind-order.json` seeded, ручной разбор, `verdict-recheck`). Приёмка 14.3: ≥30 сцен × 2 руки реальные генерации одной модели/провайдера/temperature, слепой порядок с фикс. seed, 10 оценок на пару, счётчик вызовов захвачен, итоги не объявляют победу по одному удачному случаю; манифесты обеих рук приложены.
- **W3 — биндинг + отчёт.** Скоуп: `requirements-map.json` (14.3 evidence→VERIFIED при реальном доказательстве; 14.4 REUSE-биндинг; 21.5 evidence+reason), `final-report.md` §5 (замена «не проводилась» на фактическую A/B-оценку: методика, стоимость, регрессии, откат; без обещаний). 14.0 биндится последней — только когда 14.1/14.2 тоже имеют артефакты.
- Зависимости: W1→W2→W3 (общий скоуп, сериально; `CAN_PARALLEL_WITH` — лейны 14.1/14.2, скоупы не пересекаются).

## 6. Бюджет и риски

- **Платные вызовы**: W1 = 0 (≤2 smoke); W2 = **60–100** LLM-генераций (30–50 сцен × 2, deepseek-v4-flash, temp 0.7; +≤10% ретраи); W3 = 0. Итого 60–102 — на 1–1.5 порядка больше amd-probes (9), это прямое требование источника «30–50», не раздутый скоуп. Без LLM-судьи верхняя граница не растёт.
- R2: OFF-путь после AMD.1.2 — legacy-кастомы убраны из effective-слоя; A/B меряет механику сборки (unified-слои vs простая сборка) на текущих заводских текстах, НЕ историческую реконструкцию байтов до 2.58.86 — зафиксировать в отчёте честно; манифесты обеих рук обязательны.
- R1: сцена «непрямой повод для Initiative» — прямой вызов initiative-контура локально может быть нетривиален; допустимо через writer-путь с initiative-контекстом, ограничение задокументировать.
- R1: слепота — аналитик не видит лейблы до оценки; seed и порядок в отдельном файле.
- R0: сервисный код, флаги прод-конфига, реальный чаты — не трогаются; при любых сомнениях сериализовать.
