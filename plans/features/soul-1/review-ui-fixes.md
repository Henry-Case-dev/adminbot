## Findings

### F1 (BLOCKER; правка ~1 файл/6 строк) — web/app.js:3374-3376

- Требование: пустые состояния честны, причина выводима из загруженного состояния.
- Сценарий (воспроизведён live, реальный payload из каталога, 390px): `configItems` = только prompts,
  активная вкладка `smart_cache` (0 элементов), `configSearch="zzzqqq"`.
  Рендер: `[data-empty-tab]` = «На этой вкладке нет доступных параметров / Ничего не найдено по запросу «zzzqqq» —
  параметры вкладки доступны, но не подходят под запрос.»
- Почему неверно: карточка показывается только при `currentTabItemCount === 0`, а `tabItemCount()` (app.js:15223)
  считает элементы без учёта поиска → запрос структурно не может быть причиной пустоты; фраза «параметры вкладки
  доступны» ложна во всех состояниях рендера этой ветки. Честный текст (scope/role-ветки ниже) существует, но
  перекрыт. Search сохраняется при переключении вкладок — состояние достижимо без devtools.
- Минимальная коррекция: в `emptyTabReason()` убрать эту ветку или убрать из неё утверждение о доступности
  (например, «Ничего не найдено по запросу «q»; параметры вкладки в текущей области/для роли недоступны»),
  либо переставить scope/role-ветки выше q. Пин-бамп повторять НЕ нужно: строки пустых состояний тестами не
  пинятся, f8-hash покрывает только services/*.
- Минимальный recheck: та же live-проба B/C/D/E + `pytest tests/test_webapp_round107_ui.py tests/test_webapp_round1010_ui.py`.

**Текст причины (web/app.js:3366-3389):** ветка `if (q) { … «параметры вкладки доступны, но не подходят под запрос» }`
удалена. Осталось три выводимых из состояния причины: (1) `!total` — «сервер не отдал ни одного доступного значения»;
(2) scope ≠ global — «для выбранной области (ЛС/чат) нет применимых параметров… переключите на «Весь бот»»;
(3) global + непустой payload — «нет параметров, доступных вашей роли (сервер отфильтровал их по правам)».
При непустом `configSearch` к любой из них добавляется оговорка-не-причина: «Запрос «q» здесь ничего не
изменит: фильтровать в пустой вкладке нечего».
