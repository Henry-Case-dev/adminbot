## 1. Первопричина (ранжированно)

**P1 (основная) — правила L1-промпта не дают ни одного позитивного критерия SILENT/REACT и активно противодействуют «игнорированию коротких реплик».**
Прод-промпт `prompts.direct_l1_planner_system_prompt` байт-в-байт равен кодовому канону (`services/chat_prompts.py:455-508`, SHA256 декодированного значения `99a207313889711d`, 2423 символа):
- Правило 1: «длина сообщения не определяет extent. Короткая реплика вроде „а этот?“ может требовать нормального ответа…» — установлено против «короткое = не отвечать»;
- Правило 2: «action=react - **только когда** уместнее эмодзи-реакция…»;
- Правило 3: «action=silent - **только когда** лучшее решение сейчас не отвечать вовсе» — единственное упоминание silent, подано как исключение; нет ни одного примера/признака, когда молчание правильно; нет понятия «разговор завершён», «бессмысленное повторение», «вмешательство ради вмешательства»;
- Схема: `"action": "reply|react|silent"` — reply первым; zero few-shot примеров плана с silent/react; «СИСТЕМНАЯ РОЛЬ: Ты - планировщик **ответа**».
Итог: модель (deepseek-flash) читает «на короткую реплику, возможно, нужен нормальный ответ» + «silent только в крайнем случае» и отвечает текстом всегда. События подтверждают: все 8 случаев «матрица сказала silent → L1 ответил» имеют confidence 0.55–0.82 (medium/high) — L1 **уверен** в ответе, это не неуверенность.

**P2 (вклад) — L1 не видит факт «только что ответил сам / разговор завершён».**
- Окно L1 строится из `smart_messages` (`services/direct_l1.py:572-602` ← `summary_memory.get_window_messages:2562` ← `get_smart_window`, `database.py:7442`), а ответы бота хранятся только в `bot_replies` (`direct_chat_service.remember_bot_reply:1875`, TTL 3600/cap 200) — **в окне их нет** (проверено на проде: 3/3 свежих bot-ответов отсутствуют в `smart_messages`).
- Факт `bot_replied_recently` детерминированная матрица знает (`direct_chat_service.py:1940-1959`) и молчит по нему (8 раз за 48ч), но **в L1-контекст он не передаётся**: `build_l1_context` кладёт только СООБЩЕНИЕ / ОТВЕТ НА (≤400) / ПОСЛЕДНИЕ СООБЩЕНИЯ / УЧАСТНИКИ / ПАМЯТЬ / РЕЧЕВОЙ СИГНАЛ / ВОЗМОЖНОСТИ / УСЛОВИЯ / ХАРАКТЕР.
- Единственная строка «контекста решения» — `AUTONOMOUS_LINE` = «автономный контекст (ответ на сообщение бота): действие свободное» (`direct_l1.py:98-99`): свобода без критериев.
- «ХАРАКТЕР (кадр)» режется до 400 символов (`direct_l1.py:573`) — фраза Core «…молчание тоже часть характера» остаётся за кадром.

**P3 (побочный дефект того же пути, не причина 43/43) — allowed-набор реакций никогда не доезжает до L1.** Правило 2 ссылается на «разрешённый набор реакций, если он указан в контексте», но контекст его не содержит; офлайн L1 выбрал `😄` (вне `ALLOWED_LLM_REACTIONS`, `direct_llm_react.py:51-53`) → в проде это демотируется в дет. реакцию (mclass=laughter) или тишину (mclass=other) — текст всё равно не рождается, но выбор L1 теряется.

**Не является причиной:** downstream не подменяет SILENT на reply. Путь `l1_silent` реально завершает генерацию: `direct_chat_service.py:2887-2917` → `_execute_silent_ack:2028-2066` шлёт только 🗿 (`react_moai`, без send_message), вне гейтов — чистая тишина; `MESSAGE_IGNORED(l1_silent)` за 48ч = 0 только потому, что L1 ни разу не выбрал silent. Перезаписи решения существуют только там, где и задумано: force (`:2875-2880`), decision_off (`:2881-2886`), low-confidence silent → demote в матрицу (`:2887-2894` — для тривиальных продолжений матрица даёт SILENT/REACT, не reply), невалидная реакция (`:2918-2937`), outage → `fallback_plan` (1 случай за 48ч). JSON-fallback тоже не reply-биас: невалидный `action` → repair ×1 → fallback-план берёт action из pre_action (`direct_l1.py:845-884`), а не reply.

## 3. Минимальный фикс (ПРЕДЛОЖЕНИЕ, не применено)

Точечная правка **существующего** PG-канона L1 (правила 2–3; схему/поля/контракт не трогать; force-контракт сохраняется — гейты до L1 не меняются):

Правило 2, было:
```
2. action=react - только когда уместнее эмодзи-реакция вместо текста;
   reaction бери из разрешённого набора реакций, если он указан в контексте.
```
стало:
```
2. action=react - когда смысл лучше передаёт эмодзи-реакция, чем текст:
   поддержка, смех, согласие, одобрение или лёгкая ирония без новых
   слов; reaction бери из разрешённого набора реакций, если он указан
   в контексте.
```

Правило 3, было:
```
3. action=silent - только когда лучшее решение сейчас не отвечать вовсе.
```
стало:
```
3. action=silent - полноценное и часто предпочтительное действие, а не
   отказ и не ошибка. Выбирай его, когда твой ответ был бы
   бессмысленным повторением, навязчивым продолжением уже
   завершённого разговора, ненужным пояснением или вмешательством
   ради вмешательства. Типичный случай: участник лишь отреагировал
   на твой предыдущий ответ - посмеялся, коротко подтвердил, ничего
   нового не спросил; тогда уместнее react или silent, а не новый
   текст ради текста.
```
Это критерии владельца из директивы §1 дословно по смыслу («бессмысленным повторением, навязчивым продолжением, ненужным пояснением или вмешательством ради вмешательства»), без списков конкретных слов.

Сопутствующие точечные правки СУЩЕСТВУЮЩЕГО механизма (тот же фикс-пакет, опционально, по отдельному подтверждению фикса):
- **P3:** в `_plan_direct_l1` (`direct_chat_service.py:4113-4125`) при `_toggles.reactions` класть в `force_line`/отдельную строку факта: «разрешённые реакции: 😂 🤣 👍 👌 ❤️ 🔥 🤨 🤔 💀 🤡» (константа уже есть — `ALLOWED_LLM_REACTIONS`); правило 2 тогда начнёт работать как написано.
- **P2 (опционально):** расширить `AUTONOMOUS_LINE` (`direct_l1.py:98-99`): «…действие свободное; твой предыдущий ответ - в блоке ОТВЕТ НА; молчание и реакция - равноправные исходы».

Механика применения канона: правка кода `chat_prompts.py` + бамп + слепок прежней базы (ADR-1013-3, лестница `prompt_migrations.py:155` должна признавать прод-значение `99a207313889711d` и вести его на новый канон). PG-ключ правится миграцией, не руками.

## 5. План верификации фикса (для implement-полосы)

1. **Офлайн-набор ≥10 разнообразных контекстов** (байт-в-байт через `build_l1_context`): тривиальные продолжения ×3 (смех/подтверждение/возглас), короткий содержательный вопрос ×2 («а этот?», «а если не сработает?») — обязаны остаться reply, явное поручение, медиа-реплай, ностальгический/нейтральный вопрос, болтовня не-тревиальная. Критерии: тривиальные → silent/react ≥80%; содержательные → reply 100%; валидный JSON ≥95% с учётом bounded repair; при контекст-фиксе реакция L1 ∈ ALLOWED в 100% react-планов. Прогонять ОБА промпта (текущий = контроль).
2. **Миграция канона**: тест-лестница признаёт прод-значение (SHA `99a207313889711d`) → новый канон; слепок `PREV_DIRECT_L1_PLANNER_BASE` заморожен; тесты `test_prompt_migrations` зелёные.
3. **Контракты не менялись**: `normalize_l1_plan`/repair/fallback — без правок; unit на ACTIONS/enum не трогаются.
4. **Прод-наблюдение 48ч после выката** (existing telemetry): `L1_PLAN` action-распределение перестаёт быть 100% reply на автономных; `MESSAGE_IGNORED(l1_silent)` > 0; `direct_reply`-отправки на тривиальных падают; force-ходы остаются 100% reply. - Принудительный force-ответ по явным триггерам не смешивается с обычными reply: гейты §4.1 не тронуты.

## 7. Побочные находки (не блокеры этой полосы)

- `related-nonblocking`: allowed-набор реакций не доезжает до L1 (P3) — чинится одной строкой факта в существующем вызове, иначе REACT-планы будут часто демотироваться.
- `related-nonblocking`: окно L1 без сообщений бота — L1 не видит собственной реплики, если юзер НЕ ответил реплаем (reply-блок пуст). Для autonomous-ветки не мешает (там всегда есть reply-блок), но сужает смысловой горизонт; достаточно `AUTONOMOUS_LINE`-правки, новое хранилище не нужно.
- `unrelated/pre-existing`: разовые пустые ответы flash-модели (1/8 офлайн; в проде покрывается bounded repair + 1 fallback за 48ч).
- Артефакты: `OPENCODE_WORKFLOW_SCRATCH/l1-rootcause-20261021/` (probe, replay, результаты, промпты). Скрипты одноразовые — в репозиторий не продвигать, кроме этого отчёта.

## §8. ФИКС ПРИМЕНЁН (FIX-CORRECTIVE-R1, 22.10.2026)

Коммит fix(direct-l1): оба корня закрыты минимальными правками существующего механизма.

- **P1 (правила 2-3 канона L1)**: react — позитивные критерии («смысл лучше передаёт реакция»); silent — полноценный и часто предпочтительный исход с критериями владельца (бессмысленное повторение / навязчивое продолжение / ненужное пояснение / вмешательство ради вмешательства; типичный случай — участник лишь отреагировал на ответ бота). Правило 1 и force-контракт не тронуты, списков слов нет. Кандидат из §3 применён с одним уточнением после офлайна: «явный вопрос/просьба/поручение — не „лишь реакция“» (первый прогон показал react conf 0.82 на ностальгическом вопросе). Прежний канон заморожен: PREV_DIRECT_L1_PLANNER_1021 = прод-байты (SHA256[:16] `99a207313889711d`, 2423 симв), ступень лестницы ведёт PG на новый канон (новый SHA256[:16] `5fdc90b3f114`, 3022 симв).
- **P2 (контекст)**: `build_l1_context` получил секцию «ОТВЕТЫ БОТА (недавние)» из существующей таблицы bot_replies (новый метод `_recent_bot_replies`: то же окно CHAT_BOT_REPLIED_RECENTLY_SECONDS, fail-open, ≤3 строк, кап 400); AUTONOMOUS_LINE называет блок и равноправие silent/react.
