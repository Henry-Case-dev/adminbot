# ADR-1028-23 - `mca-17c-analytics-matrix`: финальная витрина наблюдаемости — read-side матрица поверх реестра mca-17a, узкий санкционированный write-API действий, Δ DDL/каталог/KS = 0

**Статус:** Proposed (→ Accepted по прод-валидации T-5199/T-5200; преемник ADR-1027-8 `mca-17a` — ядро наблюдаемости).

**Дата:** 07.10.2026. **Автор:** @Architect (Step 2, T-5177/T-5178). **Wave 5** (`mca-round1027-plan.md:247`: `mca-12 → mca-17c → mca-21-guides → mca-release`), строка фичи `:213`, Risk **R2 confirmed** (D14).

## Контекст

MCA-17 — прозрачность всех процессов памяти/контекста/самообучения (§27 `plans/current_task.md:1323–1484`) + фуннель личности (§28 `:1588`). Ядро доставлено mca-17a ✅ (ADR-1027-8, ARCHITECTURE §100): реестр code-declared (**47** `ProcessDefinition` на HEAD `b25558e`), trace/span поверх единого `mca_events`, lifecycle 9+partial/degraded/stalled, heartbeat/watchdog/fencing, инциденты durable+fingerprint+доставка ≤10s polling/cursor, телеметрия bounded/spool/gaps, read-API `GET /api/oversight/processes|incidents|incidents/changes`. §100.4 (`ARCHITECTURE.md:4146`) прямо поручает mca-17c приёмки A54/A56/A57/A73 и **запрещает второй store/аналитику**. Всё, что матрица показывает, уже в событиях/таблицах/реестре — фича чистый read-side + UI. PM (requirements-map §5) вынес 8 развилок Q1–Q8.

## Решения

- **D1 — read-side потребитель, границы CA-17C-1…7.** mca-17c рендерит реестр/runs/инциденты/counters; запрещены: второй store/агрегатор/канал/аналитика, свой контрольный контур мимо task-механизма, дубли страниц/виджетов, правки backend-контрактов mca-17a/13/16/18/19/20. Расхождение UI с backend-контрактом = дефект рендера, не второй контракт.
- **D2 — IA без дублирования.** Три представления («Обзор процессов»/«Запуски»/«Инциденты») и фильтры — внутри существующего `#/oversight`; лейбл «Аналитика» = переименование «Диагностика» (`web/app.js:399`); нового маршрута/страницы analytics нет; витринные виджеты не переносятся вглубь (`:1370`); deep links — контракт 17c + якоря компакт-витрин mca-12 (CA-17C-3).
- **D3 — ExecutionGraph AMEND-adapter.** `window.ExecutionGraph` (`web/app.js:2863/2931/5259`) + `build_run_view` (`pipeline_analytics.py:829`) — расширение, не замена; граф только при ветвлениях/зависимостях, иначе stepper/timeline; обновление не сбрасывает UI-состояние (A54).
- **D4 — честность = read-render контракта mca-17a.** Статусы/прогресс/стейл/retention-заглушки UI не изобретает: denominator-прогресс без выдуманных %, анимация гаснет при stale/unknown, «зелёный» = завершение обязательных стадий, stalled не подменяет outcome, «детали удалены по сроку хранения» для истёкшей ретенции (§27.4/27.5/27.7-принципы как read-side).
- **D5 — фуннель личности, три статуса.** «Передано модели» (prompt_render) ≠ «проявилось по оценке» ≠ «доказан сравнительный эффект» (replay, вне процесса); per-rule included/excluded/conflict/stale + причина + frame version + trace; причинность включению в prompt не приписывается (§28 `:1588`; реестр `:1063`/`:1083–1085`; handoff mca-18 D8, `ARCHITECTURE.md:4533`).
- **D6 — матрица покрытия = сверка + отчёт, не новый источник данных.** 18 строк §27.1 + MCA-18/19/20 + фактические процессы; строка = группа карточек/фильтр с drill-down; сверка реестра↔handlers и mapping стадий на события — артефакт T-5191 (отчёт §21 п.5). Незарегистрированный процесс/новый widget-ID — эскалация @Architect (+mca-17a), не self-serve (CA-17C-7).
- **D7 — инциденты без нового транспорта.** Рендер `oversight.py:220/:244` (fingerprint/changes-cursor); ack ≠ resolved; ack-действие отсутствует в 17c (ack — backend mca-17a, при нехватке read-поля — эскалация, не свой контур); ≤10s — существующий polling; reconnect — cursor.
- **D8 — самообучение поверх mca-16.** Воронка/граф урока/«Эффект» из существующих counters/API (`experience_snapshot` `status_service.py:593`, `/api/memory/lessons*`); лента «Статуса» сохраняется, правка — в «Памяти»; unknown ≠ провал/успех; фиктивные шкалы запрещены (§27.8 `:1456–1462`).
- **D9 (Q1) — Deploy: CA-11, пер-фичевый bump 2.58.65→2.58.66.** Отдельное окно после mca-12; план `:213` DEFERRED_TO_RELEASE superseded Step 2 — прецедент mca-12 (`:212`, §1.2.10): read-side UI-фича с Δ DDL=0 деплоится пер-фичево; даёт раннюю owner-приёмку T-5199 до mca-release. Fallback: окно недоступно (SSH/fail2ban) до mca-release → DEFERRED_TO_RELEASE; решает @DevOps на окне; AGENTS.md-дисциплина (один recon + один деплой-прогон). Rollback: soft — read-side нейтрален/лейбл, cold — git revert (DDL нет — тривиально).
- **D10 (Q2) — Write-API: санкционирован узко, один endpoint.** `POST /api/oversight/jobs/{job_id}/action` (cancel/resume/retry через существующие операции TaskSupervisor — `task_supervisor.py:547/:709`; свой control-контур запрещён). RBAC `requires_global_admin()` (прецедент killswitch `oversight.py:294`); actor/audit-событие (D13); идемпотентность state-машиной + idempotency-key; retry = новый attempt (checkpoint-семантика mca-17a); при delivery_unknown — сверка, не retry (`:1468`); fault injection/произвольный SQL — запрещены (`:1470`). Вариант «только экспорт/просмотр» отклонён: A56 прямо поручена 17c (§100.4 `:4146`).
- **D11 (Q3) — Δ routes = +3, один финальный re-pin.** На существующем `oversight_router` (`web/api/oversight.py`; byte-freeze `routes.py` — прецедент mca-12): `GET /api/oversight/runs` (фильтрованный список, keyset, серверные фильтры), `GET /api/oversight/experience/funnel` (периодные агрегаты read-only), `POST /api/oversight/jobs/{job_id}/action`. `ROUTES_SHA256_F11` — один re-pin на пакете (L-F11S-1); mca-12 (+5) уже в проде 2.58.65 — конфликтов нет.
- **D12 (Q4) — Δ каталога = 0, Δ kill-switches = 0.** Рендер существующих ParamSpec (переход к настройке = ссылка); F8 NOT_APPLICABLE; REGISTRY 523 не растёт. KS не добавляются: защита write-API = RBAC+audit+идемпотентность (прецедент killswitch); OFF-паритет — честный disabled/not_run из реестра (рендер).
- **D13 — Δ reason_code = +1, Δ тулов = 0; baseline двухуровневый (Q8).** +1 `oversight_job_action` (actor/audit cancel/resume/retry; словарь не содержит control-action кода — `mca_events.py:94–100`): 279→280 на пакете, 269→270 vs HEAD `b25558e`. Тулы 14=14 (METERED_TOOLS без изменений). Baseline: абсолют — пост-mca-12 **2.58.65** (фикс @DevOps на окне T-5198); дельты 17c от него: DDL 0 / каталог 0 / KS 0 / reason +1 / тулы 0 / routes +3.
- **D14 (Q5) — Risk R2 confirmed; threat — §8 внутри spec.** R3-триггеры не сработали: DDL=0; write-path = 1 endpoint под существующим RBAC поверх supervisor; новых внешних поверхностей/провайдеров/секретов нет. Threat TH-1…TH-8 (привилегия-эскалация, cross-chat, утечка через экспорт, инъекция/DoS-агрегация, двойной side effect, UX-ложь, DOM-инъекция, раздутый audit) — `spec.md` §8; 0 Critical/High при mitigation; Scanner T-5197.
- **D15 (Q6) — Prod-smoke двухступенчатый.** (а) На 17c-окне: live-приёмка владельца T-5199 — A73-виджеты self.model/vision.media/temporal.factcheck на реальных запусках, связность trace, ≤10s-инциденты, актуальность timestamps, воронка из реальных counters; (б) §27.10-smoke «после единого включения» волны + Live TMA/нагрузочный R3/e2e takeover — mca-release (backlog `:43`; handoff T-5200; чек-лист — артефакт T-5191/T-5194). Замер нагрузки телеметрии — dev-side на воспроизводимом прогоне (T-5194).
- **D16 (Q7) — Carry-overs.** В пакете (T-5192, read-side): F14 (severity-порядок), F15 (gaps vs `_dropped_total`), F16 (`telemetry_freshness` «пусто ≠ устарело»), mca-06 M-2 (chain UI), L-3 (unchanged-метка), F12-display (расхождение runtime vs KS). Отдельным фикс-слайсом после 17c: F12-backend (унификация резолва product-гейтов) — 17c backend-резолв гейтов не трогает (CA-17C-1).

## Последствия

Позитив: полный §27-обхват без единой миграции; owner-приёмка до релиза; единый финальный re-pin; честные состояния без второго источника правды. Негатив/ограничения: 17c не чинит backend-пробелы наблюдаемости (только эскалация); write-API требует дисциплины идемпотентности и аудита; funnel-агрегация ограничена периодом (TH-4); откат деплоя возможен, но carry-over F12-backend остаётся в backlog. Если при реализации существующих операций supervisor недостаточно для action-семантики — останов и эскалация @Architect (не изобретать новый control-контур).
