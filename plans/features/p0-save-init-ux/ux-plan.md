### 5.2. Коды ответов после PERSIST-FIX и поведение UI

| Код/тело | Смысл | Поведение UI (обязательное) |
|---|---|---|
| 200, `ok:true` (`result.applied:true`) | реальная запись | успех: тост + **сбросить dirty только этого поля/раздела**; показать «Сохранено ✓ HH:MM» в разделе; `loadSpeechSection(..., true)` (read-after-write) |
| 409 `detail:"документ не прошёл проверку: …"` | валидация документа (unknown kind и т.п.) | тост-error с **текстом detail как есть**; черновик сохраняется, форма не закрывается; после текста — подсказка `Исправьте и сохраните снова`; **никогда не писать «конфликт версии»** |
| 409 `"значение изменено другим путём"` / `"не удалось сохранить: профиль чата не найден или изменён — обновите экран и повторите"` | реальный конфликт | тост-warn с человеческим текстом + кнопка/подсказка «Обновить данные»; текст пользователя не терять |

| 422 (`scope=chat требует X-Chat-Id`, `неизвестный detail_level`) | неверный запрос UI | тост-warn `Выберите чат в селекторе области` — и не отправлять такой запрос из UI (кнопка scope=chat disabled без чата) |
| 503 `"не удалось сохранить: постоянное хранилище недоступно, попробуйте позже"` / `"не удалось сбросить переопределение: …"` | инфраструктура | тост-error с текстом detail; **черновик сохраняется**, показать «Повторить сохранение» (повторный вызов того же save) |
| 403 | нет права | как сейчас (человеческий текст роли) |
| 401/сеть (ApiError 0/401) | сессия/сеть | как сейчас; черновики не сбрасывать |

Маппер ошибок: один хелпер `speechErrText(e)`; правило — **не показывать коды** (`write_error`,
`save_error`, `document_invalid`, `config_cache_unavailable`): если `e.message` — код из
известного списка, подставить человеческую причину (§3 TJ-21), иначе показать `e.message`.
В `loreErrText` (общий) ничего не менять — правим только в speech-обработчиках.

### 5.3. Видимые несохранённые изменения (dirty)

- Критерий «dirty» для каждой области: Core (по редакции: `coreFull/coreCompact` — текст редакции
  отличается от загруженного), Style (в draft есть отличия от серверного снапшота: правила/приоритеты/
  привычки), Expression (значения/note отличаются от `values`/`note` сервера). Humor/Примеры/Обучение
  сохраняются поштучно мгновенно — dirty не нужен, но их формы (пример) имеют явные «Сохранить/Отмена».
- Индикация: бейдж в шапке экрана `Есть несохранённые изменения: N` (по разделам), бейдж раздела
  (как сейчас `черновик не сохранён`), рамка редактора `.dirty`, sticky-save панель с «Сохранить».
- Черновик Style уже рендерится из черновика (W6 F2) — сохранить это поведение; добавить такой же
  признак для Core/Expression (счётчик «на сервере N, у вас M» — как в Style, `speechStyleServerRuleCount`).
- Исключить неочевидные перезаписи: правки из одного раздела не должны попадать в сохранение другого
  (у каждого раздела свой save-вызов — сохранить); «Обновить» не перезаписывает черновик (уже так).

### 5.4. Переключения и черновик

| Сценарий | Обязательное поведение |
|---|---|
| Переключение раздела с несохранёнными правками | черновик сохраняется в сессии (как сейчас) + в шапке видимый индикатор; при повторном открытии раздела патч-нотис `В этом разделе есть несохранённые правки` |
| Переключение full/compact в Core с черновиком | **не терять введённое**; каждая редакция — свой черновик; бейдж показывает, где черновик; «Сохранить» сохраняет только открытую редакцию |
| Переключение чата (области) с несохранёнными правками | подтверждение (переиспользовать `_dirtyLeaveGuard`, `app.js:6405`), при отказе — область не меняем; при подтверждении — сброс данных разделов и черновиков к новому чату (см. §6.4) |
| «Обновить данные» / возврат на витрину | черновики не теряются; данные перечитываются |
| Перезагрузка MiniApp | сохранённые значения на месте (read-after-write); черновик сессии не переживает перезагрузку — это допустимо (явно указано в подсказке при уходе) |
| Успех сохранения | dirty сбрасывается только у сохранённого; остальные бейджи не гаснут |

### 5.5. Подтверждение успеха и уведомления

- После успеха — тост (существующий) + строка в разделе `Сохранено ✓ HH:MM` (локальное время),
  исчезающая через 10 с или при следующем вводе.
- Тосты не перекрывают нативные элементы: проверяем 320px портрет и «открытая клавиатура»
  (клавиатура не задевает верхние тосты; sticky-save слушает `--kb-offset`).

## 10. Малая правка: лейбл ностальгии «Тишина: N/45» → сценарий

Проблема: `nostalgiaLabel()` (`app.js:20713-20723`) в режиме `silence` показывает обратный отсчёт
тишины, хотя после P0-followup §2 эта же ситуация — **сценарий A (живая беседа)**: контекстное
воспоминание возможно без ожидания 45 минут (воркер: `services/nostalgia_worker.py:404-423`,
`active = last_ts + silence_sec > now`). Бейдж вводит в заблуждение владельца.

Изменение (минимальное):
1. `web/api/memory_agi.py::_nostalgia_state` (745-769): добавить в возвращаемые словари поле
   `"active": bool` по той же формуле, что воркер (`last_user_ts is not None and last_user_ts +
   silence_min*60 > now`), и `"scenario": "active" | "idle"`. Остальные поля не менять
   (совместимость с `tests/test_webapp_round1013_f5_ui.py:178-190`).
   Чтобы формула не разъехалась с воркером — вынести общий чистый хелпер (например,
   `services/nostalgia_worker.py::scenario_active(last_ts, now, silence_sec) -> bool`) и
   использовать его и в воркере, и в payload (один источник).
2. `nostalgiaLabel()`: приоритет — `cooldown` (кулдаун блокирует и сценарий A) → `active` →
   `ready`. Тексты дословно:
   - `mode==='cooldown'` → `Кулдаун: ещё N ч` (без изменений);
   - `active===true` → `Живая беседа: вспомнит по контексту`;
   - иначе → `Затишье: готово вспомнить прошлое` (вместо «Готова к вбросу»);
   - если новых полей в payload нет (legacy-ветка) → прежнее поведение, включая `Тишина: N/M мин`.
3. Тест: `tests/js/routing_test.js:1680-1685` — существующие ассерты сохраняются (legacy-ветка),
   рядом добавляется кейс `active:true → 'Живая беседа: вспомнит по контексту'`
   (TEST-LIFECYCLE: REGRESSION owner=P0B-NOST/§2).

лимиты, деньги/бюджет) продолжают действовать.
