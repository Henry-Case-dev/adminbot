## 1. Инициатива — автономные сообщения не появляются

По коду `services/initiative_observer.py` обнаружены потенциальные системные блокеры:
1. **Исторический курсор.** Наблюдатель может начинать с `cursor_message_rowid=0`, сканируя многолетнюю историю по 200 сообщений каждые 300 секунд. Проверить фактический cursor lag. Обеспечить наблюдение актуальной переписки без уничтожения исторического контекста и генерации по устаревшим обсуждениям.
2. **Конфликт с Direct.** `_window_addressed_to_bot()` отклоняет всё окно из-за единственного обращения к боту. Разделить прямые обращения и самостоятельные возможности, не выбрасывая остальной контекст.
3. **Неправильный cooldown.** `_last_bot_output_age()` отсчитывает паузу от любого ответа бота. Обычный Direct не должен постоянно блокировать автономную инициативу. Разделить антифлуд и cooldown инициативных сообщений.
4. **Некорректный статус.** В админке выбранный PERMsoc отображается как `restricted` / «нет разрешённого чата». Проверить `X-Chat-Id`, RBAC, БД и фактический `chat_scope_allowed`.

Снять реальную read-only диагностику production: effective gates, heartbeat, observer ticks, cursor lag, pending, evals, opportunities, причины пропусков, Writer, Recheck и фактические отправки. Не имитировать успешную инициативу тестовым сообщением. Доказать, что автономный pipeline обрабатывает актуальный чат и способен пройти всю цепочку до отправки.

## 2. SOUL-1 — системная неисправность сохранения настроек

Наблюдаемые ошибки: Speech Style Policy: «Документ не прошёл проверку или конфликт версии»; Expression Settings: `Не сохранено: write_error`; Personality Core: проверить запись, версии, повторное чтение; возможны аналогичные неисправности других параметров «Речь и характер». Не исправлять каждый экран отдельной заплаткой, пока не проверен общий механизм сохранения.

### 2.1. Сквозной аудит persistence
Цепочка: UI → payload → API → валидация → concurrency/revision → PostgreSQL → повторное чтение → effective config → runtime LLM payload. Проверить: Personality Core (полная/компактная редакции, версии, дифф, сохранение, наследование, откат); Expression (мат, развёрнутость, global/per-chat); Speech Style Policy (строгие правила, привычки, шаблоны, scope, приоритеты); остальные редактируемые параметры SOUL-1 и жанровые компоненты; **общие обработчики сохранения MiniApp и их потребителей** (общий дефект → централизованный фикс + smoke других разделов; без несвязанного редизайна).

### 2.2. Точная причина (не `write_error` как диагноз)
Классификация: невалидная структура; несовпадение front/back схем; revision/ETag; ложный optimistic conflict; права; транзакция/БД; scope; сериализация; кеш/effective. Нельзя подавлять валидацию, отключать версионирование, ставить искусственный 200. Успех = read-after-write из постоянного хранилища + применение в runtime. При конфликте сохранять несохранённый текст и предлагать безопасное разрешение.

### 2.3. Фактическое применение
После сохранения: reread, ревизия, effective, global/per-chat, hot без рестарта, конечные LLM payload (Direct/Initiative/Factcheck/Summary Writer/fallback). Personality Core — единственный источник личности; старые каноны не возвращать активным слоем.

## 3. Полноценная переработка UX раздела «Речь и характер»

### 3.1. Иерархия: 1) Характер (Core, полная/компактная, версии); 2) Манера речи (мат, развёрнутость, Expression); 3) Правила письма (привычки, строгие ограничения, пунктуация, эмодзи, шаблоны); 4) Дополнительно (история, дифф, техсведения, диагностика, восстановление). Визуальная группировка существующих функций, не новая система.

### 3.2. Убрать техмусор из основного интерфейса (`owner_setting`, `fac:040…`, `trailing_period.hard.strip`, `emoji.hard.off`, `write_error`, `inherited` без перевода, служебные ревизии) — понятные названия/описания; техдетали — в раскрываемых деталях/диагностике. Данные и возможности не удалять.

### 3.3. Компактная адаптивная компоновка (Android Portrait/Landscape): убрать огромные кнопки/отступы/вложенные карточки; компактные переключатели/списки/селекторы; единый размер элементов; операции не «каждая — большая кнопка»; сохранение/обновление/сброс — логично; второстепенное — в меню действий; safe area/клавиатура/высота; без горизонтального переполнения и перекрытия Telegram UI; длинные тексты — расширяемый редактор; удобное переключение полной/компактной редакций Core; не терять введённое при переключении. Полигон/стекло/палитру сохранить; не редизайнить всю MiniApp. Принцип: меньше шума, больше пользы.

### 3.4. Логика сохранения: явные несохранённые изменения; без неочевидных перезаписей; подтверждение успеха; человеческая причина ошибки с сохранением текста; не закрывать/не сбрасывать при ошибке; предупреждать/черновик при переключении; корректно после перезагрузки; уведомления не перекрывают нативные элементы.

### 3.5. Global/per-chat: видно, где задано и откуда effective; переопределение помечено; «Наследовать глобальные настройки» вместо «Сбросить в inherited»; scope ≠ права; изоляция чатов; безопасное восстановление глобального.

### 3.6. Сохранить всю функциональность (полный/компактный Core, история/дифф/откат, привычки, строгие запреты/приоритеты, шаблоны, Expression, мат/развёрнутость, global/chat, предпросмотр применяемых правил, диагностика effective). Не заменять редакторы моками.

## 4. Обязательная приёмка

**Persistence (реальная БД, каждый тип настроек):** открыть → изменить → сохранить → реальный ответ API → reread из хранилища → перезагрузка MiniApp → значение осталось → effective runtime → вернуть исходное → отсутствие влияния на другие чаты; отдельно concurrency conflict, неверный документ, недоступная БД, наследование, rollback.

**UX:** Android Portrait/Landscape, Telegram Desktop, узкие viewport; реальное взаимодействие (длинный Core, Expression, добавление/удаление Style Policy, сохранение, переключение чатов, открытая клавиатура, ошибки API); Browser Use/Playwright — функциональность, не только скриншоты.

**Initiative:** подтвердить исправление реальных блокеров, актуальность наблюдаемого контекста, способность цепочки дойти до отправки; без принудительной бессмысленной публикации.
