## 1. Почему не сохранялось и какие разделы были затронуты

Единый системный дефект: все 10 chat-scope записей «Речи и характера» вызывали служебный слой **без пула соединений**
(`chat_params.py:424` → `ChatLorePgUnavailable` **до** обращения к БД). UI маскировал причины: любой 409 рисовался как
«документ не прошёл проверку / конфликт версии», а `write_error` выводился как сырой код.

Затронутые разделы/пути: Speech Style Policy, Expression Settings, чатовые настройки Personality Core (3 пути: текст, `/core/meta`, `reset(mode=chat)`),
ремесло юмора, пауза/сброс обучения, обе кнопки «Сбросить в inherited» (+ побочно перекрытый маршрут `/speech/examples/{seed|policy|why}`).
Примеры (SQLite) не затрагивались; прочие разделы MiniApp работают (пул передают).

Прод-доказательства: трейсы 2026-10-18 08:02:21 (`style_policy.py:2272`) и 08:09:49 (`speech.py:2184`), совпадают со скриншотами владельца.

- Ностальгия: подпись по сценарию («Живая беседа… / Затишье…», legacy «Тишина N/M» сохранён).

## 4. Инициатива — почему молчала (4 подтверждённых + 1 скрытая)

1. Курсор отставал на **2 194 903** сообщения (≈38 суток при 200 стр./300 с); наблюдатель читал древнюю историю.
2. Одна реплика со словом «бот» выбрасывала **всё окно** (ловил «ботаник/ботва»).
3. Cooldown считался от **любого** вывода: 127 прямых ответов/7сут × 2 ч запирали автономию.
4. Админ-статус показывал `restricted` даже при «чат не выбран» (RBAC исправен).
5. Скрытая: эфемерный повод терял контекст (`initiative_decided silent/default`, intents=0) — цепочка тихо останавливалась на L1.

Исправлено: bootstrap курсора к живому хвосту (6ч/≥200, только вперёд, `scan_anchored`);
по-репличная классификация; anti-flood 300 c + `min_gap` только по `initiative_reply`; `no_chat` ≠ `restricted`;
`opportunity_row` (goal/kind/origin) в L1/L2 + реальный `direct_pending` + истинные reason_code.
Доказательство «доходит до отправки»: тест полной цепочки (fake writer/transport, `sent==1`, ledger `initiative_reply`) + отмена при прямом запросе.
RED 7f/3p → GREEN 405. Прод-live: `scan_anchored=1` (13:40:06Z), 280 scan-событий/24ч, воронка живая, панель «Инициатива доставляется».

## 5. Ностальгия — почему не срабатывала

Главный блокер: требование **тишины 45 минут применялось ко всем сценариям** — каждый тик завершался `silence_too_short`
при непрерывно живом чате (2.03М сообщений; 26 738 кандидатов «год назад»; за историю sent=2). Плюс латентный: job не регистрировался
при OFF на старте (hot-включение не поднимало); заводской `NOSTALGIA_ENABLED=False`; на Core-пути — legacy-канон.

Исправлено: job зарегистрирован всегда (OFF → дешёвый no-op, kill-switch); **сценарий A** (контекстное воспоминание в живой беседе — без 45-мин/quiet)
и **B** (после затишья — прежние паузы); `NOSTALGIA_CORE_CANON` на Core-пути (OFF-путь байт-в-байт); единый контур Decision/Writer/SendRecheck, дедуп с инициативой.
Live-подтверждение: 14:40:03 строки `scenario=A` обоих чатов, гейты тишины не применялись, честные skip-причины (`no_candidates`, LLM `UNCHANGED`), `nostalgia_log` #217/#218; PET-гейт второго чата включён (14:12:12Z).
Остаток: сценарий B ждёт естественного затишья (механизм подтверждён кодом/тестами; не блокирует).
