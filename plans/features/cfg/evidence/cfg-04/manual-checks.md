# CFG-04 — что осталось проверить на живом клиенте/деплое

Этот лейн **не деплоил** и не имеет реального Telegram-клиента. Ниже — точные
шаги для D.4 (живой клиент, honest `PENDING_OWNER_E2E`) и D.1/D.5 (deployed SHA).
Проверки эмуляции (Playwright/Browser Use) не заменяют эти пункты.

## D.4 — живой Telegram Android (portrait + landscape) и Desktop
Статус: **PENDING_OWNER_E2E** (PET: необязательная обратная связь владельца, не
блокирующий gate; автоматические проверки выполнены — см. `visual-check.md`).

1. Открыть MiniApp в **Telegram Android** (любой из 1–2 личных чатов).
2. «Модули» → «Ответы в чате» → изменить «Обращений подряд до кулдауна»
   (например 3) — появляется панель «Изменено: N» и индикатор в шапке.
3. Проверить: в шапке — **не кнопка** (по нажатию ничего не сохраняется),
   внизу — единственная «Сохранить изменения».
4. Не сохраняя, **повернуть телефон** в ландшафт и обратно:
   - ввод, выбранный чат/область, dirty-счётчик, прокрутка и маршрут сохранены;
   - нет скачка наверх;
   - панель не уходит под нативную нижнюю зону.
5. Открыть экранную клавиатуру в поле: «Сохранить»/«Отмена» доступны касанием
   (панель не под клавиатурой).
6. Прокрутить до последнего поля: панель не перекрывает поле/каретку/подсказку.
7. Нажать «Сохранить»: значение меняется, действие реально применяется
   (проверить на следующем сообщении/лимите), затем **вернуть исходное значение**.
8. Chat override → «↪ Глобальное»: значение возвращается к GLOBAL, кнопки
   различимы и не нажимаются случайно при повороте.
9. **Telegram Desktop**: те же поля/панель, полный технический ключ
   (наведение → title, «раскрыть», «копировать»).

Ожидаемый результат: во всех шагах нет дублирующих сохранений, недоступных
кнопок и полей; фон/glass/палитра визуально не изменились.

## D.1 — воспроизведение на deployed SHA
1. Открыть deployed MiniApp (2.58.x после релиза CFG-04) в мобильном браузере/TMA.
2. Повторить сценарии дефектов из `failures.md` (F1–F7) — все должны быть
   устранены; зафиксировать `viewports`/скриншоты в новом evidence-файле релиза.

## D.5 — полный сценарий `limits.chat_burst_limit`
1. Зафиксировать исходное значение (`GET /api/config` или экран).
2. «Модули» → «Ответы в чате» → изменить `limits.chat_burst_limit` на безопасное
   (например +1 к текущему, не 0).
3. Повернуть экран (dirty сохраняется) → «Сохранить изменения».
4. Убедиться, что значение **реально** новое (read-after-write) и поведение
   (кулдаун после N обращений) соответствует; не объявлять успех по HTTP 200.
5. Chat override: изменить в чате → сохранить → вернуть «↪ Глобальное».
6. **Восстановить исходное значение** и подтвердить восстановление.

- Прод/SSH не использовались; релиз и `check --stage release` — вне лейна.
