## 5. Уборка тестовых сообщений

Волна F4 выполнила **два** прогона: первый (20:01–20:09) из-за дефекта
раннера стартовал **двумя** процессами (systemd-run + nohup-дубль), второй —
чистый (20:13–20:19). Все тестовые сообщения обеих попыток удалены:

- чистая волна — **23** (`f4/cleanup-register.json`: A 19, B 4);
- остатки дубля — **15** (`f4/final-clean` лог: A 11, B 4; при этом
  `f4/sweep.json` корректно **отказался** от сплошной уборки, обнаружив
  реальные сообщения владельца в окне);
- хвост synthetic-turn цепочки — **5** (`f4/residual-clean.json`).

Легитимные ответы бота на реальные сообщения пользователей (`1166966`,
`1166975`, `1166982`, `1166988` — parent = сообщение пользователя) **не
тронуты**. Синтетические строки SQLite (`bot_replies`, `bot_reply_parents`,
`throttle_state`) удалены; **остаток тестовых = 0**
(`f4/residual-clean.json` → `after.test_left=[]`; `f4/final-verify.json`
показывает 4 оставшихся *легитимных* ответа, `test_left` там не считается —
поэтому его `ok=false` относится к легитимным репликам, а не к тестовым).
Сообщения владельца и участников чата не удалялись. Инцидент двойного старта
и его видимость в чате зафиксированы в `f4/README.md` §6.
