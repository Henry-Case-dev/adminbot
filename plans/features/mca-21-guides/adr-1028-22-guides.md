# ADR-1028-22 — `mca-21-guides`: актуализация двух канонов справки — docs-изменение с канон-бампами, Δ код-поверхности = 0

**Контекст:** §31 `plans/current_task.md:1814–1842` (31.1 `:1820–1826`, 31.2 `:1828–1834`, 31.3 `:1836–1842`); §21 `:1048` (mca-21 — завершающий обязательный результат программы); A84 `:965`; план `:175–177`/`:214` (DEFERRED_TO_RELEASE)/`:247` (Wave 5: `mca-12 ∥ mca-17c` → `mca-21-guides` → `mca-release`); стиль §38 `:16378–16385`, запрет обещаний `:16413`. ## Решения

**D1. Два существующих канала, ноль новых поверхностей.** Гайды — тексты существующих канонов: «Гайд по возможностям» — Markdown `plans/docs/intelligence_guide`-цепочка (сид-файл ↔ PG `content.intelligence_guide` ↔ `/api/info/guide` ↔ вкладка «Справка»), «Гайд по фичам бота» — HTML `DEFAULT_INFO_TEXT` ↔ `info_text.md` (байт-тест) ↔ PG `content.info_how_it_works` ↔ `/api/info` ↔ `#/how`. Нового раздела меню нет (`:1818`); структура обоих (заголовочная рамка гайда, h1/h2/p/blockquote+b/i фич-гайда) сохраняется, содержание актуализируется до фактического поведения.

**D2. Источник фактов — код/ARCHITECTURE/ADR/прод, не ТЗ-планы.** Внутренняя матрица «требование → реализованное поведение → место в гайде → проверка» (T-5204, `:1826`) — обязательный артефакт отчёта, в гайд не попадает; честные состояния (OFF/по умолчанию/недоступно) вместо жёстких обещаний; технические исправления — через эффект, без дампа классов. Запрещённые обещания (`:1824`/`:16413`): сознание, безошибочная память, чтение недоступного архива, обучение весов, «никогда не путает»; игровая заглушка не рекламируется.

**D3. Охват = фактическая система, включая вне-волновые изменения (Q2).** `:1818` («после интеграции MCA-01…20») — про порядок выполнения, не границу охвата; критерий — «справка объясняет фактически работающего бота» (`:1816`). В охват входят ASAP-2/3/4-семантика ответов и MCA-22-атрибуция (прод 2.58.44 VERIFIED). Без номеров фич в пользовательском тексте. Повтор после будущих MCA-22/23 — отдельный handoff тем же механизмом (CA-21-4, `:15391–15393`, §38).

**D4. Содержание фич-гайда (§31.2).** Раздел изображений: авто-понимание без обязательного ответа + ручной reply на старый пост; три примера отдельными blockquote-блоками по образцу («Бот, что на картинке?» / «Бот, прочитай текст на скрине» / «Бот, опиши фото»); без слеш-команд; имя персонажа — пример, не триггер; пояснения: повтор без нового разбора, неоднозначный target → уточнение, отсутствующий файл → прислать снова, выключенный модуль/несовместимая модель → недоступно; картинка ≠ слова отправителя ≠ истина (фактчек доступен). Старые разделы фактчека/историй согласуются с фактической семантикой дат и статистикой (`:1834`).

**D5. Канон-дисциплина: бамп + полный слепок (Q3).** `INFO_CANON_VERSION 5→6` — прежний v5-текст в новую константу, `KNOWN_INFO_SNAPSHOTS` = (v1…v5); `GUIDE_CANON_VERSION 2→3` — прежний v2-текст (текущее содержимое сид-файла) в новую константу, `KNOWN_GUIDE_SNAPSHOTS` = (v1, v2) — порядок строго от старого к свежему (инвариант `guide_version_for`: 3/2/1). Реестры не чистятся. Сид-файлы синхронно (`info_text.md` — байт-тест `:342`; `intelligence_user_guide.md` — источник канона). Канон-тесты обновляются под v6/v3. Это единственная код-Δ фичи (`info_service.py` + сид-файлы + тесты).

**D6. Механика доставки не меняется (CA-21-1).** Доставка — через существующие `_seed_*`/`_migrate_*` (сид при отсутствии ключа; слепок→перезапись; одноразовый форс с `prev_html`/`prev_markdown` при неизвестном тексте без маркера; drift→не затирать, WARNING); no-op ×N при повторе; PG-only (seed не является источником истины, `:1840`); runtime tracked-файлы не пишет. `config_cache.py` — ожидаемо Δ = 0 (версии импортируются, миграция гайда версионирована содержимым); правка — только эскалацией.

**D7. Merge-политика ручных правок (Q4) — процесс, не код.** Pre-deploy gate: прод-статусы обоих ключей (`canon_drift`/версии). drift=false → штатно. drift=true → актуальные ручные правки вливаются в новый код-канон до релиза (ручная правка = источник факта). Конфликт → правка сохраняется в prev/backup + перечень неразрешённых участков в отчёте; статус доставки честный («доставлено с N неразрешёнными правками»), не «успех» (`:1840`). Авто-merge кодом не строится. Восстановление текста не откатывает функции (`:1842`).

**D8. Контракты и рендер заморожены, проверяются.** Δ routes = 0 (6 эндпоинтов `/api/info*` без изменений; `ROUTES_SHA256_F11` re-pin не требуется); RBAC `edit_info` не меняется; `GET /info/guide/backup` остаётся непубличным; санитизация (DOMPurify + лимиты) сохраняется — ручные правки не дают XSS. Проверки T-5211/T-5212: версии/drift/ветки доставки, злая санитизация, рендер обеих вкладок desktop/mobile (переносы/blockquote/ссылки/без сырой разметки), поиск видит новые заголовки, примеры воспроизводимы. Дефект рендера → текст подгоняется; UI-фикс — только эскалацией.

**D9. Санкции: Δ DDL = 0; Δ каталога = 0 (F8 NOT_APPLICABLE, записи `_CONTENT` точны); KS Δ = 0 (80/83/85 без новых); reason_code Δ = 0; тулы Δ = 0 (13/14, METERED без Δ); процессы mca-17a Δ = 0, новых widget-ID нет; routes Δ = 0; `app.js` ожидаемо Δ = 0.** Изменяемое: `services/info_service.py`, `info_text.md`, `plans/docs/intelligence_user_guide.md`, канон-тесты. Эскалация: любая Δ ≠ 0 → Step 2 amend, тихие расширения запрещены.

**D10. Deploy: DEFERRED_TO_RELEASE подтверждён (Q1), не superseded.** Пакет (тексты + бампы + тесты) готовится заранее на замороженном mca-release-кандидате; применение канон-доставки (T-5216) — в окне mca-release. Обоснование: честность контента (гайд = фактическая система после всех фич, `:1818` «входит в тот же выпуск и критерий завершения»), один канон-бамп без промежуточных версий, тексты не требуют изоляции бласт-радиуса (в отличие от supersede-прецедентов mca-19/20/12 — функциональные фичи). Rollback: soft — прежняя редакция из слепков/`prev_html`/`prev_markdown`/backup-API (текст не влияет на поведение); cold — git revert пакета (DDL нет). SSH/fail2ban-дисциплина AGENTS.md. Оговарка актуальности (Q7): приоритет — контент на замороженном кандидате; при вынужденном раннем написании — базовая прод-версия фиксируется в матрице T-5204, перед доставкой diff-сверка, финальный фильтр — live-приёмка T-5217 (no-false-acceptance); пометок версий в пользовательском тексте нет.

**D11. README (Q5) — вне пакета.** Правка остаётся в общем PM-close/mca-release-потоке (правило `:1847` — хвост всей программы); объём — краткая сводка + ссылка на «Справку», без дублирования гайдов (CA-21-2). Handoff T-5218: версии справки и матрица T-5204 → release-отчёт §21; повторная актуализация — handoff (§38).

**D12. Risk R1 confirmed; отдельный threat-failure-analysis не выпускается.** R3/R2-триггеры (новая схема/write-path/фоновая активность/новая приватность-поверхность) не сработали: DDL=0, запись — существующий DML-механизм с бэкапами, публичная поверхность — существующая (санитизация/RBAC/backup-RBAC). Угрозы (XSS ручных правок, backup-утечка, R17-контент, потеря правок, ложный успех доставки, поломка рендера) — спецификация §8 spec.md, покрываются T-5211/T-5212/T-5215/T-5216/T-5217. R17: секреты/живые чаты/персональные данные запрещены во всех артефактах фичи.

## Ответы PM Q1–Q7

1. **Deploy** → DEFERRED_TO_RELEASE подтверждён: применение в окне mca-release, пакет готовится заранее (D10). 2. **Охват** → фактическая система, включая ASAP-2/3/4 + MCA-22; без номеров фич; MCA-22/23-повтор — handoff (D3). 3. **Версии** → 5→6 / 2→3 + полные слепки, реестры не чистятся, порядок старый→новый (D5). 4. **Merge ручных правок** → процесс-санкция: gate → влить до релиза / конфликт → prev+backup+честный статус; без авто-merge кодом (D7). 5. **README** → вне пакета, общий PM-close/mca-release, ссылка+сводка (D11). 6. **Risk R1** → confirmed, все Δ = 0 (D9/D12), threat — §8 spec. 7. **Оговорка** → ждать заморозки; иначе базовая версия в матрице + diff-сверка перед доставкой + live-приёмка как фильтр (D10).

## Последствия

- **Позитив:** справка становится честным описанием финальной системы при нулевой код-поверхности (кроме канон-бампов по собственному регламенту F2/F6/F9); ручные правки владельца защищены (слепки+prev+backup+процесс merge); доставка идемпотентна и откатываема; один бамп на релиз.
- **Негатив/стоимость:** реестры слепков растут (осознанно — идемпотентность на любом прод-состоянии); merge-процесс требует ручного gate перед доставкой; контент-фаза заблокирована заморозкой кандидата (иначе — Q7-процедура).
- **Нейтрально:** ADR → Accepted по прод-валидации (T-5216/T-5217); merge в `plans/ARCHITECTURE.md` — @Architect на PM-close (T-5218).
