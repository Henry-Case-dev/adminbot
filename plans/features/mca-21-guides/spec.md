**D2. Матрица соответствия — обязательный артефакт T-5204, в гайд не попадает.** Для каждой пользовательской возможности строка «требование → реализованное поведение → место в гайде → проверка» (`:1826`). Технические исправления описываются через их эффект для пользователя, без дампа внутренних классов (`:1826`). Матрица прикладывается к отчёту T-5213 и передаётся в release-отчёт §21. **PARALLEL_SAFE уже сейчас** (read-only по коду/ARCHITECTURE).

**D3. Охват — фактическое поведение всей системы (Q2).** ТЗ `:1818` фиксирует **порядок** («последней, после интеграции MCA-01…20»), а не границу охвата; критерий `:1816` — «справка объясняет фактически работающего бота». Фиксация факта — на момент заморозки кандидата; повтор после MCA-22/23 — отдельный handoff (CA-21-4).

**D4. Честные значения вместо жёстких обещаний (`:1826`).** Темы §31.1 `:1824` покрываются по матрице D2: память/источники/честное время; личные факты и происхождение досье; честный охват и продолжение архивной пересборки; причины остановки парадигм и диагностика глубокого сна; истории и продолжения; сон/глубокий сон; убеждения/парадигмы; личность и самоидентификация; самостоятельность; случайность; обучение на опыте; достоверная статистика; изображения; временной фактчек; наблюдаемость; «где смотреть»: витрина, управление памятью, виджеты «Аналитики» (`:1824`, §21 п.5 `:1054`). Правила: (а) дефолты/состояния сверяются с кодом/каталогом на момент релиза (например «сон выключен по умолчанию, включается владельцем») — без фиксированных часов/кулдаунов как «вечных» обещаний; (б) запрещённые обещания — никогда: сознание, безошибочная память, чтение недоступного архива, обучение весов, «теперь никогда не путает даты/людей» (`:1824`/`:16413`); (в) игровая заглушка честно не рекламируется как работающая функция (`:1824`); (г) «где смотреть» — ссылки на реальные разделы миниаппы, названия экранов совпадают с релизом (`:1818`).

**SC-R1a (→A84):** каждая тема D4 имеет строку матрицы с реализованным поведением и местом в гайде; нет строк «обещано, но не реализовано» без пометки.

**SC-R1c:** все «где смотреть» открываются и показывают описанное (live-приёмка T-5217); примеры повторяемы; R17 — примеры обезличенные/тестовые.

**SC-R2a (→A84):** три примера оформлены по образцу blockquote+b/i и воспроизводимы в живом диалоге (T-5217); нет слеш-команды и хардкод-имени.

## 3. Канон и доставка: версии, слепки, drift (MCA21-R3; T-5209–T-5210)

**D7. Бамп версий + полные слепки (Q3) — единственная код-Δ фичи.** Механика `info_service.py:341–343`/`:387–388` соблюдается целиком:

Байт-тест `DEFAULT_INFO_TEXT ↔ info_text.md` сохраняется (`:342`) — сид-файл синхронно.
- **Guide (Markdown):** `GUIDE_CANON_VERSION 2→3`; прежний v2-текст (текущее содержимое `intelligence_user_guide.md`) — в новую константу, `KNOWN_GUIDE_SNAPSHOTS` = (v1 `PREV_R1023_INTELLIGENCE_GUIDE`, v2) — инвариант `guide_version_for` (`:621–623`): слепок i → `VERSION-(len-i)`, т.е. 3−2=1 (v1), 3−1=2 (v2); текущий текст → 3. `DEFAULT_GUIDE_MARKDOWN = ""` (fail-open R6) не трогается.

- **Обновление канон-тестов** (`tests/test_info_service.py`, `test_config_cache.py`, `test_guide_delivery_round1016.py`, `test_help_ui_round1023.py`): байт-тест, версии, слепки, ветки доставки — под v6/v3.

**D8. Пути доставки — существующая механика, семантика не меняется (CA-21-1).** После бампа стандартные ветки `_migrate_info_how_it_works_v1015` (`:267`) и `_migrate_intelligence_guide_r1023` (`:379`) доставляют новый канон: прод-текст == прежний канон/слепок → перезапись (+ `canon_delivered_version`); неизвестный текст без маркера доставки новой версии → одноразовый форс с бэкапом `prev_html`/`prev_markdown` (`:311–322`/`:428–433`); повторный прогон → no-op. Пустая БД → сид обоих ключей. Кеш (`hot`) и сброс — существующие. «Не ограничиваться seed, если production читает из БД» (`:1840`) выполняется самой механикой: миграция пишет PG-ключ, сид — только для отсутствующего ключа. Runtime-запись tracked-файла не возвращается (`:1840`; `InfoService.load` read-only `:656–659`, `save_text` PG-only).

**D9. Merge-политика ручных правок при drift (Q4) — процесс-санкция, авто-merge кодом не строится.**
1. **Pre-deploy gate (T-5210):** зафиксировать прод-статусы обоих ключей (`GET /api/info`, `GET /api/info/guide`, `GET /info/guide/backup` под `edit_info`): `canon_drift`, версии.
2. **drift = false** → штатная доставка (ветка слепка), merge не нужен.
3. **drift = true** (есть ручные правки владельца): снять прод-текст, дифф с новым каноном, **сохраняющие актуальность правки влить в новый код-канон до релиза** (ручная правка — такой же источник факта; правка, дублирующая новое исправление, заменяется новой формулировкой). Вливание — в рамках того же бампа (текст канона ещё не доставлен).
4. **Конфликт** (правку влить нельзя/неоднозначно): правка **не теряется** — остаётся в `prev_html`/`prev_markdown` (механизм бэкапит при любой перезаписи) и в `GET /info/guide/backup`; перечень неразрешённых участков фиксируется в отчёте T-5213; статус доставки в отчёте — «доставлено, N неразрешённых ручных правок (откат через backup/reset)», **не** «доставка успешна без потерь» (`:1840`).
5. Восстановление предыдущего текста (reset-canon/backup) не откатывает функции бота (`:1842`) — гайды не управляют поведением; проверяется тестом.

**SC-R3a (→A84):** свежий деплой на пустую БД и идемпотентный повтор миграции дают одинаковый канон (T-5209 критерий); `guide_version_for` на (текущий, v1, v2) даёт (3, 1, 2).
**SC-R3b:** прод-текст == v5-слепок → перезапись v6 с корректными маркерами; прод-текст == drift-редакция v5 с ручной правкой → форс с `prev_html` + честный лог; повторный прогон — no-op ×N.
**SC-R3c:** сценарий drift-БД покрыт end-to-end: merge/конфликт-фиксация/честный статус; восстановление из prev не меняет поведение бота (негативный тест).
