## 1. Область и исключения

**Входит (что делает A1):**
- **Координатор как расширение существующего Синтезатора** (§13/§14): единый программный слой принятия решения, охватывающий цепочку «намерение/адресат/память → выбор инструментов → оценка результатов → решение о действии» — **внутри** существующего direct-контура, без нового агента и без нового LLM-вызова.
- **Сохранение модельного выбора инструментов** (`tool_loop.chat_with_tools:89`, `tool_choice='auto'`) — координатор **не** подменяет и **не** дублирует выбор инструментов; он его обрамляет и оценивает.
- **Общий механизм цепочек** на существующем многораундовом `tool_loop` (`TOOL_MAX_ROUNDS=4`, ≤2 вызова/раунд): результаты нескольких инструментов **последовательно** передаются следующему этапу; зависимые вызовы A→B не параллелятся. **Per-combination обработчики запрещены.**
- **Разведение «решение о действии» ↔ «итоговый текст»** (§14): координатор формирует решение о действии (внутренний программный объект) **до** генерации текста; точка интеграции — существующий гейт Stage-2 (`direct_chat_service.py:814–818`).
- **Изоляция Вербализатора** (§14): Stage-2 получает **только** подготовленные факты (`stage2_payload`) + выбранный стиль (`response_mode`) и создаёт текст; **не выполняет скрытых серверных операций**; при молчании не запускается, при реакции текст не генерируется.
- **Наблюдаемость координатора** R17-safe (числа/коды/id/`error_type`), **reuse** существующих логов/событий; **граница A9** — карта вызовов/ExecutionGraph здесь не создаётся.
- **Обратная совместимость живого direct-чата** (OFF/legacy) и сохранение 2-вызовности System 2.

**Не входит (границы, категорически):**
- **Третий LLM-вызов** (§13: «Не создавать дополнительный LLM-вызов там, где достаточно обычной программной логики»); новый LLM-роутер; новый агент.
- **§15–§17 (A2):** полноценные последовательные tool calls с зависимостями, структурированные контракты инструментов §16, ограничение цепочек §17. A1 обеспечивает **только** reuse существующего общего механизма и явную границу.
- **§38–§40/§42–§48 (A7):** поле `action`, полное разведение `action`/`style`, новый Decision Making. A1 **не вводит** wire-поле `action`.
- **§18–§25 (A3/A4):** единый image request, генерация изображений на основе памяти.
- **§32–§35 (A6):** `get_user_context`, structured memory lookup.
- **§41/§44 (A8):** политика «когда молчать/отвечать/реагировать»; реакции Telegram.
- **§49/§51 (A9):** события/карта вызовов, настройки Decision Making.
- **§104 `generate_image`** — модель/провайдер/ключи/промпт/параметры/ошибки/порядок/прикрепление без изменений.
- **§85-UI** — изменения каталога/UI (Δ каталога ≠ 0) требуют **отдельной санкции**; вне A1.
- Изменения `plans/current_task.md`, машинного блока `OPENCODE_WORKFLOW_STATE_V1`, `plans/backlog.md`, `plans/metrics.md`, `plans/ARCHITECTURE.md` (на своих шагах), durable-аудита A0 (только чтение).

## 3. Наблюдаемое поведение и отказы

**Наблюдаемое поведение (что меняется в рантайме):**
- В direct-чате появляется **единый программный шаг принятия решения** (координатор), который до генерации текста фиксирует: намерение (по существующим программным маркерам), адресата (существующий резолв), необходимость памяти (существующие RAG/память-контуры), фактически вызванные инструменты и их оценку (`tool_trace`/`tool_context`), а также **решение о действии** (внутренний enum `reply`/`react`/`silent`/`tool`).
- **Модель по-прежнему выбирает инструменты** (`tool_choice='auto'`); координатор **не** вызывает инструменты сам и **не** добавляет LLM-вызовов.
- **Текст** создаётся существующим Вербализатором (Stage-2), изолированно от сырья.
- **Наблюдаемость:** R17-safe запись решения координатора (числа/коды/id/`error_type`, имена инструментов, длины) в существующие логи; новых систем аналитики/карт не создаётся.
- **Поведенческие исходы сохраняются:** A1 формализует решение о действии, но **не вводит новую политику** молчания/реакций (§41/§44 — A8). Это «структура + изоляция + наблюдаемость», а не изменение сценариев.

**Отказы/негативные сценарии (что считается НЕ выполнением):**
- Добавлен **3-й LLM-вызов** или новый LLM-роутер/агент → не принято (REQ-A1-03).
- Выбор инструментов **продублирован** координатором или заменён; `tool_choice` форсируется → не принято (REQ-A1-04/-07).
- Создан **per-combination обработчик** или второй роутер/дубликат инструмента → не принято (REQ-A1-08, freeze 10).
- **Вербализатор** выполняет серверные операции (инструменты/сеть/БД сверх передачи фактов) или получает сырьё/теги → не принято (REQ-A1-06).
- Введено wire-поле **`action`** или полное разведение `action`/`style` (граница A7) → не принято (REQ-A1-10/-11).
- Вербализатор запускается при **молчании** или текст генерируется при **реакции** → не принято (REQ-A1-01/-06).
- Изменены §104 `generate_image`, §85-UI/каталог, DDL, канон промптов вне ADR-1013-3 → не принято (REQ-A1-12).
- Создана **вторая** система аналитики/карты вызовов вместо REUSE ExecutionGraph → не принято (REQ-A1-09).
- OFF/legacy-поведение не байт-в-байт (или без явного AMEND Step 2) → не принято (REQ-A1-12).

## 4. Решения (открытые вопросы (a)–(e))

### (a) ГЛАВНОЕ — scope Координатора
**Выбрано: вариант (i) — модельный выбор инструментов сохраняется; добавляется программный слой решения о действии в рамках существующих Stage-1/2.** (ADR D1–D2.)

- **Что меняется относительно текущего.** Сейчас инструменты выбирает **модель** внутри `tool_loop.chat_with_tools:89` (`tool_choice='auto'`), а «решение о действии» **неявно**: молчание/реакция возникают только как реакция на пустой/битый ответ LLM (`direct_chat_service.py:794–802,834–839`). A1 делает решение о действии **явным и программным** и обрамляет существующие стадии, не меняя их число.
- **Где программная логика, где LLM.** Программно: намерение (существующие маркеры dig/image-пре-гейтов), адресат (`target_user_id`/`target_name`/forward), необходимость памяти (существующие RAG/память-контуры), выбор инструментов (существующий `tool_loop`), оценка результатов (`tool_trace`/`tool_context`), решение о действии. LLM — только там, где уже был: выбор инструментов моделью (первый вызов tool-loop) и создание текста (Stage-1 справка + Stage-2 Вербализатор).
- **Почему не вариант (ii).** Явный контракт Координатора в промпте Stage-1: (1) Stage-1 System 2 запускается **только** на ходах с реально вызванными инструментами (`:814–818`) — он физически не покрывает ходы без инструментов, где как раз и решается молчание/реакция/простой ответ; (2) он дублировал бы модельный выбор инструментов, который уже произошёл в tool-loop; (3) потребовал бы канон-миграции промптов (ADR-1013-3) и риска конфликта с будущим полем `action` (A7). Итог: (ii) — дороже, рискованнее и неполно по покрытию.
- **Третий LLM-вызов запрещён** (§13) — координатор не добавляет ни одного вызова. 2-вызовность System 2 (`await_count==2`) сохраняется.

### (b) AMEND-карта и канон промптов
- **ADR-1022-4 (Саммари, 2-вызовный пайплайн): NOT_APPLICABLE** — A1 не касается саммари.
- **ADR-1022-5 (Direct Chat, 2-вызовный пайплайн): effective AMEND-заметка (без структурного изменения).** A1 формально закрепляет, что роль Координатора реализуется **внутри** существующего пайплайна (первый вызов tool-loop + Stage-1 Синтезатор + программный гейт), физическая 2-вызовность System 2 сохраняется. Заметка фиксируется в ADR-1026-14; архивный ADR-1022-5 остаётся Accepted как есть.
- **ADR-1023-3 (`action` vs `style`): effective AMEND-заметка (без структурного изменения).** A1 вводит **внутренний** программный объект решения о действии (`reply`/`react`/`silent`/`tool`), но **не** вводит wire-поле `action` и не разводит контракт `action`/`style` — полное разведение остаётся **A7**.
- **ADR-1013-3 (канон промптов): NOT_APPLICABLE — промпты в A1 не меняются.** Обоснование: модельный выбор инструментов сохранён; координатор программный; Stage-1 JSON не расширяется (во избежание конфликта с A7 и дрейфа канона). Следствие: **`PREV_*`-слепки, `PROMPT_MIGRATIONS`/`ROLLBACK_MIGRATIONS`, эталонные байт-тесты не добавляются**; T-3511 закрывается подтверждением NOT_APPLICABLE. *(Если в ходе реализации понадобится правка промпта — только атомарно по ADR-1013-3 и с возвратом к Step 2; по умолчанию — нет.)*

### (c) Санкции
- **Δ DDL = 0** (ожидаемо и требуется): новых таблиц/колонок/индексов нет; SQLite v12.
- **Δ каталога = 0** (ожидаемо и требуется): `param_catalog.py` вне diff; новые PG-ключи/Settings не вводятся. Любой новый kill-switch — **env-only** (`ClassVar`), каталог не растёт (прецедент ADR-1022-4/-5).
- **§85-UI — отдельная санкция:** изменения UI/каталога в A1 не выполняются; Δ каталога ≠ 0 — блокер.

### (d) Deploy / активация / откат
- **Deploy = ДА.** A1 меняет рантайм direct-чата (программный слой решения, наблюдаемость), поэтому прецедент read-only NOT_APPLICABLE неприменим.
- **Bump:** `APP_VERSION` **2.58.29 → 2.58.30** (следующий patch; точную версию подтверждает @DevOps в T-3522).
- **Активация:** автоматическая по push/ff; координатор активен по умолчанию. Гейт: **env-only kill-switch `DIRECT_COORDINATOR_ENABLED` (default ON, Δ каталога=0)** — OFF → точный legacy-путь. `SYSTEM2_DIRECT_ENABLED=false` по-прежнему отключает System-2-путь (legacy без Синтезатора/Вербализатора).
- **Hot-OFF/rollback:** `DIRECT_COORDINATOR_ENABLED=false` (мгновенно, без рестарта кода — резолв per-call); канон-откат **не требуется** (промпты не менялись); откат кода — annotated-тег **`pre-round1026-a1`** → `e3ea367` + `git revert`. Теги/бэкапы не удаляются (R18).

### (e) Границы волн
- **A2 (§15–§17):** A1 **оставляет** A2 всё, что касается полноценных последовательных вызовов с зависимостями, структурированных контрактов инструментов (§16) и ограничения цепочек (§17). A1 делает **только**: подтверждение/усиление **общего механизма цепочек** на существующем `tool_loop` (многораундовый цикл, role `tool`, второй шаг после tool response) + лимиты/деградация (`TOOL_MAX_ROUNDS=4`, ≤2/раунд, fail-open). **Per-combination handlers запрещены.**
- **A7 (§38–§40/§42–§48):** поле `action`, разведение `action`/`style`, новый Decision Making — целиком A7. A1 — только минимальное «решение о действии ≠ текст» **программно**.
- **A3/A4 (§18–§25), A6 (§32–§35), A8 (§41/§44), A9 (§49/§51)** — не реализуются и не дублируются. A1 **reuse** ExecutionGraph только для наблюдаемости, владелец карты вызовов — A9.
- **§104 `generate_image`** — не трогать. **§85-UI** — вне scope.

## 5. Feature contract (границы ответственности)

**Preconditions:**
- direct-чат сконфигурирован (`tool_router` доступен для tool-пути); `SYSTEM2_DIRECT_ENABLED`/`DIRECT_COORDINATOR_ENABLED` резолвятся per-call.
- Канон `TOOL_CALLING_TOOLS` = **10** без изменений; `active_tools`-гейты (lore/image/transcribe) действуют как прежде.

**Invariants (нарушение = не принято):**
1. Freeze канона 10 инструментов; дубликатов/новых инструментов нет.
2. Ровно 2 физических LLM-вызова System 2 (`await_count==2`); координатор не добавляет LLM-вызовов.
3. Выбор инструментов — модельный (`tool_choice='auto'`), не форсируется, не дублируется.
4. Общий механизм цепочек = существующий `tool_loop`; per-combination обработчиков нет.
5. Вербализатор не выполняет скрытых серверных операций; получает только факты + стиль.
6. При молчании Вербализатор не запускается; при реакции текст не генерируется.
7. REUSE ExecutionGraph; вторая аналитика не создаётся.
8. Δ DDL=0; Δ каталога=0; §104/§85-UI вне diff.
9. R17/R18: только числа/коды/id/`error_type`; без ключей/промптов/сырых текстов/сырых ответов LLM; теги/бэкапы целы.
10. OFF/legacy — байт-в-байт.

**Inputs/Outputs:**
- **Вход:** сообщение Telegram + существующий контекст (`_build_user_content`), `tool_ctx`.
- **Выход:** (а) внутренний объект решения координатора (intent, addressee, memory_need, tool_calls, evaluation, action, style) — **не** wire-контракт; (б) финальное действие: reply (текст) / react / silent / tool; (в) R17-safe событие.
- **Контракт стадий (не меняется):** tool-loop `ToolLoopResult` (`tool_trace`, `tool_context`, `degraded`, `reason`, `rounds_used`); Stage-1 `parse_direct_synthesis` JSON (`user_question`, `facts[]`, `answer_outline`, `limitations[]`, `response_mode`); Stage-2 `stage2_payload` + `compose_verbalizer_system` (стиль/канал).

**Failure semantics (fail-safe):**
- Невалидная справка Stage-1 / сбой Вербализатора → `None` → финал tool-loop (существующее поведение).
- Деградация tool-loop (`degraded`) → частичный текст/заглушка; координатор не «изобретает» действие вне существующих ветвей.
- Kill-switch OFF → legacy-путь без координатора.

**Compatibility:** живой direct-чат не регрессирует; OFF/legacy байт-в-байт; 2-вызовность сохранена; контракты Stage-1/Stage-2 не ломаются (аддитивность).

**Observability:** R17-safe событие координатора (коды решения, имена инструментов, числа/длины) через существующие логи; reuse ExecutionGraph-адаптера; **без** второй аналитики.

**Acceptance evidence:** тесты координатора (intent/addressee/memory; tool selection+evaluation; action≠text; общий механизм цепочек; отсутствие per-combination), R17-тесты, регресс живого direct-чата (OFF байт-в-байт; 2-вызовность), diff-аудит (§104/§85-UI/DDL/каталог).

**Deployment applicability:** ДА, bump 2.58.30; активация авто; kill-switch env-only.

**Rollback boundary:** `DIRECT_COORDINATOR_ENABLED=false` (hot) / `pre-round1026-a1` + `git revert` (cold); канон-откат не нужен (промпты не менялись).

**Ownership верификации:** @Builder (T-3503…T-3517 — реализация+тесты) → единый @Reviewer gate (T-3518 линза requirements/correctness, T-3519 линза focused change audit) → @Architect merge (T-3520) → @DevOps deploy (T-3522). @Scanner отсутствует.
