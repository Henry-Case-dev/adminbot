# ADR-1026-14 — A1 «Tool Coordinator»: scope Координатора внутри существующего Синтезатора, общий механизм цепочек, изоляция Вербализатора, границы A2/A7

- **Статус:** **Proposed** → **Accepted по merge** (T-3519/T-3520; номер финального шага — по факту). Основание для Proposed: Step 2 @Architect (T-3501); сверка @PM (T-3502).

- **Тип:** backend/agentic (оркестрация инструментов) — **расширение существующего контура**; без нового агента, без 3-го LLM-вызова, без DDL/каталога, без правки промптов.
- **ТЗ-основание:** `plans/current_task.md` **§13** (`:4440–4479`), **§14** (`:4482–4517`); границы §15–§17 (A2), §18–§25 (A3/A4), §32–§35 (A6), §38–§40/§42–§48 (A7), §41/§44 (A8), §49/§51 (A9), §85 (UI — отдельная санкция), §104 (`generate_image` — не трогать).

- **Связано:** REUSE — ADR-1026-13 (durable-аудит/freeze 10), ADR-1022-4/-5 (2-вызовность), ADR-1023-3 (`action`/`style`), ADR-1013-3 (канон промптов), ADR-1025-24 (верификационный гейт, deploy NOT_APPLICABLE-прецеденты); AMEND — по решению D5.

## Контекст

§13 задаёт целевой логический процесс: «Сообщение Telegram → Определение намерения и адресата → Синтезатор / Координатор → Решение о действии → При необходимости — инструменты → Проверка результатов → Формирование итогового действия → Вербализатор, генератор изображения, реакция или молчание», с оговорками: «Не каждый запрос должен проходить через все этапы», «Если достаточно молчания, Вербализатор не запускается», «Если достаточно реакции, полноценный текст не генерируется», «Если требуется несколько инструментов, их результаты последовательно передаются следующему этапу», **«Не создавать дополнительный LLM-вызов там, где достаточно обычной программной логики»**.

§14 предписывает: «Существующий Синтезатор расширяется возможностью выбирать и координировать инструменты», «решение о действии и итоговый текст — разные задачи»; Синтезатор «определяет намерение; разрешает адресата; определяет необходимость памяти; выбирает инструменты; оценивает результаты; выбирает действие»; Вербализатор «получает подготовленные факты; получает выбранный стиль; создаёт текст; **не выполняет самостоятельно скрытые серверные операции**»; «Использовать существующую архитектуру tool calling, если она поддерживает последовательные вызовы»; «Не реализовывать отдельный обработчик для каждой комбинации инструментов. Нужен общий механизм выполнения цепочек».

**Фактическое состояние baseline (A0, EVIDENCE).** Выбор инструментов делает **модель** внутри многораундового `tool_loop.chat_with_tools:89` (`tool_choice='auto'`, `TOOL_MAX_ROUNDS=4`, `_TOOL_CALLS_PER_ROUND_MAX=2`; `tool_loop.py:38–39,112–196`); второй шаг после tool response **уже есть** (EV-08). «Решение о действии» **неявно**: молчание/реакция — только как реакция на пустой/битый ответ LLM (`direct_chat_service.py:794–802,834–839`); отдельного поля `action` нет (EV-26). System 2 direct — ровно 2 физических вызова (Stage-1 Синтезатор `_synthesize_direct_answer:932–935` → `parse_direct_synthesis:936`; Stage-2 Вербализатор `:972`), запускается только при реально вызванных инструментах/успешном финале/НЕ `lore_compiled` (`:814–818`).

**Проблемные вопросы (open questions Step 1 (a)–(e)), требующие lasting-решения:**
1. Что именно меняется в Синтезаторе: оставить модельный выбор инструментов + программный слой действия (i) или явный контракт Координатора в промпте Stage-1 (ii)? Как при этом **не** ввести 3-й LLM-вызов?
2. Нужны ли AMEND ADR-1022-4/ADR-1023-3 и меняются ли промпты (канон ADR-1013-3)?
3. Санкции Δ DDL/Δ каталога.
4. Deploy/активация/откат.
5. Границы A2 (§15–§17) и A7 (`action`).

## Решения

**D1. Scope Координатора — вариант (i): модельный выбор инструментов сохранён, добавлен программный слой решения о действии внутри существующих Stage-1/2.**
- Координатор реализуется как **программный слой** в существующем direct-контуре (`DirectChatService`), обрамляющий существующий пайплайн; **новый агент не создаётся**, `tool_choice='auto'` не форсируется, выбор инструментов моделью **не дублируется и не подменяется**.
- Роль Координатора покрывает: намерение (программные маркеры существующих пре-гейтов dig/image), адресат (существующий резолв `target_user_id`/`target_name`/forward), необходимость памяти (существующие RAG/память-контуры), выбор инструментов (существующий `tool_loop`), оценку результатов (`tool_trace`/`tool_context`), решение о действии (программный гейт на существующей точке Stage-2 `:814–818`).
- **Программная логика приоритетна** (§13): LLM вызывается только там, где уже вызывался (выбор инструментов моделью; Stage-1 справка; Stage-2 текст). **0 новых LLM-вызовов.**
- **Альтернатива (ii) — явный контракт Координатора в промпте Stage-1 — отклонена:** (1) Stage-1 System 2 физически запускается только на ходах с реально вызванными инструментами (`:814–818`) и не покрывает ходы без инструментов, где и решаются молчание/реакция/простой ответ; (2) дублирует модельный выбор инструментов, уже произошедший в tool-loop; (3) требует канон-миграции промптов и создаёт риск конфликта с будущим wire-полем `action` (A7). Итог: дороже, рискованнее и неполно по покрытию.

**D2. Контракт Координатора — внутренний программный объект, не wire-контракт.**
- Решение фиксируется как **внутренняя структура** (намерение, адресат, `memory_need`, `tool_calls`, `evaluation`, `action`, `style`), используется для оркестрации и R17-safe наблюдаемости; **не сериализуется** в Stage-1/Stage-2 JSON.
- **Wire-поле `action` не вводится** (граница A7, §38–§40). Существующий JSON Stage-1 (`parse_direct_synthesis`) и контракт Stage-2 (`stage2_payload`) **не меняются** — промпты не правятся (см. D5).
- Внутренний enum действия (`reply`/`react`/`silent`/`tool`) — **не** каталог/не UI/не контракт доставки; A7 формализует внешний `action`.
- **Альтернатива «добавить `action`/intent-поля в Stage-1 JSON» отклонена:** нарушает границу A7 и ведёт к дрейфу канона.

**D3. Общий механизм цепочек — reuse существующего многораундового `tool_loop`; per-combination запрещены; A2 владеет §15–§17.**
- Результаты нескольких инструментов передаются следующему этапу **последовательно** существующим циклом (`tool_loop.py:112–196`, роли `assistant`/`tool`, повтор LLM-вызова; зависимые A→B не параллелятся). Лимиты/деградация — существующие `TOOL_MAX_ROUNDS=4` / `_TOOL_CALLS_PER_ROUND_MAX=2` / fail-open (`degraded`, `round_limit`, `llm_error`).
- **Отдельный обработчик на комбинацию инструментов не создаётся**; второй роутер не создаётся; `ToolRouter` и канон 10 переиспользуются.
- **Граница A2:** полноценные последовательные вызовы с зависимостями, структурированные контракты инструментов §16 и ограничение цепочек §17 — **A2**; A1 только подтверждает/усиливает общий механизм и фиксирует границу.

**D4. Изоляция Вербализатора.**
- Stage-2 получает **только** подготовленные факты (`stage2_payload(data)`, без служебных полей) + выбранный стиль (`response_mode` через `compose_verbalizer_system`); создаёт текст; **не выполняет скрытых серверных операций** (не вызывает инструменты/сервисы, не ходит в сеть/БД сверх передачи фактов).
- При молчании Вербализатор **не запускается**; при реакции полный текст **не генерируется** (существующее поведение сохраняется; политика «когда молчать/реагировать» — A8, здесь только изоляция/условия запуска).
- 2-вызовность System 2 (`await_count==2`) сохраняется.

**D5. AMEND-карта и канон промптов.**
- **ADR-1022-4 (Саммари, 2-вызовный пайплайн): NOT_APPLICABLE** — A1 не касается саммари.
- **ADR-1022-5 (Direct Chat, 2-вызовный пайплайн): effective AMEND-заметка (без структурного изменения).** A1 формально закрепляет, что роль Координатора реализуется внутри существующего пайплайна (первый вызов tool-loop + Stage-1 Синтезатор + программный гейт), а физическая 2-вызовность System 2 сохраняется. Заметка фиксируется здесь; архивный ADR-1022-5 остаётся Accepted без переписывания.
- **ADR-1023-3 (`action` vs `style`): effective AMEND-заметка (без структурного изменения).** A1 вводит **внутреннее** программное решение о действии, но не wire-поле `action` и не разводит контракт `action`/`style`; полное разведение — **A7**.
- **ADR-1013-3 (канон промптов): NOT_APPLICABLE — промпты в A1 не меняются.** Следствие: `PREV_*`-слепки, `PROMPT_MIGRATIONS`/`ROLLBACK_MIGRATIONS`, эталонные байт-тесты **не добавляются**; T-3511 закрывается подтверждением NOT_APPLICABLE. Любая правка промпта в ходе реализации — только атомарно по ADR-1013-3 и с возвратом к Step 2; по умолчанию — нет.
- **Альтернатива «сразу переписать ADR-1022-5/-1023-3» отклонена:** A1 не меняет структуру пайплайна и не разводит `action`/`style`; переписывание архивных Accepted-ADR было бы ложным сигналом о структурном изменении.

**D6. Санкции: Δ DDL = 0, Δ каталога = 0, §85-UI — отдельная санкция.**
- Новых таблиц/колонок/индексов нет (SQLite v12). `param_catalog.py` вне diff; новые PG-ключи/Settings не вводятся. Любой новый kill-switch — **env-only** (`ClassVar`), каталог не растёт (прецедент ADR-1022-4/-5).
- §85-UI: изменения UI/каталога (Δ каталога ≠ 0) в A1 не выполняются и требуют отдельной санкции.

**D7. Deploy/активация/откат: deploy = ДА, bump `APP_VERSION` 2.58.29 → 2.58.30.**
- A1 меняет рантайм direct-чата → прецедент read-only NOT_APPLICABLE неприменим. Точная версия подтверждается @DevOps (T-3522).
- Активация автоматическая (push/ff); координатор активен по умолчанию. Kill-switch — **env-only `DIRECT_COORDINATOR_ENABLED` (default ON, Δ каталога=0)**; OFF → точный legacy-путь. `SYSTEM2_DIRECT_ENABLED=false` по-прежнему отключает System-2-путь.
- Откат: hot — kill-switch; cold — annotated-тег **`pre-round1026-a1`** → `e3ea367` + `git revert`; **канон-откат не требуется** (промпты не менялись). Теги/бэкапы не удаляются (R18).

**D8. Границы волн: A2/A7/A3/A4/A6/A8/A9 не реализуются; §104 не трогать; REUSE ExecutionGraph.**
- A2 (§15–§17), A7 (`action`/`style`, новый Decision Making), A3/A4 (§18–§25), A6 (§32–§35), A8 (§41/§44), A9 (§49/§51) — вход, не реализация.
- Наблюдаемость — **reuse** `execution_graph_source.build_graph:485` / `web/api/analytics.py:281` / `web/static/execution_graph.js:341`; вторая система аналитики не создаётся; карта вызовов — A9.
- **§104 `generate_image`** — модель/провайдер/ключи/промпт/параметры/ошибки/порядок/прикрепление без изменений.

**D9. Наблюдаемость Координатора — R17-safe, reuse существующих логов/событий.**
- Логируются только числа/коды/id/`error_type`/имена инструментов/длины; без ключей/промптов/сырых текстов/сырых ответов LLM. Новая аналитика/карта вызовов не создаётся (граница A9).

**D10. Risk-Level: R2.**
- Обоснование: изменение живого контура принятия решений direct-чата (blast radius — каждый диалог) при **поведенчески-сохраняющем** дизайне (структура+изоляция+наблюдаемость, без новой политики молчания/реакций), без DDL/каталога, обратимо (kill-switch + тег), с сохранённой 2-вызовностью и полным регрессом OFF/legacy.
- **Повышает до R3:** изменение наблюдаемых исходов действий; правка промптов (канон) или структурное изменение `tool_loop`; любой новый LLM-вызов; изменение wire-контракта Stage-1/Stage-2; утечка сырья в Вербализатор.
- Reviewer может повысить уровень.

## Последствия

- Синтезатор получает **явную роль Координатора** без нового агента и без 3-го LLM-вызова; 2-вызовность System 2 сохранена.
- Решение о действии становится **отдельным от текста** (§14) и наблюдаемым (R17-safe), без введения wire-`action` (A7).
- Вербализатор изолирован: только факты + стиль; без скрытых серверных операций.
- Цепочки инструментов идут общим механизмом `tool_loop`; per-combination обработчики отсутствуют.
- Живой direct-чат не регрессирует: OFF/legacy байт-в-байт (kill-switch), откат — тег + `git revert`; канон-откат не нужен.
- Δ DDL=0, Δ каталога=0, §104/§85-UI вне diff; REUSE ExecutionGraph.
- A2 получает чистую границу (§15–§17), A7 — (`action`/`style`).
