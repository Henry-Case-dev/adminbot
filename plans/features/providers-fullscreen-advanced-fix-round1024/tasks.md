## Цель
Устранить UI-дефект: при переходе в полноэкранный режим TMA в разделе «Провайдеры» (вкладка `llm_providers`) **схлопывается аккордеон «Расширенные системные»** (`<details>` с advanced-настройками), и раскрытие не переживает переход/ре-рендер.

**Первопричина (разведка @Memory):** разрыв между состоянием fullscreen в TMA и Vue-состоянием приложения + **нереактивный** стейт аккордеона:
1. `isFullscreen: false` (`web/app.js:939`) инициализируется константой и **никогда не читается из `Telegram.WebApp.isFullscreen`**; `toggleFullscreen()` (`web/app.js:3651-3665`) — оптимистичный локальный флаг **без подписки** на события TMA. Подписок на `fullscreenChanged` / `viewportChanged` / `safeAreaChanged` нет нигде (подтверждено: единственное `onEvent` — `'ready'`, `web/app.js:1650-1651`).
2. Стейт аккордеона **нереактивный**: `expandOpen()` (`web/app.js:3768-3772`) читает `localStorage` **на каждом рендере**, `toggleExpand()` (`:3773-3779`) пишет прямо в `localStorage`; ключ `adminbot.expand:llm_providers:prov-advanced` (`_expandKey`, `:785-787`); поле `data.expand` (`web/app.js:831`) — **мёртвое** (не обновляется). Биндинг `:open` вызывает **функцию** — Vue не отслеживает `localStorage` как реактивную зависимость.

**Итог:** переход в fullscreen на мобильном WebView вызывает ремаунт/ре-рендер вкладки, `<details>` пересоздаётся — а `:open` берёт неактуальное значение (или успевает схлопнуться), раскрытие теряется.

## Критерии приёмки
- В разделе «Провайдеры» раскрытие «Расширенных системных» **переживает** вход в fullscreen и выход из него (live TMA, доказать скриншотом/видео).
- `isFullscreen` отражает фактическое состояние TMA (инициализация из `Telegram.WebApp.isFullscreen` + события), а не только локальную инверсию; подписки снимаются при размонтировании.
- Раскрытие аккордеона хранится в реактивном состоянии; `localStorage` — только персист; повторный рендер/ремаунт не схлопывает аккордеон.
- Нет регресса вне fullscreen и на других вкладках; раздельные `scope`-ключи не конфликтуют.
- Полный pytest — 0 failed; `node --check web/app.js` — OK; JS-тесты печатают OK; `git diff --check` чист.

## Риски
- **R1 (High):** ремаунт WebView при fullscreen не воспроизводим локально → live-приёмка (T-2387) как обязательный контракт; если корень не только в ре-рендере — фикс может не закрыть дефект (эскалация @Architect).
- **R2 (Medium):** подписка на TMA-события конфликтует с решением 10.10 и/или даёт двойные подписки → **AMEND** + `offEvent` + защита от повторной подписки.
- **R3 (Medium):** общий фикс всех `details.advanced` задевает чужие вкладки (внутренние group-аккордеоны) → раздельные `scope`-ключи + регресс-тест; при сомнении — минимальный скоуп (только «Провайдеры»).
- **R4 (Low):** `Telegram.WebApp`/события недоступны вне TG (браузер, старый SDK) → безопасные обёртки try/catch и фолбэк на прежнее поведение.
- **R5 (Low):** кэш статики отдаёт старый `app.js` → cache-bust (`?v=`/`APP_VERSION`).
