# WIN-GLASS-P0 — что проверить владельцу (точные шаги)

Файл для требования `WG-WIN-05`/`MAN-WG-08..11`: воспроизводимый обход
клиентского дефекта Telegram Desktop (Windows) + живое сравнение рефракции на
Android. Проверки требуют реальных клиентов и помечены `PENDING_OWNER_E2E`.

## A. Windows — обход геометрии fullscreen (сейчас)

Почему обход нужен: у Telegram Desktop на Windows панель mini app при входе в
fullscreen **растягивается, но не перемещается** в origin монитора
(telegramdesktop/tdesktop#30963; фикс `lib_ui` PR #342 ещё не влит). Веб-код
нативного окном не управляет — в Mini Apps API нет ни одной функции геометрии
окна (только `web_app_request_fullscreen` / `web_app_exit_fullscreen`).

Шаги (по возрастанию усилий):

1. **Главное окно Telegram → в левый верхний угол монитора**, затем открыть
   mini app (Launch Mode = Fullscreen).
   Ожидаемо: панель закрывает рабочую область монитора, панель задач скрыта,
   тапы/курсор не смещены. Это подтверждённый обход апстрима: смещение
   пропорционально позиции главного окна.
2. Если окно двигать не хочется — **перенести Telegram на второй монитор** и
   открыть mini app там (в отчёте #30963 fullscreen позиционируется верно).
3. **Перезапуск окна:** выйти из fullscreen кнопкой ⛶ (панель вернётся в
   оконный вид), поставить главное окно в левый верхний угол, снова войти ⛶.
4. **Правильное лечение** — обновление клиента, когда фикс `lib_ui` #342
   (и связанные #31041/#31114/#343) попадёт в релиз Telegram Desktop.
   Проверить версию: `Настройки → внизу версия` (или `About`).
5. **Если нужен обходной UX «не стартовать в fullscreen»:** BotFather →
   `/mybots` → бот → `Bot Settings` → `Configure Mini App` → Main Mini App →
   пункт про режим запуска (Launch Mode: Compact / Fullscreen; в текущих
   версиях BotFather название пункта может отличаться). Быстрая A/B-проверка —
   открыть mini app ссылкой с `?mode=compact`.
   **Оговорка:** это не лечит баг: при ручном нажатии ⛶ дефект вернётся (тот же
   код клиента). На мобильных приложение будет открываться не на весь экран —
   изменение затрагивает все платформы, поэтому по умолчанию не предлагается.

## B. Windows — что прислать в отчёт (чек-лист)

1. Версия Telegram Desktop (Windows) и разрядность.
2. Симптом при открытии: (а) без обхода — панель смещена/панель задач видна?
   (б) после обхода §A.1 — панель занимает рабочую область?
3. Снимок админ-диагностики: в mini app `Меню → ⛶ диагностика геометрии`
   (доступна глобальному админу, off by default) → кнопка копирования даёт
   platform/SDK/`isFullscreen`/viewport/dpr/insets/rect кнопки и шапки/`slot`.
4. Поведение управления: ⛶ = выход (панель в оконный вид), ⛶ = вход, закрытие
   панели системной кнопкой, перетаскивание и изменение размера в оконном
   режиме.
5. Мультимонитор/DPI, если применимо: смещение уменьшается при переносе окна?

## C. Android — живое сравнение рефракции

1. Открыть mini app в Telegram на телефоне (Android), дойти до экранов со
   стеклянными карточками (Статус/Модули).
2. Смотреть на кромки крупных карточек: должно быть **видимое смещение**
   фонового полигонального рисунка у кромки (сжатие/сдвиг линий), а не только
   равномерный blur. Центр карточки — спокойный, текст/кнопки не искажены.
3. Повторить на контрастном участке фона (яркая грань/линия полигона у кромки
   карточки) — смещение читается отчётливее.
4. Проверить плавность при скролле и после свёртывания/возврата приложения
   (слой обязан «догнать» фон).
5. Если есть iPhone — тот же пункт 2 (ожидаемо: смещение есть, frost сохранён).

## D. Что технически уже проверено (агентами)

`tools/ui_win_glass_refraction_e2e.py` (33+ проверки): слой создаётся только на
мобильном клиенте и только для Tier A, бюджет ≤3 поверхностей, нет остаточного
`url()` в backdrop-filter, hit-тесты чистые, раскладка не двигается, яркость
кромок −1.9 %, стоимость кадра слоя ≈0.2 ms (эмуляция Chromium, mobile-вьюпорт),
раскладка/скролл без изменений. Смещение линий на тест-паттерне: −13/+16 CSS px
(corr 0.92–0.97), центр 0 px (corr 1.0). Скриншоты/числа —
`plans/features/win-glass-hotfix/evidence/`.
