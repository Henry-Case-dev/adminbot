## 1. Контекст

После закрытия программы MCA (прод 2.58.67, `6f062fa`) владельческая витрина фиксирует: (а) Hybrid Summary систематически уходит в Legacy — прод: 8/8 последних fallbacks `l2_unusable`, причина невидима (Run Inspector: «Writer не выполнено» при реально выполненном Writer'е); (б) Cover: до image-provider доходит стиль/профиль/номер/инварианты, но сюжет — единственная budget-жертва (double-squeeze + unknown-limit retry `minimal=True` выбрасывает brief; прод 911→708, 2/2), полный sent prompt не персистится нигде; (в) GraphRAG `graph_facts_vec` — квот-paused job 576 пауз/7.5 суток, checkpoint 40% заморожен: resume-gap `_ensure_job` (неистёкший `next_allowed_at` → без future-resume) + рестарты ~1.3 ч = вечный `building`/FTS-only; (г) Random `provider_unconfigured` — честный config-state, но bootstrap paradox: незаданный секрет не попадает в `/api/config` (`cache.get_all()`), карточки подключения нет; (д) парадигмы: cooldown скрывает причину прошлой попытки (прод: 16 подряд `no_anchors`); (е) граф — стена текста, без semantic zoom. RCA подтвердили 9/9 пунктов Summary-аудита, root causes Cover/GraphRAG/Random/парадигм/графа. Директива владельца: сначала root causes на HEAD+прод (выполнено), ≤3 writer-лейна при непересекающихся скоупах, без human gate, не переписывать подсистемы целиком.

## 2. Решение (D1–D19; полная аргументация — spec.md §2)

1. **D1 L1-семантика** OK / DEGRADED_MAP_FALLBACK / FAILED_TERMINAL (durable + витрина; «Writer продолжил от полного окна»; FAILED_TERMINAL — только когда Writer не стартовал: нет ни карты, ни окна/fallback package).
2. **D2 Server-owned таксономия** `FINDING_CODE_TAXONOMY`: все 15 кодов → hard|soft, promote только через deterministic proof, demote запрещён, `can_force_legacy` только у hard; unknown-код → dropped_invalid; severity-поле модели не решает.
3. **D3 `unusable`-gate:** terminal только при ≥2 независимых валидных HARD findings (разные коды И разные targets) ИЛИ deterministic proof; иначе даунгрейд до needs_fixes (трейс-событие, reason `l2_unusable_gate`).
4. **D4 Stagnation по fingerprint** `code+paragraph_id+sorted(evidence_refs)+target`; прогресс = старые fps устранены; budget/MAX_REVISIONS не растут.
5. **D5 Final policy** HYBRID_PUBLISHED / HYBRID_DEGRADED_PUBLISHED / LEGACY_FALLBACK (4 случая §4.1) + одна точная причина; soft-only → degraded publish (переиспользование `_degraded_or_legacy`); Writer/Reviewer — раздельные стадии, честные RU-тексты; reviewer-outage fail-soft сохранён.
6. **D6 Decision Trace** из существующих durable stage_events + финальная policy-строка `stage='final_policy'` в существующей `summary_run_stages` (Δ DDL = 0); без новых LLM-вызовов; телеметрия mca_events не расширяется.
7. **D7 `CoverPromptManifest`** — единая server-side структура/компиляция для Base и Style (3 UI читают одно): 6 компонент (source/priority/original/sent/status kept|compacted|omitted/reason) + provider/model/route/operation/resolved_limit/limit_unit/limit_source + attempts[] с полными фактическими строками; персист JSON в существующем job/run evidence; hash sha256[:16]; admin-only, не в generic logs.
8. **D8 Base contract:** STORY_SCENE (minimum budget) + SUMMARY_CONTEXT (bounded rep финального Summary, без LLM-call) + BASE_STYLE; сборка вынесена в `services/cover_prompt_assembly.py` (shim `compose_cover_image_prompt` сохранён).
9. **D9 Style Edit + semantic squeeze:** mandatory minimums при любом retry (P0 полностью; story ≥160 chars или 100%; profile ≥50%; refs mandatory), `minimal=True` запрещён, retry ≤1; `limit_source ∈ {capability_registry, last_success, unknown}` — честный unknown без выдуманного лимита.
10. **D10 GraphRAG recovery:** durable future-resume — периодический тик (≤15 мин) вызывает `maybe_schedule_rebuilds`; healthy («N/M», warning ×1) vs stale (один bounded resume, без duplicate jobs, visible blocker); warning не глушится; `knn_source_empty` при пустом источнике — stable terminal; `rebuild_status()` подключён к существующему embeddings/status read-API (без нового роута).
11. **D11 Embeddings:** три независимых профиля (миграция credentials без потерь); identity = sha256[:16] канонического JSON (endpoint/model+revision/dims/mode/normalization/params); canary = 3 фиксированные строки, вектора в существующем `embedding_cache`, косинус-сверка (mean<0.98/min<0.95 → drift); классы INSTANT_COMPATIBLE/REINDEX_REQUIRED/INCOMPATIBLE_DIMENSION/COMPATIBILITY_UNKNOWN (одна классификация, UNKNOWN fail-safe).
12. **D12 Generations + storage:** реестр AMEND (статусы state machine без DDL; per-chat = index-namespace; migration jobs в `task_jobs` с checkpoint-прецедентом graphrag); generation-isolated vec-таблицы через существующий shadow/swap `_activate`; atomic promotion, rollback retention, GC по политике; destructive ALTER запрещён; единственный entry-check (механизм создания vec-таблиц) с единственным предсанкционированным фолбэком — аддитивная v34 + эскалация.
13. **D13 Random bootstrap:** синтетические catalog-only items незаданных секретов в `/api/config` (`configured=false`, без plaintext/пустых строк/фиктивных строк в БД; деривационно — переживает рестарты); сборка вынесена в `web/api/config_payload.py`; entry point «Сон → Случайность»; один protected store; owner-supplied ANU-ключ (14A.2) через существующий protected path — применить сразу, не PENDING OWNER, plaintext нигде, ключ повторно не запрашивать, ротацию не рекомендовать.
14. **D14 Парадигмы:** `scheduler_gate` ≠ `last_attempt_result` (полный набор §13A.1); retry-классы A (контент-пустые — обычный интервал) / B (техошибки — bounded backoff 1 ч ×2, ≤2/сутки) / C (bootstrap — 2 ч, ≤6/сутки); manual deep run обходит cooldown; защита от LLM-спама сохранена.
15. **D15 Граф:** semantic zoom (drawThreshold/maxVisible + zoom-listener + selected-neighborhood), presentation-only; все nodes/edges остаются; canonical label не менять.
16. **D16 Write-scope/сериализация:** 3 лейна B1/B2/B3 (spec §4); hotspots SERIALIZE через parent Builder: `summary_generator.py` (B2-extraction первой, потом только B1), `app.js`/`index.html` (секции, порядок B1→B2→B3), `routes.py` (одна region B3), `mca_events.py` (Δ=0 ожидается), `settings.py` (parent: bump). §13A/§13B → B3 (подтверждено).
17. **D17 Δ-инварианты/пороги СТОП:** DDL 0 (v33; v34 только по D12-пути с эскалацией) / каталог +4…+8 (только `models.embedding_fallback{1,2}_{base_url,model,quota_group}`) / KS 0 / reason 0..+2 (только `l2_unusable_gate`, `l2_stagnation_fingerprint`) / тулы 14 / widget-ID 47 / routes 0 новых эндпоинтов (F11 re-pin ×1 на пакете) / py-js без новых red. Любое незапланированное Δ, секрет в артефакте, имитация live-проверки, fail2ban-нарушение → СТОП + возврат Step 2.
18. **D18 Deploy:** Risk **R2**; одно окно после интеграции и T-5270; CA-11 bump **2.58.67→2.58.68**; миграционный smoke обязателен только при Δ DDL ≠ 0; rollback soft (config) + cold (revert; БД совместима в обе стороны); fail2ban-дисциплина AGENTS.md (один recon ~15 с + один прогон; статус по `/healthz` 443).
19. **D19 Тесты:** §16 #1–25, #34–36 + 13N×28 = 61 позиция; гэп #26–33 зарезервирован (покрыт 13N), не перенумеровывать; live-приёмки T-5274 — no-false-acceptance; финал отчёта §19 — observable production behavior.

## 3. Последствия

**Положительные:** failed Summary- run диагностируем из UI без server log; Legacy снова аварийный контур, а не штатный исход (прод-база 8/8 `l2_unusable` получает evidence-квоту); сюжет обложки имеет гарантированный бюджет, владелец видит в точности отправленный prompt (admin); GraphRAG resume переживает рестарты без глушения warning; незаданный ANU-ключ получает видимый путь подключения без фиктивных секретов; cooldown парадигм больше не маскирует причину; граф читаем без потери данных. Параллельность: 3 лейна с непересекающимися доменами, сериализация hotspots формализована (5 точек).

**Отрицательные/цена:** серверная политика Summary усложняется (таксономия+gate+fingerprint — ~3 локальных механизма в `summary_l2_review.py`); cover-сборка переезжает в новый модуль (одноразовая миграция вызова с shim); embeddings получают +6 config-ключей и расширенный словарь статусов; две новые внутренние сущности (`cover_prompt_assembly.py`, `config_payload.py`). Risks: R2 (multi-domain) — компенсации в spec §9; поведение политики меняется на живых публикациях → обязательные controlled-прогоны T-5248/T-5254 и live T-5274.

**Откат:** soft (config/KS) / cold (git revert; v33-совместимость в обе стороны; при активации D12-v34 — аддитивная, обратимо-совместимая).
