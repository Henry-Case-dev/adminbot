Проверяемые инварианты (§5 + §3.3):

1. evidence части сохранён и не отменён техническим исходом: `cov.evidence` непуст, ровно одна
   displayable-роль `qualifies`, `citation_ids` непусты, `snippet_only=True`/`opened=False`;
2. содержательный статус: `status_detail == evidence_insufficient_for_exact_number`
   (и это не `no_relevant_sources`, не `provider_timeout`/`rate_limit`);
   `outcome == insufficient_evidence` (не `not_checked_technical`);
   `reason_code == insufficient_evidence`;
3. `gap_note` — конкретная содержательная причина («сумма/число»), без «не нашлось» и без
   технических фраз «ограничил частоту» / «не ответил вовремя»;
4. факт технического отказа не потерян на run-level: `rate_limits == 1` / `provider_timeouts == 1`,
   `queries_attempted == 2`.
