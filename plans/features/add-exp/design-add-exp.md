## 1. Единое правило и значения

### 1.1 Канонические значения

| Значение | Смысл | UI-метка |
|---|---|---|
| `inherit` | **только наследование** chat→global (не четвёртая степень частоты) | «Как в глобальных настройках (наследование)» — только в chat-scope |
| `off` | собственные формулировки без обсценной лексики; цитаты/чужой текст не искажаются | «Без мата» |
| `occasional` | редкий, но реальный мат в разговорной речи (эмоция, ирония, раздражение, интонация) | «Эпизодически» |
| `frequent` | мат — узнаваемая регулярная часть повседневного голоса | «Часто» |

Нормализация (единственная точка — новый владелец, §1.6): `allowed` → `occasional` (read-alias); неизвестное → `inherit`; closed-set канонических значений для записи: `("inherit","off","occasional","frequent")`.

### 1.2 Effective-резолв (per-control, а не per-document)

Текущий `_expression_document` выбирает документ целиком (chat **или** global) — при частичном chat-документе теряются контролы из global. Дизайн вводит **per-control merge**:

```
effective[control] = chat_explicit  → source "chat"
                  | global_explicit → source "global"
                  | иначе           → factory_default
```

- `profanity`: factory_default = **`occasional`** (см. §1.5). Значения `inherit` внутри документа = «нет явного выбора», дальше по цепочке.
- В UI видно: значение + источник (**global / chat / заводское**) для каждого контрола; в глобальном scope наследование не предлагается — эффективное значение разрешается явно (§5).

### 1.3 Миграция `allowed` → `occasional` (совместимая, без потери данных)

- **Read-alias, без фоновых записей**: нормализатор читает `allowed` как `occasional`; сохранённое разрешение мата сохраняется (occasional — «мат разрешён, редкий, реальный»).
- Payload отдаёт `migration: {"profanity": {"from": "allowed", "to": "occasional"}}` → UI показывает «перенесено из „Как в характере“» до первого сохранения.
- При следующем сохранении владельцем в документ пишется каноническое `occasional` (обычная ревизия/история, без спец-миграции).
- **Ни один чат не переводится в `frequent`** — alias ведёт только в occasional.
- Не трогаются: chat-override как объект, `revision`, `history`, `updated_at`, `note`, другие контролы, factory reset, документы Core. Reset-chat (сброс к наследованию) — без изменений.

### 1.4 Отношение к CFG-07B (один параметр, один владелец)

- Канонический storage — существующий документ `character.expression` (persistence/revision/history/UI уже отгружены и VERIFIED в P0A-PERSIST; в нём же лежит текущий `allowed` из Ф0).
- Реестровый параметр CFG-07B (`profanity_use`, factory ON, Inspector) — **проекция того же effective-правила**: ON ⇔ effective ∈ {`occasional`,`frequent`}; OFF ⇔ `off`. Второй storage/второй рендер запрещены (ADD-1.E1).
- Если к старту Ф2 окажется, что CFG-07B уже зафиксировал иную каноническую локацию — приоритет у отгруженного контракта, но ADD-EXP выполняет **разовый перенос** `allowed`→occasional из `character.expression` в каноническую локацию, сохраняя историю; второго параметра всё равно не появляется.
- `style_policy.RULE_KINDS` (W3) **не расширяется** profanity-правилами: форма и интенсивность — разные оси (EXP-INSTR.NOPOST).

### 1.5 Заводской дефолт

- При пустой цепочке (нет global/chat значения) effective = `occasional`, source = `factory_default`; UI: «Эпизодически — заводское значение».
- Совместимо с CFG-07B.1 (factory ON: разрешение мата сохраняется) и с §1 источника («не оставлять владельца с непроверяемым „как в характере“»): эффективный режим всегда разрешён явно.
- `frequent` — только явный выбор владельца (глобально или на чат).

### 1.6 Один владелец логики (анти-дрейф preview vs runtime)

Новый модуль `services/mca_expression.py` — единственный владелец: `EXPRESSION_DOC_KEY`, `normalize_expression()`, `resolve_effective(chat_doc, global_doc)`, `render_expression_text(effective)`, `build_expression_settings(chat_doc, global_doc) -> composer.ExpressionSettings` (+ `build_expression_examples_refs`, §3). `web/api/speech.py` импортирует/ре-экспортирует (публичные имена `render_expression_text`, `_normalize_expression` сохраняются для существующих тестов). Runtime (`direct_chat_service._compose_speech_system`, `mca_authorial_speech.authorial_system`) использует тот же builder — preview и бой рендерят один текст (EXP-ACCEPT.PREVIEW: «предпросмотр не врёт»).

## 2. Тексты инструкций (канонические строки)

### 2.1 Слой `<Expression_Settings>` — новый header (замена текущего)

```
<Expression_Settings>
Настройки выражения владельца: интенсивность и форма собственной речи; характер этим не меняется. Уместность выбирает L1; просьба «без мата» уважается всегда; дословные цитаты и структурированные сводки (фактчек, ошибки API, тех. отчёты) не переписываются, мат в них не форсируется:
```

Далее — строки по контролам (`- <label>: <instruction>`), затем `- Пожелание владельца: <note>`, закрытие `</Expression_Settings>`. Контролы без явного значения строку не дают (как сейчас). Профность-строка появляется, когда effective-режим разрешён (всегда, кроме `enabled=false`).

### 2.2 Строки по режимам

**Инструкция слоя (уходит в LLM), `profanity`:**

- `off`:
```
- Мат: в собственных формулировках не используй обсценную лексику — это ограничение формы, а не характера: ирония, резкость и стёб остаются. Чужую речь, цитаты и источники передавай корректно и не искажай, даже если в них есть мат.
```
- `occasional`:
```
- Мат: обсценная разговорная лексика появляется в собственных живых репликах изредка, но реально — когда добавляет эмоцию, иронию, раздражение или характерную интонацию. Большинство обычных реплик обходится без неё; это не пассивное разрешение, а редкий выразительный приём.
```
- `frequent`:
```
- Мат: обсценная разговорная лексика — узнаваемая регулярная часть твоего повседневного голоса. Используй её регулярно при подходящей ситуации, в том числе в собственных живых ответах — коротких и развёрнутых: как междометие, связку, усиление эмоции, самоиронию или шутку. Не в каждом предложении и без повтора одних и тех же слов; не только при оскорблении и не только по прямой просьбе «матерись».
```

**UI-эффект (человеческое описание в админке, отдельно от инструкции):**

- `off`: «Свои формулировки — без обсценной лексики. Цитаты и чужой текст передаются как есть.»
- `occasional`: «Мат изредка, но по-настоящему: эмоция, ирония, раздражение, характерная интонация. Большинство обычных реплик — без мата.»
- `frequent`: «Мат — узнаваемая регулярная часть повседневного голоса: короткие и развёрнутые живые реплики, не в каждом предложении, без повтора одних и тех же слов.»

**Вопрос контрола:** «Как часто мат звучит в собственных ответах бота» (вместо «Разрешён ли мат в ответах бота»). **Замена `EXPRESSION_NOTES`:** «Настройки задают интенсивность и форму собственной речи; уместность и жанр решают, где она проявляется. Просьба «без мата» уважается всегда. Реальную частоту можно проверить в «Проверить вживую».»

### 2.3 Совместимость с двумя существующими мягкими разрешениями (канон + Core)

Проблема: в payload уже есть «Разрешен мат и сленг.» (канон) и «Используй его свободно…» (Core). Как выразить интенсивность без конфликта и без новой личности:

1. **Слой говорит о ЧАСТОТЕ, а не о разрешении**: ни одна строка не повторяет «разрешено/допустимо» и не опровергает Core — они композируются: Core даёт разрешение и характер, Expression калибрует частоту.
2. **Запрещённые как единственное правило обороты**: «мат разрешён», «естественно», «при необходимости», «необязателен» — не используются в occasional/frequent вовсе (проверяется тестом на строки).
3. **`off` — ограничение формы, а не характера** (прямо сказано в строке): Core и канон в payload остаются байт-в-байт; Expression-строка специфичнее и новее по слоту (layer 7 после Core/канона) и побеждает поведенчески; live-критерий: 0 мата в собственных формулировках.
4. **Никакой новой личности**: строки не задают голос/юмор/резкость — только лексический регистр собственных формулировок; контроль «нет второго Core» — тест байт-паритета Core/канона в payload.

## 3. Few-shot черновик (owner OPTIONAL_FEEDBACK — не блокирующий)

**Статус: черновик для показа владельцу.** 3 набора на одинаковых 4 бытовых темах; короткие живые реплики; без метакомментариев; мат — междометие/усиление/самоирония, не травля. Не дублирует Sample Library (там — техники юмора; здесь — регистр речи).

### 3.1 Состав (12 пар: тема → реплика пользователя → ответ бота)

**`off`**
```
- дружеский стёб: «Ну ты и выдал вчера с этим докладом» → «Выдал, признаю. Зато никто не уснул.»
- спор: «Твой вариант вообще не работает» → «Он не работает у того, кто ставит его криво. У меня крутится, и стабильно.»
- короткий ответ: «Пойдёшь завтра?» → «Пойду.»
- быт: «Интернет опять отвалился» → «Классика. Перезагрузи роутер, обычно помогает.»
```

**`occasional`**
```
- дружеский стёб: «Ну ты и выдал вчера с этим докладом» → «Выдал, признаю. Зато никто не уснул, бля.»
- спор: «Твой вариант вообще не работает» → «Он не работает у того, кто ставит его криво. У меня крутится, пиздец как стабильно.»
- короткий ответ: «Пойдёшь завтра?» → «Пойду, хули.»
- быт: «Интернет опять отвалился» → «Классика, бля. Перезагрузи роутер, обычно помогает.»
```

**`frequent`**
```
- дружеский стёб: «Ну ты и выдал вчера с этим докладом» → «Ага, выдал. Хуёво выдал, зато никто не уснул.»
- спор: «Твой вариант вообще не работает» → «Он не работает у того, кто ставит его криво, вот и весь хуй. У меня крутится, пиздец как стабильно.»
- короткий ответ: «Пойдёшь завтра?» → «Пойду, хули. Куда я денусь.»
- быт: «Интернет опять отвалился» → «Охуенная классика. Перезагрузи роутер, помогает через раз, но хоть что-то.»
```

Типографика примеров: только короткие дефисы, обычные кавычки как делимитеры реплик; длинных тире и «ёлочек» внутри ответов нет (канон канала).

### 3.2 Формат блока для бюджетного впрыска

```
<Expression_Examples mode="occasional">
- дружеский стёб: «…» → «…»
- спор: «…» → «…»
- короткий ответ: «…» → «…»
- быт: «…» → «…»
</Expression_Examples>
```

- Впрыскивается **только набор effective-режима** (не все три); ориентир ~420 символов ≈ 105 токенов; бюджет ≤ 140 токенов; при нехватке — `budget_excluded` (честная причина в манифесте).
- Только речевые профили (`speech_plain/speech_rich/channel_text_only`), только при явном/заводском режиме, только в целевых speech-путях (Direct L2/Initiative writer; жанровые — по §4).

### 3.3 Механизм хранения/редактирования (переиспользование Sample Library, без дубля)

- Хранение — существующая таблица `humor_samples` + новый technique-идентификатор `expression_register` (добавляется в `SAMPLE_TECHNIQUES`); режим — в `tags` (`mode:off|occasional|frequent`), тема — в `context_note`.
- Сиды: 12 строк, `source_kind='bot_suggested'`, `owner_approved=0` (**черновики** — библиотека не выдаёт их за проверенные владельцем), `scope='global'`.
- Отбор: новая функция `resolve_expression_examples(chat_id, mode)` в `mca_sample_library.py`: только `technique='expression_register'` + `tags` режима + `owner_approved=1` + `status='active'`; ≤4 строки. Своя ось `expression_examples_enabled` (env kill-switch, default ON) — **не** гейтится осью юмора `humor_library_enabled`.
- Изоляция от юмора: `select_samples` (путь юмора) **жёстко исключает** `expression_register`; expression-путь берёт только его. Тест на отсутствие перекрёстного отбора.
- Одобрение/правка владельцем — существующим механизмом (`POST /speech/examples/{id}/approve`, редактирование карточек). До одобрения в runtime примеры не идут (`not_owner_approved` — честная причина); показ черновика владельцу в отчёте Ф1/Ф5 — OPTIONAL_FEEDBACK.
- Рендер в композере: блок `expression_examples` (owner `core`) в слое `few_shot`, **до** humor-примеров; свои skip-причины: `expression_examples_absent` (нет одобренных/нет режима), общий `budget_excluded`.

### 3.4 Правила качества примеров (проверяются тестом)

- никаких метакомментариев о настройках/инструкциях/«сейчас добавлю мат»;
- мат не превращается в персональную травлю (нет адресных оскорблений);
- не форсируется в жанровых контекстах (§4);
- строки не дублируют существующие humor-сиды (тест пересечения по тексту).

## 4. Жанровые исключения и контракт приоритетов

### 4.1 Карта жанровых исключений

| Контекст | Правило | Где (якорь) |
|---|---|---|
| Дословные цитаты, чужой текст, источники | Ни один режим не переписывает: при `off` мат внутри цитаты сохраняется как есть (иначе искажение факта). Цитата не «облагораживается» и не «усиливается». | `style_policy` protected spans (`verbatim_quote`, `url`, `code`, `json`…); live-сценарий «цитата с матом» |
| Структурированный фактчек | Мат не форсируется; факты/цифры/вердикт не меняются ради частоты. | `factcheck_*` writers; жанровый контракт |
| Сообщения об ошибках API/сбоях | Без мата и иронии; коротко и по делу (системные сообщения — вне Expression-слоя). | fallback/системные шаблоны; Expression не впрыскивается в сервисные тексты |
| Тех. сводки, отчёты, публикации | Мат не форсируется; `frequent` не делает сводки матерными. | `editorial_report`/rich-отчёты; профильная логика |
| Жанровые авторские тексты (nostalgia/dream/lore/story) | Голос живой, мат по режиму допустим; факты не выдумываются; служебные контракты канона (слово отказа) неизменны. | `mca_authorial_speech.authorial_system` (writers `nostalgia_writer`, `lore_writer`, …) |

Жанровое исключение действует **только в сторону «не форсировать»**; оно не разрешает мат при `off` и не отменяет дословность цитат.

### 4.2 Контракт приоритетов (кто кого перекрывает)

| P | Источник | Что задаёт | Отношение |
|---|---|---|---|
| P1 | Безопасность/факты/канал (канон канала, egress-guard, факты тулов, Telegram-разметка) | обязательные ограничения | перекрывает всё |
| P2 | Жанровый контракт (цитаты/фактчек/ошибки API/тех. сводки/публикации) | где мат не форсируется и текст не переписывается | перекрывает Expression **только вниз** (запрет форсирования), не разрешает мат при `off` |
| P3 | Явная просьба пользователя «без мата/полегче» | понижение на момент | перекрывает Expression (понижает). Просьба «матерись» режим **не повышает** и `off` не отменяет |
| P4 | **Expression (off/occasional/frequent)** | интенсивность и форма собственной речи | перекрывает мягкие разрешения Core/канона в сторону формы (off ограничивает), характер не меняет |
| P5 | Core/канон канала | личность, мягкое разрешение | не переписывается ни одним режимом (байт-паритет) |
| P6 | Style Policy (форма: пунктуация/кавычки/эмодзи) | форма | ортогональна: мат не вставляет и не вырезает (RULE_KINDS без profanity; CFG-07C не ломает) |
| P7 | L1 уместность/план | момент и место | может **понизить** частоту, не может повысить выше режима |

### 4.3 Как тестировать приоритеты

- **P4×P5**: манифест/payload с Core + каноном + `off` → Core/канон байт-в-байт, строка off присутствует; live: 0 мата в собственных формулировках.
- **P2×P4**: фактчек/цитата в каждом режиме → цитата дословна (вкл. мат при `off`), мат в собственном тексте сводки не форсируется; `factcheck`-план без examples-блока.
- **P3×P4**: live-проба `frequent` + «пожалуйста, без мата» → понижение; проба `off` + «матерись» → собственный мат не появляется (зафиксированное решение).
- **P6**: текст с матом проходит style-pass без изменений (регрессионный тест); изменение profanity детектится классом `postprocess_changed`.
- **P7**: `frequent` в нейтральной техзадаче — без спама (не в каждом предложении), в разговорной — заметно чаще `occasional`.

## 7. План тестов Ф2 (RED) и приёмки Ф6

### 7.1 Ф2 RED (детерминированные, 0 LLM)

1. **Значения/нормализация**: off/occasional/frequent; `allowed`→occasional; неизвестное→inherit; `inherit` — не четвёртая степень (нет опции «естественный»).
2. **Effective**: per-control merge chat>global>factory; источники chat/global/factory_default/migrated; глобальный scope не предлагает inherit.
3. **Миграция**: документ с `allowed` → effective occasional, разрешение сохранено; revision/history/note/другие контролы/override не потеряны; ни один чат не frequent.
4. **Тексты**: три режима дают три различные позитивные инструкции; строки §2.2 байт-в-байт; отсутствуют запрещённые как единственное правило обороты; off упоминает цитаты; frequent — «регулярно… в собственных живых ответах».
5. **Wiring**: манифест Direct L2 (`_compose_speech_system`), `initiative_writer`, `tool_phase`, `system2_stage2` — `expression` present с ревизией, без `expression_absent` при активном режиме; machine-writers (`l1_planner`, `system2_stage1`, `initiative_l1`) — профильная причина (не expression_absent-дефект); `budget_excluded` рендерится честно.
6. **Приоритеты §4.3** (детерминированная часть) + байт-паритет Core/канона.
7. **Диагностика**: каждый класс эмитится в своей точке (fixture-сбои: урезанный marker, fallback-адаптер, stub-postprocess); дедуп; R17.
8. **UI payload**: опции/метки, effective+source, `runtime_wired=true` после wiring, честный preview, reset-chat, изоляция чатов (A frequent vs B off → разные rendered_text).
9. **No-postprocessor**: нет кода вставки мата (RULE_KINDS без profanity; egress не вырезает — регрессионный тест).
10. **Few-shot**: отбор ≤4, только своего режима, только owner_approved; humor-путь не берёт `expression_register`; бюджет/`expression_examples_absent`; тест пересечений текстов с humor-сидами.

### 7.2 Ф6 — живой набор (postdeploy, 20–30 сценариев)

- **Harness** (паттерн `evidence/f0/harness/f0_live.py`): реальный prod-путь, локальная Bot API-сессия; **сам сохраняет тексты ответов** (`bot_replies` TTL 1 ч); переключает режим через `POST /api/speech/expression` (scope=chat тестового чата; global — заводское occasional); изоляция — второй чат с `off`.
- **Матрица (24–27 проб)**: 7 контекстов × 3 режима (дружеский стёб, спор, короткий ответ, бытовая реплика, шутка/ирония, нейтральная техзадача, фактчек/цитата) + 3 повторяемости (стёб/короткий ответ/шутка) + жанровые пробы (цитата с матом; тех-сводка). ≤30 пользовательских ходов, ≤~60 LLM-вызовов.
- **Измерение**: детектор мата по корням (бля, хуй/хуе/хуё, пизд, еб/ёб, заеб, охуе, мудак, нахуй/нахер, долбоеб, сука-осторожно) — по собственным формулировкам, исключая защищённые спаны (цитаты/URL/код); распределение по контекстам, повторяемость.
- **Критерии**: `off` — 0 мата в собственных формулировках (цитата сохраняется); `occasional` — >0 и не более 40% разговорных реплик; `frequent` — ≥50% разговорных и ≥2× occasional, минимум в 3 разных контекстах, не в каждом предложении, без повтора одного слова; `frequent`-чат не влияет на `off`-чат.
- **Плюс**: переключение без рестарта; reread после сохранения; wire-payload содержит `<Expression_Settings>` + строку режима (preview vs production trace); диагностические классы §6 по каждому промаху; отчёт «было/стало».

## 9. Риски и owner-вход

1. **Бюджет**: examples (≤140 токенов) в слое `few_shot` вытесняются первыми при перерасходе — измерять `budget_excluded` в Ф6.
