## 1. Новый продуктовый дефект (IN_SCOPE, блокер)

**Симптом.** Даже РАЗРЕШЁННАЯ идентичность не могла выполнить
`prompt_readback` через существующий tool-путь:

```text
ToolRouter.dispatch("prompt_readback", {...}, owner_ctx)
→ ОШИБКА prompt_readback: Такое действие для возможности не предусмотрено.
  [denied_action_not_supported]
```

**Причина.** `diagnostic_policy.check_tool_call` всегда запрашивал действие
`run`: `decide(capability_id, "run", ...)`. Но `prompt_readback` зарегистрирован
в возможности `prompts`, у которой действия ровно `("view", "edit")` — `run`
не существует, поэтому политика отказывала ВСЕМ (включая владельца) до
исполнения handler'а. Старый тест проверял только «deny без identity» и этот
дефект маскировал.

**Фикс (минимальный, без второго ACL):**

- `services/diagnostic_policy.py`: карта `TOOL_ACTIONS = {"prompt_readback":
  "view"}`; `check_tool_call` берёт `action = TOOL_ACTIONS.get(tool, "run")` и
  пишет его же в аудит `diag_call`. Для `inspect_runtime`/`get_bot_health`/
  `read_source_code` поведение прежнее (`run`).
- Семантика двойной проверки сохранена: router спрашивает `prompts.view`,
  затем D5 handler сам вызывает `open_gate("prompts", "view")`. Матрица
  «Самодиагностики» (`view_roles` для `prompts`) теперь реально управляет
  readback'ом, как и задумано D2/AMX.

## 2. Новые тесты (реальный dispatch, не только deny)

`TestPromptReadbackAllowedDispatch` (2 теста), существующие фикстуры
`tests/test_prompt_readback.py` (FakeCache/FakeBot/FakeChatStore, реальный
`prompt_registry`), реальный `ToolRouter.dispatch`:

   (`OWNER_ID`, роль `global_admin` в FakeCache):

     `@@PROMPT_READBACK v1 status=delivered destination=group chunks=1
     prompt_id=memory.extract revision=act:3459d3580788 source=factory_default
     chars=616 classification=factory_public redaction=clean`;
   - в чат ушёл ровно ОДИН текст, и `payload_body(text)` равен
     `prompt_registry.effective_prompt("memory.extract").text`; revision в ack
     равен `expected.revision`;
   - `prompt_readback_requested` эмитится при `sent=0`, `prompt_readback_allowed`
     — ровно один и при `sent=1` (строго ПОСЛЕ фактической отправки);
   - сигнал ToolResult не `denied`.
2. `test_member_dispatch_is_denied_and_not_counted_allowed` — участник
   (`MEMBER_ID`, Telegram `member`):
   - отказ политики ДО исполнения: `denied_prompt_content_member`;
   - `bot.sent == []`, `prompt_readback_allowed`/`requested` не эмитятся,
     `ctx.tool_result_signal is None` (инструмент не исполнялся).
