### 1.1 `LocalSnapshotProvider` (`name = "local_snapshot"`)

Реализует существующий `Protocol SourceProvider`: `search_repos`, `resolve_repo`,
`resolve_commit`, `list_tree`, `read_file`.

- только чтение байтов внутри `repo_root` после `realpath`; `..`, абсолютные
  пути, выход за корень, симлинк-файл/наружу → закрытый `path_denied`;
- единый `deploy_identity.path_is_denied` применяется к каждому чтению и
  листингу (секреты/credentials/cookies/backups/`.git`/`deploy_*.py`), с
  исключением self-read `services/deploy_identity.py`;
- commit-pinned: отдаётся только текущий `HEAD` checkout; другой commit/ref →
  честный `provider_unavailable` (`commit_not_available`), без чтения «похожего»
  файла; `HEAD`/branch/40-hex разрешаются через существующий D4-A identity,
  второго парсера `.git` нет;
- ни сети, ни shell, ни `import/exec` файлов репозитория (тест-ловушка);
  байты идут в существующий `decode_source_bytes`/`build_snippet`;
- лимит файла — существующий `SOURCE_READ_MAX_FILE_BYTES`; карта дерева
  ограничена предохранителем 20 000 записей и не обходит каталоги
  инструментов/зависимостей (`node_modules`, `.venv`, `__pycache__`, `build`…);
- наружу только repo-relative пути; ссылка —
  `repo://adminbot@<sha>/<path>#Lx-Ly` (§3.2), без путей хоста;
- `verification()` — срез существующей записи identity (`code`, `reason`,
  `checkout_sha`, `dirty`, `branch`, `local_source_verification`), никогда не
  бросает.

### 1.2 Маршрутизация `SourceReader`

- `GitHubProvider` остаётся default; поведение сторонних репозиториев не
  менялось (75 существующих тестов + отдельные кейсы D4-B).
- Локальный провайдер выбирается **только** при точном (casefold) совпадении
  `owner/name` с `repo_origin`; `other/repo`, `Henry-Case-dev/adminbot-fork` и
  т.п. идут в GitHub. Автоподстановки repo identity в чужой вопрос нет
  (`SD1-SEM-04`).
- Провайдер выбран на один вызов (`_RunState.provider`), без мутации общего
  `SourceReader`; параллельные вызовы не меняют чужие маршруты.
- Локальный ответ помечается в payload: `provider="local_snapshot"`,
  `local_source_verification`, `local_source_note`; при `dirty=true`/неизвестном
  состоянии `verified=false`; при чистом HEAD и совпавшем commit — `verified=true`
  с commit-pinned `repo://`-ссылкой. `local_unverified` не выдаётся за
  подтверждённую исполняемую ревизию.
- Локальный провайдер включается **только** при заданном
  `SELF_DIAG_LOCAL_REPO_ROOT`; пустое значение = поведение ровно как до D4-B
  (только GitHub). Это осознанная env-only конфигурация (прецедент
  `SOURCE_READ_*`), а не новая админ-страница/стор.

### 1.3 `repo_origin` (`SD1-D4-03`, `SD1-AC-06`)

- Одна запись в существующем каталоге: `flags.self_diag_repo_origin`
  (категория `flags`, группа `flags_service`, вкладка «Диагностика»,
  non-secret, PG-only, `global_only=True` → чатовый override отклоняется 422).
  Заводской default — `deploy_identity.DEFAULT_REPO_ORIGIN`
  (`Henry-Case-dev/adminbot`), читается через существующий `hot.get`.
- Нормализация: `owner/name`, `https://…`, `git@host:…` → `owner/name`;
  схема/host/userinfo/токены вырезаются; невалидная форма → default.
  Секреты не пишутся в запись/трейсы.
- Смена — только явной owner-настройкой через существующий `POST /api/config`;
  событие `[self_diag] repo_identity_changed | old=… | new=… | by=config`
  пишется при первом эффективном чтении нового значения. Actor пишется
  существующей строкой `[api] config updated | key=… | by=<id>`; отдельного
  аудит-стора не вводится. Из текста сообщения/README/памяти repo identity не
  выводится.

### 1.4 Минимальный интеграционный шов reuse

`tool_router._source_pointer` больше не хардкодит `provider="github"`: указатель
несёт `provider`/`host`/`local_source_verification`/`local_source_note`, и
reuse-ответ сохраняет локальную пометку. Для GitHub значения прежние
(`provider=github`, `host=github.com`), поведение не меняется.

## 4. Честные границы

1. Деплой не выполнялся; production-манифеста нет; live-проверок нет.
2. `SELF_DIAG_LOCAL_REPO_ROOT` в тестовой среде не задан (значение по умолчанию
   `""`); локальные провайдеры в тестах создаются явно на `tmp_path`. В
   production эффективное значение должно задаваться unit/EnvironmentFile;
   до этого D4-B ведёт себя как GitHub-only.
3. `flags.self_diag_repo_origin` в тестах читается при пустом hot-кэше → default
   `Henry-Case-dev/adminbot`; precedence: сохранённое PG-значение → module
   default. Секреты в значении вырезаются.
4. В linked worktree `.git` — файл вне корня; D4-A identity честно даёт
   `path_denied`, поэтому self-read на самом worktree D4-B не проверялся;
   тесты используют обычные `tmp_path`-checkout'ы. Production — обычный
   checkout.
5. Локальное чтение делает до ~3 вызовов identity (resolve/read/provenance),
   каждый — фиксированный `git status` из D4-A. Для бюджета D6 (≤3 git-вызовов
   на чекап) это нужно учесть при интеграции; отдельного кэша identity D4-B не
   вводит.
6. `list_tree` пропускает каталоги инструментов/зависимостей (не источник
   git-дерева) и ограничен 20 000 записей; явное чтение файла этим списком не
   ограничено.
7. `tool_router._source_pointer` теперь несёт provider/host/local-пометку;
   `scope` reuse по-прежнему выбирается по наличию GitHub-токена (локальный
   ответ при токене попадёт в chat-scope — консервативно, не дефект).
8. UI/визуальных изменений нет; Playwright/Browser Use неприменимы. Новых
   маршрутов/страниц/таблиц/планировщиков/агентов нет.
