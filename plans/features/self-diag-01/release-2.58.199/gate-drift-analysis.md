# Release gate 429 «source-item drift» — разбор и устранение (2.58.199)

Дата: 2026-11-13. Автор: PM (postdeploy reconciliation SELF-DIAG-01 corrective).
Скоуп: только книга карты и порядок запуска гейта. Код, прод и данные не менялись.

## Что наблюдалось

Во время выката 2.58.199 гейт `requirements_gate.py check --stage release
--candidate d20a7f73 --deployed-commit d20a7f73` вернул `exit=1`:

```
FAIL: source not present: plans\owner_inputs\2026-11-09-self-diag-01.md
FAIL: inventoried source item gone or edited L00002
... (всего 429 строк ошибок, показаны первые 50)
stage=release inventory=183 manual=53 scoped=189 errors=429
```

Полный вывод — `release-gate.txt`. Это выглядело как «дрейф исходных пунктов»
ТЗ, но источники требований не менялись.

## Фактическая причина (воспроизведена)

Гейт запускался в выложенном checkout релизной ветки, где лежит **снимок карты
из `release/2.58.199`**, а не авторитетная карта линии планирования:

```
git show d20a7f73:plans/features/self-diag-01/requirements-map.json
  source_path = plans/owner_inputs/2026-11-09-self-diag-01.md
  items = 183, additional_requirements = 53
```

Файл `plans/owner_inputs/2026-11-09-self-diag-01.md` в релизной ветке
отсутствует (в `plans/owner_inputs/` ветки 48 файлов, этого среди них нет):
ветка `release/2.58.199` — производственная линия кода, исходники владельца
живут в линии планирования (`master`).

`requirements_gate.py` разрешает `source_path` относительно текущего каталога
и при отсутствии файла подставляет пустой список строк. Дальше:

- каждый из 183 инвентаризованных пунктов помечается `gone or edited` (сравнение
  идёт с пустым источником);
- каждая из 53 manual-строк падает на проверке `source_line` вне диапазона;
- 189 required-строк скоупа теряют привязку доказательств;
- итог: `errors=429`.

Локальное воспроизведение ровно этого состояния (снимок карты из
`d20a7f73` + рабочий каталог без `plans/owner_inputs/2026-11-09-self-diag-01.md`,
`--repo` указывает на реальный репозиторий):

```
stage=release inventory=183 manual=53 scoped=189 errors=429
```

совпадает с `release-gate.txt` до последней строки, включая первый
`source not present` и перечень `L001xx`.

## Почему это не дрейф требований

На авторитетной линии планирования источник карты — неизменяемая композитная
копия `plans/features/self-diag-01/corrective-2026-11-13/source-selfdiag01-plus-corrective-2026-11-13.md`
(prefix = исходное ТЗ владельца verbatim, suffix = corrective 2026-11-13 verbatim),
её `source_sha256` совпадает с записанным в карте (`b72efb39…a1dc8e`), а
`check --stage plan` даёт `inventory=324 manual=76 scoped=0 errors=0`, то есть
все пункты источника классифицированы, ни один не потерян и не изменён.

Отдельно: corrective владельца от 2026-11-13 — **самостоятельный owner input**
(`plans/owner_inputs/2026-11-13-selfdiag-corrective-journal-code-identity.md`),
вошедший в композит суффиксом. Это не раздел `plans/current_task.md`, поэтому
инвентарь разделов `current_task.md` (`source_inventory` в `progress_scope.json`)
этим разбором не затрагивается и переклассификации не требует.

## Что изменено

1. Гейт считается по авторитетной карте и источнику линии планирования
   (этот рабочий каталог), а не по снимку карты из релизного checkout.
   Релизная ветка остаётся производственной линией кода; снимок карты в ней
   не является источником истины.
2. Карта привязана к фактическому деплою: `candidate_commit`/`deployed_commit`
   = `d20a7f730715ba9e9cba7673c0557794979be339`, `deployed_version` 2.58.199,
   `deployed_branch` `release/2.58.199`, `deployed_evidence` = `release-2.58.199`.
3. Доказательства строк перепривязаны на выложенный SHA с сохранением исходного
   кандидата в `bound_from_candidate`; наблюдения и файлы-артефакты не менялись.
   Обоснование — `artefact_rebinding_note_2026_11_13` в карте: все исходные
   кандидаты строк являются предками `d20a7f73`, кумулятивная дельта к прежней
   продакшн-базе `23477658` — 106 файлов (76 поезд + 30 пинов версии).

## Остаточное ограничение

Снимок карты в релизной ветке остаётся старым (183/53) и при повторном запуске
гейта из релизного checkout снова даст `source not present`. Это ограничение
процесса (гейт обязан запускаться по линии планирования), а не дефект карты;
переписывать релизную ветку ради книги не требуется.
