## 1. NOST-01 — семантический хардкод удалён

**Удалено из рабочего пути полностью** (`services/nostalgia_prompts.py`):
`_SELF_DECLINE_VERDICT_RES`, `_SELF_DECLINE_NOTHING_RE`, `_SELF_DECLINE_NOTHING_REV_RE`,
`_SELF_DECLINE_ALL_RES`, `is_self_declining_text`; из `services/nostalgia_worker.py` —
импорт и гейт `is_self_declining_text(text)` перед отправкой/делегированием. Не заменено
ни регэкспами, ни словарями, ни «запретами тем» (`test_self_decline_hardcode_removed`:
символов не существует; `grep` по runtime — 0 живых ссылок).

**Сохранён формальный контракт отказа UNCHANGED** (`is_unchanged_response`,
`contains_unchanged_token` — машинный управляющий результат, не смысловой анализ;
байт-в-байт прежние, пины `test_is_unchanged_response_cases` и др. зелёные).

**Типизированное решение тем же LLM-вызовом** (санкционировано источником: «Допустимо
возвращать типизированный результат принятого решения через существующий вызов»):
канон требует первой строкой ровно `UNCHANGED` (отказ, прежний формальный контракт) или
`SAY` + реплика со второй строки. Парсер `parse_nostalgia_answer` — детерминированный
разбор служебного протокольного маркера первой строки (разрешённая детерминированная
логика «служебных протокольных маркеров»), НЕ семантический поиск слов:
`(unchanged|say|legacy)`; `legacy` = ответ без вердикта → прежний контент-путь (обратная
совместимость старых моков/клиентов; в логе честный `protocol`). Решение об отказе и
готовый текст больше не противоречат друг другу структурно: отказ — UNCHANGED и ничего
после; контент — SAY + реплика.

**Честный остаток (не скрывать):** если модель нарушила протокол и вернула прозу-самоотказ
без маркера, на legacy-пути (K1/K3 OFF) такой текст трактуется как контент. Это
сознательное решение источника: семантическая пригодность — зона LLM/Decision (NOST-10),
а не списка фраз. На делегированном пути (прод-дефолт) второй семантический гейт —
`handle_initiative` (recheck/demote). Дополнительного LLM-вызова не появилось (по-прежнему
1 на чат-тик).

Отказ = отсутствие публикации; публичного «вспоминать нечего» не создаётся
(`test_incident_shape_declined_not_posted`, `test_llm_decline_typed_verdict_silence`,
T23). Дневной лимит отказом не тратится.

## 3. NOST-03 — адаптивные временные окна

Лестница уровней `_next_research_level`: **день → неделя (ISO) → месяц (календарный,
не 30 дней) → продолжение `month+k`, k ≤ 3 (уровень D)**. Переход на следующий уровень —
ТОЛЬКО когда найденный сегмент касается границы текущего окна ближе, чем зазор
`SEGMENT_GAP_SECONDS` (30 мин), которым сам сегментатор закрывает сегменты: «событие
продолжается наружу» — данных, не фиксированных стадий (`test_expands_week_on_edge_touching_reply_chain`,
`test_month_level_for_multi_week_event`, T10–T12-механика). Сегмент закрыт внутри окна →
расширение не выполняется вовсе (`test_closed_episode_stays_base_level`,
`test_expansion_stops_when_no_new_material` — 1 и 2 выборки, T8-механика). Потолок
продолжения терминален (`test_expansion_cap_is_terminal`: ≤3 выборки на эпизод; NOST-11).
Принцип расширения — по найденному материалу: фактические границы эпизода фиксируются в
карточке (`start_ts/end_ts` — границы сегмента, не календарной обрезки).

## 4. NOST-04 — исторический эпизод вместо отдельного сообщения

Реконструкция — **существующее детерминированное ядро эпизодов** `mca_episodes.segment_messages`
(union-find: время + reply-граф (горизонт 6ч) + участники; консервативные границы — ложная
склейка запрещена A12): сырые smart_messages окна → сегменты → сегмент-повод года →
адаптивное дооснащение → карточка эпизода (`_episode_card`). Второго хранилища эпизодов
не создано; пишется только существующая `nostalgia_log`.

- Эпизод из одного сообщения — валиден (минимума нет, T8:
  `test_single_message_episode_is_valid`).
- Reply-диалоги собираются в один эпизод (T9/T15: `test_reply_chain_three_messages_one_episode`),
  продолжительные события (T10–T12) — см. §3; эпизод через Новый год не обрывается
  (`test_cross_new_year_episode_not_cut`).
- Несвязанные обсуждения дня НЕ склеиваются (T13: `test_parallel_discussions_same_day_not_merged`;
  разные события с тем же участником — T14: `test_two_similar_events_not_one_story`).
- Кап строк эпизода = голова+хвост хронологии (12, начало и финал истории сохранены);
  полный счётчик и достигнутый уровень исследования — в meta лога (`episodes[]`,
  честная диагностика; заготовка NOST-12).
- Динамический выпуск лет ограничен капом предъявления `_EPISODES_MAX=4` (свежие первыми,
  технический признак предварительного отбора, не семантическая оценка — NOST-05 вне
  слайса; `test_more_than_three_years_not_cut_off` фиксирует: ПОИСК покрывает все годы,
  кап — только предъявление).
- `mca_episodes`/`mca_stories` таблицы: карточки/истории пайплайна НЕ подключались как
  источник этого слайса — навигационный материал §4.1 (не подтверждение фактов), их
  пересечение с окнами планируется вместе с NOST-05/06 (оценка пригодности/тематический
  поиск). Реконструкция идёт от первичных сообщений — «приоритет проверяемым структурам,
  для которых можно восстановить первичные сообщения».

  пути (`get_chat_history_messages`; `test_bot_own_rows_excluded_from_history`); golden-путь
  W1 не тронут.
- **Идентичность по uid** (T26/T27): `_display_names` — единый каскад `summary_aliases`
  (алиас чата → глобальный; `build_alias_resolver`, fail-open); алиас приоритетнее
  исторического author_name (`test_identity_by_uid_alias_priority`); резолвер отдал сам id —
  имени нет, фолбэк author_name («автор 12345» не выдумывается; прецедент direct_chat);
  тексты исторических сообщений не переписываются.
- **Недостаток данных честно** (T19): вне годовщин кандидата нет → LLM не вызывается,

  развязки (`deterministic_episode_card`-принцип: только первичные сообщения в строках;
