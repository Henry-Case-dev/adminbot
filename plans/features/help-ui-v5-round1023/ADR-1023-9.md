# ADR-1023-9 — Справка v4→v5 и версионирование «Гайда по возможностям»

- **Статус:** **Accepted** (Step 2 @Architect, 19.09.2026)
- **Фича:** F9 `help-ui-v5-round1023`
- **Тип:** контент/код-канон + PG-миграция (DML-only)
- **Связано:** ADR-1016-3 (версионирование канона/`KNOWN_INFO_SNAPSHOTS`), ADR-1022-7 (канон v4), F3/F4/F5/F6/F7 (фактура)

## Context

Справка доставляется двумя независимыми канонами:
1. **«Гайд по фичам бота»** — `services/info_service.py::DEFAULT_INFO_TEXT` (+ байт-эталон `info_text.md`, PG `content.info_how_it_works`), версия `INFO_CANON_VERSION`; идемпотентная миграция `config_cache._migrate_info_how_it_works_v1015` уже **версионо-обобщённая**.
2. **«Гайд по возможностям»** — Markdown `plans/docs/intelligence_user_guide.md`, PG `content.intelligence_guide`; сид `_seed_intelligence_guide` срабатывает **только если ключа нет**, версии у гайда **нет**.

ТЗ требует (Жёсткий маппинг): в «Гайд по возможностям» — умный Вербализатор/3 режима, System 2, динамический анти-клише; в «Гайд по фичам бота» — команды изображений. PM-задачи F9 смешали два канона (блок «Как бот думает» живёт в гайде, а не в `DEFAULT_INFO_TEXT`).

Проблема доставки: без версионирования гайда новый текст **не доедет** до прод-PG (сид не перезаписывает существующий ключ; миграции гайда нет).

Инварианты: DML-only (DDL нет), Δ каталога = 0, `parse_mode`/rich-доставка не меняются, ручные правки владельца не затираются молча.

## Decision

1. **Справка v5 (`DEFAULT_INFO_TEXT`):** секции 1–10 без изменений + новая секция `<h2>11. Генерация изображений</h2>` (команды в `<blockquote>`). `INFO_CANON_VERSION` 4→5; прежний v4 → `PREV_R1023_DEFAULT_INFO_TEXT` в `KNOWN_INFO_SNAPSHOTS`; `info_text.md` — байт-в-байт. PG-миграция v4→v5 выполняется **без нового кода** существующим `_migrate_info_how_it_works_v1015` (читает `_INFO_CANON_VERSION`/`_KNOWN_INFO_SNAPSHOTS`): слепок v4 → перезапись v5, повтор → no-op, ручной дрейф → не затирать.
2. **Гайд по возможностям v1→v2:** в `§11` добавляются умный Вербализатор/режимы (человеческим языком, без внутреннего жаргона), актуализируется System 2, добавляется динамический анти-клише; при необходимости — `§12 Словарик`.
3. **Версионирование гайда (новое):** `GUIDE_CANON_VERSION = 2`, `PREV_R1023_INTELLIGENCE_GUIDE` (v1), `KNOWN_GUIDE_SNAPSHOTS`; в `services/config_cache.py` — идемпотентная `_migrate_intelligence_guide_r1023()` по паттерну ADR-1016-3: канон → no-op; слепок v1 → перезапись + маркер `guide_delivered_version`; неизвестный (ручной) ∧ доставка не состоялась → **одноразовая форс-доставка** с бэкапом `prev_markdown`/`prev_updated_at`; неизвестный после доставки → WARNING, не затирать.
4. **Вёрстка/тон:** только `<h1>`/`<h2>`; команды — `<blockquote>`; между соседними примерами нет точек/запятых/«или»; секреты/значения ключей не упоминаются (R17/R18).
5. **Каталог/DDL/web:** Δ каталога = 0; DDL = 0 (DML-only); правок `web/**` нет (доставка/рендер не меняются).
6. **Откат:** `git revert` + обратная PG-миграция: слепок v4 в `KNOWN_INFO_SNAPSHOTS` и v1-гайд в `KNOWN_GUIDE_SNAPSHOTS` позволяют распознать и вернуть прежний текст; явный force-reset (`POST /api/info/reset-canon`, RBAC `edit_info`) для Справки.

## Consequences

- (+) Справка отражает фактуру раунда; гайд доезжает в прод автоматически и идемпотентно; ручные правки владельца защищены маркером доставки/бэкапом.
- (+) Переиспользование существующей миграционной машинерии Справки — минимум кода.
- (−) У гайда появляется новый внутренний контракт сопровождения (бамп `GUIDE_CANON_VERSION` + слепок при каждой правке) — распространение правила канона на второй текст.
- (−) Требуется уточнить v4-тесты (`h2`/`blockquote` счётчики, `test_guide_avoids_impl_details`) — осознанное изменение эталона.
- Инварианты сохранены: DML-only, Δ каталога = 0, порядок роутеров `bot.py` не тронут.

## Alternatives

| Вариант | Вердикт |
|---|---|
| Только `DEFAULT_INFO_TEXT`, без гайда | Отклонён: ТЗ явно требует «Гайд по возможностям» (режимы/анти-клише) |
| Правку гайда оставить владельцу через UI | Отклонён как единственный путь: не гарантирует доставку и противоречит «Жёсткому маппингу»; оставлен как ручной override/force |
| Сид гайда всегда перезаписывать | Отклонён: молча удалит ручные правки владельца |
| Отдельная таблица/DDL для версий гайда | Отклонён: DDL не нужен; версия — поле в JSONB, как у Справки |
| Хэш вместо реестра слепков | Отклонён: нельзя восстановить `prev_markdown`/откатиться |
| Новый env-флаг для миграции гайда | Отклонён: доставка контента — не рантайм-фича; идемпотентность и бэкап достаточны |
| Единый канон-ключ для Справки и гайда | Отклонён: разные форматы (HTML vs Markdown) и разные UI-блоки |

## Migration / порядок

- Ступень: F9 **последняя** (после F3/F4/F5/F6/F7) — контент должен отражать готовую фактуру.
- `bot.py`/`config_cache.init`: новый вызов `_migrate_intelligence_guide_r1023` добавляется после `_seed_intelligence_guide`; порядок существующих миграций не сдвигается.
- Канон-атомарность: правки `DEFAULT_INFO_TEXT`/гайда + слепки + `info_text.md` + тесты — одним коммитом.

## Human Gate

- Подтвердить версионирование/миграцию гайда (новый контракт) vs ручная правка владельцем.
- Подтвердить человеческие (без жаргона) формулировки режимов/анти-клише в гайде.
- Подтвердить, добавлять ли строку про обложку саммари (F6) в «Гайд по фичам бота».
