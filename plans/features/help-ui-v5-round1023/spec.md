### 0.1. Ключевое расхождение с PM-задачами (устранено здесь)

В `tasks.md` F9 формулировка смешала два разных канона: «блок **«Как бот думает»** дополнить в `DEFAULT_INFO_TEXT`». Фактически:
- **«Гайд по фичам бота»** = `DEFAULT_INFO_TEXT` (HTML, PG `content.info_how_it_works`) → сюда добавляются **команды генерации изображений**;
- **«Гайд по возможностям»** = `intelligence_user_guide.md` (Markdown, PG `content.intelligence_guide`), и блок «Как бот думает (System 2)» — **именно там** (§11) → сюда добавляются **умный Вербализатор, System 2, динамический анти-клише**.

Настоящий spec фиксирует это разделение. Дополнительно:`intelligence_user_guide.md` **не версионирован** (сид только при отсутствии ключа) — без миграции новый текст не доедет до прод-PG. Решение — версионирование гайда по паттерну info-канона (ADR-1023-9).

## 1. Цель

Справка **v4 → v5**. В «Гайд по возможностям» добавить: умный Вербализатор (3 режима), принцип System 2, динамический анти-клише. В «Гайд по фичам бота» — команды генерации изображений. Стиль вёрстки сохранить (`blockquote`, `h1`/`h2`, без точек/запятых между примерами команд).

## 2. Требуемое поведение

1. `DEFAULT_INFO_TEXT` (v5) = v4 + новая секция `<h2>11. Генерация изображений</h2>`; только `<h1>×1`/`<h2>×N`; команды — в `<blockquote>`; между соседними примерами — без точек/запятых/«или».
2. `INFO_CANON_VERSION` 4 → 5; прежний v4 → `PREV_R1023_DEFAULT_INFO_TEXT` в `KNOWN_INFO_SNAPSHOTS`.
3. `info_text.md` — **байт-в-байт** с `DEFAULT_INFO_TEXT`.
4. PG `content.info_how_it_works`: идемпотентная миграция v4→v5 (распознать слепок v4 → перезаписать v5; повтор → no-op; ручной дрейф → не затирать).
5. `intelligence_user_guide.md` (§11, при необходимости §12) — добавить умный Вербализатор/режимы, System 2, динамический анти-клише — **человеческим языком, без внутреннего жаргона**.
6. PG `content.intelligence_guide`: идемпотентная доставка v1→v2 (сид + миграция; ручные правки — не затирать без явного force).
7. Δ каталога = 0; DDL = 0; веб-код = 0.

## 3. Контент-план

### 3.1. `DEFAULT_INFO_TEXT` v5 (T-2177)

- Секции 1–10 — без изменений (сохраняем v4-текст как есть).
- Новая секция (пример структуры; финальный текст — @Builder, тон канона сохраняется):

```
<h2>11. Генерация изображений</h2>
<p>Бот умеет рисовать. Скажи, что нужно, и он выдаст картинку.</p>
<blockquote><b><i>Бот, нарисуй ...</i></b></blockquote>
<blockquote><b><i>Бот, создай изображение ...</i></b></blockquote>
<blockquote><b><i>Бот, создай мем ...</i></b></blockquote>
<p>Нюансы: генерация занимает время, а при сбое провайдера бот отмажется в своём стиле.</p>
```
- **Запрещено:** любые новые теги заголовков кроме `<h1>`/`<h2>`; точки/запятые/«или» между соседними `<blockquote>`; упоминание секретов/ключа (R18).
- Опционально (по решению @Builder): одна строка в секции «10. Саммари чата» о том, что саммари приходит с обложкой (F6) — только если не ломает счётчики/стиль.

### 3.2. `intelligence_user_guide.md` v2 (§11 + §12) (T-2177)

Дополнить §11 «Как бот думает (System 2)»:
- **Умный Вербализатор / режимы (человеческим языком):** бот сам выбирает, как подать ответ — коротко и небрежно (для трепа), спокойно и по делу (для средних вопросов) или развёрнуто, со структурой и таблицами (для серьёзного разбора). **Без** слов «вербализатор/синтезатор/промпт/LLM/режим» как технических терминов, если этого можно избежать; при необходимости ввести бытовой термин.
- **Динамический анти-клише:** бот ведёт самообновляемый список ИИ-штампов; если ответ прозвучал штампованно, он переписывает его заново. **Без** деталей regex/scrubber/validator-loop.
- **System 2:** §11 уже есть — актуализировать формулировки под раунд.
- §12 «Словарик»: при необходимости добавить бытовые определения («Режим ответа», «Анти-клише»).
- Тест v4 `test_guide_avoids_impl_details` (запрет слов `вербализатор/синтезатор/промпт/llm/validator/loop/аналитик`) **осознанно уточняется**: сохраняем запрет на внутренний жаргон (`llm`, `промпт`, `validator`, `loop`, `scrubber`), но допускаем человеческие формулировки новых возможностей. Обновление теста — в том же коммите (F9).

## 4. Канон/версионирование

### 4.1. Справка (`content.info_how_it_works`)

T-2180 = тестовая фиксация этого пути.
- `info_text.md` — байт-эталон (read-only сид).

### 4.2. Гайд (`content.intelligence_guide`) — новое версионирование

- `GUIDE_CANON_VERSION = 1 → 2` (новая константа в `services/info_service.py`).
- `PREV_R1023_INTELLIGENCE_GUIDE = <текущий v1-текст>`; `KNOWN_GUIDE_SNAPSHOTS = (PREV_R1023_INTELLIGENCE_GUIDE,)`.
- `services/config_cache.py`: новая идемпотентная `_migrate_intelligence_guide_r1023()` (вызов в `init` после `_seed_intelligence_guide`), паттерн ADR-1016-3:
  - текст == канон ∧ версия/маркер актуальны → no-op;
  - текст ∈ `KNOWN_GUIDE_SNAPSHOTS` → перезапись каноном + `guide_delivered_version`;
  - неизвестный текст (ручная правка) ∧ доставка v2 не состоялась → **одноразовая форс-доставка** с бэкапом `prev_markdown`/`prev_updated_at`;
  - неизвестный текст после доставки → не затирать (WARNING).
- Существующий `POST /api/info/guide` (RBAC) и `InfoService.save_guide` — без изменений (write-path PG-only); `get_guide` отдаёт новый markdown.
