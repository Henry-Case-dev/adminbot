### Чего эти логи не показывают

* `uvicorn` запущен с `log_level="warning"`, access-log строк — **0**, HTTP-статусы и
  User-Agent в логах приложения отсутствуют.
* Caddy-логи (page loads `/web/`, UA реальных клиентов, ответы 200/401/403) в этом
  бюджете подключений **не снимались** (прокси оказался Caddy, а не nginx; это
  выяснилось уже в основном прогоне).
* Следствие: HMAC-валидный `initData` выпускает Telegram, но такую же строку
  теоретически может собрать процесс, знающий `BOT_TOKEN`. Непрерывный 8-дневный
  паттерн, 3 разные учётные записи, свежий `auth_date` и payload-длины делают версию
  «реальные клиенты» основной, но UA-подтверждение `/web/` остаётся не снятым.

## 3. ACL: не-админ против привилегированных ручек

Код (не моки):

* `web/api/deps.py:90-109` — нет `initData` / битая подпись / нет `user` → **401**;
* `web/api/deps.py:110-120` — `auth_date` старше `TMA_AUTH_MAX_AGE` → **401**;
* `web/api/deps.py:182-195` — `requires_permission(...)` → **403** при отсутствии права;
* `web/api/deps.py:198-229` — `requires_global_admin()` → **403**;
* `web/api/deps.py:58-64` — неизвестный Telegram ID → роль `user` с пустыми правами;
* права считаются только по `parsed.user.id`; `chat_id`/`chat_instance`/`start_param`
  в ACL не участвуют (`registration-state.md`, раздел «Server-side initData»).

Наблюдения в рантайме:

* 17 запросов от principal `role=user perm=none` **прошли аутентификацию** (валидный
  `initData`), т.е. не-админ реально пользуется приложением. Маршрут в valid-строке не
  пишется, поэтому судить, упирался ли он в 403, по логам нельзя.
* Наблюдаемых отказов 401/403 в логах: **0 записей** (не потому, что отказов не было,
  а потому что они не пишутся). Единственные зафиксированные отказы — 15 × 401
  «missing init data» из §2 (следует из кода `deps.py:90-94`; статус в лог не попадает).

Вывод: ACL-код доказан статически и тестами (см. `registration-state.md`), факт
присутствия не-админа в проде подтверждён, но **наблюдаемый отказ 403 в логах не
зафиксирован** — это пробел наблюдаемости, а не доказательство разрешения.

## 5. Анонимизация

* Telegram ID в этот файл не попадают. Для счётчика уникальных пользователей и примера
  использован `sha256(случайная соль прогона + id)`, обрезанный до 10 hex. Соль
  генерировалась в памяти на один прогон и не сохранена → хеши необратимы и не
  сопоставимы между прогонами.
* Содержимое `initData`, `hash`, `BOT_TOKEN`, `query_id` не читались и не печатались;
  логировались только длина blob, источник (header/query/body) и результат проверки.
* Пути API приведены без query-строк.

## 6. Что доказано, а что — нет

Доказано на реальном проде:

1. Прод развёрнут на `a563ee31` (2.58.161), сервис healthy, `/web/` и `/api/health` → 200.
2. За 8 дней — **8077 успешных серверных проверок `initData`** (HMAC + `auth_date` +

3. Среди этих идентичностей есть **не-админ** (`user/none`, 17 запросов) — аутентификация
   отделена от авторизации.
4. В группе `/menu` сейчас отдаёт подсказку: 2 реальных вызова, оба `group hint`.
5. Флаги deep-link на проде отсутствуют; `TMA_AUTH_MAX_AGE` не отключён (дефолт 86400).

Не доказано / открыто:

1. `/web/` page loads и User-Agent реальных клиентов (Caddy access log не снят в этом
   бюджете подключений; uvicorn access-log выключен).
2. Наблюдаемый 403 для не-админа (403 не логируются).
3. Работа group-кнопки в рантайме — только после деплоя кандидата.
4. Матрица устройств Android/Desktop и private/group/supergroup из реального клиента

## 7. Deploy-ready чек-лист (ничего не выполнено)

Кандидат `14400b73` сейчас **висячий коммит**: ни одна ветка/ref его не содержит
(`git for-each-ref --contains` пусто), на проде объекта нет. Проверено локально:
и `master`, и `int/evol-port-menu01-rci-evol-impl` содержат **старый** `handlers/menu.py`
(4584 байта, 0 `startapp`). Поэтому одного `git pull` недостаточно.

1. **Дать кандидату ref и влить в прод-линию**
   `git branch menu-01 14400b73` → merge в релизную ветку → push.
   Проверка: `git merge-base --is-ancestor 14400b73 <release-head>` → да.
2. **Выкатить** (штатная схема проекта):
   `cd /var/www/admin_bot && git fetch origin && git pull --ff-only && systemctl restart admin_bot`
   (перезапуск один — после выставления флагов, см. п.3).
3. **Прод-env, ровно два значения** (до рестарта, чтобы не делать второй):
   * `MINI_APP_REGISTRATION_CONFIRMED=1` (`_env_bool` принимает `1/true/yes/on`);
   * `MINI_APP_DEEP_LINK_MODE=main` (Main App подтверждён; форма `https://t.me/<bot>?startapp`).
   `MINI_APP_SHORT_NAME` **не задавать** — только для режима `named`.
   `TMA_AUTH_MAX_AGE=0` **не задавать** (отключает проверку свежести).
   `WEBAPP_URL` менять не нужно (дефолт уже правильный).
4. **Проверка после деплоя**: `/menu` в группе → URL-кнопка «Открыть мини-приложение»
   с `https://t.me/PERMsoc_bot?startapp` (домена приложения в URL нет), лог
   `[menu] sent (telegram deep link)`; в личке — прежняя `web_app`-кнопка.
5. **Откат**: вернуть прод на `a563ee31` и `systemctl restart admin_bot`. Флаги
   `MINI_APP_*` на старом коде инертны (полей в Settings нет), удалять их для отката
   не требуется.
