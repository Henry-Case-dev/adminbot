## 1. SOURCE — установление фактического маршрута и runtime-верификация источника фактов

**Маршрут инцидента (кодо-путь + prod-аудит).** Цепочка воспроизводится по коду базы
`1b93c6db` и совпадает с read-only prod-аудитом
`plans/features/nostalgia-audit-2026-10-21.md` (та же воронка, byte-сверка 6/6 кандидатов
с `smart_messages` на прод-данных):

`get_year_back_messages` (smart_messages, пул ≤3 строки) → `_pick_candidate` (вес 0.7 всегда
≥ порога 0.45 при непустом пуле) → `build_nostalgia_user` (весь пул + лор + мемы) → 1 LLM-вызов
(NOSTALGIA_PROMPT / NOSTALGIA_CORE_CANON) → детект UNCHANGED (точное равенство) →
`contains_unchanged_token` → отправка: legacy `bot.send_message` ИЛИ делегирование
`_delegate_initiative` → `handle_initiative` (единый Decision, audit-1021 §3: текст не
перерешается, SendRecheck — свежесть условий).

**Почему инцидент прошёл мимо отказа (§5):** детекторы отказа покрывали только служебный
токен (`is_unchanged_response` — ровно UNCHANGED; `contains_unchanged_token` — токен в любом
обрамлении). Проза-самоотказ («Вспоминать тут особо нечего… Это не та история, из которой
делают кстати») токен не содержит → прошла на отправку как «контент».

**Runtime-верификация источника каждого факта (реализовано в этом слайсе):**

- provenance-лейбл репоста: строки пула с `is_forward=1` рендерятся как
  `[Имя дата | Переслано: источник]: текст` (`format_year_back_line` + `_forward_label`;
  поля Epic 28 R28-1, прецедент канонического контекста `format_context_item`). Репост
  внешней новости больше не выглядит как реплика участника.
- канон: «Строки памяти с пометкой „Переслано“ — чужие новости и материалы не из этого чата:
  событие из пересланного текста — не событие чата, а люди в нём — не участники чата»
  (обе константы). Лица из новостей не могут легально conflated с участниками.
- self-echo на пути кандидатов уже существующий: golden-факты исключают собственные слова
  бота по origin (`search_golden_facts_fts`: `origin != 'bot_direct_reply'` /
  `bot_self_reply`, ADR-1014-2 D6) — неточный пересказ ботом не является независимым
  подтверждением.

**Ограничение (честно):** строки `nostalgia_log`/`mca_bot_outputs` за конкретную публикацию
26.10 с прода не снимались — SSH/прод-доступ данному лайну запрещён брифом. Вывод о маршруте —
код-путь + audit-1021 (прод-верифицированная воронка); состав пула инцидента восстановлен по
форме текста (репост новости + посторонняя реплика — ровно класс year_back-пула). Строка карты
REQ-NOST-SOURCE помечена PARTIAL с этим остатком (снять лог-строки — лайну с prod-доступом).

## 2. SELECT — семантический отбор (§3)

Механизмы кандидатов НЕ тронуты (история/Golden Facts/старые сообщения/контекст — существующие
`_year_back_lines`/`_golden_rows`, веса и порог прежние; регресс-сьюиты зелёные). Критерий
повода — директива владельца §8 дословно в обоих канонах: «Вспоминай прошлое естественно,
когда есть интересная связь с разговором или само воспоминание действительно заслуживает
внимания». Отказ при отсутствии содержательного повода: UNCHANGED-ветка (existing) +
self_decline-ветка (новая, ниже). Слабое воспоминание не компенсируется вымыслом:
анти-вымысел R1 сохранён дословно («не приписывай участникам того, чего нет в строках памяти»).
Неожиданная, но осмысленная ассоциация не запрещена (формулировка §8 допускает «само
воспоминание заслуживает внимания» без привязки к теме).

## 3. COHERENCE — цельность мысли (§4)

- Канон: «Не склеивай несвязанные события и не вытягивай смысл из случайных фактов» (§8
  дословно) + «Если из воспоминания не получается осмысленной реплики, лучше промолчи».
- Дефект №6 §4 (мета-объяснение плохого кандидата вместо отказа) и №8 (служебная оценка)
  закрыты детерминированно: `is_self_declining_text` — узкий страж самоотказа ДО публикации
  (`_candidate_llm_send`, после `contains_unchanged_token`, до делегирования/отправки).
  Ловит только явные вердикты «эта история не годится»: «не та история», «история не та»,
  «вспоминать нечего»/«нечего вспоминать» БЕЗ содержательного поворота. Ироничные формы
  «…нечего, кроме/разве что/только…» НЕ блокируются (запрет владельца §5 на универсальный
  словесный бан) — тест `test_ironic_twist_and_normal_speech_not_blocked`.
- Остальные дефекты §4 (участники без связи, потеря смысла, невытекающий вывод, пересказ без
  реакции) — поведенчески через канон (запрет склейки + «говори своими словами…из которой
  складывается история» + анти-вымысел); детерминированная проверка невозможна без нового
  LLM-вызова (запрещено брифом).
- Цензура/моральные предупреждения/списки запрещённых тем/запрет мата и чёрного юмора НЕ
  введены: стиль и свобода тем сохранены дословной фразой §8 «сохраняя характер, юмор и
  свободу выражения»; композиция/объём/драматургия не предписываются; {max_words} —
  существующий слот, критериев длины нет (Addendum #3).

## 6. PROVENANCE (§6)

- Репост ≠ личное событие участника: лейбл «Переслано: источник» доходит до LLM
  (`test_forward_provenance_reaches_llm`: строка новости маркирована, обычная реплика
  участника — без лейбла) + канон-разделение.
- Комментарий участника к новости не становится подтверждением новости: комментарий остаётся
  `[Имя дата]: текст` репликой участника (лейбл только у forward-строки); утверждения новости
  — в строке с «Переслано»; канон противопоставляет их.
- Разделение источников пути Ностальгии: исходные сообщения/репосты — smart_messages с
  provenance; пересказы L2/GraphRAG — golden-факты с origin-фильтром self-echo и лейблом
  target_user (R1); лор/мемы — существующие секции; интерпретации модели — зона анти-вымысла
  канона. Новая память и отдельный фактчекер НЕ созданы; шутки над историей чата не
  запрещены (канон сохраняет иронию/сленг/свободу).
- `database.get_year_back_messages`: в SELECT добавлены `is_forward, forward_source`
  (аддитивно; легаси-вызовы с dict-row без полей совместимы — `_row_get` default).
  Это минимальное необходимое изменение вне перечня write_scope слайса (без него
  provenance-механизм Epic 28 физически не доходит до рендера кандидата); файл
  ностальгия-специфичный метод, конфликтов с параллельными лайнами нет.

## 7. DELEGATION (§7)

Оба маршрута проверены (тесты `TestAsap5W1Delegation`):

- **Legacy** (K1/K3 OFF): прямая отправка не изменена — существующие сьюиты зелёные.
- **Delegated** (K1+K3 ON): `_delegate_initiative` → `handle_initiative` (единый Decision):
  - sent → `nostalgia_log sent, path=initiative`; ровно один вызов Decision; `bot.send_message`
    НЕ вызывается (второго send-пути нет);
  - происхождение кандидата не теряется: `prepared_text_ref="nostalgia:<fact_id|kind>"`,
    meta несёт kind/полный пул;
  - silent (Decision отказался) → `skipped, reason=initiative_silent`, без отправки и без
    повторной попытки;
  - error → честный `error`, legacy-фолбэка нет (нет задвоения отправки);
  - fresh-conditions: по коду `handle_initiative` (§18D) — свежий recheck-контекст перед
    отправкой, `plan_logical_send` может demote (silent/recheck_demoted); семантическое
    решение принято на слое композиции ностальгии (этот слайс) — Decision повторно текст не
    перерешает (audit-1021 §3), fallback/восстановление сохранены, второй Decision Making и
    конкурирующие отправители не созданы.
- Повторной отправки после неудачного результата нет (error/silent терминальны для прогона).
