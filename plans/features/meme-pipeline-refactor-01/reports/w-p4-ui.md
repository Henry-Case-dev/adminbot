## 1. Что сделано по пунктам чек-листа

### 1.1 Два РЕАЛЬНЫХ поля промптов (P2 §5.1–5.4, P3 §5)

`web/index.html` (блок `data-meme-prompt`): пассивный `div.meme-prompt-text` с
`{{ promptImage.text }}` заменён на два `<textarea v-model="memeDraft.prompt_joke|prompt_image">`
(`data-meme-prompt-joke` / `data-meme-prompt-image`), с подписью слоя
(`chat` / `global` / `factory` / `registry` человеческими словами), ревизией и заводской
ревизией, слотом ошибки у каждого поля (`data-meme-prompt-error-joke|image`), подсказкой
«пусто — снять чатовое переопределение» и бейджем валидности `{joke}` у шаблона.

`web/app.js`:
- `memeDraftFromSettings` собирает черновик из ЭФФЕКТИВНОГО текста `prompts.*.text`;
- `saveMemeSettings` отправляет промпты существующим `put(...)`-путём
  (`POST /api/initiative/meme-settings`), только изменённые поля; пустая строка уходит как
  есть — сервер снимает **чатовое** переопределение (ключ удаляется), а не пишет пустоту;
- новый `memeFieldErrorsFrom(err)` превращает `422` в ошибки КОНКРЕТНЫХ полей: строка
  гейта шаблона (`prompts.meme_image: …`) и список Pydantic (`loc: ["body","prompt_image"]`);
  при ошибке у поля общая строка не заполняется, но тост остаётся видимым (ничего не «молча»);
- неизвестное имя поля (клиент собрал по другому имени) ошибкой поля **не** приписывается
  нашему — показывается общей строкой (громкий отказ, а не ложный успех).

### 1.2 Три честных числа вместо устаревшей подписи (P2 §5.2, ТЗ строки 114–121)

Строка «цель выжимки: — … считается ДО выжимки» удалена. В блоке `data-meme-budget`:

```
Потолок итогового промпта: 400 симв.
Длина шаблона картинки:     5 симв.
Доступно для прикола:       395 симв.
источник потолка: настройка администратора · режим шаблона: подстановка {joke}
(потолка у выжимки нет — этап A не обрезается)
```

При `known === false` оба производных числа показывают **«неизвестен»** (не 0);
длина шаблона — факт и показывается всегда. Значения читаются из канонических имён
`MemeBudget` (`ceiling` / `template_chars` / `joke_budget`).

### 1.3 Диагностика прикола (P6 §9.1–9.9, строка `MEME-JOKE-DIAG-UI`)

Блок `data-meme-speech` из `analytics.last_joke.speech` (`memeSpeechView`):

- `composer` → «собран единым композером» / «композер недоступен — payload прежней сборки»;
- `system_sha12` и `manifest` — идентификаторы фактического payload/манифеста;
- ревизии `Core` (+`core_detail`), `Identity`, `Expression`, `Style Policy`, `Humor Craft`
  (`data-meme-speech-rev`), пустая строка → «нет»;
- приём: «приём применён: **literalism**» / `skip:<код>` → «приём не применён: <ярлык>»;
- `off_axes` → «Выключенные оси: humor_library_enabled» (или «все включены»);
- таблица слоёв: `слой / блок / ревизия / символы` + бейдж `вошёл` | `пропущен`
  (`data-meme-speech-state=rendered|skip`) и причина пропуска;
- `skipped` — причины по слоям человеческими ярлыками (`no_l1_plan_in_genre` →
  «план L1 для жанра не строится», `self_model_folded_into_identity`,
  `expression_examples_absent`, `channel_output_not_required`, `style_requests_absent`,
  `lessons_absent`, `speech_absent`, `samples_disabled`, `humor_disabled`, …);
- нет `last_joke`/`speech` → «Приколов ещё не было — фактических ревизий и манифеста нет»;
- **никогда** не печатаются текст прикола, тексты слоёв, персона, выжимка (проверено
  тестом: объект, содержащий `joke`/`layer_text`, в DOM представление не попадает).

### 1.4 Диагностика инициатив: ДВА отдельных блока (P9 §6, строка `MEME-IIC-DIAG-UI`)

Новый read-only `GET /api/initiative/mechanism-diagnostics` (см. §2) отдаёт ровно то, что
собрал `services.initiative_diagnostics.collect_mechanism_diagnostics` — без склейки,
пересчёта и второго хранилища. Карточка рисует два узла
`[data-meme-diag="text_initiative"]` и `[data-meme-diag="meme"]`, каждый из СВОЕГО блока
(`memeDiagBlocks`), поэтому значения одного механизма не могут подменить другой.

Честные правила (все проверены тестами и видны в UI):

| Правило | Где видно | Поведение |
|---|---|---|
| `null`/`{}` = «нет данных», а не 0 | все поля блока | «нет данных», «нет данных о жеребьёвке», «нет данных» у условий |
| `last_check_ts = null` | «Последняя проверка» | **«никогда»** (не 0 и не 1970) |
| `next_check_ts = null` | «Следующая проверка» | «не рассчитана (проверок ещё не было)» |
| `cooldown.remaining_seconds = 0` | «Свой кулдаун» | «0 с» + базис («от последнего вызова провайдера: …») — законный ноль |
| `cooldown.own_seconds = null` | там же | «неизвестен (настройка не прочитана)» |
| `quota.limit = null` | «Своя квота дня» | «лимит: неизвестен · израсходовано: неизвестно · осталось: неизвестно» |
| конфликт | «Публикации» | ТОЛЬКО из `publication`: «конфликта нет» / «конфликт: сейчас публикует другой механизм»; `publication=null` → «бронь не проверялась» |
| `coordination="degraded"` | плашка + «Публикации» | «координация недоступна» (никогда «конфликта нет») |
| `random.performed=false` | «Случайное решение» | «жеребьёвка не выполнялась: порог случайности 100 % — жеребьёвка не нужна» |
| `skip` vs `skip_recorded` | «Мешает сейчас» / «Запись прошлого прохода» | текущая причина (с origin «ворота/квота/свой кулдаун/тихие часы/бронь») отдельно от записи прошлого прохода («журнал попыток») |
| `ready=null` | «Готовность» | «неизвестна» |

### 1.5 Ярлыки (P3 §5, P6 §9.9, `MEME-ANALYTICS-STAGES`)

Все подписи сведены в один модульный словарь `MEME_REASON_LABELS`/`MEME_STAGE_LABELS`
(методы `memeStageLabel`/`memeSkipLabel` делегируют), поэтому один код = одна подпись:

- `joke` → «Генерация прикола»;
- коды пайплайна: `joke_generation_failed`, `joke_empty`, `no_joke_budget`, `template_empty`,
  `publication_conflict`, `publication_in_flight`, `publication_stale`, `publication_expired`
  (+ прежние `initiative_disabled`, `schema_absent`, `cooldown_active`, `daily_quota_reached`,
  `quiet_hours`, …);
- причины речевых слоёв: `no_l1_plan_in_genre`, `self_model_folded_into_identity`,
  `expression_examples_absent`, `channel_output_not_required` и остальные коды композера;
- маркеры «нет данных» P9 (`never_checked`, `no_random_trace`, `no_attempts_journal`, …).

Неизвестный код честно отдаётся кодом (подпись не выдумывается).

### 1.7 Видимая аналитика по стадиям (`MEME-ACC-12`)

В блоке `data-meme-analytics` под счётчиками добавлен `data-meme-attempt-stages`:
стадии САМОЙ СВЕЖЕЙ попытки (`job_id` первой строки журнала) списком, каждая со своим
исходом и фактами — на 1280 и 390 одинаково читаемо (список, а не таблица: таблица на
390px ломала слова в заголовках).

```
Выжимка            пройден              · выжимка 41 симв.
Генерация прикола  пройден              шаблон 5 симв. · бюджет прикола 395 симв. · прикол 6 симв.
Генерация картинки пройден              шаблон 5 симв. · итоговый промпт 23 симв. · прикол 6 симв.
Публикация         опубликовано         фактов этапа нет
```

Пропуск рисуется как «пропуск» + человеческая причина + код; «символы» не путаются между
этапами (у выжимки — её длина, у картинки — итоговый промпт + длина прикола). Нет журнала →
«Попыток ещё не было — стадии показывать нечего».

   - ничего не пишет, LLM не вызывает, новых таблиц/полей/событий нет.
   Расширение заявленного write-scope (`web/index.html`, `web/app.js`,
   `tests/test_evol014_ui.py`): `web/api/routes.py` (только снятие алиасов, требование

Попутно исправлен связанный дефект карточки, без которого не выполнялась приёмка «после
сохранения и перезагрузки страницы видны сохранённые значения»: данные карточки грузились
только по событию смены `workspaceTab`, поэтому при входе по прямой ссылке
`#/modules/initiative/settings` (и после F5) карточка оставалась пустой («Настройки мемов

## 8. Правка после ревью B1: пины F8/F11 (L-F11S-1)

Ревью (`w-p4-review.md` B1) зафиксировало три красных теста на кандидате `0ccdd7fa`:
`test_routes_file_unchanged`, `test_routes_set_unchanged`, `test_routes_pin_untouched`.
Закрыто **вариантом (a)** — новый маршрут вынесен в отдельный файл-зону — плюс
**осознанным переизданием ТОЛЬКО sha256-пина** (без изменения набора маршрутов).

### 8.1 Почему (a), а не (b) целиком

1. **Конвенция зон — часть процедуры заморозки.** `web/api/__init__.py` и комментарий в
   самом пине говорят дословно: «роутер — отдельный файл зон (прецедент memory_agi/oversight);
   регистрация — в web/app.py; `web/api/routes.py` не меняется», а
   `tests/test_mca23_planned_vs_actual.py` — «routes.py byte-freeze: аддитивный endpoint
   живёт в analytics.py». Набор маршрутов `routes.py` в F8 — это **tripwire против нового
   маршрута в routes.py**; если разрешать ему расти «осознанно», ловушка слабеет: следующий
   случайный маршрут тоже можно будет провести переизданием списка.
2. **Прецедент P2 здесь не подходит по форме.** P2 переиздавал F8 при контентной правке
   существующих эндпоинтов (Δ routes=0, новых маршрутов не было). Точно так же закрыт и
   p0-admin-cache-toggle-save: «Δ routes=0, новых endpoint'ов нет». Наш случай отличается:
   маршрут НОВЫЙ, а значит его место — зона, а не routes.py.
3. **Минимальность.** Вариант (a) не трогает `routes`-инвентарь `f8_baseline.json` вообще
   (55 путей, как было), переиздаётся ровно один sha256 и только потому, что снятие алиасов
   (п.1.6) — принятое и протестированное поведение P4 (`test_meme_pipeline_api.py` прямо
   запрещает алиасы; вернуть их = молча ослабить контракт). Байт-фриз `routes.py` при этом
   остаётся честным: файл изменился, пин это и фиксирует.

### 8.2 Что именно сделано

- `web/api/mechanism_diagnostics.py` — новый файл-зона, ровно 1 маршрут
  `GET /initiative/mechanism-diagnostics` (тот же URL `/api/initiative/mechanism-diagnostics`,
  что ждёт `web/app.js`), права `_require_chat_access`, ответ сборщика как есть;
  re-export в `web/api/__init__.py`, регистрация в `web/app.py` рядом с `initiative_vitality`.
- `web/api/routes.py` — удалён только блок нового маршрута; снятие алиасов осталось.
- `ROUTES_SHA256_F11` → `7ea62c3ee88b…` в каноне (`test_round1025_f8_registry.py`) и в
  синхронной копии (`test_mca23_planned_vs_actual.py`); остальные четыре пина импортируют
  канон и обновились автоматически. В оба пина дописан rationale-блок.
- `tests/fixtures/round1025/f8_baseline.json` — обновлён `sha256["web/api/routes.py"]` и
  запись в `superseded_by`; `routes`-список НЕ менялся (55 = 55).
- `tools/_meme_p4_reissue_f8.py` — переиздание с проверками: идемпотентно (второй прогон →
