## 2. Причина старого read-only: подтверждена по коду базы и закрыта

## 3. Слои настройки и рантайм: проверено реальным резолвером

Тесты полосы подменяют `chat_params.get_chat_param_sourced`, то есть сам шов, который они удостоверяют. Поэтому я проверил слои отдельно, через настоящий `ChatParamsCache` и `get_chat_param_sourced` (двойники PG взяты существующие, из `tests/test_chat_params.py`), а числа витрины сравнил с фактами журнала **реального** прогона `consider_chat`:

- чатовое переопределение: текст "Чатовый прикол.", `source=chat`, `setting_key=prompts.meme_joke`;
- без чатового переопределения: "Глобальный прикол.", `source=global`;
- без обоих слоёв: заводской текст дословно (`Придумай короткий абсурдный прикол из этой выжимки.`), `source=factory`;
- рантайм читает ровно это же значение (совпадение текста и источника, `runtime factory` = витрина);
- пустая строка, отправленная в API по HTTP, удаляет ключ из `overrides`, после чего действует глобальный слой, затем заводской. Кэш чат-параметров пересоздавался перед каждым чтением, поэтому чтение шло из хранилища, а не из памяти прошлого запроса.

Границы, которых тесты полосы не касаются (мой прогон):

- `J=0` (шаблон 39 символов при `L=40`): витрина даёт `T=40, J=0, known=true`, рантайм честно пропускает с кодом `no_joke_budget` и **не вызывает провайдера** (0 вызовов);
- `L` неизвестен (нет ни настройки, ни capability модели): витрина `ceiling=null, T=5, J=0, known=false`, рантайм пропускает с кодом `length_limit_unknown`, провайдер не вызван.

## 4. Витрина = рантайм (закрытие расхождения 371 против 395)

`resolve_length_limit` и `LengthLimit` удалены: в коде упоминаний нет, осталась только негативная проверка `not hasattr`. Витрина считает `resolve_meme_budget(template=<эффективный шаблон>)`. Мои числа в формате L / T / J (витрина и журнал реального прогона совпали во всех случаях):

- заводской шаблон: 400 / 29 / 371, режим append;
- чат `Мем: {joke}`: 400 / 5 / **395**, режим slot;
- чат `Мем:` без плейсхолдера: 400 / 5 / 395, режим append;
- глобальный `Глоб: {joke}` при L=300: 300 / 6 / 294, режим slot;
- два `{joke}`, занесённые мимо API (прямая запись в БД): 400 / 16 / 384, режим invalid;
- `J=0`: 40 / 40 / 0;
- `L` неизвестен: null / 5 / 0, known=false.

Расхождение, измеренное в P1-ревью (витрина 371 против рантайма 395 на шаблоне `Мем: {joke}`), отсутствует: 395 и там, и там. Фактический prompt провайдера: `Мем: прикол` (11 символов при потолке 400), директива "не более 395 символов" дописана после редактируемого промпта, поэтому правка в админке потолок не отменяет.

Мутация для проверки силы тестов (моя): витрина снова считает от константы `MEME_IMAGE_PROMPT` - падают ровно кейсы `chat_slot` и `chat_append` (`test_preview_numbers_equal_runtime_numbers`). Файл восстановлен, sha256 совпал, рабочее дерево чистое.

- **5. Поле промпта картинки реально редактируется, а не только отображается.** На сервере - да (путь записи починен и проверен). В интерфейсе на этом кандидате шаблон всё ещё пассивный текст (`web/` не менялся), поэтому критерий **пока НЕ выполнен** и остаётся за P4. Это не дефект P2, но и не VERIFIED.
- **6. Потолок применяется к итоговому image prompt, а не к выжимке.** VERIFIED: `T + len(joke) <= L` на фактическом prompt провайдера, выжимка без потолка, рантайм и витрина дают одинаковые числа.
- **7. Бюджет прикола считается автоматически.** VERIFIED: `J = max(0, L - T)` в одной функции, использован и витриной, и рантаймом; директива с конкретным N доходит до модели; проверены `J=0` и неизвестный `L`.

## 8. Две заявленные оговорки: решения

**1. Алиасы `length_limit.value` / `prefix_chars` / `summary_target` до P4: принимаю.** Второго расчёта нет - значения берутся из того же `MemeBudget` (одна функция), дублируются только имена, и это условие сохраняет работоспособность текущей карточки, файлы которой держит соседняя полоса COG-MAP. Ограничение по времени обязательно: пункт 6 чек-листа P4 должен удалить алиасы и обновить `tests/test_evol014_ui.py::test_settings_quota_and_analytics_payload` в том же коммите, иначе "одно число, два имени" останется навсегда.

**2. Запись мем-промптов из карточки мемов идёт мимо матрицы прав `/api/config` и не пишет журнал ревизий.** Требований владельца это не нарушает: в разделе 2 ТЗ сказано "сохраняться и загружаться штатно" и "по текущей модели конфигурации", про журнал ревизий и про матрицу прав для этих ключей требований нет; пункт "не обходить права доступа" в ТЗ относится к команде `/meme`, а не к настройкам. Гейт карточки (владелец в ЛС, global или local admin в группе) не слабее дефолтной матрицы `prompts.*`: модератор в неё не проходит, а DM-владелец и local admin дефолтно и так имеют право правки. Отклонение достижимо только при специально настроенном per-key override, запрещающем правку local admin. Журнал: `/api/config` пишет неизменяемый снимок ревизии (`_prompt_record_saved_snapshots`), карточка мемов - нет, поэтому история версий этих двух блоков не увидит правок из карточки. Это несогласованность существующего контракта правки промптов, а не потеря данных и не нарушение ТЗ, поэтому **не блокирует P2**. Требуется осознанное решение в P4 (см. пункт 11 чек-листа): либо звать тот же механизм снимков и проверять матрицу, либо пометить ключи `hidden` и признать карточку единственным владельцем (прецедент `prompts.summary_cover_style_id`).

## 9. Неблокирующие замечания (без расширения полосы)

1. **Имена полей расходятся с текстом слайс-графа.** `slice-graph.json` для `MEME-API-SCOPE` требует "POST принимает joke_prompt/image_prompt", а реализация принимает `prompt_joke`/`prompt_image` (так же в отчёте P2 и в чек-листе P4). `MemeSettingsUpdate` лишние поля молча игнорирует, поэтому UI, собранный по тексту графа, получит 422 "нет изменений" или 200 без сохранения. Минимальное исправление: привести текст графа к коду и включить `extra="forbid"` в модели (или добавить тест на отказ неизвестного поля). Владелец: PM (текст графа) + Builder (модель, окно P4).
2. **Нет durable-теста на чат-путь `/api/config`** с двумя `{joke}` (тестом закрыт только глобальный путь) и **нет теста слоёв через настоящий `get_chat_param_sourced`** (сейчас слои всегда замоканы). Поведение я подтвердил своими пробами, поэтому approval не блокируется, но регрессионной защиты нет: одна проверка на путь + одна через штатный резолвер (образец есть в `tests/test_chat_params.py`). Владелец: Builder, окно P4.
3. **Слой с пробельным значением в БД проваливается сразу к заводскому тексту, минуя глобальный.** Через API недостижимо (`/api/config` отклоняет пустые/пробельные промпты, карточка мемов трактует пробелы как снятие переопределения), поведение унаследовано из P1, лечится только прямой правкой БД. Замечание на будущее, действий не требует.
4. **Провенанс F8.** `param-registry-round1025.meta.md` фиксирует `HEAD (short)` на момент генерации (в коммите стоит `242fbd38`). Это свойство генератора, `--check` эту строку не сверяет. Если для релиза важна точность провенанса, мета-файл переиздаётся в финальном коммите.
