### Точки сериализации (обязательные)

1. **`web/index.html` + `web/app.js`** — сейчас их держит линия COG-MAP S3:
   worktree `.../evol-71536a366a11-814456b9`, ветка `feat/cog-map-s3`, `git status`
   показывает `M web/app.js`, `M web/index.html` (+ `web/static/app.css`,
   `web/static/cognitive-map.js`). P4 стартует только после освобождения этих файлов.
2. **`web/api/routes.py` + `web/index.html` + `services/meme_initiative.py`** пересекаются с
   незакрытым пакетом `UI-MEME` линии asap-evol (`plans/features/asap-evol-anticliche-memory-admin-ux/`,
   5 строк `PENDING`, среди них `UI-MEME-GLOBAL`, `UI-MEME-CHAT-INHERIT`). Решение о
   глобальном scope мем-настроек уже принято в
   `arch/integration-decisions.md:125` (`chat_id=None` = Глобально, запись в hot-ключи
   `initiative.meme_*`), поэтому P2 реализует это по готовому решению, а не изобретает своё.
   Порядок мёржа между этой задачей и `UI-MEME` фиксирует Оркестратор: либо глобальная часть
   `UI-MEME` поглощается P2/P4, либо `UI-MEME` идёт после.
3. **`services/meme_initiative.py`** — P1 и P5 никогда не пишут одновременно.
4. **Схема БД не меняется**: диагностика прикола (шаблон, `J`, фактическая длина) кладётся в
   существующие колонки `detail` / `limit_source` / `limit_value` журнала попыток
   (`meme_initiative.py:157-160`). Если по ходу реализации выяснится, что колонок не хватает —
   это отдельное решение Архитектора о миграции v41, а не «тихая» правка DDL.

## 6. Порядок исполнения

Владелец поставил задачу приоритетной: она идёт сразу после текущей активной линии,
**до** пакетов FINAL v8 и эпика E/P.

1. **Можно начинать сейчас, без ожидания web-лока:** P1 (`MEME-PIPE-CORE`) — только
   `services/*.py` и тесты; COG-MAP S3 эти файлы не держит.
2. После P1 параллельно: P2 (`API`), P3 (`/meme`), P5 (аналитика). Web-лок им не нужен.
3. P4 (админка) — только после P2 **и** освобождения `web/index.html` + `web/app.js`.
   До этого UI временно показывает старую подпись «цель выжимки» — это осознанный
   промежуточный разрыв в одной ветке, релиз собирается после P4.
4. Джойн-барьер: P4 + P2 + P3 + P5 на одном кандидате → независимое ревью → релиз по
   PET_PROJECT без дополнительного согласования.

Первые три пакета по порядку: **P1 → P2 → P3** (P5 параллелен P2/P3, P4 последний).
