1. **`web/index.html` + `web/app.js`** — сейчас их держит линия COG-MAP S3:

   показывает `M web/app.js`, `M web/index.html` (+ `web/static/app.css`,
   `web/static/cognitive-map.js`). P4 стартует только после освобождения этих файлов.
2. **`web/api/routes.py` + `web/index.html` + `services/meme_initiative.py`** пересекаются с
   незакрытым пакетом `UI-MEME` линии asap-evol (`plans/features/asap-evol-anticliche-memory-admin-ux/`,
   5 строк `PENDING`, среди них `UI-MEME-GLOBAL`, `UI-MEME-CHAT-INHERIT`). Решение о
   глобальном scope мем-настроек уже принято в
   `arch/integration-decisions.md:125` (`chat_id=None` = Глобально, запись в hot-ключи
   `initiative.meme_*`), поэтому P2 реализует это по готовому решению, а не изобретает своё.
   Порядок мёржа между этой задачей и `UI-MEME` фиксирует Оркестратор: либо глобальная часть
   `UI-MEME` поглощается P2/P4, либо `UI-MEME` идёт после.
3. **`services/meme_initiative.py`** — P1, P2, P5 и P6 никогда не пишут одновременно: P2 изменил этот
   файл (слой промпта, удаление `LengthLimit`), поэтому P5 стартует только после P2, а P6 — сразу
   после P1 и до P5 (запись ревизий слоёв и manifest появляется в P6).
4. **Схема БД не меняется**: диагностика прикола (шаблон, `J`, фактическая длина) кладётся в
   существующие колонки `detail` / `limit_source` / `limit_value` журнала попыток
   (`meme_initiative.py:157-160`). Если по ходу реализации выяснится, что колонок не хватает —
   это отдельное решение Архитектора о миграции v41, а не «тихая» правка DDL.

**до** пакетов FINAL v8 и эпика E/P.

   (`MEME-INITIATIVE-LAYERS`) независим** и идёт параллельно с P4/P6, web-лок ему не нужен.
4. P4 (админка) — только после P2 **и** P6 (нужны ревизии/manifest для показа) **и**
   освобождения `web/index.html` + `web/app.js`. До этого UI временно показывает старую подпись
   «цель выжимки» — это осознанный промежуточный разрыв в одной ветке, релиз собирается после P4.
5. Джойн-барьер: P4 + P2 + P3 + P5 + P6 (+ P7, если его проверка нашла дефект и потребовала
   правку) на одном кандидате → независимое ревью → релиз по PET_PROJECT без дополнительного
   согласования.

Первые три пакета по порядку: **P1 → P2 → P3** (P6 — сразу после P1, P5 — после P2 и P6,
P4 последний; P7 — в любой момент).

### 9.5 Что обязан проверить Reviewer (без нового процесса)

Захват «реального payload» — фейковый клиент `llm.generate` на боевом пути `_default_joke` (без
инъекции `joke_generator` и без обращения к модели), как зафиксировано в
`arch/joke-speech-layers.md` §6:

1. **Реальный payload модели этапа B**: system начинается с текста задания и содержит J-директиву
   (задание не вытеснено), содержит фактические строки Core (чат-редакция), Expression,
   `HUMOR_TEXT` и hint стиля, при включённом Humor Craft — текст выбранного приёма; `user` — ровно
   выжимка. Наличие функций в коде приёмкой не считается (`MEME-JOKE-REAL-PAYLOAD-REVIEW`).
2. **Связь payload с журналом**: `system_sha12` из захвата совпадает с `facts.joke.speech` в
   журнале попытки, `manifest.layers` (rendered/skip + ревизии) совпадает с `speech.layers/skipped`,
   все причины ∈ `SKIP_REASONS`.
3. **Независимая попытка опровержения**: переопределить текст задания в чате и убедиться, что слои
   не исчезли; выключить Humor Craft и увидеть честную причину пропуска (`humor_disabled`), а не
   тихую подстановку; выключить отдельную технику и убедиться, что она не выбирается; на разных
   `job_id` увидеть больше одной техники.
4. **Проверка тестов на осмысленность**: тест числа вызовов должен падать при возврате второго
   вызова; тест ревизий — падать при потере слоя; тест выжимки — падать, если в system этапа A
   появится Core/Humor.
5. **P7 отдельно**: реальные сообщения инициативы + срабатывание Style Policy по чатовой настройке
   и её отсутствие при выключенной оси; `test_soul1_w5_observer_gates` не правится, байт-паритет
   обычного Direct-ответа подтверждён существующими тестами, `direct_chat_service.py` этим пакетом
   не меняется.
