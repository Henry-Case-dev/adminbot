## 6. Порядок исполнения

Владелец поставил задачу приоритетной: она идёт сразу после текущей активной линии,
**до** пакетов FINAL v8 и эпика E/P.

1. **Можно начинать сейчас, без ожидания web-лока:** P1 (`MEME-PIPE-CORE`) — только
   `services/*.py` и тесты; COG-MAP S3 эти файлы не держит.
2. После P1 параллельно: P2 (`API`) и P3 (`/meme`); P5 (аналитика) — после P2 (тот же
   `services/meme_initiative.py`). Web-лок им не нужен.
3. **P6 (`MEME-JOKE-SPEECH`) — сразу после P1** и до закрытия 13 критериев §8; P5 теперь ждёт
   и P6 (ревизии слоёв и manifest пишутся на этапе прикола). **P7
   (`MEME-INITIATIVE-LAYERS`) независим** и идёт параллельно с P4/P6, web-лок ему не нужен.
4. P4 (админка) — только после P2 **и** P6 (нужны ревизии/manifest для показа) **и**
   освобождения `web/index.html` + `web/app.js`. До этого UI временно показывает старую подпись
   «цель выжимки» — это осознанный промежуточный разрыв в одной ветке, релиз собирается после P4.
5. Джойн-барьер: P4 + P2 + P3 + P5 + P6 (+ P7, если его проверка нашла дефект и потребовала

| **КОНФЛИКТ 4.** Общий проход связывает падения | **НАРУШЕНО** | `_meme_phase` — под-фаза одного прохода (`services/initiative_observer.py:1107-1112`); исключение в любой предыдущей фазе обрывает проход до мемов (единый `try`, `:1107-1127`). У мемов нет собственного «времени следующей проверки» |
| **КОНФЛИКТ 5.** Приоритет `/meme` не выражен | **ЧАСТИЧНО** | ручной прогон просто обходит гейт публикации (`manual` → `True, "manual_bypass"`, `services/meme_initiative.py:1519-1521`) и ничего не сообщает текстовой стороне; автоматическая публикация о ручном запуске не знает |
| **КОНФЛИКТ 6.** Параллельные воркеры | **ЧАСТИЧНО** | резерв квоты атомарен (`BEGIN IMMEDIATE`, `services/meme_initiative.py:783-823`), но защита от гонки `fresh_inflight` стоит до резерва и не покрывает межтиповой случай (`:1387`): два воркера могут дважды сделать выжимку/прикол, а «одна публикация» обеспечивается только дневной квотой, не интервалом |
| **КОНФЛИКТ 7.** Ростер мемов — побочный результат текстового скана | **НАРУШЕНО** | `_meme_phase` берёт чаты только из `payload["chats"]` (`services/initiative_observer.py:1139-1146`), который наполняется лишь чатами с новыми сообщениями и обрезается до `CHATS_TRACKED_MAX` по давности (`:1315-1331`, кандидаты `:1488-1492`): тихий чат вытесняется, и мем в нём не рассматривается вовсе |
| **КОНФЛИКТ 8.** Чат-тумблер инициативы не останавливает мемы | **НАРУШЕНО** | `_meme_phase` не передаёт `chat_enabled` (`services/initiative_observer.py:1147-1151`), из-за чего проверка чата пропускается (`services/meme_initiative.py:1302-1303`): при `initiative.enabled=false` в чате мемы продолжают работать и тратить квоту |
| Диагностика per-mechanism | **ЧАСТИЧНО** | текстовая сторона: гейты с last/next, антифлуд, кулдаун (`services/initiative_observer.py:2044-2084`); мемы: `analytics_snapshot` (`:1727-1763`) даёт counters/skip_reasons/quota/attempts, но без времени следующей проверки, без источника и результата draw в снимке, без признака конфликта публикаций |

Отдельно: `ANTI_FLOOD_AFTER_BOT_OUTPUT_SECONDS` и профильные `min_gap_seconds` остаются осмысленными как
собственные правила механизмов — дополнение не разрешает их отменять, а требует, чтобы межтиповой
интервал был **отдельным** конфигурируемым ограничителем.

### 10.3 Архитектурная классификация: решение заморожено (`arch/initiative-coordination.md`)

`ARCH_FROZEN` (снимает прежнюю пометку `ARCHITECT_REQUIRED`). Решение по контракту принято Архитектором
03.11.2026 и лежит в репозитории: `plans/features/meme-pipeline-refactor-01/arch/initiative-coordination.md`
(коммит `77555550`, `docs(arch): initiative independence + publication coordination`). Карта ссылается на
него как на замороженное решение; повторно вопросы контракта не открываются.

Признаки, которые требовали Архитектора, и что по ним зафиксировано:

| Признак | Замороженное решение |
|---|---|
| Новый общий контракт между подсистемами | новый модуль `services/publication_coordination.py` (интервал, чтение журнала, claim, маркер); второго планировщика/воркера/очереди нет |
| Персистентность/схема | одна строка на чат `chat_publish_claim` (миграция **v41**, `CREATE TABLE IF NOT EXISTS`, PG-копии нет, откат — cold revert) |
| Атомарность | compare-and-set одним `UPSERT` по `chat_id`, без `BEGIN IMMEDIATE`-блока и без in-process lock; `rowcount==1` — право отправки, затем второй стейтмент `claimed → sending`; TTL: `claimed` 90 с, `sending` 120 с |
| «Недавние публикации» | существующий `db.list_recent_bot_outputs(..., kinds=PUBLICATION_KINDS)`, `PUBLICATION_KINDS=("initiative_reply","meme_initiative")` |
| Публичный контракт журнала выводов | `record_delivered_output(..., output_kind="meme_initiative", correlation_id=job_id)` + мем-тип в `BOT_OUTPUT_KINDS`; DDL журнала не меняется |
| Проигравший/устаревание | мем — отмена с явной причиной, сгенерированная картинка позже не отправляется; текст — отмена реплики с сохранением durable intent и перепроверкой существующим механизмом; устаревание мема — по watermark окна (`MAX(id)`) до/после claim → `publication_stale` |
| Межтиповой интервал | ключ `initiative.cross_type_publication_interval_seconds`, дефолт — **существующая** `MIN_GAP_FLOOR_SECONDS` (`services/initiative_observer.py:200`), резолв чат→hot→дефолт одной функцией; ограничивает только пару разных типов |
| Случайность | один клиент; purpose `meme_trigger` + новый `initiative_trigger`; ось `initiative.trigger_probability` с дефолтом 1.0 (draw не выполняется, поведение текста байт-паритетно); фолбэк по настройке владельца — действительный источник с честной трассировкой, прежнее поведение `meme_initiative.py:1070-1073` **отвергнуто** |
| Деградация | нет таблицы → мем останавливается на `schema_absent`; текст публикует с `coordination=degraded` + один WARN (нельзя молча гасить основной механизм) |
| Приоритет `/meme` | маркер `manual_priority_until` ставится до генерации; при чужом `sending` — одна повторная попытка и честный `publication_in_flight`, второй публикации нет |

Что это меняет: P8/P9 больше не ждут архитектурного решения. Прежние открытые вопросы PM (примитив
захвата, семантика интервала, окно актуальности, носитель отложенного решения, способ записи
мем-публикации) закрыты решением Архитектора и не переспрашиваются. Открытым остаётся только показ в
админке (P4) — он ждёт не решения, а освобождения `web/**`.

### 10.6 Что обязан проверить Reviewer (опровержимые проверки, не список утверждений)

1. **Независимость планирования** (`MEME-IIC-REVIEW-INDEPENDENCE`): отключить мемы и убедиться, что
   текстовая инициатива проверяется и публикуется со своими метками; затем искусственно уронить фазу
   текста и увидеть, что мем-проверка выполнена, а не потеряна.
2. **Одновременное срабатывание** (`MEME-IIC-REVIEW-SIMULTANEOUS`): принудительно сделать оба механизма
   готовыми и увидеть ровно одну публикацию + явную причину у второго (отложено/отменено).
3. **Несколько параллельных воркеров** (`MEME-IIC-REVIEW-N-WORKERS`): N процессов на одной БД в одном
   чате — без дублей и без превышения интервала/квоты.
4. **Восстановление после рестарта** (`MEME-IIC-REVIEW-RESTART`): рестарт между решением и отправкой —
   ни повторной, ни устаревшей отправки, состояние восстановлено.
5. **Ручной `/meme`** (`MEME-IIC-REVIEW-MANUAL`): при готовом авто-посте публикуется ручной результат,
   авто откладывается/отменяется с причиной, RBAC и технические гейты сохранены.
6. **Разные чаты** (`MEME-IIC-REVIEW-CROSS-CHAT`): публикация в чате A не блокирует чат B.
7. **Отсутствие дублей** (`MEME-IIC-REVIEW-NO-DUP`): повторный вызов на том же `job_id` не публикует
   второй раз.
8. **Запреты — проверяются опровержением, а не описанием:** нет `sleep`/`asyncio.sleep` на пути
   координации (`MEME-IIC-PROHIB-SLEEP`), нет хардкода таймингов — значения приходят из конфигурации
   (`-HARDCODED-TIMINGS`), нет глобальной блокировки всех чатов (`-GLOBAL-LOCK`), нет второго
   планировщика/брокера/очереди (`-NEW-SCHEDULER`).
9. **Сверка с найденными нарушениями (строки `MEME-IIC-INDEP-ROSTER`, `-SET-CHAT-TOGGLE`,
   `-DEGRADE-VISIBLE`):** тихий чат вне текстового окна всё равно получает мем-попытку или явную причину;
   чат с `initiative.enabled=false` не тратит мем-квоту; при отсутствии служебного состояния координации
   мем не отправляется, а текстовая инициатива публикует с видимым признаком деградации — и ни в одном
   из трёх случаев нет дубля.

Требования к доказательствам — прежние: candidate-bound артефакт в репозитории, наблюдаемое поведение, а
не наличие функции; `live_required: false` для всех строк (PET_PROJECT), живой показ в рабочем чате —
добровольное наблюдение владельца.
