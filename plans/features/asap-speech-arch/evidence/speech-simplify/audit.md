# Аудит речевых слоёв (read-only) — 25.10.2026

LANE_ID: SPEECH-AUDIT-READONLY. Вердикт: **ARCH_REUSE_CONFIRMED**. Новый слой/обработчик не нужен; целевые тексты ложатся в существующие контракты. Ниже — конфликты, которые дают многословие и навязанный юмор, и минимальные точки замены.

## 1. Конфликты

1. **`services/mca_expression.py`** — помимо короткого режима в system добавляется `EXPRESSION_CONTRACT` (~1200 симв.) с требованиями «обязательно используй мат», «строй шутку», «не объясняй» и примерами; для FREQUENT — отдельный длинный блок. Он конкурирует с короткой инструкцией режима.
2. **`services/mca_humor.py`** — 5–6 обязательных юмористических приёмов, требование «в каждом ответе», «доведи до кульминации», «комбинируй виды юмора». Прямое противоречие новому `HUMOR`.
3. **`services/prompt_composer.py`** — `STYLE_POLICY` + `LENGTH_GUIDE` требуют «развёрнуто», «добавляй детали», «литературная обработка»; дублируют `RESPONSE_LENGTH` и провоцируют длину.
4. **`services/mca_prompts.py` / Core** — в авторском Core есть оперативные императивы «сыпь шутками», «строй истории», «демонстрируй характер». Их надо точечно убрать, сохранив биографию и характер.
5. **`services/style_policy.py`** — детерминированная постобработка не подавляет мат, но `quotation_marks`/`dash` могут менять пунктуацию; проверено, мат не режется.
6. **Direct Answers / L2 writer** — функциональные промпты добавляют «будь выразительным», «добавь метафору», «не будь сухим»; дублируют юмор и длину.
7. **Initiative** — отдельный `INITIATIVE_TONE` требует «ярко и с юмором»; для инициативы это может быть уместно, но не должно протекать в обычные ответы.

## 2. Минимальные точки замены

- `services/mca_expression.py`: заменить `EXPRESSION_CONTRACT`/длинные блоки на одну короткую инструкцию по режиму; убрать few-shot-обязательность и «обязательный мат».
- `services/mca_humor.py`: заменить весь набор на одну `HUMOR`.
- `services/prompt_composer.py`: убрать `LENGTH_GUIDE`/«литературность»; вставить `BASE_SPEECH` + `RESPONSE_LENGTH` в существующий общий блок.
- `services/mca_prompts.py` / Core: точечно удалить только дублирующие оперативные команды, сохранив биографию/характер.
- `services/style_policy.py`: не менять, кроме проверки, что мат не режется.
- `services/direct_*` / `l2_writer`: убрать дубли «выразительности/метафор».
- `services/initiative*`: оставить отдельный тон инициативы, но не подмешивать в обычный ответ.
- Заводские стили: реестр в `services/mca_prompts.py` (factory styles) + UI-библиотека `web`/API; добавить `STYLE_DVACH` как пресет, без нового обработчика; права «Медведь Press» не трогать.

## 3. Риски

- Core авторский: удаление императивов должно быть построчным и с доказательством, что они дублируют Expression/Style Policy, иначе потеряется характер.
- `mca_humor.py` может использоваться в нескольких путях (Direct/Initiative/Summary); замена должна быть единой, без разных текстов.
- `prompt_composer` общий для всех; изменение длины влияет на все ответы, включая фактчек/сводки; нужен regression-набор.
- `STYLE_DVACH` не должен переопределять Expression; проверить порядок сборки.

## 4. Ограничение

Аудит Read-only; точные номера строк должны быть подтверждены Builder'ом перед правкой. Коммит аудита был утерян при параллельном `git reset --hard`; файл восстановлен по отчёту лейна. Это не отменяет выводы, но требует проверки каждой правки в текущем коде.
