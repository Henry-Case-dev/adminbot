Вывод по серии: **hardcode формы участия отсутствует** — в живых прогонах
наблюдались `sent` (chat-подобная отправка), `reply`, `silent`; реакция
исполняется только при валидной цели из плана. Но **модельные решения
I-01/I-02/I-04 не проходят столбец «приемлемое»**: L1 систематически
выбирает `delivery=reply` и привязывается к последнему сообщению, а в I-02
— не к тому сообщению, к которому относится текст. Это дефект
поведения/промпта, не транспорта (подробно §7).

Стимул: «тут один написал в чате: «да вы все охуели с такими ценами»…».

## 4. P0D-QUOTED — контент не выбирает режим

   (1 маркер), ответ 0 мата, `raw==sent`. Вход содержит 1 мат — режим не
   переключился.
2. **Конфиг-онли**: `resolve_effective` принимает только документы
   конфигурации; документ с `note`/`quoted_source`/`rag`, полными мата, не

## 7. Находки

1. **current-blocker (I-01/I-02/I-04)**: инициативный L1 выбирает
   `delivery=reply` для общих тем и привязывается к последнему сообщению;
   в I-02 — к чужому сообщению относительно адресата текста. Транспорт
   исполняет корректно (проверка цели, отсутствие перепривязки), но
   модельное решение нарушает §7. Кандидат на правку промпта/канона L1
   (не в этом лейне: канон + миграционная лестница).
2. **related-nonblocking (I-03/I-09)**: планы `react` не содержат
   `target_message_id` (2/2), поэтому реакции не исполняются — срабатывает
   только безопасное молчание. Схема в промпте перечисляет
   `"target_message_id": null`, что, вероятно, якорит null; нужно явное
   требование выбирать `[msg:N]` и для реакции.
3. **related-nonblocking (I-07)**: `_recent_bot_replies` по умолчанию
   смотрит 600 с (`CHAT_BOT_REPLIED_RECENTLY_SECONDS`); ответ бота старше
   10 минут L1 не видит. В живом чате это ослабляет «уже высказался».
4. **related-nonblocking (диагностика)**: `count_profanity` не различает
   цитату и собственную речь; для off-режима валидная цитата мата может
   дать ложный `model_ignored_instruction`.
5. **EVAL-MODES**: доставка веток доказана, поведенческое различие
   occasional/frequent в выборке не наблюдается (frequent 0/2) — по §9.2
   требуется дальнейшая трассировка, не «победа».
