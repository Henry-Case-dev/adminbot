## 3. Payload / raw output: что доступно, а что нет

Доступно (факты из БД):
- полный **доставленный (postprocessed)** текст обоих ответов + `content_hash`
  в `mca_bot_outputs` — это то, что увидел чат;
- последовательность стадий, длительности, reason-коды, `speech_extent`,
  `chat_statistics`-вызов, `FACTS_EXTRACT`.

Недоступно (и почему — по коду, не по догадке):
- **raw LLM output не логируется и не хранится.** Есть прямой тест-контракт
  `tests/test_summary_generator.py::test_raw_response_not_logged`.
- **LLM payload (слои Core/Expression/Style/Functional Writer/analysis) не
  сохраняется.** `PromptManifest` живёт только в памяти процесса:
  `services/prompt_composer.py:995-996` (`_manifests` — `OrderedDict` LRU,
  `MANIFEST_CACHE_MAX`), чтение `get_manifest` — `:1147-1160`. Сервис
  перезапущен в 21:03:19 UTC, т.е. через ~37 мин после прогонов; манифесты
  этих двух ходов уже уничтожены.
- **`prompt_layers` телеметрия не содержит размеров/хэшей слоёв.** Событие
  эмитится только для *пропущенных* слоёв и несёт `status="<layer>:<reason>"`
  (`services/prompt_composer.py:2195-2223`). За окно A — 9 событий, все
  `outcome=silent`, `reason_code=source_missing`, `usage_json=NULL`.
- Слои `model/provider/config_version` для send-событий не заполнены → какая
  модель отвечала, из БД не доказать (только `settings`/`.env` на сервере).
- Веб-Inspector (`web/api/speech.py`, `_inspector_payload` ~:1940) строит
  **preview из текущего состояния композера**, а не восстанавливает прошлый
  payload; для аудита прошедшего хода он не годится.
- Мой probe не покрыл `task_jobs`/`graph_facts` (ошибки имён колонок в моём
  SQL `no such column: id` / `no such column: ts`) — там данных за окно я не
  читал; это ограничение выгрузки, а не вывод об отсутствии записей.

Итог: **полного payload и raw output за эти два запроса не существует ни в
одном хранилище.** Восстановить их задним числом нельзя. Трасса
«сообщение → история/память → слои → payload → raw → postprocessing»
обрывается на шаге «слои»: дальше есть только финальный доставленный текст.

## 5. Причины по слоям (что именно ломает трассу)

1. **Нет персиста payload.** Манифест слоёв — RAM-LRU, Inspector — preview.
   После рестарта аудит невозможен by design.
2. **`prompt_layers` не несёт состава.** Только reason пропусков; ни chars,
   ни sha12, ни rendered-флага. Доказать участие Core/Expression/Style/Writer
   пост-фактум нельзя.
3. **Текущий ход смешан с корпусом.** Оба ответа цитируют сообщение, которое
   только что пришло (A — свой вопрос, B — реплику спрашивающего) как элемент
   истории/мема. Это кандидат на корневую причину «выдуманных дат»: модели
   подаётся свежий текст без границы хода. Требует проверки Builder'ом по
   коду сборки контекста (`Global_Context`/история), не по догадке.
4. **`deep_research` непрозрачен.** Прогон 87 с, `mca_pipeline_runs` пуст,
   отдельного события стадии анализа нет.
5. **Вывод инструментов не сохраняется.** `chat_statistics` вызывается
   (`dur=0`), числа в ответе невоспроизводимы.

## 6. Минимальный безопасный способ получить payload/raw (без новых LLM-вызовов)

Вариант 1 (дешёвый, приватно-безопасный, только телеметрия):
- в `prompt_layers` (или отдельное событие `prompt_payload`) писать по
  каждому *отрендеренному* слою: `layer`, `chars`, `sha12`, `rendered`,
  `writer`; плюс в send-событие — `model`, `provider`, `config_version`;
- в `DIRECT_FRESH_GENERATION` — `raw_len`, `raw_sha12`, `paragraphs`.
  Контента не хранит, но позволяет доказать состав и сравнить прогоны.

Вариант 2 (полный, под явным флагом `DEBUG_PROMPT_DUMP=1` + TTL):
- дамп payload+raw в отдельный файл (`/var/www/admin_bot/var/debug/`, ротация
  N файлов/часов), с `correlation_id`; выключен по умолчанию.

Оба варианта — работа Builder/Architect (меняется контракт событий), не DevOps.
До их появления «достать payload/raw за прошлый ход» технически невозможно.
