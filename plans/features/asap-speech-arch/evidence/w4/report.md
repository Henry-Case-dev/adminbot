## U-01. Desktop «ИИ»: карточки разрезаны наложенным блоком

**Симптом (скриншот):** внутри `Библиотека промптов` / `Модели и подключения` —
яркий прямоугольник с жёсткими кромками, не совпадающий с формой карточки;
швы по кромкам, при hover/scroll не цельная поверхность.

**Причина (найдена в коде, не «на глаз»):** декоративный слой преломления
`web/static/glass-refraction.js` (`.lg-refract`, WIN-GLASS-P0) рисует копию
полигонального фона под поверхностью и маскирует её «рамкой у кромок»:

1. полосы рамки были **абсолютными** (`RING_SOLID_PX=20` + `RING_FADE_PX=46` =
   66 px на сторону). У компактной карточки (78–100 px высоты) верхняя и нижняя
   полосы смыкаются, union-маска покрывает **всю** поверхность — слой показывал
   прямоугольную копию фона поверх подложки;
2. копия фона **не учитывала затемняющие подложки контейнеров**
   (desktop `main.scroll-area` = `rgba(9,13,23,.62)`): полоса выходила на **+33 %
   ярче** интерьера карточки → жёсткий «шов» по кромке;
3. собственная подложка поверхности в слое не воспроизводилась в правильном
   порядке (слой `z-index:-1` рисуется ПОВЕРХ `background` родителя).

**Исправлено** (`web/static/glass-refraction.js`):
- `ringBand(side)` — полосы пропорциональны стороне (10 % / 14 %, капы 20/46 px),
  горизонтальные считаются по ширине, вертикальные по высоте → на любой
  поверхности остаётся спокойный центр ≥52 % стороны;
- `ancestorVeil(el)` — цепочка alpha-подложек предков (снаружи → внутрь, без
  `body`), красится в слой после копии фона;
- порядок отрисовки = фактический стек: копия фона → подложки предков →
  подложка самой поверхности;
- маска пересчитывается при изменении геометрии (`rec.maskW/maskH`).

**Доказательство (пиксельный замер, Chromium):**

| Поверхность | полоса сверху | центр | полоса снизу |
|---|---|---|---|
| `[data-prompt-library-modules]`, до | **+33.4 %** | +17.4 % | — |
| после | **0.0 %** | 0.0 % | +2.2 % |
| `.speech-head`, после | 0.0 % | 0.0 % | +2.3 % |

(допуск в e2e: полоса ≤6 %, центр ≤2 %). Полигональный фон, его геометрия,
цвета, анимация и число полигонов не менялись — правка только в слое стекла.

## U-02. Desktop «Речь и характер»: разрыв/overlay между шапкой и контентом

- Визуальный разрыв — тот же корень, что U-01 (полосы рамки + отсутствие
  veil/подложки): после правки `.speech-head` и «Как рождается ответ» —
  цельная поверхность (таблица выше).
- **Все 7 рядов карты сборки** приведены к честным аффордансам
  (`web/app.js::speechLayerNodes`, `openSpeechLayerRow`; шаблон
  `index.html` → `data-speech-layer-readonly`):

| Ряд | Что делает |
|---|---|
| `Характер (Core)` | раздел `core` (редактор характера) |
| `Самоощущение (SelfModel)` | **только чтение** + причина: «правила кода о себе…» |
| `Планировщик (L1)` | блок каталога `direct.base.l1_planner` (редактор в «Все инструкции») |
| `Уроки (опыт)` | раздел `learning` |
| `Примеры (образцы)` | раздел `examples` |
| `Юмор (стратегия)` | раздел `humor` |
| `Writer` | блок каталога `direct.base.l2_writer` (тот же редактор) |

- Неинтерактивный ряд не имеет шеврона, `cursor: default`, бейдж «только
  чтение» + текст причины (e2e проверяет шеврон↔действие, высоту ≥44 px и что
  каждый интерактивный ряд действительно открывает раздел/блок).

## U-03. Desktop: каталог/редактор промптов

- Одна адаптивная сетка `.prompt-module-grid` (grid `auto-fill minmax(min(240px,
  100%), 1fr)`, `align-items: stretch`, кнопки прижаты к низу) вместо
  `flex-wrap` с карточками по содержимому; e2e: у всех карточек одинаковая
  ширина (±2 px), одинаковое число в ряду, 1 колонка <600 px, ≥3 колонки ≥1024 px.
- Подпись `prompts.direct_chat_verbalizer_system_prompt` в UI:
  **«Direct: финальный ответ (Writer)»** + «Преобразует план и данные в готовый
  ответ; характер задаётся отдельно.» Ключ/ID не менялись (это presentation-
  override `CONFIG_ITEM_UI_OVERRIDE` + `configItemTitle/configItemDescription`);
  применено и в карточке группы, и в дереве/редакторе фокуса промпта, и в
  мета-панели.
- Кнопки этапов (`Синтезатор`/`Вербализатор`) показываются только если этап
  реально есть у модуля (`workspacePromptItems(m, stage).length`) — проверено
  для Direct/Сводок/Поиска и т.д.

## U-04. Mobile: кодовые поля и Inspector

- `.speech-pre` (просмотр payload `СИСТЕМНАЯ РОЛЬ: …`, предпросмотр выражения,
  ответ «Попробовать») переведён на `white-space: pre-wrap` +
  `overflow-wrap: anywhere` + `word-break: break-word`; горизонтальный скролл
  остался только у явного кода (`.speech-pre.speech-code`, diff-строки).
- `textarea.speech-editor`: `white-space: pre-wrap`, `max-width: 100 %`;
  проверено: ввод/вставка доходят до значения, `setSelectionRange` работает,
  вторая горизонтальная прокрутка страницы не появляется.
- E2E на 320/360/390/430/667×375: `scrollWidth <= innerWidth` на маршруте и во
  всех разделах; кодовое поле не выходит за карточку; внутреннего
  горизонтального скролла в режиме просмотра нет.

## U-05. Mobile: редактирование Core

- Переключатель редакций: `.speech-tabs` переносится/сжимается
  (`flex-wrap`, `min-width:0`, подписи не режутся), на ≤359 px — по одной в
  строке; e2e проверяет, что блок не выходит за экран и подписи не обрезаны.
- **«Развернуть»** (главная находка): `.speech-fullscreen` лежал ВНУТРИ
  `.card` с `backdrop-filter` — для `position: fixed` это containing block,
  поэтому «крупный экран» открывался шириной с карточку (278 px при 320).
  Оверлей перенесён на корень `#app` (как остальные модалки): теперь он
  реально покрывает viewport, поле сразу в фокусе, закрытие — «✕ Закрыть»,
  «Готово» и **Esc**; заголовок показывает выбранную редакцию.
- Сохранение действует на выбранный scope и выбранную редакцию: e2e для
  GLOBAL/CHAT проверяет `POST /api/speech/block/core.personality` с
  `scope=global` (без `X-Chat-Id`) и `scope=chat` (с `X-Chat-Id`), без тихих
  переключений.

## U-06. Header / breadcrumb / scope

- Один главный заголовок: крошка теперь показывает только **путь**
  (`Статус / ИИ`), имя раздела — единственный `.header-title`
  (`headerTitle()` = последний элемент маршрута). Раньше над заголовком
  «Промпты» стояла крошка «Статус / ИИ / Библиотека промптов» — два разных
  имени одной страницы.
- Селектор области — один; индикатор `GLOBAL/ЧАТ` — в триггере; статус
  сохранения — чип в шапке (только dirty/saving/error/conflict).
- Шапка не перекрывает контент: измеренные `header.bottom == main.top`
  (320: 116/116, 768: 113/113, 1280: 109/109, 1440: 109/109, landscape: 87/86.6);
  добавлен `html { scroll-padding-top: var(--header-h) }` — на desktop
  скроллится документ, и `scrollIntoView` больше не ставит верх контента под
  липкую шапку.
- Мобильное «Ещё» отдаёт **полный** список разделов (все `navItems` минус три
  закреплённых); на 768–1199 кнопка раскрытия открывает drawer со всем списком
  (e2e считает элементы и проверяет «ИИ»/«Память»). Fullscreen-кнопка не
  переизобреталась.

## U-07. Sticky Save

- Один активный CTA на раздел: единственная кнопка сохранения живёт в панели
  `.speech-savebar`; в `speech-actions` убраны дублирующие accent-Save
  (в режиме «только чтение» там остаётся disabled-кнопка + объяснение).
- Единый state machine (проверено e2e на 390 и 1280):

| Состояние | Панель | Активных Save |
|---|---|---|
| pristine | нет | 0 |
| dirty | «Не сохранено: …» + Save | 1 |
| saving | Save disabled «Сохранение…» (`data-speech-save-state=saving`) | 1 (disabled) |
| saved | «Сохранено ✓ HH:MM», кнопки нет (10 с, как в §5.5) | 0 |
| error (503) | причина + «Повторить сохранение» | 1 |
| conflict (409 «изменено другим путём») | причина + «Обновить данные», основной Save скрыт | 0 |

- Конфликт — новое устойчивое состояние (`speechConflict`, снимается
  перечитыванием раздела): нельзя «вслепую» перезаписать чужую редакцию;
  ложного «сохранено» нет (dirty гасится только после `applied`).

## U-08. Glass/material + доступность

- Материал — существующая архитектура Liquid Glass (`lg-panel*`, `--glass-*`,
  `data-glass`), новых оверлеев нет; правки U-01/U-02 вернули честную копию
  подложки вместо «вырезанного прямоугольника».
- Контраст вторичного текста на 390 px (фактические пиксели фона + computed
  цвет): `speech-card-sub` **9.26:1**, `speech-layer-detail` **7.67:1**,
  `speech-layers-sub` **5.74:1** (порог 4.5:1). Внутри `.speech-screen`
  подняты только вторичные токены (`--text-2/--text-3`) и `text-gray-400/500`;
  базовые цвета не менялись.
- `prefers-reduced-motion: reduce`: слой/фон статичны — 0.0 % изменённых
  пикселей между кадрами (1.2 с) на 390 и 1280.
- Polling («Обновить данные» при остановленном фоне): 0.0 % изменённых
  пикселей — фон не мерцает, стекло не «прыгает».
- Fallback без blur/преломления (`?glassrefract=off`) — читаемая поверхность,
  яркость кромок совпадает с интерьером (таблица U-01).

## U-09. Маршрут

`Статус → ИИ → Речь и характер → Core → Expression → Библиотека промптов →
Direct Writer → Назад` пройден кликами для **GLOBAL** и **CHAT**:

- переходы ведут ровно на `#/ai`, `#/ai/speech`, `#/ai/prompts`,
  `#/ai/prompts/direct/verbalizer`; Direct Writer показывает
  «Direct: финальный ответ (Writer)» и пояснение роли;
- при выборе чата дефолт цели сохранения = «Только этот чат», сохранение уходит
  `scope=chat` + `X-Chat-Id`, в GLOBAL — `scope=global`;
- активный раздел подсвечен (`activeNav` в sidebar/mobile «Ещё»);
- Back (`page.go_back`) возвращает в библиотеку, resize 1280↔390 сохраняет
  маршрут и раздел; горизонтального overflow нет ни на одном шаге.

## Честные границы / что не сделано

1. **Заголовок в `services/param_catalog.py`** (`"Вербализатор прямого чата
   (Характер)"`) не менялся: `services/**` вне write-scope слайса. Переименование
   сделано presentation-слоем UI (ключ и ID неизменны). Если серверный `title`
   используется где-то ещё (экспорт/CLI), там останется старое имя — это нужно
   закрыть владельцу `services/param_catalog.py`.
2. **`tools/ui_soul1_w6_speech_e2e.py`** имеет 2 падающие проверки
   («предпросмотр выражения не обновился», 390/1440) **до** и **после** правок:
   фикстура W6 отдаёт `Остроумие=high`, тест выбирает то же значение → no-op.
   Это рассинхрон теста и фикстуры (не поведение продукта), подтверждён прогоном
   на `git stash` (см. `evidence/w4/regression.md`).
3. Реальный Telegram WebView/физический Android в этом слайсе не гонялся
   (стенд = Chromium). По стоячему правилу проекта device-проверка владельца
   необязательна; архитектурные гарантии перфа уже покрыты
   `tools/ui_win_glass_refraction_e2e.py` (paintMs < 6 ms, p95 < 40 ms) — он
   зелёный после правок.
4. FPS на живом устройстве не измерялся; выводы о материале — по пиксельным
   замерам и существующему glass-контракту, без заявлений о «стало быстрее».
