# ADR-1023-2 — Двунаправленное окно фактчека + граф реплаев (без дубля `FACTCHECK_CONTEXT_MESSAGES`)

- **Статус:** **Accepted** (Step 2 @Architect, 19.09.2026)
- **Фича:** F2 `factcheck-deep-context-round1023`
- **Тип:** backend (окно/граф) + канон промпта + UI-параметр
- **Связано:** ADR-1020-1 (канонический контекст), ADR-1013-3 (канон-миграции), F1 (маркировка), F3 (общий канон/фактчек)

## Context

Фактчек получает только «последние N» сообщений чата (`get_recent_messages`, `FACTCHECK_CONTEXT_MESSAGES`, default 6). Это не даёт контекста **после** целевого сообщения (реакции, уточнения) и не показывает, кто кому отвечал — контекст, «размазанный» по диалогу. ТЗ требует двунаправленное окно (N до/после) как настраиваемый UI-параметр и программный граф реплаев. Дополнительно Синтезатор фактчека «ленится» искать в вебе.

Ограничения: нельзя дублировать семантику `FACTCHECK_CONTEXT_MESSAGES`; вынос `_collect_thread_chain` из direct не должен ломать direct-чат; канон-атомарность ADR-1013-3.

## Decision

1. **Новые ключи каталога** `limits.factcheck_context_before` и `limits.factcheck_context_after` (group `limits_factcheck`), дефолты **6/6**; жёсткий код-кап **`FACTCHECK_CONTEXT_TOTAL_CAP = 40`**, считаемый по сумме `before + after` (якорь БД добавляется сверх капа → фактический максимум строк **41**; R1023F2-06). **Δ каталога = +2**; группа/вкладка не меняются (`tma-menu-freeze`).
2. **Legacy `FACTCHECK_CONTEXT_MESSAGES` — депрекейт:** активный код-путь читает только `before`/`after`; legacy используется как источник одноразовой идемпотентной миграции `migrate_factcheck_context_defaults` (переносит значение в `before`, если `before` не задан или равен своему дефолту; кастом не затирается; legacy == своему дефолту → мигрировать нечего; R1023F2-08). Ключ остаётся в реестре (не ломает пин-тесты), но уходит из UI-вида фактчека (внутренний/hidden). Второго источника правды нет.
3. **Запрос окна:** `DatabaseService.get_messages_around(chat_id, target_tg_message_id, before, after)` — `before` старше якоря + якорь + `after` новее, хронологически ASC. Fail-open → legacy `get_recent_messages(before + after)`.
4. **Граф реплаев — общий util:** `_collect_thread_chain` выносится в `services/thread_chain.py`, переиспользуется direct-чатом (регресс обязателен) и фактчеком. Глубина = существующий `limits.chat_thread_max_depth`, резолвится **per-chat** (`get_chat_param`) и в direct, и в фактчеке (**паритет с direct**; новый ключ не вводим; R1023F2-02). Цепочка строится для **якоря**; отдельный под-блок с note «не доказательства»; fail-open.
5. **Бюджет рендера (R1023F2-01):** `format_chat_context` гарантирует длину всего `<chat_context>` ≤ `max_chars` с учётом `<reply_chains>` (обёртка + окно + цепочка); цепочка сверх бюджета обрезается keep-end (дальние ходы первыми) и имеет отдельный потолок `_REPLY_CHAINS_MAX_CHARS = 1200`.
6. **Grounding-якоря (R1023F2-04):** `chat_context`/`<reply_chains>` **исключены** из источников якорей `FactCheckService._trusted_text` — контекст «не доказательства» не должен «заземлять» фантомные `[ММ.ГГГГ]` теги через свои таймстампы. Якоря — только RAG/поиск/tool-контекст.
7. **Промпт-правило обязательного веб-поиска** для тейков о реальном мире/новостях/датах/политике/общеизвестных фактах — в `FACTCHECK_ANALYST_SYSTEM_PROMPT`; канон-миграция одним коммитом (ADR-1013-3).
8. **Порядок:** F2 идёт **после F1** (общий промпт фактчека трогают обе фичи — F1 маркировка, F2 правило веб-поиска) — ступень канон-контура `F1 → F2`.
9. **Fail-open рендера:** `_fetch_chat_context` держит под общим `try/except → ''` и выборку, и построение цепочки, и рендер (R1023F2-03).
10. **Откат:** `git revert` + обратная канон-миграция; значение legacy-ключа сохраняется, миграция обратима.

## Consequences

- Фактчек видит «до/после» и связки реплаев → точнее разбор контекста; стоимость растёт (кап 40 и дефолты 6/6 ограничивают).
- Прямой чат получает общий util — риск регресса митигируется полным регрессом direct.
- `FACTCHECK_CONTEXT_MESSAGES` уходит из активного код-пути, но остаётся как migration-source — второго источника правды нет.
- Δ каталога ровно +2 (намеренно зафиксировано).

## Alternatives

- **Заполнить `before` = legacy, `after` = legacy (по 6)** — отклонено: неявный рост окна без явного решения.
- **Удалить legacy-ключ из каталога** — отклонено: сломает пин-тесты/Δ и усложнит обратный откат.
- **Дублировать `_collect_thread_chain` в фактчеке** — отклонено: расхождение логик direct/фактчек (риск R3).
- **Отдельный ключ глубины для фактчека** — отклонено: лишний Δ каталога, нет требования ТЗ.
- **Строить цепочки для всех сообщений окна** — отклонено: неконтролируемый рост контекста/стоимости; цепочка якоря достаточна для «размазанного» контекста.

## Cost / латентность

- Окно ≤ `min(before, cap)` старше + якорь + ≤ `min(after, cap)` новее, сумма `before+after ≤ cap = 40` (фактический максимум строк — **41** с якорем). Бюджет `format_chat_context` считает и окно, и `<reply_chains>` (весь `<chat_context>` ≤ `max_chars`; цепочка ≤ `_REPLY_CHAINS_MAX_CHARS = 1200`). Граф — чтение БД без LLM-вызовов. Число LLM-вызовов не меняется (по-прежнему 2 физических). Хард-кап + тесты границ.

## Известные ограничения (зафиксировано при ревью iter1)

- **R1023F2-08:** явный `before == дефолту` неотличим от сид-дефолта без отдельного маркера; в этом случае мы считаем legacy-значение намерением владельца и переносим. Если `before` — не-дефолт (кастом/PG-каст) либо legacy равен своему дефолту (`FACTCHECK_CONTEXT_MESSAGES`), миграция не выполняется (env-дефолт `before` не затирается).
- **R1023F2-07:** `<reply_chains …>` / `</reply_chains>` — структурная обёртка (allowlist `label_exempt` в `canonical_context`), внутренние строки цепочки каноничны; инвентарный сэмпл `factcheck_context` включает под-блок.

## Canon migration

**Обязательна (ADR-1013-3), атомарно в ступени F2.** Слепок `PREV_FACTCHECK_ANALYST_R1023` (с учётом правки F1 — порядок F1→F2), `PROMPT_MIGRATIONS` + `ROLLBACK_MIGRATIONS`, `plans/docs/canon/**`, тесты — один коммит.

## Human Gate

- Подтвердить дефолты **6/6** и суммарный кап **40** (стоимость/латентность). Если владелец захочет меньше — меняются только дефолты, контракт не меняется.
- Подтвердить, что legacy-ключ остаётся «внутренним» (не удаляется).
