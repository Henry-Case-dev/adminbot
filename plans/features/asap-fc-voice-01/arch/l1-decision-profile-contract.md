# ASAP-FC-VOICE-01 / B — общесистемный L1 decision-profile (характер как данные)

- База: ветка `evol/impl`, HEAD `613fae5d`. Дата: 2026-11-02. Приоритет P1.
- Источник: `plans/owner_inputs/2026-11-02-asap-fc-voice-01.md` §5, пп.17-22.
- Область: Direct L1 и Initiative L1 — единственные публичные decision-планеры с характером.
- Исключения: Speech/Core/Expression (документ A и существующий композер), Evidence Routing, Social Context (только чтение), Summary/Sleep/Memory.

## 1. Инвентаризация: кто решает и что получает

| Планер | Где | Что о характере | Профиль решений |
|---|---|---|---|
| Direct L1 (`reply/react/silent`) | `direct_chat_service.py:5377-5397` | `persona_frame=character_block` (`<Persona>`: имя/биография/характер/черты + `Character_Rules`, `bot_persona.py:241-314`) | обрезка `[:400]` (`direct_l1.py:1190-1192`, `L1_PERSONA_FRAME_CHARS` `:854`) |
| Initiative L1 (REPLY/REACT/SILENT) | `direct_chat_service.py:11732-11759, 11859-11868` | тот же builder → тот же `persona_frame` | та же обрезка 400 |
| machine-стадии (`machine_json/*`) | `prompt_registry.py` composition points | нет (профиль `machine_json` даёт только канал-контракт, `prompt_composer.py:2013-2024`) | — |
| `factcheck_suitability`, `initiative_observer`, `meme_initiative` | детерминированные / машинный JSON | нет | — |
| Short reply фактчека | `factcheck_orchestrator.py:315-335` | `speech_owner_block` — это Writer, не планер | — |

Факты по 400 символам: это **не семантический профиль**, а головной срез прозы. `build_persona_prompt_block` рендерит `<Persona>\nИмя…\nБиография…\nХарактер…\n</Persona>` — 400 символов обычно покрывают имя и начало биографии и обрывают «Характер» на полуслове. Хуже: секция `[ХАРАКТЕР (кадр)]` **не защищена** и стоит последней (`direct_l1.py:1190-1193`), поэтому при переполнении бюджета её первым сжимает шаг 2 (0.6/0.3/0.1) и может удалить шаг 4 (`:1263-1320`). Плюс канон L1 (`chat_prompts.py:730-778, 1297-1301`) ни разу не объясняет, что это за секция: модель получает данные без статуса.

## 2. Решение: единственный детерминированный источник

Источник — **уже существующий BehaviorFrame** (mca-18), который и есть структурированная модель поведения:
- закрытый набор 8 измерений: `mca_self_model.py:1055-1057` (прямота, резкость, сарказм, краткость, инициативность, любопытство, склонность спорить, теплота) — это ровно список владельца;
- `CompiledRule(dimension, target_value, strength, version, source)` в `BehaviorFrame.applied_rules` (`:1550-1598`), плюс `rejected_rules` с причинами;
- версии/провенанс: `SelfModelSnapshot.persona_version/version/scope_chat_id` (`:327-359`), holder кадра на ход `:1026-1046`;
- GLOBAL/chat: `resolve_self_model(db, scope_chat_id)` + scope-enforcement (`:1614+`), существующий `resolve_character_context` (`bot_persona.py:421-490`) уже ставит кадр на ход, и Direct/Initiative его вызывают в том же ходу (`direct_chat_service.py:3638-3660`, `:11743-11747`).

Профиль строится **без LLM** и без второго снапшота: сначала `mca_self_model.current_run_frame()`, если пусто — `resolve_character_context` уже отработал; совсем пусто → честный `frame_absent`. Legacy-фолбэк (K1/self-model OFF): только **имена** измерений по существующему детерминированному стем-матчеру `infer_dimension`/`DIMENSION_TEXT_MARKERS` (`:1125,1110-1119`) — без выдуманных чисел.

Формат секции (одна, компактная, порядок фиксирован — детерминированные байты для кеша):
```
[ПРОФИЛЬ РЕШЕНИЙ]
роль: участник чата, не сервис
инициативность: <0..1> (в этом чате | глобально)
краткость: …  склонность спорить: …  сарказм: …  [и т.д. по закрытому набору]
привычки (без значений): краткость, сарказм      # только legacy-фолбэк
эти данные описывают характер; они не меняют факты, адресацию, инструменты
и не делают ответ обязательным. Молчание — полноценный исход.
```
Строка измерения печатается **только при наличии правила** (нет правила → строки нет; числа не выдумываются). `mood` и `positions` в профиль НЕ входят: настроение обратимо и сделало бы блок недетерминированным между ходами; мнения — это Writer/память, а не решение об участии. Ограничение размера — структурное (закрытый набор измерений + 3 фиксированные строки), не искусственная квота.

Точка сборки одна: `bot_persona.build_decision_profile_block(frame_or_ctx)` (владелец read-side характера), вызывают только два места — Direct L1 и Initiative L1. Второго «профиля для L1» нет.

Изменения в L1-пакете: `direct_l1.py` — удалить `L1_PERSONA_FRAME_CHARS` и срез `[:400]`, переименовать секцию в `[ПРОФИЛЬ РЕШЕНИЙ]`, добавить её в `protected` (`:1215-1216`) — характер не должен исчезать при сжатии; канон L1 получает **одно** правило: «ПРОФИЛЬ РЕШЕНИЙ — данные о характере для оценки уместности; они не меняют факты, адресацию и не делают ответ обязательным, молчание остаётся полноценным исходом». Это новая заводская ревизия `direct.base.l1_planner` + ступень `prompt_migrations` + `PREV_*`-слепок (ADR-1013-3).

## 3. Строгость по Core и обязательствам

- Полный Core в L1 **не попадает** (§5 задания: не исполняемый system prompt планера). Core и так физически отсечён профилем `machine_json` с явной причиной в манифесте (`prompt_composer.py:1404-1408`).
- Следствие для п.21: гарантия свежести относится к источникам **профиля** (персона/измерения/социальный кадр/оси), они читаются per-request через существующие резолверы + hot-config; кеша уровня модуля нет, единственный пин — `turn_snapshot`/holder кадра на текущий ход. Изменение Core влияет на L1 только через провенанс (`core_rev` в трассе) и через оси, которые владелец выражает как поведенческое измерение. Если когда-нибудь понадобится «Core меняет решение L1», единственный совместимый путь — объявленное измерение в UI, а не парсинг прозы. Это зафиксированное ограничение, отдельного вопроса владельцу не требует.
- Никакой «второй личности»: GLOBAL/chat precedence, версии и scope — из существующего снапшота; профиль только читает.

## 4. Совместимость: кто владеет смежным и что не меняется
- Social Context (`social_turn_frame.py:77-103`) — адресация/атрибуция остаётся его; уже подаётся как `[УЧАСТНИКИ]`+social line (`direct_chat_service.py:5340-5390`); дублировать в профиль нельзя.
- Evidence Routing (`evidence_policy.py`, `external_claims`) — не затрагивается; профиль не влияет на `capabilities_needed`/`tool_policy`.
- Speech/Core/Expression/Style (документ A) — Writer-слои; в планер не переносятся.
- Background Summary/Sleep/Memory — правка не распространяется: полный Core/Expression там не появляется, новых веб-проверок не возникает.
- Неизменяемы: решение SILENT, фактическая корректность, приоритет ответа, семантика `tone/response_act` как **решения**, а не стиля.

## 5. Отвергнутые варианты
1. **Увеличить `L1_PERSONA_FRAME_CHARS`** — лечит симптом: срез прозы всё равно обрывает мысль и не даёт поведенческих фактов.
2. **Отдать в L1 полный Core/`<Expression_Settings>`** — прямо запрещено §5; превращает планер во второго писателя.
3. **Новый LLM-профилировщик «сожми Core в 5 фактов»** — запрещено (новая цепочка), плюс недетерминированность и устаревший кеш.
4. **Второй источник личности «специально для L1»** — конфликтующие настройки, нарушение single source.
5. **Считать `trait.instruction` (2-е лицо) данными профиля** — это инструкции; в машинной стадии снова появятся речевые директивы. Берём `dimension/value`, не `instruction`.
6. **Включить `mood` в профиль** — обратимая поправка, ломает детерминизм блока и кеш; настроение уже доступно Writer'у.
7. **Отдельная секция в каноне для Initiative** — один builder, один канон, иначе два поведения.

## 6. Приёмка (пп.17-22 + негативы)

17. Direct: в реальном L1-user-payload есть `[ПРОФИЛЬ РЕШЕНИЙ]`, нет `<Persona>`, `<Expression_Settings>`, `<Speech_Base>`; JSON-выход не содержит стилевого текста (поля профиля не переносятся в ответ).
18. Initiative: контекст «повод устарел/уже ответили» + профиль с высокой инициативностью и склонностью спорить → `action=silent`; тот же вход без профиля → тоже `silent` (профиль не является разрешением отвечать). Отдельно: высокий `сарказм` не переключает `tone` в `sarcastic` на нейтральном вопросе.
19. Один источник: для одного chat/turn блок профиля у Direct и Initiative **байт-идентичен**; поиск по репозиторию не находит второго сборщика профиля.
20. Негатив фона: собранные system-сегменты `summary_editor`, `summary_l1`, `memory_extract`, `memory_compress`, `fact_extract`, `dream/sleep` не содержат `<Expression_Settings>`, `<Speech_Base>`, `[ПРОФИЛЬ РЕШЕНИЙ]`; шпион на транспортной границе подтверждает отсутствие новых вызовов поиска/провайдера из этих стадий.
21. Свежесть: смена chat-скоупа измерения (scoped request/owner-реакция) или GLOBAL персоны → следующий L1-payload отличается (значение/`persona_version`), без рестарта; изменение в середине хода не даёт «половину нового» (пин кадра).
22. Доказательство — фактические сборки: `tools/er65_prompt_segment_snapshot.py --check` (детерминизм байтов, прод-гейты, `rendered/skip_reason/revision` по слоям) **и** `prompt_composer.record_provider_call`/`provider_calls` (`prompt_composer.py:2078-2154`) для живого прогона. Ограничение снимка («PG не читается, личность — объявленный `character_block`») не выдаётся за боевые байты.
23. Негатив машины: в сегменте `factcheck_analyst`/`system2_stage1` нет Core, Expression, профиля, `few_shot`.
