# ADR-1025-7 — Обложка на fallback-пути саммари, честный контракт анти-клише, STT-компрессия аудио и fail-fast LLM

- **Статус:** Proposed → (после деплоя) Accepted
- **Дата:** 2026-09-21
- **Раунд:** 10.25, внеплановый хотфикс **`hotfix3-summary-stt-anticliche-round1025`** (T-2482…T-2506)
- **Связано:** `spec.md`; ADR-1025-6 (Bot API local mode), `plans/ARCHITECTURE.md` §52 (F0), §53 (hotfix media), §54/§54.1 (F1/P0-fix); ADR-1023-6 (cover article); ADR-1022-4 (two-call summary)
- **Затрагивает:** `services/summary_generator.py`, `services/system2_handoff.py`, `services/anticliche_worker.py`, `services/negative_constraints.py`, `web/api/anticliche.py`, `web/app.js`, `SmartModule/{service.py, transcriber/*}`, `handlers/{youtube.py, voice_transcription.py}`, `config/settings.py`, `services/llm_client.py`

## Контекст

Прод-дефекты после hotfix2 (`fea2daa`):
- **A [P0]:** саммари уходит **plain без обложки**, если Stage-1 «Редактор» (`parse_summary_handoff`) не парсится из-за таймаутов `nano-gpt.com` → одиночный путь → `cover_prompt=""` → rich-путь не вызывается. Успешный rich-путь с обложкой в логах есть (эталон).
- **C [P0]:** анти-клише — ручные фразы **молча не сохраняются**: `build_patterns` тихо дропает (длина <2/>120, хардкод-клише, дубли, cap); API отдаёт 200 и уменьшенный `count`; UI всегда «Сохранено».
- **B [P0]:** STT не выполняется — сырой файл 28 МБ > лимитов провайдеров (Groq 25 / OpenRouter 20), извлечения/сжатия аудио нет.
- **D [P1]:** хронические LLM-таймауты `nano-gpt.com` (24ч: ReadTimeout 189, LLMTimeoutError 28) — корень A.

## Решение

### D1 (A). Stage-1 — «оба»: устойчивость + обложка на fallback
- **Безопасный разбор** `parse_summary_handoff`: невалидный JSON/выжимка → явная ошибка с причиной (не молча), **ограниченный повтор ≤1** только при таймауте/транзиентной ошибке; при валидном повторе одиночный путь не включается; попытки/причина — R17-safe лог.
- **Fallback не теряет обложку:** при фолбэке Stage-1 **не** выставлять `cover_prompt=""` — сгенерировать `cover_prompt` и отправить **rich с обложкой** существующими `build_cover_media`/`send_rich_message`. Plain — только если rich/обложка реально недоступны (**явная залогированная причина**).
- **`cover_prompt` на fallback — ДЕТЕРМИНИРОВАННО, без доп. LLM-вызова** (уточнение по ревью): visual-промпт выводится из текста саммари (первая фраза после снятия разметки/постфикса, канон ≤300). Обоснование: корень фолбэка — провайдерские таймауты `nano-gpt.com`, поэтому повторный вызов того же провайдера ненадёжен и лишь увеличивает латентность/зависание. Промпт-каноны не меняются; rich-путь идёт прежним кодом.
- **Обоснование «оба»:** (a) снижает частоту фолбэков (корень — провайдер), (b) даёт пользовательскую гарантию обложки независимо от Stage-1. Основное для приёмки — (b).
- **Kill-switch `SUMMARY_COVER_FALLBACK_ENABLED`** (env-only `ClassVar`, default **ON**, вне `param_catalog`): ON — новое; OFF — прежнее plain-поведение байт-в-байт. Обратимость без `git revert`.

### D2 (C). Анти-клише — единый канон и честный отчёт
- **Единый канон длины фразы:** `DYNAMIC_PHRASE_MIN=2`…`DYNAMIC_PHRASE_MAX=120` (`services/negative_constraints.py`). UI/API приводятся к **120**; «лимит длины фразы» (120) **разведён** с «числом паттернов» (вместимость `limits.anticliche_max_patterns`).
- **Ручные фразы НЕ фильтруются** `find_forbidden_cliches`: применяется только к автогенерации; пользовательский ввод сохраняется (допустимо пометить `hardcoded`, но не дропать). Ограничения — только длина/дубли/cap.
- **Честный контракт API:** `{saved, dropped:{invalid, hardcoded, duplicate, over_limit}, count}`; 200 ≠ «всё сохранено».
- **UI warn:** «Сохранено N из M» + причины; без «Сохранено» при отбросе.

### D3 (B). STT — извлечение/сжатие аудио (общая точка)
- Helper **`extract_audio_for_stt(path, max_mb)`**: ffmpeg `-vn -ac 1 -ar 16000 -c:a libopus -b:a 24k -f ogg` (ogg/opus mono 16 kHz ~24 kbps); если всё ещё > лимита — **fallback-чанкинг**; без ffmpeg → чанкинг, иначе честная ошибка.
- Врезка в **`VoiceTranscriber.transcribe_voice`** — покрывает **видео и ГС/кружки** одной точкой; логировать `reason=compressed`/`chunked`/`no_ffmpeg` + размеры до/после.
- **Kill-switch `STT_AUDIO_COMPRESS_ENABLED`** (env-only `ClassVar`, default **ON**): OFF → прежний размерный гейт байт-в-байт.

### D4 (D). LLM — fail-fast + наблюдаемость
- Оценить и при обосновании **снизить** `LLM_FALLBACK_TIMEOUT_SECONDS` (120 → **60**) и/или `LLM_TIMEOUT`/`LLM_MAX_RETRIES` с числами «до/после» — fail-fast вместо долгого ожидания; смысловую логику ретраев не менять. **Уточнение (ревью M-2):** `LLM_FALLBACK_TIMEOUT_SECONDS` — таймаут **одной попытки** фоллбэка (`asyncio.timeout` вокруг одного POST), а НЕ суммарный бюджет цепочки; число ретраев (до 3 попыток) не менялось, значения каталогово/ENV-переопределяемы.
- **Корень — провайдерский** (явно пометить). R17-safe лог причины таймаута; событие/метрика доли таймаутов и fallback (`llm_stats()`, отдаётся аддитивно в `GET /api/status` полем `llm_stats` — только числа). Второй резервный провайдер — решение «внедряем/нет + почему».

### D5. Флаги и инварианты
- Флаги — **env-only `ClassVar`** (`SUMMARY_COVER_FALLBACK_ENABLED`, `STT_AUDIO_COMPRESS_ENABLED`), вне `param_catalog` → **Δ каталога = 0**. Прогрессивная раскатка не требуется (прецедент §53/§54.1). **Δ DDL = 0**. Каноны промптов не трогаем; F0/П0-fix/F1/Эпик 2 не ломаем.

## Последствия

**Positive**
- Обложка/rich не теряются из-за неустойчивого Stage-1; фолбэки наблюдаемы.
- Крупные видео/ГС транскрибируются; ручные фразы сохраняются с честным отчётом.
- Таймауты логируются/метрятся; fail-fast снижает зависания.

**Negative / издержки**
- `cover_prompt` на fallback — детерминированный (без доп. LLM-вызова): нулевая доп. стоимость/латентность, обратимо флагом `SUMMARY_COVER_FALLBACK_ENABLED` (OFF → прежнее поведение); визуальное качество промпта ниже «Редакторского», но обложка гарантирована.
- Сжатие/чанкинг — доп. CPU/время (ffmpeg на проде есть); при отсутствии ffmpeg — честный фолбэк.
- Смена формата аудио (opus) — риск качества STT; покрывается тестами на 28 МБ + малых файлах.

## Рассмотренные альтернативы
| Альтернатива | Почему отклонена |
|---|---|
| Только (a) retry Stage-1, без обложки на fallback | Провайдерский таймаут → обложка всё равно теряется; нет пользовательской гарантии |
| Только (b) обложка на fallback | Не снижает частоту фолбэков/потерь handoff |
| Оставить plain на fallback | Прямо противоречит ожиданию «rich с обложкой» |
| Фильтровать ручные фразы хардкод-правилами | Молча теряет осознанный ввод пользователя (текущий дефект C) |
| Поднимать лимиты STT-провайдеров | Не наш контракт; лимиты внешние |
| Поднимать таймауты LLM | Усиливает зависания; выбран fail-fast |

## Верификация
- A: rich+обложка уходит на fallback-пути (тест+лог); успешный rich не изменён; plain — только с причиной.
- B: видео 28 МБ и ГС > лимита транскрибируются (`reason=compressed`); малые файлы без деградации; без ffmpeg — фолбэк.
- C: ручная «подводя итог» сохраняется; API `saved`+`dropped`; UI «N из M».
- D: причина таймаута логируется; метрика есть.
- Регресс: pytest 8003/0 (+ новые), JS 21/21, matrix 0, `database is locked`=0.
