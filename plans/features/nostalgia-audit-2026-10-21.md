## §2. Почему сообщение «достойно воспоминания» (скоринг)

- `_pick_candidate` (`nostalgia_worker.py:708-732`): year_back = **фиксированный 0.7** при наличии ХОТЬ ОДНОЙ непустой строки в окне ±2д (`_YEAR_BACK_WEIGHT`); golden = 0.3+0.05×importance.
- `_threshold` (`:701-706`): 0.3+aggressiveness(0.3)×0.5 = **0.45**. 0.7 ≥ 0.45 **всегда** → любое сообщение годичной давности проходит порог. Golden с prod-минимумом importance=5 → 0.55 ≥ 0.45 — тоже всегда; но 0.7 > 0.55 → **year_back побеждает golden всегда, пока в окне есть строки** (golden обгоняет только при importance ≥ 9).
- **Содержательная оценка ДО скоринга отсутствует полностью**: `get_year_back_messages` (`database.py:9619-9635`) фильтрует только `text IS NOT NULL AND TRIM(text) != ''`. Нет длины, нет содержательности, нет веса строки в чате, нет важности автора. «Жиртрест» и «ауру вижу» проходят по тем же правилам, что и развёрнутые сообщения.
- Порядок выбора ≤3 строк: `ORDER BY ABS(timestamp − center) ASC, id ASC` — **ближайшие к моменту годовщины, не самые ценные**; первая строка становится «кандидатом» для лога/решений, но **все 3 едут в LLM**.
- Итог: порог — декорация (отсекает только пустой пул); «достойность» делегирована LLM целиком, при промпте из §4.

## §3. Автор / участники / связи

- Автор строки рендерится в LLM: `[author_name ГГГГ-ММ-ДД]: текст` (`format_year_back_line`); fallback user_id → «?».
- **Проверок «участник ещё в чате / реален» нет** — ни для year_back, ни для golden; roster участников чата в user-блок не входит.
- Golden-факты едут БЕЗ привязки к человеку: `format_golden_line` рендерит `[дата] факт`, поле `target_user` (есть в SELECT, `database.py:9664-9666`) **не используется** → модель может привязать факт не к тому человеку.
- Упомянутые в строках третьи лица («Славик», «лешенька», «олеся») для модели — просто текст; контекста, кто из них реален/в чате, нет. «Славик» — мем-персонаж, «лешеньки нет в чате» — сама цитата об отсутствующем.
- В LLM едет также лор чата (≤600 симв.) и ≤10 мемов (по 120 симв.) — дополнительные источники имён без дат/проверки.
- Делегация: Decision для `nostalgia_due` детерминирован (текст не перерешается), SendRecheck — свежесть условий, не осмысленность; W3-проход формы может править текст; ledger пишет фактически отправленное (сверка §1 — по нему, авторитетно).

## §4. Давление жанрового промпта и право отказа

**Цитаты давления (существующий канон):**
- `NOSTALGIA_PROMPT` (OFF-путь): «В чате давно тихо.»; «**Вбрось этот старый факт** так, как будто ты давний участник беседы, **которого внезапно пробило на воспоминания**: с иронией и сленгом из лора, по-свойски, будто вспомнил вслух. **Не пиши как робот-архивариус**.»
- `NOSTALGIA_CORE_CANON` (ON-путь, прод с композером): «Если вспомнить уместно и по делу - **вбрось этот старый факт** обычно 1-2 короткими фразами «кстати...»».
- Жанровая рамка `GENRE_NOSTALGIA_RULES`: «Воспоминание звучит твоим живым голосом, а не архивной справкой: по-свойски, с иронией… **будто вспомнил вслух**.»
- User-блок: «В чате давно тихо. **Вот память:**» — пул подаётся как отобранная «память чата», что имплицирует ценность каждой строки.

**Право отказа есть, но:**
1. Условие отказа — только «**Если вспоминать неуместно или память бедна** - ответь ровно одним словом: UNCHANGED» (оба канона). Критерия «факт скучный/односложный/из него нечего вспомнить» **нет**. При непустом год-окне «память бедна» почти никогда не истинна.
2. Нигде не сказано, что отказ — нормальный/предпочтительный исход; структура «Если вспомнить уместно и по делу — напиши…» делает публикацию главной веткой.
3. Факт: 2/8 LLM-раундов за 14д — отказ (25%), причём только на очевидный мусор (URL, бытовая просьба). Тривиальные/вульгарные односложники публикуются с домысливанием — модель «спасает» слабый факт эвфемизмом и выдумкой вместо отказа.

## §5. Вывод: первопричина и минимальный фикс

**Почему публикуются случайные архивные записи (ранжировано):**
1. **Дата вместо ценности.** Кандидат = «любое непустое сообщение ровно год назад ±2д», вес 0.7 ≥ порога 0.45 всегда; содержательная ценность не оценивается нигде до LLM. Это ровно та «проверка содержательной ценности кандидата», отсутствие которой владелец предположил в §3.3 — подтверждено.
2. **Промпт заставляет «оживлять» слабый факт вместо отказа.** Императивы «Вбрось этот старый факт… пробило на воспоминания», «не пиши как робот-архивариус», «будто вспомнил вслух» + узкое условие UNCHANGED («неуместно или память бедна») без критерия «неинтересно». Отсюда же «ложные факты»: модель строит «живое воспоминание» из вульгарных односложников — эвфемизирует и дорисовывает («справочку получил», «счастье по-савельевски»), адресует «ты» без адресата.
3. **Аудит-слепое пятно:** лог хранит только первую строку пула, LLM получает три → построчная сверка финал↔источник по логу невозможна (это и уронило прошлую попытку диагностики — колонка была верной, не хватало пулов).
4. **Участники без проверок:** «ещё в чате?» не спрашивается; golden без subject; «Славик/лешенька» без контекста реальности.

**Минимальный фикс СУЩЕСТВУЮЩЕЙ семантики (без хардкодов годовщин, ручных списков, новых систем):**
1. **Право отказа в обоих существующих канонах** (`NOSTALGIA_PROMPT`, `NOSTALGIA_CORE_CANON`, правка констант — PR, не новая подсистема): расширить условие UNCHANGED до «если факт скучный, односложный или из него нечего вспомнить — UNCHANGED; отказ — нормальный и чаще всего правильный исход»; заменить императив «Вбрось этот старый факт…» на «если в памяти есть что-то, о чём действительно стоит вспомнить — …»; убрать давление «пробило/робот-архивариус» до совместимого с отказом вида. Одной фразой в жанровой рамке усилить анти-вымысел: «не приписывай участникам событий и последствий, которых нет в строках памяти».
2. **Детерминированный фильтр вырожденных кандидатов** в существующей `_year_back_lines` (опционально, ключ в существующей секции memory-лимитов): строки короче ~3 значимых слов не формируют кандидата. Снимает класс «Жиртрест»/«ауру вижу» до LLM; это параметризация текущего механизма, не пороговые качели 0.45↔0.7 (подбор чисел владелец прямо отверг).
3. **Аудит-хвост:** в `meta` `nostalgia_log` писать **все** строки пула (уже есть `year_lines` в dict) — закрывает слепое пятно сверки.
4. **`format_golden_line`:** рендерить `target_user` (поле уже в строке БД, форматтер меняет одну строку) — снижает ложную привязку фактов.

Пункты 1+2 закрывают первопричину (публикация ради активности); 3–4 — диагностируемость и достоверность. Ничего из «запрещённого» списка §3/§5 директивы не предлагается.
