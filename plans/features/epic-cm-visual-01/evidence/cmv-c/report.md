### 1.2 Подписи в экранных координатах: приоритет, коллизии, пересчёт

* `cognitive-map.js:1233` — ранги приоритета заданы **явно**: выбранный (0) →
  найденный поиском (1) → hover (2) → сосед выбранного (3) → центр района (4) →
  прочие (5). Порядок — §4.4 спеки и §5.4 контракта (поиск выше hover).
  `labelRankOf` уважает и числовой ранг от вызывающего (политика уровня).
* `app.js:31544` — на уровне 0 подписи одиночных узлов опускаются ниже районов,
  иначе шесть названий групп проигрывали полусотне парадигм.
* Аллокатор (`allocateLabels`) остался единственным: районы и узлы идут в ОДИН
  план, поэтому наложения между ними невозможны по построению (не два слоя
  текста). Ширина бокса меряется `ctx.measureText` (сделано в CMV-B, сохранено).
* Пересчёт: `labelKey` (камера, масштаб, LOD, `selectionRev`, `viewRev`,
  `searchRev`, число районов, размер кадра, ширина символа) — `app.js:31500`.
  Hover намеренно **не** входит в ключ: подпись наведения выводится
  принудительным путём (как в CMV-B), иначе план 702 узлов пересобирался бы на
  каждом движении курсора (замерено −2…−3 FPS).

### 1.3 Агрегаты уровня 0 (главный пункт, который не смог закрыть CMV-B)

* `cognitive-map.js:701` `buildAggregates(opts)` — визуальные **районы**
  занятой площади: тайлинг в сетевых координатах (`tileCss ≈ 220` CSS-px при
  обзоре, потолки 6×4), редкие тайлы приклеиваются к ближайшему, потолок числа
  районов. Каждый район несёт:
  * `memberIds` — РЕАЛЬНЫЕ id (отсортированы), `count` = `memberIds.length`;
  * `apexId` — реальный узел-якорь (максимальная степень, тай-брейк по id);
  * `componentCount` — сколько НАСТОЯЩИХ компонент (`computeClusters` по
    принятым рёбрам) попало в район (честная метрика вместо догадки);
  * `label` — реальный тип при однородности ≥80 %, реальное название парадигмы
    при её доминировании, иначе нейтральное «Группа» + реальное число;
  * `flows` — РЕАЛЬНЫЕ рёбра между районами (число, не оценка).
  Сумма `count` по районам равна числу размещённых узлов: районы не теряют и не
  добавляют элементы.
* `cognitive-map.js:1000`-блок — центры районов разводятся детерминированно
  (внутри цикла — прижатие к кадру, чтобы разведение не выдавливало центр за
  границу и не схлопывало его у кромки).
* `web/static/cog-visual.js:1314` `drawGroupFlows` и `cog-visual.js:1348`
  `drawGroupCentres` — отрисовка в слое `fx` ТОЛЬКО на уровне 0: свечение,
  кольцо, дуги состава по долям реальных типов, мягкие потоки (альфа/толщина
  логарифмически от реального числа связей).
* `app.js:30951` `_cogApplyLodVisibility` — на уровне 0 участники крупных
  районов не рисуются поштучно (флаг `hidden` ОДНИМ батчем на переходе уровня,
  данные и id не теряются), видны якоря районов и закреплённые узлы. Возврат на
  L1/L2 возвращает все узлы. Есть защита: без посчитанных районов или без
  позиций свёртка не выполняется (иначе `getPositions()` в vis 9.1.9, который
  не отдаёт скрытые узлы, оставил бы сцену пустой навсегда).
* `app.js:31020` `_cogExpandAggregate` + `app.js:31077` `_cogOnSceneClick` —
  раскрытие: клик по центру района (bubble-фаза на контейнере сцены, §6
  контракта; слой `fx` клики не перехватывает) → `moveTo` к bbox РЕАЛЬНЫХ
  участников (r ≥ 2.2) → выбор реального узла-якоря. Клик по реальному узлу
  имеет приоритет над районом.
* `_cogSyncPositions` и `_cogComputeFit` теперь сохраняют геометрию скрытых
  узлов (кэш позиций полнее `getPositions()`), иначе район терял бы форму, а
  `fitScaleRef` зависел бы от LOD-решения (петля).

## 6. Что осталось за CMV-D (и почему)

1. **Отрисовка счётчиков в шапке.** Данные готовы (`_cogCounts`), но разметка и
   подписи — `web/index.html` (зона D). Сейчас шапка показывает только
   «Отображено: 702 узла · 2400 связей» и «показано 702 из 52 600».
2. **Корневая причина «комка» на мобильном.** Позиции мобильного режима
   (`simple`) собираются `_cogFallbackPosition`, где узлы с общими соседями
   получают одинаковые координаты. На обзоре это скрыто районами, но при
   раскрытии района раскладка снова плотная. Правка — в раскладке (зона D),
   не в LOD; мой пакет её не трогал.
3. **Инспектор и fullscreen**: инспектор в потоке под сценой, bottom sheet,
   `44×44`, возврат фокуса — зона D. `_cogExpandAggregate` уже выделяет реальный
   узел, поэтому карточка откроется штатно, но её раскладка — D.
4. **CSS-легенда** уже совпадает с палитрой (проверено тестом), но если D будет
   менять легенду — источник истины `KIND_STYLE` (адаптер) и `CONFIG.spec`
   (сцена), их сверка закреплена тестом.

## 7. Честные ограничения и риски

* **Стенд B правился минимально** (`tools/ui_cmv_b_scene_fps.py`, только
  `SNAPSHOT`): его метрики `fillW/fillH/bigGroups` считались по
  `net.getPositions()`, а vis 9.1.9 не отдаёт скрытые узлы — после свёртки
  района кадр «заполнял» 0.37 ширины и «не имел видимых областей». Теперь
  заполнение считается по кэшу позиций сцены (это свойство раскладки), а район
  входит в метрику «видимая область» своим РЕАЛЬНЫМ числом элементов. Пороги
  проверок не менялись; файл принадлежит CMV-E — правку нужно зафиксировать.
* **Свёртка узлов на уровне 0** — не удаление данных: строки DataSet остаются,
  снимается только флаг `hidden`, районы обратимы в реальные id, а
  `componentCount` честно показывает, сколько настоящих компонент попало в
  район. Это и есть LOD §5.2 («видны центры групп и ключевые узлы»), но решение
  стоит подтвердить на ревью: контракт §4.3 в колонке «свечение» говорит лишь
  об ореолах, а о видимости ядер умалчивает.
* **Плотностная поправка** — единственная интерпретация §5.2 («`r < ~0.85`, с
  корректировкой по плотности»): без неё кадр `fit` на 702 узлах попадал в
  рабочий уровень и §12.1 не выполнялся. Ограничение `r ≤ 1.05` добавлено по
  результату живого обхода порогов (иначе уровень откатывался в 0 при
  приближении).
* **Центры районов разводятся** (детерминированно, только наш слой): у плотного
  ядра реальные центроиды совпадали, и «несколько отделённых групп» не было
  видно. Позиции реальных узлов при этом не двигаются, камера не двигается;
  клик по центру раскрывает именно реальную область участников.
* FPS: на детальном уровне — паритет с базой (±0.3 FPS), на обзоре — плюс
  8–10 FPS. Разброс стенда (44.7…48.1) больше самой дельты, поэтому в отчёте
  приведено A/B в одинаковом состоянии камеры.
