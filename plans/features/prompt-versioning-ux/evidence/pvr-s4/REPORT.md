# PVR-S4 — единый контроль версий промптов в админке (UI)

Ветка: `pv/ux` (от `7a8af045`, ветка `evol/impl`). Пакет:
`plans/owner_inputs/2026-11-04-epic-prompt-versioning-ux-01.md` §2.1, §2.2,
§4, §6. Контракт: `arch/versioning-ux-contract.md` §6.

## Что сделано

Один компонент `prompt-version-card` (`web/app.js`, шаблон
`#prompt-version-card-tpl` в `web/index.html`) смонтирован там, где
редактируется промпт:

| # | Поверхность | Монтаж |
|---|---|---|
| 1 | вкладка «Промпты» — редактор библиотеки | `web/index.html` (`data-prompt-editor`) |
| 2 | карточки модулей (два generic-рендерера `:data-cfg-key`) | `variant="bar"` |
| 3 | «Инициатива → Мемы» — два промпта | два `v-model` на `memeDraft.*` |
| 4 | Speech/Character — редактор блока | `data-speech-block-detail` |
| 5 | Speech/Character — раздел «Характер» (`core.personality` / `core.personality.compact`) | `variant="bar"`, ключ = активная редакция (`data-speech-core-versions`) |
| 6 | каталог зарегистрированных промптов | `variant="history"` |

Вторая реализация панели истории удалена вместе с корневым состоянием
`promptHistory` и его методами (`web/app.js` −450 строк): история, diff,
активация, baseline и восстановление живут только в компоненте.

## Поведение

- **Карточка**: имя, область человеческими словами (`Глобально` /
  `этот чат · <название>`), состояние одной фразой — `Действует в этом чате ·
  изменён вручную · 03.11 23:42`, `Наследуется от глобального`, `Изменён
  глобально`, `Базовый по выбору владельца`, `Исходный из кода`. Сырые
  `act:`/`fac:`/`sha`/`revision_id` в карточке отсутствуют — только в
  раскрываемых «Подробностях» (`⋯`).
- **Черновик** визуально отличается (`pv-text--dirty`, бейдж «черновик не
  сохранён», раскрываемый действующий текст сервера), кнопки «Отменить
  несохранённое» / «Сохранить».
- **Панель истории**: боковая на десктопе (`min(560px, 46vw)`), полноэкранная
  на ≤767px; полный список по `entries[]` с догрузкой по `page.next_cursor`
  (потолка 50 нет); строки: номер, дата, источник, кто, область, статус,
  «Посмотреть»; полный дословный текст без обрезки и без пересохранения;
  diff «было → стало» красит только `+`/`-` (контекст — `pv-diff__ctx`).
- **Действия по правам**: «Применить эту версию» — только при непустом
  `revision_id` и `actionable`; иначе видимая причина (`нет прав`,
  `code-only`, `несовместима`, `retired`, `журнал недоступен`).
  «Назначить базовой» меняет только указатель и говорит прямо: «Базовая
  версия изменена, действующий текст пока прежний». Панельные действия:
  «Снять назначение», «Восстановить базовую (для чата)», «Вернуть исходную из
  кода» (с подтверждением), «Скопировать глобально» в чатовой области.
- **Никакого оптимистичного «сохранено»**: после Save/Применить/Назначить
  компонент перечитывает `/versions`, хост — конфигурацию (`promptVersionReload`);
  409/422/503 показываются честным текстом, черновик остаётся в поле.
- **Мемы**: два промпта рядом на ≥1024px и столбиком на мобильном, у каждого
  своя «История версий»; сырой `{joke}: 0` заменён спокойной подсказкой:
  `0` → «Прикол автоматически добавится после шаблона», `1` → «Прикол
  вставится в отмеченное место», `≥2` → существующая ошибка конфигурации.
  Текст шаблона и рендерер не тронуты.

## Исправления после ревью PVR-S4 (Needs Fixes)

- **B1.** Раздел «Характер» переведён на тот же компонент: legacy-блок
  «Дополнительно: версии и откат» (сырой `sha256_12`, отдельный «Откатить»,
  первая страница из 50) удалён; карточка (`variant="bar"`) привязана к
  активной редакции (`core.personality` / `core.personality.compact`),
  история — из единого журнала с догрузкой. Мёртвые
  `rollbackSpeechBlock`/`speechHistKind`/`speechHistScope` удалены.
  «Стиль письма» второй истории не имеет: `style.policy` — документ, а не
  блок реестра промптов, версий с откатом там нет (только технические
  ревизии внутри «Подробнее», без действий).
- **B2.** «Подробности и диагностика» теперь раскрывают постоянный блок
  `[data-pv-details]` под карточкой (как `prompt-editor-meta` в библиотеке);
  меню закрывается. Содержимое рендерится только в раскрытом виде, поэтому
  в свёрнутой карточке сырых id в DOM нет. Блок стоит после поля — контракт
  клавиатуры (EVOL-044) не сдвигается.
- **B3.** Добавлены проверки «назначение базовой не активирует»: node-тест
  (`assignTest` — нет POST `/activate`) и e2e (нет нового POST `/activate`,
  активная строка панели не изменилась). Мутация M4 теперь ловится.
- **B4.** Подтверждение успеха переживает перечитывание:
  `reloadPreservingResult` сохраняет `hist.result` при `reloadToken`;
  сообщение закрывается явной кнопкой `[data-pv-result-dismiss]` или
  следующим действием.

## Замечания ревью (разобраны)

- **`body_available=true` для любой строки с `revision_id`.** Это не
  UI-ошибка: сервер действительно всегда отдаёт тело существующей ревизии
  (`services/prompt_release_policy.py:3883-3898` — `body` + `body_available:
  True`, даже для `retired`/несовместимых; в списке флаг означает «тело можно
  запросить по revision_id», `:3749`). UI читает флаг честно
  (`canViewBody`), а недоступность обрабатывает и по факту ответа (нет
  `body`/404/403) — сообщение «текст недоступен» остаётся резервным и не
  маскирует пустой текст. Правок API в этом срезе нет и не требуется.
- **`tests/ui_p0a_ux_speech_compact_e2e.py`**: сценарий смены чата падает на
  клике `.scope-option` («Чат B») — элемент перекрыт (`elementFromPoint`
  даёт `BODY`), воспроизводится и на `b734a4eb`, и на `7a8af045` до S4 →
  предсуществующий дефект заголовочного селектора чата/теста, не связан с
  этой правкой. Раздел «Характер» в этой же пробе проверен отдельно:
  тач-цели ≥44px и `run_core_extras` — 0 падений.

## B4 (re-review 2): подтверждение видно без прокрутки — раунд 3

**Причина.** Блок `[data-prompt-history-result]` стоял ПОСЛЕДНИМ в
прокручиваемом теле панели, за 50 строками ленты. Панель после перечитывания
остаётся в `scrollTop=0`, поэтому сообщение физически не попадало на экран:
1536 — `rect.top=5670` при теле `150..847`, 390 — `9047` при `192..733`.
Проверка раунда 2 читала `textContent`, поэтому оставалась зелёной.

**Правка (одна, на общий компонент — библиотека, мемы, «Характер», каталог).**
`web/index.html`: блок перенесён ПЕРВЫМ элементом в `.pv-panel__body` и получил
`.pv-result--sticky` (`position: sticky; top: 0`, непрозрачный фон, нижняя
граница). `web/static/app.css`: правила `.pv-result--sticky` (+ компенсация
мобильных отступов). Кнопка `×` (явное закрытие) сохранена. Список при
действии НЕ прокручивается — `scrollTop` остаётся 0.

**Проверка теперь геометрическая.** `tests/ui_prompt_version_card_e2e.py`:
`result_geometry` / `assert_result_visible` / `assert_result_sticky` —
после «Применить» и после «Назначить базовой» проверяется `rect` блока внутри
видимого прямоугольника тела панели при `scrollTop=0`, попадание центра в
`elementFromPoint` (не перекрыт) и видимость после прокрутки ленты в конец;
затем явное закрытие `×`. Скриншоты вида окна: `result_library_*`,
`result_baseline_*`, `result_speech_*` (5 вьюпортов). Дополнительно
`tests/js/prompt_version_card_test.js` утверждает порядок разметки
(подтверждение до списка, внутри тела панели).

**Мутация.** Возврат блока в конец тела панели (файлы восстановлены из `HEAD`)
= **CAUGHT**: 45 падений (3 проверки × 5 вьюпортов × библиотека/назначение
базовой/«Характер»), числа совпали с замером ревьюера
(`rect=5670..5710, тело=150..847`; `9047..9098, тело=192..733`). Файлы
восстановлены побайтово (`index.html` sha256 `4c648efb…`, `app.css`
`17bfa2aa…`).

**Реальный Chrome (Browser Use, HTTP-стенд с теми же /api-стабами).**
1536: `rect 149..193` в теле `149..847`, `scrollTop=0`; 390: `191..246` в
`191..733`. Скриншоты `chrome_result_library_1536.png`,
`chrome_result_speech_1536.png`, `chrome_result_library_390.png`,
`chrome_result_speech_390.png`.

**Побочная находка (тест).** `tests/ui_p0a_ux_speech_compact_e2e.py` падал на
клике `.scope-option` («Чат B») на экране «Речь и характер» при 390:
последняя строка панели области выходит за клипающий контейнер оболочки,
`elementFromPoint` в её центре даёт `BODY` (дефект существует и на
`7a8af045`). Переключение чата в тесте переведено на штатный клавиатурный путь
селектора (`ArrowDown`/`Enter` → `scopeMove`/`scopePickFocused`); после этого
файл проходит целиком (`failures=0, POST=21`), то есть проверки PVR-S4 B1 в
`run_core_extras` снова исполняются (мутация «вернуть `data-speech-core-more`»
= CAUGHT). Сама геометрия панели области на мобильном — отдельный
предсуществующий дефект вёрстки заголовка, вне S4.
