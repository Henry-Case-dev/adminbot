## Проверка исправлений по коду

- **F1 rollback.** В не-owner ветке _attempt_journal_writer._write под уже
  взятым serialized() при любом BaseException выполняется conn.rollback(),
  ошибка отката логируется, исходное исключение пробрасывается. Reentrant-ветка
  (db._write_owner is current_task) по-прежнему возвращает без commit и без
  rollback: чужая транзакция не трогается. Контракт совпадает с
  DatabaseService.write_transaction (_safe_rollback_locked).
- **F2 таймаут.** Writer-замыкание несёт атрибут busy_timeout_ms, который читает
  PRAGMA busy_timeout собственного соединения; при недоступности используется
  JOURNAL_BUSY_TIMEOUT_MS (5000). Файловый sync-путь по-прежнему сообщает 250.
  PRAGMA-чтение идёт после снятия lock, не пишет и транзакций не открывает.
- **F3 тест.** test_spool_drain_deduplicates_already_written_attempt_id: в журнале
  уже есть dup-1, в спуле dup-1 и new-2; требуется пустой спул, ids ровно
  [dup-1, new-2] и порядок витрины [new-2, dup-1]. Мутация INSERT без OR IGNORE
  ловится (проверено ниже).
