### 2.1. Как различаются версии (§E3)

* `deployed_sha` — только из `.deploy/release.json` (иначе env
  `ADMINBOT_DEPLOYED_SHA` при отсутствии манифеста). Манифест никогда не
  выводится из checkout: нет файла — `deployed_sha=None`.
* `checkout_sha` — из реального git-каталога дерева.
* `runtime identity` — каталог фактически исполняемого приложения + `APP_VERSION`
  загруженного модуля + `status.started_at` (через существующий seam).
* «Доступные файлы» — `revision_kind=deployed_files`/`files`; такие байты
  отдаются честно, но `commit_bound=False` и `version_verified` только по
  сверке метки версии манифеста.
* Удалённый commit — `exact_remote_commit`/`exact_remote_commit_available`
  в записи и `remote_deployed_commit` в выборе источника.

### 2.2. Порядок источников (§E4)

1. `resolve_local_source` берёт первый `usable` кандидат: явный `root`
   (configured) → `SELF_DIAG_LOCAL_REPO_ROOT` → runtime root.
2. `SourceReader._provider_for(self repo)` маршрутизирует собственный repo в
   локальный провайдер (точное совпадение `repo_origin`), внешний — в GitHub.
3. Если локального дерева нет/оно пропало/read-error — ровно один переход на
   GitHub по **точному** deployed SHA (`state.remote_fallback`), без второго
   шанса и без поиска/листинга.
4. Нет ни локального источника, ни deployed SHA — честный
   `source_missing/deployed_revision_unknown`, ветка по умолчанию не читается.
