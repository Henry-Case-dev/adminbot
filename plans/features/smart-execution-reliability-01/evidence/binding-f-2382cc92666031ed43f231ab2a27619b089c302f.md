## 1. Root cause (localized in production recon, not assumed)

`plans/features/smart-execution-reliability-01/evidence/production-recon-2026-11-14/safefetch-diagnostic.txt`:

```text
GUARDED {... "host": "api.github.com", "port": 443, "resolved": ["140.82.114.5"]}
TLS {"ip": "140.82.114.5", "peer": "140.82.114.5", ... "subject": "*.github.com"}
RAW_PEER {"peer": "('140.82.112.6', 443)", "status": 200, "validated": false}
SAFEFETCH_ERROR {"code": "destination_blocked", "stage": "connect",
                 "reason": "actual peer address not validated", "retryable": false}
```

The pre-flight snapshot of DNS (`140.82.114.5`) and the address httpcore actually connected to
(`140.82.112.6`) differ because `api.github.com` has a rotating pool of A records and httpx resolved
the name **again** at connect time. The TLS handshake itself was valid (`*.github.com`), so the
refusal was a false positive of anti-rebinding, not a real SSRF attempt. `PROXY_ENV` was empty,
provider was `nanogpt`, no name-based trusted bypass existed.

## 2. Change (lowest layer owning the root cause)

Only `services/safe_fetch.py` (single fetch contour) + its tests:

- `_resolve_ip` result of **this** attempt is now also the connect target: TCP goes to a literal
  address from the SSRF-validated set, the original name stays in `Host` and TLS `sni_hostname`
  (httpcore `sni_hostname` → `server_hostname`, so certificate verification is unchanged).
  There is no second resolution, therefore the peer cannot change after validation.
- `_pin_candidates` / `_pinned_url` / `_host_header` / `_send_once`: pinning honours scheme port,
  IPv6 literal brackets, non-default ports; body is replayed to the next validated address only
  when it is replayable (`bytes`/`str`/JSON), never for streaming bodies.
- `_request`: one `aguarded_target` per hop; each redirect hop is resolved and pinned separately;
  `peer_allowed` still compares the actual `server_addr` with the validated set (canonical IP form,
  so compressed IPv6 no longer produces a false mismatch).
- Retryable semantics: temporary DNS (`EAI_AGAIN`/`EAI_SYSTEM`, empty answer) → `retryable=True`;
  NXDOMAIN stays permanent; all validated addresses unreachable → `client_error`/`connect`
  retryable; TLS handshake/certificate failure → `client_error`/`connect` **non-retryable** and
  never `destination_blocked`.
- Proxy path: when an env proxy is configured the previous path (name URL + peer check) is kept,
  because the TCP peer there is the proxy, not the destination (production has no proxy env).

Security invariants check (SXR-F3-01): no SSRF relaxation, no removal of peer validation, no
`verify=False`, no redirect-check relaxation, no private/link-local/metadata allowance, no trusted
bypass by name `api.github.com`, no shell/curl path, no credential/header disclosure (error reasons
contain no URL/IP).
