## Порядок (6 этапов из §10)

1. **W0 — FORENSIC** (`FORENSIC`): трасса запуска 23.10 по 10 этапам, извлечение подписи/изображения/меты/дат, проверка лимитов planner и лексического фильтра, ошибки Tavily/Exa/DDG/SafeFetcher. Только чтение прода, артефакт в `forensic/`.
2. **W0 — PROMPTS** (`PROMPTS`): provenance_missing по существу, восстановление связи штатным API, Inspector/редактор показывает сохранённую и действующую редакцию, причину, источник, ревизию и способ разрешения. Защита не отключается, метаданные не выдумываются.
3. **W0 — EXPRESSION** (`EXPRESSION`): диагностика пути `effective -> payload -> raw -> outbound` по пяти маршрутам, затем семантика FREQUENT без квот и постпроцессора, серия реальных проб.
4. **W1 — FACTCHECK** (`FACTCHECK`, после FORENSIC): семантические запросы, отдельные вердикты по утверждениям, различение «нет доказательств / сбой поиска / сбой обработки / частично проверено», честный renderer.
5. **W1 — CHECKUP + CORE** (`CHECKUP`, `CORE`, после PROMPTS): Checkup получает Core/Expression/Style и не задаёт личность, убирается строчная буква; Core дополняется качествами §5.1 без замены авторской редакции.
6. **W2 — OPS** (`OPS`, после CHECKUP), затем **W3 — ACCEPT**: 23 сценария, governance-запреты §1, отчёт §11, деплой и postdeploy-наблюдение.
