## 3. Блок B — единый effective-config/gate resolver (T-4703…T-4707; R06-C-001, B-001, B-005, A-004)

### 3.1 Контракт resolver'а (D6)
Модуль: **расширение `services/mca_gates.py`** (новый подмодуль/функции сна; второй резолвер запрещён). Единая точка для 4 потребителей: scheduler-тик, ручной запуск (web API), `DreamWorker._run_deep_once` (:1514), UI (`/api/memory/deep-sleep` :529).

```python
resolve_dream_gate(db, chat_id: int | None) -> DreamGateState
# DreamGateState (frozen dataclass):
#   gate: str            # canonical gate key: master_sleep | deep_sleep | rag |
#                        # memory_service | schedule | queue | cooldown | resource
#   blocked: bool
#   reason: str          # один из 8 кодов §3.3 | None
#   global_value: bool   # глобальное значение ключа
#   chat_override: bool | None  # per-chat override или None (не задан)
#   effective: bool      # фактическое значение
#   source: str          # chat | global | env | default (прецедент :539)
#   detail: str | None   # конкретный диагноз: имя ключа/override/лимита
```

Инварианты:
- Один запрос resolver'а отвечает «можно ли сейчас спать этому чату и почему нет» — одинаковый ответ для всех 4 потребителей (тест-инвариант T-4703).
- Resolver — **информационный**, не human gate: уже выданное MCA-разрешение на память учитывается, повторного подтверждения владельца не создаёт (:374; round1022-human-gate-map). Тест «нет второго human gate» обязателен.
- Неисправная конфигурация → `detail` с конкретным именем ключа/override/лимита (не «проверьте настройки»).

### 3.2 Порядок проверки (детерминированный)
1. `memory_service_missing` — `self.memory is None` (воркер :1564; для API — состояние сервиса).
2. `master_sleep_off` — `memory.dream_enabled` (глобально/override/env).
3. `deep_sleep_off` — `flags.deep_sleep_enabled` (:1520–1525).
4. `rag_off` — `flags.graph_rag_enabled` (исторический поиск неосуществим; обычный сон-ветка может продолжить — различие фиксируется, не склеивается).
5. `schedule_outside_window` — вне расписания/окна сна (показанное расписание ≠ доступность: `schedule_outside_window` ≠ gate-off).
6. `queue_busy` — конкурирующий запуск/занятая очередь (см. §6.3 singleflight).
7. `cooldown` — завершённый cooldown последнего прогона чата (:1544–1546).
8. `resource_limit` — суточный токен-кап / лимит попыток (глобальная защита; см. §6.1).
Порядок фиксирован; первый сработавший gate — возвращаемая причина (тест-матрица T-4703).

### 3.3 Восемь различимых причин
`master_sleep_off`, `deep_sleep_off`, `rag_off`, `memory_service_missing`, `schedule_outside_window`, `queue_busy`, `cooldown`, `resource_limit`. Коды — в **едином** словаре: расширение `mca_events.REASON_CODES` (mca_events.py:60) аддитивно + замена `_DEEP_REASON_MAP` (memory_agi.py:498–510) на вывод resolver'а; второй словарь не создаётся (T-4702).

### 3.4 Фикс API (T-4705; О2)
- memory_agi.py:571–582: `paradigms_reason` перестаёт быть `"master_off"`-обобщённостью — отдаёт код resolver'а (master_sleep_off или deep_sleep_off по факту).
- memory_agi.py:554–564: ошибка чтения счётчиков → отдельный код `counters_error` + честная пустота с диагнозом (не нули, не «disabled»).
- Лог конкретного запуска (`memory_dream_log` + отчёт §8.5) — источник подтверждения реальной прод-причины (:366).

### 3.5 Врезка (T-4704) и развязка traits (T-4707)
- Scheduler/worker: решение «пропустить/запустить» — по `DreamGateState`; каждый skip пишет различимый код (не `master_off`).
- Traits-ветка остаётся запущенной до ранних выходов ветки парадигм (:1547–1557 — сохранить); traits-успех **не** пишет success-счётчик парадигм и не подменяет парадигм-статус (тест: traits-ok + парадигм-блокер → счётчик парадигм не увеличен; A94-хвост).
- Существующие ветки/rate-пути при всех kill-switch OFF — прежняя последовательность (включая traits-в-конце :1696–1700).

## 4. Блок C — исторические кандидаты и возраст (T-4708…T-4712; R06-C-002/003, B-002/003)

### 4.1 Исторический профиль поиска (D7)
Отдельный профиль **поверх существующих каналов mca-07** (`retrieve_fact_candidates` summary_memory.py:3150, `with_meta=True` — несёт стабильный `id`, `rag_ts`, `tg_message_id`); эпизоды — кандидат-источник через `EpisodeRepository.list_episodes` (mca_episodes.py:452). Прямой RAG (`get_rag_facts` :3120) и его смысл **не меняются** (регресс-тесты); ACL не обходится (каналы уже scoped по chat_id; скоуп-фильтр — ограничение, не обход).

### 4.2 Порядок «фильтр ДО top_k» (О5; фикс R06-B-002)
Сегодня: `get_rag_facts` → top_k (:1587–1589) → `historical`-фильтр (:1590) — старые вытесняются до проверки возраста. Новый порядок в ветке исторического поиска:
1. Выборка кандидатов с pre-limit (`≥ 4×top_k`, константа профиля) по тематическим пакетам.
2. **Сначала** возраст/период/scope-фильтр (§4.3), дедуп оснований (§5.1).
3. Затем финальный top_k (`limits.deep_sleep_top_k`, значение не трогается).
Fixture «20 свежих + 1 релевантный старый» → старый в кандидатах (A92).

### 4.3 Возраст от message_timestamp (О5; T-4711/T-4712)
- Возраст = проверяемое время исходного сообщения/события: `message_timestamp` (mca-03 пара `(chat_id, tg_message_id)`); дата индексации/повторного извлечения (`created_at`) — **отдельное поле**, в порог возраста не подставляется (:368).
- `rag_ts = COALESCE(message_timestamp, created_at)` (RAG-контракт) для исторического профиля **не считается доказанной датой события**: факт без валидного `message_timestamp` → не проходит порог; `missing_timestamp++` + доля недоступных оснований в отчёте. Unknown ≠ «старая» (:376).
- T-4712: обследование реальной БД + bounded восстановление `message_timestamp` по оригиналам (data-операция, отчёт в plans/reports; без изменения смысловых значений вне восстановительного контракта).
- Direct-RAG и его контракты не изменены (регресс).

### 4.4 Тематические пакеты и enrichment (T-4709/T-4710)
- Темы/субъекты и сравниваемые периоды — **ограниченные пакеты** (bound на число пакетов/расширение на прогон; константы kill-switch-фичи, env-only). Один общий запрос из несвязанных убеждений не расширяется бесконечно (:375).
- Пустой episodes-пул (v21-таблицы до live-извлечения владельцем) — **штатная ветка**: `no_anchors` / запуск ограниченного resumable enrichment, не сбой и не «архив пуст» (:362, CA-4).
- Enrichment (поиск первичных сообщений на старую историю без извлечённых фактов): bounded бюджет, checkpoint, resume без дублей (донор mca-05 backfill worker-budget; durable job, не payload-трекинг — урок L-EXTRA-6); exhaustion → `paused`, никогда не гильотина; отчёт в §8.5.

### 4.5 Vec-независимость (О12, CA-10)
Исторический профиль не требует активных vec-поколений как предусловия: неактивное поколение/карантин → FTS/lexical-фолбэк каналов mca-07; полный честный `no_anchors` при пустом результате (не ошибка). Тест: `graph_facts_vec` disabled → профиль работает.

## 5. Блок D — независимость и валидация (T-4713…T-4716; R06-C-004, A-007…009)

### 5.1 Подсчёт уникальных первичных событий (О6; T-4713)
- Каноническая идентичность основания: пара `(chat_id, tg_message_id)` (mca-03) / SourceRef-идентичность (mca-04a); для graph_fact-опор — их собственная SourceRef-цепочка до сообщения.
- Несколько `source_ids`/производных пересказов **одного** события → independence=1; тема ≠ событие (соответствие MCA05-R2).
- Счётчик независимости фиксируется в отчёте прогона и `belief_meta` парадигмы.

### 5.2 Анти-самоподтверждение (T-4721)
- Основания канала `bot_self_reply` (включая пересказ ботом собственного вывода участником) — **не** независимые подтверждения: исключаются из independence-подсчёта. REUSE `services/bot_output_ledger.py` (mca-22); «вывод → пересказ → усиление» не поднимает счётчик (тест-контрпример :352).

### 5.3 Валидатор моста «раньше → сейчас» (О1; T-4714/T-4716)
Проверки (все обязательны для `written`):
1. Субъект: участник/объект вывода присутствует в основаниях обоих периодов.
2. Временная последовательность: «раньше» строго раньше «сейчас» (по проверяемым временам, §4.3).
3. Смысловой мост: событие/обоснование изменения между периодами (не произвольная пара старых фактов; случайные старые сообщения → отказ).
4. Противоречия/исключения/дрейф: валидатор ищет опровергающие и дрейфовые основания (:353); найденное противоречие → вывод сужается/помечается спорным, фиксируется EvidenceLink `contradicts` (mca-22) — не игнорируется.
5. Источник: каждое основание резолвится до первичного сообщения.
Порог: `min_anchors=2` **независимых** первичных событий (:1616 `min_anchors=2` сохраняется; D10 — не снижается). Недостаточно → статус `insufficient_evidence` (новый, §7.1), не «unchanged» и не запись ради счётчика. Промпты сна (`dream_prompts.py:154/:237`) — правка только явно, одним коммитом «код+эталон+тесты» (прецедент R4-D-003).

### 5.4 Валидатор ссылок (О14; T-4717)
