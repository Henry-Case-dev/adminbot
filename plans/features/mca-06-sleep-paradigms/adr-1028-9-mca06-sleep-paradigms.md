## Решения (D1–D12)

**D1. Единый gate-resolver сна поверх `services/mca_gates.py`.** Один resolver (`resolve_dream_gate` → `DreamGateState{gate, global_value, chat_override, effective, source, detail}`) для 4 потребителей (scheduler / ручной запуск / worker / UI); 8 различимых причин (`master_sleep_off, deep_sleep_off, rag_off, memory_service_missing, schedule_outside_window, queue_busy, cooldown, resource_limit`); фиксированный порядок проверки; resolver информационный — нового human gate не создаёт (round1022-map, :374). Второй резолвер запрещён. Диагноз неисправной конфигурации — конкретный (ключ/override/лимит). *Альтернативы:* (а) отдельный sleep-резолвер — отклонено (два источника правды); (б) расширение `GET /api/config` — отклонено (спящий контекст ≠ общий конфиг-API).

**D2. Фикс API-склейки гейтов.** `_DEEP_REASON_MAP`/`master_off` (memory_agi.py:498–510, :571–582) заменяется выводом resolver'а; ошибка чтения счётчиков → отдельный `counters_error` + честная пустота с диагнозом (не нули). Владельческий дефект :366 закрывается; прод-причина — журналом конкретного запуска.

**D3. Исторический профиль поиска — отдельный профиль поверх каналов mca-07.** Кандидаты через `retrieve_fact_candidates(with_meta=True)` + эпизоды (`EpisodeRepository.list_episodes`); возраст/период/scope-фильтр **ДО** финального top_k; pre-limit ≥ 4×top_k; тематические пакеты с bound; empty-episodes → штатная no_anchors/enrichment-ветка. Direct-RAG и ACL не меняются (регресс-тесты обязательны). Resumable enrichment — bounded, checkpoint, никогда не гильотина (донор mca-05 worker-budget).

**D4. Возраст — только от проверяемого времени исходных сообщений.** `message_timestamp` (mca-03); `created_at`/дата индексации в порог не подставляется; unknown-время → не проходит порог + `missing_timestamp`/доля в отчёте; обследование/восстановление timestamps по оригиналам — отдельная bounded data-операция (T-4712). Это снимает порочный `COALESCE`-путь для исторического порога (:368) без изменения RAG-контракта.

**D5. Δ DDL = v25, минимальная.** Через реестр `mca-14`, аддитивно/идемпотентно, PG no-op, backup pre-DDL (fail-closed guard): `mca_pipeline_runs` + nullable `chat_id` + nullable `report_json` (bounded отчёт прогона: стадии/найдено-отсеяно-независимые/причины отсева/диапазоны дат/LLM-вызовы/валидация/записано/missing_timestamp) + 1 индекс. Стадии — span-события `mca_events` (v19-колонки); run-строка — v19-таблица (PM-ожидание «стадии в v19» уточнено: стадийные данные в span-событиях, отчёт — в run-строке). Типизированные якоря — в существующие v17-таблицы provenance (Δ 0); scope/время убеждения — в JSON `belief_meta` (Δ 0). Backfill не требуется. *Альтернативы:* (а) новая таблица отчётов — отклонено (второй run-store); (б) `task_jobs.payload` — отклонено (урок L-EXTRA-6).

**D6. Словари — один.** Десять статусов (`disabled/error/no_context/no_anchors/insufficient_evidence/unchanged/duplicate/budget/cooldown/written`) с маппингом старых кодов (`ok→written`, `budget_skip`/`daily_limit→budget`, `no_memory→disabled+detail`); reason-коды — аддитивное расширение `mca_events.REASON_CODES` (mca_events.py:60); `_DEEP_REASON_MAP` не дублируется. Служебные коды остаются reason-кодами отчёта/trace. UNCHANGED — полноценный проверяемый исход (UI ≠ ошибка); сбой БД/RAG/парсера ≠ успешная пустая выдача.

**D7. Независимость по первичным событиям + анти-самоподтверждение.** Каноническая идентичность основания — mca-03-пара/SourceRef; пересказы одного события → independence=1; bot_self-основания (включая пересказ ботом собственного вывода) исключены REUSE `bot_output_ledger.py`. Порог «двух якорей» сохранён на независимых первичных событиях — **не снижается** (:377; ограничение round1021 подтверждается, пороги/капы не трогаются, CLI-консолидация не трогается).

**D8. Валидация — мост + ссылки.** Мост-валидатор: субъект, временная последовательность, смысловой мост, противоречия/исключения/дрейф (→ EvidenceLink `contradicts`, сужение области — видимый результат), источник. Валидатор ссылок: существование (`resolve_source_ref`) + соответствие + недубльность; «проверки ID в JSON недостаточно» (:358). Новый статус `insufficient_evidence` для честного отказа. Промпты сна правятся только явно (коммит «код+эталон+тесты»).

**D9. Квоты двухуровневые; cooldown/backoff/ресурсы раздельные.** Per-chat суточный учёт попыток поверх `memory_dream_log` (те же правила стоимостных статусов, что `count_deep_attempts` database.py:6811) + глобальный кап и токен-бюджет сохраняются как защита ресурсов. Cooldown (завершённый прогон, per-chat), backoff (ограниченный экспоненциальный, сброс по настройкам/новым данным), ресурсные лимиты — три независимые различимые причины; циклические ретраи заблокированы. Ручной запуск: RBAC, singleflight + повторная проверка `last_deep_attempt`, отчёт той же структуры с пометкой manual.

**D10. Происхождение/версии/пересмотр — REUSE контрактов.** Обе группы ссылок (входные `source_ids` + исторические якоря) — через `services/provenance.py` (второй контракт запрещён); версии — supersede-семантика mca-22, старые версии читаемы; идемпотентность — `_deep_dedup_key` + provenance-дедуп; пересмотр зависимых выводов — bounded очередь (cap, приоритет ниже прямых, не мгновенный каскад); раскрытие цепочки до сообщений — extension-эндпоинт существующего `/api/memory/dream*` + карточка delta.

**D11. Наблюдаемость — mca-17a, без новых каналов.** Процессы сна code-declared в реестре; run/span/heartbeat/watchdog по модели ADR-1027-8; отчёт прогона durable (D5); телеметрия bounded; heartbeat ≠ progress, progress-stall по типу стадии (LLM-стадия допускает законную длительность). «Аналитика»-витрина — mca-17c, отсюда только данные.

**D12. Deploy-политика — пер-фичевый релиз (см. AM-4).** Bump 2.58.48→2.58.49, атомарный коммит «код+эталон+тесты», миграция v25 идемпотентно + backup, health-гейт, soft/cold-откат.

## Последствия и совместимость
- **Сохраняется:** workers/расписания/UI сна (:344); пороги/капы round1021; direct-RAG/ACL; provenance-контракт единственный; словарь reason-кодов единственный; mca-05-семантика «событие ≠ тема»; отсутствие повторных human gates.
- **Меняется:** порядок исторического отбора (фильтр до top_k), статус-словарь (10, с маппингом), квоты (per-chat + global), API-причины (без `master_off`-склейки), отчётность (durable отчёт прогона), происхождение якорей (типизированное), поведение при коррекциях (bounded пересмотр).
- **Kill-switches:** 7 env-only default-ON, послойный OFF = бит-в-бит 2.58.47 (spec §11.1); Δ каталога = 0 (новые настройки env-only вне каталога — прецедент ASAP-4.1; открытый вопрос `mca-round1027-plan.md:404` закрыт положительным «0» — F8-переиздание NOT_APPLICABLE).
- **Риски:** `threat-failure-analysis.md` THR-1…THR-15 (R3); остаточные — компенсированы отчётом прогона и bounded-очередью пересмотра.
- **Откат:** soft (7 рубильников) → cold (`git revert`; v25 аддитивна, старый код не читает); restore БД — аварийный сценарий.
