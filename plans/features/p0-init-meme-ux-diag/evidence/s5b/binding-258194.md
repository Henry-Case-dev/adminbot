## 2. Что живая выкладка действительно показала

Живой read-model обоих чатов (`release-258194/live-overview-2.58.194.json`,
`checked_at 2026-11-11T23:27Z`, `api_status 200`, `console_errors: []`):

```
meme_quota (оба чата): limit 3, used 3, remaining 0, limit_reached true,
                       delivered 2, not_delivered 1,
                       not_delivered_reasons {"publisher_not_bound": 1},
                       next_reset 2026-11-12T00:00:00+00:00
text_initiative_quota (оба чата): delivered null, not_delivered null,
                       not_delivered_reasons {}
```

1. **Отказ и доставка разведены на реальных данных.** Счётчик отказа называет
   причину (`publisher_not_bound`), а не пустоту; экран печатает одну строку
   «Генерации сегодня: 3 / 3 · Осталось: 0 · сброс: 2026-11-12T00:00:00+00:00 ·
   израсходовано без отправки: 1 (отправитель не привязан в этом процессе)».
2. **«Нет данных» не превращается в «0».** У текстовой инициативы фактов доставки
   нет — поля `null`, причины `{}`; это ровно то, что требовалось вместо нулей.
3. **Подтверждённая отправка читается честно.** `meme_last_delivery` обоих чатов:
   `status=confirmed`, непустой `message_id` (1210056 и 10472), `reason_code=""`,
   `run_id` вида `meme:<chat>:2026-11-11:<hash>`. Это строки, записанные прежним
   кодом; новый код читает их без искажений.

## 3. Почему строки остаются `READY_FOR_LIVE` (граница честно)

- **События `publisher_not_bound → отложено → доставлено` после выкладки не было.**
  Суточная квота мемов исчерпана в обоих чатах (`used 3/3`, `limit_reached true`,
  сброс `2026-11-12T00:00:00Z`), новых мем-попыток нет.
- Счётчики отказа — реальные, но **исторические**: их посчитал новый код по старым
  строкам. Самого решения «не выбрасывать оплаченное» на живом тике не наблюдалось.
- `last_delivery` обоих чатов — `confirmed` (последняя по времени отправка), поэтому
  порядок «более поздний отказ не перезаписывает подтверждённую отправку» на живых
  данных не наблюдался: отказ старше подтверждения.
- Симуляция с фейковым отправителем этого не заменяет: она доказывает поведение кода
  (`evidence/s5b/binding-e92cdcd5.md` §2), но не то, что живой тик реально отложил
  и затем доставил байты.

Остающийся триггер записан один раз в карте:
`waiting_observations` → `WO-258194-S5B-DEFERRED` (поля для чтения — там же).
