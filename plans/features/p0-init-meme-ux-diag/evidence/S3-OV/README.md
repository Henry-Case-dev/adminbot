# S3-OV — «Обзор: две карточки с пятью осями» — доказательства

Срез: `S3-OV` эпика `p0-init-meme-ux-diag`. Кандидат: ветка `init/meme-axes`
(база — прод-релиз 2.58.188 `c087253d`, поверх — S1-AXES/S2-ID `4c59a483`).
Контракт: `architecture.md` §4/§5 и строки `P0IM-OV-CARDS`,
`P0IM-OV-FALSEOFF`, `P0IM-OV-PERCHAT-CAUSE`.

## Что изменено

* `web/app.js` — пять осей читаются из ответа
  `GET /api/initiative/mechanism-diagnostics` (`configuration` / `health` /
  `readiness` / `last_attempt` / `last_delivery`) и переводятся в бытовые
  фразы. Клиентской сборки «включено» из мастер-флага/наблюдателя больше нет.
  Загрузчики `loadMemeDiagnostics` / `loadMemeSettings` применяют ответ только
  при совпадении `scopeEpoch` И `payload.chat_id`; у диагностики один
  in-flight запрос и один «хвост» на последний epoch (прежний молчаливый выход
  оставлял старый снимок).
* `web/index.html` — в существующем обзоре: строка «Чат · пояс · снимок ·
  Обновить», две равнозначные карточки с осями (каждая ось в своём узле
  `data-ini-axis`), полоса координации только при живом конфликте/приоритете/
  деградации. Новых секций нет.
* `web/static/app.css` — `.ini-scope-line`, `.ini-fact__code`,
  `.ini-note--warn` (существующая тёмная система, без новых токенов).
* `tests/js/initiative_ui_rework_test.js` — юнит-проверки витрины и привязки
  ответа к чату (в т.ч. негативные случаи).
* `tests/ui_initiative_rework_e2e.py` — существующий Playwright-приёмочный
  тест страницы: оси, отрицательные состояния, обрезка/прокрутка.

## Формулировки пяти осей (фактический текст, 390×844 и 1536×960)

| Ось | Карточка «Текстовая инициатива» | Карточка «Мемы» |
|---|---|---|
| Разрешено | «включено — настройка этого чата» (бейдж «ВКЛ») | «включено — настройка этого чата» (бейдж «ВКЛ») |
| Сейчас | «может сработать сейчас — ничего не мешает» | «ждёт: кулдаун, осталось 1 ч (код: cooldown_active)» |
| Дальше | «точное время не назначено — рассматривается на ближайшем проходе» | «не раньше 15.01 09:05 UTC (по собственному кулдауну)» |
| Последняя проверка | «никогда» (проверок не было) | «15.01 08:04 UTC» |
| Последняя попытка | «15.01 08:03 UTC · автоматически · опубликовано» | «15.01 03:05 UTC · вручную (/meme) · опубликовано» |
| Последняя отправка | «подтверждено · 15.01 08:03 UTC · чат -100500 · сообщение 4321» | «подтверждено · 15.01 03:05 UTC · чат -100500 · сообщение 555444» |
| Дневная квота | «3 / сутки · израсходовано 1 · осталось 2» | «Генерации сегодня: 1 / 3 · Осталось: 2 · …» |

Шапка: «Чат: Чат A · пояс чата не задан — время в UTC · снимок: 15.01 08:05
UTC · Обновить». Пояс берётся из уже загруженных параметров
(`limits.chat_timezone` → `limits.summary_timezone`); не задан ни один —
честный UTC с пометкой, а не выдуманная зона.

Отрицательные состояния (Playwright, 1536×960 и 390×844):

* явный OFF: «выключено — глобальный выключатель: выключено глобальным
  выключателем», «Сейчас: заблокировано: выключено настройкой»;
* кулдаун (`ready=false`, `enabled=true`): «Разрешено: ВКЛ» + «ждёт: кулдаун»,
  слова «выключено» на карточке нет;
* доставка: у мемов «доставка неизвестна · запись … · id сообщения нет», у
  текста «ещё не доставлял» — строки различаются;
* ответ чужого чата: карточки пустые, шапка без снимка, на экране объяснение
  «Диагностика пришла для другого чата и отброшена — обновите экран».

## Измерения

`live-measure.json` (Playwright, живые размеры, режим «кулдаун»):
оба вьюпорта `hScroll=0`, ни одно значение оси не обрезано
(`clip=false`), `right ≤ vw`, JS-ошибок нет.

`playwright-e2e.json` — прогон `tests/ui_initiative_rework_e2e.py`:
все проверки осей/адаптива проходят; остаются два ПРЕДСУЩЕСТВУЮЩИХ отказа,
воспроизведённых на неизменённой базе `4c59a483` («после снятия override
источник не „Исходный из кода“» — карточка версий промптов на вкладке «Мемы»).

## Принятые пробелы

* Квота мемов по-прежнему берётся из настроек чата (`memeSettingsView`) и
  показывает `reset` в ISO-виде — это существующая формулировка вне пяти осей,
  не менялась в этом срезе.
* Пояс чата в тестовом стенде не задан (в стабах `/api/config` пусто),
  поэтому снимки показывают честный UTC; в проде пояс читается из
  `limits.chat_timezone`.
* Живой снимок двух реальных чатов (READ_ONLY) и трасса `S4-TRACE` — вне этого
  среза.
