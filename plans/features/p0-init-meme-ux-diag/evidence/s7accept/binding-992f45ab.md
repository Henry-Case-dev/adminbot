## 2. Что матрица закрывает и чего она НЕ закрывает внутри заявленных строк

Заявка строки возможна только при всех `passed` проверках строки (правило `row_claims`), но заявка строки ≠
полное acceptance строки. Ниже — остаток по каждой строке; он и определил статус `REVIEW`, а не `VERIFIED`.

| Строка | Закрыто проверками | **НЕ закрыто этой матрицей (остаток строки)** |
|---|---|---|
| `P0IM-AC-MATRIX-CONFIG` (12) | слои чата/общего/заводского, `enabled=false`/`null`, «разрешено ВКЛ + waiting» на шести ожиданиях, живой payload двух боевых чатов | «100% вероятности, когда жребий не нужен»; «отсутствие повода у L1» |
| `P0IM-AC-MATRIX-FAIL` (5) | провайдерное исключение с этапом остановки, отсутствие строки, три состояния доставки, незнакомый код, реальный `message_id` доставки | ранние гейты без `job_id`; обрыв после LLM A/B; пустое изображение; конфликт отправок; старые неполные записи |
| `P0IM-AC-MATRIX-RBAC` (2) | не-админ 403, без чата 422, ответ админа не смешивает чаты | полная трасса без утечки секретов; конкурирующие чаты/держатели брони |
| `P0IM-AC-MATRIX-UI` (4) | рендеры отданной сборки на двух чатах в 1536×960 и 390×844, отсутствие прокрутки и обрезки, гонка scope (2.4 с), контрпример «чужой `chat_id` + истёкший маркер» | собственные контрпримеры Reviewer под это изменение UI |
| `P0IM-AC-POSTREL` (1) | послерелизные снимки двух чатов со штампом версии и сверкой SHA, строка доставки, счётчики/квота, раскрытая трасса | продуктовый вердикт независимого Reviewer по выложенному релизу (живой Telegram-клиент устройства — ограничение среды, не acceptance) |

Матрица **не заявляет**: `P0IM-AC-MATRIX-MANUAL` (нужен живой ручной `/meme` при исчерпанной квоте и истечение
`manual_priority_until` на проде) и `P0IM-AC-DONE` (агрегат собирается по всем срезам).
Единственная живая проверка в состоянии `not_yet` — `AC-LIVE-DEFERRED-CHAIN`; её обязательство записано один раз
в `waiting_observations[] → WO-258194-S5B-DEFERRED` (триггер и точные поля не менялись).

## 3. Что изменилось в карте от этой привязки

**Повышено до `VERIFIED`** — `P0IM-S5B-DELIVERY-FACT`: его acceptance требует, чтобы факт доставки был отделён
от факта попытки (`last_delivery` = «не доставлено» с точным кодом причины, а не пустота и не «опубликовано»;
число изображений и подтверждённых отправок различаются). Первая половина наблюдалась живьём на 2.58.194
(`not_delivered=1`, причина `publisher_not_bound`, экран «израсходовано без отправки: 1 (отправитель не привязан
в этом процессе)»), вторая — теперь тоже живьём: доставленная попытка несёт отдельную строку вывода
(`ledger_id 1620`, `tg_message_id 11107`) и `last_delivery.confirmed` с тем же `message_id`, а счётчики
(`spent 3 / delivered 2 / not_delivered 1`) считаются раздельно. Порядок «поздний отказ не перезаписывает
подтверждённую отправку» остаётся доказанным на кандидате — на живых данных обратного порядка не было.

**Остались `READY_FOR_LIVE`** — `P0IM-S5B-NODISCARD`, `P0IM-S5B-QUOTA`: их живая половина — именно
`publisher_not_bound → отложено → доставлено`, этого тика не было (в снимке 2 отложенные строки, обе
`claim_held`, созданы до выкладки).

**Остались `REVIEW`** — `P0IM-MM-*`: живой половине нужен ручной `/meme` (после выкладки `attempt_mode=manual`
не было ни одного), а не факт доставки. Живой `message_id` их не закрывает; в частности `P0IM-MM-PRIO`
по-прежнему ждёт снятия маркера на терминале нового кода.

**Закрыто наблюдение** `WO-258193-MEME-DELIVERED-ID` (триггер «сброс квоты 2026-11-12T00:00:00Z + следующая
автономная публикация» наступил в 00:34:19Z, доставка несёт `publication` с непустым `output.tg_message_id`,
id совпал с `last_delivery.message_id` и с `mca_bot_outputs`). Закрыт ровно этот долг: `P0IM-MM-PRIO` в части
ручного маркера и `P0IM-AX-DELIVERY` (уже `VERIFIED`) не переоткрываются и не переоцениваются.

## 4. Границы, зафиксированные при привязке

- Реальный Telegram-клиент (настоящий TMA-хост на устройстве) матрицей не проверялся: UI снят Chromium с
  мобильным вьюпортом против отданной страницы с реальным `initData`. Это ограничение среды, а не действие владельца.
- Живой ручной `/meme` при исчерпанной квоте не выполнялся: исполнять команду от имени владельца запрещено,
  а чужой ручной запуск не воспроизводим. Строка `P0IM-AC-MATRIX-MANUAL` остаётся `PENDING`.
- Истечение `manual_priority_until` на живой автоматической попытке 00:34Z видно: `manual_priority_until
  1794403592` истёк, публикация прошла с `manual=false` и без ожидания по маркеру. Это не заменяет ручную
  половину строки.
- Контрпримеры Reviewer под последующие изменения UI — постоянное обязательство ревью, а не одноразовое
  доказательство; в матрице их нет по построению.
