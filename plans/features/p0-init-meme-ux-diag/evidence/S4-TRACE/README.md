# S4-TRACE — «Публикации» и «Диагностика»: одна попытка, связная трасса

Срез: `S4-TRACE` эпика `p0-init-meme-ux-diag`. Ветка `init/meme-axes`,
база прод-релиза `c087253d` (2.58.188). Строки контракта: `P0IM-PB-ROW`,
`P0IM-PB-TRACE`, `P0IM-PB-LLM` (`requirements-map.json`).

Ни новой секции, ни нового эндпоинта, ни нового хранилища: обе поверхности уже
существовали, ответы — те же два маршрута (`/api/initiative/publications` и
`/api/initiative/publications/detail`), в них добавлены только окно и счётчики
воронки плюс компактные стадии строки.

## Строка попытки (`P0IM-PB-ROW`)

Одна строка = одна попытка. Показывает: время, механизм, **run id и чат**
(`job-77 · Чат A`), режим (`авто` / `ручной /meme` / «способ не записан»),
последовательность **реальных стадий** (`Выжимка → Генерация прикола →
Генерация картинки → Публикация`, с `✕`/`⊘` у упавшего/пропущенного шага),
причину, исход и признак доставки. Ошибка названа отдельной строкой:
`ошибка на шаге «Прикол (LLM B)»`. Историческая строка без родителя помечена
`историческая запись без идентификатора`, run id показывается как
`без идентификатора` — не выдуманный ключ.

Счётчики называют окно и не схлопываются:
`за 7 дн.: проверено 2 · решено 2 · опубликовано 2 · доставлено 2 · ожидает 0`
(+ `без подтверждения N`), с пометкой «категории вложенные, не слагаются».
`window.days/since/until` приходят с сервера; «всё время» — отдельное окно.

Фильтры — этой же поверхности: чат (переключает ТУ ЖЕ область, что и шапка),
тип, режим, исход, причина, период; всё серверное, только существующие
параметры эндпоинта.

## Трасса шагов (`P0IM-PB-TRACE`)

Фиксированный словарь на механизм/режим:

* ручной мем (`mode=manual`, из терминальной записи): получение команды →
  проверка прав → обработка команды → приоритет `/meme` → обязательные гейты →
  чтение сообщений → выжимка (LLM A) → прикол (LLM B) → запрос картинки →
  бронь публикации → отправка в Telegram → видимый результат;
* автоматический мем: триггер → гейты → чтение сообщений → выжимка → прикол →
  картинка → бронь → отправка → результат (без `/meme`-шагов);
* текстовая инициатива: оценка повода → условия и гейты → контекст и окно →
  решение (LLM) → отправка и перепроверка → видимый результат (без «Прикол» и
  «Картинки»).

Каждый шаг — одно из состояний: `выполнено` (с меткой времени записи),
`ошибка`, `пропущено`, `не выполнялось`, `нет данных`, `по косвенному факту`.
«По косвенному факту» подписывает вывод из соседних записей (например «гейты
пройдены: попытка дошла до следующих этапов»), а не читаемую строку — так и
написано. Место остановки: `остановилось на шаге «Прикол (LLM B)»: генерация
прикола не удалась`; неизвестный код → `код: brand_new_gate` без выдуманного
шага, `этап остановки не определён`.

Попытка без единой строки: `Попытка не запускалась: в журнале нет ни одной её
записи.` и все шаги `не выполнялось` (вид механизма берётся из `meme:`/`text:`
идентификатора, а не угадывается).

## Данные провайдера и промптов (`P0IM-PB-LLM`)

В шагах показывается то, что реально записано: источник промпта выжимки и её
длина; предел прикола, факт обрезки, источник, **манифест сборки, system sha12 и
ревизии Core/Identity/Expression/Style Policy/Humor**; длина итогового
image-промпта, источник и ревизия шаблона, число символов из прикола; факт
ответа image API (`bytes`); `message_id` и запись журнала выводов.
Там, где запись отсутствует, прямо написано `модель не записана`, `текст
промпта и ответа исторически не сохранялся` — согласно `architecture.md` §5:
полный текст промптов не начинает сохраняться.

## Правки после ревью на `430703be` (четыре дефекта)

Ни новой секции, ни нового эндпоинта/флага/хранилища: исправлены чтение уже
существующих данных и тексты на уже существующих поверхностях.

1. **Отсутствие факта этапа ≠ «не выполнялось».** Если более поздний шаг имеет
   реальные факты (промпт картинки, `image_ready`, бронь, отправка, строка
   публикации), шаг без своей записи читается как «по косвенному факту» или
   «нет данных» с причиной. Тот же признак применён к шагам «Картинка» и
   «Бронь» (один класс дефекта).
   * до: `Прикол (LLM B) — не выполнялось — до прикола не дошло`
     (при этом «Запрос картинки — выполнено, промпт 20 символов»);
   * после: `Прикол (LLM B) — по косвенному факту — прикол был: из него собран
     промпт картинки (7 симв.)` + `текст прикола и модель исторически не
     сохранялись`; без косвенного признака — `нет данных — записи этапа нет, но
     попытка дошла до следующего шага`.
2. **Неизвестный код не выбирает шаг остановки.** Место остановки по
   терминальному этапу берётся только когда кода причины нет вовсе; при
   неизвестном коде — `этап остановки не определён`, читаемая подпись остаётся.
   * до: `остановилось на шаге «Прикол (LLM B)»: код: zz_not_in_any_dict`;
   * после: `автоматическая попытка · остановилась: код: brand_new_gate,
     этап остановки не определён`.
3. **Журнал: чужой чат, чужое окно, отсутствие счётчиков.** Ответ применяется
   только к тому чату и тем фильтрам, для которых он запрошен; подпись окна
   берётся из серверного `window`; отсутствие счётчиков — «нет данных», не нули.
   * до (поздний ответ на 7 дней при фильтре «30»): `за 30 дн.: проверено 10 ·
     решено 10 · опубликовано 2 · …`;
   * после: `за 7 дн.: проверено 10 · решено 10 · опубликовано 2 · доставлено 3
     · ожидает 1 · без подтверждения 2`;
   * до (ответ чужого чата): строки и числа другого чата молча подменяли журнал;
   * после: `0` строк, `Ответ пришёл для другого чата и отброшен — обновите
     журнал`, `нет данных: счётчики не пришли`;
   * до (нет счётчиков): `за 7 дн.: проверено 0 · решено 0 · опубликовано 0 …`;
   * после: `нет данных: счётчики не пришли` (и «нет данных» по каждому
     отсутствующему полю).
4. **В свёрнутой строке — только читаемый текст.** Голый `reason_code` убран из
   строки списка; код причины виден лишь в раскрытой трассе рядом с `код: …`.
   * до: `публикацию отложил конфликт с другим механизмом · в цепочке: код:
     publication_deferred_conflict`;
   * после: `публикацию отложил конфликт с другим механизмом` (код
     `publication_deferred_conflict` — в событиях раскрытой детали).

## Правки после второго ревью (сырые токены в свёрнутой строке + живой замер)

Сервер иногда присылает КОД в `reason_label`, а имена незнакомых событий — в
`other_events`. Плюс этап текстовой попытки печатался английским слагом.
В свёрнутой строке теперь только человеческий текст; коды и сырые имена видны
исключительно в раскрытой трассе рядом с `код: …`.

| Случай | было (свёрнутая строка) | стало |
|---|---|---|
| `reason_label` = код `zz_raw_code` | `zz_raw_code` | `причина не расшифрована (код — в трассе)` |
| `reason_label` = машинный токен, `other_events` | `publication_pending · pending` | `без причины` / читаемая подпись; сырое имя — в раскрытой трассе |
| этап текстовой попытки `claim` | `claim` | `захват брони` |

## Принятые пробелы

* Проверка прав **на входе команды** и удаление сообщения команды пишутся только
  в debug-лог: в журнале попытки их нет, поэтому шаги честно показывают
  «нет данных» (а не выдуманное «выполнено»).
* Старт стадии картинки не пишет отдельного INFO-маркера: время шага берётся из
  строки этапа/события `image_ready`, а для убитого процесса записи нет вовсе —
  такая попытка читается как «не запускалась» (R0-случай `/meme` 11.11.2026).
* Полные тексты промптов/ответов исторически не сохраняются (решение
  `architecture.md` §5): показываются ревизии, манифест, длины и источники.
