## Fix

1. **Separate state model.** `web/app.js` now derives:
   - selected primary from `primary_setting_raw` / `primary_setting_state`
     (absent → factory IBM; invalid → `requires_resolution`);
   - effective provider from `effective_provider` / `resolved_primary`;
   - saved fallback order from `fallback_order_raw` / `fallback_order_state`
     (`null` = absent, `[]` = real saved empty, invalid = requires_resolution);
   - factory order IBM→ANU→LfDR (display only) and the full
     `effective_order` chain from runtime diagnostics.
   Live `[]` with inherited primary is labelled
   «сохранён пустой; действует заводская цепочка»; it is not rendered as an
   empty/disabled reserve.
2. **No false badge.** `randomFallbackRows()` unions every provider in the
   effective fallback chain into the displayed reserve. «не в резерве» is
   impossible for a provider in the effective chain; excluded providers alone
   receive that badge.
3. **Explicit edit.** Toggle/up/down change only `randomFallbackDraft`; no POST.
   Editor starts from saved/effective/factory chain, so enabling ANU from the
   old false-empty state keeps LfDR. «Сохранить» posts the full proposed order;
   «Отмена» discards the draft. Invalid primary/order initializes the editor from
   the effective chain, not from the invalid saved string.
4. **Provider state vs key presence.** Five provider states are exposed
   separately: `adapter_not_implemented` (IBM P5), `unconfigured`,
   `unavailable`, `saved_unverified`, `checked`. Key presence alone is
   `badge-info`, never «проверено»/`badge-ok`.
5. **Mobile preservation.** Added `min-w-0` to QRNG cards and changed fallback
   rows to wrap label/status within the available width. No horizontal overflow
   at 320/390; desktop block unchanged in structure.
