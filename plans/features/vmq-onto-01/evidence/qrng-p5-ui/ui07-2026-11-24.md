## Implemented behavior

1. **Compact summary** above the existing cards: one adaptive grid with the
   three providers in canonical order IBM → ANU → LfDR. Each row shows:
   - factual provider state from the existing `providers[].state` /
     `configured` (`adapter_not_implemented`, `unconfigured`, `unavailable`,
     `saved_unverified`, `checked`, `disabled`);
   - consumable reserve from `providers[].reserve` / `consumable` and
     quarantined count; missing data is «нет данных», never a fabricated `0`;
   - last successful receipt from durable `last_batch` (provider + `created_at`
     + length + `config_matches`), or the provider's own last successful
     fetch/check (`last_success_at`) explicitly labelled as a check;
   - last switch reason code + Russian label. Derivation is deliberately
     conservative (see below);
   - IBM remains `adapter_not_implemented` until P5B, with no invented
     reserve or green state.
2. **Global line** «Последнее переключение» from
   `last_fallback_reason` / `last_fallback_at`; unknown codes render as the
   raw code + «причина не описана», with no invented translation.
3. **Secrets/details** stay in the existing provider cards, now wrapped in a
   `<details data-random-provider-details>` closed by default. The compact
   summary contains no key/CRN/fingerprint/diagnostic fields and no
   secret-field inputs.
4. **Mobile/history:** the grid uses `repeat(auto-fit, minmax(220px, 1fr))`;
   the existing detailed cards, settings, history and DTO compatibility are
   preserved. No new network call on page open or details expansion.

### Switch-reason attribution (important honesty boundary)

The existing `/api/status.random` DTO does **not** contain a per-provider
historical switch record. A draw row's `provider` is the provider that
actually produced the draw (`python-random` for a PRNG fallback), not the
provider whose failure caused the switch. The UI therefore does **not** use
`recent_draws[].fallback_reason` for per-provider attribution (the test
contains a deliberate non-realistic draw row to prevent that regression).

Current sources used:

| Provider | Source | Meaning |
|---|---|---|
| IBM | card state `adapter_not_implemented` | adapter absence; no switch timestamp |
| LfDR | `providers[lfdr].last_error` + `last_failure_at` | last LfDR health error (in-memory) |
| ANU | `last_fallback_reason` + `last_fallback_at`, only when ANU state is `degraded` / `quota_exhausted` / `provider_unconfigured` / `provider_unavailable` / `disabled` | `mca_random_state` is ANU-scoped and `anu_state()` is derived from this reason |
| ANU/LfDR fallback | `random.blocker` + `resolved_primary` when no provider-specific historical reason exists | current selection blocker, attributed only to `resolved_primary`; no invented historical time |

If an independent per-provider historical switch record is required beyond
this, it needs a separate read-only DTO contract; no backend field was invented
here.

## Remaining / RFL

- **RFL-UI07-1:** per-provider *historical* switch attribution is limited by
  the existing DTO (see table). The UI shows only attributable sources and
  «нет данных» otherwise; it does not use the draw journal as a false
  per-provider source. A separate read-only DTO field is needed if a full
  per-provider switch history is required.
- **RFL-UI07-2:** LfDR `last_success_at`/`last_error` are in-memory health and
  reset on restart; they are labelled as a check, not a durable batch.
- **RFL-UI07-3:** IBM real adapter/check/job/usage states remain P5B; this
