## 1g. Architect 988e6af34 — narrow IBM state machine

- **Live owner:** `status=running` + свежий `heartbeat_at` + захваченный `fencing_token`. Recovery не трогает такую строку. Любая non-live строка сначала атомарно переводится в `interrupted` с `fencing_token+1`; `interrupted` тоже клеймится через token+1 (cross-process CAS). `_ibm_recovering`/`_ibm_recovering_rows` — process-local singleflight, не authority.
- **S1:** после `mark_running` durable cursor `prepared` + `config_fp`; если checkpoint не применён — submit не начинается, строка закрывается `abandoned_before_submit`.
- **S2:** cursor `submitting` + `submit_started_at` + `job_tag` непосредственно перед `sampler.run`; false/error checkpoint → abort. После S2 и непосредственно перед submit — повторная lease-проверка status/token; takeover в этом окне даёт `claim_revoked`, `sampler.run` не вызывается.
- **Bounds:** `prepared` закрывается сразу `abandoned_before_submit`; S2/legacy/no-cursor остаются non-terminal до `submit_bound = max(deadline_at, submit_started_at+job_max_age, created_at+job_max_age)`, затем один `submit_uncertain`; positive-absent tag не закрывается сразу. Известный job ID не poll'ится после `2×job_max_age` (кроме cursor `completed`, где результат уже известен и требует ровно одного deposit).
- **Settlement:** одна module-level `_ibm_settle_job` (`_settle_ibm_row`/`_settle_ibm_job` делегируют) — finish + cursor + terminal release; все записи условны по token; cursor сохраняется до finish, чтобы `result_ref` не затирался служебным `processed`. Live `_finish_claim` удалён.
- **Rotation:** guard перед resume/deposit/finish сверяет `interrupted`, token, `quarantined`, `config_fp`, job ID; старый late result не зачисляется и не смешивается с новым key/CRN. `resume` сохраняет captured `config_fp`, не подставляет текущий.
- **Exactly-once deposit** сохранён: `ibm_<sha256(job_id)[:32]>`.
- **Тесты (T1–T6):** transient tag → unresolved/no sampler; positive-absent → hold до bound, затем `submit_uncertain`; batch tri-state `unknown` → unresolved; live fresh skip; stale takeover; restart S2 по tag → attach/completed без submit; rotation before resume / during result → quarantine/no deposit; takeover между S2 и submit → `claim_revoked`, sampler 0; stale token → settlement/checkpoint rejected; ancient job → no IBM poll (`job_horizon_exceeded`), ancient queued → `submit_uncertain`; ancient completed + существующий batch → completed без attach/дубля; S1/S2 barrier failures → row `abandoned_before_submit`, sampler 0.
- **DDL/миграций нет**; задействованы существующие `task_jobs`/`payload.cursor`/`fencing_token`/`batch_id`.
