## Что стало (основной экран)

Одна карточка, две колонки на desktop и стек на mobile:

1. **Управление**
   - один `select` «Основной источник» — его значение и есть сохранённое или
     заводское значение; подпись только «По умолчанию» / «Выбрано вручную» /
     предупреждение о недействительном сохранённом значении;
   - один тумблер «Автоматическое резервирование» + короткая provenance
     («наследуется по умолчанию» / «выбрана» / «выключена»);
   - **одна** последовательность резервных источников: чекбоксы, ↑/↓, явные
     «Сохранить»/«Отмена» только при черновике; статус-бейдж
     `по умолчанию` / `сохранено вручную` / `сохранено пустым` /
     `резерв отключён` / `не применяется`;
   - короткое пояснение только для неоднозначных состояний.
2. **Снимок runtime**
   - «Сейчас используется»: фактический источник + человеческая причина
     переключения + время (последнее переключение);
   - компактная таблица трёх провайдеров: имя, `используется` (только
     фактический), состояние подключения (`проверено` / `не проверено` /
     `не настроен` / `недоступен` / `нет данных`), доступный запас;
   - одно «Последнее успешное получение».

Разрешённый, проверенный и фактически используемый источники теперь разные
признаки: ANU — `используется` + `проверено`; LfDR — разрешён в
последовательности, но `не проверено`; IBM с сохранённым ключом, но без
проверки — `не проверено`, не зелёный и не «используется».

## Явное решение vs заводская цепочка

- Наследование: строки `random.fallback_order` нет → показан заводской порядок,
  бейдж `по умолчанию`, тумблер `включено` + «наследуется по умолчанию».
- Намеренное отключение: `fallback_enabled=false` → бейдж `резерв отключён`,
  пояснение «отключён вручную: переключения не будет»; заводская цепочка не
  выдаётся за действующую.
- Сохранённый пустой резерв: бейдж `сохранено пустым`, строки **не** выглядят
  выбранными пользователем. Если основной источник наследуется, backend всё
  ещё строит заводскую цепочку; это явно написано в пояснении («сейчас
  действует заводская цепочка; отметьте источники и сохраните…»). При явном
  основном источнике пустой резерв означает «переключений не будет».
- Runtime-использование разрешённого, но не отмеченного пользователем
  источника показывается отдельным бейджем `в цепочке`, а не подменяет
  сохранённое решение.

Backend-семантика `build_effective_order` не изменялась (запрет задачи);
поэтому единственное ограничение — объяснение заводской цепочки при
наследуемом primary и сохранённом пустом резерве.

## Остаточные ограничения (честно)

1. **RFL-UI08-1:** mock-DTO, не production `/api/status` (нужен Telegram
   initData). Live-проверка — Reviewer/release.
2. **RFL-UI08-2:** backend при наследуемом primary и сохранённом пустом
   резерве продолжает строить заводскую цепочку; UI показывает это явно, но
   не переписывает backend-семантику (запрет задачи). Полное устранение
   потребовало бы изменения fallback-контракта.
3. **RFL-UI08-3:** в mock IBM имеет сохранённый key/CRN, но provider state =
   `unconfigured`, поэтому основной экран показывает `не проверено`, а не
   `не настроен`. Это соответствует UI-правилу «наличие ключа ≠ проверка»;
   live-состояние берётся из `/api/status` и check/smoke.
4. **RFL-UI08-4:** общая шапка модуля сохраняет master-тумблер «Весь бот» и
   чатовый tri-state — это функциональные контролы модуля, не конфигурация
   источника; они не удалялись, чтобы не ломать контракт workspace.
5. **RFL-UI08-5:** старый `tools/ui_qrng_p4_e2e.py` остаётся устаревшим
   (`RFL-UI06-R1-03`), в гейты не входит; новый гейт — `ui_qrng_ux0810_e2e.py`.
6. Визуальный стиль админки сохранён (карточки, badges, 11.5 px badges,
   glass/shell не менялись); новых карточек нет — число основных карточек
   уменьшено.
