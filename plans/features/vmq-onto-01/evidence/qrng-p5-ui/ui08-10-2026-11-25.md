- Absent-тесты покрывают primary IBM/ANU/LFDR + mixed duplicate effective;

## Что стало (основной экран)

Одна карточка, две колонки на desktop и стек на mobile:

1. **Управление**
   - один `select` «Основной источник» — его значение и есть сохранённое или
     заводское значение; подпись только «По умолчанию» / «Выбрано вручную» /
     предупреждение о недействительном сохранённом значении;
   - один тумблер «Автоматическое резервирование» + короткая provenance
     («наследуется по умолчанию» / «выбрана» / «выключена»);
   - **одна** последовательность резервных источников: чекбоксы, ↑/↓, явные
     «Сохранить»/«Отмена» только при черновике; статус-бейдж
     `по умолчанию` / `сохранено вручную` / `сохранено пустым` /
     `резерв отключён` / `не применяется`;
   - короткое пояснение только для неоднозначных состояний.
2. **Снимок runtime**
   - «Сейчас используется»: фактический источник + человеческая причина
     переключения + время (последнее переключение);
   - компактная таблица трёх провайдеров: имя, `используется` (только
     фактический), состояние подключения (`проверено` / `не проверено` /
     `не настроен` / `недоступен` / `нет данных`), доступный запас;
   - одно «Последнее успешное получение».

Разрешённый, проверенный и фактически используемый источники теперь разные
признаки: ANU — `используется` + `проверено`; LfDR — разрешён в
последовательности, но `не проверено`; IBM с сохранённым ключом, но без
проверки — `не проверено`, не зелёный и не «используется».

## Явное решение vs заводская цепочка (R1/F-01)

- Наследование (строки `random.fallback_order` нет): показан заводской порядок,
  бейдж `по умолчанию`, тумблер `включено` + «наследуется по умолчанию».
- Намеренное отключение: `fallback_enabled=false` → бейдж `резерв отключён`,
  пояснение «отключён вручную: переключения не будет»; заводская цепочка не
  выдаётся за действующую.
- **Явный непустой сохранённый порядок при наследуемом primary теперь
  действует.** `build_effective_order(None, saved_order, True)` строит голову
  из заводского primary (IBM) и хвост из сохранённого порядка, а не из
  канонической цепочки. UI показывает тот же порядок в последовательности и в
  «Сейчас используется»; `savedLabel` и `effectiveLabel` совпадают.
- **Явный пустой сохранённый резерв теперь означает «без резерва» и при
  наследуемом primary** (backend больше не подставляет заводскую цепочку).
  Бейдж `сохранено пустым`, строки не выбраны, статус `не в резерве`,
  пояснение «Сохранён пустой резерв: переключений не будет.».
- Защита от расхождения (R2-01 → R3-01, тотальная и каноническая):
  `randomFallbackCanonical(order, primary)` — единственный нормализатор обеих
  сторон: фильтрует текущий primary, невалидные id и дубли, сохраняет порядок,
  missing/absent приводит к сравнимой форме. `randomFallbackComparison()`
  сравнивает канонические `selection` и `effective`; бейдж
  `сохранено, не применяется` появляется только при их реальном различии —
  включая `[] ↔ непустой` в обе стороны, несовпадение порядка, old/mixed DTO
  и `state=absent` при доступном primary IBM/ANU/LFDR. Мёртвый `savedHint` и
  устаревшая подпись «действует заводская цепочка» удалены (R2-02).

Отдельного изменения режима/флага при сохранении не требуется: применяется
существующий `random.fallback_order`, backend-семантика исправлена в рамках
того же контракта. P3-тест до фикса падал
(`effective_order == ('ibm_quantum','anu','lfdr')` вместо сохранённого
`('ibm_quantum','lfdr','anu')`).

## Провайдеры: один источник истины (R1/F-02)

- «Сейчас используется» и таблица используют общий `randomMainEffectiveProvider()`.
  Если DTO одновременно заявляет `effective=X` и `X` со state
  `unconfigured/unavailable/disabled`, X не показывается используемым:
  «используется» и «не настроен/недоступен» в одной строке невозможны.
- Причина fallback больше не висит без субъекта: при переключении с основного
  источника показывается «переключение с IBM Quantum: источник не настроен».
  Это причина переключения, а не состояние фактического ANU.
- `error` у провайдера на основном экране переводится как «ошибка
  подключения»; стадия (`instance/CRN`, `ключ`, …) остаётся в «Ключах» и
  «Диагностике» (F-03).
- Дублирующийся маркер `data-random-setting-primary` разделён:
  основной экран — `data-random-setting-primary`, диагностика —
  `data-random-setting-primary-raw` (F-05).

## Остаточные ограничения (честно)

1. **RFL-UI08-1:** mock-DTO, не production `/api/status` (нужен Telegram
   initData). Live-проверка — Reviewer/release.
