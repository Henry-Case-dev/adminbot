# Решение: канал периодного добора для событийного класса (VMQ-MEM-TIME)

База: `vmq/time-bias` @ `31991b6f` (линия прода 2.58.181 от `92070d0e`), read-only. Правило владельца: `plans/owner_inputs/2026-11-10-vmq-time-refinement.md` §11, §17, §21, §30, §35. Проверенный симптом: при `history_import`-факте 3223 (31.12.2023, confirmed) добор `_RAG_PERIOD_CHANNELS = ("lexical",)` (`direct_chat_service.py:12275`) находит его только для префикса «колбас*».

## 1. `vector` в периодном доборе — ОТКЛОНЁН (технически невозможен без перестройки индекса)
- Ограничить KNN старым периодом **нельзя на индексе**: `graph_facts_vec` — `vec0(embedding, +fact_id, +chat_id, +origin, +expires_at)` (`summary_memory.py:118-122`), года в aux-колонках нет; sqlite-vec 0.1.9 **не принимает** фильтр по aux-колонке в KNN (документированная проба «illegal WHERE constraint … auxiliary column», `summary_memory.py:124-134`). Pre-filter потребовал бы DDL-миграции vec-таблицы и перезалива векторов — запрещено (нет перестройки эмбеддингов, нет новой системы памяти).
- Остаётся post-filter после overfetch, но потребитель режет результат до `limit` ДО любого фильтра (`_rag_rows_from_result`, `direct_chat_service.py:12392-12408`) ⇒ фильтровать по году нечего. Обход = подать в фильтр 200–500 строк и вынести отбор из этого метода — это больше правок, чем весь выбранный вариант.
- Качество: в замере top10/top50 векторного канала — только 2026, т.е. факт 3223 вне семантической окрестности вопроса. Добор «старый срез post-filter» вернул бы **ближайшие старые** строки, а не релевантные: тематически похожая история 2023 подменила бы текущее состояние. Доказательства достижимости именно 3223 нет — принимать по вере нельзя.
- Цена: +1 KNN-стадия (staged overfetch k до `_KNN_SCOPE_K_CAP=512`, `summary_memory.py:6743-6797`) + `get_graph_fact_records` на весь набор на БД 2 ГБ на каждый вопрос. Не оправдано нулевой доказанной отдачей.
Итог: если бы вариант применялся, период задавался бы только post-filter'ом по году с капом `period_slots`; в этом виде он **не принимается**.

## 2. Лексическая морфология — ВЫБРАН (минимальный набор правок)
Что уже есть в репозитории: единственный FTS-сборщик `build_fts_query` — prefix-OR `"kw1"* OR "kw2"*` (`summary_memory.py:1763-1796`, явно «unicode61 без стемминга»); детерминированная «лёгкая морфология без зависимостей» `term_key` с таблицами `_RU_SUFFIXES`/`_EN_SUFFIXES` (`search_aggregator.py:160-199`); FTS-уровня морфологии нет нигде (в `chat_statistics`/`tool_router` префикс явно назван «НЕ морфология»). Библиотека-стеммер не нужна.
Правки (4 файла, ~12 строк):
1. `search_aggregator.stem_word(word)` — снятие словоизменения по **существующим** таблицам суффиксов, без 6-символьного клипа `term_key`, минимум 4 символа основы; `term_key` не меняется (его клип — контракт сравнения в factcheck).
2. `build_fts_query(..., mode="prefix_or_stem")` — прежние префиксы **плюс** префикс основы; режим аддитивный, как прежние MCA-15-режимы, дефолт прежний.
3. `mca_retrieval_context.RetrievalRequest.lexical_stem: bool = False` и одна ветка на `:1459` (этот `match` используется только лексическим каналом, `:1604-1629`); все прочие потребители `retrieve` — байт-паритет.
4. `_rag_retrieve(..., lexical_stem=True, include_archived=policy in ("historical","auto"))` для периодного вызова (`direct_chat_service.py:12359-12361`). `include_archived` обязателен: лексический канал зовёт `search_graph_facts_fts` с `include_archived=False` (`:11190-11191`), поэтому вытесненные квотой `archived_fact` 2023 в добор не попадают вовсе. `_RAG_PERIOD_CHANNELS` остаётся `("lexical",)`, `operative` не меняется, словарных триггеров года нет — основа обычного слова, не список лет.
Цена: recall — падежные/числовые формы одного слова («колбасой/колбаску/колбаса» → «колбас*»), чего достаточно для 3223 (rank 2 по этому префиксу). Не покрывает другую основу, синоним, опечатку. Precision — префикс ловит однокоренное («колбасный»); шум ограничен бюджетом добора и правилом «только год, которого в срезе нет».

## 3. Комбинация не требуется; почему добор не превращается в наводнение
Потолок `limit // 5` = 2 строки в `historical`, 1 в `auto` (`:12339`, `:12352`); берутся только годы, отсутствующие в срезе (`:12433-12435`); self-origin исключён (`:12431`); порядок — FTS-rank, т.е. лучший лексический матч на каждый недостающий год; строки помечаются `period_fill` и не отбрасываются реранком (`:2662-2673`, `:12615-12631`). Названная хрупкость (не меняется этой правкой): гейт `auto` `usable ≥ limit//2` (`:12347-12351`) при срезе 4 строк выключает добор целиком — замер обязан печатать `usable` и `policy`.

## 4. Обязательный замер (прод-конфигурация) и условие прохождения
Read-only копия прод-БД (схема 47, чат `-1002661910336`), код кандидата, **эффективные прод-значения** зафиксированы в артефакте (`flags.chat_rag_rerank_enabled=true`, `flags.graph_rag_enabled`, `limits.graph_rag_facts_limit=10`, `flags.graph_mmr_enabled`, `limits.graph_mmr_fetch_k_historical`), путь — не `retrieve()`, а `_rag_unified_rows → _build_rag_block` с реранком ON, финальная строка `<RAG_Memory>`; событие `mca07_retrieval` само по себе блок не доказывает (эмитится на каждый `retrieve`, до реранка).
Прохождение (событийный класс, VMQ-TIME-03 + known-answer): под `historical` **и** `auto` в финальном блоке присутствует строка факта 3223 с меткой года (31.12.2023) после реранка; 2026 сохраняет ≥ `limit − period_slots` строк; `years` в событии содержит 2023; вопрос задаётся словоформой, отличной от исходного префикса («…с колбасой»), без упоминания года. Контроль: `operative` — байт-в-байт, 0 строк `period_fill`; «что сейчас …» — 2026-доминирование, 0 периодных строк. Провал = правка не принята.

## 5. Честная приёмка VMQ-MEM-TIME
Person (уже закрыто): многолетний материал доходит до блока, строки без привязки помечены «(общий контекст чата)» + год; многолетние ФАКТЫ о НАЗВАННОМ третьем лице невозможны на этих данных (38 субъектов, ни один не покрывает 2 года; 8 927 импортированных фактов без автора и ссылки на сообщение) — названный остаток данных, не понижение правила.
Event: обычный вопрос без года доходит до материала 2023–2024 в финальном блоке, если в вопросе есть обычное слово, присутствующее в тексте старого факта/сообщения (лексический якорь), с реальным source ref и годом. **Граница:** вопросы, сформулированные целиком другими словами, этим каналом не гарантированы — семантический добор в старый срез не вводился, индексировать его нечем (§1). Ничего не объявляется VERIFIED до прогона §4.

Риск R2. Параллельность: один writer, файлы `summary_memory.py`, `search_aggregator.py`, `mca_retrieval_context.py`, `direct_chat_service.py` — SERIALIZE. Откат — снятие `lexical_stem=True` у периодного вызова (одна строка). Временных файлов не создавалось — очистка не требуется.
