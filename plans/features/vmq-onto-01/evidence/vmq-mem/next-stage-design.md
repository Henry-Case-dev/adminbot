# VMQ-MEM next stage — семантический добор старого периода

База: прод `0fed5845` (2.58.183), поведение слайса = `709865f6`. Не новый контур и не правка замороженного слайса. `ARCHITECT_ADJUSTMENT_REQUIRED` к формулировке «просто добавить vector в каналы»: общий `_search_graph_facts` режет MMR до `limit` и 2026-доминирован; фильтр после этого среза старое не достаёт.

## 1. Семантический recall в существующем доборе
Один периодный `_rag_retrieve` (второй вызов `_rag_unified_rows`, `direct_chat_service.py` ~12375). Третьего `retrieve` нет. `operative` — прежний один вызов, байт-паритет.

Аддитивно, default выкл: `RetrievalRequest.period_fill=False`, `exclude_years=()`. Периодный вызов ставит `period_fill=True`, каналы `("lexical", "vector")`, `top_k=32`, `lexical_stem=True`. `exclude_years` — годы уже лежащие в базовом срезе. Пустой набор → предикат не добавляется (`NOT IN ()` запрещён).

Векторная нога **не** идёт в `_search_graph_facts` / MMR / staged `k×4`. Рядом с `_vec_candidates` — периодная функция, только при `period_fill`:

```sql
SELECT v.rowid, v.distance
FROM (SELECT rowid, distance FROM graph_facts_vec
      WHERE embedding MATCH ? AND k = 32) v
JOIN graph_facts f ON f.id = v.rowid
WHERE f.chat_id = ?
  AND CAST(strftime('%Y', COALESCE(f.message_timestamp, f.created_at), 'unixepoch') AS INTEGER)
      NOT IN (/* exclude_years */)
```

`k=32` фиксирован, один float-`MATCH`, без int8-coarse и без чтения float-блобов. JOIN по `rowid` (= `fact_id` в проде), не `WHERE` по aux (на 0.1.9 это illegal). Фильтр **после** k: старый факт вне 32 ближайших честно не находится (`vector_pool_miss`). k=128/512 не поднимать.

Дешёвое SQL-окно — только `search_graph_facts_fts`, keyword-only `exclude_years=None` (прочие вызывающие байт-идентичны). Предикат тот же, **до** `ORDER BY rank LIMIT`. Годы — int из среза, не текст вопроса.

Пост-фильтр `rag_ts`: `_rag_append_period_rows` по-прежнему берёт год из `message_timestamp` / `created_at` / `rag_ts` и только отсутствующий в срезе. В пул 32 передаётся сам пул, не `limit` (срез `extra, limit=10` снял A8). Порядок обхода: сначала строки vector-JOIN, затем lexical. Слоты по-прежнему `limit//5`, self-origin исключён. Профиль `get_user_context_facts` не трогать.

Цена хода (`historical`, и `auto` только если `usable >= limit//2`): +1 embed запроса + 1 KNN k=32 + тот же lexical FTS с предикатом года. MMR на этой ноге нет. Оценка k=512 (~5 с, ~6 МБ) к этому пулу не относится. Потолок приёмки: p95 периодного вызова ≤ +400 мс к текущему периодному вызову на той же копии; выше — не выкатывать и не увеличивать k.

## 2. Тот же предмет, не то же слово
Лексическая строка входит, только если вопрос и текст делят **≥2** разных основы: `_TOKEN_RE` + существующий `stem_word`, длина основы ≥4. Порог 1 оставляет шум одного слова (5/18: айтишники, покупк, предпочтения, сейчас). Списка тем нет.

Векторная строка порог не проходит: иначе смысловой путь отменён. При `chat_rag_rerank_enabled=True` она уходит в тот же `rerank_rag_facts` вместе с непериодным срезом и живёт только если модель её выбрала. При `False` (прод) она входит в слот с `subject_proxy=knn` — ближайший сосед в окне, не оракул предмета.

Отказ: лексический верный факт с одной основой (шаурма, собака, витамины) не входит лексикой; vector может вернуть его, только если он внутри k=32. Ближайший старый сосед может быть не ответом — это строка гистограммы, не скрытый успех.

## 3. Пустой вердикт не гасит несудьимую историю
Вердикт применяется только к строкам, отданным в `rerank_rag_facts`. Валидный `{"selected":[]}` по непериодному срезу значит «в этом срезе нет релевантного», и эти строки не показываются. Он **не** судит лексические строки, которые в реранк не отправлялись.

Лексическая строка, прошедшая порог §2, не отправляется в реранк, переживает пустой вердикт по остальному срезу, потолок `limit//5`. Строка, порог не прошедшая, не защищается и не показывается — блок не собирается из чужого 2023 года. Векторная строка, которую модель видела, при валидном пустом выборе отбрасывается. `empty_response` / timeout / invalid — прежний fail-open, это не вердикт релевантности.

Так честность сохраняется для судимого набора, а найденная история с двумя основами не гибнет из-за молчания по другому набору (A3, A4; 7/34).

## 4. Старая строка в ответе о текущем
Наблюдаемый случай: C1 auto, 8436 (2025), единственное пересечение — «сейчас». Порог §2 её не пускает (одна основа). Отдельного словаря «сейчас» нет.

`operative` по-прежнему без добора. Под `auto` старый год входит только через §2; монополия текущего года в базовом срезе сама по себе добор не выключает — иначе исторический вопрос, оставленный L1 в `auto`, потеряет доставку. C2 может оставить старую строку, только если у неё ≥2 основы; доминирование текущего года (≥ `limit - period_slots`) не заменяется сортировкой по дате.

Наблюдаемость, без текста фактов: в существующий `direct: rag block` добавить `period_kept`, `period_rejected_subject`, `period_kept_despite_empty`, `vector_pool_miss`. В `usage_json` события retrieval — только эти счётчики и `subject_proxy`.

## 5. Приёмка
Копия прод-БД, чат `-1002661910336`, путь `_rag_unified_rows → _build_rag_block`. Те же 15 вопросов A1–A15 и якоря из `time/independent-sample-709865f6.md`, плюс C1 и C2. Не новая выборка. `mca07_retrieval` блок не доказывает.

- Доставка якоря в финальный блок ≥ 6/15 под `historical` при реранке True и при False. Доля 2026 на этих 15 не выше, чем на `709865f6`.
- Гистограмма дозаливки: по теме / тот же предмет без ответа / явно нерелевантно. База 8/18, 5/18, 5/18. Явно нерелевантных строго меньше 28 % нового набора; доля «по теме» не хуже 8/18.
- Хотя бы один из A6, A9, A13, A15 доходит vector-ногой, либо в трассе честный `vector_pool_miss`. 15/15 не требовать.
- Двойник `rerank_rag_facts` → `[]`: строка 2023–2024 с ≥2 основами остаётся. На архиве пустых блоков, где такая строка уже была в пуле, — 0. Пусто, если такой строки не было, — допустимо.
- C1 auto: 0 периодных строк. C2 auto: нет строки, не прошедшей §2; текущий год не в меньшинстве.
- Латентность: p50 и p95 `_build_rag_block` на этих 17 вопросах, до/после, реранк False и True, отдельно `knn_ms` и `fts_ms`. Пока поколение индекса `compat_not_proven`, vector-нога UNVERIFIED и ступень не принимается. +110 мс лексики заменой не является.

Прод сейчас `chat_rag_rerank_enabled=False`, выборка мерилась при True. Приёмка обязана печатать эффективный флаг. Поведение §3 и отсев vector-строк моделью в проде неактивны, пока флаг выключен; пользователю виден порог §2 и `subject_proxy=knn`. Флаг этой ступенью не переключать.

`include_archived=True` на этом архиве не срабатывал (0 archived_fact, 0 archived_belief). В описание правки это не переносить как причину эффекта.

## CORRECTION (2026-11-11)

Утверждения выше о прод-значении флага — §2 («При `False` (прод) она входит в слот с `subject_proxy=knn`») и §5 («Прод сейчас `chat_rag_rerank_enabled=False`, выборка мерилась при True») — **неверны**. Глобальная строка `flags.chat_rag_rerank_enabled` в `bot_settings` содержит `true` с `2026-09-06 14:48:01.866578+00`; переменной окружения нет, чатовых переопределений нет ни в одном из трёх чатов, реальный resolver отдаёт `True` с источником `global` и до, и после 2.58.186. Причина ошибки — поиск по имени настройки/переменной (`CHAT_RAG_RERANK_ENABLED`) и по ключу без префикса, тогда как в базе ключ хранится с префиксом `flags.`.

Что это меняет в этой ступени: реранк в проде включён, поэтому отсев vector-строк моделью и поведение §3 в проде **активны**, а не «неактивны, пока флаг выключен»; `subject_proxy=knn` — это не то, что пользователь видит сейчас. Требование приёмки «печатать эффективный флаг» остаётся в силе и теперь означает `True`/`global`; замеры «при True и при False» сохраняются как контроль обоих режимов, а не как «прод против выборки». Сам дизайн, пороги и объём ступени не пересматриваются.
