## §2. Установленные причины (file:line, зафиксировано ДО правок)

### §4 — количественное и техническое рассуждение

- C4.1 «теоретическая модель ≠ физическая реализация»: ни один слой payload
  не различает математическую оценку / теоретическую архитектуру / физическую
  реализацию / совместимость с устройством / экономику. Writer-канон ТОЧНОСТЬ
  (`services/chat_prompts.py:515-516`) - только «не выдумывай» и «не выдавай
  предположение за подтверждённый факт»; КАК ПИСАТЬ (`chat_prompts.py:519`) -
  про план и полноту. Правила L1 (`chat_prompts.py:968-996`, ред.4) различают
  «материал vs мнение» и глубину, но не типы технических вопросов.
  АНТИ-ГАЛЛЮЦИНАЦИИ tool-phase (`chat_prompts.py:294-298`) - про цифры
  статистики чата, не об инженерных размерностях. В инциденте модель читала
  вопрос о теоретическом расчёте через зафиксированное ограничение конкретной
  платы и продолжала спорить с уже снятым условием.
- C4.2 «размерности/параметры»: правила проверки размерностей (скорость линии
  × ширина интерфейса = пропускная способность; корпуса ≠ независимые каналы)
  отсутствуют во всех носителях (grep по services/chat_prompts.py,
  prompt_style_blocks.py, factcheck_prompts.py - 0). Контрольный пример §4.2
  источника (32×9600/8=38400; 448/38.4≈11.67→12) в рабочем коде/промптах
  ОТСУТСТВУЕТ (проверено) - по запрету источника он и не должен появиться;
  он используется только как тестовый сценарий.
- C4.3 «невозможность реализации ≠ невозможность принципа»: правила нет ни в
  одном носителе (grep «принцип» по канонам Direct - 0 релевантных).
  ДОСТОВЕРНОСТЬ tool-phase (`chat_prompts.py:364-365`) и ТОЧНОСТЬ Writer не
  ограничивают категорические выводы пределами установленных условий.

### §5 — решение об использовании поиска (причины несработавшего поиска)

- C5.1 доступность инструмента: `execute_web_search` входит в базовый набор
  (`services/tool_schemas.py:74`, `active_tools` `tool_schemas.py:909-955` -
  поиск не отключается ни одним флагом); capability `web_search` резолвится
  (`services/direct_capabilities.py:29`). Недоступность поиска в конкретном
  чате (ключ/модуль/квота) резолвится честно: REASON_NOT_READY
  (`direct_capabilities.py:59-61`) + вычистка tools из анонса
  (`services/direct_chat_service.py:4639-4647`). Инструмент был доступен.
- C5.2 L1 не видел необходимости внешней проверки: канон L1 НЕ УПОМИНАЕТ
  web_search ни разу (grep web_search по base/rules/секциям канона L1,
  `chat_prompts.py:577-1173` - 0). Правило 4: «capabilities_needed
  перечисляй только из доступных возможностей... если хватает разговора -
  оставь пустым» (`chat_prompts.py:847-848`, frozen-редакция R3b, входит в
  активные правила) - смещает к пустому набору, когда модель СЧИТАЕТ, что
  знает ответ. Правило 8: «запроси доступную возможность истории или
  памяти из списка выше» (`chat_prompts.py:894-899`) - для внешних данных
  называет только историю/память. Планер видит список имён «ДОСТУПНЫЕ
  ВОЗМОЖНОСТИ» (`services/direct_l1.py:857-859`, инжект
  `direct_chat_service.py:4382`, `:4416`), но семантического правила
  «характеристики современных устройств → проверка» нет ни в каноне L1,
  ни в tool-phase, ни у Writer.
- C5.3 механическое следствие C5.2: если планер не назвал web_search,
  поиск невозможен механически - `resolve_capabilities` резолвит пустой
  план в пустой анонс (`direct_chat_service.py:4610-4653`), execution_mode
  деривацией = none (`direct_l1.py:132-135`), tool-фаза не запускается
  (`direct_chat_service.py:4668-4672`). Дет. интент-детектор - НЕ источник
  поиска для таких вопросов: `detect_action_intent` поднимает
  search-интент только по явным командным маркерам «поищи/найди/загугли/
  в интернете/search» (`direct_capabilities.py:290-291`, шаг 7
  `:547-556`); вопрос «что за устройство X» маркеров не содержит - это
  корректно (детектор - для команд), но принудительной двери поиска нет.
- C5.4 фрейминг tool-phase: ИНСТРУМЕНТЫ п.3 описывает execute_web_search
  как «свежие внешние данные: новости, проверка фактов в интернете, то,
  чего нет в контексте и памяти» (`chat_prompts.py:287-292`, блок живёт
  в активном каноне через `_CHAT_W1_BASE` `chat_prompts.py:401-406`).
  «Характеристики современных устройств/новые архитектуры/спецификации
  производителей» не названы; правила «не нужен поиск на каждый технический
  вопрос» тоже нет - обе стороны §5.2 не покрыты.
- C5.5 fallback: `infer_fallback_capabilities` +
  `_FALLBACK_SEARCH_RE` (`direct_l1.py:1326-1350`) - только явные маркеры
  поиска и URL; при сбое планера поиск тоже не inferred.
- C5.6 возражение → повторная проверка: до W1 правила не было ни в одном
  носителе; W1 добавил «проверь доступными средствами» для возражений,
  опирающихся на проверяемое (`services/chat_prompts.py:1050`, секция
  intent-update). Остаточный дефект (этот срез): своевременная ИНИЦИАЦИЯ
  поиска по неподтверждённым характеристикам до первого возражения не
  покрыта (C5.2/C5.3/C5.4).
- C5.7 Writer не блокирует поиск: Writer by design без tools
  («Это этап написания текста, а не поиска...» `chat_prompts.py:505`) -
  блокировки нет, граница этапа корректна.
- Честная ремарка §5.1: данные о современных устройствах могут
  отсутствовать в знании модели и в контексте - корректное поведение
  «поиск или честное неизвестное с помеченными допущениями», а не
  уверенная галлюцинация (закрывается вместе с §6).

### §6 — уверенные технические галлюцинации

- C6.1 носители достоверности общие, без различения источников: ТОЧНОСТЬ
  Writer (`chat_prompts.py:515-516`) - «не выдумывай факты... не выдавай
  предположение за подтверждённый факт»; ДОСТОВЕРНОСТЬ tool-phase
  (`chat_prompts.py:364-365`) - «не выдумывай факты, статистику...»;
  DELTA-инструкция research-ответов (`services/prompt_style_blocks.py:
  290-291`) - «не выдавай предположения за факты»; ANALYSIS_DIRECTIVE_TEXT
  (`prompt_style_blocks.py:218-225`). НО: ни один носитель не различает
  известная информация / результат поиска / проверенный расчёт /
  разумное предположение / неподтверждённая догадка; нет правила
  «незнакомый продукт ≠ выдуманная архитектура, не заполнять пробелы
  жаргоном». В инциденте модель заполнила пробел знания о Crescent Island
  правдоподобной технической архитектурой (фотонный интерконнект/оптика/
  чиплеты) - запрета на заполнение пробелов жаргоном не было.
- C6.2 гипотезы НЕ запрещены (это правильно, §6.2): правила «откажись от
  технических рассуждений без источника» и «документ для каждой арифметики»
  отсутствуют (grep - 0). Ассошиешн-маркировка существует и переиспользуется:
  «Не выдавай предположение за подтверждённый факт» (`chat_prompts.py:516`),
  Core: «подменять проверяемое утверждение красивой догадкой по-прежнему
  нельзя» (`chat_prompts.py:1221`). Пробел: нет ПОЗИТИВНОЙ рамки «гипотеза
  допустима, если помечена как гипотеза» - инцидент показал уверенную подачу
  спекуляции как спецификации.
- C6.3 «ЕСЛИ ПОЙМАЛИ НА НЕСТЫКОВКЕ» tool-phase (`chat_prompts.py:303-304`)
  - про цифры чата в саркастичной манере; техническую спекуляцию про
  устройства не покрывает, но не противоречит ей (переиспользуется как есть).
