## 1. Что добавлено в «Стиль письма»

Раздел «Стиль письма» (`web/index.html`, `web/app.js`, `web/static/app.css`) получил
блок «Ограничения подсказки» с ДВУМЯ независимыми контролами:

* «Ограничивать размер инструкций Style Policy» — чекбокс + числовое поле (символы);
* «Ограничивать количество инструкций» — чекбокс + числовое поле (штуки).

По умолчанию оба выключены (`0` = без ограничения), строка состояния показывает
«Без ограничения». Включение лимита само по себе ничего не отрезает: стартовое
значение — фактический текущий размер блока/количество инструкций из серверной
витрины (`hint_limits.current_chars`, `hint_render.total_items`), 400/5 — только
запасной вариант для пустого блока. Дальше владелец уменьшает значение и сразу
видит последствия.

Рядом видно: «Сейчас: 180 зн.; входят 2 из 3 инструкций. Действует: до 2 инструкций»,
источник каждого действующего значения (этот чат / все чаты / не задан).

Лимит хранится в документе слоя (`hint_limits` в `style.policy`), сохраняется
существующим `POST /api/speech/style`. Черновик отправляет ТОЛЬКО собственные поля
слоя (его читает `hint_limits.layers` из витрины): отсутствующее поле наследует
другой слой, явный `0` — осознанное «OFF для этого слоя». Чатовый override не
затрагивает другие чаты (проверено серверными тестами стиля).

## 2. Предупреждение о превышении (§1.3)

Если `hint_render.excluded` непустой, в разделе показывается предупреждение:

* «В действующий лимит (до 2 инструкций) помещаются не все инструкции: 2 из 3.
  Часть активных правил в подсказку НЕ попадает»;
* каждая не вошедшая инструкция названа человеческим текстом и причиной
  («В этом чате короче — лимит владельца»), а не машинным ключом;
* кнопки «Изменить лимит» (фокус на числовом поле) и «Отключить лимит»
  (пишет явный `0` и помечает черновик);
* если ничего не исключено — честная строка «Все активные инструкции входят»,
  при пустом блоке — «Активных инструкций нет».

Текст «все инструкции действуют» при непустом `excluded` не выводится.

## 3. Inspector: фактическая сборка, а не один слой (§1.5)

Корневая ошибка: `_preview_manifest` читал **один** документ `style.policy`
(чат подменял глобальный, а при отсутствии override глобальный выдавался за
чатовый) → при любом лимите предпросмотр показывал не то, что уходит модели.

Исправлено в `web/api/speech.py`:

* `_style_layer_documents()` отдаёт ОБА слоя (global + chat); кандидат формы
  пишется в тот слой, куда сохраняет редактор;
* `effective_policy_sync(global, chat)` собирает ту же политику, что рантайм;
* `StylePolicyRef` получает фактические метрики подсказки
  (`hint_total/included/excluded/limits/limited_by/truncated`) — композер
  больше не теряет состав;
* `_style_build_summary()` отдаёт в Inspector: доступно/включено, источник
  global/chat, лимит или «Без ограничения», причину исключения
  (`user_limit` / `budget_excluded`), **точный текст** блока, попавшего в
  слой 10, и состояние слоя (`rendered` / `budget_excluded` / `absent`);
* `documents` показывает ревизии обоих слоёв — видно, что сборка двухслойная;
* в снимке реального хода (`sent`) добавлен слой Style Policy (chars/tokens/
  state) и сам блок подсказки (маскирован как весь payload).

В Inspector появилась карточка «Стиль письма в сборке» и строка в блоке
«Фактически отправленный payload». Исключённое правило НЕ показывается как
включённое: точная редакция содержит только вошедшие строки, исключённые
перечислены отдельным предупреждением.

## 8. Ревью UI (`review-ui.md`, Needs Fixes): исправления

Кандидат ревью: `0243441452f0`. Все три блокера закрыты точечно, без переделки
дизайна и без изменений `services/**`.

### BLOCKER-1 — частичное сохранение отменяло унаследованный лимит

**Было** (`web/app.js`, `speechStyleDocument`): при наличии любого собственного
поля отправлялись ОБА поля, отсутствующее превращалось в `0`; сервер трактует
явный `0` как «выключить», а не «наследовать».

**Стало** (`web/app.js:20629-20645`): в `hint_limits` копируются ТОЛЬКО ключи,
реально присутствующие в черновике слоя. «Отключить лимит»
(`web/app.js:20452-20462`) ставит `0` только действующим полям, неактивные не
трогает. Явное включение = число, явное выключение = `0`, «не задано» = ключа нет.

Проверка: `api/partial_merge` в e2e (реальный `merge_hint_limits` и
`effective_policy_sync`: global `max_chars=180` + chat `max_items=3` →
`max_chars == 180`) и UI-сценарий `style-inherited`: после включения item-лимита
POST содержит ровно `{"max_items": N}` (ключа `max_chars` нет).

### BLOCKER-2 — действующий унаследованный лимит выглядел выключенным

**Стало** (`web/app.js:20388-20430`): контрол показывает ЭФФЕКТИВНОЕ состояние:
`speechStyleEffectiveLimit` (серверное значение слоя), `speechStyleLimitInherited`
(своё поле отсутствует, лимит действует), `speechStyleLimitOriginText`
(«унаследовано: все чаты»). Черновик переопределения важнее серверного значения
для уже изменённого поля, поэтому «Отключить лимит» виден сразу, но до Save
действующее значение остаётся в статусе.

В разметке (`web/index.html:8054-8117`): чекбокс отмечается по действующему
лимиту, рядом badge «унаследовано», поле показывает действующее значение,
строка `data-speech-hint-limit-source` называет «Действует: до 180 симв. ·
унаследовано: все чаты» и объясняет, что отключение снимет лимит только для
этого слоя, а изменение поля создаст переопределение.
Скриншот: `shots/style_inherited_390.png`.

### BLOCKER-3 — `budget_excluded` противоречил «ничего не исключено»

**Стало**: `speechStyleBuildInPayload`/`speechStyleBuildReasonText`
(`web/app.js:21710-21727`), карточка Inspector (`web/index.html:9415-9455`):

* при `payload_included=false` вместо «Ничего не исключено» — предупреждение
  «Слой Style Policy не вошёл в фактический payload — модель этот текст НЕ
  получила», причина «бюджет композитора (технический лимит модели)»;
* числа подписаны «в подсказке (НЕ отправлено): N»;
* заголовок блока меняется на «Что было бы включено (НЕ отправлено)», сам текст
  остаётся с явной пометкой; `data-speech-inspector-style-payload-included="no"`;
* в разделе «Стиль письма» строка «все входят» квалифицирована как «в пределах
  пользовательского лимита» + ссылка на технический бюджет в Inspector.

Проверка: e2e-сценарий `budget` (390 + desktop) — `Ничего не исключено`
отсутствует, есть «не вошёл», «бюджет композитора», «не отправлено»,
`payload_included=no`, показан текст, который был бы включён.
Скриншот: `shots/inspector_budget_390.png`.
