# P1 — рекомпоновка страницы «Модули → Инициатива»

- **Ветка:** `feat/initiative-ui-rework` (база `7536df96`)
- **Источник требований:** `plans/owner_inputs/2026-11-03-hotfix-meme-publication-initiative-ui.md` §2.2–§2.4 (дословный снимок ТЗ владельца)
- **Область работ:** только UI/чтение. `services/**` НЕ менялись; пайплайн публикации меряет независимая P0-полоса (`fix/p0-publication-stale`).

## 1. Что сделано

Одна страница вместо «огромного полотна»: шапка (название + область + итоговое состояние + вход в каталог) и **пять вкладок**, каждая со своим содержимым и своим источником данных.

| Вкладка | Назначение | Источник данных |
|---|---|---|
| Обзор | состояние ДВУХ механизмов, координация отправки, 3–5 значимых событий | `GET /api/initiative/mechanism-diagnostics`, `GET /api/initiative/meme-settings`, `GET /api/memory/initiative-vitality`, `/api/status` |
| Текстовая инициатива | «Включение и условия», «Частота и лимиты», «Последнее решение» | `/api/status` (intent_snapshot), config-каталог (`flags_intent`/`limits_intent`), mechanism-diagnostics |
| Мемы | весь мем-конвейер: верхняя строка, две колонки, два промпта, бюджет, «Последняя попытка», ручной `/meme` | `GET/POST /api/initiative/meme-settings` + mechanism-diagnostics |
| Публикации | общий журнал логических попыток (текст и мемы), фильтры, пагинация, деталь по клику | **новый** `GET /api/initiative/publications` (read-only) |
| Диагностика | трасса РОВНО одной попытки + полное состояние двух механизмов | **новый** `GET /api/initiative/publications/detail` (read-only) |

**Новый бэкенд — один аддитивный модуль `web/api/initiative_publications.py`** (прецедент `mechanism_diagnostics.py`: собственный роутер, `routes.py` не тронут, RBAC — доступ к конкретному чату). Он только ЧИТАЕТ существующие журналы:

- `meme_initiative_attempt` (строки этапов; логическая попытка = один `job_id`);
- `mca_events` (решения `initiative_decided`, перепроверка, писатель + **любые** будущие `publication_*` по префиксу — новые коды P0-полосы видны без правки файла);
- `mca_bot_outputs` (факт реальной доставки: `tg_message_id`, `delivery_status`).

Ничего не пишется, свои квоты/счётчики не считаются, `delivered = null` означает «неизвестно», а не «нет».

### Смысловые правила, зашитые в UI

- **Эффективное ON/OFF берётся из гейта самого механизма** (`ready` + `skip.code`), а не из одного мастер-флага: выключенная ось наблюдателя/чата читается как «выключено». Если ось недоступна роли и блока нет — честное «состояние неизвестно», а не «включено».
- **«Координация отправки»** — только из API (`coordination`, `conflict`, `claimed_by`, `interval_seconds`, `manual_priority_until`, `checked_at`). Никакого клиентского отсчёта таймера.
- **Публикации** различают генерацию и отправку: итог детали печатается как «генерация успешна, отправка отменена · устаревшая бронь публикации (`publication_stale`)», «генерация успешна, публикация доставлена» и т.п. — из фактической цепочки этапов, а не из догадки.
- **Диагностика** по умолчанию сжата: семь групп (`условия`, `случайное решение`, `контекст/снапшот`, `этапы генерации`, `речевые слои Core/Expression/Humor`, `send/recheck`, `события и ошибки`); ревизии, манифест и безопасный текст prompt manifest — при раскрытии; полные блоки двух механизмов — отдельным свёрнутым разделом на этой же вкладке (второго debug-места нет).
- **Один save** мемов: `POST /api/initiative/meme-settings` (второго эндпоинта нет), «Отменить изменения» возвращает серверные значения без запроса, «Вернуть наследование» очищает поле и сохраняется пустой строкой (существующий контракт снятия override), результат сохранения показан текстом («Сохранено для этого чата: …» / «Не сохранено: …»).
- **Ручной `/meme`** помечен как админская команда с числом фактических запусков из журнала — под авто-триггер не маскируется.
- **«Обзор» не грузит тяжёлые данные**: журнал публикаций и трассы запрашиваются только на своих вкладках (`initiativeTabEnter`), у каждого загрузчика свой single-flight.

- Sticky-полоса сохранения **намеренно не делалась**: единственная кнопка сохранения стоит в заголовке блока промптов (выше полей), поэтому в Telegram WebView клавиатура её не перекрывает. Это осознанное решение, а не забытый пункт ТЗ.

## 6. Что тесты НЕ доказывают

- Реальные данные продакшена: ответы API в e2e — стабы той же формы, что отдают `mechanism-diagnostics`/`meme-settings`; новый журнал проверен на форме контракта, но не на живом PostgreSQL-журнале бота.
- Публикационная семантика `publication_stale` (это P0-полоса `fix/p0-publication-stale`): UI показывает коды и цепочку как есть; если P0 изменит набор кодов, новые `publication_*`-события попадут в «Диагностику» автоматически (фильтр по префиксу), но подписи неизвестных кодов останутся кодами до добавления в словарь.
- Клавиатура/WebView на реальном устройстве: sticky-панели нет по конструкции, но фактический показ экранной клавиатуры проверяется только на устройстве владельца.
- Скролл-виртуализация длинных журналов не вводилась: пагинация по 40 строк с ограниченным чтением на сервере (600 строк журнала мемов / 400 событий / 300 доставок).

## 7. Инцидентные наблюдения (вне этой полосы)

- В старом UI `Лимиты` были отдельной вкладкой с 5 параметрами — параметры на месте (секция «Частота и лимиты»), но старые прямые ссылки `#/modules/initiative/limits` теперь канонизируются на `.../text` (данные не теряются).
- `tests/test_webapp_evol_w12_internals.py::test_palette_css_*` ограничивает литеральные `font-size` в хвосте `app.css`; аддитивный слой `ini-*` написан в `em`, чтобы не ломать систему токенов.
