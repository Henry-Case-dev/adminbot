## Implemented

### A. Settings semantics / removals

- `CONFIG_ITEM_DISPLAY_OVERRIDES` now carries UI-21 titles/descriptions:
  - `CHAT_GLOBAL_CONTEXT_LIMIT` — «сколько последних сообщений читать
    первично», explicitly not «память 200»; real amount is in the inspector.
  - `SUMMARY_MAX_WINDOW_MESSAGES` / `SUMMARY_WINDOW_HOURS` — first-read
    boundary/pagination, not the source of truth for all memory.
  - `CHAT_GLOBAL_CONTEXT_MAX_CHARS`, `CHAT_THREAD_MAX_CHARS` — legacy caps,
    read-only.
  - `CHAT_GLOBAL_CONTEXT_MAX_TOKENS`, `CHAT_THREAD_MAX_TOKENS` — compat
    profiles, read-only.
  - `CHAT_THREAD_MAX_DEPTH` — depth for reading, with actual depth in the
    inspector; no character-cut claim.
  - `CHAT_BRANCH_CONTEXT_HOPS` — internal safety/debug, not «ровно 3 хода».
  - `CHAT_RUNNING_SUMMARY_TAIL` — advanced debug internal fallback.
  - `CHAT_LEVEL2_MIN_RAW_COUNT` — legacy watermark-era threshold, not
    «качество ответа».
  - `CHAT_LEVEL2_MAX_CHARS` — legacy blind cap, read-only; reduction reason
    is visible in the inspector.
  - `RUNNING_SUMMARY_TTL_MINUTES` — technical storage TTL, not «время жизни
    памяти»/«забывание через час».
  - `CHAT_MAP_PARTICIPANTS_HOURS` — auxiliary map period; author/alias by UID.
  - `CHAT_BUDGET_*_RATIO` — legacy read-only shares.
  - `CHAT_BUDGET_RESERVE_RATIO` — technical output-reserve share; actual
    reserve is shown in the inspector.
- `UI21_ITEM_UI` hides `CHAT_CONTEXT_FILL_RATIO` from config groups and config
  search, moves debug/legacy keys to «Расширенные», and marks the listed
  legacy/compat keys read-only. Values/overrides are preserved; no catalog
  key was removed.
- Generic numeric inputs now bind `:disabled="!canEditConfig(item.key)"` (not
  only `v-model`), so legacy/read-only values are actually not editable.
- Advanced config cards now render the effective-meta legacy/no-op badge as
  well as the existing notice.
- `canEditConfig` honors UI-21 read-only flags before the wildcard admin
  shortcut: the form is read-only even for a global admin. Backend values are
  untouched.
- Direct-context block states: «Конспект обновляется по вытесняемому
  содержанию и watermark, а не по порогу заполнения окна; TTL — техническое
  хранение».

### B. Inspector / status

Added a compact `data-ur21-inspector` block inside the existing turn inspector,
driven only by already-loaded `turnDiag` + config:

- used vs setting: `counts.available_messages`, `window_messages`,
  `included_messages` and the effective `CHAT_GLOBAL_CONTEXT_LIMIT`;
- actual branch depth from the trace `thread`/`reply_branch` block; `≥N` when
  the trace is truncated (no invented exact count);
- actual output reserve (`budget.output_reserve`) vs
  `CHAT_BUDGET_RESERVE_RATIO`;
- summary coverage dates/watermark (`global_head` first/last), window count,
  TTL as technical storage, and whether `global_tail` has newer replies than
  the summary;
- reduction reason with code + human label (`turnCodeText('drop_reason', …)`,
  unknown → `код: …`) and count;
- UID/alias identity note: the map is auxiliary and not more authoritative
  than reply-source.

The existing «Direct Context → Диагностика последнего прогона» now also shows
the last run’s used-vs-setting line and actual output reserve
(`data-direct-used-setting`).

No new DTO, endpoint, store or network call was added. Opening the inspector
uses the existing `/api/direct/turn-diagnostics`; the status block uses the
existing `/api/direct/context-diagnostics`.

## Remaining / RFL

- **RFL-UI21-1:** `CHAT_BUDGET_RESERVE_RATIO` is still read by
  `services/model_capacity.py::output_reserve_tokens`; the literal backend
  replacement by a model-aware physical reserve is not proven. UI now labels
  it as a technical output-reserve share and shows the actual reserve in the
  inspector, but leaves it editable. A backend contract change is required if
  literal removal/replacement is mandatory.
- **RFL-UI21-2:** `CHAT_THREAD_MAX_DEPTH`, `CHAT_BRANCH_CONTEXT_HOPS`,
  `RUNNING_SUMMARY_TTL_MINUTES` and `CHAT_MAP_PARTICIPANTS_HOURS` remain active
  backend parameters; this change is presentation-only (labels, advanced
  placement, inspector visibility), as scoped.
- **RFL-UI21-3:** actual branch depth is derived from the trace
  `thread`/`reply_branch` source-id list; it is bounded/truncated, so the UI
  prints `≥N` rather than inventing an exact depth. A separate DTO would be
  needed for an authoritative full count.
- **RFL-UI21-4:** `CHAT_CONTEXT_FILL_RATIO` is hidden from user settings and
  config search, but remains in the backend registry/role-permission matrix
  for compatibility; its value/override are preserved.
- **RFL-UI21-5:** existing `tools/ui_urf_visual_e2e.py` is stale for this base
  (its `/api/config` mock lacks the `modules` registry, so workspace routes do
  not open); it was not modified because it is outside the assigned file
  scope. Standalone `tests/js/ur_ui_settings_test.js` also has a pre-existing
  `mod_time` assertion failure on base; it is not part of pytest and was not
  changed.
- **UI-06/QRNG:** `web/app.js` was free after the accepted QRNG UI-07 tip;
  QRNG behavior is untouched. Unified Reply backend/UR-13 remains untouched.

No product backend, API, settings, config-cache, DB or user values were
