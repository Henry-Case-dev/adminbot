## 1. Live path

`_build_user_content` (composer ON) передаёт в `_compose_user_content`:
`live_selection=True`, `extra_media_markers`, `rag_memory` с `rows`, `global_parts` с
`summary_row`, `episode_stats` с `rows`. Внутри `_compose_user_content` live-ветка
`_run_live_selection` выполняется **до** старого блочного allocation; старый путь
остаётся только fail-open.

Порядок live-сборки:

1. `_current_question_source` — тот же текст/медиа-маркеры, что у
   `_render_current_question` (единственный источник, без второго рендера).
2. Chain (`_collect_thread_chain`, current→root) нормализуется в root→current;
   branch/thread — `split_reply_branch`; reply-parent — `chain[1]`.
3. Окно: `global_parts["tail_rows"]` → fresh P1; `middle_rows` → background P3.
4. Summary: `summary_row` копируется с `summary = "\n".join(head_lines)` —
   материализатор сохраняет прежний head-текст/watermark.
5. Episode: `episode_stats["rows"]` → memory tier 4; `history_supplement` →
   memory tier 4 (source `supplement:*`), отдельный слот.
6. RAG: `rag_memory["rows"]` (canonical kept tuples) → memory tier 3.
7. Canonical memory leg: **один** `build_memory_request` + `retrieve` +
   `collect_memory_fragments` с `addressee_uid`, `reply_parent_uid/text`,
   `trigger_ref`; fail-open по источнику.
8. Durable self-outputs: **один** `collect_self_output_fragments`; fail-open.
9. `build_context_selection(..., allocate=False)` — полная selection без
   внутренней отсечки.
10. `fixed_p0_tokens` считается **один раз** по map/target/relations/protected/
    lore/correction/nostalgia/sandwich; `selection_budget = max(0, budget - fixed)`.
11. **Один** `allocate_selection(full_selection, selection_budget)`.
12. Материализация существующими рендерерами:
    `_chain_line` (branch/thread), `_context_row_line` (окно/middle/episode/
    self-outputs/memory-messages), `build_rag_context` (fact tuple),
    summary/middle строки, `_render_current_question`.
13. Payload: `map → branch → episode → history_supplement → rag → global
    (head/middle/tail) → thread → target → relations → protected → lore →
    nostalgia → correction → current → sandwich` (`CANONICAL_ORDER`).
    Prepared-вариант хранит `global_head/middle/tail` раздельно для trace,
    payload склеивает их в один `<Global_Context>`.
14. Provenance: `PreparedTurnPayload.event_blocks` из selection (kind/role/
    source_ids/first_ts/last_ts/tokens), `dropped` из `provenance.dropped`,
    self-outputs — bot-фрагменты окна + ledger; `available_messages` — окно ∪
    chain ∪ episode (память не завышает счётчик сообщений).
15. Fallback recompose: `allocate_selection` на **той же** `full_selection` с
    fallback-бюджетом; повторного retrieval/сборки нет.

## 3. Ошибки, overflow, caps

- Исключение selection/материализации → WARNING, `degraded=True`,
  `policy_mode="legacy_fail_open"`, старый блочный allocator.
- `fallback_selection_budget == 0` — это НЕ «полная selection»: live вызывает
  allocator с `max(1, budget)`, поэтому получается explicit P0/overflow, а не
  пропуск всего контекста мимо окна.
- Fallback adapter failure → WARNING, **capacity-only** prepared
  (`policy_mode="fallback_capacity"`, `degraded=True`,
  `physical_overflow=True`), current/fixed blocks; primary-as-is больше не
  отправляется на меньшую модель.
- P0 overflow: `current_parts`/`reply_parent_parts` материализуются (части
  склеиваются, потерь нет); не вошедшие части — в `provenance.overflow_parts`.
- `graph_rag_context_max_chars` на live-selection пути **не применяется**
  (`_build_rag_block(selection_mode=True)`), включая plan-rescope; текстовый cap
  остаётся только для legacy/fail-open. Thread идёт с `truncate=False`;
  episode/middle row-лимиты — candidate limits, не смысловая отсечка.
- Safety/Telegram caps не снимались; новых порогов/гейтов нет.
- Trace `dropped` агрегируется по block-kind (`thread/global_tail/rag/...`) и
  причине; quote-события строятся из РЕАЛЬНО материализованных строк, поэтому
  вытесненная цитата не засчитывается, а сжатая/выжившая — засчитывается один раз.

## 4. Фиксы 2a, потребовавшиеся live-путем

- `_alias_label` понимает `AliasResolver.resolve` (live) и старый `.get`.
- `preserve_projections=True` в `build_context_selection`: thread/branch и окно
  дедупятся внутри своей проекции; memory/self-outputs — против обеих. Иначе
  окно терялось при совпадении tg с chain.
- `_prepared` для global head/middle/tail + `_settle_delivered_turn`: виды
  блоков совпадают, счётчики `included_messages` честные.
- Summary head: `source_ids=[]`, даты из `window_start_ts/window_end_ts`
  (id конспекта не выдумывается).
- `fragment_from_fact_row` принимает canonical tuple; RAG rows идут в
  materializer без второго retrieval.
- Live `selection_budget=0` не означает «полная selection»: allocator получает
  `max(1, budget)`; иначе контекст проходил мимо окна без отсечки.
- `dropped`/quote trace: block-kind агрегация и `chain_rendered` из реально
  материализованных строк (сжатая цитата засчитывается, вытесненная — нет).
- Fallback failure: capacity-only prepared + current/fixed blocks вместо
  primary-as-is; `policy_mode="fallback_capacity"`, `degraded=True`.
