## 2. Behavior implemented

### 2.1 `direct_l1.select_l1_window`

New helper in `services/direct_l1.py`:

- accepts the raw window and stage budget;
- builds one `ContextPiece` per row;
- P0: trigger message and reply parent (non-evictable, full text);
- P1: fresh tail (`fresh_tail_min_messages`, default 20);
- P3: older background;
- calls the existing `direct_context_composer.allocate_budget` (no second allocator);
- returns selected rows with P0 full text and P1/P3 budget-compressed text;
- preserves `id/tg_message_id/author/reply_to` so `render_window_lines` keeps reply markers.

### 2.2 `build_l1_context`

Added optional:

```python
window_limit: int | None = None
line_chars: int | None = None
```

- `window_limit` controls the active row limit; legacy default remains `L1_WINDOW_MESSAGES` for callers that do not pass a selected window.
- `line_chars=0` means the allocator already produced the final text: `render_window_lines` does not apply the 200-char per-line cap.
- `render_window_lines` keeps its legacy default (`line_chars=None` → 200) for old paths.
- `history_partial` is still honored; initiative computes it from raw window > selected window.

### 2.3 Live call sites

- `_plan_direct_l1` (`services/direct_chat_service.py:8425`): after `get_window_messages`, calls `select_l1_window(..., trigger_message_id=message.message_id, reply_to_id=_replied_message_id(message))`, records raw/selected counts, passes `window=_l1_window, window_limit=len(_l1_window), line_chars=0`.
- `plan_initiative_decision` (`:17441`): same selection without trigger/reply; passes selected window and `line_chars=0`.

`L1_WINDOW_MESSAGES`/`L1_WINDOW_LINE_CHARS` remain as legacy defaults/compat, but the active route no longer applies them a second time.
