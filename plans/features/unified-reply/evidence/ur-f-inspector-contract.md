## 2. Изменение схемы событий (ΔDDL=0, миграции нет)

Новое событие `direct_turn_selection` (component=`direct_chat`, stage=`turn_selection`, `trace_id`=correlation_id): эмиттер — новая `note_selection(correlation_id, *, chat_id, payload)` в `services/turn_trace.py` рядом с `note_tools`, работает БЕЗ in-memory `TurnTrace` (событие не теряется, если `begin()` не состоялся). Поля payload: `counts{available_messages:int,included_messages:int,window_messages:int}`, `budget{slot:str,window:int,window_source:str,output_reserve:int,available:int,budget:int,policy_mode:str,payload_tokens:int,fallback_window:int|None}`, `blocks[{kind:str,role:str,rendered:bool,skip_reason:str,source_ids:list[str≤8],first_ts:int,last_ts:int,tokens:int}≤16]`, `dropped[{reason_code:str,kind:str,count:int}≤8]`, `self_outputs[{source_id:str,tg_message_id:int,ts:int}≤6]`, `policy_version:str`. Дополнения в существующие события: `context_payload` — 5 скалярных полей UR-20.4 + `clock_stages:list[str]`; `ToolEvidence.trace_fields` — `source_links` (в отдельном JSON-слое `source_ref_json`, свой лимит 2000 симв. `e33b88b65e09:616-680`); событие `style_policy` получает `trace_id` и `rules` (`additive param correlation_id` в `apply_style_policy`).

Старые строки частично заполнены: недостающие ключи просто отсутствуют (не `null`-заглушки в БД). UI обязан рендерить «нет данных (трасса старше 2.58.18x)» для отсутствующего поля и никогда не выводить 0 вместо «неизвестно» — кроме счётчиков `dropped/counts`, где 0 честен только при наличии `policy_version`.

**Backfill — против.** (а) `mca_events` — телеметрия с ретенцией и prune: восстанавливать нечего; (б) значения (`alias_source_author`, `output_reserve`, `preserved_kinds`, `first_ts/last_ts` блоков) существовали только в памяти процесса того хода — восстановление было бы выдумкой, что нарушает «дата/источник не придумывается» (UR-23.7); (в) цена: пере-запись истории без пользы для приёмки, которую даёт только новый живой ход. Вердикт: **backfill не делаем, честная пустота**.

## 3. Доступ и приватность

Текст в `mca_events` не пишется ни в каком виде — инвариант `turn_trace` сохраняется (`_TEXT_KEYS`/`_scrub`, `809d873b24c5:308-343`). Единственное место, где может появиться оригинальный текст, — ответ API при явном `include_text=1`; он берётся из существующих хранилищ по id, а не из трассы: `get_smart_message_by_tg_id(chat_id,tg_message_id)` и `get_bot_output_by_tg(chat_id,tg_message_id)`/`get_messages_around(chat_id,reply_parent,before=0,after=0)`.
Предикат (обязан выполняться ДО любого чтения текста): `access_srv.can_access_chat(ctx, chat_id)` на **том же** `chat_id`, что в пути, И каждый запрос к БД ограничен этим `chat_id` (`WHERE chat_id = ?`), И `rows[].chat_id == chat_id` для каждого события цепочки. События уже фильтруются по чату (`e33b88b65e09:918-950`), фильтр нельзя ослаблять. `include_text` без права администратора чата → 403, не пустая строка.
Алиас/username: только `alias_source_author`/`alias_reply_parent` (≤48 симв., 2 значения на ход, `@` срезается); полный ростер `_turn_aliases_snapshot()` НЕ пишется — это список имён всех участников.
Исключено навсегда: `SourceRecord.snippet`/`content`/`_content` (чужая выдача и тексты страниц), `RuleOutcome.detail`, `StyleOutcome.repetition`, тексты фрагментов контекста, `text/caption` пользовательских сообщений, любые поля другого чата. `source_url`/`source_title`: URL — публичный адрес выдачи (не текст чата), но длина растёт до 300 симв., поэтому в `_scrub` нужна явная allow-ветка `_LINK_KEYS={"source_url"}` с проверкой `^https?://[^\s]{4,300}$` (иначе поле = `""`) и `source_title` ≤120 симв. — без этого `_scrub` превратит ссылку в digest (`:314`) и UR-20.7 не закроется.

## 4. Форма API (`GET /api/direct/turn-diagnostics`, `9e88bfd81771:1426-1496`)

Сигнатура: `chat_id, trace_id?, turn=1..8, include_text=0|1` (новый параметр, по умолчанию 0 — обратная совместимость полная).
`_TURN_STAGE_EVENTS` остаётся якорем цепочки (3 события) — иначе черновики без контекста создавали бы «ходы». Добавляется `_TURN_DETAIL_EVENTS = {direct_turn_selection, reply_search_evidence, tool_phase, style_policy}`: их строки приклеиваются к уже существующей цепочке по `trace_id`, новых цепочек не создают.
Ответ дополняется братьями `context/writer/delivery`: `stages{context,writer,delivery,selection,search,tool_phase,style}` (bool присутствия), `source{message_id,author_id,author_alias,message_ts,reply_to_id,reply_to_author_id,reply_to_alias}`, `clock{timezone,as_of_utc,timezone_source,config_version,stages[]}` (расширение существующего), `selection{policy_version,counts,budget,blocks,dropped,self_outputs}`, `search{decision,called,status,skip_reason,evidence_class,required,source_count,source_ids[],links[]}`, `style{revision,source,applied,counts,rules[]}`. Старые трассы: `selection/search/style = null`, `stages.* = false` — ответ остаётся валидным, `available:true` не меняется. `include_text=1` добавляет `source.text`, `source.reply_parent.text`, `self_outputs[].text` (каждое ≤600 симв. с флагом `truncated`).

## 5. UI (index.html `1332-1540`, app.js `15321-15404`)

Каркас не перестраивается: 3 уровня и 4 карточки (`data-turn-stage="l1|tools|writer|delivery"`, сетка `grid gap-2 md:grid-cols-2`).
1 · Планирование (L1): `source` — «отвечал: <алиас автора> (сообщение N, <локальное время>)» + «в ответ на: <алиас> (сообщение M)» или «не ответ на сообщение»; `clock` + строка «часы поданы на этапах: L1, инструменты, ответ».
2 · Инструменты и поиск: `search.decision` словами — «поиск обязателен / поиск полезен / поиск не нужен» (код только рядом, mono), «что сделано»: `called`+`status`+`skip_reason` по-русски; список ссылок `links[]`: заголовок → адрес; пусто → «поиск не дал ссылок»; `published_at` пусто → «дата публикации не сообщается источником» (не выдумывать).
3 · Что видел ответ (Writer): `budget` одной строкой («окно модели N · запас на ответ M · вошло K из бюджета B · режим»); `counts` — «доступно сообщений N · вошло в запрос M»; `blocks` — вертикальные строки, каждая: понятное имя блока + даты (`dd.mm hh:mm` в часовом поясе чата) + ссылки «сообщение 12345 / конспект до <дата> / факт 42»; потерянные — отдельным списком «не вошло, потому что …» из `dropped[]`; `self_outputs` — «свои реплики в истории разговора (не образец стиля)» с tg id и датой.
4 · Операции и доставка: существующая цепочка ops + `style.rules` — «сработало правило: <понятное имя> · причина <код>», секретов и текста правил не показывать.

Расшифровка кодов обязательна (UR-20) через словари в `app.js` рядом с `turnOpLine/turnClockLine` (`15361-15404`): `MAP → «карта участников»`, `Branch → «ветка ответов»`, `Anchor → «привязка к сообщению»`, `TTL → «срок жизни записи»`, `trace_id → «код хода (служебный, по нему собрана трасса)»`; block-kind: `global_tail→«свежие сообщения»`, `global_middle→«подобранные сообщения»`, `episode→«старые эпизоды»`, `rag→«память, факты»`, `global_head→«конспект»`, `thread→«ветка ответов»`, `protected→«защищённые факты»`, `sandwich→«напоминание»`; ops (`l2_scrubber` и др.) — тоже подписи, не сырые коды.
Mobile-first: без таблиц; строки блоков — `flex flex-col` с `break-words`, длинные списки (blocks>5, links>3, rules>4) сворачиваются кнопкой «показать ещё» (локальное состояние, не раскрывать по умолчанию); никакого горизонтального скролла и никаких `truncate` на id/датах; на <768px карточки в одну колонку, `source`/`counts` — две строки с переносом.

## 6. Порядок работ и границы

Шаг 1 (события, невидим для UI): `services/turn_trace.py` (5 полей контекста, `clock_stages`, `note_selection`, allow-ветка ссылок в `_scrub`) + `services/direct_chat_service.py` (передача reply-parent/даты/алиаса в `begin`; прокидка `correlation_id` в `_build_user_content`→`_compose_user_content`; сбор `blocks/dropped/self_outputs`; спаны эпизодов в `episode_stats`; out-параметр `_build_rag_block`; маркеры `clock_stages`) + `services/direct_execution.py` (`source_links` в `trace_fields`) + `services/style_policy.py` (`correlation_id`+`rules`). Проверка: один реальный ход в тестовом чате → в `mca_events` ровно 4 `direct_turn_*` строки + `reply_search_evidence`/`style_policy` с тем же `trace_id`.
Шаг 2 (проекция): `web/api/routes.py` — только `_turn_chain_view`/endpoint, аддитивно. Проверка: старый `trace_id` (до слайса) отдаёт прежний ответ + `null`-поля; новый — все поля.
Шаг 3 (UI): `web/app.js` + `web/index.html` — карточки/подписи/сворачивание. Проверка: Playwright + Browser Use на мобильном вьюпорте (`390×844`) и десктопе, снимок до/после, отсутствие горизонтального скролла, ни одного неизвестного кода.
Порядок обязателен: шаг 1 фиксирует контракт данных до UI; шаг 2 и 3 не начинать параллельно с шагом 1 на тех же файлах.

**Вне области:** никакого нового retrieval/эмбеддингов; без изменения стилевых правил и их применения (только наблюдение); без перестройки секции и её навигации; без нового endpoint (всё в существующем); без нового хранилища, DDL и backfill; без изменения `direct_turn_context` семантики существующих ключей; `initiative`/`factcheck` не трогаем (тот же шов пригодится позже, но не в этом слайсе).

## 7. Риски

R1 объём/долговечность: +1 событие на ход (~1.8 КБ максимум) и +~35% строк `mca_events`; для пет-проекта приемлемо, ретенция/prune уже есть (`e33b88b65e09`), буфер `_PENDING_MAX` не увеличиваем. Списочные поля жёстко ограничены (блоки ≤16, id ≤8, ссылки ≤6) — иначе `_pack` начнёт вытеснять `tools`/`ops`.
R2 PII: алиасы (2 на ход) и текст по `include_text` — самые чувствительные новые данные; смягчение — фильтр по `chat_id` в каждом чтении, `include_text` выключен по умолчанию, текст не логируется и не кэшируется, `snippet` страниц не пишется; URL ограничен схемой/длиной и проходит существующий `sanitize()`.
R3 отказ/частичность: нет `selection` → секция «что вошло» показывает «нет данных», а не 0; нет `style` → «правила не зафиксированы»; нет `search` → «решение о поиске не зафиксировано»; сбор данных на стадии записи обязан быть `try/except`-fail-open (как все `note_*`), иначе новый код начнёт ронять ответ — недопустимо, ход важнее трассы.
R4 совместимость: `_scrub`-allow-ветка для URL — единственное место, где ослабляется защита от текста; она принимает только `^https?://…` и один ключ, покрывается негативным тестом (текст чата в `source_url` → отброшен).
