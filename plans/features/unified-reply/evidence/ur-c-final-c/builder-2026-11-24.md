## 2. `UR-21.18` — замороженный контракт

Активные стадии: только `direct.primary` / `direct.fallback`.
Summary, `direct.l1`, `intel.*`, `initiative.*` сохраняют прежнюю policy.

```text
1) caller max_output_tokens > 0        -> reserve = max(1024, caller)
2) stage output_reserve_env (Summary)  -> без изменений
3) model_max > 0 && switch ON:
       target  = reserve_target_tokens > 0 ? reserve_target_tokens : model_max
       reserve = max(1024, min(model_max, target + 256))
       source  = "model_capability"
4) model_max неизвестен / switch OFF   -> capacity.output_reserve_tokens(window)
       source  = "ratio_fallback"
5) иначе floor 1024, source = "floor"
```

- `reserve_target_tokens` Direct передаёт как
  `response_extent.longform_max_output_tokens()` (default 4096).
- `model_max` берётся из `CapacityResult.max_output_tokens` через новый
  `model_capacity.resolve_stage_limits` — **тот же** резолв, что
  `resolve_stage_window`, без второго сетевого вызова (capacity cache).
- `DIRECT_RESERVE_MODEL_AWARE_ENABLED` — env-only `ClassVar`, default **ON**;
  UI/per-chat настройки нет. OFF даёт точную прежнюю ratio-формулу.
- `limits.chat_budget_reserve_ratio` не сбрасывается; `/api/config` отдаёт
  `eff.status="legacy"`, `active_consumer="services.auto_budget (fallback)"`.
- UI: `UI21_ITEM_UI[...] = {advanced:true, readonly:true}`, title/description
  честно называют fallback-смысл. Инспектор показывает источник резерва:
  `model_capability` → «предел вывода модели (M)»; `ratio_fallback`/
  `legacy_ratio` → «fallback-доля S»; нет поля → «источник не зафиксирован».
