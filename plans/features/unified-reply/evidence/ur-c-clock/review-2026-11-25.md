## 3. Блокирующий finding

### URC-CLOCK-R1 — второй резолвер действующего пояса чата (`UR-25`)

- **Severity:** medium (контракт/инвариант строки; не security/data-loss).
- **Статус:** open; previously_open=false. **Disposition: IN_SCOPE (блокирует
  биндинг UR-25).**
- **Контракт:** arch §2 D2 («Инвариант фиксируется так (и только так):
  действующий пояс чата резолвится ровно одним кодом»), §3 (worker_budget
  отнесён к «validator/system», источник зоны «имя/`SUMMARY_TIMEZONE`»),
  §8 (`UR-25` ← «единственный резолвер/алгоритм»);
  `requirements-map.json` req_id `UR-25`: «…без независимых алгоритмов часов
  в других местах». Impl §6 утверждает «второй резолвер … отсутствует».
- **Expected:** пояс, по которому считаются per-chat сутки/лимиты в контуре
  среза, резолвится только `chat_clock`.
- **Actual:** `services/worker_budget.py:581-607` `_chat_tz_name` самостоятельно
  резолвит **действующий пояс чата**: per-chat canonical
  `limits.chat_timezone` → global `limits.chat_timezone` → fallback
  `limits.summary_timezone`/`SUMMARY_TIMEZONE`, через
  `canonical_context.resolve_timezone`. Нет per-chat legacy
  `limits.summary_timezone` и `GOODMORNING_TZ`. `image_day`
  (`worker_budget.py:610-617`) использует его для календарного дня per-chat
  image-брони (`:718`) и остатка лимита (`:989`) — то есть для
  user-visible суточного сброса, а не «дня отчёта».
- **Repro (read-only probe, вне репозитория):** чат с единственным
  per-chat legacy `limits.summary_timezone=Asia/Almaty`, global canonical пуст:

```
cp.read_override_sync = lambda cid,key: (("Asia/Almaty",True) if key=="limits.summary_timezone" else ("",False))
hot.get = lambda key,default=None: ("" if key=="limits.chat_timezone" else default)
worker_budget._chat_tz_name(1001)            -> "Asia/Yekaterinburg"
chat_clock.resolve_chat_timezone_sync(1001)  -> ("Asia/Almaty","chat_legacy")
DIVERGENT = True
```

- **Impact:** для конфигурации «только per-chat legacy» (она прямо
  поддерживается и является кейсом D2.5) сутки image-лимита сбрасываются по
  другому поясу, чем локальные сутки ответов/инициатив. Дефолтная
  конфигурация (ничего не задано) совпадает (оба → `SUMMARY_TIMEZONE`), поэтому
  это не кандидатная регрессия, а незакрытый второй резолвер; но именно он
  назван в acceptance `UR-25`.
- **Почему блокирует:** иначе `UR-25` будет помечен VERIFIED на основании
  аудита, фактически неверного для `worker_budget`, и impl §6 останется
  ложным утверждением. Это не «старый несвязанный баг»: это acceptance
  exit-строки среза.
- **Fix options (решает Architect/Orchestrator; Reviewer не правит):**
  - **A.** Расширить §4 на `services/worker_budget.py` и делегировать
    `_chat_tz_name` в `chat_clock.resolve_chat_timezone_sync` (сигнатура/тип
    прежние; sync best-effort; поведение меняется только для legacy/
    GOODMORNING-конфигураций — в сторону согласованности), + тест
    «legacy-only chat → `image_day` == локальная дата ChatClock».
  - **B.** Формальное решение Architect/PM, что per-chat image-budget day
    вне `UR-25`; исправить §3/§8 и impl §6 (убрать ложное «второй резолвер
    отсутствует»), привязать `UR-25` с явным residual. В этом случае R1
    переходит в BACKLOG_ONLY и кандидат может быть принят после быстрой
