### UR11A-R1-B1 — DB PK путался с Telegram id

- **RED:** до фикса `l1._row_matches_message_id({"id": 7, "tg_message_id": 999}, 7)`
  возвращал `True`; regression падал. Чужая строка `id=7/tg=999` тихо
  исключалась как P0 при trigger=7.
- **Fix:** `_row_matches_message_id` теперь делегирует каноническому

  `tg_message_id`, DB PK никогда не считается Telegram-id.
- **Regression:** `test_p0_exclusion_uses_tg_message_id_not_db_pk`:
  `id=7/tg=999` не исключается; `tg=7` исключается; `window_rows_excluded_p0=1`,

### UR11A-R1-B2 — `sqlite3.Row` отбрасывался `isinstance(dict)`

- **RED:** Direct-L1 с реальным `sqlite3.Row` (4 строки) давал
  `l1_window_rows_raw=0`; regression падал. Live-фейки на dict это скрывали.
- **Fix:** новый `normalize_window_rows` (dict/Mapping-like/sqlite3.Row) в
  `direct_l1`; применён в `build_l1_context`, `render_window_lines`,

  перед сборкой. `window_rows_raw`/`selected` теперь честные.
- **Regression:** Direct и Initiative L1 с настоящим `sqlite3.Row` (не
  dict-фейк): `window_rows_raw=4`, `window_rows_selected>=1`,
  `render_window_lines` отдаёт 4 строки.
- Initiative до фикса уже делала `[dict(r) ...]`, поэтому её regression
  проходил и до фикса; Direct — падал. Fix сохраняет оба контракта.

## 1. Исходный дефект (RED, base `3a5c6c219`)

На base `3a5c6c219` (`preallocated=True`, window=20×300 chars, current 5000,
reply 5000, budget 1600; чистый `direct_l1`, без БД/LLM):

```text
current_full=False  reply_full=False  overflow=False
used=1409  budget=1600  has_window=True
```

То есть `select_l1_window` забирал весь бюджет, а `_cap_context` затем тихо
срезал P0 current/reply, не сообщая overflow. Это ровно дефект §1.2 Architect.

После UR-11a тот же прогон:

```text

used=5145  budget=1600  has_window=False
```

P0 полный, окно не получает места, overflow честный. Проверка выполнена
временным read-only probe-скриптом; скрипт удалён.

## 2. Что изменено

### `services/direct_l1.py`

- `build_l1_context(preallocated=True)`:
  - fixed-секции (current/reply/trust/bot/diagnostic/participants/hints/
    capabilities/conditions/profile/time/history-range) строятся до окна;
  - `fixed_tokens` считается один раз тем же `count_tokens`;
  - `window_budget = max(1, stage - fixed)`; trigger/reply исключены из
    candidate window (`trigger_message_id`/`reply_to_message_id`, аддитивные
    default None);
  - окно выбирает `direct_context_composer.allocate_window_projection`
    (внутри — существующий `allocate_selection`, политика не менялась);
  - фактический рендер строк ([msg:]/[user:]/имя/разделители) может дать
    небольшой overhead; тот же allocator делает bounded net-fit (≤3), а
    `window_render_overhead` честно показывает разницу. Новых порогов нет;
  - `_cap_context(..., guard_only=True)` — только статус, без `clip_body`
    и без semantic cut; P0 остаётся полным.
- `_cap_context` получил аддитивный `guard_only`; legacy-ветка
  (`preallocated=False`) не менялась.
- `select_l1_window` остаётся legacy/fail-open (docstring обновлён); live L1
  его не вызывает.
- `out_status`/`window_budget_out` несут: `budget_tokens`, `used_tokens`,
  `overflow`, `overflow_sections`, `fixed_tokens`, `window_budget`,
  `window_render_overhead`, `window_rows_raw`, `window_rows_selected`,
  `window_rows_excluded_p0`, `window_preserved`, `window_dropped`.

### `services/direct_context_composer.py` (аддитивно)

- `allocate_window_projection(rows, budget_tokens, p0_ids, fresh_count, ...)`:
  строки окна → P1 fresh/P3 background существующим `row_to_fragment`;
  `p0_ids` (trigger/reply) исключаются как уже доставленные fixed P0;
  выбор — `allocate_selection`; возвращает `(selected_rows, selection)` с
  исходным хронологическим порядком. Строки без `tg/id` получают уникальный
  projection-id, чтобы не склеиваться в один источник.

### `services/direct_chat_service.py`

- Direct L1 (`_plan_direct_l1`): убран `select_l1_window` с полным бюджетом;
  в `build_l1_context` передаются **сырое** окно + trigger/reply ids.
- Initiative L1 (`plan_initiative_decision`): то же; `history_partial`
  вычисляется самим builder'ом по факту drop'а.
- `generate_initiative_reply`: `render_window_lines(..., line_chars=0)` —
  выбранная строка не режется повторно 200-символьным cap.
- Meta/diagnostics: `l1_window_rows_raw/selected/excluded_p0`,
  `l1_window_budget`, `l1_fixed_tokens`, `l1_window_render_overhead`,
  `l1_context_overflow`, `l1_context_used_tokens`, `l1_window_preserved`
  добавлены в существующий `_TURN_DIAGNOSTIC_KEYS` (R17: числа/bool).

### `services/param_catalog.py` (только `EFFECTIVE_STATUS_META`)

- `limits.chat_current_question_max_chars` → `no_op`, consumer `""`.
- `limits.chat_budget_{map,global,thread,rag,target,branch}_ratio` → `legacy`,
  consumer `direct_chat_service (legacy/fail-open)`.
- `limits.chat_global_context_max_{tokens,chars}`,
  `limits.chat_thread_max_{tokens,chars}`,
  `limits.graph_rag_context_max_chars`, `limits.chat_level2_max_chars` →
  `legacy`, consumer `direct_chat_service (legacy/fail-open)`.
- `limits.chat_context_budget_tokens`/`limits.chat_budget_reserve_ratio`
  остаются `active`; значения/override не удаляются; `_PARAM_SPECS` не
  трогались.
