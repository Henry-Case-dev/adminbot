# UNIFIED-REPLY — план внедрения (PM, планировочный документ)

Источник: `plans/owner_inputs/2026-11-05-unified-reply.md` (дословный снимок 503 строк, UR-01..UR-30, редакция 1.1; взят из `plans/current_task.md` L5651-6153).
Карта требований: `requirements-map.json` (254 обязательные строки, все `PENDING`). Машинный граф: `slice-graph.json`.
Основание порядка: §10 источника. Сквозное время §9 (§10 не выделил его отдельным пакетом) оформлено двумя подпакетами `UR-C-CLOCK` и `UR-C-SCHED`.

## Классификация архитектуры

`ARCHITECT_REQUIRED` до Builder для `UR-A`, `UR-C`, `UR-C-CLOCK`, `UR-C-SCHED`, `UR-D`, `UR-F`:
меняются сквозные контракты — `TurnRequest`/`ContextSelection`, единый L1/L2 исполнитель вместо двух реализаций,
`ToolEvidence`, `LLMCompletion` (finish_reason/continuation), `ChatClock`/`TimeSnapshot` и его инъекция во все маршруты,
per-chat планирование Summary/Goodmorning, контракт effective-config для UI, аддитивные миграции ledger.
PM не замораживает эти интерфейсы сам. `UR-B` и `UR-E` исполняются внутри этих контрактов после их фиксации.

## Один писатель на файл

`services/direct_chat_service.py`, `services/direct_l1.py`, `services/param_catalog.py`, стадии саммари и фактчека
имеют последовательных владельцев: `UR-A` → `UR-C` → `UR-C-CLOCK` → `UR-D` → `UR-E`.
Параллельная запись по ним запрещена независимо от размера правки. Git-уровень: каждый Builder работает в своём worktree,
мерж в `evol/impl` в порядке волн, конфликт по общему файлу решается только через зависимость в графе.

## Приёмка и доказательства

- Каждая закрытая строка требует candidate-bound evidence: `artifact_path` (repo-relative), `observation`, `type`; для финальных отчётов — `artifact_sha256`.
- Чеклисты §11 (А-Д) вынесены как `UR-ACC-*` и обязательны; их владелец — `UR-G` (эпическая приёмка), а не отдельный агент.
- Запреты §12 — `UR-BAN-01..09`, каждый привязан к срезу, который обязан их не нарушить.
- `live_required`: `UR-ACC-E9` и `UR-30.7` — на рабочем развёртывании (postdeploy); `UR-08.2` — preprod на размеченном наборе поиска.
- PET_PROJECT: после независимого ревью допустим штатный релиз без отдельного согласования; ручные проверки владельца релиз не блокируют.

## Что не входит

Мем-инициатива и её промпты, переписывание содержательной логики саммари/фактчека/видео кроме сквозного времени,
миграция и переиндексация эмбеддингов, новая агентная инфраструктура, OpenSpec и GitHub Issues как канал поручений.

## Внешние зависимости очереди

UI-пакет ждёт освобождения web-файлов от `EPIC-CM-VISUAL-01`. Backend-пакеты (`UR-A`..`UR-E`, `UR-C-CLOCK`, `UR-C-SCHED`)
от web-файлов не зависят и стартуют в свободных слотах, не прерывая уже идущую работу.
Кроме `web/**`, пересечения с активными пакетами есть только по backend-файлам, которые сейчас не пишет ни один живой Builder;
все такие пересечения перечислены в отчёте PM и снимаются сериализацией по графу.
