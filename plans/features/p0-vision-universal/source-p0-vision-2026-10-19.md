# P0 HOTFIX — универсальная совместимость Vision с любыми провайдерами (снапшот директивы владельца, чат, 19.10.2026)

> Приоритет P0. Добавлено в общую очередь; не прерывает уже выполняемые задачи; выполняется в ближайшем безопасном окне, затем автоматически продолжается `current_task`.

После настройки `google/gemma-4-31b-it:free` через OpenRouter проверка возвращает `vision_unavailable`. В Analytics повторяются `vision_capability_probe failed`, а `VisionMediaWorker` иногда пропускает тики из-за занятого экземпляра.

**Принципиальное требование: это НЕ исправление исключительно для OpenRouter или Gemma. OpenRouter используется только как воспроизводимый пример. Vision должен корректно работать с любым совместимым провайдером и любой моделью, поддерживающей изображения.** Без хардкода под модели/провайдеров/URL/форматы.

## 1. Универсальная архитектура подключений
- Любые OpenAI-compatible endpoints с изображениями.
- Разные base URL, включая `/v1`, `/api/v1` и др. префиксы.
- Смена моделей/провайдеров без изменений кода.
- Разделение конфигурации основной модели и выделенной Vision-модели.
- Пользовательские ключи и настройки.
- Для другого формата API — адаптер в рамках поддерживаемых типов; не отправлять несовместимый OpenAI payload; для неподдерживаемого протокола — конкретная причина.
- Не допускать: двойного `/chat/completions`, неправильной сборки URL, смешивания ключей разных провайдеров.

## 2. Универсальная проверка возможностей (`services/mca_vision.py`)
1) Тестовый запрос с валидным изображением подходящего размера (не прозрачная PNG 1×1).
2) Отдельно: доступность модели и поддержка мультимодального ввода.
3) Различать: конфигурацию, авторизацию, отсутствие модели, неподдерживаемую модальность, некорректное изображение, rate limit, таймауты, сбои провайдера.
4) HTTP 400 ≠ доказательство отсутствия Vision.
5) Временную недоступность НЕ кешировать как постоянную несовместимость.
6) При смене модели/ключа/endpoint/типа API — инвалидация capabilities и повторная проверка.
7) Диагностика без раскрытия ключей/чувствительных данных.
**Capability detection — по реальному ответу API, а не по списку известных моделей/провайдеров.**

## 3. Сквозной pipeline
Настройки → сохранение → разрешение маршрута → capability probe → постановка задания → VisionMediaWorker → запрос провайдеру → структурированный результат → сохранение → использование в контексте бота.
Проверить: переключение провайдера без правок кода; основная/резервная модели по конфигурации; fallback не скрывает ошибки и не переключается на несовместимую модель; самовосстановление после временного сбоя; worker без дублей задач и без зависаний при долгих запросах; изображения реально распознаются и используются в контексте.
Не ограничиваться кнопкой «Проверить подключение».

## 4. UI и диагностика
- Вместо `vision_unavailable` — понятная причина («Неверный ключ», «Превышен лимит», «Модель не принимает изображения», «Провайдер временно недоступен»).
- Убрать артефакт `function () { [native code] }`.
- Исправить горизонтальное переполнение формы и неудобную компоновку Android.
- Отображать фактического провайдера, модель, тип подключения и результат проверки.
- Не раскрывать секреты и полные значения ключей.

## 5. Тестирование и завершение
Тесты с несколькими провайдерами/моделями: OpenRouter (воспроизводимый случай); другой OpenAI-compatible endpoint; провайдер с отдельным API-адаптером (если предусмотрен архитектурой); модель без Vision; неверный ключ, неправильный URL, 429, 5xx, таймаут; смена провайдера во время работы. Для недоступных внешних сервисов — контрактные моки, честно отделённые от живых проверок.
**Критерий завершения:** Vision работает через универсальный механизм, не зависит от OpenRouter/Gemma, корректно определяет возможности, обрабатывает ошибки, восстанавливается после временных сбоев и реально распознаёт изображения.

Использовать существующий workflow, независимый Reviewer и штатный деплой. Не создавать отдельный эпик, не дублировать реализованное, не отменять существующие задачи. После завершения автоматически продолжить `current_task` с прежней позиции.
