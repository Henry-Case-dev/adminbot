# ADR-1028-19 — `mca-19-image-understanding`: понимание изображений в исходном сообщении и позднее обогащение

**Статус:** **Proposed** (06.10.2026, Step 2 @Architect, T-5098/T-5099) → Accepted по merge `plans/ARCHITECTURE.md` (следующий фактически свободный раздел после §122+, mca-19 → прод-валидация; прецедент ADR-1028-18).
**Контекст:** §29 `plans/current_task.md:1608–1745`; план Wave 4 `plans/docs/mca-round1027-plan.md:163–169/:210/:242–244`; PM-наработка `requirements-map.md` (MCA19-R1…R7, CA-19-1…12, §5 — 12 открытых вопросов). Baseline: HEAD `2d4e3ad`, прод 2.58.62, SQLite v31, каталог 510, kill-switches 76, reason_code 257, канон тулов 12. ADR-1028-18 занят mca-18; **1028-19 свободен** (grep plans/** 06.10.2026).
**Risk: R3 (confirmed).** **Deploy: CA-11, пер-фичевый bump 2.58.63.** Threat: `threat-failure-analysis.md` (этой папки).

## Решения

**D1. Один контур понимания.** Единый сервис анализа `services/mca_vision.py` (auto/manual/tool/backfill — один вход, один планировщик mca-01/task_jobs, один renderer, один процесс `vision.media` mca-17a). Второй vision-пайплайн, второй планировщик, второй renderer, второй словарь событий запрещены (CA-19-1/2/9). `services/image_generation.py` — генерация, не трогается (`:1620`); «vision»-комментарий в LLM-клиенте не принимается за pipeline (проверено grep HEAD: законченного входящего vision-контура нет).

**D2. Канон сообщения — AMEND mca-03, Origin-блок.** mca-03 (v16, `database.py:245–264`, `save_smart_message_identity:6278`) уже даёт стабильный ключ `(chat_id, tg_message_id)`, sent_at/ingested_at/edited_at, caption отдельно, content_hash, current_revision, `sent_at_source=legacy_unverified`. mca-19 добавляет только недостающее: `ALTER TABLE smart_messages ADD COLUMN` ×10 nullable (sender_chat_id, origin_type, origin_sent_at, origin_sender_user_id, origin_chat_id, origin_message_id, origin_display_name, origin_author_signature, thread_id, media_group_id). Старые строки — legacy/unknown без переписывания времени (`:1622`). AMEND: `summary_observer` (`summary.py:193`, ingested_at=`int(time.time())` :259 — остаётся, sent_at/origin берутся из Telegram), `save_smart_message` (`database.py:6061`), `wrap_media_fact` (`media_common.py:62` — event-time исходника для image-фактов). Три роли атрибуции различны: отправитель ≠ оригинальный автор ≠ автор текста на изображении (CA-19-3).

**D3. Схема v32: MediaAsset/MediaAnalysis.** `mca_media_assets` (asset_id PK, message_key, chat_id/tg_message_id, asset_kind, file_id, file_unique_id, size_variant, content_hash, mime, byte_size, width/height, media_group_id, revision; idx ×3) + `mca_media_analyses` (asset_id, access_scope, analysis_schema_version, analyzer_provider/model/config_revision, prompt_version, quality_profile, status CHECK ∈ {pending, running, ready, no_text, unreadable, unsupported, unavailable, failed}, revision, ocr_blocks JSON, visual_description, uncertainty, source_coordinates, quality_flags, error_reason, self_reported_confidence — имя фиксирует «self-reported ≠ точность», config_revision, времена; UNIQUE (asset_id, access_scope, analysis_schema_version, analyzer_config_revision, quality_profile, revision); idx (access_scope, status)). **Δ DDL = v32 (не 0):** без реальных колонок/ограничений невозможны CAS/fencing по revision, idempotent upsert `:1683`, atomic singleflight и честный legacy; JSON-блоб в smart_messages смешал бы raw с производными и нарушил контракт mca-03. PG — no-op (GEN-R4). Δ DDL ≠ 0 отвергнут.

**D4. Маршрут модели: отдельная → основная → честная авто-деактивация.** Порядок `:1642–1646`: (1) валидное отдельное подключение; (2) эффективная основная диалоговая через действующий резолвер (никаких background/embedding/image-gen/запасных; унаследованное глобальное vision = «задано», «не задано» оценивается после резолва scope); (3) основная без image input → `effective_enabled=false, reason=main_model_no_vision` + видимая причина, без base64-заглушек и очереди повторов. Capabilities — по адаптеру + пробному запросу с нейтральным изображением; `capability_check_pending` для неизвестного; **таймаут/401/403/429 ≠ no_vision** (ошибка доступа/временная + ограниченный retry; CA-19-10). Пользовательский OFF приоритетен; авто-деактивация обратима (перепроверка при смене модели/подключения → авто-возобновление, `:1652`); кеш capabilities по provider/endpoint/model/config_revision; старые jobs хранят свой config revision. Битая форма не сохраняется как рабочая; явный сброс отдельного подключения = включение fallback; ключ одного профиля не смешивается с endpoint другого.

**D5. Хранение настроек и секретов — существующий каталог + защищённое хранилище.** Группы по образцу `models_images`/`keys_images`/`keys_random` (`param_catalog.py:186/:209/:214`): `models_vision` (провайдер/endpoint/model ID), `keys_vision` (API key — маска, пустое маскированное поле = «оставить сохранённый», возврат открытым текстом запрещён), `limits_vision` (качество/очередь/антиспам — значения владельца), `flags_module_vision` (тумблер модуля). Эффективное состояние (requested/effective + причина) — производный рендер, не новые параметры. Новый обязательный провайдер/аккаунт не вводятся (GEN-R2).

**D6. Транспорт: getFile + SafeFetcher, токен не наружу.** Telegram-медиа — только Bot API getFile; bytes после безопасной загрузки (MIME-сниффер + факт-формат, max bytes/pixels, таймауты, лимит параллельных загрузок, cleanup). URL с bot token не передаётся внешней модели и не логируется (R17). Произвольные внешние ссылки — только SafeFetcher mca-02 (`MCA_SAFE_FETCH_ENABLED`/`MCA_EGRESS_GUARD_ENABLED` уважаются); cookies/profile видеосервисов не трогаются. Decompression-bomb — лимит декодированных пикселей (env-потолки клампят владельческие значения).

**D7. Рендер: enrichment-in-place, два времени, replay-режимы.** Единый renderer для всех путей (`:1668`); структура `:1670–1677` с явными лейблами («OCR, не слова Васи», «результат модели», «Распознано: …; версия анализа»). Pending — на месте исходника с известной подписью; ready — атомарное обновление projection/revision, raw сохраняется; без нового chat-message/замены подписи/публикации в Telegram (CA-19-2). Сортировка live — по событию; импорт — historical; replay до completed_at — «что бот тогда знал» без распознавания / «нынешняя реконструкция» с меткой (прецедент mca-06). Completion — idempotent upsert; зависимые FTS/vector/summary/episode — механизм mca-04/07, без лишнего embedding. Fencing/CAS по revision запрещают старому job перезапись/воскрешение; удаление — по доступным приложению данным. Вне окна — reply/retrieval, не «свежий» хвост; коррекция ошибочного ответа — отдельное отслеживаемое действие.

**D8. Кеш содержимого ≠ контекст публикации.** Ключ анализа = `access_scope + content_hash + analysis_schema_version + quality_profile`; `file_unique_id` — ранний поиск, не адрес скачивания; perceptual hash — только кандидаты (разные надписи не склеиваются). Переиспользование готового успеха без vision-вызова; singleflight с атомарной уникальностью (UNIQUE-гранула D3 + coalesce task_jobs), включая несколько workers; автор/дата/пересылка — всегда из текущего сообщения; права/приватность не переносятся между чатами (CA-19-5/8). Failed/pending ≠ success-кеш; TTL без массового переразбора; удалённое из кеша не восстанавливается.

**D9. Очередь/антиспам: один планировщик, bounded, справедливый.** task_jobs mca-01 (durable, checkpoints) — второй движок запрещён. Стартовый профиль `:1721`: 2 одновременных vision, 100 готовых, token bucket 10/мин+burst 10 (участник), 60/мин+burst 30 (чат) — владельческие значения (limits_vision), env-потолки клампят; защита от лавины ≠ денежный лимит. Избыток — durable deferred со ссылкой на исходник, TTL/cap, истечение → skipped с причиной; manual > auto > backfill; retry backoff/jitter/Retry-After; circuit breaker при массовом сбое; повторный update ≠ второй job; повтор с неизвестным исходом — отдельный учёт риска расхода; завершение фона не отправляет сообщений. Аналитика: cache hit/coalesced/deferred/rate limited/queue age/retry/usage/причины.

**D10. Tool `recognize_image` в общем пуле.** Аргументы: target MessageRef, asset_selector?, question?; scope/права из доверенного runtime; от LLM не принимаются URL/API key/модель/флаги обхода. ToolResult: status ∈ {ready, pending, disabled, unavailable, ambiguous, failed} + source refs + analysis revision + cache_hit + job_id + причина. OFF: инструмент скрыт + серверная проверка устаревших вызовов. Канон 12→13 (подтверждено grep: 12 различных, `generate_image`×2 схемы); добавляется в `METERED_TOOLS` (`tool_loop.py:57`). Отдельная vision-модель обслуживает текстовую основную; разговор не переключается на vision-модель (`:1745`). Pending — shared job через координатор, без LLM-опросов; ≤1 ответ на trigger.

**D11. Производные факты, инъекции, фактчек.** SourceRef mca-04a до `message + asset + analysis revision + OCR block`; «так написано» ≠ «это верно». Инструкции в изображении/подписи (включая фейковый system-скриншот) — недоверенные данные: не меняют system prompt/настройки/инструменты/личность (GEN-R18 `:43`; CA-19-4). Фактчек по reply на photo разрешает тот же asset; claim в caption/OCR/сочетании с указанием части; отсутствие текста ≠ ложность; описание модели ≠ экспертиза подлинности. **Контракт mca-20 заморожен:** ClaimEnvelope ↔ `(asset_id, analysis revision)` + селектор `caption|ocr_block:<i>|combined` через SourceRef (§30.1 `:1763`) — mca-20 не запускает свой vision.

**D12. UI: существующие поверхности.** Тумблер — в существующем списке модулей; подключение — по образцу настроек моделей; качество/очередь/антиспам — в настройках модуля; диагностика — в «Аналитике»; обязательные ссылки тумблер↔подключение↔диагностика; альтернативный экран запрещён. Requested/effective раздельно с пятью причинами («выключено владельцем»/«нет совместимой модели»/«проверка подключения»/«временно недоступно»/«работает»). Без рестарта; OFF гасит авто/ручной/tool; начатый запрос — отменить/сохранить без новых реплик; включение не разбирает архив самопроизвольно.

**D13. Санкции (согласованы со spec §8 и arch-frames §1.2.8):**

## Последствия

- Позитив: бот понимает изображения внутри исходного поста (без ложных «только что написал Вася»), честные статусы/атрибуция/времена, антиспам bounded, OFF бит-в-бит, mca-20 получает замороженный контракт.
- Негатив/цена: v32 (+2 таблицы, +10 колонок), F8-переиздание (+9 параметров), новый внешний API-контур (расход vision-токенов — учтён категорией), 4 новых kill-switch. Deferred/backfill — отложенная нагрузка на task_jobs.
- Откат: soft (env) без потери данных; cold revert безопасен (аддитивная схема). Данные кеша/анализов переживают откат.

R17: секретов в ADR/spec/threat нет; примеры чужих моделей из §29.8 в настройки не копируются (`:1745`).
