**D3. Атрибуция — три роли различны** (REUSE mca-03 identity + mca-04a SourceRef + mca-22 паттерн; CA-19-3): **отправитель** (кто принёс в чат) ≠ **оригинальный автор** (Origin) ≠ **автор текста на изображении** (распознанное утверждение). Sender не подменяется оригинальным автором и наоборот (`:1622`); «я увольняюсь» на картинке — слова на изображении (`:1612`); переславший мем не автор текста и не сторонник утверждений (`:1658`).

**SC-R1a (→A64):** картинка без подписи обрабатывается (asset создаётся, caption=NULL — валидно); история не превращается в дубликаты текста/медиа (lookup `(chat_id, tg_message_id)` + уникальность asset-гранулы); альбом — каждый item свой asset + общая `media_group_id`, подпись первого не размножается (`:1656`).
**SC-R1b (→A65):** событие 12:00 и обработка 12:07 хранятся как два разных времени; `sent_at` ≠ `ingested_at` ≠ `completed_at`; старые строки честно `legacy/unknown`.
**SC-R1c:** sender/origin/автор-на-картинке различимы во всех записях и рендерах; forward не переписывает автора.
**SC-R1d:** пять статусов анализа различимы; confidence помечен self-reported; uncertainty обязательна в выходе.

## 2. Подключение vision-модели и безопасность (MCA19-R2; T-5103–T-5106)

**D4. Группа «Модель распознавания изображений» — по образцу существующих групп каталога** (прецеденты `models_images`/`keys_images`/`keys_random`, `param_catalog.py:186/:209/:214`): провайдер/тип API (существующий адаптер), endpoint (стандартный наследуется из профиля), Model ID, ключ — через группу keys (маска, защищённое хранилище), «Проверить подключение» (доступность + поддержка image input + причина ошибки). Рядом: основной маршрут, фактически выбранные provider/model, источник конфигурации (отдельная/основная), поддержка изображений, effective status, последняя проверка (`:1640`). Секрет не возвращается открытым текстом; пустое маскированное поле = «оставить сохранённый»; очистка отдельного подключения — явное действие; **не смешивать ключ одного профиля с endpoint другого**; global/chat наследование — существующий контракт. Незаполненная форма не сохраняется как рабочая: ошибки полей, прежняя конфигурация остаётся; ошибочно настроенную отдельную модель не подменять основной молча; явный сброс включает fallback (`:1648`).

**D5. Обязательная последовательность выбора маршрута** (`:1642–1646`):
1. Валидное сохранённое отдельное подключение → эта модель.
2. Иначе — эффективная основная диалоговая модель чата **через действующий резолвер моделей**; НЕ background/embedding/image-generation/случайная запасная. Унаследованное глобальное vision-подключение = «задано»; «не задано» оценивается после резолва scope.
3. Выбранная основная без image input → авто-деактивация: `effective_enabled=false`, `reason=main_model_no_vision`, видимая причина «Распознавание отключено: основная модель не поддерживает изображения…»; **никаких** отправок ей изображений/base64/фиктивных текстовых запросов и бесконечной очереди повторов.

**D6. Capabilities и requested/effective:** поддержка image input — по достоверным capabilities адаптера/модели **и** пробному запросу с нейтральным тестовым изображением (не по названию модели); неизвестная совместимость → `capability_check_pending`; **таймаут/401/403/429 ≠ отсутствие vision** — фиксируется ошибка доступа/временная недоступность + ограниченные retry, без ложного `main_model_no_vision` (`:1650`). Пользовательский OFF приоритетен; авто-деактивация не переписывает намерение: смена основной модели или сохранение рабочего подключения → перепроверка и авто-возобновление (`:1652`). Кеш capabilities ключуется `provider/endpoint/model/config_revision` (не сетевой запрос на каждую фотографию); старые задания хранят свой config revision; возобновление пропущенных — отслеживаемый backfill без самопроизвольных реплик.

**D7. Безопасная загрузка/передача** (`:1662`): Telegram-файл только через Bot API getFile; **URL с bot token не передавать внешней vision-модели и не логировать**; наружу — bytes/поддерживаемый upload после безопасной загрузки. Произвольные внешние ссылки — только через SafeFetcher mca-02 (`MCA_SAFE_FETCH_ENABLED`/`MCA_EGRESS_GUARD_ENABLED` уважаются). Лимиты: одновременные загрузки, декодированные пиксели, validate MIME **и фактического формата** (сниффер, не доверять заголовку), timeouts, max bytes, decompression-bomb protection, cleanup временных файлов после завершения/отмены. Cookies/profile видеосервисов не трогать.

**D8. Выход анализа разделён** (`:1658–1660`): (1) буквальная транскрипция видимого текста, (2) краткое описание визуального содержимого, (3) предположения/неопределённости — раздельные поля (`ocr_blocks`/`visual_description`/`uncertainty`). Имя/дата на скриншоте — распознанные утверждения, не проверенные Telegram metadata; авторство лиц не устанавливается по внешнему сходству. Не уменьшать изображение до потери мелкого текста без причины; длинные скриншоты — ограниченные перекрывающиеся фрагменты с координатами и дедупом строк; повторное чтение сомнительного фрагмента — в пределах технического бюджета (env-лимит попыток), без бесконечной самопроверки; конфликт OCR/подпись/картинка — **сохранить**, не разрешать молча.

**SC-R2a (→A74):** маршруты «отдельная задана / пусто → основная / основная текстовая → честная авто-деактивация / смена основной модели → авто-возобновление» — все корректны; ошибки доступа не записаны как `main_model_no_vision` (тест на 401/403/429/таймаут).
**SC-R2b:** форма не сохраняется при невалидных полях; секреты маскированы; «оставить сохранённый»/явный сброс работают; effective и источник конфигурации отображаются.
**SC-R2c:** токен бота отсутствует в запросах к VLM и логах; ключ не возвращается открытым текстом (Scanner-проверка).
**SC-R2d:** фрагментация ограничена бюджетом; мелкий текст не теряется без причины; конфликт сохранён.

## 3. Рендер контекста и позднее завершение (MCA19-R3; T-5110–T-5112)

**D9. Единый renderer — одна функция-фасад для всех путей** (direct/autonomous/Summary Hybrid/RAG/истории/сон/фактчек; `:1668`). Смысловая структура (не буквальный шаблон, `:1670–1677`): строка исходника `[время | автор | msg:chat/id | изображение]`; «Переслано из …, исходная публикация …»; «Подпись отправителя: …»; «Текст на изображении (OCR, **не слова Васи**): …»; «Визуальное описание (результат модели): …»; «Распознано: …; версия анализа: N». Pending на том же месте: «изображение, содержание ещё не распознано» + известная подпись (`:1679`).

**D10. Два времени и enrichment-in-place:** сообщение существовало в чате (`sent_at`) ≠ бот получил знание о содержимом (`completed_at`). После ready — **атомарное** обновление projection/revision исходной записи; raw-message и оригинальные media сохраняются; **не** добавлять OCR в хвост новым chat-message, **не** заменять подпись, **не** публиковать изменённый пост в Telegram; «на место поста» = представление того же события в контексте (`:1679`). Сортировка live-истории — по исходному событию, не completed_at; импортированные посты — historical event time (`:1681`). Replay до completed_at: режим «что бот тогда знал» — без распознавания; режим «нынешняя реконструкция» — с явной меткой (прецедент mca-06). Completion — idempotent upsert по `(asset, analyzer version)`; зависимые FTS/vector/summary/episode обновляются механизмом mca-04/07; при неизменном результате embedding не перезапускается. **Fencing/CAS**: старый job не перезаписывает новую картинку/подпись и не воскрешает удалённую запись (CAS по `revision` строки asset/analysis + `message_state` mca-03); удаление обрабатывается, когда известно приложению; Bot API ≠ универсальный источник удалений (`:1683`). Сообщение вне окна — не «свежим» в конец: подтягивается релевантным reply/retrieval; late-context event может обновить зависимую сводку; новая автономная реплика не обязательна (обычный контроль уместности/дедуп); коррекция уже данного ошибочного ответа — отдельное отслеживаемое действие со ссылкой на старый ответ, не спам после каждого OCR (`:1685`).

**D11. Shared job и конкурентность** (`:1687`): два одновременных вопроса об одном изображении → один job (singleflight, §6); прямой запрос может ограниченно ждать ready; timeout → честный ответ о недоступном содержимом либо продолжение по известной подписи. Одинаковые bytes — переиспользование анализа в разрешённом scope; **автор/дата/пересылка всегда из текущего сообщения**; ссылочные права и приватные данные одного чата не переносятся в другой вместе с кешем.

**SC-R3a (→A65):** сценарий 12:00→12:07: в истории один пост на прежнем месте; 12:01 не сдвинулось; event time ≠ knowledge time видны в рендере.
**SC-R3b (→A66):** поздний stale job после edit/delete/нового анализа — отброшен CAS/fencing; нет дублей и воскрешённой записи; нет нового chat-message в хвосте.
**SC-R3c:** конкурентные запросы коалесцируются в один job; кросс-чат-утечка прав/данных отсутствует (негативный тест).

## 4. Память, фактчек, архив, наблюдаемость (MCA19-R4; T-5113–T-5116)

**D12. Производные факты и трассировка** (`:1693`): каждый производный факт — SourceRef mca-04a до `message + asset + analysis revision + OCR block` (гранулярность блока — обязательна); фабрикация запрещена. Статус «так написано на картинке» отделён от «это верно». **Инструкции внутри изображения/подписи — недоверенные данные** (GEN-R18, `:43`): не меняют system prompt, настройки, инструменты, личность — включая скриншот интерфейса/текст с фальшивой ролью system (канал данных, а не инструкций; лейблинг + изоляция в рендере, тест A67).

**D13. Фактчек по фото** (`:1695`): reply-фактчек на photo разрешает **тот же asset**, а не отвечает «нет текста»; Claim может быть в caption, OCR или сочетании — выбор сохраняется с указанием части и неопределённости; отсутствие текста ≠ доказанная ложность; визуальное утверждение требует отдельного подтверждения; описание модели ≠ экспертиза подлинности. **Контракт для mca-20 (замораживается здесь, §30.1 `:1763`):** ClaimEnvelope ссылается на MediaAnalysis парой `(asset_id, analysis revision)` + селектор части `caption|ocr_block:<i>|combined` через mca-04a SourceRef — mca-20 не читает пиксели и не запускает свой vision.

**D14. Архивный backfill** (`:1697`): только по доступным файлам/работоспособным ссылкам; текстовый Telegram export сам по себе без изображений — недоступные assets помечаются `missing_source`, без «восстановления из догадок»; очередь с checkpoints, приоритет live над архивом, технические caps, видимый прогресс.

**D15. Наблюдаемость (GEN-R17):** процесс **`vision.media` v1** в реестре mca-17a (code-declared, прецедент `sleep.deep` `mca_process_registry.py:163`); стадии точно `:1699`: `ingest → download → decode → vision → validate → store → project → reindex → consumers`. В «Аналитике»: возраст очереди, длительности, исходная/производная версии, неполный OCR, late arrival, stale result discarded, цена/usage; причины unavailable честные — «зрение» не рисуется по факту отправки запроса. Просмотр оригинала — под действующими правами; в общих логах нет bytes/base64 и полного OCR приватных сообщений. Витрина — компактное превью последнего разбора (`:1614`), без нового раздела/маршрута.

**SC-R4a (→A67):** инструкция в изображении не повышается до системной и не меняет настройки/личность; производный факт трассируется до OCR block.
**SC-R4b (→A68):** timeout/недоступная модель/нет файла в архиве → честный статус и причина (`unavailable`/`missing_source`), без выдуманного OCR; ресурсы ограничены.

## 5. Тумблер и размещение настроек (MCA19-R5; T-5117)

**D16. Размещение — без альтернативного экрана** (`:1707`): главный тумблер «Распознавание изображений» — в существующем списке модулей (стиль/права/scope те же; прецедент `flags_module_images` `param_catalog.py:365`); подключение §29.2 — по образцу настроек моделей (группы models/keys); качество/очередь/антиспам — в настройках модуля (группа limits); результаты/диагностика — в «Аналитике»; обязательные ссылки тумблер↔подключение↔диагностика.

**D17. Requested vs effective и OFF-семантика** (`:1709`): requested ON/OFF отображается отдельно от effective: «выключено владельцем» / «нет совместимой модели» / «проверка подключения» / «временно недоступно» / «работает». Изменения действуют **без перезапуска** (runtime-флаг, не env-restart). OFF запрещает новые автоматические и ручные vision-вызовы, включая tool calling; уже начатый запрос отменяется по возможности, иначе результат сохраняется без новых реплик/продолжений. Сохранённое распознавание читается без нового API-вызова, с указанием происхождения. Включение не запускает разбор всего архива: новые — автоматически, старые — по запросу или контролируемым backfill. Обычный участник не включает модуль разговорной командой (владелец-флаг).

**SC-R5a (→A75):** тумблер рядом с модулями; requested/effective различны и оба видны; пять effective-причин различимы.
**SC-R5b:** OFF (UI, без рестарта) блокирует авто/ручной/tool вызовы; начатый запрос не порождает новых реплик; сохранённое читается офлайн.
**SC-R5c (→A81):** разговорная команда участника не меняет состояние модуля; включение не запускает массовый разбор архива.

## 6. Автообработка, кеш, очередь, антиспам (MCA19-R6; T-5107–T-5109)

**D18. Автоочередь с первого релиза** (`:1715`, `:1656`): все доставленные боту поддерживаемые изображения в разрешённых чатах — photo, документы-изображения, каждый элемент альбома; статические стикеры — если доступны как raster input. Без требования подписи/ключевого слова. Альбом: каждый item + общая связь; подпись первого фото не переносится как OCR остальных. Анимация/видео — своим пайплайнам; `unsupported` помечается явно. «Все» ≠ доступ к недоставленному и ≠ обещание успеха на повреждённом файле. **Сначала реестр/запись сообщения, затем durable job** (порядок инверсии недопустим). Отдельного бот-поста с OCR нет по умолчанию (CA-19-2).

**D19. Кеш содержимого ≠ контекст публикации** (`:1717–1719`): ранний поиск — `file_unique_id` с учётом вариантов размера; после загрузки — криптографический `content_hash` (при необходимости hash нормализованных пикселей). Ключ анализа = `access_scope + идентичность содержимого + analysis_schema_version + quality_profile`; смена модели сама по себе не инвалидирует успешные результаты (analyzer_config_revision в ключе upsert, не в ключе переиспользования). Perceptual hash — только поиск кандидатов: похожие мемы с разной надписью не склеиваются без проверки. `file_unique_id` ≠ адрес скачивания (загрузка по `file_id`). Совпадение готового успешного анализа → переиспользование без vision-запроса; совпадение выполняемого задания → подписать MessageRef на тот же job — **singleflight с атомарной уникальностью в хранилище, включая несколько workers** (UNIQUE-гранула D2 + coalesce task_jobs mca-01). Failed/pending не становятся success-кешем. TTL/очистка не превращают повторы в массовый переразбор: компактный индекс + результат в политике хранения; удалённые данные не восстанавливаются из кеша.

**D20. Один планировщик и защита от лавины** (`:1721–1723`): единственный планировщик обслуживает auto/manual/tool/backfill. REUSE `task_jobs`/TaskSupervisor mca-01 (durable, coalesce, checkpoints) — второго движка очереди нет. Ограничения (стартовый профиль, значения владельцу, уточняются нагрузочной T-5122): 2 vision-запроса одновременно, 100 готовых заданий, 10 новых уникальных изображений/мин на участника (burst 10), 60/мин на чат (burst 30) — token bucket; это защита от лавины, не денежный лимит. Cache hit не тратит vision-токены. Избыток — deferred со ссылкой на исходник, продолжение справедливо по отправителям; устойчивый спам не раздувает очередь в памяти (deferred — durable строки task_jobs, ограниченный срок/объём; истечение → `skipped` с причиной + возможность ручного запроса). Приоритеты: manual > auto (с защитой от вытеснения), backfill ниже live. Retry — ограниченные, backoff/jitter/Retry-After; массовый сбой → circuit breaker без бесконечного обхода моделей. Повторный входящий update ≠ второй job (idempotency-ключ). Повтор сетевого вызова с неизвестным исходом — отдельный учёт риска повторного расхода (без обещания exactly-once внешнего API). Завершение фонового распознавания само не отправляет сообщение. Аналитика: cache hit/coalesced/deferred/rate limited, длина/возраст очереди, retry, отказы, фактический usage, причина по каждому исходнику.

**SC-R6a (→A76):** все элементы альбома/документы/фото учтены без подписи; OCR не отправляется в чат; подпись не размножена.
**SC-R6b (→A77):** один анализ на эквивалент содержимого; cache hit — 0 vision-токенов; повторный update не создаёт второй job.
**SC-R6c (→A78):** похожие изображения с разными надписями не склеиваются (perceptual-кандидат проходит проверку content/hash).
**SC-R6d (→A79):** поток изображений + 429 + рестарт процесса: ресурсы ограничены, очередь справедлива по отправителям, deferred виден с причинами, диалог не заблокирован.

## 7. Старые картинки, естественный запрос, tool (MCA19-R7; T-5118–T-5120)

**D21. Резолв намерения и target** (`:1729–1731`): в существующем маршруте обращений (имя/алиасы бота): «что на картинке», «опиши фото», «прочитай скрин», «что тут написано» + смысловые варианты. Ключевые слова — быстрый маршрут, не единственный способ вызова и не глобальный триггер на чужую цитату. Приоритет target: reply на изображение → собственное вложение запроса → однозначная ссылка на доступный пост → однозначный контекст ветки; несколько кандидатов → уточнение (не случайный «последний»). Альбом: reply на элемент выбирает его; «разбери весь альбом» — доступные элементы с явными пределами. Без перехода в другой чат без разрешённого доступа. Reply может **зарегистрировать ранее неизвестный старый пост** из доступного `reply_to_message` с исходными метаданными; иначе — поиск в собственном реестре; Bot API не даёт универсальной выгрузки истории по ID: нет bytes/file_id → попросить переслать/прикрепить; не восстанавливать изображение из соседнего текста; момент запроса ≠ дата исходного поста.

**D22. Tool `recognize_image`** (`:1733`): регистрируется в общем пуле tool calling (канон 12→13, §8). Аргументы: `target` MessageRef, необязательный `asset_selector`, необязательный `question`; chat scope и права — из доверенного runtime; **не принимать от LLM** произвольный URL, API key, модель или флаг обхода ограничений. Результат — действующий ToolResult: `status ∈ {ready, pending, disabled, unavailable, ambiguous, failed}`, source refs, analysis revision, описание/OCR/неопределённость, `cache_hit`, `job_id`, стабильная причина. При отключении инструмент скрывается из доступного набора, но сервер всё равно проверяет OFF для устаревших вызовов (defence in depth). Отдельная vision-модель позволяет основной текстовой пользоваться инструментом; клиент основной модели не обязан принимать изображения; последующие вопросы не переключают разговор на vision-модель (`:1745`).

**D23. Один сервис для auto/manual/tool + pending-семантика** (`:1735–1737`): если готового анализа достаточно — вернуть его; уточняющий вопрос сначала решается по нему; новый вызов допустим только для реально отсутствующей детали/нечитаемого фрагмента — с причиной, версией и дедупом эквивалентных вопросов; повторение «что на картинке» не принуждает к повторному vision; принудительная переобработка — отдельное действие владельца с аудитом (не аргумент модели). Pending → связать с существующим job, **без LLM-опросов**; после завершения — возобновление через координатор и **не более одного ответа на trigger** (повторная доставка trigger ≠ новый ответ); затянувшийся — один статус ожидания с последующим обновлением; новый явный вопрос другого участника — собственный ответ из того же кеша. Смена/удаление исходника проверяется перед использованием; при ручном OFF — объяснить, что модуль отключён.

**SC-R7a (→A80):** старый доступный пост распознаётся по reply и появляется на исходном месте; разбор всего архива не запускается.
**SC-R7b (→A81):** неоднозначный target → уточнение; нет файла → просьба прислать; OFF → внятное объяснение.
**SC-R7c (→A82):** общий ToolResult/ACL; pending без LLM polling; ровно один ответ на trigger (повторная доставка — тест).
**SC-R7d (→A83):** сначала кеш; дополнительный vision-вызов только с причиной/версией; эквивалентные вопросы дедуплицируются.
