# ADR-1020-6 — Формат доставки длинных историй «Летописца» (конфликт markdown vs plain-text и канон 1–2 предложений)

- **Статус:** 🟢 **Принято** (Step 2 @Architect, 16.09.2026; **AMEND ред. 2** — решение О5 FINAL)
- **Раунд:** 10.20, фазы C + D, задачи T-1886…T-1893 (доставка), T-1894 (UI-контракт)
- **Спека:** [`spec.md`](spec.md) §3.4, §3.5
- **Аудит-основание:** `round1020_llm_engine_audit.md` §Q2.2-4/5 (расхождение №7 ТЗ и кода)
- **Связанные ADR:** [ADR-1020-4](adr-1020-4-lore-compiler-tool.md), ADR-1015-3 (tool calling)

## Контекст

ТЗ БЛОК 1 задаёт storytelling-промпт с требованием **маркдауна и жирного выделения** и многопараграфной структурой.
Фактическое состояние кодовой базы:

1. **Доставка — plain-text.** `send_chunked_reply(bot, chat_id, text, reply_to_message_id, ..., parse_mode=None)`
   (`services/smartmodule_utils.py:113-120`, `:143`) — markdown/HTML не рендерится; `rich_message` в репозитории отсутствует.
   Каноничный ответ DirectChat вообще **запрещает маркдаун** (`services/chat_prompts.py:160`).
2. **Канон длины.** `CHAT_SYSTEM_PROMPT` требует «ОЧЕНЬ коротко… СТРОГО ИЗ ОДНОГО ИЛИ ДВУХ ПРЕДЛОЖЕНИЙ»
   (`services/chat_prompts.py:171-172`). Финальный текст истории проходит через тот же ответ DirectChat
   (`direct_chat_service.py:656-663`) — значит история будет обрезана/переписана каноном.
3. **Пост-обработка ответа — одна строка кода.** `answer = str(raw).strip()` (`:656`) — ни среза тегов, ни выбора
   формата по интенту.
4. Чанкование уже есть (4096, `smartmodule_utils.py:130`) — технический предел длины не проблема.

Итог: без отдельного решения БЛОК 1 в текущем пайплайне **не может** выдать историю в требуемом виде.
Это скрытый P0-блокер эпика, не описанный в ТЗ.

## Решение

1. **Изоляция синтеза** (ADR-1020-4 п.3): история генерируется внутри инструмента своим каноном
   (`LORE_STORY_SYSTEM_PROMPT`), а не диспетчерским `CHAT_SYSTEM_PROMPT` → канон «1–2 предложения» на неё не действует.
2. **Детерминированный сигнал режима:** инструмент выставляет `ToolContext.lore_compiled = True`;
   DirectChat после `chat_with_tools` проверяет флаг и применяет **режим доставки летописца**:
   `send_chunked_reply(..., parse_mode=<выбранный формат>)`. Инструкция «верни `story` дословно» дублируется
   в tool-response (мягкая страховка), но **не** является единственным механизмом (детерминизм — в коде).
3. **Формат — FINAL (О5):**
   - **Глобальный `parse_mode` остаётся `None`** (владелец подтвердил) — обычный путь DirectChat не меняется.
   - **Для историй Летописца локально форсируется `parse_mode=HTML`**; `LORE_STORY_SYSTEM_PROMPT` использует
     **HTML-теги** (`<b>`, `<i>`, `<a href>`) **вместо Markdown** — `**жирный**` в выдаче не появляется,
     экранирование предсказуемее MarkdownV2 (меньше `can't parse entities`).
   - **Обязательный фолбэк:** `TelegramBadRequest` при HTML → повтор с `parse_mode=None` (plain-text),
     прецедент деградации `summary_generator:406-416`.
   - MarkdownV2 — **отклонён** (спецсимволы/эмодзи/юникод ломают разметку слишком часто).
4. **Границы изменения:** правило доставки применяется **только** к turn'у, где вызван `compile_lore_story`;
   все прочие ответы DirectChat — байт-в-байт как раньше (регресс-гейт R13-эталонов).
5. **Механику доставки не расширяем** до `rich_message`/кастомных рендеров в этом эпике (НЕ-скоуп) — только
   параметр `parse_mode` + отключение канона короткого ответа для режима летописца.

## Альтернативы и отклонения

- **Считать историю обычным ответом DirectChat (как есть):** отклонено — канон 1–2 предложения + запрет markdown
  убьют фичу (это и есть P0-блокер).
- **Бэкенд сам отправляет историю вторым сообщением (прецедент `download_media`):** отклонено — разрывает диалог,
  лишает модель короткой язвительной ремарки, ломает поток reply-цепочек.
- **Ввести `rich_message`/кастомный рендер:** отклонено — вне скоупа, риск регресса на мобильных клиентах
  (опыт 10.16/10.17).
- **Ослабить канон 1–2 предложений глобально:** отклонено — это ядро характера бота; режим включается только по факту вызова тула.
- **Срезать теги-черновики как часть этого ADR:** **ПЕРЕСМОТРЕНО (AMEND ред. 2, БЛОК 7.2)** — реализуется
  отдельным ADR [ADR-1020-7](adr-1020-7-agentic-ai-refactor.md) §2 (stripper-middleware + парсинг `reasoning_content`).

## Последствия

- БЛОК 1 становится реализуемым без слома характера бота и без смены архитектуры доставки.
- Появляется **условная ветка доставки** — обязательны тесты: «обычный ответ — plain, как раньше»,
  «ответ после `compile_lore_story` — выбранный parse_mode», «ошибка/фолбэк инструмента — обычный режим».
- Риск: невалидная разметка модели → падение отправки. Митигация: **HTML (FINAL О5)** + обязательный фолбэк
  на plain-text при `TelegramBadRequest` (прецедент `summary_generator:406-416`).

## Инварианты

Обычный путь DirectChat не меняется (R13-эталоны байт-в-байт); меню мини-аппа не менять; R17 (в логи — без текстов
историй); тон бота/мат не переписывать; порядок роутеров `bot.py` не менять; `media/`/`.env` не трогать.
