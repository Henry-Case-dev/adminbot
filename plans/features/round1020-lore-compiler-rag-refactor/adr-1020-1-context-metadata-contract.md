- **Статус:** 🟢 **Принято** (Step 2 @Architect, 16.09.2026; **ред. 2 AMEND** — Human Gate пройден, О7;
  **ред. 3 — разрешение конфликта T-1874**, фаза B, Step 2 @Architect 16.09.2026)
- **Раунд:** 10.20, фаза B (`metadata-injection-round1020`), задачи T-1872/T-1873/T-1874 + **БЛОК 7.3 (§18.3 спеки)**
- **Спека:** [`spec.md`](spec.md) §2 + §12 + §18.3
- **Аудит-основание:** `plans/reports/round1020_llm_engine_audit.md` §Q3 (нет единого форматтера, ≥10 точек подачи контекста)
- **AMEND ред. 2:** вводится **тонкий Context Middleware** (п.8 пересмотрен), `graph_facts` получает
  `tg_message_id`/`forward_from` (SQLite v11→v12), ID/forward-политика расширяется. См. [ADR-1020-7](adr-1020-7-agentic-ai-refactor.md) §3.
- **AMEND ред. 3 (T-1874):** вводится **двухъярусный контракт представления метаданных** (канонический префикс

## Контекст

ТЗ (БЛОК 0) требует, чтобы LLM **нигде** не получала «голый» текст, а только
`[Дата Время | Автор | ID сообщения (если применимо) | Переслано: откуда]: Текст`.

Фактическое состояние (аудит): единого форматтера нет, есть 4 частных рендера —
`summary_memory._fact_prefix` (`:877-901`), `_format_origin_labeled_line` (`:927-940`),
`summary_xml.build` (`:56-104`), `tool_router._resolve_name`+`_dig_date` (`:1036-1048`/`:984-989`).
Точки подачи контекста размазаны по ≥14 местам (спека §2.3). Сборка промпта — монолит
(`direct_chat_service._build_user_content:717-840`), middleware/интерцепторов нет.

Данные для полного формата доступны не везде: `graph_facts` не имеет ни `tg_message_id`,
ни `is_forward`/`forward_source` (`database.py:286-296`); у `smart_messages` есть всё (`:209-221`).
**AMEND ред. 2 (БЛОК 7.3):** `graph_facts` **расширяется** колонками `tg_message_id`/`forward_from`
(SQLite v11→v12) → ID-политика и сегмент «Переслано» становятся доступны и для фактов, где источник известен.

## Решение

1. **Один хелпер** `services/canonical_context.py::format_context_item(*, ts, author, item_id,
   forward_source, text, kind)` — единственная точка рендера строки контекста.
2. **Формат (kind):**
   - `msg`: `[ДД.ММ.ГГГГ ЧЧ:ММ | Автор | ID | Переслано: Источник]: Текст`
   - `fact`: `[ММ.ГГГГ | Автор | fact:ID]: Текст` (+ существующий суффикс «(Внимание: возможно устарело)»)
   - `archive`: `[Архивная справка: ДД.ММ.ГГГГ | Автор | ID]: Текст`
3. **Нормализация ТЗ:** пример архива в ТЗ записан через запятые — принимается пайп-формат для всех kind
   (парсируемость + единый хелпер); словесный маркер «Архивная справка» сохранён дословно.
4. **ID-политика:** `tg:<tg_message_id>` → `msg:<smart_messages.id>` → `fact:<graph_facts.id>`
   (**AMEND ред. 2:** после v12 `tg:` доступен и для фактов, где `tg_message_id` известен).
5. **Forward-политика:** сегмент только при `is_forward=1` и непустом `forward_source`; для фактов — при непустом
   `forward_from` (**AMEND ред. 2**); иначе сегмент опускается.
6. **Опускание недоступных полей** вместе с разделителем; `\n`/`\t` схлопываются в пробел; **никаких выдуманных** авторов/ID (R16).
7. **Применение обязательно** во всех 14 точках спеки §2.3 — **в смысле критерия «метаданные фактически
   присутствуют»** (ред. 3: канонический префикс **ИЛИ** эквивалентная явная сериализация, см. §«Разрешение
   конфликта T-1874»); вводится инвентаризационный тест «нет строк контекста без меток».
8. **Middleware — AMEND ред. 2.** Вводится **тонкий** `services/context_middleware.py` над хелпером
   (`context_item`, `metadata_header`, `truncate_keep_header`) с **приоритетом метаданных**: заголовок `[…]`
   никогда не режется бюджет-капом, режется только body. Архитектура сборки (`_build_user_content`, порядок
   блоков, дедуп/реранк/MMR) **НЕ переписывается**; `_apply_context_budget`/`_truncate_block` переиспользуют
   header-safe усечение. См. §18.3 спеки.

## Разрешение конфликта T-1874 (ред. 3, 16.09.2026)

**Проблема конфликта.** T-1874 осталась PARTIAL: @Builder применил `format_context_item` в точках 6/9, а 4 точки
оставил байт-в-байт, сославшись на «инвариант ADR-1020-1 (R42/R46/D206) и сотни снапшот-тестов `direct_chat`».
Формулировка п.7 («применение обязательно во всех 14 точках») вступила в противоречие с байт-инвариантом.
Причина — **смешение трёх разных сущностей** под одним словом «инвариант»: (i) XML-**структура** legacy-RAG,
(ii) хронологический **порядок** (D206), (iii) байт-точный **текст строки**. Реальными каноническими
инвариантами являются только (i) и (ii); (iii) инвариантом никогда не был — это была осторожность к тест-поверхности.

### Р1. Двухъярусный контракт представления метаданных

Требование ТЗ (БЛОК 0) — **семантическое**: LLM нигде не получает «голый» текст, а любой контекст
атрибутирован. Пайп-префикс `[…]` из п.2 — **один** способ сериализации (выбран за парсируемость и единый
хелпер), но **не единственный допустимый**.

| Ярус | Определение | Когда применяется |
|---|---|---|
| **A — канонический префикс** | `format_context_item(...)` → `[Дата Время \| Автор \| ID \| Переслано: X]: текст` | обязательно там, где у строки **нет явного временного маркера** (или метаданные «зашиты» в свободный текст) |
| **B — эквивалентная явная сериализация** | структурированные атрибуты/маркеры с **той же или большей** информативностью: XML-атрибуты `<message id/timestamp/author/is_forward/forward_source>`, `[Имя [YYYY-MM-DD HH:MM]]`, `N. [YYYY-MM-DD]`, `[ГГГГ-ММ-ДД ЧЧ:ММ] автор:`, `[ММ.ГГГГ \| Автор: X]` | допустим, когда обязательные метаданные фактически присутствуют; фиксируется **pattern** в реестре `CONTEXT_POINTS` и проверяется инвентарным тестом |

### Р2. Критерий «нет голого текста» (FINAL)

Строка контекста (элемент данных, а не служебная метка) **compliant**, если она несёт:

1. **временной маркер** — обязательно, если источник его отдаёт (обязательное поле);
2. **автор** — обязательно, если источник отдаёт автора;
3. **ID** — best-effort: `tg:` → `msg:` → `fact:` (п.4), если контракт данных его несёт;
4. **`Переслано: Источник`** — best-effort, если источник отдаёт forward.

Отсутствие поля, **значения которого нет в источнике**, — разрешено: сегмент опускается вместе с разделителем
(R16); **выдумывание** — запрещено. Отсутствие обязательного поля (1–2) при наличии значения в источнике —
**не-compliance** → ярус A.

**Служебные строки** (не элементы данных) критерию не подлежат и перечисляются явным allowlist:
метки `<Global_Context>` `«широкий фон: …»`/`«фон: …»`, `_SELF_ECHO_INSTRUCTION` внутри `<RAG_Memory>`,
XML-обёртки/отступы.

### Р5. Обязательные сопутствующие фиксы (иначе — скрытая регрессия)

1. **`strip_context_header(line) -> str`** — новый хелпер (в `canonical_context` или `context_middleware`):
   срезает ведущий `^\[[^\]]*\]:\s?` (канонический заголовок).
2. **`direct_chat_service._line_markers:287-300`** — сейчас берёт `text.find(":")` (ПЕРВОЕ двоеточие). После
   форматирования #2/#3 первое двоеточие попадёт **внутрь заголовка** (`msg:5`) → маркеры важности (E1
   keep-importance) деградируют. **Обязательно**: анализировать `strip_context_header(line)`.
3. **`summary_memory._fact_tokens:1007-1010`** (F2-дедуп `dedup_rag_vs_global`) — токенизация `_TOKEN_RE`
   включает цифры, поэтому заголовок добавит токены (`12`,`09`,`2026`,`msg`,`5`) и может дать ложные
   пересечения. Docstring уже обещает «без дат-префиксов». **Обязательно**: токенизировать после
   `strip_context_header` (обе стороны).
4. **Замер `facts=%d | chars=%d`** до/после (R18) — обязательный гейт.

### Р6. Что остаётся PENDING (вне T-1874)

- **Точка 7, fallback-ветка** (`vector_search` → `list[str]`): follow-up-задача (предлагается **T-1932**).
- **ID/forward для фактов** (#4/#5/#10/#14): фаза **G**, T-1924 (v12 + provenance в 4-кортеже + канонический
  `kind="fact"`). До этого — эквивалентные ts+author (не «голый текст»).
- **Служебные метки** `<Global_Context>` — постоянный allowlist инвентарного теста.

## Альтернативы и отклонения

- **Полный рефакторинг сборки на middleware/ContextBlock-объекты:** отклонено — НЕ-скоуп эпика, риск сломать
  бюджет/кап/дедуп (`_apply_context_budget:1200-1351`, `dedup_rag_vs_global`).
- **Свой формат на каждый домен:** отклонено — ровно тот рассинхрон, который ТЗ запрещает.
- **Включить `ID` и `Переслано` в факты RAG любой ценой (DDL для forward у `graph_facts`):** ~~отклонено в этом эпике~~
  **ПЕРЕСМОТРЕНО (AMEND ред. 2, БЛОК 7.3):** DDL санкционирован владельцем → `graph_facts` += `tg_message_id`/`forward_from`
  (SQLite v12, идемпотентная аддитивная миграция); для legacy-фактов (метаданных нет) — честное опускание поля (R16).
- **Header-safe усечение через отдельный механизм рендера:** отклонено — `truncate_keep_header` встраивается
  в существующий `_truncate_block`/`_apply_context_budget` (минимальная регресс-поверхность).
- **Менять `build_rag_context` legacy-ветку:** ~~отклонено — риск R42/R46 (XML `<context>/<user_gossip>/<bot_knowledge>`)~~
  **УТОЧНЕНО (ред. 3, Р4):** байт-инвариант — **структура** XML (R42/R46), а не текст строки факта; текст строки
  сознательно обновляется в фазе G (T-1924) при неизменной разметке.
- **Требовать канонический префикс от `<chat_history>` (Tier A):** отклонено (ред. 3) — XML-атрибуты несут
  **больше** метаданных (`reply_to_id`, `type`), чем префикс; переписывание = массовый слом снапшотов
  `test_summary_xml`/`test_graphrag_memory` без выигрыша по критерию «нет голого текста».
- **Признать `<Global_Context>`/thread/branch «эквивалентными»:** отклонено (ред. 3) — временной маркер
  **структурно отсутствует**, а данные в источнике есть; это нарушение ТЗ, а не «иная сериализация».
- **Тянуть `fact:ID`/forward в строки фактов уже в фазе B:** отклонено — ID отбрасывается 4-кортежем
  `_search_graph_facts`, а `tg_message_id`/`forward_from` не существуют до v12 (T-1924) → физически невозможно
  без переписывания контракта RAG до DDL.
- **Менять контракт `vector_search` (`list[str]` → строки с метаданными) ради fallback-ветки точки 7:**
  отклонено в B — общий контракт с `summary_generator`; вынесено в follow-up (Р6).

## Последствия

- Один источник формата: правка канона метаданных = правка одного хелпера.
- Длина строк контекста растёт → меняется, сколько единиц проходит cap/бюджет → обязателен замер
  `facts=%d | chars=%d` до/после (`direct_chat_service.py:1928-1938`); **AMEND ред. 2:** заголовок метаданных
  защищён от усечения (`truncate_keep_header`), режется только body → «Дата/Время/Автор» сохраняются всегда.
- **AMEND ред. 2:** SQLite **v12** (`graph_facts` += `tg_message_id`/`forward_from`) — миграция идемпотентна,
