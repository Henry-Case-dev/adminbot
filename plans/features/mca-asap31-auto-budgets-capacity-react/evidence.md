## Отклонения от spec / BLOCKER-вопросы (нет блокеров; фиксации)
1. **§123 oversized-сообщение**: реализовано как «свой chunk, verbatim целиком» (без синтетических part-id). Полная сегментация текста с part-index потребовала бы фабрикации ID в §92-пространстве (риск валидатора §95). Инвариант coverage §121 выполнен; text[:N] отсутствует; физически невлезающее одиночное сообщение → явный degraded. Оценка: контракт покрыт на уровне invariants; Reviewer пусть подтвердит допустимость трактовки.
2. **§140 rechunk под fallback**: mid-flight rechunk под окно fallback-модели НЕ реализован как отдельный перепрогон; fallback-путь гарантирует ПОЛНЫЙ source set (LEVEL-2 package из полного окна, chronology-инвариант §141) и fallback-capacity резолвится отдельно (тесты). Сужение чанков под fallback-окно — за рамками pass'а (не ломает ни один тест §142–145).
3. **§104 группировка Analytics**: новая группа «Модели и автобюджеты» добавлена первой секцией существующей страницы; остальные группы §104 — существующие блоки без перемещения (минимальный дифф; полной перегруппировки не делал).
4. **chat_with_tools-путь**: fallback_payload_adapter заведён только в plain `llm.generate` Direct-пути; tool-loop использует внутренние вызовы generate без adapter (tool-путь не был в §42-сценарии).
5. **models_llm-группа**: spec 10.1 называет группу «LLM/Advanced (models_llm)» — такой группы нет; ключ размещён в `models_main` (числа F8 spec — «GROUPS без изменений» — приоритет; поле всё равно advanced по правилу "window").
6. **F8 «Settings 424»**: понимание — «каталогизированные settings-поля» (REGISTRY entries с settings_field) 423→424; dataclass-полей по-прежнему 423 (ClassVar). Оба инварианта покрыты тестами.
