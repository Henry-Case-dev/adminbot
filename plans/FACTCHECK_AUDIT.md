# Аудит фактчека — Epic 46 (R46-6, D179, T-368)

> Код фактчека НЕ менялся. Это текстовый отчёт простыми словами: гарантирован
> ли выход в сеть, и что можно улучшить в будущем (вне скоупа v2.35.0).
> Дата: 2026-08-20. Ветка: master (v2.35.0 в разработке).

## 1. Резюме-вердикт

**Да, выход в сеть гарантирован — структурно, а не «на удачу».** Пайплайн
фактчека физически не может выдать LLM-вердикт без предварительного успешного
сетевого поиска: первым шагом `check_claim()` зовёт поисковый каскад
`Tavily → Exa → DuckDuckGo`, и только при его успехе доходит до LLM. Если все
три уровня падают, бот честно отвечает фразой из пула ошибок и НИКАКОГО
«мнения без сети» не выдаёт.

## 2. Паспорт пайплайна

| Шаг | Что происходит | Где |
|---|---|---|
| 1. Триггер | reply/репост на сообщение + слово «фактчек» в начале вызова | `handlers/factcheck.py` |
| 2. Кулдаун | 300 сек per (chat, user); сработал → троттлинг-фраза реплаем на вызов | там же |
| 3. Пустой контекст | у цели нет текста/caption → фраза из пула 5.3, БЕЗ поиска | там же |
| 4. Поиск | `aggregator.search(target_text, FACTCHECK_MAX_SYMBOLS)` — каскад Tavily → Exa → DDG | `services/search_aggregator.py` |
| 5. Промпт | `FACTCHECK_SYSTEM_PROMPT` с `{max_symbols}` (4000) через `.replace` | `services/factcheck_prompts.py` |
| 6. Контекст | XML `<claim>` (+`is_forward`/`forward_source`/`<user_hint>` опц.) + `<search_results>` | `factcheck_service.build_user_content()` |
| 7. LLM | `llm.generate([system, user])`, таймаут 60с, ретраи 429/5xx | `services/llm_client.py` |
| 8. Cleanup | `cleanup_llm_text` (ёлочки/тире/двойные пробелы) — ВСЕГДА | `factcheck_service.check_claim()` |
| 9. Ответ | вердикт чанками реплаем на ЦЕЛЕВОЕ сообщение | `handlers/factcheck.py` |
| Ошибки | поиск мёртв → `FACTCHECK_ERROR_PHRASES` (5.4b); LLM мёртв → `LLM_ERROR_PHRASES` (5.5) | `handlers/factcheck.py` |

## 3. Гарантия выхода в сеть (структурный анализ)

1. **Поиск — первый шаг, безусловный.** `check_claim()` (`services/factcheck_service.py`)
   первой строкой зовёт `await self.aggregator.search(...)`. LLM вызывается
   только ПОСЛЕ успешного возврата результатов. Ветки «LLM без поиска» в коде
   не существует.
2. **Каскад Tavily → Exa → DDG.** Уровень падает — включается следующий
   (каждый обёрнут в try/except, таймауты 5/10/15 сек, пустой результат =
   фейл уровня). DDG — уровень 3 и у него НЕТ ключа: он не может быть
   «выключен конфигом», только фактическим сбоем.
3. **Пустые ключи → skip уровня.** `TAVILY_API_KEY`/`EXA_API_KEY` пустые —
   уровень пропускается с логом (D104), каскад идёт дальше.
4. **Все три уровня мертвы → `AllSearchEnginesFailedException`** — сервис
   бросает исключение, хендлер ловит и шлёт фразу из пула ошибок поиска
   (5.4b). **LLM в этом сценарии не вызывается вообще.**
5. **Вывод: ГАРАНТИРОВАН структурно.** Ответ «по памяти»/галлюцинация без
   сетевых данных невозможна: либо есть результаты поиска и вердикт на их
   основе, либо честная ошибка. Единственный теоретический путь — сам
   поисковик отдаёт нерелевантные результаты; это вопрос качества данных, а
   не архитектуры.

## 4. Рекомендации (вне скоупа, код НЕ менять)

- **(а) Промпт.** Обязать LLM явно указывать в ответе вердикт-формат
  («фейк / правда / полуправда / вырвано из контекста / инфы нет») и
  упоминать источники/даты из выдачи — сейчас формат вердикта не
  зафиксирован жёстко, LLM может размыть вывод.
- **(б) Скорость.** Таймауты 5/10/15 сек и `LLM_TIMEOUT=60` уже стоят;
  оптимизировать особо нечего. Возможно: параллелить Tavily+Exa вместо
  последовательного каскада (сейчас худший случай 5+10+15=30 сек до DDG).
- **(в) Кэш одинаковых проверок.** Нормализовать claim (lower/strip/стоп-слова)
  → хэш → кэш вердикта с TTL ~1 час (в `channel_state` или новой таблице).
  Один и тот же репост в чате проверяется один раз, экономим квоты поисковиков.
- **(г) Query expansion.** Разбивать claim на N подзапросов или брать
  DDG-суггесты перед поиском — улучшает релевантность выдачи для длинных
  утверждений (сейчас в поиск уходит весь claim целиком).

## 5. Фактика Шага 0 (фиксация)

- `check_claim()` ПЕРВЫМ шагом зовёт `aggregator.search()`; LLM — только при
  успехе поиска; все 3 уровня упали → `AllSearchEnginesFailedException` →
  пул ошибок (5.4a/5.4b по Section 42).
- Каскад `Tavily → Exa → DDG`; DDG всегда есть (без ключа); пустые ключи →
  skip уровня с WARNING (D104).
- Таймауты: Tavily 5с, Exa 10с, DDG 15с; `LLM_TIMEOUT=60с`; ретраи LLM на
  429/5xx; 401/403 → мгновенная `LLMAuthError`.
- Кулдаун `FACTCHECK_COOLDOWN_SECONDS=300` per (chat, user); фразы ошибок —
  `FACTCHECK_ERROR_PHRASES`/`LLM_ERROR_PHRASES`/`FACTCHECK_EMPTY_CONTEXT_PHRASES`.
- Epic 46 (v2.35.0) добавил: fire-and-forget-хук `memorize_facts` (raw-результаты
  поиска → GraphRAG v2) и гибридный RAG-контекст префиксом user-контента —
  гарантия выхода в сеть при этом НЕ изменилась (хук идёт ПОСЛЕ поиска и не
  блокирует ответ).
