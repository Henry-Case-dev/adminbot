## §72 «единый переключатель = ровно одна мутация»

Сценарий: чат A → «Модули» → переключатель модуля «Сводки чатов»
(`mod_summary`, ключ `flags.summary_enabled`) → проверка трёх представлений →
reload.

| Метрика | Значение |
|---|---|
| Зафиксированных write-запросов (`POST /api/config`) на одно действие | **1** |
| Переключатель в быстром управлении | `false` |
| Переключатель в карточке каталога | `false` |
| Каноническое состояние store (`getModuleState`) | `false` |
| Состояние после reload | `false` (= серверное) |

Вывод: три визуальных представления используют одно каноническое состояние;
действие вызвало **ровно одну** серверную мутацию; reload сохраняет серверное
значение.

## §73 «независимость чатов + незавершённый запрос»

Сценарий: мутация в чате A с **задержанным** ответом (перехват через `route`,
ответ отдаётся позже из main-потока) → переключение на чат B → чтение B →
освобождение ответа A.

| Метрика | Значение |
|---|---|
| Отложенный POST A перехвачен | `true` |
| Состояние чата B до гонки | `false` |
| Состояние чата B при висящем запросе A | `false` |
| Состояние чата B после позднего ответа A | `false` |
| Серверное значение A после освобождения | `false` |

Вывод: состояния чатов не смешиваются; поздний ответ A **не** изменяет B
(scoped-ключ `scope_type/scope_id/module_id`).

## §74 «наследование без потери локальных»

Сценарий: у чата A — локальный override; глобальное значение изменено на
**противоположное** override; reload; чтение фактического состояния чата A.

| Метрика | Значение |
|---|---|
| Локальный override чата A (до) | `true` |
| Новое глобальное значение | `false` |
| `effective` чата A после смены глобального | `true` (= override) |
| `globalValue` чата A | `false` (= новое глобальное) |
| `hasOverride` / `chat_source` | `true` / `chat` |

Вывод: локальный override не исчез; фактическое состояние = override (не
глобальное). Серверная семантика наследования **не изменялась** (`git diff` по
рантайму пуст).
