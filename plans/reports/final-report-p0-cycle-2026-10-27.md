# Финальный отчёт владельцу — Speech/Fact-check/P0 DELTA цикл (27.10.2026)

Отчёт по коррективам 25–26.10: P0 CORRECTIVE (речь), P0 FACTCHECK (фото/альбомы),
P0 DELTA (маршрутизация анализа и память). Простым языком, по структуре,
запрошенной владельцем. Версия на production в конце отчёта.

## 1. Почему бот отвечал «и че тут проверять, пустоту?»

Разобран реальный случай: пересланный пост — альбом из 10 фотографий, текст поста
(2846 символов) лежал только на первом фото, пользователь ответил «Фактчек» на девятое
фото. Между сохранением альбома и командой прошло 84 секунды, а буфер альбомов жил
60 секунд и хранил только одну подпись. Буфер опустел → бот увидел «пустое» сообщение
и ушёл в ветку «проверять нечего», не посмотрев ни в сохранённые сообщения, ни на
изображения. Причина доказана production-данными (логи + база), не догадками.

## 2. Как исправлена обработка фото, альбомов и пересылок

- Публикация восстанавливается целиком из постоянного хранилища: все элементы альбома,
  подпись с любого элемента, отдельный текст поста, связь картинок с текстом.
- Ответ на любое фото поста = проверка всего поста (ответ на фото — только точка входа).
- Если в целевом сообщении нет утверждения — бот проверяет окружение: соседние
  сообщения, цепочку ответов и до 300 сообщений вокруг (механизм широкого контекста
  уже существовал, но был выключен — теперь включён по умолчанию, тумблер в
  «Модули → Фактчек»).
- Одиночная фотография без текста — распознаётся через существующий Vision/OCR.
- Различаются честные состояния: «есть фото без текста», «альбом неполный»,
  «распознавание не готово», «на изображении нет проверяемого утверждения»,
  «данных нет». Только последнее — «проверять нечего», и с объяснением, что проверено.
- 15 регрессионных сценариев покрыты тестами; независимое ревью — Approved
  (6 блокеров из первого ревью устранены и перепроверены).

## 3. Алиасы: как решена проблема путаницы имён

Раньше имя человека в разных местах бралось из разных источников: из Telegram-ника,
из старой записи в истории, из памяти — поэтому один человек назывался по-разному,
а бот путал автора цитаты с адресатом.

Теперь одно правило для всего пути: имя всегда определяется по Telegram user ID,
приоритет — алиас чата → общий алиас → нынешний ник → @имя → номер. Смена имени
действует сразу, без перезапуска. Старые записи не переписываются: боту добавлено
указание брать актуальное имя из списка участников по номеру, а история остаётся
доступной для поиска по старым именам.

Проверено по 11 пунктам независимо (Approved): приоритеты, живое применение без
рестарта, «мои сообщения» = автор запроса, автор цитаты ≠ адресат, два одинаковых
имени не сливаются, «Гипербореец» — историческое имя в сохранённых сообщениях, а
действующий алиас «Макс» доходит до модели (проверено в реальном payload).

## 4. Речь: что исправлено и как проверено

- Сложные запросы («проанализируй мои сообщения») снова уходят в разбор: правило
  переписано по смыслу (материал → разбор, тон не меняет тип действия), синонимы
  нормализуются. Стабильность подтверждена живыми прогонами; на грубой форме
  «проникся тоном вместо сути» была нестабильность — правило усилено
  разделением тона и сути, финальный прогон чистый.
- Пустые вступления («давай посмотрим», «сейчас разложу») устранены: 5 из 8 → 0 из 6.
- Формула «начинай с вывода» снята по вашему указанию — NO_META теперь запрещает
  только служебные анонсы и метакомментарии; форма ответа свободная.
- Полный Personality Core (3294 символа) доходит до модели целиком — скрытая обрезка
  убрана, запрет квот инструкций соблюдён (отдельный guard-тест).
- FREQUENT берётся из живой настройки; мат — естественный, без вставок и без
  обязательных примеров. Остаточная вариативность выразительности задокументирована
  как статистическая, не блокер (условия приёмки зафиксированы отдельным документом).
- Старые выдуманные истории помечены provenance и больше не выдаются за факты;
  собственные прошлые ответы исключены из фактического RAG.

## 5. P0 DELTA: понимание запросов и память (выкачено в 2.58.134)

- Готовая история больше не подменяет ответ на анализ — только на заказанный рассказ.
- Период поиска выразим в инструментах (год от/до), доходит до SQL.
- Покрытие истории честное: сэмплирование по всему периоду, «показано X из N»,
  фильтры до ограничения выборки.
- Субъект анализа — по Telegram ID; при неоднозначности — честный отказ.
- Пересказы памяти помечены происхождением и не считаются дословными свидетельствами.
- Убран последний словесный хардкод в резервном классификаторе (12 триггеров).
- Ревью подтвердило: ни одного нового шаблона, ни одного нового слоя или лишнего
  вызова модели (12/12 пунктов анти-шаблонного стража).
- Живая проверка на проде: сценарий «как менялся человек за 2022–2026» теперь даёт
  развёрнутый разбор (1627 знаков) с честной оговоркой о глубине архива, вместо
  заглушки на 125 знаков.

## 7. Что осталось (честно)

1. `REQ-EX-STABLE-EFFECT` — статистическая вариативность выразительности FREQUENT:
   документированный остаток с зафиксированными условиями приёмки, не блокер.
2. `REQ-DONE-MAIN-CRITERION` — финальный критерий «ответ соответствует настройкам»:
   закрывается этим отчётом + живыми наблюдениями.
3. Проверки, требующие реальных устройств/событий (Windows-клиент, перенос
   супергруппы, векторный E2E) — вне знаменателя, ждут естественных событий.
4. Видео-сценарий SOUL — ждёт настройки медиа-источника (инфраструктура).
5. **ASAP 5** — следующая большая волна (в конце очереди), затем **POST-ASAP5**.
