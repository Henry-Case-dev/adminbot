# OI-2026-10-31-ASAP-FC-EVIDENCE-STYLE — полнота поиска, релевантность доказательств, живая речь фактчека

- **Origin:** root chat prompt, 2026-10-31; спецификация добавлена в `plans/current_task.md` со строки 1617.
- **Kind:** new_task (дополнительный corrective к EVOL; не новый эпик).
- **Очередь (строго):** `QUEUED` до завершения ВСЕХ ранее поставленных и исполняемых фактчек-изменений и их Reviewer PASS: критический разнос/Core/Expression/Style, `ASAP-FC-ADMISSION-01`, интеграция Media Readiness/Vision в части фактчека. Действующих агентов не прерывать, параллельную переработку тех же файлов не начинать.
- **Симптом (скриншот 31.10):** составная рыночная новость (индексы, золото/серебро, крипта, потери капитализации, причины) → много `недостаточно данных` по проверяемым событиям, мало/нерелевантные источники, шаблонный отчёт без манеры речи.
- **Требования:**
  1. Per-claim retrieval: каждая существенная независимая claim unit получает попытку поиска; связь claim → query → evidence → status → итог; 4 из 6 подтверждены → показать 4 и два конкретных пробела.
  2. Адаптивный планировщик: не «≤3 запроса на новость»; запросы по тезисам (индекс/компания/дата/метрика/валюта/интервал, английские названия/тикеры), различать событие/величину/причинную интерпретацию; coverage-loop с уточнением только непокрытых; убрать жёсткий 10-секундный потолок как безусловный, ввести конфигурируемое адаптивное время/вызовы; `deadline_exceeded` честно; только существующий SearchAggregator.
  3. Источник ↔ конкретный claim: релевантность конкретному тезису, чтение содержимого (метрика/период/сущность/причина), не подтверждать по заголовку/сниппету, техническая ошибка ≠ «нет данных», первичные данные предпочтительны, даты публикации/события/таймзоны/единицы, противоречия не замалчивать, URL только из текущего прогона и привязаны к claim IDs, background_only/irrelevant не как «Источники».
  4. Статусы: `claim_unidentified`, `search_not_started`, `provider_error`, `deadline_exceeded`, `source_extract_failed`, `no_relevant_sources`, `evidence_conflicting`, `evidence_insufficient_for_exact_number`, `verified/refuted/partial`; публичные формулировки различают эти случаи; техническая неисправность не выдаётся за нехватку данных.
  5. Живой фактчек в рамках структуры: CheckedVerdict/per-claim/evidence сохраняются; публичный текст — существующий verbalizer/Writer; композиция: короткий вывод → разбор тезисов человеческими фразами → критический разнос подтверждённых натяжек; ехидная манера внутри фрагментов (не один матерный абзац в конце), без regex-мата; директива «Жестко разъеби тейк автора и поясни почему он не прав.» и её настройка — те же; renderer/egress/кеш не перетирают стиль.
  6. Телеметрия: claim_id → queries → provider/status/latency → candidates → opened → relevance/evidence → reason_code → displayed citations; итог охвата, причины неполноты, verbalizer_path, effective Core/Expression/Style revision, critical_section_enabled, renderer_path, fallback_reason; компактный UI-итог без новой панели.
- **Приёмка:** 12 фиксированных сценариев §8 (составная новость 6 claims; 4+2; off-topic золото vs Alphabet; русский пересказ с тикером; дата статьи vs события; цифра без методологии; противоречия; провайдер/дедлайн; полный пакет источников; частичный вердикт со стилем; стиль off/fallback; доставка/кеш) + релевантная регрессия; Reviewer проверяет весь путь Claim→Search→Evidence→Verdict→Verbalizer→Renderer→Send.
