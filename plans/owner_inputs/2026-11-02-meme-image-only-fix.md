# Срочный фикс: мем — только изображение, без текстовой подписи (02.11.2026)

Источник: сообщение владельца в root-чате, P0-корректировка.
Тип: correction (срочный фикс действующей фичи генерации мемов).

## Дословный текст

> Срочный фикс мемов
> Проблема:
> При генерации мема бот после картинки дополнительно отправляет текстовую подпись/расшифровку промпта отдельным сообщением. Это неправильное поведение и ломает UX.
>
> Что нужно сделать:
> Для фичи генерации мемов бот должен отправлять только итоговое изображение мема, без любой дополнительной текстовой подписи после него.
>
> Обязательные требования:
> - После успешной генерации мема в чат уходит только картинка.
> - Нельзя отправлять следом:
>   - исходный промпт,
>   - пересказ содержимого мема,
>   - список панелей,
>   - текст вида "Создай мем с шрифтом impact: ...",
>   - служебные комментарии,
>   - пояснение, что именно было сгенерировано.
> - Если генерация успешна - текстовый follow-up отсутствует полностью.
> - Исключение: если генерация не удалась, тогда можно отправить только короткое сообщение об ошибке.
> - Никакого хардкода под конкретный чат, пользователя или конкретный тип мема.
> - Не ломать остальную логику инициативы, лимитов, аналитики и логирования.
> - Если текст нужен системе внутренне для генерации, он должен оставаться внутренним, а не публиковаться в чат.
> Критерии приёмки:
> 1. Бот генерирует мем по инициативе - в чат приходит только изображение.
> 2. Бот генерирует мем по явному запросу - в чат приходит только изображение.
> 3. После отправки изображения нет второго текстового сообщения с промптом/описанием.
> 4. В логах и аналитике событие генерации сохраняется как раньше.
> 5. При ошибке генерации картинка не отправляется, бот пишет короткую ошибку.

## Инженерная трактовка

1. Успешная генерация: в чат уходит ровно одно сообщение — изображение. Любой текстовый follow-up (промпт, описание, панели, служебные комментарии, пояснения) запрещён.
2. Неуспешная генерация: изображение не отправляется, допускается одно короткое сообщение об ошибке.
3. Внутренний текст (промпт и т.п.) остаётся внутренним: он может жить в логах/аналитике, но не публикуется.
4. Никаких хардкодов под чат/пользователя/тип мема.
5. Логика инициативы, лимитов, аналитики и логирования не меняется.
6. Приёмка: сценарии «по инициативе» и «по явному запросу», проверка отсутствия второго сообщения, сохранность событий аналитики, поведение при ошибке.
