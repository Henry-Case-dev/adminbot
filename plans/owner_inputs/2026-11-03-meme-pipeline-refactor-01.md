## MEME-PIPELINE-REFactor-01

### Цель
Переделать генерацию мемов так, чтобы она шла в три явных этапа:

1. **Выжимка** по окну сообщений  
2. **Генерация прикола** из выжимки  
3. **Генерация изображения** по итоговому промпту

При этом нужно сделать пайплайн управляемым из админки, убрать неправильное ограничение длины у выжимки, перенести ограничение длины на этап генерации прикола и добавить админскую диагностическую команду `/meme`, на которую не действуют ограничения и кулдауны.

---

## Что реализовать

### 1. Новый пайплайн мемов

Текущий пайплайн мемов переработать в следующую последовательность:

#### Этап A. Выжимка
- Из окна сообщений формируется **выжимка**.
- Выжимка остаётся внутренним промежуточным артефактом.
- **Для выжимки больше не применяется потолок длины**.
- Выжимка не должна искусственно обрезаться по лимиту символов, который раньше использовался для всего пайплайна.

#### Этап B. Генерация прикола из выжимки
После выжимки добавить **новый обязательный этап**: отдельный LLM-вызов, который на основе выжимки придумывает короткий абсурдный прикол.

Базовый промпт по умолчанию:
> **"Придумай короткий абсурдный прикол из этой выжимки."**

Требования:
- этот промпт должен быть **редактируемым в админке**;
- именно на этом этапе формируется текст прикола, который потом подставляется в промпт генерации изображения;
- именно здесь применяется ограничение длины.

#### Этап C. Генерация изображения
- Промпт генерации изображения должен остаться отдельным этапом.
- Промпт генерации изображения тоже должен быть **редактируемым в админке**.
- В него подставляется результат этапа B, а не сырая выжимка.

## 2. Два отдельных редактируемых промпта в админке

В разделе **Модули → Инициатива → Мемы в инициативе** нужно сделать два отдельных редактируемых поля:

### Поле 1. Промпт генерации прикола
- новое поле рядом с текущими настройками мемов;
- редактируемое;
- значение по умолчанию:
  - `Придумай короткий абсурдный прикол из этой выжимки.`
- использоваться должно на этапе B.

### Поле 2. Промпт генерации картинки
- текущее поле с шаблоном картинки сделать **редактируемым**;
- сейчас оно фактически недоступно для правки — это исправить;
- использоваться должно на этапе C.

Оба поля:
- должны сохраняться и загружаться штатно;
- должны поддерживать глобальные настройки и чатовые переопределения по текущей модели конфигурации;
- должны быть честно отражены в интерфейсе, без фиктивной read-only логики, если редактирование реально поддерживается.

## 3. Перенос потолка длины с выжимки на прикол

### Новое правило
Параметр `Потолок длины промпта, симв.` больше **не относится к выжимке**.

Теперь он относится к **итоговому тексту, который идёт в image generation**, то есть к связке:

- шаблон промпта картинки
- плюс подставленный в него прикол

### Как это должно работать
Нужно считать **доступный бюджет прикола** автоматически.

Если:
- `L` = настроенный потолок длины итогового промпта для image generation
- `T` = длина шаблона промпта картинки **без подставленного прикола**
- `J` = максимально допустимая длина текста прикола

То:
- `J = max(0, L - T)`

Далее на этапе генерации прикола модель должна получать явную инструкцию с этим лимитом.  
То есть фактически система должна дополнить промпт генерации прикола ограничением вроде:

> "Сгенерируй прикол длиной не более N символов."

где `N` вычисляется автоматически.

### Важно
- Нельзя просто обрезать уже готовый прикол тупым хардкодом после генерации, если этого можно избежать.
- Основной способ — **сразу инструктировать модель** на нужную длину.
- Защитная финальная обрезка допустима как страховка, но не как основной механизм.

### Что показать в интерфейсе
В админке рядом с лимитом или под ним показать:
- эффективный лимит итогового промпта;
- длину шаблона картинки;
- вычисленный доступный бюджет для прикола.

Пример:
- `Потолок итогового промпта: 800`
- `Длина шаблона картинки: 123`
- `Доступно для прикола: 677`

## 4. Диагностическая команда `/meme` только для админа

Добавить специальную **диагностическую команду**:

> `/meme`

### Назначение
Это ручной запуск мем-пайплайна для проверки и отладки.

### Ограничения доступа
- команда доступна **только админу**;
- не должна быть доступна обычным пользователям;
- не должна рекламироваться как обычная пользовательская команда в поведении бота;
- если нужно — можно позже отдельно решить, добавлять ли её в справку для админа.

### Поведение
Команда должна запускать мем-пайплайн вручную и **игнорировать ограничения и кулдауны**.

Это значит:
- не действуют суточные квоты мемов;
- не действует кулдаун между мемами;
- не действует минимум сообщений для триггера;
- не действуют ограничения, связанные именно с автоматическим инициативным запуском мемов.

### Уточнение
Это **диагностический/manual запуск**, а не обычная автоинициатива.  
Поэтому он не должен зависеть от того, прошёл ли авто-триггер по инициативе.

### Но при этом
Не надо ломать безопасность и здравый смысл:
- команда не должна обходить права доступа;
- если реально недоступна модель или сломан image pipeline — должна вернуться нормальная ошибка;
- системные аварийные запреты уровня "вообще нет рабочего image backend" можно не обходить.

## 5. Выдача результата

Сохраняем ранее зафиксированное правило:

### После успешной генерации мема бот отправляет только изображение
- без текстовой подписи;
- без промпта;
- без пересказа прикола;
- без служебного follow-up.

Исключение:
- при неуспехе допускается короткое сообщение об ошибке.

## 6. Чего делать нельзя

- не хардкодить поведение под конкретный чат;
- не хардкодить под конкретный мем;
- не вводить новые искусственные бюджеты, которые конфликтуют с уже заданным лимитом;
- не дублировать существующий pipeline инициативы отдельной параллельной веткой без причины;
- не ломать аналитику мемов;
- не ломать существующие настройки инициативы;
- не ломать глобальные/локальные переопределения.

---

## 7. Что должно появиться в аналитике / диагностике

В аналитике мемов и логах должны быть различимы этапы:

1. выжимка;
2. генерация прикола;
3. генерация картинки;
4. публикация.

Нужно видеть:
- какой этап упал;
- какой этап был пропущен;
- какой итоговый шаблон использовался;
- какой лимит был посчитан для прикола;
- какой фактический размер получился у прикола.

Без слива лишнего мусора в пользовательский чат.

---

## 8. Критерии приёмки

1. Мем-инициатива теперь работает через 3 этапа: выжимка → прикол → картинка.
2. Выжимка больше не режется потолком длины.
3. Есть отдельный редактируемый промпт генерации прикола.
4. Есть отдельный редактируемый промпт генерации картинки.
5. Поле промпта картинки реально редактируется, а не просто отображается.
6. Потолок длины применяется к итоговому image prompt, а не к выжимке.
7. Для прикола автоматически рассчитывается допустимая длина.
8. Модель прикола получает явное ограничение по длине.
9. После успешной генерации мема бот отправляет только изображение.
10. Админская команда `/meme` работает вручную и не подчиняется кулдаунам/квотам/авто-триггерам.
11. `/meme` недоступна не-админу.
12. Аналитика и логи отражают все этапы пайплайна отдельно.
13. Не сломаны существующие механизмы инициативы и публикации.
