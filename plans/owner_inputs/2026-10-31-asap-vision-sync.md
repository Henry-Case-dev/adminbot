# OI-2026-10-31-ASAP-VISION-SYNC — глобальная синхронизация медиаанализа

- **Origin:** root chat prompt, 2026-10-31; спецификация добавлена в `plans/current_task.md` со строки 1433.
- **Kind:** new_task (общепроектный P0 corrective; не новый эпик).
- **Очередь:** ближайшая совместимая — запускается параллельно с UI-волной (web/**), не прерывая её; координируется с видео-фиксом (handlers/youtube.py — не трогать) и ревью ASAP-FC (read-only).
- **Симптомы:** «скрин не открылся» при здоровом Vision; `vision_adapt outcome=failed | error=""`; две возможные причины: (1) непригодный structured output (max_tokens=1024, reasoning, JSON/length), (2) асинхронное распознавание обгоняется потребителем (pending → ответ без OCR).
- **Главный инвариант:** ни один потребитель не отправляет окончательный ответ/фактчек/сводку и не создаёт долговременное знание по изображению, пока анализ не получен или не зафиксирован достоверный терминальный исход, явно отражённый в ответе. Барьер только для media-dependent запросов, не блокирует весь чат.
- **Контракт:** MediaReadinessBarrier / prepare_media_evidence: chat_id, target_message_id, source_message_id, asset_id/media_group_id, association_kind (own_caption/reply/quote/adjacent_before/adjacent_after/explicit_ref/album), association_status (resolved/ambiguous/missing), analysis_status (ready/pending/failed/unavailable/unsupported/disabled), analysis_revision+model+config revision, ocr_blocks/visual_description/uncertainty, нормализованный reason_code, durable job/coalescing key/стадия/correlation_id, признак актуальной ревизии.
- **Связывание:** фото+подпись в одном сообщении; reply/quote/пересылка; media group/альбом; ближайшее до запроса в локальной ветке; после запроса в bounded окне при объявленном ожидании. Несколько равновероятных → ambiguous/уточнение, не случайное фото. Изоляция чатов.
- **Синхронизация:** resolve → reuse/enqueue (single-flight по asset+config revision) → await через существующие события + durable state (не только asyncio.Event) → rebuild actual media block → L1/FactCheck/Writer получают актуальную ревизию → проверка перед отправкой. Timeout → не выдумывать, pending фиксируется, возобновление/терминал по lifecycle. Идемпотентность, restart recovery, bounded lifetime.
- **FactCheck:** сначала media+OCR, потом извлечение тезиса, потом suitability/поиск/вердикт/Writer; `no_claim` запрещён при pending OCR; текстовая пустота ≠ отсутствие тезиса из изображения; при терминальном отказе Vision — честно указать непроверенное изображение. Одна логика допуска с ASAP-FC-ADMISSION-01.
- **Vision output contract:** убрать магический max_tokens=1024 (конфигурируемый предел по возможностям модели/провайдера, видимый админу); reasoning off только если поддерживается; structured output/response_format где возможно; различать length/invalid JSON/empty content/неожиданный формат/4xx/429/5xx/timeout/unsupported/reasoning; transport_success/schema_valid/analysis_ready/consumer_received раздельно; без бесконечных retries; длинный OCR — сегментация/детерминированное объединение без фиксированной обрезки.
- **Админка:** «Проверить» = input accepted → schema valid → OCR received → saved/readable → consumer injection; цепочка media_received → media_target_resolved → vision_queued/running → vision_ready/failed → consumer_unblocked → context_revision_applied → final_sent/final_deferred; поля без приватного контента.
- **Приёмка:** 20 сценариев §8 + релевантные регрессии (Direct, media/vision, FactCheck, context, persistence, инициатива, consumer-интеграции); Reviewer проверяет все пути потребления включая legacy/fallback.
