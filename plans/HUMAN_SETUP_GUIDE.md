# HUMAN SETUP GUIDE — TMA Admin Dashboard

> Для владельца бота. Выполняется перед стартом кодинга (шаг 5 пайплайна).
> Время: ~15 минут. Все шаги последовательные.

## Шаг 1. Включи MCP-серверы в OpenCode

Открой настройки OpenCode → раздел MCP (или `opencode.json`). Минимальный практичный набор:

| MCP | Зачем |
|---|---|
| **Exa** (web search + web fetch) | Веб-ресерч для агентов: актуальные доки, примеры кода, страницы Telegram/aiogram |
| **DuckDuckGo** (web search) | Запасной поисковик, когда Exa недоступен или нужен второй источник |
| **Context7** | Актуальная документация библиотек (aiogram, FastAPI) без гугления |
| **Filesystem** | Чтение/запись файлов проекта агентами через MCP-протокол |
| **Memory** | Долговременная память агентов (knowledge graph) между сессиями |
| **Sequential Thinking** | Пошаговое рассуждение для сложных задач (архитектура, декомпозиция) |

Это весь необходимый набор для пайплайна. Ничего дополнительно ставить не нужно.

## Шаг 2. Привяжи URL дашборда к кнопке меню в BotFather

1. Открой чат с **@BotFather** в Telegram.
2. Отправь команду `/mybots` → BotFather покажет список твоих ботов с кнопками.
3. Нажми кнопку с именем нужного бота → откроется меню настроек бота.
4. Нажми **Bot Settings** (настройки бота).
5. Нажми **Menu Button** (кнопка меню).
6. Нажми **Configure menu button** (настроить кнопку меню).
7. BotFather спросит: «OK. Send me a URL to open when users press the button.» — отправь сообщением ровно:

   `https://embody-grafted-ritalin.ngrok-free.dev/web/`

8. BotFather спросит текст кнопки: «Now send a text for the menu button...» — отправь, например: `Админка` (или оставь предложенный вариант).
9. BotFather ответит: «Menu button successfully set» — готово.

Альтернатива одной командой: отправь BotFather `/setmenubutton` → выбери бота → URL → текст кнопки. Ответы BotFather будут теми же.

> Кнопка меню появляется в чате с ботом только при открытой ссылке (клавиатура) — это штатно. Проверка: в чате с ботом слева от поля ввода появится кнопка «Админка».

## Шаг 3. Проверь ngrok-туннель и локальный сервер

**3.1. Web-интерфейс ngrok:** открой в браузере `http://127.0.0.1:4040` — увидишь список туннелей и статус `online`. Если страница не открывается — ngrok не запущен: запусти `ngrok http 8000` (или с конфигом домена).

**3.2. Проверь домен:**
```bash
curl https://embody-grafted-ritalin.ngrok-free.dev/health
```
Должно вернуться `{"status":"ok"}` (после реализации эндпоинта). Пока сервера нет — вернётся 404/502, это нормально до запуска бота с веб-частью.

**3.3. Убедись, что бот слушает порт 8000 локально:**
```bash
netstat -ano | findstr :8000
```
На проде (Linux): `ss -tlnp | grep 8000`. Если пусто — uvicorn не поднялся.

**Типичные ошибки:**
- **502 Bad Gateway** — ngrok жив, но на `127.0.0.1:8000` никто не слушает (бот/uvicorn не запущен или слушает другой порт).
- **ERR_NGROK_* / «Tunnel not found»** — туннель упал; перезапусти ngrok и убедись, что `http://127.0.0.1:4040` показывает `online`.
- **Неверный порт** — самая частая: uvicorn должен слушать ровно тот порт, на который проброшен туннель (8000).
- **404 на `/`** — проверь путь: дашборд живёт на `/web/`, health — на `/health`.
