## 2. Фиксы (по задачам B–D)

### 2.1 T-870 — Шапка (flexbox)

- Header/панель навигации: `display: flex; align-items: center; gap: 8px; flex-wrap: wrap;` вместо float/absolute/инлайн-костылей.
- Элементы: заголовок/логотип, активная вкладка, чат-бейдж (появляется из F-7/F-11 — подготовить слот-стили, не ломать текущий рендер).
- Проверка на 380px ширины: horizontal scroll или перенос строк (flex-wrap), ничего не обрезается.
- Маркер для тестов: класс `main-header flex items-center gap-2` (или существующий +новая группа классов; маркер-строка в app.js: `'main-header'`).

### 2.2 T-871 — Логи (вкладка «Статус»/debug-зона)

- Контейнер: `<pre><code>` моно (`font-family: ui-monospace, SFMono-Regular, Menlo, monospace`), `font-size: 0.75rem`, `white-space: pre-wrap; word-break: break-all;`.
- Компактный скролл: `max-height: 320px; overflow-y: auto;` — thin scrollbar (`::-webkit-scrollbar{width:6px}` и т.п. — существующий стиль), автоскролл к низу при новых записях (`nextTick` → `scrollTop = scrollHeight`).
- Строки: `line-height: 1.25; padding: 2px 4px;` (компактно).
- Не ломать: ring-логи (сам вызов метода/URL/фолбэки — без изменений).

### 2.3 T-872 — relations: имена/аватары

- Резолв имени участника: приоритет **Alias** (`limits.summary_aliases`, существующий каскад `summary_aliases.py:50-75`) → nickname → username → фолбэк `user_id` (строкой).
- Аватар: существующий прокси `/api/avatar` (`app.js:avatarUrl()`, bdd5e89) с фолбэком-инициалом (первая буква имени) — если нет blob (ошибка/превышен лимит кэша).
- Заменить «голые» user_id в строках relations (строки вида `«... (user_id)»` → `имя + user_id мелким`), длина строки — компакт (`max-width`, ellipsis).

### 2.4 T-873 — Титулы вместо chat_id

- В списках/карточках «Лор чатов» (и в других местах с «-100…»): заголовок = имя чата (из локального кэша чатов бота/`chat_lore.chats`-списка `title`/`getChat`-названий) + `chat_id` мелким шрифтом (класс `text-xs opacity-60`-стиль) или сноской.
- Фолбэк при неизвестном имени — старый вид (id без имени).

### 2.5 T-874 — «— авто» → чип «авто»

- Заменяем текстовые «— авто»/«— автоматически» на компактный чип-бейдж «авто» (существующий палитр-цвет акцента, радиус pill, размер text-xs).
- Места: авто-лор лента, истории, relations-профили. Смысл/данные не меняются; маркер-класс `chip-auto`.

### 2.6 T-875 — relations-дропдаун стадии + note-поле

- Дропдаун стадии: компактный (высота/ширина уменьшены, короткие метки: stranger→новенький, acquaintance→знакомый, friend→приятель, close_friend→близкий, best_friend→лучший друг, veteran→старый друг — использовать существующие ванильные значения RU из маппинга стадий), placeholder.
- «Заметка»/note: `textarea` с `min-width: 100%; min-height: 60px; resize: vertical;` авто-рост (`rows=…` не блочит), тёмная тема-стилизация.

### 2.7 T-876 — Перенос «Telegram ID админа» из «Реакции и Триггеры» → «Доступы» (C1)

- rg-аудит: найти поле (ключ `reactions.*_user_id`? — вероятно, `reactions.slavik_user_id`-место) и перенести блок в `index.html`-ветку `activeTab === 'access'` (+ соответствующее метод app.js), **значения/ключи БД остаются**.
- В «Реакциях и Триггерах» вход не показывать (в данных БД — без изменений).
- Если речь идёт о **фактическом** админе-телеграме для ролей/доступа (а не person-id), перенести только блок-«доступ» (запись «единственный администратор» — context-анализа: в этом случае поле — `bot_settings` ключ с категориями «Доступы»-на-проверку — по коду TMA; окончательный выбор id — по факту кода (решение в T-876: 2 варианта, определяемые rg).
- Обновить test-аудит вкладок: маркер наличия в access, отсутствие dup в reactions.
