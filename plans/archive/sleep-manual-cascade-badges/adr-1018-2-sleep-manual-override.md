# ADR-1018-2 — Ручной приоритет Сна (безусловный, без флагов), каскад Сон→Глубокий→Личность, реактивные бейджи без WebSocket

- **Статус:** Proposed (обновлён после human-gate, итерация 2 — 15.09.2026)
- **Дата:** 2026-09-15
- **Раунд:** 10.18, фича F2 `sleep-manual-cascade-badges` (T-1712)
- **База:** HEAD `118a03c`. **Связано:** ADR-1015-2, F-10 раунда 10 (`feature-gates-worker-budget`), ADR-1017-3, **ADR-1018-7 (`settings-worker-sync` — обязательная зависимость)**.
- **SUPERSEDE/AMEND:**
  - **SUPERSEDE F-10 §5-6** («ручные `run_once/generate_for_chat` тоже гейтятся и бюджетируются; manual не минует gate/budget») — **полностью, для `DreamWorker`, без флага**. Новый стандарт: явный ручной запуск из UI выполняется безусловно. Worker Budget как **учёт расхода** сохраняется (не как запрет).
  - **AMEND ADR-1017-3**: сохраняются §2.1 (серверный `generated_at`), §2.2 (формат остатка), §2.5 (эмодзи), §2.6 (**без живого tick-таймера**, без WebSocket) — **дополняется** §2.3 (`active_until` считается и при `running` вне окна) и §2.4 (активация при manual).
  - **AMEND (итерация 2, по UPD п.2)**: удалены все упоминания фича-флага `flags.sleep_manual_priority_enabled` как **ошибочные** для базовой логики; удалён флаг `flags.sleep_relaxed_thresholds_enabled` (ослабление порогов — это и есть фикс, а не опция).

## Context

1. **Прод-симптом:** с 12.09 Сон ничего не дистиллирует, Глубокий сон пуст, черты Личности = 0; ручной запуск из админки не даёт результата; бейджи «Сон через…» не меняются.
2. **Диагноз по коду (не по ТЗ):** `window_skip` для manual **уже** обходится (`dream_worker.py:588`). Реальные обрывы: (а) kill-switch `gates_enabled(chat_id,"dream")` применяется и к manual (`:569-577`), при глобальном `DREAM_ENABLED=False` возвращает False; (б) near-limit/суточные бюджеты (`:600-620`, `:115-116`); (в) `distilled==0` из-за порогов 3/12/5 (`:522-534`, `settings.py:1090-1107`); (г) жёсткий порог кандидатов `min_new_facts_per_chat=5` + «тишина 30 мин» (`:437-451`); (д) `DEEP_SLEEP_ENABLED=False`/`DREAM_ENABLED=False` (дефолты) → каскад глух (`_maybe_deep_after_sleep:1103-1109`); (е) traits требуют `bot_self_reply`-фактов и вызываются только из глубокого сна (`:1315-1331,1460-1493`).
3. **Бейджи:** `active_until` вычисляется только при `dream_in` (окно) (`memory_agi.py:484-485,500-501`), при `running` вне окна — `null`; фронт показывает «Сон идёт» без «до» и не перезагружает `cognition` после POST (`web/app.js:4974-4999`).
4. **Инфраструктура:** WebSocket в проекте нет; polling 15с (`web/app.js:5385-5408`). ADR-1017-3 §2.6 сознательно отклонил живой tick-таймер.
5. **S10.17-2:** при `cognition==null` бейдж «Сон через —».
6. **(Итерация 2, критично) Рассинхрон настроек UI → воркеры.** Владелец: тумблеры Dream/DeepSleep в мини-аппе были включены, а бэкенд/воркеры видели OFF. Причина — слой чата (`chat_profiles.chat_params.overrides`) пишется UI-ом, но `DreamWorker._key` читает только глобальный `hot.get` (`:252-253`), а планировщик регистрирует джоб один раз на старте (`:294-351`). Полный аудит и решение — **ADR-1018-7 / F7**. Этот ADR на них **ссылается и зависит** от них: без F7 F2 не проверяема (см. D8).

## Decision

### D1. «Абсолютный приоритет» = `manual=True`, **без фича-флага**
Ручной приоритет — **новый стандарт базовой логики**. Никакого `flags.sleep_manual_priority_enabled`. Триггер — исключительно факт явного ручного запуска (`run_once(chat_id=…, manual=True)` / API `POST /api/memory/dream/run`). Откат — `git revert` (не переключение флага). Это прямое решение владельца (UPD п.2, строки 116-117).

### D2. Что обходит manual (безусловно)
- `window_skip` — **уже** обходится (`:588`); сохраняем.
- **Kill-switch** `gates_enabled(chat_id,"dream")` (`:569-577`) — обходится, **с аудитом** `memory_dream_log.status="gate_override"` и WARNING `[dream] manual override: gate dream | chat_id=%s`. (Ранее блокировал manual **и** был главной причиной «нажимаю — ничего».)
- **Near-limit early-stop** (`:609-620`) — обходится (аудит `budget_override`).
- **Суточные бюджеты** (`_budget_reason` `:601-608`, `_dream_budget_ok`) — обходятся для решения «запускать/не запускать», но **расход всё равно записывается** (`worker_budget.consume`, fail-open). Worker Budget как учёт **сохраняется**.
- **Тайминги каскада** — `_maybe_deep_after_sleep(manual=True)` игнорирует `deep_sleep_enabled` и `trigger != after_sleep`; `_run_deep_all(manual=True)` не делает `break` после первого успеха; `_run_deep_once(manual=True)` уже обходит cooldown/daily-limit.
- **Порог кандидатов** — для manual `only_chat` задаёт чат явно (`:433-435`), т.е. «мин. новых фактов» не участвует.

### D3. Что НЕПРИКОСНОВЕННО (перепроверено на совместимость; manual не обходит никогда)
| Guard | Не обходится | Почему это совместимо с «абсолютным приоритетом» |
|---|---|---|
| `_run_lock`/`_deep_lock` (`already_running`, 409) | **да** | «безусловно» = запуск не отклоняется гейтами, а не «параллельно»; обход = порча watermark/двойной расход |
| `protected_facts`-гейт | **да** | явный пользовательский запрет на факты; manual выбирает *что* обрабатывать из разрешённого |
| Анти-галлюцинация: ≥2 реальных `source_ids` | **да** | без него manual создаст мусорные убеждения |
| R17 (логи без секретов/текстов), fail-safe | **да** | инвариант проекта |
| `PERSONA_TRAITS_MAX` / дедуп (`bot_persona`) | **да** | целостность данных персоны |
| `flags.persona_enabled` | **да** (но **не глушит молча**) | **разрешённый конфликт:** запрет на запись traits уважается (контентный гейт владельца), но manual-каскад **доходит** до шага Личности и логирует `reason=persona_disabled` (раньше — тишина). Обход записи traits **не** делаем |
| Целостность БД/оптимизм | **да** | не мутируем чужие данные |

### D4. Каскад Сон→Глубокий→Личность при manual
`run_once(manual=True)` → `_run` → `_maybe_deep_after_sleep(manual=True)` (без ранних return, критерий `chats>0`) → `_run_deep_all(manual=True)` (все чаты) → `_run_deep_once(manual=True)` → traits при `persona_enabled` (иначе WARNING `reason=persona_disabled`). `run_once` возвращает аддитивный `stats["cascade"]` (deep/traits) — контракт 202 не ломается.

### D5. Реактивные бейджи без WebSocket
- **Backend:** при `dream_running` → `active_until = now + _DREAM_RUN_TIMEOUT_SECONDS` (код-константа 900с, Δ=0); при `dream_in` — `min(конец окна, now+timeout)`; иначе `None`. То же для deep. Аддитивные `dream.manual`/`deep_sleep.manual`. **S10.18-23:** `manual` — настоящий маркер ручного прогона воркера (`_manual_run_until`/`_manual_deep_until`, выставляет `run_once`), а не «running вне окна»; таймаут `active_until` вне окна применяется только при `manual`, авто-тик вне окна даёт `None`. **S10.18-29:** deep-маркер выставляется не только при `run_once(deep=True)`, но и при любом ручном `_run_deep_all(manual=True)` (в т.ч. каскад из `run_once(deep=False)`) — бейдж deep не «теряет» фазу; флаг `_manual_deep_run` держит `manual` на протяжении всего прогона (в т.ч. >15 мин), TTL-маркер — после него.
- **Frontend:** после POST — оптимистичный `active=true` + немедленный `loadCognition()` + ретраи 1/3/8с; временный polling 5с на время прогона. D2: общий `_startCognitionTimer(ms)` без раннего return по `cognitionTimer`, restore возвращает **базовые 15с** (ранее `startCognitionPolling()` в restore раннеретурнил → 5с навсегда). D6 (пересмотрен в R2-1, итерация 2, вариант b): гейт по вкладке при СТАРТЕ ускорения снят — кнопка «Запустить синтез сейчас» на вкладке `modules`, поэтому 5с стартует сразу после POST; `setTab` → `stopCognitionPolling` снимает оба таймера при уходе (вечного 5с вне вкладки нет). **S10.18-22/-26 (фикс инварианта «вне Статуса — стоп»):** restore-путь стартует 15с только при `activeTab==='status'`; `closeModule` вне Статуса гасит polling; ретраи хранятся в `_cognitionRetryTimers` и снимаются в `stopCognitionPolling`. Без живого tick-таймера (ADR-1017-3 §2.6 сохранён).
- **S10.17-2:** `cognition==null` → `{text:'—', cls:'badge-muted'}`.

### D6. Ослабление порогов (безусловное, без флага) + идемпотентная DML-миграция
Новые code-defaults: 2/8/2/10/60/300000/10 (полная таблица с обоснованием — spec §4.1). PG-значения мигрируются идемпотентно **только если равны прежнему дефолту** (3/12/5/5/30/60000/30) — прецедент `migrate_prompt_canons`/`migrate_direct_reply_ttl_default`; кастом владельца не трогается. Флага `sleep_relaxed_thresholds_enabled` **нет**. Анти-мусор сохраняется (токены len≥5, overlap≥2, ≥2 источника, `protected_facts`, F5-пенализация).

### D7. Диагностика Личности
R17-safe WARNING/ERROR на каждый исход: `no_self_facts`, `persona_disabled` (**новое**), `json_error` (raw_len, без текста), `all_duplicates`, `budget_skip`, `llm_error`, `write_error`. Причины 0 черт видны в journald/логах без раскрытия содержимого.

### D8. Жёсткая зависимость от ADR-1018-7 (F7)
Настройки воркеров обязаны резолвиться по приоритету **per-chat DB → глобальный DB → env-дефолт** (единый accessor `services/worker_settings.py`, ADR-1018-7 D2), и планировщик должен быть реактивным (ADR-1018-7 D4). До этого:
- включение Сна в scope чата воркером не видится;
- включение Сна без рестарта не регистрирует джоб.
Порядок раунда: **F7 → F2 → F4/F5**. F2 обязана использовать тот же accessor, а не локальный `hot.get`.

### D9. Аудит без нового каталог-ключа
Новые исходы manual-обхода пишутся строковыми `status` в существующую `memory_dream_log` (`gate_override`, `budget_override`) — строки не являются записями каталога → **каталог-Δ = 0**. R17-safe (только статус/chat_id/числа). Новый `source=chat|global|default` в логах настроек — из F7.

### D10. Включение рубильников
`DREAM_ENABLED=True` / `DEEP_SLEEP_ENABLED=True` — **после** F7, для целевого чата (через UI/scope), с обоснованием в отчёте T-1713. Не «вслепую»; не через хардкод в коде (остаётся env/PG-значение).

## Consequences

**Positive**
- Ручной запуск реально прогоняет весь пайплайн и даёт результат; интеллект перестаёт быть «пустым».
- Ручной приоритет — базовое поведение (платформа «делаем нормальную систему»), без риска «забыли включить флаг».
- Бейджи меняются в пределах целевого интервала без WebSocket/живого таймера.
- Ослабление порогов возвращает реальный поток фактов при сохранении анти-мусора.
- Каталог-Δ=0 (флаги не вводятся) — свод раунда упрощается (см. F6).
- Расход остаётся видимым (учёт worker_budget), но перестаёт быть запретом.

**Negative**
- Безусловный обход гейтов/budget без флага — оператор может «прожечь» бюджет ручными прогонами; принято (UPD п.5: «игнорировать экономию»), митигируется аудитом и поднятыми лимитами.
- DML-миграция порогов — риск задеть кастом; mitigated «только если == прежний дефолт».
- Больше LLM-расходов при ослабленных порогах — осознанно (ТЗ §2.1 «снять паранойю»).
- Manual-каскад вне окна может синтезировать beliefs вне «ночного» окна — семантика «сна» размывается; принято по ТЗ.
- F2 не может быть выкачена/проверена раньше F7 (последовательность раунда).

## Alternatives

- **A1. Оставить фича-флаг `sleep_manual_priority_enabled` (default OFF).** **Отклонено владельцем** (UPD п.2): базовая логика, без флагов.
- **A2. Оставить «manual соблюдает gate/budget» (F-10 §5-6).** Отклонено: прямо противоречит ТЗ §2.2 и не решает прод-проблему.
- **A3. Ввести WebSocket для реактивных бейджей.** Отклонено: инфраструктуры нет, большой объём, ADR-1017-3 §2.6; polling+оптимистика достаточны.
- **A4. Живой `setInterval`-tick для остатка.** Отклонено: дублирует polling, риск утечек; ускорение polling только на время прогона.
- **A5. `active_until = None` при running (оставить «идёт»).** Отклонено: ТЗ требует «до [окончание/таймаут]».
- **A6. Менять только промпт Личности.** Отклонено: причина 0 черт — флаги/пороги/read-path (`deep_sleep_enabled`, self-факты), а не промпт.
- **A7. Обходить `flags.persona_enabled` в manual-каскаде.** Отклонено: это контентный гейт владельца; вместо обхода — явная диагностика `reason=persona_disabled` (D3).
- **A8. Обходить локи/`protected_facts` ради «абсолютности».** Отклонено: это не гейты стоимости, а safety/целостность; обход нарушил бы R17/приватность.
- **A9. Починить рассинхрон настроек внутри F2.** Отклонено: другой класс дефекта и объём → вынесено в F7/ADR-1018-7; F2 лишь зависит от неё (D8).
