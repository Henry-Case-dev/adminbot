## Приёмочные инварианты S3 (нарушение = НЕ принято)
1. **Ровно 2 физических LLM-вызова** на целевой пайплайн (L1 + L2; ADR-1022-3/4/5). Третий вызов — блокер. В S3 вызовов не добавляется: L1-модуль/слот не врезаны в живой путь.
2. **В S3 живой путь не меняется:** `summary_generator._generate_two_call` (Stage-1 «Редактор» `SUMMARY_EDITOR_SYSTEM_PROMPT`/`parse_summary_handoff_ex` + Stage-2 «Рассказчик» + fallback `step="single"`) — **вне diff**; публикация/`cover_prompt`/`response_mode`/обложка (§104) не тронуты; **гейт S6/S10 закрыт** (D4).
3. **L1 НЕ пишет Саммари** (§94): выход — только темы/факты/ID, без прозы, заголовков и абзацев.
4. **Строгий JSON §95** + валидация (структура, существование `message_id`, `evidence_message_ids`, отсутствие висячих ссылок); **невалидный JSON не передаётся в L2** (fail-closed, §95/§106) — не публиковать пустое/выдуманное.
5. **Пространства ID различаются и обрабатываются явно:** DB `id` (`Fragment.message_ids`) ↔ TG `message_id` (§92-payload) ↔ `reply_to_id`; конвертация/сверка по явной таблице, без подмены и без фабрикации.
6. **Канон ADR-1013-3:** промпт L1 — отдельный (не общий с L2, §81); `resolve_prompt` + `PREV_*` + ступень `PROMPT_MIGRATIONS` + ROLLBACK + эталон — **одним коммитом**.
7. **Δ DDL = 0.** **Δ каталога = 0 или письменная санкция @Architect** (слот модели: каталог vs env-only — решение Step 2).
8. **Детерминизм:** один вход → одинаковый выход (порядок тем/ID, повторный прогон байт-идентичен после нормализации).
9. **CSP/zero-build, R17/R18** (логи — только числа/коды/id, без ключей и содержимого сообщений); `plans/current_task.md` не изменяется.
10. **Интеграция в живой путь — только по санкции @Architect и не раньше S5/S6**; S9 §113 — отдельная фича.
