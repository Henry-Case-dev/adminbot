# ADR-1026-5 — S3 «L1 Кластеризатор»: контракт §95, вариант (a) двухвызовности и AMEND состава Stage-1

- **Статус:** Accepted (Step 2 @Architect, 23.09.2026)
- **Фича:** S3 `summary-l1-clusterizer-round1026` (Эпик 2, шаг «L1 — Кластеризатор», §94–§95)
- **Тип:** backend/LLM + канон промптов; **Δ DDL = 0**; **Δ каталога = +1** (санкция D4 — промпт-ключ L1)
- **Связано:** **ADR-1022-4** (Саммари two-call) — **AMEND (состав Stage-1; вступает в силу на S5)**; **ADR-1023-3** (`response_mode` в Stage-1 JSON) — **AMEND (источник поля)**; **ADR-1023-6** (`cover_prompt` в Stage-1 JSON) — **AMEND (источник поля)**; ADR-1022-3/5 (2-вызовность фактчека/прямого чата — REUSE); ADR-1023-1/-8, ADR-1024-4/-10, ADR-1025-8 (hotfix4) — REUSE; ADR-1013-3 (канон) — задействован; ADR-1025-24 **D4** (гейт S6/S10) — governed-by; ADR-1026-1/-2 (границы S1, переиздание F8), ADR-1026-4 (S2→S3) — REUSE
- **Baseline:** HEAD `4007081` == `origin/master`, `APP_VERSION` 2.58.21, pytest `.venv` 8569/0, JS 43/43, каталог 467/426/442/100/98/21, Δ DDL=0

## Контекст

§80/§81 задают целевой пайплайн: фильтр → восстановление → **L1 Кластеризатор** → пакет фактов → **L2 Писатель** → форматирование → существующая публикация. Сейчас Саммари — ровно **2 физических LLM-вызова**: Stage-1 «Редактор» (Markdown-выжимка + служебные `response_mode`/`cover_prompt` в том же JSON) → Stage-2 «Рассказчик» (ADR-1022-4, ADR-1023-3/-6, тест `await_count==2`). §94 требует от L1 строгий JSON тем/фактов и прямо запрещает писать Саммари; §95 требует валидации структуры/`message_id`/`evidence_message_ids` и запрета передачи невалидного JSON в L2; §106 — не публиковать пустое/выдуманное.

Открытые вопросы Step 1: (1) как совместить L1-LLM с инвариантом 2 вызовов; (2) кто после замены Stage-1 отдаёт `cover_prompt`/`response_mode` (§104 обложку не трогать); (3) когда врезать L1; (4) состав §82 в S3; (5) каталог vs env-only для слота; (6) deploy/bump. Разбор PM (`tasks.md` §«Открытые вопросы») подтвердил вариант (a) как единственный, не нарушающий инвариант.

## Решения

**D1. Вариант (a): L1 заменяет Stage-1, L2 заменяет Stage-2 ⇒ ровно 2 LLM-вызова; третий вызов — блокер.**
- Целевой пайплайн (после S5): `L1 (кластеризация §94) → пакет фактов §96 (S4, детерминированно) → L2 (писатель §97–§99)`. Физических LLM-вызовов — **два** (L1 + L2); сборка пакета фактов и форматирование — без LLM.
- **L1-слой = ровно 1 вызов на запуск.** §93-фрагменты (overlap=1) **упаковываются в один вход** L1 (ASC, дедуп, маркеры границ), а не обрабатываются отдельными вызовами; при нехватке бюджета — детерминированный `truncated` + `skipped_ids` + лог («не резать молча»). Мультивызовый chunk-merge — **BLOCKED**; пересмотр — только отдельным ADR при живых данных S6/S10 (санкция владельца на третий вызов отсутствует).
- **AMEND ADR-1022-4** (в части состава Stage-1; вступает в силу на S5):
  - **меняется:** Stage-1 «Редактор» (Markdown-выжимка) → Stage-1 «Кластеризатор» (строгий JSON §95 + те же служебные поля); ключ промпта Stage-1 `prompts.summary_editor_system_prompt` → `prompts.summary_l1_clusterizer_system_prompt` (старый ключ/константа/парсер сохраняются для отката и OFF-пути); вход Stage-2 — не «digest», а валидированный пакет фактов §96 (S4).
  - **сохраняется:** ровно 2 физических вызова; изоляция Stage-2 (видит только валидированный промежуточный объект); fallback на одиночный путь при невалидном Stage-1; доставка/стриминг/постфикс шиза; kill-switch `SYSTEM2_SUMMARY_ENABLED`; validator-loop Рассказчика; `{max_symbols}`/`{username}`-инварианты; rich/plain-каналы (ADR-1023-6).
- Альтернатива (b) «L1 третьим вызовом» — **отклонена**: нарушает инвариант 2-вызовности (ADR-1022-3/4/5), Critical-риск; альтернатива (c) «та же замена под другим именем» — отклонена как не отличающаяся от (a) по существу.

**D2. `cover_prompt`/`response_mode` остаются служебными полями JSON Stage-1; после замены их отдаёт L1 (вариант i).**
- L1 возвращает в **том же JSON §95** дополнительные опциональные поля: `response_mode` (enum, `normalize_response_mode`) и `cover_prompt` (EN ≤300, `normalize_cover_prompt`) — **без третьего вызова**. Семантика ADR-1023-3 п.1 (роутер режимов внутри Stage-1) и ADR-1023-6 п.1 (промпт обложки в том же JSON) сохраняется; меняется только эмитент.
- **AMEND ADR-1023-3 / ADR-1023-6** (в части источника полей; вступает в силу на S5): `response_mode` и `cover_prompt` по-прежнему едут в Stage-1 JSON, но формируются L1-Кластеризатором; нормализаторы, обрезка, конкатенация «стиль + cover_prompt» (`compose_cover_image_prompt`), `_resolve_cover_prompt`/фолбэк (hotfix4/ADR-1025-8 D1), каналы rich/plain и §104 («generate_image не трогать») — **без изменений**.
- В S3: контракт/валидатор принимают и нормализуют эти поля, **живой путь не меняется** (Stage-1 «Редактор» продолжает их отдавать). Отсутствие/невалидность поля → graceful-деградация ровно как сегодня: `response_mode=""` → ключ-предохранитель `prompts.verbilizer_default_mode`; `cover_prompt=""` → существующий fallback-промпт обложки.
- Альтернатива (ii) «отдельный детерминированный источник» — отклонена: теряется динамический выбор режима/качество обложки, поведение S5 изменилось бы относительно S3 без санкции, противоречит §104 («промпт обложки сохранить») и принципу «роутер внутри Stage-1». Альтернатива (iii) «перенести в L2» — отклонена: L2 не видит сырьё (изоляция) и не может осмысленно выбрать режим/сцену; меняет канальную логику.

**D3. Врезка — S5/S6, не в S3; в S3 активируются модуль+канон+валидация+слот.**
- В S3: новые `services/summary_l1_contract.py` и `services/summary_l1_clusterizer.py`, промпт-канон (+1 ключ, `PREV_*`, ступень миграции, эталон), env-слот, логи `L1_*`, тесты. `services/summary_generator.py` (`_run`/`_generate_two_call`/`_llm_generate`), XML, публикация/обложка/режимы — **вне diff**.
- Врезка L1 в живой путь — **не раньше S5** (нужен S4-пакет фактов, иначе L1 не сможет питать Рассказчик) и **S6** (публикация); по письменной санкции @Architect, после live-приёмки Эпика 1 (гейт S6/S10 + D4/ADR-1025-24).
- Проверка S3 без врезки: юнит/интеграционные тесты модуля с моком LLM (прямой вызов ядра) + регрессия живого пути (`await_count==2`, Stage-1/Stage-2 байт-в-байт, OFF-цепочка) + канон-тесты. E2E не требуется (S9 — отдельная фича).
- Альтернатива «врезать сразу в S3 с kill-switch» — отклонена: L2 ещё не существует; врезка изменила бы публикационный контур до live-приёмки Эпика 1 (нарушение D4).

**D4. Состав §82 в S3: только слот summary L1; промпт — каталог (+1, санкция), модель/провайдер/ключ — env-only до S5.**
- Слот summary L1: провайдер+модель (согласованная пара), промпт слоя, существующая политика fallback, «не выбрано» → глобальная основная модель (наследование ≠ аварийное резервирование). Параметры генерации — существующие (`LLM_TIMEOUT`/ретраи), temperature не вводится.
- **Промпт L1 — новый PG-ключ** `prompts.summary_l1_clusterizer_system_prompt` (группа `prompts_summary`, advanced, `synthesizer`): **Δ каталога = +1 — санкционировано** (ADR-1013-3-канон требует `resolve_prompt`+`PREV_*`+`PROMPT_MIGRATIONS`+эталон; §85 «один промпт — один источник», библиотека промптов). Каталог: REGISTRY 467→**468**, Settings **426 (без изменений** — prompts-ключи PG-only)**, categorized 442→**443**; GROUPS/`_TAB_BY_GROUP`/TAB_RULES — без изменений. **Переиздание frozen-артефактов F8** — штатная процедура ADR-1026-2.
- **Модельный слот — env-only ClassVars** `SUMMARY_L1_BASE_URL`/`SUMMARY_L1_MODEL_NAME`/`SUMMARY_L1_API_KEY` (**Δ каталога = 0**): резолвер читает `hot.get("models.summary_l1_*", settings.*)` (forward-compatible), «не выбрано» → глобальная модель. Обоснование: до S5 у слота нет живого потребителя — каталог/UI-слот создали бы переключатель, который ничего не меняет (§86 «не показывать фиктивные значения»), и преждевременный Δ каталога. На S5 (врезка) каталог/UI-слот добавляются отдельной санкцией (образец — `INTEL_*` + `PROVIDER_BLOCKS`), резолвер не переписывается.
- **Summary L2 — S5; direct L1/L2 (§84) — вне S1–S10** (независимый роутинг прямого чата — отдельное решение после Эпика 2; F5-витрина честно показывает одну модель для обеих стадий — техдолг §61.8-3).
- Альтернатива «каталог сразу» (+3 модели/+1 секрет, новая группа, TAB_RULES, `PROVIDER_BLOCKS`) — отклонена для S3: мёртвый UI-слот до врезки, лишний Δ каталога без потребителя; S5 добавит без переработки резолвера.

**D5. Контракт §95/§93/§92: строгая схема, явные пространства ID, fail-closed, детерминизм.**
- Схема: `{schema_version:1, threads:[{thread_id, topic, message_ids[], facts:[{text, evidence_message_ids[]}]}], unassigned_message_ids[]}` + опциональные служебные `response_mode`/`cover_prompt` (D2). Лишние поля → `invalid`; типы строгие; `schema_version` ровно `1`.
- Лимиты: `topic` ≤200 без `\n`; `fact.text` ≤500 без `\n\n`, без системных тегов (R17); тредов ≤100, фактов/тред ≤30, всего ≤1000 — превышение → `invalid` (fail-closed, без тихого усечения фактов).
- **Пространства ID:** вход/выход L1 — TG `message_id` (§92-payload, индекс по payload); `Fragment.message_ids` — DB `id` — только упаковка §93, конвертация через таблицу соответствия строк окна; неоднозначность/пропуск → `invalid` (`id_space_mismatch`), подмена/фабрикация запрещены. `evidence ⊆ message_ids` треда; один id — ровно в одном треде; `unassigned ∩ threads = ∅`; пропущенные моделью payload-id детерминированно добавляются в `unassigned` (не терять молча).
- Парсер — существующий `system2_handoff.parse_json_object` (фенсы/обрамление/`raw_decode`); канонизация — дедуп+ASC по `(timestamp,message_id)`, перенумерация `thread_001…`, дедуп фактов по нормализованному тексту с объединением evidence; двойной прогон байт-идентичен.
- **Fail-closed:** `L1Result{status: ok|empty|invalid|truncated|error, payload, invalid_reason, …}`; `empty`/`invalid`/`error` → **в L2 не передаётся** (§95), пустое/выдуманное не публикуется (§106). Аддитивные счётчики для S7/S8 без узлов ExecutionGraph.
- Альтернатива «мягкий валидатор с авто-починкой ссылок» — отклонена: §95 требует отсутствия несуществующих ссылок, авто-починка = фабрикация. Альтернатива «multi-call chunk merge» — отклонена (см. D1).

**D6. Инварианты/deploy.**
- Ровно 2 вызова на целевой пайплайн (S3 не добавляет); Δ DDL=0; Δ каталога = +1 (санкция D4) + переиздание F8 (ADR-1026-2); CSP/zero-build; R17/R18; §57–§73/F0–F11/S1/S2, публикация/обложка/XML — не тронуты.
- **Deploy = ДА** (T-3280 применим): меняются рантайм-файлы (`param_catalog.py`, `summary_prompts.py`, `prompt_migrations.py`, `config/settings.py`, новые модули) и сид промпт-ключа в PG → **bump `APP_VERSION` 2.58.21 → 2.58.22** + `README.md` + cache-bust; перед деплоем — минимальные §114-тесты. Альтернатива NOT_APPLICABLE — отклонена: рантайм и каталог реально меняются, «bump без поставки» не применим.
- Откат: `git revert` + annotated-тег `pre-round1026-s3` (T-3253); hot-OFF не требуется (живой путь не изменён); канон-откат — документированный ROLLBACK (слепок `PREV_SUMMARY_L1_CLUSTERIZER_R1026`).

## Последствия

- Инвариант 2-вызовности сохранён при полной замене семантики Stage-1 (§94–§95); §93 реализуется упаковкой в один вход — при экстремально больших логах возможен `truncated` (статус+лог), что осознанно предпочтено третьему вызову.
- `cover_prompt`/`response_mode` сохраняют текущее поведение без третьего вызова и без правок публикации/обложки (§104).
- S3 поставляет автономный, тестируемый модуль и канон, не меняя живой контур; S5 получает готовые контракты (S4 — пакет фактов, S5 — врезка L1+L2).
- Новый промпт-ключ становится доступен в библиотеке промптов; модель-слот до S5 — env-only (UI честно не показывает несуществующую возможность).
- Ограничения (документируются): слот модели без UI до S5; семантика chunk-merge ограничена одним вызовом; `mentions` в §92-payload отсутствует (не выдумывается).
