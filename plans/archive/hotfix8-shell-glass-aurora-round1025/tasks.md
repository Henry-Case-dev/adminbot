## ✅ Acceptance criteria UPD2 §9 (зафиксировано явно)

**Работа НЕ принята (любой пункт = возврат в сборку):**
1. Sidebar/topbar снова выглядят как обычные карточки.
2. Вокруг shell есть яркий ореол.
3. Стекло выглядит как дешёвый blur или виньетка.
4. Фон выглядит статичным.
5. Mobile layout перекрывает контент.
6. SaveBar и внутренний scroll конфликтуют.
7. Shell не отделён по глубине от контентных карточек.

**Работа принята:**
1. Shell стал тёмно-серым glass-слоем, а не карточкой.
2. Эффект стекла subtle, дорогой и аккуратный.
3. Background живой и атмосферный.
4. Desktop/mobile/fullscreen стабильны.
5. Всё выглядит как единый polished Control Center UI.

**Обязательные 5 режимов проверки (UPD2 §8.5):** Desktop normal · Desktop fullscreen · Tablet · Mobile portrait · **Mobile fullscreen inside Telegram WebView**.

## Открытые вопросы для @Architect (решить в `spec.md`/ADR-1025-16 либо эскалировать владельцу через @Orchestrator)

- **(a) Эквивалент Framer Motion.** UPD2 §2 просит Framer Motion/React — **несовместимо** с Vue 3 zero-build + CSP `script-src 'self'`. Зафиксировать ограничение и выбрать эквивалент для «анимации и микродвижений»: чистый CSS (transitions/keyframes), **Web Animations API**, Canvas 2D/rAF или SVG. Нужен один последовательный подход для shell/aurora.
- **(b) Точная механика aurora/mesh в рамках CSP.** CSS-`blob`-слои (transform/filter/keyframes) vs **Canvas 2D + rAF** vs гибрид. Обосновать перф на Telegram WebView (CPU/GPU/батарея, слабые устройства), поведение при `visibilitychange` (пауза), `prefers-reduced-motion`, dirty-check и кап нагрузки; где живёт слой (`body::before` vs отдельный контейнер), z-index относительно shell/карточек.
- **(c) Как снять цветную «линзу»/halo с shell, сохранив стекло.** Shell-панели несут `data-glass="a"` (`index.html:55/3824/3840`) → `[data-glass="a"]::before` (`app.css:1142-1157`) рисует цветную teal/blue/violet линзу с radial-mask. Решить: убрать атрибут с shell-панелей, сузить селектор или нейтрализовать `::before` для shell — **не задев** остальных носителей `data-glass` и прецедент hotfix6 (запрет `backdrop-filter: url()`). Плюс ослабить `--shell-border-color .20`/`--shell-highlight .18`.
- **(d) Точные значения токенов и радиусов.** Привести shell-токены к UPD2 §4: bg `rgba(24,28,38,0.72)` (mobile `0.78`), border `1px solid rgba(255,255,255,0.08)`, highlight `inset 0 1px 0 rgba(255,255,255,0.06)`, shadow `0 8px 24px rgba(0,0,0,0.18)`, backdrop `blur(18px) saturate(115%)`, очень слабый SVG displacement; радиусы (sidebar 0/большой; topbar/pill/selector/floating 14–18; mobile 16–20). Как разделить **три слоя** (фон → shell → карточки) по тону и глубине без нарушения AA и без «карточка просто получила blur».
- **(e) Где снять/оставить SVG displacement.** Очень слабый displacement не должен искажать текст/интерактив («не лупа и не желе»): на каких именно поверхностях (или фоновых слоях) фильтр допускается, а где — deny-list (прецедент F2 §9 / hotfix7).
