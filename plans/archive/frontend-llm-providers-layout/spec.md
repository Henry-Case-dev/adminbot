# spec.md — frontend-llm-providers-layout (ТЗ 6 раунда 10.4, фича E)

Задачи: T-1024…T-1032 (tasks.md). Стадия старта — PLANNED → ARCHITECTED (наст. файл).
База: HEAD `1410a68`. Порядок: после D/C, до A/B.

## 1. Контекст и проблема

Вкладка `llm_providers` рендерит категории моделей и ключей БЛОКАМИ: `groupedForTab` (app.js:1433-1485) сортирует группы по рангу КАТЕГОРИИ (первое вхождение в sources) → категория models (8 групп) целиком, затем keys (7 групп) целиком. ТЗ 6: логический порядок **основные модели → ключи → фолбэк → расширенные**.

## 2. Ключевые решения

| ID | Решение | Обоснование |
|----|---------|-------------|
| **E-1** | **TAB_RULES-секционирование** (param_catalog.py:1374-1406): `TAB_LLM_PROVIDERS` = 4 правила-секции (повтор категории — формат `frozenset` допускает):<br>1) `(MODELS, {models_main})` — «Основные модели»;<br>2) `(KEYS, {keys_llm, keys_groq, keys_openrouter})` — «Ключи»;<br>3) `(MODELS, {models_fallback})` — «Фолбэк»;<br>4) `(MODELS, {остальные 6})` + `(KEYS, {остальные 4})` — «Расширенные».<br>Каждая группа моделей/ключей — ровно на одной вкладке (покрытие целиком: `_TAB_BY_GROUP` :1424-1431 без ValueError). | Серверный контракт — источник истины; секции задаются ПОРЯДКОМ правил (flat-порядок «(категория, группа)» — то, что требования ТЗ «модели → ключи → фолбэк → расширенные»). |
| **E-2** | **groupedForTab → плоский порядок**: сортировка витрины следует порядку ПРАВИЛ (не категорий): ранг пары «(category, group)» = порядковый номер вхождения группы в правила вкладки; внутри — `group.order`; «Прочее» — в конец. Обобщение без изменения контракта: раньше rank = `index of category` (app.js:1446), теперь для вкладок с секционированными правилами — flat-rank. **Совместимость**: вкладки без повторения категорий — поведение не меняется (порядок правил = порядок категорий → тот же результат). | AC-E2 (порядок = целевой); регресс «прочие вкладки без изменения порядка» — обязательный негативный тест. |
| **E-3** | **Визуальная иерархия — заголовки секций** через расширение **TABS-зеркала**: запись `llm_providers` в app.js получает `sections: [{title: 'Основные модели', category: 'models', groups: [... ]}, ...]` (та же схема источника: category + groups/except/null). `<template>`-рендер перед первой группой секции выводит заголовок секции (h3/подзаголовок). Вкладки без `sections` — как раньше (общий рендер). | TABS-зеркало — принятая архитектура (3.5.1; B-1-тесты); новый серверный API/контракт не вводим (минимальный дифф); заголовки секций — требование T-1028 AC-B2. |
| **E-4** | Разметка прогрессивных уровней: секции 1-3 — целиком basic (группа `models_main`/`keys_llm`/`models_fallback` — все базовые); секция «Расширенные»: `models_llm_timeouts`/`models_llm_guard` — advanced (маркеры timeout/budget, как сейчас, **без изменений**); `models_embeddings`/`models_extra_providers`/`models_video_summary`/`models_checkup` + `keys_search`/`keys_betterstack`/`keys_youtube`/`keys_media` — basic (явно/по дефолту). | AC-E3: у секции «Расширенные» ≥1 basic-группа (после фичи D свёрнутый аккордеон не «прячет» секцию — она видна базовыми группами); таймауты/бюджеты остаются advanced (их и видно в аккордеоне). |
| **E-5** | Ключи-секреты: маска `{configured, last4}`, виджет password, права (глобальные — только global admin; local — BYOK-блок) — **без изменений**; перенос группы — только рендер-группа. | AC-B3 (маска/тесты webapp_rbac зелёные). |
| **E-6** | `tabCategories` для `llm_providers` = уникальные категории всех секций (models, keys) — без изменений (RBAC не трогаем — models/keys строго глобальные, per_chat=False). | Канон «модели/ключи — строго глобальные» (F-7 §4). |
