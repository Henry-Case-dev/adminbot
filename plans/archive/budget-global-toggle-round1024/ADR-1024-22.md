# ADR-1024-22 — Глобальный master-рубильник бюджетов (`flags.budgets_enabled`): OFF = лимиты не ограничивают, статистика ведётся

- **Статус:** ✅ **ACCEPTED** (Step 2 @Architect, раунд 10.24 / UPD5-critical). Обязывает @Builder.
- **Дата:** 2026-09-20
- **Фича:** F21 `budget-global-toggle-round1024`
- **Раунд:** 10.24, `plans/current_task.md:404`; backlog §10.24, F21
- **База:** HEAD `a406440` (прод `4314ea4`); каталог сверен рантаймом: `REGISTRY 458 / GROUPS 97 / mapped 95 / TAB_RULES 20 / Settings 417 / categorized 433`
- **Связано:** ADR-1018-7 (единый резолв `chat → global → default`), ADR-1024-21 (F20 write-path per-chat), ADR-1024-9 (образец модульной вкладки/карточки)
- **AMEND:** **ADR-1019-3** (D1/D9), **ADR-1019-8** (D1/D2/D9), **ADR-1019-2** (D4/D7). **SUPERSEDE: нет.**
- **Приоритет:** P0 / Critical. **Δ DDL = 0.** Δ каталога = **≠ 0** (санкция owner, Gate G №1): +1 ключ / +1 группа.

## 1. Context

1. Владелец (UPD5, `current_task.md:404`) требует **один глобальный тумблер бюджетов** в разделе «Модули»
   (карточка `mod_budgets`): выключение бюджетов целиком — **глобально или для выбранного чата**, с проверкой,
   что настройка реально работает.
2. Сегодня такого рубильника нет: карточка помечена `noToggle: true` (`web/app.js:393-395`), вкладка
   `TAB_MOD_BUDGETS` содержит только `limits_*` (`param_catalog.py:2117-2120`), а enforcement живёт в трёх
   независимых точках (`chat_usage.budget_snapshot`, `worker_budget.consume`, `direct_chat_service._build_context`);
   срабатывание даёт `NoApiKeyForChat('budget')` (`llm_client.py:404-420`) → заглушку `content.no_key_reply`.
3. Рядом уже есть **другой** гейт — `flags.chat_context_budgets_enabled` (`direct_chat_service.py:1141-1145`),
   управляющий усечением контекста (не master-лимитами); сид `scripts/backfill_104_chat_flags.py` ставит его `false`
   целевому чату. Их нельзя смешивать: нужна явная иерархия.
4. Каталоговый слой поддерживает ровно такой паттерн: модульные группы `flags_module_*` (`param_catalog.py:290-334`),
   per-chat резолв `chat → global → default` (`worker_settings.py:123-150`), образец резолвера `image_generation.resolve_module_enabled`.
5. **Границы (критично):** OFF не должен обходить `keys.allow_global=false` (право BYOK, не бюджет), ключи/провайдеры,
   `physical-two-call`; и не должен останавливать запись usage-статистики (требование owner №2).
6. Инварианты: Δ DDL = 0, R16 (аддитивность), R17/R18 (секреты), `physical-two-call`, `tma-menu-freeze`,
   порядок роутеров `bot.py`. F20 write-path (`web/api/routes.py`) — предпосылка и зона «не ломать».

## 2. Decision

### D1. Новый ключ `flags.budgets_enabled` + группа `flags_module_budgets` (Δ каталога санкционирован)

Добавляется одна запись REGISTRY (`BUDGETS_ENABLED`, категория `flags`, `type=bool`, default **True**) и одна
`GroupSpec("flags_module_budgets", "flags", "Модуль: Бюджеты", …, 21)`. Группа приписывается к **существующей**
вкладке `TAB_MOD_BUDGETS` (добавлением `(CATEGORY_FLAGS, frozenset({"flags_module_budgets"}))` в её rule).
Новых вкладок/карточек не создаётся — `tma-menu-freeze` не затрагивается.

### D2. Дефолт ON (обратная совместимость)

`config/settings.py: BUDGETS_ENABLED = _env_bool("BUDGETS_ENABLED", True)`. При отсутствии ключа в PG
`hot.get` падает на код-дефолт `True`; авто-сид `PgDatabase._seed_settings` вставит `flags.budgets_enabled=true`
(ON CONFLICT DO NOTHING) при следующем старте. Поведение без явного тумблера — **байт-в-байт как прежде**.

### D3. Область: global + per-chat, per-chat override приоритетнее

Резолв — единый `services/budget_gate.py::budgets_enabled(chat_id)` поверх `worker_settings.resolve_setting_cached`
(приоритет `chat → global → default(True)`). `chat_id=None` (фон-скоп `'global'`) видит только глобальный слой.
Per-chat override всегда перекрывает глобальный. **Fail-open:** ошибка резолва → `True` (enforcement как прежде).

### D4. OFF = прекращение enforcement, НЕ прекращение учёта

Полный перечень enforcement-точек фона (`worker_budget`) и их связь с master-флагом:

| Точка фона | Роль | Поведение при master OFF |
|---|---|---|
| `consume` | UPSERT счётчика + проверка cap/`0`-sentinel | UPSERT **до** гейта (расход пишется); затем `return True` — лимит не применяется |
| `_metric_limit` | резолв суточного лимита метрики | **не вызывается** (нет резолва — стоп невозможен) |
| `global_degradation_allows` | предохранитель деградации: воркеры (`dream`/`lore`/`nostalgia`/deep-sleep) решают «идти ли в тик» **до** `consume` | `return True` **до** чтения usage (глобальный скоп → `chat_id=None`) |
| `allowed_workers` | чистый (sync) помощник матрицы деградации | отдельного гейта не требует — в проде вызывается только из `global_degradation_allows` |

- `worker_budget.consume`: UPSERT счётчика **до** проверки; при OFF → `return True` (лимит не применяется, расход записан).
- `chat_usage.budget_snapshot`: предельные значения и usage читаются, но при OFF `exceeded=False`, `exceeded_metric=None`;
  в dict добавляется аддитивный `budgets_enabled` (R16). `report_call`/`register_usage` гейтом не затрагиваются.
- Новая точка `budget_gate` — единственный источник решения; дублирующий резолв в `llm_client` не вводится
  (ветка `if snapshot["exceeded"]` получает `False` транзитивно).

### D5. Master-рубильник приоритетнее `flags.chat_context_budgets_enabled`

В `direct_chat_service._build_context` эффективный гейт контекста = `master AND context_flag`:
при master OFF усечение контекста выключено, даже если `flags.chat_context_budgets_enabled=true` (owner №3).
При master ON поведение не меняется — контекстный флаг по-прежнему решает. Вторую (синхронную) точку
`_apply_context_budget(enabled=None)` не трогаем: единственный production-call-site передаёт `enabled` явно.

### D6. Границы OFF (что НЕ отключается)

OFF снимает только бюджетные ограничения: суточные cap прямого/фонового контура, бюджетный sentinel `0`=запрет
и контекстное усечение. OFF **не** обходит: `keys.allow_global=false` (`NoApiKeyForChat('forbidden')`),
BYOK-резолв ключа, выбор провайдера/модели, `physical-two-call`, любые права доступа.

### D7. UI — существующая карточка, без новых пунктов

`web/app.js`: у `mod_budgets` убрать `noToggle: true`, добавить `toggleKey: 'flags.budgets_enabled'`; в `TABS`
`mod_budgets` добавить source `flags_module_budgets` (зеркало Python-rule). Сохранение — существующим путём
`saveConfigItem` (`global` только при `per_chat=false`; для `flags.*` — per-chat + `X-Chat-Id`). F20-путь не меняется.

### AMEND ADR-1019-3 (`budget-settings-section`, D1/D9)

**Было:** вкладка `mod_budgets` — «раздел без master-тумблера (это лимиты, а не модуль)» (D1);
«Feature flag не вводится» (D9).
**Стало (уточнение, не отмена):** у `mod_budgets` появляется **master-рубильник** `flags.budgets_enabled`
(новая группа `flags_module_budgets` на той же вкладке); D9 заменяется: **продуктовый тумблер вводится**
(он же kill-switch). Sentinel-семантика, состав групп лимитов, тумблер «Безлимит по чату» и nav-разметка
вкладки **не меняются**.

### AMEND ADR-1019-8 (`per-chat-limits-and-seed`, D1/D2/D9)

**Было:** единственный путь изменения бюджетной политики — per-chat данные; «Feature flag не вводится» (D9);
sentinel-таблица (D2) не предусматривала master-уровня.
**Стало (уточнение, не отмена):** над per-chat-данными вводится **глобально-перчатный master-слой**
(`flags.budgets_enabled`); D1 сохраняется (значения остаются данными чата), D2 (таблица sentinel) — без изменений,
D9 заменяется: master-флаг = kill-switch бюджета. Сид бюджетов (`config/chat_settings_seed.json`) не меняется;
новый ключ сидится автоматически код-дефолтом True.

### AMEND ADR-1019-2 (`direct-chat-budget-unlimited`, D4/D7)

**Было:** D4 — `budget_snapshot`/BYOK-резолв как единственный решающий снимок; D7 — «Feature flag не вводится».
**Стало (уточнение, не отмена):** в `budget_snapshot` добавляется master-короткое замыкание (`exceeded=False`
при OFF) и аддитивный `budgets_enabled`; BYOK-порядок «свой → глобал-бюджет → свой-фоллбэк → sandbox» сохраняется,
но бюджетная ветка не срабатывает при OFF. D7 заменяется: kill-switch — `flags.budgets_enabled`.

## 3. Consequences

**Positive**
- Один понятный владельцу рубильник «выключить все бюджеты» глобально/для чата; состояние сохраняется штатным
  per-chat путём (F20), без новых таблиц/эндпоинтов.
- OFF не «ослепляет» аналитику: счётчики вызовов/токенов продолжают расти (owner №2).
- Границы OFF узкие и явные: права/ключи/`allow_global`/провайдеры не затрагиваются (R1-митигация).
- Минимальный дифф: 1 новый модуль + точечные гейты в 3 точках + 3 строки каталога + 1 строка UI.

**Negative / долг**
- Δ каталога ≠ 0 вскрывает широкую поверхность пин-тестов (≈17 файлов) — обновляется одним коммитом (§7.1 spec).
- Две «бюджетные» сущности (`flags.budgets_enabled` master и `flags.chat_context_budgets_enabled` контекст)
  сосуществуют — требует явной иерархии (`master AND context`) и теста на совместное состояние.
- При master ON поведение контекстного флага сохраняется — «OFF контекста при master ON» по-прежнему возможен
  (осознанно: master не включает то, что контекст выключил).

## 4. Alternatives

| Альтернатива | Почему отклонена |
|---|---|
| Гейт только в `llm_client` (без `budget_snapshot`/`worker_budget`) | Не покрывает фон-контур и Сводку; рассинхрон трёх точек enforcement. |
| OFF = сброс/удаление лимитов (запись `-1`) | Разрушает данные, необратимо, ломает «статистику» и откат; противоречит «OFF не трогает данные». |
| OFF = полное отключение аналитики/счётчиков | Прямо противоречит owner №2 («статистика ведётся»). |
| OFF с обходом `keys.allow_global=false` | Смешивает бюджет и права доступа (R1 Critical); недопустимое расширение доступа. |
| Новый ADR без AMEND старых | ADR-1019-3 D9/ADR-1019-8 D9 явно утверждали «флаг не вводится» — требуется AMEND для непротиворечивости. |
| Новый `ClassVar`-флаг только в env (вне каталога) | Не даёт per-chat/global UI-тумблера, который прямо требует владелец. |
| Отдельная новая вкладка/карточка для тумблера | Нарушает `tma-menu-freeze`; карточка «Бюджеты» уже существует. |
| Дублирующий резолв флага в `llm_client` | Лишний I/O и риск рассинхрона; гейт в `budget_snapshot` покрывает транзитивно. |
| Добавить `budgets_enabled` в `.env` как обязательный | Секретов нет, но функционально достаточно код-дефолта; `.env.example` — только консистентность. |
