# ADR-1017-1 — Мини-апп Android: hostname/DNS, граница «репо vs инфра», процедура смены домена

> **Статус:** Accepted (Step 2 @Architect, 14.09.2026). **Раунд:** 10.17. **Фича:** F1 `miniapp-mobile-dns-round1017` (T-1666).
> **Связано:** ADR-1016-2 (self-host/CSP), `plans/current_task.md` UPD3 (стр. 155–157), UPD2 §4 (стр. 153).

## 1. Контекст

Android WebView: `net::ERR_NAME_NOT_RESOLVED`, десктоп — ОК. В 10.13–10.16 `WEBAPP_URL`/`MEDIA_PUBLIC_BASE_URL`/`menu.py`/путь/схема не менялись; внешних CDN в `web/` нет. `ERR_NAME_NOT_RESOLVED` — сбой **топ-доменного** резолва (`admin-bot.duckdns.org`), не субресурсный (иначе страница хотя бы грузилась без стилей/скриптов). Значит причина уровня DNS/сети клиента, а не рендеринга.

Гипотезы: блокировка `duckdns.org` мобильным оператором; stale/пустая AAAA; Android Private DNS/DoH; кэш резолвера.

## 2. Решение

1. **Не менять hostname/схему/путь в репозитории.** `WEBAPP_URL`/`MEDIA_PUBLIC_BASE_URL` — env-driven (`config/settings.py:172-173,988-989`), смена домена = правка `.env` + restart, **без кода**. Продуктовую миграцию с `duckdns.org` на собственный домен @Architect не решает — фиксируется как опция для владельца (§4).
2. **Граница ответственности:** DNS/DuckDNS/Caddy/LE/сеть оператора — **@DevOps (вне репо)**; в репо — только диагностические артефакты и regression-гейты.
3. **Repo-меры:** явные `HEAD /web/` + `/web/index.html`; unauthenticated `/healthz` (GET+HEAD, `no-store`); startup-лог host/scheme/path (host-only, R17); тест «нет внешних CDN + консистентные absolute-URL».
4. **Внешние CDN не возвращать** (ADR-1016-2 в силе).

## 3. Рассмотренные альтернативы

| Вариант | Вердикт |
|---|---|
| Вернуть внешние CDN (Telegram SDK/Tailwind/Vue) | **Отклонён:** не чинит топ-домен, возвращает субресурсные сбои и исходный баг |
| Немедленно мигрировать на собственный домен | **Отложено владельцу:** требует регистрации/DNS/LE, вне репо; не блокирует диагностический гейт |
| Сменить hostname в коде (захардкодить другой домен) | **Отклонён:** ломает env-driven конфигурацию, плодит дрейф (R17-риск) |
| Диагностический эндпоинт в `/api/*` (за initData) | **Отклонён:** Android-сбой до initData → нужна unauth-точка (`/healthz`) |
| Service worker/офлайн-кэш | **Отклонён:** не решает DNS; риск stale-cache (прецедент ADR-1016-2) |
| Ничего не делать в репо (только чек-лист) | **Отклонён:** нет воспроизводимого гейта и различимости «DNS vs Caddy» |

## 4. Фоллбэк/смена домена (процедура, env-only)

1. @DevOps выбирает альтернативный hostname (собственный домен или иной DNS-провайдер, устойчивый к блокировке).
2. A→`198.46.175.136`, AAAA — только если IPv6 реально обслуживается; LE-сертификат на новый host.
3. Caddy: vhost нового host + прокси на `127.0.0.1:8000`, `encode zstd gzip`.
4. `.env`: `WEBAPP_URL=https://<new-host>/web/`, `MEDIA_PUBLIC_BASE_URL=https://<new-host>`; `systemctl restart admin_bot`.
5. `/menu` → WebApp; Android-смоук; старый host оставить как редирект/на переходный период.
6. **Код не меняется** (кроме документации).

## 5. Последствия

- (+) Диагноз отделён от догадок: `/healthz` + `/dig` различают DNS/Caddy/клиент; смена домена — правка env.
- (+) Репо-инварианты (self-host, CSP, каталог) сохранены; ноль Δ каталога, ноль SQL.
- (−) Реальный фикс зависит от @DevOps и сети оператора — вне контроля раунда; DoD требует живого Android-смоука.
- (−) Появляются две публичные unauth-точки (`/healthz`, HEAD HTML) — без секретов и персональных данных.

## 6. Инварианты

Порядок роутеров `bot.py` не тронут; `media/`/`.env` не тронуты; каталог Δ=0; SQLite v9; R17 (host-only в логах); ADR-1016-2 (self-host/CSP) в силе.
