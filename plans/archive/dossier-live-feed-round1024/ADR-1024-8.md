# ADR-1024-8 — Вертикальная лента досье + click-through в «Досье» (F4)

> **Статус:** proposed → применяется в раунде 10.24.
> **AMEND:** 10.20 T-1897 / ADR-1022-8 (горизонтальный marquee 42s признан нечитаемым).
> **Слой:** web (`index.html`/`app.js`/`app.css`) + API (`web/api/oversight.py`,
> `services/database.py`). Δ DDL = 0, Δ каталога = 0.

## Контекст

В раунде 10.20 виджет «Живая лента досье» сделан **горизонтальной бегущей строкой**
(42s, `translateX`, дублирование для seamless-скролла). Владелец (UPD2 п.2) признал
её нечитаемой: текст «пролетает» быстро и в одну строку, длинные выдержки не
успеваешь прочитать; интерактивности нет.

Источник данных — `graph_facts`: строка факта хранит `target_user` (каноническое
**имя** участника), но **не** `user_id`. API отдаёт `{chat_id, name, excerpt}`.
Модалка «Досье» (`openDossier`) требует `user_id` **и** активный чат
(`this.activeChatId`), а лента по умолчанию GLOBAL (чат не активен) — прямое
открытие досье из ленты физически невозможно. UPD3 №9 санкционировал сценарий:
«переключать контекст на чат этого факта и открывать модалку Досье».

Ключевой архитектурный вопрос: как получить `user_id`, если его нет в источнике,
**не нарушая** нулевой DDL и инвариант `imported-history-immutable`.

## Решение

### D1. Вертикальная медленная лента (CSS, без JS-анимации)

Переиспользуем тот же CSS-приём дублирования, «повернув» его: `flex-direction:
column`, фиксированная высота контейнера, `translateY(calc(-100% - gap))`,
180°-маска, `prefers-reduced-motion` → статичный прокручиваемый список. Это
подтверждено практикой (CodeFronts, CSS-Zone): вертикальный marquee **обязательно**
требует явной высоты контейнера, иначе клиппинг/цикл не работают.

Скорость: базовая ≥ **72s** (в ~1.7× медленнее горизонтали) и масштабируется от
числа элементов (`max(72s, items×6s)`), чтобы при длинном списке скорость строки не
росла. Ограничиваем `limit ≤ 24`.

### D2. `user_id` — read-time обратный резолв, БЕЗ новой колонки

Отклоняем DDL-вариант (`graph_facts.target_user_id`) как нарушающий нулевой DDL
раунда и создающий долг синхронизации при записи фактов. Вместо этого API резолвит
`name → user_id` на чтение, используя уже существующий канон имён:
`db.get_active_participants` (`{user_id: author_name}`) + `AliasResolver`
(канонизация). Резолв кэшируется в пределах запроса; при неудаче —
`user_id=null` (fail-open), лента остаётся текстовой.

### D3. Аддитивный контракт (R16)

В `items[]` добавляются `user_id` и `user_name`; существующие `chat_id/name/excerpt`
не трогаются. Никаких новых персональных полей сверх уже используемых.

### D4. Click-through контракт (UPD3 №9)

- Строка с `user_id` — интерактивна (`role="button"`, клавиатура).
- Строка без `user_id` — **некликабельна** (никакого ложного affordance).
- GLOBAL-режим: сначала `setActiveChat(it.chat_id)` (смена scope → reload), затем
  `openDossier({user_id, name})`. Активный чат совпадает → открыть сразу.
- `openDossier` (per-chat) не меняем — контекст готовит вызывающий.
- Ошибка переключения → toast, модалка не открывается.

### D5. Kill-switch

`DOSSIER_LIVE_FEED_ENABLED` (env-only, default ON) через `ui_flags`; OFF → прежняя
горизонталь 42s и некликабельные строки.

## Последствия

**Плюсы:** читаемая лента; интерактив без DDL; нулевой риск для сырой истории;
повторно использует канон имён (единый источник правды имён).
**Минусы/долг:** обратный резолв имён не идеален при коллизиях (два участника с
одинаковым отображаемым именем) — разрешаем детерминированным tiebreaker и
допускаем `null` (строка просто некликабельна). Если в будущем у фактов появится
явный идентификатор автора — резолв можно заменить.
**Стоимость:** один дополнительный read на чат в пределах запроса ленты.

## Альтернативы

| Альтернатива | Почему отклонена |
|---|---|
| Добавить `graph_facts.target_user_id` (DDL) | нарушает Δ DDL=0; долг синхронизации при записи; риск для immutability-инвариантов |
| Денормализовать `user_id` в отдельную PG-таблицу | новая PG-сущность без нужды; sync-долг |
| Искать `user_id` на фронте через отдельный API-вызов на строку | N запросов, медленно, сложнее fail-open |
| Оставить горизонталь, только замедлить | прямо отклонено (UPD2 п.2) |
| Открывать досье по имени (без `user_id`) | контракт `openDossier`/API досье строится на `user_id` (R16: id — ключ) |
