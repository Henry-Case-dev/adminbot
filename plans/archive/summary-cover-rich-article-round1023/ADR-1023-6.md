# ADR-1023-6 — Доставка Article `sendRichMessage` с обложкой (тихий фолбэк) для Саммари

- **Статус:** **Accepted** (Step 2 @Architect, 19.09.2026)
- **Фича:** F6 `summary-cover-rich-article-round1023`
- **Тип:** backend/LLM + канон + egress + UI-настройка
- **Связано:** ADR-1013-3 (канон-миграции), F3 (`response_mode`/JSON Stage-1), F5 (`services/image_generation.py`, ADR-1023-5), F8 (`prompts.summary_editor_system_prompt` в каталоге)

## Context

ТЗ требует: (1) валидированный **визуальный промпт EN ≤300** из Stage-1; (2) авторский **«Стиль обложки»**, конкатенируемый с ним; (3) доставку саммари нативным **Article** через `sendRichMessage` (Bot API 10.1+) с прикреплённой обложкой; (4) **тихий откат** на обычное текстовое саммари при любой ошибке; (5) регистрацию новой egress-точки.

Ограничения: неизменность plain-пути R11 и стриминга (`parse_mode=None`); ровно 2 физических LLM-вызова; локальная версия aiogram — **3.29.1** (в ней `InputRichMessage` есть, но полей `media`/`blocks` нет); `requirements.txt` пинит `aiogram>=3.31.0,<4.0.0`.

**Вывод:** обложка-медиа возможна только на **aiogram ≥ 3.30.0** (фактически `>=3.31.0` по `requirements.txt`); локально 3.29.1 → rich-media недоступны. Проект **уже** использует `bot.send_rich_message` (3.29.1) для Справки без media (`handlers/info.py:103-104,157-158`) — образец сохраняется, но обложка требует апгрейда.

## Decision

1. **Поле Stage-1 `cover_prompt`.** `SUMMARY_EDITOR_SYSTEM_PROMPT` возвращает JSON `{response_mode, digest, cover_prompt}` (EN, ≤300). Валидатор `normalize_cover_prompt` в `system2_handoff` (нормализация пробелов, обрезка по слову до 300, пусто→`""`, never-raise). Служебное поле не попадает в Stage-2 и не логируется (R17). Число LLM-вызовов не растёт.
2. **«Стиль обложки» — ключ `prompts.summary_cover_style`** (группа `prompts_summary`, advanced). **Δ каталога = +1**. Финальный промпт изображения = `style + " " + cover_prompt`, жёсткий кап 300.
3. **Обложка генерируется только сервисом F5** (`generate_image(...) -> str | None` — фактически **путь к локальному файлу** с байтами; внутри `response_format="url"` + серверное скачивание, `worker_budget`, fail-open). F6 не дублирует провайдера, не хранит ключ, владеет временным файлом и удаляет его. В Telegram обложка уходит байтами (`BufferedInputFile`), keyed-URL не покидает сервер (R17).
4. **Формат Article — HTML или markdown + `media`:** `media=[InputRichMessageMedia(id="summary_cover", media=InputMediaPhoto(media=BufferedInputFile(...)))]` (байты из локального файла F5). Plain-текст → `InputRichMessage(html=…)` со ссылкой `<img src="tg://photo?id=summary_cover">` и `<p>`-абзацами; rich-контент (Markdown/таблицы, Сценарий Б) → `InputRichMessage(markdown=…)` со ссылкой `![summary cover](tg://photo?id=summary_cover)` (HTML `<img>` в markdown-режиме не документирован). Заполняем ровно одно из `html`/`markdown`/`blocks`; текст саммари (plain R11) → `sanitize_outgoing` **до** `html.escape`.
5. **`blocks` не используем** (альтернатива `InputRichBlockPhoto` отклонена: HTML-путь совпадает с рабочим образцом `handlers/info.py` и проще совместим с plain-текстом).
6. **Egress-точка:** новая обёртка `send_rich_message` в `services/telegram_send.py` (sanitize plain-источника → rich). Регистрация: `SEND_POINTS["services/summary_generator.py"] += "send_rich_message"`; `handlers/info.py` → `SEND_ALLOWLIST` («текст справки — админ-канон/PG, не Stage-2 LLM»). Тест-сканер `_SEND_RE` расширяется `\.send_rich_message\(`.
7. **Fail-safe совместимости aiogram:** `_rich_media_supported()` проверяет поле `media` у `InputRichMessage` и `Bot.send_rich_message`. Ложь → Article-путь пропускается, plain. Это закрывает риск «несовместимая версия aiogram».
8. **Тихий фолбэк:** вся rich-ветка в `try/except Exception` → plain-путь (`_send_streaming`/`_send_chunked`), **без** UX-сообщений; лог — только `type(exc).__name__` (R17). Rich-ветка **не стримит** → дублей нет. `generate_image → None` — штатный фолбэк.
9. **Канон-атомарность (ADR-1013-3):** правка Редактора + слепок `PREV_R1023_SUMMARY_EDITOR_SYSTEM_PROMPT` + `PROMPT_MIGRATIONS`/`ROLLBACK_MIGRATIONS` + `plans/docs/canon/**` + тесты — одним коммитом (ступень `… → F4 → F6`). Ключ `prompts.summary_editor_system_prompt` появится только в F8 → запись миграции `skip` до сида, после сида `no-op`. **Ступень `system2_handoff`: F3 → F6 → F7** (уточнение к §3.1 архитектурного дока).
10. **Флаг** `SUMMARY_COVER_ARTICLE_ENABLED` (env-only, default ON, Δ каталога = 0). OFF → plain.
11. **Канальный контракт разметки — Сценарий Б (UPD владельца 19.09.2026; синхрон ADR-1023-3 п.10 / F3 §3.6).** Article — rich-канал: **полный Markdown/HTML и таблицы разрешены** (`InputRichMessage` — структурированный вход, text-`parse_mode` не применяется). Для `deep_research` Stage-2 использует `FORMAT_RICH_BLOCK`; digest может нести таблицы/сетки. `plain_no_tables` (F3) на rich-канале не активен. Plain-фолбэк **обязан даунгрейднуть** rich-контент в R11-plain (снять markdown/HTML и таблицы) до отправки.
12. **`aiogram >= 3.31.0` — ЖЁСТКОЕ условие F6/деплоя** (UPD владельца 19.09.2026), а не опция: без него лонгриды с обложками не работают. `requirements.txt` уже пинит `>=3.31.0,<4.0.0`. Guard `_rich_media_supported()` остаётся лишь defense-in-depth/локальным фолбэком; отсутствие rich-media на деплое — ошибка приёмки, не «допустимый режим».

## Consequences

- (+) Саммари получает нативный карточный вид с обложкой; R11/plain-путь и стриминг сохранены; стоимость ограничена одним image-вызовом.
- (−) Появляется зависимость от внешнего media и от версии aiogram (**жёстко ≥3.31.0**): апгрейд обязателен для F6. Локальный/прод-рантайм ниже версии — блокер деплоя (guard остаётся только защитным фолбэком).
- (+) Article получает полную мощь rich-канала: Markdown/HTML, таблицы, сетки, глубокая разметка (Сценарий Б); plain-фолбэк даунгрейдит контент в R11-plain.
- (−) Обложка — платный внешний вызов: при дефиците бюджета F5 вернёт `None` → plain (без ошибок пользователю).
- Инварианты: physical-two-call (без роста), egress-реестр (точка зарегистрирована), `parse_mode=None` для plain, DDL = 0, Δ каталога = +1.

## Alternatives

| Вариант | Вердикт |
|---|---|
| `blocks=[InputRichBlockPhoto(...), InputRichBlockParagraph(...)]` | Отклонён: сложнее совместить с plain-текстом; HTML-путь = рабочий образец проекта |
| Генерировать обложку отдельным LLM-вызовом | Отклонён: нарушает physical-two-call-pipeline |
| Не оборачивать `send_rich_message` в egress-обёртку | Отклонён: «серая» отправка модель-текста (инвариант 3) |
| Падать/сообщать пользователю об ошибке обложки | Отклонён ТЗ: требуется **тихий** фолбэк |
| Требовать обложку обязательно (fail-closed) | Отклонён: обложка не должна ронять саммари |
| `sendRichMessageDraft` для стриминга | Отклонён: отдельный ephemeral-протокол (только private), усложняет без требования |

## Cost / латентность

- +1 внешний image-вызов (F5, `response_format="url"`), subject to `worker_budget`; LLM-вызовов по-прежнему 2. Article отправляется одним запросом (без стриминга) — добавляет один сетевой round-trip.

## Canon migration

**Обязательна** (ADR-1013-3), атомарно в ступени F6. Слепок `PREV_R1023_SUMMARY_EDITOR_SYSTEM_PROMPT`, `PROMPT_MIGRATIONS`/`ROLLBACK_MIGRATIONS` по ключу `prompts.summary_editor_system_prompt`, `plans/docs/canon/**`, тесты — один коммит.
