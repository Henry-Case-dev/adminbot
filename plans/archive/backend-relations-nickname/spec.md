## 1. Контекст и проблема

В «Участниках и отношениях» (вкладка relations — фича F; данные GET /api/chat_lore/{id}/relations) у людей есть username, но нет nickname; у некоторых нет ни того ни другого (в карточке — только id). Каскад: `alias (AliasResolver, limits.summary_aliases) → nickname (_participant_names: последние 30 дней, top-200 smart_messages) → username (Bot API-обогащение ТОЛЬКО топ-50 списка, _RELATIONS_ENRICH_TOP=50) → '' (id никогда)`. Корневая причина «только id»: участник вне top-200 nickname-окна И вне top-50 username-обогащения → name у него удаляется (R16-страховка), остаётся голый id.

## 5. Негативные тесты (что НЕ сломать)

- **R16**: «id никогда имя» — сохранён во всех ветках (тест инварианта).
- **Каскад**: alias → nickname → username → '' — порядок/приоритет (тест); **`@` снят** (username.lstrip('@')).
- **«Имена как есть»** (10.2-инвариант: без strip/чистки/капа для nickname) — не трогать.
- **Отношения/стадии/notes/409** — без диффов (серверная часть; stage/score/др. поля).
- **F-14-гейт summary_enabled** — каскад имён участников НЕ зависит от него (Hotfix-R10-инвариант; B-13 сохраняет) — тест.
- **SQLite v8** — ноль миграций/DDL; **REGISTRY 383/71/359** — без изменений; **каноны** — без дифов; **bot.py-роутеры** — без дифов.
- **R17** — username/имена не секреты; photon-файлы/фото — как были (топ-50), ленивый догруз — как есть.
- **Производительность**: 100 вызовов Bot API при первом рендере — прогрев; провалы → fail-open (имена из nickname/алиасов; если пусто — '') — бот жив, UI деградирует мягко.
