# ADR-1023-8 — Разделение карточек Синтезатор/Вербализатор + UI-режимы + мониторинг клише

- **Статус:** **Accepted** (Step 2 @Architect, 19.09.2026)
- **Фича:** F8 `ui-verbilizer-tabs-round1023`
- **Тип:** каталог + UI (`web/**`) + API
- **Связано:** F3 (режимы/`MODE_*_BLOCK`), F4 (кэш клише + API), F5 (ступень `web/**`/каталога), ADR-1023-3, ADR-1023-4, ADR-1013-3

## Context

ТЗ требует разделить карточки модулей (Фактчек, Поиск, Прямой чат, Саммари, YouTube, Веб) на **«Синтезатор (Логика)»** и **«Вербализатор (Характер)»**, добавить UI-селектор режимов (Tabs `Casual`/`Serious`/`Deep Research`) и блок мониторинга `dynamic_cliche_list` (дата/форс/ручное редактирование).

Факты, задающие ограничения:
- В каталоге **нет** Stage-1/Stage-2 промптов: один legacy `prompts.*_system_prompt` на модуль (`param_catalog._PROMPTS`, 10 ключей). Реальный Stage-1/Stage-2 (F3) читает **код-константы**, не PG-ключи.
- Реальный двухстадийный конвейер есть только у Фактчек/Прямой чат/Саммари; Поиск/YouTube/Веб — одностадийные.
- Freeze-меню: 20 вкладок, `NAV_ITEMS`, витрина 11 модулей — **не менять**.
- Кэш клише питает **детектор** F4, не scrubber (ADR-1023-4).

## Decision

1. **Каталог: +1 группа `prompts_verbilizer`** (order 9, категория `prompts`) и **+10 промпт-ключей**: по одному Stage-1 и Stage-2 для трёх двухстадийных модулей (Фактчек/Саммари/Прямой чат) + 3 режимных блока + `prompts.verbilizer_default_mode` (`select`). Δ REGISTRY +10, categorized +10, GROUPS +1; **TAB_RULES Δ = 0** (группа ловится категорийным правилом `TAB_PROMPTS`), settings-поля Δ = 0. Пины `test_param_catalog` обновляются одним коммитом.
2. **Одностадийные модули не получают фейкового Синтезатора:** существующие `prompts.search/youtube/youtube_video/webpage_system_prompt` помечаются `stage="verbalizer"`; в карточке рендерится одна секция «Вербализатор (Характер)» с пометкой «модуль одностадийный».
3. **Аддитивное поле `ParamSpec.stage`** (`"synthesizer"`/`"verbalizer"`/`"mode"`/`None`), отдаётся в `GET /api/config`; UI группирует элементы внутри generic-карточки. GROUPS/TAB_RULES от этого не меняются.
4. **Рантайм-чтение (кросс-фичевый контракт):** функции Stage-1/Stage-2 сервисов (`summary_generator`, `factcheck_service`, `direct_chat_service`) читают новые PG-ключи через `hot.get(key, <код-константа>)`; режимные блоки — `hot.get("prompts.verbilizer_mode_<mode>", MODE_*_BLOCK)`, fallback режима — `prompts.verbilizer_default_mode` (default `serious`). Это **аддитивные** чтения; отсутствие/пустота ключа → прежняя код-константа; число LLM-вызовов не меняется. Правки вносятся в коммите F8 (после F6), поэтому не конкурируют параллельно, но формально расширяют эксклюзивы F3/F6 (см. Human Gate).
5. **UI:** вкладка «Промпты» получает под-секции по `stage`, спец-блок Tabs для группы `prompts_verbilizer` и спец-блок мониторинга клише. Витрина модулей/`NAV_ITEMS`/20 вкладок — **без изменений** (tma-menu-freeze).
6. **API Δ = 0:** сохранение через существующий generic `POST /api/config`; блок клише — через API F4 (T-2132). При ином нейминге F4 добавляется тонкий прокси-роут с теми же RBAC/`param_permissions`.
7. **Кэш клише:** ключ `content.dynamic_cliche_list` в каталоге **не регистрируется** (review iter1, Low). Данные F4 живут в PG-таблице `anticliche_cache` (не `bot_settings`), UI-блок работает через `/api/anticliche`; registry-ключ был бы «мёртвой ручкой» в матрице прав. Логика обновления/валидации — F4; F8 — читатель + кнопки. Δ F8 = REGISTRY +10 (только prompts-ключи).
8. **Откат:** `git revert`; новые PG-значения безвредны (при отсутствии ключей рантайм берёт код-константы). Отдельного флага нет.

## Consequences

- (+) Карточки становятся управляемыми по-настоящему: правка Stage-1/Stage-2 реально меняет ответы; режимы видны и настраиваются; мониторинг клише прозрачен.
- (+) Freeze-меню соблюдён (меняется только внутренний рендер вкладки).
- (−) Материальный Δ каталога (+10/+1 группа) ломает пин `test_param_catalog` — обновляется осознанно.
- (−) Кросс-фичевые `hot.get`-чтения в сервисах F3/F6 — расширение их эксклюзивов; снижено последовательной ступенью (F8 после F6) и тестами.
- Инварианты: physical-two-call (без новых вызовов), egress — не затрагивается, `parse_mode=None`, DDL = 0.

## Alternatives

| Вариант | Вердикт |
|---|---|
| Только UI-секции без новых ключей (переиспользовать legacy `prompts.*_system_prompt`) | Отклонён: Stage-1 некуда положить; правка мёртвых полей |
| Фейковые Stage-1 ключи для Поиск/YouTube/Веб | Отклонён: не соответствуют реальному одностадийному конвейеру |
| Новые группы `prompts_<module>_synth/_verb` (12 групп) | Отклонён: раздувает GROUPS и UI; секции решаются полем `stage` |
| Отдельный серверный флаг UI-табов | Отклонён: статический TMA-бандл, RBAC уже есть, откат — `git revert` |
| Разместить режимные блоки внутри каждой модульной группы | Отклонён: режимы общие для всех модулей (один источник истины) |
| Передавать `stage` из бэкенда отдельным эндпоинтом | Отклонён: лишний API; поле добавляется в существующий `GET /api/config` |
| Превратить мониторинг клише в scrubber/редактор канон-списка | Отклонён (запрет владельца, ADR-1023-4): только мониторинг/регенерация |

## Migration / порядок

- Ступени: `param_catalog` — F2 → F5 → **F8**; `web/**` — F5 → F7 → **F8** → F9.
- Пины `test_param_catalog.py` (REGISTRY/GROUPS/prompts-count), `test_frontend_tab_mapping.py`, freeze-тесты и JS-гейты обновляются в одном коммите с F8.
- Канон-промпты F8 **не меняет** (ключи сидятся из уже актуальных констант F3/F6).

## Human Gate

- Подтвердить, что Stage-1/2 промпты становятся PG-редактируемыми (кросс-фичевые `hot.get`-чтения).
- Подтвердить правило одностадийных модулей (без фейкового Синтезатора).
- Подтвердить общий (не per-module) блок режимов Вербализатора.
- Подтвердить владельца hidden-ключа `content.dynamic_cliche_list` (F4 vs F8) и имя F4-эндпоинтов.
