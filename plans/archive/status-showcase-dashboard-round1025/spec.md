## 2. Решения по открытым вопросам (D1–D7)

### D1 — механизм 12-колоночной сетки (§12) — **принято**
- Контейнер: **новый** `<div class="status-grid">` внутри ветки `activeTab === 'status'` (обёртка вокруг текущих карточек `web/index.html:3388–3807`), CSS `display:grid; grid-template-columns: repeat(12, minmax(0,1fr)); gap: var(--space-4); align-content:start;`.
- `main.scroll-area` (`:267`, `repeat(auto-fill, minmax(320px,1fr))`) **не меняется**; `.status-grid` как единственный ребёнок получает `grid-column: 1/-1`. Прочие вкладки/hub-экраны не затрагиваются.
- **Ни один виджет не теряется:** карточки **оборачиваются** (`<div class="sg sg-N">`), внутренности не переписываются. Порядок DOM = порядок чтения §12 → на mobile тот же вертикальный порядок.
- Спаны (12-кол. база): Hero `5` · метрики+HB `7` · граф `8` · сон `4` · мониторинг интеллекта `12` · превью `7` · «Новые факты» `5` · бюджеты `12` · доступность ключей `12` · история ключей `12` · логи `12`. Декоративный `glass-surface` — `12` (первый; рендерится только при `UI_LIQUID_GLASS_LIB=ON`). Карточка-ссылка «Аналитика» и `statusError` — **вне** `status-grid` (над ним, полная ширина) → §12-строки остаются ровно шесть.
- Адаптив (§70): `≥1200` и `992–1199` — 12 колонок (спаны §12); `768–991` (tablet) — 6 колонок, все карточки `span 6` (полная ширина); `≤767` (mobile) — 1 колонка, порядок: Hero → метрики+HB → граф → сон → мониторинг → превью → «Новые факты» → бюджеты → доступность ключей → история ключей → логи.
- Защита от горизонтального скролла: `minmax(0,1fr)` + `min-width:0` на карточках и внутренних flex/grid-детях; таблицы (`avail-list`) — существующее поведение.

### D2 — разделение `.status-block` на Hero(§13)/метрики(§14) — **принято**
- **Hero (5 кол., Liquid Glass `data-glass`, без постоянной яркой пульсации):** название бота; статус (`bot.state`, `stateBadge`); последняя активность (`uptime.last_heartbeat`, humanize; нет → «—»); аптайм (только если отличается от серверного — при текущем контракте не отличается, поэтому в Hero не дублируется); компактное предупреждение при ошибке (`bot.errors_total > 0` / `statusError`); **сохраняются** кнопки «Рестарт/Стоп/Старт» (`hasPerm('action.control.*')`) — §11 «состояние бота» + управление процессом (карта виджетов).
- **Метрики + heartbeat (7 кол.):** CPU (число + progress), RAM (число + progress), диск (занято/всего + %), аптайм (человекочитаемо), **существующий heartbeat-компонент `status-block__pulse` как есть** (Canvas 2D/rAF + SVG-фолбэк, §15), плюс сохранённые детали «Сервер» (Load / PID / RSS / threads) и пометка при выбранном чате: «Метрики относятся ко всему серверу, а не к выбранному чату» (`isChatContext()`).
- **Честные `null`:** если `statusData.server` недоступен (`{}`) или поле `null/undefined` → «нет данных»; progress-бар **не заливается** (устранить текущий `(cpu_percent || 0)` — 0 при null).
- **Секция «Бот»** (uptime/state/errors/controls) распределяется: состояние/ошибки/контролы → Hero, аптайм → метрики. Потери секций нет; внутренности heartbeat не переписываются.

### D3 — единый источник времени сна (§17) — **принято**
- Источник — **существующий** `GET /api/memory/cognition/status` (уже опрашивается `loadCognition` каждые 15 с): `dream.next_wake_at` / `dream.active` / `dream.active_until` / `dream.last_run_at` / `dream.state` / `dream.budget`; `deep_sleep.next_run_at` / `deep_sleep.active` / `deep_sleep.active_until` / `deep_sleep.last_run_at`; общий `generated_at`.
- Виджет сна **reuse существующих computed** `dreamPhaseBadge`/`deepPhaseBadge` (`web/app.js:2743/2765`): «🌙 Сон через…», «🌌 Глубокий сон через…», «Сон до HH:MM» / «Глубокий сон до HH:MM» при активном, свечение `.badge.glow` при активном, эмодзи сохранены. **Новых таймеров/поллеров нет** — countdown считается от серверного `generated_at`, обновление по существующему 15-сек. поллингу. Таймер ≠ доказательство: `active` берётся только с сервера.
- «Последнее выполнение» — `last_run_at`; «результат, если доступен» — из `dream.state`/`budget`; при отсутствии — «нет данных» (не выдумывать). Тяжёлый лог `/api/memory/deep-sleep` — только lazy по запросу пользователя (существующий endpoint), без нового поллера.
- Отказ/ошибка → понятный нейтральный статус («—», не выдуманный «запуск»).

### D4 — расширение графа §16 и mobile-экран — **принято**
- Desktop (8 кол.): расширение существующего vis-network `renderCognitionGraph` (`app.js:10436`): поиск по имени (label) + по алиасу (reuse `.graph-search`, `searchCognitionGraph`/`clearCognitionGraphSearch`); фокус; «ближайшие связи» (соседи выделенного узла — фокус/подсветка, **алгоритм/семантика веса и layout не меняются**); фильтры (group/состояние — витринные, клиентские); «подробности» узла (реальные поля `label/group/degree`, связи); «сброс вида» (существующий `clearCognitionGraphSearch` + `fit()`); lazy-загрузка vis-network сохранена.
- **Алиасы (честно, без новой API):** узел графа несёт только `id/label/group/degree` (`database.graph_snapshot`, label = канон-имя). Поиск матчит `label` **и** значения алиасов из **уже загруженного** `summaryAliasesMap()` (`limits.summary_aliases`). Если запрос совпал только с алиасом, для которого в графе нет узла, — честное «в графе нет узла …» (без выдумывания связи). Новых endpoint'ов/полей/каталоговых ключей **нет**.
- **Mobile (≤767):** упрощённый граф (без физики/перетаскивания, фиксированный fit) + **отдельный экран полного исследования**.
- **Владелец routing — F1 (`web/app.js` роутер).** Принят **hash-маршрут `#/status/graph`** (аддитивно в `ROUTE_TO_TAB` → `status`; `ROUTE_PARENT['#/status/graph']='#/'`, `routeDepth=1`), с нативной «назад» и хлебными крошками. Fallback при `IA_V2_ENABLED=false`/нет hash-навигации — полноэкранная шторка (toggle), тот же компонент. RBAC — существующий global-admin.

### D5 — §19/§20/§21 — **принято**
- **«Новые факты» §19 (5 кол., строка 4):** подзаголовок «Что бот недавно запомнил»; reuse `dossierFeed`/`loadDossierFeed` (`app.js:5195`) + `/api/oversight/dossier_feed?limit=16`; **вертикальный пользовательский скролл**, новые факты **не сбрасывают позицию** (`:key` стабилен, DOM-список не пересоздаётся, не автопрокрутка). Маппинг полей честно: имя (`name`/`user_name`), текст (`excerpt`); **время/тип показываются только если присутствуют в ответе** — сейчас их в ответе нет, поэтому они опускаются, а не выдумываются (см. §11 spec → follow-up `F11-FU-DOSSIER-TS`). Полная работа с памятью/досье — в «Память»/«Аналитика» (существующие поверхности не трогаются).
- **«Бюджеты интеллекта» §19 (12 кол., строка 5):** reuse существующих oversight-источников и computed: контекст-бюджет из `/api/status.context` (`memoryContext`), дневной фон `/api/workers/budget` (`budgetInfo`), сон (токены) `cognition.dream.budget`. «Без лимита» — без заполненного бара; «Нет данных» вместо `$0`; **Δ каталога = 0** (новых параметров нет). Полный oversight-блок на «Аналитике» не удаляется.
- **§20 быстрый переход (верх Статуса):** счётчики «Ошибки: N · Предупреждения: N». Источник — **существующий** `GET /api/status/logs`: один лёгкий запрос (`level=ALL&limit=1`) читает **аддитивное** поле `counts` (точные числа по всему ring-буферу, corrective H-F11S-1; поле `count` ограничено `limit` и для счётчиков не годится). Семантика раздельная: «Ошибки» — только `ERROR`; «Предупреждения» — только `WARNING` (без «warn и выше»). Нет `counts`/ошибка → «—» (не выдуманный 0). Клик — плавный скролл **к карточке логов**; фильтры/раскрытие/копирование/столбцы **не менять**, viewer **не переписывать**; логи остаются внизу и не переносятся только на техстраницу.
- **Граница F6/F11 §21:** F6 владеет **данными и компонентом** (`ExecutionGraph.fromTrace('/analytics/usage/latest')`, `execPreview`, `web/static/execution_graph.js`, фильтры §27 — только «Аналитика»). F11 — **только размещение/обёртка** `exec-preview` (7 кол., строка 4) без изменения внутренней разметки/рендера/контракта. Превью не заменяется одной строкой с числом токенов.

## 4. Наблюдаемое поведение и failure-cases

**Успех:** Статус — 12-кол. сетка; Hero и метрики в одной строке (desktop); граф 8 / сон 4; мониторинг на всю ширину; превью 7 / «Новые факты» 5; бюджеты и логи на всю ширину; горизонтального скролла нет на 320–2560.
**Отказы (честные, без выдумывания):**
- `server = {}` или поле `null` → «нет данных», бар пуст (не 0).
- Нет `uptime.last_heartbeat` → «—».
- Нет `cognition` → бейджи «—», виджет сна нейтрален.
- Пустой `dossierFeed` → «Пока нечего показать…».
- `budget = -1`/unlimited → «Без лимита» без бара; нет данных → «Нет данных» (не `$0`).
- Логи недоступны / нет аддитивного `counts` → счётчики «—», скролл не ломается.
- Граф пуст/нет vis-network → честное сообщение, страница не падает.
- Поиск по алиасу без узла → «в графе нет узла …».
- 401/403/ошибка `/api/status` → существующие сообщения + heartbeat → UNKNOWN.
