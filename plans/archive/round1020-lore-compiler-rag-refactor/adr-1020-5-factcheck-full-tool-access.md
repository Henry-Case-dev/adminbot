# ADR-1020-5 — Full Tool Access фактчекера + техдолг 10.19 (БЛОК 6)

- **Статус:** 🟢 **Принято** (Step 2 @Architect, 16.09.2026; **AMEND ред. 2** — О1/О5 FINAL)
- **AMEND ред. 2:** фактчекер наследует fail-safe tool-loop из [ADR-1020-7](adr-1020-7-agentic-ai-refactor.md) §1
  → при исчерпании раундов/сбое LLM выдаёт **деградированный вердикт**, не молчание; снятие канона «1–2 предложения»
  для вердикта — §7.2 спеки.
- **Раунд:** 10.20, фаза E (`persona-worker-ui-factcheck-round1020`), задачи T-1905…T-1912
- **Спека:** [`spec.md`](spec.md) §7
- **Аудит-основание:** `round1020_llm_engine_audit.md` §Q1.2-3, §Q4.2-4

## Контекст

1. `FactCheckService` (`services/factcheck_service.py:30-34`) **не имеет** `ToolRouter`/`ToolDeps` и вызывает
   `llm.generate(...)` без `tools` (`:69-74`) — посылка ТЗ БЛОК 6.2 верна: фактчекер «слеп» к локальной базе.
   Второй, независимый RAG-инжект у него есть (`get_rag_context`, `:60`), но без дат/авторов в формате БЛОК 0.
2. Тон фактчекера (`FACTCHECK_SYSTEM_PROMPT`) переписывать **нельзя** (политика, ТЗ стр. 217–219) — только
   функциональные инструкции.
3. Техдолг 10.19 подтверждён аудитом:
   - **S10.19-15:** `services/oversight.py:203-216` (`_limits_block`) вызывает `chat_usage.key_status` **дважды на чат**;
   - **S10.19-23:** `services/memory_maintenance.py:389-425` — fsync **файла** есть, fsync **каталога** нет;
   - **CLI `manage.py retention`** — падает при живом боте (WAL/lock).
4. БЛОК 5.5/6.1 (ручной DeepDream, пороги) **уже реализованы** в 10.18 (ADR-1018-2) → verify-only.

## Решение

1. **Full Tool Access, реюзом существующего контура.** `FactCheckService.__init__` получает аддитивный kwarg
   `tool_router` (DI из `bot.py` — только kwargs, порядок роутеров не менять); вердикт считается через
   **существующий** `chat_with_tools` (`services/tool_loop.py`) с tool-сетом `dig_into_lore` + `compile_lore_story`
   + `execute_web_search`. Пайплайн «claim → вердикт» сохраняется: tool-loop — обёртка вокруг `llm.generate`,
   второго синтеза не появляется.
2. **Метаданные БЛОК 0 обязательны** в `<chat_context>` (`factcheck_service.build_user_content:87-118`) —
   через `format_context_item` (ADR-1020-1); это делает проверку «кто что сказал» доказуемой (дата/время/автор).
3. **Промпт — только функциональные инструкции** (тон/мат как есть):
   (а) мировые факты/наука/новости → веб-поиск; (б) спор «кто что сказал в этом чате» → **обязательно**
   `dig_into_lore`/`compile_lore_story`; (в) использовать метки `[Дата Время | Автор | Переслано: откуда]`
   для аргументации точной датой/временем. Канон-миграция атомарно (эталон + код + тесты).
4. **S10.19-15:** один вызов `budget_snapshot`/`key_status` на чат, обе метрики — из одного результата;
   тест-ассерт «ровно 1 вызов» (`test_direct_contour_reads_key_status` обновляется).
5. **S10.19-23:** `os.open(dir, O_RDONLY)` + `os.fsync` в том же `to_thread` после fsync файла (POSIX);
   на Windows — **no-op** с честным логом (dev-платформа win32).
6. **CLI `manage.py retention`:** чтение SQLite в WAL/read-only-режиме либо временный снапшот БД;
   **dry-run остаётся дефолтом**; R17 — в вывод не печатать пути/значения секретов.
7. **БЛОК 6.1 — verify-only** (не переписывать): подтвердить работоспособность и UI-доступность ручного триггера.

## Альтернативы и отклонения

- **Собственный tool-loop в фактчекере:** отклонено — дублирование (`tool_loop.chat_with_tools` уже есть, реюз дешевле).
- **Разрешить фактчекеру ВСЕ 8 инструментов** (включая `download_media`/`summarize_video`): отклонено —
  в вердиктном пайплайне скачивание/выжимка не нужны, растёт стоимость и риск (риск `factcheck-full-tools-cost`).
- **Переписать тон фактчекера:** отклонено политикой (ТЗ стр. 217–219).
- **Сменить дефолт `retention` на «выполнять»:** отклонено — dry-run обязателен (риск порчи данных, R13).
- **Понижать `user_version`/менять матрицу миграций под retention:** отклонено — утилита читает, а не мигрирует.

## Каталог-Δ

**Δ = 0** (фактчекер использует существующие инструменты и флаги; лимиты — существующие/код-константы).

## Последствия

- Фактчекер становится «всевидящим» по локальной истории, но растёт латентность и стоимость LLM →
  обязателен замер (T-1911) и наблюдение на живой проверке.
- `key_status` читается 1× → меньше нагрузки на PG и меньше шансов на рассинхрон виджетов «Сводки» (связь с п.6.4 спеки).
- fsync каталога закрывает остаточный риск потери имени файла после краша (best-effort на Windows).
- retention перестаёт падать при живом боте → эксплуатационная надёжность без остановки сервиса.

## Инварианты

Тон/мат промптов не переписывать; порядок роутеров `bot.py` не менять; `user_version` не менять; R16/R17;
`media/`/`.env` не трогать; БЛОК 5.5/6.1 — только подтверждение работоспособности.
