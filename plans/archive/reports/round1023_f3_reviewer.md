## Краткий вердикт (без смягчения)

Механику двухвызовного пайплайна автор собрал аккуратно: роутер действительно живёт
в Stage-1, `normalize_response_mode` не бросает, обёртка `validate_summary_digest`
жива, guard таблиц — это именно браковка+регенерация, а не резание строки. Каталог не
задет, egress не расширен, полный прогон зелёный.

Но центральный пользовательский сценарий фичи — `deep_research` на plain-канале с
**обязательным** жирным и буллитами — в текущем виде **не работает и не может работать**:

1. В собранном Stage-2 промпте для `deep_research` живёт **прямое противоречие**:
   одни и те же системные блоки «СТРОГО ЗАПРЕЩАЮТ» буллиты, а новый `FORMAT_PLAIN_BLOCK`
   их «ОБЯЗАТЕЛЬНО» требует.
2. `FORMAT_PLAIN_BLOCK` предписывает `<b>акцент</b>` для саммари и фактчека, но у этих
   каналов **нет пути рендеринга HTML**: саммари отдаёт `<b>` пользователю сырым текстом,
   фактчек либо теряет жирный (при тулах), либо тоже светит сырые теги.

Это не «мелкая шероховатость» — это ровно тот пункт, за который владелец на Step 2
поставил «ОБЯЗАТЕЛЬНО». Тестами это не поймано, потому что тесты мокают LLM и не
проверяют ни состав промпта, ни реальную доставку. Возвращаю на доработку.

### [Severity: High] H1 — Собранный промпт `deep_research` сам себе противоречит: буллиты запрещены и одновременно обязательны

- **Файл:** `services/prompt_style_blocks.py:29` (`ANTI_BOT_BLOCK`, п.4

  Markdown, списки, пункты и эмодзи: только сплошной текст»)
  **против** `services/prompt_style_blocks.py:116-123` (`FORMAT_PLAIN_BLOCK` —
  «Перечисления давай простыми буллитами: "- "»).
- **Где всплывает:** `services/prompt_style_blocks.py:154-168`
  (`compose_verbilizer_system`) слепляет базу (внутри неё `STYLE_BLOCKS_SUFFIX` с
  `ANTI_BOT_BLOCK`) и `FORMAT_PLAIN_BLOCK` в один system-промпт для всех трёх сервисов:
  `summary_generator.py:331`, `factcheck_service.py:155`, `direct_chat_service.py:887`.
- **Проверено программно:** в `compose_verbilizer_system(SUMMARY_NARRATOR..., "deep_research", "plain")`
  одновременно присутствуют «Списки с буллитами… СТРОГО ЗАПРЕЩЕНО» (True), «только
  сплошной текст» (True) и «буллитами» из `FORMAT_PLAIN_BLOCK` (True).
- **Почему это важно:** модель получает взаимоисключающие инструкции. Валидатор
  буллитов намеренно выключен для `deep_research`
  (`services/negative_constraints.py:137`), т.е. код ждёт буллиты, а промпт их
  запрещает. Итог — либо буллитов нет (провал критерия приёмки «жирный + `- `-буллиты
  обязательны»), либо модель слушает новый блок и ломает R11-жанр саммари. Поведение
  непредсказуемо и не воспроизводимо.
- **Требуемый фикс:** привести композицию к непротиворечивому виду: для
  `deep_research` явно снимать запрет на `- `-буллиты (не переиспользовать
  `ANTI_BOT_BLOCK`/R11-правило 2 в этой ветке без оговорки «кроме deep_research»),
  либо не требовать буллиты там, где база их запрещает. Добавить тест на состав
  собранного промпта: в `deep_research`-ветке нет запрещающих буллиты формулировок.

### [Severity: High] H2 — Обязательный `<b>` не доставляется на plain-каналах саммари и фактчека: утекает literal-тегом или молча вырезается

- **Файл/локации:**

    `жирный для акцентов: <b>акцент</b>`.

  - `services/summary_generator.py:241` — `cleanup_llm_text(raw)` типографику правит,

  - `services/summary_generator.py:558` / `:570` — `send_text(self.bot, chat_id, chunk)`
    без `parse_mode` ⇒ `parse_mode=None`; пользователь увидит сырой `<b>акцент</b>`.
  - `services/factcheck_service.py:244` — `strip_lore_html(out)` вызывается
    **только `if used_tools`**: без тулов `<b>` утекает сырым, с тулами жирный молча
    стирается (требование «жирный» не выполнено ни в одном из вариантов).
  - Единственный корректный путь — `services/direct_chat_service.py:942`
    (`escape_lore_html` + `parse_mode="HTML"`), и он есть **только** для direct
    `deep_research`.
- **Почему это важно:** spec §3.6.2 явно направляет `FORMAT_PLAIN_BLOCK` на
  direct/factcheck/plain-саммари. Но spec §3.6.4 определил safe-HTML-доставку лишь для

  отрендерить. Это прямые пользовательские баги: сырые HTML-теги в ответе бота —
  в лучшем случае выглядит как поломка, в худшем — раздражает и снижает доверие.
- **Требуемый фикс:** ввести единый обработчик безопасного HTML для `<b>`/буллитов на
  всех plain-каналах (по образцу `escape_lore_html` + фолбэк), либо не требовать `<b>`
  там, где доставка его не рендерит. Обязателен тест: финальный текст summary и
  factcheck не содержит literal-`<b>` ни при одном режиме.

## Обход guard'а

Одиночная pipe-строка без separator (`| a | b |`, `a | b`) намеренно **не** считается
таблицей — это корректно (одна строка не таблица) и явно зафиксировано в
`spec.md §11.4` и канон-доке. Реальные Markdown-таблицы ловятся separator'ом или
≥2 подряд pipe-строками, HTML — `<table`, ASCII — `+---+`. Скрытого обхода нет.
