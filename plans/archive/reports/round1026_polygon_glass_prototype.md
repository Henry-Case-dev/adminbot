# round 10.26 — прототип стекла над полигональным фоном (гейт §12.2 / ADR-1026-3 D6)

> **Фича:** `polygonal-luminescence-round1026` · **Маркер:** `POLYGON-LUMINESCENCE-OK`
> **Задачи:** T-3201…T-3203 (блок I). **Артефакт-прототип (gitignored):**
> `tools/_polygon_glass_prototype/{index.html,mount.js,probe.json,*.png}`.
> **Проба:** `tools/polygon_glass_probe.py` (запуск: `.venv/Scripts/python.exe tools/polygon_glass_probe.py`).

## Что проверялось

Изолированный прототип: полигональный фон (`polygon-background.js`, Canvas 2D) +
**одна** `[data-glass-surface]` поверх линий/узлов фона, внутри — кнопка с текстом
«Статус» и SVG-иконкой. Стекло монтируется **только** с явным источником:
`mountGlass(root, { source: #polygon-background, mode: 'webgl' })`
(ADR-1026-3 D6/§13.3) — путь, единственно дающий рефракцию анимированного canvas.
`mountGlass` без источника (причина hotfix10) не вызывается.

## 7 проверок §12.2 — результат

| № | Проверка | Метод | Результат |
|---|---|---|---|
| 1 | Настоящее преломление | headless-эвристика: `meanAbsDiff` области стекла при снятом/поставленном стекле = **8.503** (стекло читает фон позади, а не фильтрует свой декор) | ⚠ **PENDING OWNER** (оптическая корректность не воспроизводима headless) |
| 2 | Текст/иконка чётки | `getBoundingClientRect` + `elementFromPoint(центр текста)` → внутри button | ✅ PASS |
| 3 | Эффект не перекрывает кнопку | hit-test центра кнопки → сам button | ✅ PASS |
| 4 | Нет белого непрозрачного прямоугольника | доля near-white (R,G,B>240) в области стекла = **0.0046** (< 3 %) | ✅ PASS |
| 5 | Нет яркого внешнего ореола | `lum(кольцо 26px)` − `lum(стекло)` = **−6.19** (ореола нет) | ⚠ **PENDING OWNER** (субъективно) |
| 6 | Нет конфликта WebGL-контекстов | `__PolygonBackground.mode()='canvas2d'`, `#aurora-flow-canvas` отсутствует, OGL-Aurora не запущена | ✅ PASS |
| 7 | Перф mobile приемлема | headless Chromium 390×844 → **~60 FPS** (фон+стекло) | ⚠ **PENDING OWNER** (реальный WebView) |

**JavaScript-дефект, найденный гейтом (исправлен, T-3203):** штатный
`glass.js::detectMode` считал режим по наличию DOM-слоя `.ps-glass__refract`, но
WebGL-путь библиотеки (`source` + `mode:'webgl'`) такого слоя **не создаёт** —
он ставит `data-render="webgl"` и поднимает собственный WebGL-контекст. Теперь
`detectMode` честно распознаёт и `data-render="webgl"` как рефракцию
(`web/static/glass.js`). Это не расширяет цели стекла и не монтирует стекло без
источника; поведение «нет слоя и нет webgl → `frosted`» сохранено (hotfix10).

## Решение по интеграции (T-3204…T-3206, блок J)

По §13.2 прототип переносится в интерфейс **только если проходят все 7 проверок**.
Пп. 1/5/7 headless не воспроизводимы, поэтому интеграция стекла в основной UI
**не выполнена** (честно, без выдачи blur за рефракцию):
- `UI_LIQUID_GLASS_LIB` остаётся **default OFF** (без изменений);
- `glass.js::sync` по-прежнему **не** передаёт `source` — на функциональные
  элементы (селектор области / ⛶ / карточка «Статус») стекло не монтируется;
- `detectMode` улучшен только в части честности отчёта режима.

Итого эпик поставляет **фон** (полигональная сеть) как основной результат;
точечная glass-интеграция — блок J — **заблокирована гейтом** до ручной проверки
владельцем (7 проверок в реальном Telegram WebView).
