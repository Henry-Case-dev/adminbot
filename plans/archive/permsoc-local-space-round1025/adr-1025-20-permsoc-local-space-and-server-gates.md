## Контекст

§60 объявляет **PERMsoc локальным пространством чата** («PERMsoc не является глобальной конфигурацией», «Использовать канонический `chat_id`»), §60 задаёт **6 блоков** (Славик, Костик, Оля, Мимикрия, **Общие реакции**, **Расписания**), §61 — иерархию **мастер → блок → функция**, запрет декоративных тумблеров и требование «при выключении общего блока сохранять дочерние».

Факты, проверенные по коду (детали — `spec.md` §2):
1. Вкладка `#/permsoc` — **5** owner-блоков; «Общее/Мастер» собирает **остаток** групп, т.е. является свалкой; `«Общие реакции»`/`«Расписания»` не выделены.
2. **Дефект:** при `activeChatId == null` шаблон прямо сообщает «Без чата меняются только общие значения ниже» (`web/index.html:1294-1298`) — то есть правит **глобальные** значения, что противоречит §4/§60.
3. Мастер `permsoc` — **global-admin-only** через `chat_params["gates"]` и `PUT /api/chat/{id}/gates`; персональные суб-флаги — **per-chat overrides** через `POST /api/config`. Это **разные** контракты (RBAC, хранилище, действие сброса).
4. `war_alert`, `common` (otboy/danger/selfdev/work), `vasya`, `kucha` — **не гейтированы** вообще; `alan` — только под мастер (`flags.alan_replies_enabled` читается глобально, без чата).
5. **goodmorning** — процессный планировщик по `GOODMORNING_TARGET_CHAT_IDS`; **per-chat гейта нет**.
6. Per-chat `/api/config` принимает **только каталожные** ключи (`spec.per_chat=True`); произвольные новые ключи записать нельзя (422). Значит, для блок-гейтов, у которых нет каталожного ключа, единственный путь без Δ DDL/каталога — **`chat_params["gates"]`** (feature_gates).
7. Группы каталога **смешивают блоки** (`limits_media_permsoc`, `limits_mimic`, `flags_media`, `reactions_slavik`) → нужен key-level владелец.
8. Мастер `permsoc` дефолт **False** и исторически гейтит **только** плагин персонажей (Славик/Костик/Оля/Мимикрия/Леха). war/danger/goodmorning им **не** гейтировались.

## Решение (D1–D7)

### D1. Канонический scope: `activeChatId` + `.scope-tech`; без чата — не редактировать
**Решение.** Единственный источник `chat_id` — F3-scope (`this.activeChatId`); заголовок «PERMsoc · Только этот чат» + `chat_id` в `.scope-tech`. Без выбранного чата **блоки и тумблеры не рендерятся** (banner «Выбери чат»), текст `:1294-1298` удаляется. Дополнительно — **guard записи**: попытка записать PERMsoc-ключ в global отклоняется.
**Альтернативы.** (a) read-only блоки без чата — отклонено: значение всё равно видно как «эффективное глобальное», легко спутать с редактируемым; (b) оставить текущий текст — отклонено (прямое нарушение §4/§60); (c) авто-редирект на первый чат — отклонено (ложный scope, риск записи не в тот чат).

### D2. Шесть блоков и правило «ключ ровно в одном блоке»; мастер — отдельный уровень
**Решение.** `PERMSOC_OWNER_BLOCKS` → 6 блоков с **явными key-level списками** (из-за смешанных групп); группы каталога — только добор невзятых. Мастер `flags.permsoc_enabled` выводится из owner-блока в **отдельный уровень** §61 (остаётся `gates.permsoc`). «Общее» перестаёт быть свалкой.
**Контракт тумблера блока.** Пишет **только** `owner.toggleKey` (персональные — `saveConfigItem`; новые блоки — `toggleGate`); дочерние не сбрасываются (§61). Тумблер показывается только при реальном серверном пути (D3).
**Derived.** Персональные блоки = `master AND sub_flag`; новые блоки — собственная ось (см. ниже).
**Альтернативы.** (a) group-level владение — отклонено (группы смешаны, ключи попали бы в 2 блока); (b) оставить «Общее» как остаток — отклонено (§60: не свалка); (c) 4 блока + «Общее» — отклонено (ТЗ прямо называет 6).

### D3. Пер-чат блок-гейты «Общие реакции»/«Расписания» через `feature_gates.gates` (Δ DDL = 0)
**Решение.** Ввести feature-id `permsoc_reactions` и `permsoc_schedule` в `ALL_GATED_FEATURES`; хранить в `chat_params["gates"]`; `DEFAULT_BY_FEATURE` = **True** (нет явного гейта → функция работает — сохраняет baseline). В `services/permsoc.py` (расширение, **не** второй модуль) — `block_enabled(chat_id, block)` (fail-open OFF при исключении) и `BaseFilter PermsocBlockGate(block)`; фильтр добавляется к ранее негейтированным хендлерам и **к существующим** alan-гейтам (master сохраняется). goodmorning: `_tick` проверяет `block_enabled(chat_id, "schedule")` **перед** отправкой. `gates_put`/RBAC — global-admin для всего семейства `permsoc*`; `gates_get.who_can_toggle` = `"global"` для `permsoc*`.
**Почему не «расширить мастер на всё».** Мастер default **False** и исторически не гейтит war/danger/goodmorning; распространение на них молча выключило бы **живые** функции → регрессия, запрещённая приоритетом №1 ТЗ («сохранить существующую функциональность»). Поэтому новые блоки — **независимая** ось, а мастер остаётся рубильником плагина персонажей. Отклонение от буквального «master OFF → всё OFF» **осознанно** и документируется; UI показывает это честно (для новых блоков мастер не заявлен как их родитель).
**Альтернативы.** (a) новый каталожный ключ `flags.permsoc_*_enabled` — **отклонено** (Δ каталога = 0); (b) новый `overrides`-ключ вне каталога — **отклонено** (per-chat `/api/config` отвергает неизвестные ключи, Ф17); (c) отдельная таблица/DDL — **отклонено** (Δ DDL = 0); (d) отдельный модуль гейтов — отклонено (дублирование `PermsocGateFilter`/`feature_gates`, лишняя поверхность).
**Fail-open.** И мастер, и блок-гейты при недоступности PG/кэша → **False** (безопасная тишина), без спама (WARNING) — семантика `PermsocGateFilter` сохранена.

### D4. Содержание блоков и единицы
**Решение.** Ключи и группы — по `spec.md` §4/§6. Ключевое: `limits.kostik_reply_probability` — **сервер 0.0–1.0**, UI — **проценты 0–100 %** (конвертация на границе, клип [0,1], round-trip-тест); §67-лимиты отнесены к «Расписаниям» буквально по §67; `reactions.goodmorning_time` = `HH:MM`, `_tz` = IANA (валидация `ZoneInfo`); `kostik_replies` — построчный редактор; `reactions.slavic_photo_path` — **deprecated, видим, не удаляем** (код читает legacy-fallback).
**Серверные единицы/семантика наследования не меняются** (§59-прецедент, §74).

### D5. Каталог не трогаем: presentation-группировка в JS
**Решение.** `services/param_catalog.py` не изменяется (Δ каталога = 0); владельцы/подгруппы — JS-константы (`PERMSOC_OWNER_BLOCKS[].keys`, `PERMSOC_BLOCK_SUBGROUPS`).
**Альтернативы.** Дробить `GroupSpec` — отклонено (Δ каталога ≠ 0).

### D6. Инварианты и доказательность
**Решение.** Δ DDL = 0, Δ каталога = 0, CSP/zero-build, R17/R18. Ключевые проверки: «глобальные PERMsoc не меняются без чата», «локальные не перезаписываются глобальными», «OFF блока сохраняет дочерние», «фоновая задача прекращается» (goodmorning no-send), partition ключей, единицы, deprecated, изоляция чатов (§73). Не ломать §57–§65/F0/F1/F3/F4/F5/F6/ADR-1024-24. Доказательная планка (прецедент §63/§65): зелёная сборка/вердикт/новый флаг — **не** доказательство; только воспроизводимые поведенческие проверки.

### D7. Kill-switch и bump
**Решение.** Env-only `ClassVar[bool]` **`PERMSOC_BLOCK_GATES_ENABLED`** (default **ON**, ∉ каталога → Δ каталога = 0), доставка в UI через `GET /api/me.ui_flags`. OFF → **baseline**: `block_enabled` всегда `True`, goodmorning без per-chat проверки, новые блок-тумблеры — честный read-only. Отдельного feature-flag на UI-каркас не вводим (мягкий откат — `git revert`). Bump `APP_VERSION` 2.58.14 → **2.58.15**.
**Почему не только мастер-тумблер.** Мастер не покрывает новый серверный слой и не может выключить уже раскатанное поведение.

## Последствия

**Положительные.** PERMsoc становится честным локальным пространством (нет записи в глобал, нет «свалки»), «Общие реакции» и «Расписания» реально отключаются per-chat (включая фоновую goodmorning), иерархия и derived-состояние честны, инварианты Δ DDL/каталога = 0 и CSP соблюдены, F0/F1/F3/F4/F5/F6/ADR-1024-24 не затронуты.

**Отрицательные / цена.** Появляется серверная поверхность (2 feature-id + фильтр + проверка в `_tick`) и расхождение с буквальным чтением «master OFF → всё OFF» (сознательно, ради неразрывности baseline). UI-тумблеры новых блоков доступны только global-admin (локальные админы — read-only) — компромисс ради простоты RBAC (`gates_put`).

**Затронутые контракты.** `GET/PUT /api/chat/{id}/gates` (новые feature-id в ответе `gates`; `who_can_toggle`); `POST /api/config` (guard для PERMsoc-ключей в global); `GET /api/me.ui_flags` (новый флаг soft-rollback); `PermsocGateFilter` (без изменений) + новый `PermsocBlockGate`.
