# ADR-1010-3 — «Роли»: источник ника/аватара глобальных админов

- **Статус:** Accepted (@Architect, 12.09.2026)
- **Контекст:** список назначений «Роли» (`#/access/admins`) показывает голый Telegram ID. Нужны аватар+ник, ID — мелким серым рядом; фолбэк — ID. `cache.admins_full()` имени/аватара не содержит.

## Решение
- **Backend:** новый `global_user_display_info(user_id)` в `web/api/avatars.py`: имя best-effort `bot.get_chat(user_id)` → full name → username; фото — `get_user_profile_photos(user_id, limit=1)` (общий `_user_photo_cache`); RAM-TTL 1ч; fail-open `None`. `chat_id` не требуется (в отличие от `user_display_info(chat_id, uid)`).
- **Endpoint `GET /api/admins`:** обогащение копий строк `display_name`/`photo_file_id` через `asyncio.gather`+`Semaphore(5)`, fail-open; модель `admins_full()`/`bot_admins` не меняется.
- **Frontend:** `loadAdmins` вызывает `loadAvatar('user', id, admin)` (blob через `/api/avatar/user/{id}`, без прямых `<img src>`, 401-safe); рендер — аватар/инициал + ник, ID всегда мелким серым (`text-[10px] text-gray-500 font-mono`); fallback при неизвестном имени — только ID. Для себя допускается `me.first_name`.

## Альтернативы
- `transient` имена из `initData` — отклонено: покрывает только текущего пользователя.
- Хранить имена в новой таблице/кэше — отклонено: новый DDL/инфра, вне инварианта.
- Ручные alias-списки — отклонено (вне скоупа; можно позже).

## Последствия
- Плюс: UI читаемый; секретов нет; кэш 1ч не долбит Bot API.
- Минус: для админов, которых бот «не знает» (никогда не запускали бота), имя недоступно → только ID (owner decision §9.2).
