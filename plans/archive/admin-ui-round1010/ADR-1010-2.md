# ADR-1010-2 — Mobile key-availability chart: дорожки + временная сетка

- **Статус:** Accepted (@Architect, 12.09.2026)
- **Контекст:** на мобильном график «История доступности ключей» выглядит одной плоской полосой. Данные (`/api/status/key-history`, ring 288×5мин) корректны и одинаковы для desktop/mobile. Причина — отрисовка.

## Решение
Не менять контракт `api_payload`. Переписать `renderKeyHistoryChart` через чистую `keyHistoryChartModel(providers)`:
- каждый провайдер — своя дорожка (`i+0.75` ok / `i+0.25` err), `y.max = laneCount+0.2`;
- временная сетка с шагом 300с, минимум 12 бакетов (1 час) до последнего слота, отсутствующие слоты = `null` (`spanGaps:false` сохранён);
- `pointRadius:3` при ≤1 сэмпле, иначе 0;
- высота `max(120, 44 + laneCount*22)`, `maintainAspectRatio:false`, обёртка `.keys-chart` с реактивной высотой;
- сохранить маркеры `stepped: true` и `legend: { display: true`.

## Альтернативы
- Ввести `type:'time'` (date-adapter) — отклонено: новая зависимость, меняет рендер/вес.
- Менять `api_payload` (плотная сетка на сервере) — отклонено: контракт и leak-safe слой остаются стабильными, задача решается на клиенте.
- Показывать таблицу вместо графика — отклонено: теряется временной ряд.

## Последствия
- Плюс: различimость провайдеров, читаемая ось времени, корректные 1–2 точки и пустое состояние.
- Минус: график выше на многих провайдерах (осознанно).
