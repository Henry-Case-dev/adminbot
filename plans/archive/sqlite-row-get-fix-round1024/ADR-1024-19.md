# ADR-1024-19 — Канон доступа к строкам курсора: `row_get` вместо `Row.get` (UPD4-D)

> **Статус:** proposed → применяется в раунде 10.24.
> **Слой:** web-API (`web/api/chat_lore.py`) + инвариант для сервисов. **Δ DDL = 0, Δ каталога = 0.**
> **Связано:** инцидент UPD4 «кластер D»; фича `sqlite-row-get-fix-round1024`.

## Контекст

`web/api/chat_lore.py::_participant_names` строит карту `{user_id: author_name}` из
`db.get_active_participants(...)`. Источник — SQLite с `row_factory = aiosqlite.Row`
(это `sqlite3.Row`), у которого **нет** `.get`. Код вызывал `r.get("user_id")` /
`r.get("author_name")` → `AttributeError`, который **глотался** широким
`except Exception` с WARNING и возвратом `None`. Итог: тихая деградация — имена
участников в relations-списке пропадали, UI показывал сырые ID (uid-fallback),
и никто не замечал, потому что исключение не поднималось наружу.

Это не первый случай класса: тот же баг уже чинили точечно в
`services/tool_router.py:1030-1031` («T-678: aiosqlite.Row не имеет .get» →
`[dict(row) for row in rows]`). Есть и обратный случай-ловушка: asyncpg `Record`
**имеет** `.get` (напр. `services/anticliche_cache.py:197`), поэтому «на глаз»
SQLite-строки и PG-строки неразличимы.

Ключевой вопрос: как единообразно и дёшево читать поля строки, не порождая новых
`AttributeError` и не переписывая каждый запрос.

## Решение

### D1. Единый аксессор `row_get` для строк курсора

В местах одиночного доступа к полям использовать канонический
`services/database.py::row_get(row, key, default)` — он проверяет `hasattr(row, "get")`
(dict/asyncpg Record) и иначе делает `row[key]` с ловлей `KeyError/IndexError/TypeError`.
Это минимальная правка (импорт + 3 строки), без изменения семантики маппинга и без
лишних аллокаций. `_participant_names` переводится на `row_get`.

### D2. Предварительная нормализация `dict(row)` — легальный, но не выбранный вариант

`rows = [dict(row) for row in rows]` (прецедент `tool_router.py:1030`) допустим, когда
дальше нужен именно словарный интерфейс/несколько `.get`. Для одной функции это
избыточная аллокация и разрыв с «аксессорным» каноном; оставляем как совместимую
альтернативу, а не как дефолт.

### D3. Правило вместо разового фикса

Канон: **строка курсора → `row_get(row, key)` либо предварительный `dict(row)`;
прямой `row.get(...)` на `aiosqlite.Row` запрещён.** Широкие `except` в read-путях
сохраняются как fail-open, но не должны быть единственной защитой от этого класса:
регресс закрепляется тестом на **настоящем** `sqlite3.Row`. Превентивный аудит
`web/api/**` и `services/**` (T-2330) проверяет существующие `.get` по строкам.

### D4. Разграничение с F4 `dossier-live-feed`

F4 добавляет обратный резолв `name → user_id` в `web/api/oversight.py` на том же
`db.get_active_participants`. Решение: **общий код не выносим** — `_participant_names`
остаётся приватным helper F18, F4 дублирует паттерн `row_get` в своём модуле. Это
дешевле и не создаёт связности между web-модулями разных фич; правило D3 обязательно
для обеих сторон.

## Последствия

**Плюсы:** баг закрыт возвратом имён; единый предсказуемый способ чтения Row;
регресс не сможет снова «спрятаться» за тихим `except`; нулевой DDL/каталог/флаги.
**Минусы/долг:** `row_get` вызывается несколько раз на строку (мелочь для ≤200 строк);
канон нужно соблюдать вручную (lint-правила `.get` на Row в проекте нет) — аудит T-2330
снижает риск, но не исключает будущих повторов.
**Стоимость:** ноль рантайм-изменений кроме корректного ветвления; поведение
fail-open сохранено.

## Альтернативы

| Альтернатива | Почему отклонена |
|---|---|
| Оставить `dict(row)` как обязательный паттерн везде | лишняя аллокация на каждый read; для одиночного доступа аксессор честнее |
| Заменить `.get` на голый `r["user_id"]` | работает, но теряет единый аксессор и default-семантику; дублирование ручных `try/except` |
| `try: r.get(...) except AttributeError: r[...]` на месте | размножение ad-hoc-кода; ровно то, что инкапсулирует `row_get` |
| Сменить `row_factory` на `dict` для SQLite-соединения | глобальный риск: ломает все `row["col"]`/`dict(row)`-инварианты и существующий код; несопоставимо с масштабом фикса |
| Поднять уровень логирования `except` до `error`/проброса | меняет fail-open контракт relations; баг уже устранён, шум в логах не нужен |
| Вынести общий helper для F4 сейчас | преждевременная связность web-модулей разных фич; дублирование паттерна дешевле |
