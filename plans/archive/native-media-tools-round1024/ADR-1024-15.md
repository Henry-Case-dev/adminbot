# ADR-1024-15 — Нативное медиа: приоритет над caption-URL + контракт инструментов нативного источника

> **Статус:** Proposed (Step 2 @Architect, 19.09.2026; **обновлён под UPD5**). **Раунд:** 10.24. **Фича:** F14 `native-media-tools-round1024` (T-2299).
> **Тип:** AMEND — ревизия канона инструментов (**9→10**) и контракта скачивания/выжимки/транскрибации.
> **Связано:** ADR-1015-3 (tool calling), ADR-1016-1 (контракт скачивания), ADR-1017-2 (качество в tool-пути), ADR-1020-4 (канон инструментов, «Летописец»), ADR-1023-5 (`generate_image`), ADR-1024-17 (YouTube raw-транскрипт, F16).
> **Границы:** F13 `native-reply-media-context-round1024` (медиа-маркер в контексте), F15 `video-download-native-ux-round1024` (формулировки/меню качества).
> **R17/R18:** URL/file_id/секреты в тексте ADR не цитируются; `current_task.md` untracked.

## 1. Контекст

Прод-баг UPD4-A-2: «Бот скачай видос» реплаем на **нативное TG-видео** с непустым caption-URL
уходит в URL-ветку Fast-Track, потому что `_extract_urls` собирает ссылки и из сообщения, и из
реплая (`handlers/video_download.py:144-161`). Живое видео в реплае игнорируется. При провале
probe срабатывает bounded fallback (`:439-483`) и юзер видит «⏳ Скачивание без выбора качества…»
и общую фразу пула `VD_ERROR_PHRASES` («че ты мне суешь? я не могу это скачать») — **причина не
объясняется**, меню качества осознанно не показывается (ADR-1016-1 §2.5).

Дополнительно инструменты `summarize_video`/`download_media` не умеют нативный источник: `url` —
единственный обязательный аргумент (`services/tool_schemas.py:120-172`), а `_summarize_video`/
`_download_media` требуют http(s)-URL. Сценарий «Бот что на видео» (реплай на нативное видео)
физически не может ответить через инструмент.

Три причины решать одним ADR:
1. Расхождение канона инструментов: ADR-1020-4 зафиксировал **8** инструментов; раунд 10.23
   (ADR-1023-5, F5) добавил `generate_image` → **9**; UPD5 добавляет `transcribe_video` → **10**,
   а шапка `tool_schemas.py` всё ещё описывает «7» (техдолг 10.23 I2). Ревизия канона нужна явная.
2. Приоритет «нативное медиа > caption-URL» меняет принятое ранее поведение Fast-Track.
3. Понятный отказ probe требует изменения контракта фраз (`ADR-1016-1 §2.4`).

## 2. Решение

### 2.1. Канон инструментов: ревизия R9 — **10 инструментов** (AMEND ADR-1020-4 / ADR-1015-3)

- Канон R9 фиксируется как **10 инструментов**: порядок первых **9** — байт-в-байт
  (`query_chat_memory`, `dig_into_lore`, `execute_web_search`, `summarize_video`,
  `download_media`, `get_bot_health`, `get_recent_history`, `compile_lore_story`,
  `generate_image` — ADR-1023-5 §D2); **10-й — `transcribe_video`** (новый, в конец, канон-дисциплина
  «новое — в хвост»). Закрывается рассинхрон комментария в `tool_schemas.py` (техдолг 10.23 **I2**).
- **UPD5 — разделение инструментов по функциям:** один `summarize_video` с
  `mode: summary|transcript` заменяется **двумя** инструментами с однозначными назначениями:
  `summarize_video` = **выжимка** (саммаризация; `mode` удаляется), `transcribe_video` =
  **сырая транскрибация** (голый текст без пересказа). Так LLM выбирает инструмент по
  формулировке пользователя (см. §2.3-bis). Это AMEND контракта ADR-1015-3.
- `download_media` сохраняется (меняется только модель источника `url`/`source`, §2.3).
- `active_tools`/`factcheck_tools` не меняются (фактчекер видео-инструментов не получает).
- Счётчик в шапке модуля и у `TOOL_CALLING_TOOLS` актуализируется до фактического (**10**).
- **Ступень F14 → F19 (UPD5 №3):** настоящий ADR фиксирует **канон/контракт** (два инструмента,
  определения, `summarize_video` без `mode`); финальную схему `transcribe_video` в коде, dispatch
  и счётчик 10 вливает **F19 `media-transcribe-tool-round1024`** поверх правок F14
  (`services/tool_schemas.py`/`services/tool_router.py` — ступень **F14 → F19**).

### 2.2. Приоритет нативного медиа над caption-URL (AMEND ADR-1016-1 §2 / ADR-1017-2)

- Fast-Track сначала резолвит нативное видео (своё `video`/видео-`document` → медиа реплая).
  Найдено — идёт `_handle_native_media` **независимо** от наличия http(s)-ссылок в text/caption.
  `_extract_urls`-ветка (probe/меню/fallback) применяется только при **отсутствии** нативного медиа.
- Причина: реплай-видео — непосредственный референт запроса «скачай»; caption-URL на нативном
  видео обычно метаданные/источник. Прятать за URL-веткой живое видео — регресс UX.
- Уточнение ADR-1016-1 §2: для прямого/pлатформенного URL, данного **явно** (без нативного медиа),
  поведение прежнее. Дополнительно: своё сообщение-документ квалифицируется `document_is_video`
  (невидео-документ больше не уходит в нативный путь).
- Меню качества к нативному медиа **неприменимо** (ADR-1016-1 §2.5 сохраняется для ссылок);
  пользовательские формулировки/сообщение о конфликте «видео + ссылка» — F15 (T-2307/T-2309).

### 2.3. Контракт инструментов нативного источника

- `url` в `summarize_video`/`transcribe_video`/`download_media` становится **необязательным**;
  добавляется необязательный `source: enum["link","reply"]`.
- Резолв: http(s)-`url` → ссылочный путь (байт-в-байт); пустой/внутренний-реф `url` при наличии
  нативного медиа в контексте → нативный путь. Нативный источник берётся из
  **`ToolContext.native_media`** (разрешённый aiogram-объект), а **не** из текстового аргумента
  модели — file_id невозможно восстановить из БД, а доверять модели как источнику bytes нельзя.
- **Интерфейс F13 → F14:** `ToolContext.native_media` определяется в F14 (`tool_router.py`),
  заполняется в `direct_chat_service` (владелец — F13; эмиссия T-2295, где медиа уже резолвится
  для маркера T-2294). F14 тестируется юнит-инъекцией поля, независимо от F13.
- Нативный путь: `download_media` → `fetch_media_to_tmp` → `send_media`, без меню качества и без
  сжигания download-кулдауна (копирование файла TG, как Fast-Track нативный путь); лимит 2 ГБ.
  `summarize_video` → tmp → **выжимка**: `media_share` + `deps.video.summarize_media_url`,
  STT-фолбэк выжимки (опциональный `deps.transcriber`). `transcribe_video` → tmp → **STT**, наружу
  сырой текст (без пересказа). Таймауты/лимиты tool-loop не меняются.
- Единый источник квалификации видео/документа — новый модуль `services/native_media.py`
  (устраняет дублирование `handlers/youtube.py` ↔ `handlers/video_download.py`).

### 2.3-bis. Разделение функций: выжимка vs транскрибация (UPD5)

Ключ к решению LLM — **однозначные EN-`description`** у двух инструментов (полные схемы — в spec §4.4):

| Инструмент | Функция | Когда вызывать | Что вернуть |
|---|---|---|---|
| `summarize_video` | **выжимка** (конденсат) | «что на видео», «че за видос», «о чем видео», «перескажи/выжимка» | сжатый пересказ, **не** сырой транскрипт |
| `transcribe_video` | **транскрибация** (сырой текст) | явный «транскрипт»/«транскрибация», повтор транскрибации ГС/кружка/видео | дословный сырой транскрипт, **без** пересказа |

- `summarize_video.description` прямо сообщает, что это SUMMARY и что сырой транскрипт — не сюда;
  `transcribe_video.description` — что текст возвращается **дословно** и сжимать его нельзя.
- `tool_choice` **не форсируется** (канон ADR-1020-7 / backlog §16 п.2): выбор — за моделью.
- Источник (`url`/`source`, ссылка или медиа реплая) у обоих инструментов единый (§2.3).
- Egress не расширяется: `transcribe_video` возвращает **строку** (как query-инструменты); доставка
  сырого транскрипта курсивом — командный путь 0e (F16, `_send_transcript_reply`), уже allowlisted.

### 2.4. Понятный отказ probe (AMEND ADR-1016-1 §2.4 / ADR-1017-2)

- Для probe-причин (`probe_timeout`, `probe_failed`) вводится отдельный пул
  `VD_PROBE_FAIL_PHRASES`; общий `VD_ERROR_PHRASES` больше не маскирует probe-провал.
- Маппинг конкретных причин (`probe_bot_check`, `cobalt_down`, `*_too_big`) сохраняется.
- Реальная причина probe остаётся в R17-safe логе (`error=<Class> reason=<code>`) и, где доступно,
  уходит в `services.external_log.trace_step`. Формулировки — F15 (T-2308).

### 2.5. Флаг и совместимость

- `NATIVE_MEDIA_TOOLS_ENABLED` — env-only `ClassVar`, default **ON**, вне `param_catalog`.
  OFF → прежнее поведение (urls-first; инструменты требуют `url`). Поэтапная раскатка не требуется.
- **Δ DDL = 0**; **Δ каталога = 0**; `media/`, `.env` не трогаются.

## 3. Последствия

- (+) Баг A-2 закрыт: живое видео больше не вытесняется caption-URL.
- (+) Инструменты работают с нативным видео реплая; сценарий «Бот что на видео» реализуем.
- (+) Канон инструментов консистентен (**10**), устаревший комментарий устранён (закрыт I2).
- (+) Разделение выжимки и транскрибации (UPD5): LLM выбирает функцию по однозначным `description`,
  без `mode`-двусмысленности; сырой транскрипт и пересказ больше не смешиваются.
- (+) Единый резолвер медиа (`services/native_media.py`) убирает дубль квалификации.
- (−) Ослабление `required` в схемах: LLM может вызвать инструмент без `url` — митигируется
  понятной ошибкой при отсутствии `ctx.native_media` и тестами (b)/(e).
- (−) Удаление `mode` у `summarize_video` — ревизия LLM-facing контракта; покрывается канон-тестом
  (d)/(d2) и не затрагивает Python-сигнатуры/`active_tools`.
- (−) Появляется зависимость live-пути от F13-эмиссии `ToolContext.native_media`; юнит-путь F14
  от неё не зависит (инъекция), риск R6.
- (−) Нативный путь — дополнительная точка расхода (fetch/публикация/STT); ограничена
  tool-timeouts, лимитами размера/длительности и глобальным локом downloader'а.
- Инварианты: порядок роутеров `bot.py` (только DI-kwargs), лимиты tool-loop, egress-реестры,
  `parse_mode=None`, `imported-history-immutable`, media-политика — без изменений.

## 4. Рассмотренные альтернативы

| Вариант | Вердикт |
|---|---|
| Оставить URL-приоритет, показать меню качества при конфликте | **Отклонён:** меню качества неприменимо к нативному видео; баг A-2 остаётся |
| Приоритет ссылки, нативное медиа — fallback | **Отклонён:** воспроизводит прод-симптом; ссылка в caption не должна перебивать живое видео |
| Новый инструмент `download_reply_media` | **Отклонён:** лишний раунд tool-loop, дублирование `download_media`; нативное медиа отдаётся тому же инструменту через `source` |
| **Один** `summarize_video` с `mode: summary\|transcript` (статус-кво) | **Отклонён (UPD5):** LLM путает функции, «транскрипт» и «что на видео» ведут к одному инструменту; владелец требует два отдельных инструмента с чёткими определениями |
| `transcribe_video`, отдающий **выжимку** транскрипта | **Отклонён:** транскрибация = дословный сырой текст (как у ГС); пересказ — только `summarize_video` |
| Прокидывать нативное медиа через текстовый внутренний реф, который модель эхо-ит | **Отклонён:** file_id/bytes не восстановимы из БД; доверие модели как источнику bytes хрупко и небезопасно |
| Публичный URL нативного файла как `url` для инструментов | **Отклонён:** утечка публичной ссылки в контекст/логи (R17), лишняя публикация |
| Резолв медиа внутри `tool_router` из `reply_to_message_id` | **Отклонён:** file_id не хранится в БД; нужен aiogram-объект из DirectChat (эмиссия F13) |
| Сжигать download-кулдаун на нативный re-send | **Отклонён:** это копирование TG-файла, не внешнее скачивание; паритет с Fast-Track нативным путём |
| Оставить общий `VD_ERROR_PHRASES` для probe-fail | **Отклонён:** маскирует причину, противоречит требованию UPD4 |
| Новый PG/SQLite-стол для pending/медиа | **Отклонён:** Δ DDL=0; in-memory/pending уже есть |
