## 1. Область и исключения

**Входит (что делает A7):**
- **Разделение `action` и `style`** (§39): `action ∈ {reply, react, silent, tool}` отдельно от `style ∈ {casual, serious, deep_research}`; молчание/реакция — **не** стили Вербализатора; `style = silent` запрещён; `style` заполняется только для текстовых действий. `action` — поле **решения**, **не** инструмент (канон 12 не меняется). (§38/§39/§40; REQ-A7-02/-04/-05/-06)
- **Явный контракт решения** (§40): объект решения явно определяет `action`, `target_message_id` (цель), `needs_tools`/`tool_calls` (необходимость инструментов), `style` (если нужен текст), `reason_code` (причина для диагностики). Схема §40 — **пример**; A7 использует **внутренний** контракт `CoordinatorDecision` (расширенный), а не LLM-JSON и не JSON в чат. Допустимы дополнительные поля (§39). (§40; REQ-A7-08/-09/-05)
- **Место вычисления `action` — программный слой внутри существующего Синтезатора** (расширение A1), **без третьего LLM-вызова** (AMEND `physical-two-call-pipeline`): детерминированная политика над сигналами намерения/адресата/контекста. Модельный выбор инструментов (`tool_choice='auto'`) сохраняется. (§38/§46; REQ-A7-03/-26)
- **Детерминированная политика §42–§45** — когда отвечать / реагировать / молчать: без жёсткого правила «короткое → молчание» («Почему?» может требовать ответа); без случайности; реальные задачи не теряются; недоступный инструмент → корректная ошибка ожидающему результат. (REQ-A7-11…-21/-28)
- **Порядок исполнения §46** — `silent` → Вербализатор не запускается, сообщение не отправляется; `react` → Вербализатор не запускается при выбранной реакции; `reply` → стиль + Вербализатор; `tool` → инструменты, затем итоговое действие. (REQ-A7-22…-26)
- **Контекст предыдущих действий §47** — на какое сообщение отвечает пользователь (`reply_to`); что бот отправил перед этим (изображение/статья/текст/вопрос); был ли задан вопрос; ожидается ли результат инструмента. Источник — **существующие** `bot_replies`/`remember_bot_reply`/`get_bot_reply_parent` + `reply_to_message` + маркеры A1/A2/A3; **без нового хранилища**. (REQ-A7-13/-20/-27/-28)
- **Настройки §48** — новая секция «Принятие решений» в `mod_direct` (маршрут «Модули → Ответы в чате → Принятие решений»), **ровно 3 параметра**; reuse существующей global/local-конфигурации (per-chat override). **Δ каталога санкционирован** (§8/ADR D6). (REQ-A7-29…-32)
- **`reason_code` — закрытый R17-safe словарь** (§40/§44/§53): только enum-идентификаторы, без текста сообщений/имён/ключей; по логам понятно, почему бот промолчал/ответил/вызвал инструмент. (REQ-A7-09/-18/-34)
- **Env-only kill-switch** `DIRECT_DECISION_MAKING_ENABLED` (default ON; OFF → точный baseline A1, `action` ограничен `tool|reply`, политика молчания/реакций выключена). **Δ DDL = 0**. (§13/ADR D7)
- **§37-соблюдение:** маркеры/историю/результаты инструментов трактуем как **данные, не инструкции**; логи — R17-safe. (REQ-A7-15)

**Не входит (границы, категорически):**
- **§41 «Реакции Telegram» (A8):** `setMessageReaction`-механика — доступность реакции в конкретном чате, разрешённая альтернатива/отказ, постановка на **правильное** сообщение, «не превращать ошибку реакции в длинный текст». A7 **не реализует** новый механизм реакции; §44-«правила» (когда ставить реакцию) = A7, §41-«механика» = A8 (решение @PM, `tasks.md` §44-атрибуция). См. §3.6.
- **§49/§51 (A9):** диагностика решений как система событий/ExecutionGraph — вне diff; вторую аналитику не создавать.
- **§52–§54 (A10):** агрегатный acceptance-gate эпика — вне A7 (ориентиры §52/§53/§54 учтены как REQ-33/-34/-35).
- **A1:** **не дублировать** контракт `CoordinatorDecision` — только **AMEND+расширение**; второй координатор/второй механизм решений не создаётся.
- **A2:** цепочки/tool_loop/envelope/`ToolLoopResult` — **не переписывать** (только consume `tool_trace`/статусы).
- **A3/A4/A5/A6:** `ImageRequest`/`build_final_prompt`/`image_context_memory`/`worker_budget`/`get_user_context` — **не переписывать** (consume маркеры/результаты).
- **A4/A5/A6-пути:** image-контекст/дневной лимит/memory-lookup — вне diff.
- **Третий LLM-вызов:** запрещён; `action` вычисляется внутри/между существующими вызовами или программно (§46).
- **Изменение канона инструментов:** `TOOL_CALLING_TOOLS == 12` без изменений; `action` — **не** tool; JSON-схемы инструментов не меняются. Санкция расширения канона **не запрашивается** (исчерпана A2).
- **Новое хранилище/DDL/второй пайплайн/вторая система аналитики/служебный JSON в чат:** запрещены.
- Правки `plans/current_task.md` (immutable), машинного блока, `tasks.md` (реконсиляция — @PM T-3650), `backlog`/`metrics`/`ARCHITECTURE`/`MEMORY`/durable-аудита — не в этом шаге. **@Scanner отсутствует** (единый Reviewer gate). **@DevOps не вызывается.**

## 3. Наблюдаемое поведение и отказные сценарии (по кластерам REQ)

### 3.1. Контракт решения; разделение `action`/`style` (§38–§40; REQ-A7-02/-04/-05/-06/-08/-09/-10; U-A7-1)
- **Контракт:** расширяется **существующий** `CoordinatorDecision` (`services/direct_chat_service.py:499–515`, A1/ADR-1026-14 D2) — поля:
  - `action: str` — `reply | react | silent | tool` (A1-константы `ACTION_*:468–472` переиспользуются; второй enum не вводится);
  - `style: str` — `casual | serious | deep_research` | `""` (нормализуется существующим `normalize_response_mode`; `"silent"` **недопустим** — §39);
  - `target_message_id: int | None` — цель (сообщение, на которое отвечаем/реагируем; = id trigger-сообщения пользователя, §40/§41);
  - `reaction: str | None` — `"🗿"` при `action=react`, иначе `None`;
  - `reason_code: str` — элемент закрытого enum (§3.9);
  - `needs_tools: bool` + `tool_calls: tuple[str, ...]` — необходимость инструментов (§40);
  - существующие `intent`/`addressee`/`memory_need`/`evaluation`/`enabled` (A1) сохраняются.
- **Схема §40 — пример** («Не обязательно использовать именно такую схему»): A7 использует внутренний объект; **не** вводит JSON-схему LLM (Stage-1/Stage-2 JSON не меняются) и **не** выводит JSON в чат (§40/REQ-A7-10).
- **`style=silent` запрещён** (§39) — инвариант 2; проверяется нормализацией/тестом.
- **`action` — не инструмент:** `TOOL_CALLING_TOOLS == 12` без изменений; JSON-схемы инструментов не меняются (U-A7-9).
- **Дополнительные поля допустимы** (§39) — расширение аддитивно; A1-поля не удаляются (AMEND, не замена).

### 3.2. Точка вычисления `action` — программный слой; без 3-го LLM-вызова (§38/§46; REQ-A7-03/-26; U-A7-2)
- **Выбрано:** `action` вычисляется **программно внутри существующего direct-контура** (расширение A1-координатора), **не** отдельным LLM-вызовом и **не** полем Stage-1 JSON. Модельный выбор инструментов (`tool_choice='auto'`) сохраняется.
- **Почему не «модель предлагает `action` в Stage-1 JSON»:** Stage-1 System 2 физически запускается **только** на ходах с реально вызванными инструментами (`direct_chat_service.py:1037–1043`); первичные §42/§45-кейсы («АХАХА» после изображения, не-адресованное сообщение) происходят на ходах **без** инструментов, где Stage-1 вообще нет. Кроме того, «решить молчание» через генерацию текста противоречит §46/инварианту 13, а такое поле дублировало бы A1-слой и провоцировало дрейф канона (A1 D2 уже отклонил JSON-поле). **Отвергнутая альтернатива задокументирована (ADR D2).**
- **Двухфазное решение (без 3-го вызова):**
  - **Фаза P (до генерации текста):** детерминированная политика над сигналами §42–§45/§47 возвращает `silent` / `react` / `reply`. `silent`/`react` — короткое замыкание: **LLM-вызов вывода текста не выполняется**, Вербализатор не запускается; `reply` — продолжаем существующий путь.
  - **Фаза T (A1, после LLM/tool-loop):** существующий `_coordinator_choose_action` (`:579–591`) расширяется: если инструменты вызваны и финал не деградировал и не `lore_compiled` → `tool`; иначе `reply`. `tool` → существующий Stage-2 (Вербализатор) → итоговое `reply` (или `reply` с честной ошибкой при недоступности инструмента).
- **Инвариант 13:** ровно 2 физических LLM-вызова System 2 (`await_count==2`) на tool-ходе; на silent/react — **0** вызовов вывода текста; общее число LLM-вызовов не растёт.
- **Порядок встраивания:** Фаза P — после throttle/CB/dedup и после пре-гейтов dig/image (`:860–883`), **до** сборки system prompt/LLM (`:884–970`). Это позволяет короткое замыкание без реордера пре-гейтов и без текстовой генерации; при сработавшем пре-гейте (уже отправлен результат) политика не выбирает `silent`.

### 3.3. Политика §42–§45 (когда отвечать / реагировать / молчать) (REQ-A7-11…-21/-28; U-A7-10)
- **Детерминизм:** одинаковый вход → одинаковое решение; **никакой случайности** (§44/REQ-A7-19). Реакция — фиксированная 🗿 (U-A7-5, §3.6).
- **Классы сообщений (программно):** `explicit_request` (маркеры §43: «нарисуй», «фактчекни», «объясни», «что ты знаешь», «ответь в стиле», адресованность боту), `question` («?»/вопросительное намерение), `laughter` («АХАХА»/«Лол»/смех), `emoji_only`, `acknowledgement` («Ок»/«Понял»/«Спасибо»/короткое одобрение), `other`.
- **Приоритет (сверху вниз; первое совпадение выигрывает) — реальные задачи всегда перевешивают:**

| # | Условие | `action` | `reason_code` |
|---|---|---|---|
| 0 | kill-switch OFF | A1-baseline (`tool`/`reply`) | `disabled` |
| 1 | explicit_request / §43-маркер / адресовано боту | `reply` (или `tool` при выборе инструмента) | `explicit_request` |
| 2 | question (в т.ч. «Почему?») | `reply` | `question` |
| 3 | сработал image/dig-пре-гейт (результат уже отправлен) | `reply`/`tool` | `tool_result` |
| 4 | ожидается результат инструмента (пост-tool) | `reply` (итог/ошибка) | `tool_result`/`tool_unavailable` |
| 5 | reply на **собственное** изображение бота + короткая/смех/эмодзи-реакция + toggle (в) | `react` | `image_reaction`/`laughter` |
| 6 | emotional short (смех/одобрение/эмодзи) без ожидания контента + toggle (в) | `react` | `laughter`/`emotion`/`emoji_reaction` |
| 7 | acknowledgement («Ок»/«Понял»/«Спасибо») + ignore-toggle (в) | `silent` (или `react` при react-toggle) | `acknowledgement` |
| 8 | не адресовано боту (§45) | `silent` | `not_addressed` |
| 9 | диалог завершён / бот недавно ответил, продолжение не нужно | `silent` | `dialogue_completed`/`recent_reply` |
| 10 | иначе | `reply` | `default` |
| — | fail-safe (ошибка политики) | `reply` | `error` |

- **«Нет жёсткого правила короткое → silent»** (§42/REQ-A7-12): длина **не** является решающим признаком; решают класс (question/explicit) и контекст §47. «Почему?» → `question` → `reply`.
- **«Реальные задачи не теряются»** (§43/REQ-A7-14/-15): explicit_request/question **никогда** не `silent`; проверяется adversarial-тестами.
- **«Не на каждое сообщение» + контекст** (§44/REQ-A7-18): `react` выбирается только для эмоционально-реактивного класса в соответствующем контексте; не является универсальным ответом.
- **«Бот не полностью пассивен»** (§45/REQ-A7-21): `silent` — только для не-адресованных/тривиальных/завершённых; автономная активность (вне direct-сообщений) не затрагивается (U-A7-12).

### 3.4. Порядок исполнения §46 (REQ-A7-07/-22/-23/-24/-25/-26)
- **`silent`:** Вербализатор не запускается; сообщение не отправляется; на tool-ходе `await_count` не растёт; пустой текст не генерируется «на удаление».
- **`react`:** Вербализатор не запускается, если реакция выбрана и текст не нужен; исполнение реакции — через **существующий** примитив (см. §3.6), без нового механизма; текст не генерируется.
- **`reply`:** выбирается стиль (`style`; на tool-пути — из Stage-1 `response_mode`, как сегодня; на простом пути — существующая доставка модельного текста); Вербализатор — на tool-пути (Stage-2, как сегодня). Нового LLM-вызова не добавляется.
- **`tool`:** выполняются необходимые инструменты (существующий `tool_loop`, не переписывается); затем определяется **итоговое** действие (§46): успех + нужен текст → `reply`; недоступность/ошибка при ожидании результата → `reply` с честной ошибкой (`tool_unavailable`).
- **Существующий safety-net не ломается:** пустой ответ модели → существующий `react_moai`-фолбэк (`direct_chat_service.py:1004–1008,1061–1070`) остаётся **ниже** слоя решения (срабатывает только на reply-ветке, когда текст пуст). Legacy-путь OFF остаётся байт-в-байт.

### 3.5. Контекст предыдущих действий §47 (REQ-A7-13/-20/-27/-28; U-A7-7)
- **Источники (все — существующие, без нового хранилища):**
  1. **Текущий `reply_to`** — `message.reply_to_message`: id/автор; если автор — бот, классифицируем сообщение бота.
  2. **`bot_replies`** — `remember_bot_reply`/`get_bot_reply`/`get_bot_reply_parent` (`:726–764`): текст/наличие последнего ответа бота, parent-линк (тред), «бот недавно ответил».
  3. **Признак изображения** — replied-сообщение бота = фото/медиа **или** маркер image-пре-гейта (A3 `image_request_handled`/`image_pre_gate_fired`).
  4. **Признак статьи** — replied-сообщение бота похоже на пересказ/ссылку (существующие маркеры), результат `fetch_article` (A2-envelope).
  5. **Наличие вопроса** — «?»/вопросительная конструкция; намерение A1 `INTENT_QUESTION` (`:526–538`).
  6. **Ожидание результата инструмента** — пост-LLM `tool_trace`/`ToolLoopResult` (A1/A2), `degraded`; pre-LLM — эвристика по replied-сообщению бота-результата.
  7. **Маркеры A1** — `intent`/`addressee` (`_coordinator_intent/_addressee`), `lore_compiled`.
- **Наблюдаемость:** выбранный контекст-признак отражается в `reason_code` (R17-safe), без сырого текста.
- **§47-пример:** изображение бота + «АХАХА» → `image_reaction`/`not_addressed` → `react`/`silent`, не анализ; «А почему у него шесть пальцев?» → `question` → `reply`.

### 3.6. Источник реакции + граница A8 (U-A7-3/U-A7-5; REQ-A7-17/-18/-19)
- **A7-решение:** при `action=react` `reaction` = фиксированная **🗿** (`REACTION_MOAI`); `target_message_id` = id **trigger-сообщения пользователя** (не `reply_to_id` и не id предыдущего сообщения бота — §41 предупреждает о путанице; правило цели = A7).
- **Исполнение:** A7 **переиспользует существующий** примитив `smartmodule_utils.react_moai` (`:93–107`) как best-effort исполнитель. A7 **не реализует** новый механизм `setMessageReaction`; полная §41-механика (доступность реакции в чате, разрешённая альтернатива/отказ, устойчивость к неверному сообщению, «не превращать ошибку в длинный текст») — **A8**.
- **Fallback:** недоступная реакция → `react_moai` уже fail-silently (WARNING, без текста); политика §44/§45 **не** заменяет ошибку реакции длинным ответом (REQ-A7-16/-34); при полном отказе — эффект = молчание (не текст). Альтернативное поведение (skip vs reply) при недоступности — **A8**.
- **§44 «не использовать одинаковую реакцию в любой ситуации»:** на уровне A7 гарантируется тем, что `react` **не** является универсальным исходом (политика §3.3) и контекстно-обусловлен; разнообразие эмодзи/выбор по контексту через доступный набор — §41/дальняя волна (контекстная реакция). **Интерпретация зафиксирована в ADR D5; не ослабляет §44**, т.к. «одинаковая» относится к политике (не реакция на всё), а не к одному разрешённому примитиву.
- **Note для @PM:** формулировка `tasks.md` T-3654/§18 («без вызова `setMessageReaction`») уточняется: A7 не реализует **новый** механизм и **не вызывает** `setMessageReaction` напрямую, но переиспользует существующий `react_moai` как исполнитель решения. Реконсиляция — на T-3650.

### 3.7. Настройки §48 + санкция Δ каталога (REQ-A7-29…-32; U-A7-4)
- **Маршрут:** «Модули → Ответы в чате → Принятие решений» = новая секция (группа) внутри `mod_direct` (`web/app.js:489–494` карточка «Ответы в чате»; `WORKSPACE_TABS.mod_direct:573`).
- **Ровно 3 параметра** (категория `flags`, per-chat-совместимые, default **ON**):
  1. `CHAT_DECISION_IGNORE_TRIVIAL_ENABLED` — «Игнорировать незначимые обращения»: «Позволяет боту не отвечать на сообщения, которые не требуют продолжения разговора».
  2. `CHAT_DECISION_REACTIONS_ENABLED` — «Использовать реакции вместо ответа»: «Бот может поставить реакцию, если полноценный текст не нужен».
  3. `CHAT_DECISION_IMAGE_REACTIONS_ENABLED` — «Реакции на короткие ответы к собственным изображениям»: «Позволяет использовать реакции или молчание вместо развёрнутого ответа».
- **Новая группа:** `GroupSpec("flags_decision_making", "flags", "Принятие решений", <описание>, <order>)`, добавленная в правило `TAB_MOD_DIRECT` (`param_catalog.py:2149–2156`). **Новых вкладок/TAB_RULES-записей нет.**
- **Минимум параметров:** ровно 3; «десятки коэффициентов» запрещены (§48/REQ-A7-31). Новые — только после отдельного исследования/санкции.
- **Global/local reuse:** категория `flags` → `per_chat == True`; резолв `get_chat_param(chat_id, "flags.…", hot.get(...))` (override→global→default), как A1/A5/A6. Один параметр — один источник (§50); дублирования в независимых формах нет.

### 3.8. Сосуществование с `CHAT_SILENCE_*` и legacy-фолбэком (U-A7-6)
- **`CHAT_SILENCE_ENABLED`/`CHAT_SILENCE_AFTER_COOLDOWNS`** (`param_catalog.py:846/:1251`; троттлинг-путь `:782–793`) — **не трогаются**: это молчание по **стаку кулдаунов** (анти-абьюз), а не по контенту. Условия **не пересекаются** с политикой A7 (та работает только для допущенных сообщений) → **двойного молчания нет**.
- **Precedence:** (1) throttle/CB/кулдаун-стак — как сегодня; (2) допущено → решение A7 (OFF → A1-baseline); (3) `silent`/`react` → короткое замыкание; (4) `reply` → существующий путь, где legacy пустой-reply → `react_moai` (`:1061–1070`) и провайдер-пустой → `react_moai` (`:1004–1008`) остаются **safety-net ниже** слоя решения. `CHAT_SILENCE_*` **не поглощается** — остаётся как есть (вход-сигнал/защита).
- **Нет регресса существующих пользователей:** при OFF kill-switch — точный A1/legacy; при ON и выключенных 3 тумблерах — фактически A1-baseline; двойной реакции нет (реакция — только из ветки решения либо safety-net при пустом тексте, не оба).

### 3.9. `reason_code` — закрытый R17-safe словарь + логи (U-A7-10; REQ-A7-09/-18/-34)
- **Enum (закрытый, R17-safe; только идентификаторы):**
  `explicit_request`, `question`, `image_reaction`, `laughter`, `emotion`, `acknowledgement`, `emoji_reaction`, `not_addressed`, `dialogue_completed`, `recent_reply`, `tool_result`, `tool_unavailable`, `disabled`, `default`, `error`.
- **Логи:** расширение существующих A1-логов (`_log_coordinator_decision/_log_coordinator_outcome`, `:626–643`) полями `reason_code`/`target_id`/`needs_tools`/`reaction` — только id/enum/числа/длины. **Никогда:** текст сообщений/имена/ключи/промпты/сырой контекст (R17). По логам однозначно видно, **почему** бот промолчал/ответил/вызвал инструмент (§53).
- **Служебный JSON не в чат** (REQ-A7-10).

### 3.10. Scope U-A7-12 + сохранение автономной активности
- **Scope:** **только direct-чат** (зависимость A1: `CoordinatorDecision` живёт в `direct_chat_service.py`; §38 говорит о расширении существующего механизма ответов direct-чата). ## 6. Feature contract

**Preconditions:**
- direct-чат сконфигурирован; `SYSTEM2_DIRECT_ENABLED` (при наличии) и `DIRECT_COORDINATOR_ENABLED` (A1) — как сегодня; `DIRECT_DECISION_MAKING_ENABLED` (A7, env-only) ON.
- Существующие сервисы доступны: `tool_router`/`tool_loop` (A1/A2, не переписываются), `react_moai`, `bot_replies`/`get_bot_reply_parent`, `get_chat_param`/`hot`.
- Канон `TOOL_CALLING_TOOLS == 12` без изменений; `json`-схемы инструментов не меняются.
- Вычисления политики — **чистые/детерминированные**, без сети; чтения контекста — существующие, fail-open.

**Invariants:** §5 (15). Дополнительно: ровно 2 физических LLM-вызова System 2 на tool-ходе (`await_count==2`); 0 LLM-вызовов вывода текста на `silent`/`react`; OFF kill-switch → A1-baseline байт-в-байт по поведению.

**Inputs/Outputs:**
- **Вход:** `message` (текст/`reply_to_message`), `user_id`, `chat_id`, маркеры A1 (intent/addressee/tool_trace), контекст §47, 3 тумблера §48, kill-switch.
- **Выход:** расширенный `CoordinatorDecision` → исполнение: `silent` (0 отправок), `react` (реакция 🗿 на trigger через существующий `react_moai`), `reply` (существующая доставка/Stage-2), `tool` (существующий tool-loop → итоговое действие) + R17-safe лог. **Второго пайплайна/канала нет.**
- **Контракты:** `CoordinatorDecision` — аддитивно расширяется; `ToolLoopResult`/envelope (A2), `ImageRequest` (A3/A4), `get_user_context` (A6) — reuse, не меняются; Stage-1/Stage-2 JSON — **не меняются**.

**Failure semantics (fail-safe):**
- Ошибка политики/контекста → `reply` (`error`), никогда не ложное молчание; политика не бросает.
- Недоступность `bot_replies`/контекста → консервативно `reply`.
- Недоступный инструмент → `reply` с честной ошибкой (`tool_unavailable`).
- Реакция недоступна → fail-silently (без длинного текста).
- Kill-switch OFF → A1-baseline.

**Compatibility:** OFF-паритет; A2/A3/A4/A5/A6-контракты не затрагиваются; `CHAT_SILENCE_*`/dedup/throttle/CB-пути не изменяются; простой direct-путь без триггеров политики — без изменений при OFF/тумблерах-OFF.

**Observability (R17):** §3.9 — только id/enum/числа/длины; без текстов/имён/ключей; система событий/ExecutionGraph не создаётся (граница A9).

## 13. Risk-Level и усиление

- **Risk-Level: R3.** Обоснование: A7 меняет **кор-поведение живого direct-чата** (когда бот отвечает/молчит/реагирует) для каждого диалога; **AMEND-ит `physical-two-call-pipeline`** (порядок/ветвление существующих вызовов); трогает **каталожно-UI-модель** (+3 параметра/+1 группа, переиздание F8). Blast radius широкий; ошибка политики приводит к **ложному молчанию** (потеря реальной задачи) или **ложному ответу** (лишний вызов/пустой текст) на живых пользователях.
- **Что повысит/удержит R3 (Reviewer-триггеры):** потеря explicit-обращения/вопроса; `silent`/`react` запускают Вербализатор; рост LLM-вызовов; `style=silent`; утечка служебного JSON/приватного контента в логи (R17); регресс существующих инструментов; отсутствие OFF-паритета; выход за санкционированный Δ каталога; переписывание A1/A2/A3/A4/A5/A6-контрактов; изменение §41-механики.
- **Усиленные требования (обязательны для R3):**
  1. **`threat-failure-analysis.md`** (threat→mechanism→code→test): ложное молчание, ложный ответ/лишний вызов, неверная цель реакции, `style=silent`, утечка JSON/приватного контента в логи, регрессия инструментов, недоступный инструмент/реакция, OFF-паритет; создаёт **@Builder** (T-3661).
