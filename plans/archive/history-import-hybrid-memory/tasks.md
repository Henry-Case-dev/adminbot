Окончательный выбор охвата — до старта FTS-импорта на проде (письменно юзеру, G5); CLI обязан принимать явный `--files` (без дефолта «всё вслепую»).
- **Код импорта — новый пакет `tools/history_import/`** (parser, loader, checkpoints, промпт-константы, llm-клиент-помощник) + корневой `manage.py` (argparse-диспетчер, подкоманда `import_history`). Только stdout-логи (как у существующих scripts/), без запуска бота. Общий для серверного FTS-этапа и локального graph-этапа.
- **Парсер строго потоковый (ijson)** — серверная RAM 961 МБ, json.load 480МБ-файла недопустим; файлы pretty-printed (построчный парсинг исключён). ijson в requirements. Устойчивость: на битую запись — счётчик ошибок + пропуск (fail-continue), отчёт.
- **tg_message_id/дедуп (Q4):** экспортные id отрицательны/коллизятся между файлами → собственный ключ импорта. База: `import_key = sha256("{timestamp}|{user_id}|{text}")` — хеш-префикс 32 hex, ПОЛНАЯ коллизия практически исключена; порядок файлов «свежий первым» (2026.json → 10.08.2025.json → 10.2024.json → желтая) + INSERT OR IGNORE = приоритет свежему экспорту на пересечении. Хранение ключа для идемпотентности: **миграция v7 добавляет `smart_messages.import_key TEXT` + частичный UNIQUE-индекс `idx_smart_messages_import_key ON smart_messages(import_key) WHERE import_key IS NOT NULL`** (проверено: UNIQUE-ограничений на smart_messages нет; колонка nullable — live-строки бота не затронуты; повторный запуск идемпотентен, `INSERT OR IGNORE`). Alternative — чекпоинты per-file (всё равно нужны для resume): `import_checkpoints (path, processed, total, done)` — аддитивная таблица (CREATE IF NOT EXISTS в цепочке initialize, БЕЗ user_version — прецедент smart_cache R51-5) + локальный side-файл чекпоинта не нужен.
- **FTS-синхронизация при импорте:** построчно в одной транзакции на батч (500–1000) вместе с INSERT smart_messages — внешний content, триггеров нет. Последующий `--rebuild-fts` НЕ нужен (строки с пустым text в FTS не попадают — как save_smart_message). После импорта — `VACUUM` (сжатие) + `PRAGMA wal_checkpoint(TRUNCATE)`.
- **Маппинг записи:** type!='message' → отсев; пустой text БЕЗ медиа → отсев; text список/объекты → join по `text_entities`/склейка кусков; `date_unixtime` (str) → int timestamp; `from_id` `user<id>` → int user_id, `channel<id>`/прочие → user_id NULL (сообщения каналов-постингов); `from` → author_name (как есть; alias-резолв A8 к живым юзерам НЕ делаем — история); медиа-поле (photo/video/animation/voice/video_note/document/sticker/…) → media_type (иначе 'text'); `forwarded_from`/`forward_from` → is_forward=1 + forward_source (текст источника, если есть); `reply_to_message_id` → reply_to_id (опционально, экспортные id отрицательны — только информационно). Сообщения с медиа и без подписи — сохранять (text NULL), отсеву не подлежат.
- **Эмбеддинги graph-этапа: канал (а) — API gemini-embedding-001 dim 3072 через `LLMClient.embed`** (бесшовно в существующие `graph_facts_vec` float+int8, код vec-записи уже есть — `MemoryManager._save_graph_fact_embedding`, summary_memory.py:1475); локальные Ollama-эмбеддинги (б) и int8-only (в) — отклонены как основной путь (новая vec0-таблица другой dim = второй KNN-путь/дорого; int8-only = потеря точности) — Q2 подтверждает @Architect. Оценка стоимости API: ~300k фактов × ~40 токенов ≈ 12M токенов ≈ $4–10 (gemini-embedding ~$0.3/1M). Ретраи/кэш: переиспользовать `_embed_cache_*`/ретраи (прецедент _EMBED_RETRY_ATTEMPTS). При недоступности API-embed на этапе: факты сохраняются текстом+FTS (деградация как в бою: «факт остаётся ТЕКСТОМ», summary_memory.py:1223-1235), vec доберётся backfill-фоном на проде.
- **graph_facts для истории — новый origin `history_import`** (отдельный от chat_history: свой вес/семантика, не задевает существующие механизмы); **миграция v7** (Q3): rebuild graph_facts по D201-паттерну (v5 :465-510): + колонка `message_timestamp INTEGER` (nullable), CHECK-список через единый `_GRAPH_FACT_ORIGINS_SQL` += `'history_import'`, все существующие колонки сохраняются; backfill `UPDATE graph_facts SET message_timestamp = created_at` (существующие факты: дата-рендер не меняется — COALESCE); user_version=7.
