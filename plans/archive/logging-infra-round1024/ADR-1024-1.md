# ADR-1024-1 — Единое R17-safe логирование внешних API и фоновых пайплайнов

- **Статус:** **Accepted** (Step 2 @Architect, часть 1/2 раунда 10.24, 19.09.2026)
- **Фича:** F2 `logging-infra-round1024`
- **Тип:** backend-инфраструктура (helper + точки внедрения)
- **Связано:** ADR-1013-3 (канон-атомарность — не затрагивается), ADR-1023-5 (секрет только env/PG), `round1024-architecture.md` §3.1/§3.4, F1/F7/F8/F12 (потребители)
- **Задачи:** T-2196…T-2204

## Context

1. Владелец зафиксировал принцип: **«тихий откат для конечного пользователя ≠ тишина в серверных логах»** (UPD2 п.11). Сейчас `image_generation` логирует только R17-safe код (`_reason_from_status`), без тела ответа провайдера; крон анти-клише пишет лишь имя класса/статус; пайплайн Экстрактора не имеет сквозной трассировки этапов. Дебаг п.0/п.5/п.6/п.10 упирается в «тихий откат».
2. В репозитории уже есть сильный R17-механизм: `services/log_ring.py::sanitize` (Bearer, `sk-`/`gsk_`/`or-`/`tvly-`-префиксы, URI-креды, литеральные секреты каталога) и `SecretMaskFilter` на консольном хендлере. Дублировать маскировку нельзя — её надо переиспользовать.
3. Egress-сканер секретов (`tests/`, паттерны R17/R18) должен остаться зелёным: любое тело внешнего API обязано быть усечённым и обезвреженным.
4. Три подсистемы (image / cron клише / extractor) плюс embed/graph пишут разнобойным форматом; поддержка/алерты не могут грепать единый признак.

## Decision

### D1. Новый helper `services/external_log.py` — единственная точка лога внешних API
- `log_external_api(logger, *, provider, method, url, status, reason, body, duration_ms, attempt, level)` — одна структурированная строка с `event=ext_api`.
- `trace_step(logger, *, component, step, status, reason, chat_id, extra, level)` — `event=pipeline_step` (Сон/крон/граф).
- `log_dropped(logger, *, component, reason, count, chat_id, extra)` — `event=dropped_metric` (потеря данных видима и считается).
- `redact_url(url, *, keep_query=False)` — убирает `://user:pass@` и query; `keep_query=True` маскирует только секрето-подобные параметры.
- `safe_text(text, *, limit=None)` — `log_ring.sanitize` + схлопывание пробелов + обрезка до `EXTERNAL_API_LOG_BODY_CHARS`.

### D2. Секреты — только через существующий `sanitize`, никогда «ручной» строкой
- Хелпер НЕ изобретает маскировку: `safe_text` делегирует `log_ring.sanitize`.
- URL в лог попадает **без query/userinfo** по умолчанию (`EXTERNAL_API_LOG_URL_QUERY=False`).
- Ключи/токены как аргументы хелперу не передаются вообще (wire-контракт: helper принимает только `provider/status/reason/body` — без auth).

### D3. Контроль объёма — усечение и уровни
- Тело внешнего ответа ≤ `EXTERNAL_API_LOG_BODY_CHARS` (env-only `ClassVar`, default **1024**).
- Уровни: нормальный 2xx → `INFO`; ожидаемый fallback/деградация → `WARNING`; реальный сбой/потеря → `ERROR`.
- Известный несовместимый primary embed (шум 400) → **WARNING + один раз конфигурация**, без ключей (согласовано с UPD3 п.7: код embed не меняется, поведение лога — только наблюдательное).

### D4. Kill-switch
- `EXTERNAL_API_LOGGING_ENABLED` (env-only `ClassVar`, default **ON**). OFF → хелпер не печатает тело/URL, но сохраняет краткую строку `status/reason` — наблюдаемость не теряется полностью.
- Δ каталога = 0, Δ DDL = 0.

### D5. Точки внедрения (обязательный минимум)
- image-провайдер (POST/GET/download) — статус + тело;
- крон анти-клише — фаза (`fetch|llm|parse|empty|write`), `next_run_time`, `exc_info`;
- Сон/Экстрактор — сквозная трассировка этапов с `chat_id`, без сырых текстов;
- graph-extract — тип исключения/число чанков (потребляет F1);
- embed/chat 4xx — выравнивание формата (без изменения логики).

## Consequences

**Positive**
- Любой сбой из п.0/п.5/п.6/п.10 диагностируем: причина + тело (усечённое) в логе.
- R17 сохраняется за счёт переиспользования `sanitize`; egress-сканер не ломается.
- Единый формат `event=` пригоден для алертов (Betterstack) и для отчётов DevOps.
- Δ DDL = 0, Δ каталога = 0.

**Negative**
- Логи становятся объёмнее → митигируется лимитом тела и уровнями; согласовано с retention F9 (логи 7 дней).
- Появляется риск «случайно передать секрет в `body`» → тест на маскирование + запрет передачи auth-аргументов.

## Alternatives

- **A1. Логировать полный `resp.text` без лимита** — **отклонено**: раздувание journald + риск утечки.
- **A2. Своя маскировка внутри хелпера** — **отклонено**: дублирование R17-логики, расхождение с `log_ring`.
- **A3. Логировать сырые тексты сообщений для трассировки Экстрактора** — **отклонено**: нарушает приватность (R17).
- **A4. Оставить разнобойные вызовы `logger.*` по местам** — **отклонено**: нет единого греп-признака, дебаг не масштабируется.
- **A5. Хранить метрики сбоев в PG-таблице** — **отклонено** в этом раунде: Δ DDL; достаточно лог-событие + in-process счётчик.
