## 4. Наблюдаемое поведение и режимы

### 4.1. Главный поток
```
document.body
├── #polygon-background    (canvas; fixed; inset:0; pointer-events:none; z-index:0)
└── #app                   (Vue-приложение, выше по DOM/стекингу)
```
Анимация целиком живёт в `polygon-background.js`. Vue управляет **только жизненным циклом** сцены (`start/stop/pause/resume/resize`) через уже существующие вызовы `app.js`. Координаты точек **не** проходят через Vue reactivity.

### 4.2. Матрица режимов (ровно один активный рендерер)
| `UI_POLYGON_BG_ENABLED` | `UI_AURORA_FLOW_V2` | Активный рендерер | Класс на `<html>` | Legacy-слои |
|---|---|---|---|---|
| **ON (default)** | (не важно) | **Polygon Canvas 2D** | `polygon-bg` | скрыты (`polygon-bg` гасит `.aurora-bg`/`body::before/after`) |
| OFF | ON | Aurora (OGL) | `aurora-flow-v2` | скрыты |
| OFF | OFF | legacy CSS-aurora | (нет) | `.aurora-bg` видим |
| OFF | OFF + `UI_AURORA_BG_ENABLED=OFF` | legacy page-wash | `bg-wash-legacy` | `body::before` |

Флаги **независимы** (env-only, soft-откат без редеплоя). Комбинации выше — единственные допустимые; одновременный запуск двух сцен — нарушение (SC-07).

### 4.3. Внешние режимы
- **`document.hidden`** → `pause()` (rAF отменён); возврат → `resume()` (без сброса seed).
- **`prefers-reduced-motion: reduce`** → один качественный статичный кадр (геометрия и свечение сохранены, движение выключено); rAF не запускается. CSS `html.lg-bg-paused` совместим.
- **Canvas 2D недоступен / `lost`** → честный фолбэк: `renderer='none'`, canvas скрыт, `html.polygon-bg` снимается → активным остаётся legacy-путь (`bg-wash-legacy`). Сцена не «замирает» белым экраном.
- **Delaunator не загрузился** (CSP/сбой vendor) → `renderer='none'`, тот же честный фолбэк; патч незаметен как «пустой фон».

## 5. Контракт модуля `web/static/polygon-background.js` (D4)

IIFE, CSP-safe (same-origin, без инлайна/eval), **без** Vue-зависимостей. Публичный API:

```js
window.__PolygonBackground = {
  start(),            // создать/поднять canvas, инициализировать сцену, запустить rAF
  stop(),             // остановить rAF, снять canvas из DOM, освободить буферы
  pause(),            // остановить rAF, сохранить состояние и canvas
  resume(),           // возобновить rAF без пересоздания сцены/сброса seed
  resize(),           // пересчёт CSS-размера + drawing buffer + scale + composition (без скачка)
  getDiagnostics(),   // см. §14 (не в UI)
  mode()              // 'canvas2d' | 'none'
};
```

**Адаптер совместимости** (T-3171): при загрузке модуль сохраняет легаси-ссылку и подменяет публичный символ:
```js
window.__AuroraFlowLegacy = window.__AuroraFlow;   // если был (aurora-flow.js)
window.__AuroraFlow = { start, stop, resize, setPaused(p){p?pause():resume();}, sample(), mode };
```
`app.js` продолжает вызывать `window.__AuroraFlow.*` без переписывания. `sample()` — 8×8 сетка RGB из фактического canvas (совместимо с матрицей/тестами).

**Все методы идемпотентны и безопасны без canvas** (аналог `__AuroraFlow.resize` no-op).

**Детерминизм:** сцена строится из **фиксированного seed** (константа модуля, напр. `SEED = 20260923`), собственный детерминированный ГПСЧ (mulberry32/xorshift). `Math.random()` в построении сцены и топологии **запрещён**. `resize()` **не** сбрасывает seed: базовые позиции хранятся в нормализованном пространстве `[0..1]`, а в пиксели пересчитываются на каждом resize → масштабирование без «новой композиции».

## 6. Единственный активный рендерер, отсутствие конкурирующих rAF (D1/D4)

- `app.js::_syncBgLayer` получает computed `polygonBgEnabled` и:
  1. переключает `html.polygon-bg`;
  2. при ON — `__PolygonBackground.start()`, **легаси Aurora не запускается** (`__AuroraFlowLegacy.stop()`);
  3. при OFF — `__PolygonBackground.stop()` (canvas снят из DOM), затем легаси-путь по матрице §4.2.
- `stop()` Polygonal **обязан**: отменить `requestAnimationFrame`, снять canvas из DOM, отключить `ResizeObserver`, обнулить ссылки на буферы. В DOM не остаётся «невидимо анимирующейся» сцены.
- `aurora-flow.js`: **SUPERSEDE как активный рендерер** — файл **сохраняется** (откат), в DOM не поднимается при ON; его canvas создаётся только при явном `__AuroraFlowLegacy.start()`.
- **Один WebGL-контекст в активном режиме:** Polygon — Canvas 2D (WebGL не поднимает); OGL-Aurora при ON не запускается. Единственный WebGL-контекст возможен у стекла (`mountGlass(..., {mode:'webgl'})`) — конфликта с OGL нет, т.к. OGL в этом режиме не активен (SC-31).

## 8. Canvas, resize, fullscreen/TMA (D5)

- **Один** видимый canvas `id="polygon-background"`, класс `.polygon-background-canvas`, прямой потомок `document.body` (первым), вне max-width-контейнеров. CSS: `position:fixed; inset:0; width:100%; height:100%; pointer-events:none; display:block; z-index:0`. **Не** помещать в `.module-list`/`.module-catalog`/`.scroll-area`/карточку. Отрицательный z-index **не** использовать (риск «исчезновения» за заливкой `body`).
- **Порядок слоёв:** фон (canvas, z-index:0) → графит shell → рабочая поверхность (`--work-surface-bg`) → карточки → модалки. `#app` выше по DOM/стекингу.
- **resize (без скачка):** получить фактический размер контейнера (`documentElement.clientWidth/Height` — та же `measure()`-семантика, что в `aurora-flow.js`); выставить CSS-размер; `canvas.width/height = round(w*dpr), round(h*dpr)`; `ctx.setTransform(dpr,0,0,dpr,0,0)`; пересчитать композицию из нормализованного состояния. Старая ширина после fullscreen не используется.
- **Переиспользование viewport-адаптера:** `polygon.resize()` вызывается из **тех же** точек, что и `_auroraResize()` (`_onResize`, `setFullscreenFromTma`, `visualViewport`/`_onVV`, опц. `ResizeObserver(documentElement)`). **Второго** механизма расчёта высоты/`--app-usable-height` не создаётся. `telegram-init.js` **не** переписывается.
- **Без левой полосы/сдвига:** canvas не входит в контейнеры с `max-width`; ширина Sidebar **не** вычитается из композиции; центр композиции не привязан к Sidebar.
- **DPR-кап:** desktop ≤ 2, mobile ≤ 1.5.

## 9. Геометрия, seed, триангуляция, фильтр, топология (D7)

**Узлы (§6.1, обязательные ориентиры):** desktop **90–140** (цель ~110), mobile **45–75** (цель ~55). Неравномерная плотность: кластеры + разреженные области; **не** равномерная сетка. Число узлов/треугольников фиксировано для вьюпорта (mobile — меньше).

**Seed:** фиксированный (см. §5). На каждом кадре сцена **не** пересоздаётся.

**Триангуляция (§6.2):** `Delaunator.from(points)` → `triangulation.triangles` (тройки индексов → грани). Не соединять всё со всем.

**Фильтр треугольников (§6.3):** учитывать длину ребра, площадь, принадлежность цветовому кластеру, расстояние до световых центров. Большие — почти прозрачные, часть мелких — насыщеннее. Запрещены длинные линии через весь viewport и плотная диагональная решётка.

**Топология (§6.4):** пересчёт **с ограниченной частотой (≤ 4 Гц)**, не каждый кадр; короткое плавное смешивание при смене топологии; без резких скачков форм.

**Композиция (§4, обязательна):**
- Зона A — глубокое индиговое пространство (подложка, глубина, умеренные тонкие линии, мелкие узлы).
- Зона B — сиреневое облако (lilac/lavender/violet/magenta-violet), преимущественно слева-сверху и центр; мягче и прозрачнее.
- Зона C — цианово-голубой кристаллический кластер (electric blue/cyan/ice blue/светло-сиреневый), справа/центр; самые яркие участки, часть граней почти белая.
- Зона D — соединительные нити (тонкие линии + мелкие узлы), **без** плотной паутины.

**Палитра (§5, единые константы, без разбросанных RGB):** `#090D17`, `#16125A`, `#3030C8`, `#355CFF`, `#7C3AED`, `#A78BFA`, `#C4B5FD`, `#C026D3`, `#42D6C4`, `#9AEAFF`, `#F2F7FF`. Сиреневые/лавандовые **заметно** присутствуют в гранях; яркость локальна, **не** равномерна по экрану.

## 10. Свет и bloom (D7)

- **Фоновое излучение (§7.1):** несколько локальных цветовых областей, привязанных к кластерам; мягкие радиальные градиенты. **Не** один blur на весь viewport.
- **Свечение граней (§7.2):** 3 прохода (полупрозрачная заливка → мягкая подсветка → локальные яркие акценты); `globalCompositeOperation` `screen`/`lighter` с контролем итоговой яркости; **без** «сплошного белого пятна».
- **Узлы (§7.3):** тиры «слабые / умеренные / яркие»; яркие — преимущественно в центрах кластеров; **не** все белые.
- **Линии (§7.4):** тонкие; glow **выборочно**, не на всех рёбрах.
- **Bloom (§7.5):** offscreen-canvas **уменьшенного разрешения** (mobile — ещё меньше) + мягкое размытие offscreen-слоя + композиция поверх; финальный canvas **не** размывается. **Запрещено** `filter: blur()` на полноэкранном canvas и на интерфейсе.

## 11. Переливы и движение (D7)

- **Цветовой morph (§8.1):** плавные переходы (Violet→Lilac→Ice Blue; Cyan→Electric Blue→Lavender); без резких/случайных цветов.
- **Дрейф световых центров (§8.2):** центры смещаются внутри своих кластеров; яркость грани — от расстояния до центра.
- **Импульсы (§8.3):** редкие плавные усиления на пересечениях; **без** стробоскопа и синхронной пульсации всей сети. **Уточнение времени (v2.58.20, owner):** «мерцание свечения» замедлено ровно ×2 — `PULSE_SPEED_MIN/MAX = 0.025/0.075` rad/s (§8.3) и `GLOW_SHIMMER_SPEED = 0.03` rad/s (§7.1, радиус фонового свечения); движение узлов §9, цветовой morph §8.1 и дрейф световых центров §8.2 **не** меняются. Дизайн не затронут.
- **Движение узлов (§9):** база + **амплитуда 4–18 CSS px** + индивидуальная фаза/скорость; различимо за **5–10 с**; детерминированная функция (не новая случайная координата на кадре).

## 13. Liquid Glass: прототип до интеграции (D6)

### 13.1. Изолированный прототип (обязательный гейт; gitignored `tools/`)
Harness в gitignored каталоге (`tools/_polygon_glass_prototype/`, по прецеденту `tools/_hotfix9_glass_probe/`): полигональный фон + **одна** стеклянная поверхность + линии/узел позади + текст и иконка поверх. **7 проверок (§12.2):**
1. Изображение за стеклом **действительно преломляется** (меняется содержимое позади, а не фильтрация своего декора).
2. Текст и иконка остаются **чёткими**.
3. Эффект **не** перекрывает содержимое кнопки.
4. **Нет** белого непрозрачного прямоугольника.
5. **Нет** яркого внешнего ореола вокруг поверхности.
6. **Нет** конфликта WebGL-контекстов с фоновым рендерером.
7. Производительность на мобильном приемлема.

### 13.2. Правило «до интеграции»
Прототип **не** переносится в основной интерфейс, пока не проходит все 7 проверок. При провале — эпик поставляет **только фон**; интеграция стекла не выполняется (честно фиксируется).

### 13.3. Источник преломления (обязательная корректность)
- Для анимированного фонового **canvas** использовать `mountGlass(root, { source: <#polygon-background>, mode: 'webgl' })` (единственный путь, дающий рефракцию анимированного canvas; SVG-путь над перерисовываемым canvas в Safari «выпадает» из фильтра — GOTCHAS 0.5.3).
- **Не повторять hotfix10/ADR-1025-18 D1:** `mountGlass` **никогда** не вызывается без предоставленного источника преломления (иначе авто-режим → frosted → белые прямоугольники). Если источник недоступен — режим честно `frosted`, **не** выдаётся за рефракцию (`glass.js::detectMode`).
- Монтировать **только** на изолированный `[data-glass-surface]`; `dispose` идемпотентно удаляет все `.ps-glass*` и `data-lg-*` (существующий `purge`/`clearAttrs`).

### 13.4. Точечное применение (§12.3/§12.4)
После гейта — **только**: селектор области, кнопка ⛶ (fullscreen), отдельные **декоративные** элементы Статуса. **Не** весь Sidebar-линза, **не** каждая карточка. Sidebar/Header остаются **графитовыми**, без фиолетового ореола и без компенсации яркости. `blur ≠ рефракция` (не выдавать). Прозрачность всех карточек ради фона **не** снижается. Параметры в интерфейсе остаются читаемыми.

## 14. Диагностика и автоматическая проверка (D8)

### 14.1. `getDiagnostics()` (не выводится в UI)
Возвращает: `renderer`, `canvasWidth`, `canvasHeight`, `devicePixelRatio`, `nodeCount`, `triangleCount`, `frameCount`, `lastFrameTime`, `isPaused`, `isReducedMotion`, `contextLost`.

### 14.2. Проверка движения (Playwright)
Фиксация состояния canvas на **0 / 5 / 10 / 20 с**; сравнение кадров: меняется **положение** части геометрических элементов, **не только** общая яркость; существуют реальные движущиеся световые области; анимация не останавливается после входа в fullscreen.

### 14.3. Проверка композиции (программно, не «Canvas в DOM»)
Подтвердить наличие: узлов, полигонов, линий, **сиреневой** цветовой области, **циановой** цветовой области, локальных ярких участков. Одного pixel-diff/наличия canvas **недостаточно** для вывода о качестве.

### 14.4. Материалы для визуальной проверки
Desktop-Статус, Desktop-Модули, Mobile-Статус, Mobile-Модули; normal + fullscreen; короткая видеозапись анимации; сравнение нового фона с предыдущей Aurora в одинаковых условиях.
