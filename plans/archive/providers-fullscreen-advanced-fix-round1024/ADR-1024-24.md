# ADR-1024-24 — TMA-fullscreen ↔ Vue sync + реактивный аккордеон (F24)

> **Статус:** proposed → Accepted (ожидает санкции владельца по O4 — AMEND 10.10; реализация на безопасном дефолте).
> **Фича:** `plans/features/providers-fullscreen-advanced-fix-round1024/` (раунд 10.24, UPD6).
> **Слой:** web (Vue in-DOM + интеграция Telegram WebApp). **Δ DDL = 0, Δ каталога = 0.**
> **AMEND:** решения раунда **10.10** (`plans/archive/admin-ui-round1010/spec.md:53`).

---

## Контекст

Владелец зафиксировал боевой дефект: в разделе **«Провайдеры»** (`llm_providers`) аккордеон **«Расширенные системные»** (advanced-настройки) **пропадает/схлопывается при переходе TMA в fullscreen** и не переживает ре-рендер/ремаунт.

Разведка (Step 2, @Architect; координаты сверены с `HEAD`) выявила **два независимых разрыва**:

1. **Разрыв «TMA-fullscreen ↔ Vue».** `isFullscreen` (`web/app.js:939`) инициализируется константой `false` и меняется только инверсией локального флага в `toggleFullscreen()` (`:3651-3665`). `Telegram.WebApp.isFullscreen` не читается; подписок на `fullscreenChanged`/`viewportChanged` нет (единственный `onEvent` — `'ready'`, `:1650-1651`). При входе в fullscreen нативной кнопкой Telegram Vue-состояние рассинхронизировано; `.fullscreen-mode` (`web/index.html:26`) не отражает факт.
2. **Нереактивный стейт аккордеона.** Биндинг `:open` (`web/index.html:526-527,559-562,804-806,1990-1992,2358-2360`) вызывает `expandOpen()` (`web/app.js:3768-3772`), которая читает `localStorage` на каждом рендере. Vue **не отслеживает** `localStorage` как реактивную зависимость. При пересоздании `<details>` (ремаунт/ре-рендер вкладки) `:open` берёт значение вне реактивной системы → схлопывание. Поле `data.expand` (`:831`) — мёртвое.

CSS ни при чём: `.fullscreen-mode` (`web/static/app.css:659-668,686-690`) меняет только height/overflow; скрытий (`:fullscreen`/`.tg-fullscreen`/`@media max-height`) нет.

**Конфликт с 10.10.** `plans/archive/admin-ui-round1010/spec.md:53` явно постановил: «JS не менять: `toggleFullscreen` остаётся оптимистичным локальным флагом; слушатель `fullscreenChanged`/`contentSafeAreaChanged` только опционально при live-лаге — не требуется по умолчанию». Живой дефект доказал недостаточность этого решения → требуется **AMEND**.

## Решение

### D1. Синхронизация fullscreen с TMA (источник истины — TMA)

- `initFullscreen()` — инициализация `isFullscreen` из `Telegram.WebApp.isFullscreen` (boolean); вызов в `mounted()` и в `onEvent('ready', …)` (контекст может появиться позже).
- Подписки `onEvent('fullscreenChanged')` и `onEvent('viewportChanged')` → `setFullscreenFromTma()` (берёт `WebApp.isFullscreen`; при отсутствии — no-op, не угадывать). Guard `_fsSubscribed` против двойных подписок.
- `teardownFullscreen()` в `beforeUnmount` — `offEvent` с теми же fn-ссылками (паттерн `_onVisibility`).
- `toggleFullscreen()` — user-action `requestFullscreen`/`exitFullscreen`; флаг берётся из фактического `isFullscreen`, а не «угадывается» (legacy-фолбэк — инверсия, только если SDK не отдаёт boolean).
- `safeAreaChanged` не подписываем: safe-area — CSS-переменные `--tg-*` (решение 10.10 CSS, `app.css:686-690`).

### D2. Реактивный стейт аккордеона

- Единственный источник рендера — реактивная карта `expand` (оживляем существующее `data.expand`, `web/app.js:831`); `localStorage` — **персист**, а не источник рендера.
- `initExpandState()` в `created()` — однократный скан `localStorage` по префиксу `adminbot.expand:` → `expand[key] = true` (try/catch). Ключи `_expandKey` (`:785-787`) не меняются (обратная совместимость формата).
- Рендер-доступ — через **computed** (реактивные значения, без вызова state-функций в шаблоне): `advancedOpen`, `chatLoreAdvancedOpen`, `provAdvancedOpen`.
- `expandOpen(tabId, scope)` сохраняется как метод (JS-юниты), но читает реактивное `this.expand`.

### D3. `toggleExpand` синхронизирует, а не инвертирует

`toggleExpand(tabId, scope, ev)`: при наличии `ev.target.open` (boolean) берёт факт DOM; иначе (legacy/юнит без события) инвертирует. Пишет реактивно (`this.expand[key]`) **и** в `localStorage`.
**Причина:** `@toggle` срабатывает и при программной установке `open` из Vue; при общих bare-ключах (несколько `details` на вкладке делят `adminbot.expand:<tab>`) инверсия вызвала бы осцилляцию. Синхронизация идемпотентна.

### D4. Скоуп — все `details.advanced` с биндингом

Единый механизм для 5 зон (`index.html:526-527,559-562,804-806,1990-1992,2358-2360`); раздельные `scope`-ключи сохраняются. Lightweight `<details>` `:1040-1062` (без `advanced`-класса и без персиста) — вне скоупа (не менять поведение).

### D5. Флаг / откат

Продуктовый флаг **не вводим** (клиентский багфикс; тумблер лишь вернул бы баг). Раскатка обычная; откат — `git revert` + синхронный cache-bust (`APP_VERSION`/`?v=`).

## AMEND 10.10 (явно)

AMEND отменяет в части JS-fullscreen тезис `plans/archive/admin-ui-round1010/spec.md:53`:

> «JS не менять: `toggleFullscreen` остаётся оптимистичным локальным флагом; слушатель `fullscreenChanged` … не требуется по умолчанию».

**Отменяется:** запрет на изменение JS и отказ от подписки на события TMA.
**Остаётся в силе из 10.10:** CSS-подход safe-area (`app.css:686-690`), модель скролла `.fullscreen-mode .scroll-area` (`app.css:659-668`), `max(env, --tg-*)` для шапки; `safeAreaChanged` в JS не требуется.
**Новый источник истины:** `Telegram.WebApp.isFullscreen` + события `fullscreenChanged`/`viewportChanged`; `toggleFullscreen` — user-action-триггер.

## Последствия

**Плюсы:**
- Закрывается реальная причина (реактивность `:open` + синхронизация с TMA), а не симптом.
- Раскрытие переживает и частичный ре-рендер (реактивный стейт), и полную перезагрузку WebView (`initExpandState` из `localStorage`).
- Устраняется класс мелких рассинхронов `⛶`-иконки/`.fullscreen-mode` при нативной смене режима.
- Единый механизм на все `details.advanced` — меньше шансов на повтор бага.

**Минусы / долг:**
- Меняются 5 биндинг-сайтов и добавляются 3 computed-аксессора — правка `web/app.js`/`web/index.html` (уже общие файлы web-очереди + F21 → сериализация).
- Требуется обновить пины, зашивающие старый синтаксис (`tests/test_webapp_round1011_ui.py`, `tests/test_webapp_nav_disclosure_ui.py`, `tests/test_ui_verbilizer_tabs_round1023.py`, `tests/js/routing_test.js`).
- Ремаунт WebView не воспроизводим локально → **обязательна live-приёмка TMA** (High-риск).

**Инварианты:** `tma-menu-freeze`, Δ DDL=0, Δ каталога=0, R16/R17/R18, CSP (нет новых библиотек), `parse_mode=None` — не нарушены.

## Альтернативы

| Альтернатива | Почему отклонена |
|---|---|
| Оставить `:open="expandOpen(...)"`, но читать реактивный `this.expand` (метод в шаблоне) | Технически реактивно (чтение реактивного свойства внутри render-effect), но не выполняет директиву владельца «биндить к реактивному значению, не вызывать функцию в шаблоне»; computed-подход однозначнее и идиоматичнее Vue |
| Инвертировать состояние в `toggleExpand` (как сейчас) + реактивный биндинг | Осцилляция при общих bare-ключах и программном `toggle`; нестабильно |
| Ввести feature-flag (`ui_flags`, ADR-1024-13) | Лишняя серверная поверхность для клиентского багфикса; OFF вернул бы баг; откат и так есть через `git revert` |
| Только «Провайдеры» (минимальный скоуп) | Тот же нереактивный `:open` в 4 других зонах → повторный баг на других вкладках; единожды исправить дешевле |
| Форсировать раскрытие advanced (дефолт открыт) | Меняет UX-семантику 10.4/10.11 (свёрнуто по умолчанию); не требуется для устранения дефекта |
| Подписка на `safeAreaChanged` | Safe-area решается CSS-переменными `--tg-*` (10.10); JS-состояние не нужно |
| Полностью ориентироваться на `viewportChanged` и убрать реактивность | Не адресует нереактивный `:open`; дефект при ре-рендере остался бы |
