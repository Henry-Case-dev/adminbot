# spec.md — frontend-advanced-collapse-default (ТЗ 5 раунда 10.4, фича D)

Задачи: T-1018…T-1023 (tasks.md). Стадия старта — PLANNED → ARCHITECTED (наст. файл).
База: HEAD `1410a68` (раунд 10.3 закоммичен и задеплоен). Порядок в раунде: **D → C → E → A → B → F → H → G** (D первым — изолированные аккордеоны; C/E/A реструктурируют группы и обязаны опираться на уже сворачиваемые advanced).

## 1. Контекст и проблема

`web/index.html:673-675` рендерит `<details class="advanced" :open="basicItems(grp).length === 0 || expandOpen(activeTab)">` — группа БЕЗ базовых карточек принудительно раскрыта. ТЗ владельца (п.5): «Расширенные настройки» должны быть СВЁРНУТЫ по умолчанию **всегда**; эвристика `basicItems(grp).length === 0` (чтобы «вкладка не выглядела пустой») — устаревшая, после реструктуризации (фичи A/C/E) групп с 0 базовых станет больше и принудительное раскрытие будет выглядеть сломанным.

## 2. Ключевые решения

| ID | Решение | Обоснование |
|----|---------|-------------|
| **D-1** | Единый источник истины для `:open` = `expandOpen(activeTab)`. Выражение `:open="expandOpen(activeTab)"` в `web/index.html:674`; эвристика `basicItems(grp).length === 0 ||` **удаляется**. | ТЗ 5: свёрнуто по умолчанию всегда; персист `adminbot.expand:<tab>` (app.js:1293-1303) остаётся единственным способом раскрытия («юзер раскрыл — помним»). |
| **D-2** | Поведение групп с 0 базовых (но N>0 advanced): **свёрнутый `<details>` с видимым `<summary>` «▶ Расширенные настройки (N)»**. Группа НЕ выглядит сломанной: заголовок группы + описание (index.html:566-567) и счётчик `(N)` в summary (:679-681) видны всегда; клик по summary раскрывает. | «0 базовых» означает не «нет параметров», а «нет параметров в базовой сетке» — счётчик N это сообщает. Против варианта «пустые+раскрытые»: прямо противоречит ТЗ 5. Название группы и описание всегда видимы — вкладка не воспринимается пустой. |
| **D-3** | UX-защита (T-1020): **минимальный вариант — без дополнительных бейджей/шапок-счётчиков**. | (а) Счётчик `(N)` в summary уже есть; (б) обязательный тест AC-B1 (T-1022) гарантирует каждой config-вкладке ≥1 группу с basicItems>0 после фич C/E — «вкладка выглядит полностью пустой» структурно исключено; (в) лишние UI-элементы = лишние маркер-тесты/диффы без пользовательской ценности. Допустимый минимальный декоративный вариант (если Builder сочтёт нужным): `title`-подсказка «Раскрыть (N) параметров» на `<summary>` — НЕ обязателен и не меняет разметку-маркеры. |
| **D-4** | BUG-5-семантика «(0)» сохраняется как есть: группа рендерится при `basicItems(grp).length || advancedItems(grp).length` (index.html:564, фильтр groupedForTab app.js:1482-1484) — пустых групп и «(0)»-карточек нет; группы 0/0 полностью скрыты. | ТЗ 5 + BUG-5: «0 базовых» ≠ «пустая группа»; «(0)» нигде не появляется. |
| **D-5** | Персист `expandOpen`/`toggleExpand` (app.js:1293-1303) и семантика `@toggle="toggleExpand(activeTab)"` (index.html:675) — **без изменений**. | НТ: персист не ломается: раскрыл → перезагрузил → раскрыто (live-маркер T-1023). |
