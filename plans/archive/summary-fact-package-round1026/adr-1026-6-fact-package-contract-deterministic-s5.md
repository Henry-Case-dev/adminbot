# ADR-1026-6 — S4 «Пакет фактов §96»: детерминированная схема, бюджет и граница S4/S5

- **Статус:** Accepted (Step 2 @Architect, 23.09.2026)
- **Фича:** S4 `summary-fact-package-round1026` (Эпик 2, этап «Пакет фактов для L2», §80/§96)
- **Тип:** backend/сборка (чистый алгоритм); **0 LLM-вызовов**; **Δ DDL = 0**; **Δ каталога = 0**; **врезка — GATED (S5/S6)**
- **Связано:** ADR-1026-5 (S3 L1-контракт §95, `L1Result`, ID TG/DB) — REUSE; **ADR-1022-4** (Редактор→Рассказчик, вход Stage-2 → пакет §96) — AMEND **effective S5** (не меняется этим ADR); **ADR-1023-3/-6** (`response_mode`/`cover_prompt`) — REUSE/AMEND effective S5; ADR-1022-3/5 (2-вызовность) — REUSE; ADR-1026-1/-4 (S1/S2) — REUSE; ADR-1025-24 **D4** (гейт S6/S10) — governed-by; ADR-1026-2 (frozen F8) — **не запускается** (Δ каталога=0)
- **Baseline:** HEAD `59f5921` == `origin/master`, `APP_VERSION` 2.58.22, pytest 8685/0, JS 43/43, каталог 468/426/443/100/98/21, Δ DDL=0

## Контекст

Целевой пайплайн Эпика 2: S1-фильтр → S2-восстановление → L1 «Кластеризатор» (S3, §94–§95, 1 вызов) → **пакет фактов §96 (S4, 0 вызовов)** → L2 «Писатель» (§97–§99, S5, 1 вызов) → форматирование → существующая публикация. §96 требует на тему: название, **описание**, **хронологию**, факты, подтверждающие ID, необходимые исходные фрагменты; запрещает повторную передачу всего сырого лога и генерацию доказательств. Инвариант — ровно 2 физических LLM-вызова (ADR-1022-3/4/5), значит пакет обязан быть **детерминированным и без LLM**.

Проблема: §95-JSON (S3) содержит `threads[{thread_id, topic, message_ids[], facts[{text, evidence_message_ids[]}]}]`, но **не содержит `description` и хронологии**. Их нельзя «дописать моделью» (третий вызов = блокер) — нужен детерминированный источник. Также не решены: бюджет L2-входа (ключи vs env-only), судьба `cover_prompt`/`response_mode`, граница S4/S5, семантика неполноты, deploy.

## Решения

**D1. Схема пакета — новый чистый контракт `FactPackage` v1; описание и хронология — детерминированные, не LLM.**
- Модуль `services/summary_fact_package.py` (чистый: без БД/сети/часов/LLM). Топ-уровень: `{schema_version:1, status, threads[], unassigned_message_ids[], service{response_mode, cover_prompt}, budget{kind,limit,estimated,fits}}`; `PackageThread`: `{thread_id, name, description, chronology[], facts[], evidence_ids[], fragments[]}`. Фиксированный порядок ключей; двойной прогон байт-идентичен.
- **Название** = `topic` verbatim. **Описание** = компактная агрегация `facts[].text` (дедуп, схлопывание пробелов, фикс-разделитель, кап `DESCRIPTION_MAX`); нет фактов → `""`. **Хронология** = ASC `(timestamp,message_id)` по `message_ids` темы, `timestamp` из §92-payload. **Факты/подтверждающие ID** = verbatim из L1 + union `evidence_message_ids`. **Фрагменты** = отбор из §92-payload по evidence-first приоритету с лимитами.
- Альтернатива (a) «`description` генерирует LLM/сборщик» — **отклонена**: третий вызов/фабрикация (Critical, ADR-1022-4, §96). Альтернатива (b) «описание = сырой текст сообщений темы» — отклонена: не описание, риск воспроизведения лога. Альтернатива (c) «хронология как текст-дамп» — отклонена: дублирует фрагменты, раздувает бюджет.

**D2. Бюджет L2-входа — переиспользование существующих `summary_*` лимитов; Δ каталога = 0.**
- `resolve_chat_limit(limits.summary_max_context_tokens, default 30000, "SUMMARY_MAX_CONTEXT_CHARS", chars, "SUMMARY_FACT_PACKAGE")` — тот же приём, что `resolve_l1_budget` (`summary_l1_clusterizer.py:305-320`). Токены (приоритет) + chars-fallback; новых env-переменных и ключей каталога **нет**; per-chat-резолв — S5.
- Приоритет усечения (отбрасываемое первым): фрагменты (старые → первыми, последние сохраняются, §93) → `description` (производное) → целые темы (старая первой). Факты/evidence не обрезаются частично. Любое вытеснение → `truncated`+`skipped_ids`/`skipped_threads`+WARN; не влезает ни одна тема → `empty` → L2 не вызывается.
- Альтернатива «новые ключи `limits.fact_package_*`» — отклонена: Δ каталога>0 требует санкции+переиздания F8 без потребителя до S5; переиспользование честнее (§86).

**D3. `cover_prompt`/`response_mode` — транзит в служебной секции пакета, вне L2-контента.**
- Пакет несёт их в `service` (verbatim, уже нормализованы L1). Секция исключена из L2-контента (изоляция Stage-2); S5 читает её для narrator-режима и обложки. §104/обложка/живой путь/`compose_cover_image_prompt`/фолбэк hotfix4 — без изменений.
- Альтернатива «вне пакета, читать `L1Result` напрямую на S5» — допустима, но отклонена: единый объект передачи снижает риск потери полей при врезке. AMEND ADR-1023-3/-6 (источник — L1, effective S5) сохраняется.

**D4. Границы S4 vs S5: S4 — модуль+схема+тесты, врезка GATED.**
- S4 активирует модуль/валидатор/бюджет/логи/тесты; **врезки нет** (не раньше S5/S6, гейт S6/S10 + D4/ADR-1025-24, после live-приёмки Эпика 1). Интерфейс для S5 объявлен без вызова: `build_fact_package(l1_result, payload_items, *, budget=None) -> FactPackageResult`.
- S5 получает: врезку L1+пакет+L2, слот/UI L2-модели, каталог, per-chat-резолв, follow-up S3 (`L-R1026S3-1/-2/-3`, `R-R1026S3-1/-2`). `run_id` — S7; ExecutionGraph — S8; §113 — S9.
- Альтернатива «врезать сразу с kill-switch» — отклонена: L2 ещё не существует; изменило бы публикационный контур до live-приёмки Эпика 1 (D4).

**D5. Fail-closed, ID-пространства, детерминизм.**
- `ok` → `ok`; `truncated` → `truncated`+проброс `skipped_ids`/`skipped_tg_ids`; `empty`/`invalid`/`error` → соответствующий статус, `threads=[]`, **в L2 не передаётся** (§95/§106); нет `usable`/`payload` → пакет **не строится** (`not_built`+reason). Пустой пакет → L2 не вызывается.
- Пакет оперирует **TG `message_id`**; DB `id` — только бухгалтерия усечения в логах. Все id обязаны существовать в §95- и §92-payload; висячие/дублированные/перекрёстные → `invalid`. Фабрикация/подмена запрещены. `evidence_ids ⊆ message_ids` темы.
- Детерминизм: фиксированный порядок, ASC `(timestamp,message_id)`, дедуп, вход не мутируется.
- Альтернатива «мягкая авто-починка ссылок» — отклонена: §96 прямо запрещает генерацию доказательств.

**D6. Инварианты/deploy.**
- **0 LLM-вызовов** (модуль не импортирует `llm_client`; `await_count==2`, `steps=[stage1,stage2]` в живом пути не тронуты); **Δ DDL=0**; **Δ каталога=0** (F8 не переиздаётся); CSP/zero-build; R17/R18; §57–§74/F0–F11/S1–S3/публикация/обложка/XML — не тронуты.
- **Deploy = ДА** (T-3305 применим): **bump `APP_VERSION` 2.58.22 → 2.58.23** + `README.md` + cache-bust; перед деплоем — минимальные §114-тесты. Обоснование: в деплой-дерево добавляется новый рантайм-модуль (артефакт поставки); version-tracking/откат требуют маркера; наблюдаемое поведение/каталог/DDL не меняются (подтверждается тестами). Альтернатива **NOT_APPLICABLE** рассмотрена и отклонена: оставила бы прод и master рассинхронизированными до S5 при отсутствии выигрыша.
- Откат: annotated-тег `pre-round1026-s4` → `59f5921`; hard — `git revert`; hot-OFF не требуется (живой путь не изменён).

## Последствия

- S4 даёт автономный, тестируемый контракт пакета §96 без изменения живого контура; S5 получает готовый интерфейс для врезки L1+пакет+L2.
- §96-полнота достигается без третьего LLM-вызова: `description`/`chronology` детерминированы из уже валидированных полей L1/§92.
- Компактность: сырой лог повторно не передаётся; фрагменты ограничены; усечение всегда явное (`truncated`+`skipped_ids`+WARN).
- Ограничения (документируются): `description` — агрегация фактов (не проза; при отсутствии фактов пусто); бюджет переиспользует общий summary-лимит (отдельного `fact_package_*` нет); слот/UI L2 и per-chat-резолв — S5; `evidence_message_ids: []` (L-R1026S3-2) и прочие follow-up S3 — S5.
