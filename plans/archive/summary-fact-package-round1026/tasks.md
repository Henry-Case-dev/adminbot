## Приёмочные инварианты S4 (нарушение = НЕ принято)
1. Пакет — детерминированная сборка из валидированного `L1Result` по схеме `FactPackage` v1 (D1); **0 LLM-вызовов**; ровно 2 вызова пайплайна не затронуты (`await_count==2`, живой путь вне diff).
2. **В S4 живой путь не меняется:** `services/summary_generator.py`/`summary_xml.py`/публикация/обложка (`image_generation.py`/`telegram_send.py`)/`web/**` — вне diff; врезка — **GATED (S5/S6)**.
3. **Fail-closed (D5):** `ok`→`ok`; `truncated`→`truncated`+проброс skipped; `empty`/`invalid`/`error`→соответствующий статус, `threads=[]`, в L2 не передаётся (§95/§106); нет `usable`/`payload` → **`not_built`+reason (пакет не строится)**. Пустой пакет → L2 не вызывается.
4. **§96-полнота:** каждая тема — `name`/`description`/`chronology`/`facts`/`evidence_ids`/`fragments`; `name`=topic verbatim; `description` — компактная агрегация `facts[].text` (дедуп/схлопывание пробелов/кап `DESCRIPTION_MAX`; нет фактов → `""`); «доказательства» только из полей L1/§92-payload, без генерации.
5. **ID-пространства:** TG `message_id` (payload) ↔ DB `id` — только внутренняя бухгалтерия усечения в логах; висячие/дублированные/перекрёстные ссылки → `invalid`; `evidence_ids ⊆ message_ids` темы; выдуманные/фабрикованные ссылки невозможны.
6. **Компактность:** весь сырой лог повторно не передаётся; фрагменты — только подтверждающие/необходимые (§92-payload, evidence-first); бюджет L2-входа соблюдён (переиспользование `summary_*`-лимитов).
7. **Детерминизм:** один вход → байт-идентичный выход (двойной прогон); вход не мутируется; фиксированный порядок ключей, ASC `(timestamp,message_id)`.
8. **Δ DDL=0; Δ каталога=0** → **F8 (ADR-1026-2) не переиздаётся (N/A)**; любое иное — только письменная санкция @Architect.
9. **Логи аддитивны (R17):** числа/коды/id/host; без ключей/текстов сообщений/сырых ответов.
10. **CSP/zero-build; R17/R18;** критерии — трассируемы к §96 (и смежным §93–§95/§106), без выдуманных требований.
