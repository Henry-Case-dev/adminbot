## 1. Цель и контекст

§80/§96 задают этап между L1 «Кластеризатор» (S3, `L1Result.payload` §95) и L2 «Писатель» (S5, §97–§99): **пакет фактов для L2**. L2 не должен получать «только названия тем и `message_id`» (§96). Для каждой темы пакет несёт: **название, описание, хронологию, факты, подтверждающие ID, необходимые исходные фрагменты текста**; **весь сырой лог повторно не передаётся**; **доказательства не генерируются** (§96). Пакет строится из **валидированного** `L1Result` (S3) и §92-payload (`build_l1_payload`), детерминированно, **без единого LLM-вызова** — иначе нарушится инвариант ровно 2 вызовов (ADR-1022-3/4/5, ADR-1026-5 D1).

**Ключевое ограничение (D1):** в §95-JSON **нет** `description` и **нет** хронологии. Их источник — **детерминированный**, 0 LLM: описание = компактная агрегация `facts[].text` (уже валидированных, evidence-backed), хронология = ASC `(timestamp, message_id)` по `message_ids` темы из §92-payload. **Описание моделью не генерируется** (третий вызов — блокер).

## 4. Схема пакета фактов (D1)

**Модуль:** `services/summary_fact_package.py` — **чистый** (без БД/сети/часов/LLM). Пакет — канонический JSON-объект с **фиксированным порядком ключей**; повторный прогон на том же входе — байт-идентичен.

**Топ-уровень (ровно эти ключи):**
```
{
  "schema_version": 1,                     # версия схемы ПАКЕТА (≠ §95)
  "status": "ok"|"truncated"|"empty"|"invalid"|"error",
  "threads": [ PackageThread, ... ],       # ASC по первой паре хронологии
  "unassigned_message_ids": [int, ...],    # TG, транзит из L1 (§95)
  "service": { "response_mode": str, "cover_prompt": str },   # D3, §7
  "budget": { "kind": "tokens"|"chars", "limit": int, "estimated": int, "fits": bool }
}
```
Fail-closed (`invalid`/`error`): `threads=[]`, `status` + R17-safe `reason` (код), `service` — только транзит. `empty` — валидный L1 без тем. Пустой пакет в L2 не передаётся (§9).

**PackageThread (ровно эти ключи, фиксированный порядок):**
```
{
  "thread_id": str,                        # verbatim из L1
  "name": str,                             # §96 «Название» = topic verbatim (0 генерации)
  "description": str,                      # §4.2 — детерминированная агрегация (0 LLM)
  "chronology": [ {"message_id": int, "timestamp": int}, ... ],   # ASC (timestamp,message_id)
  "facts": [ {"text": str, "evidence_message_ids": [int,...]}, ... ],  # verbatim из L1
  "evidence_ids": [int, ...],              # union evidence фактов темы, ASC — «подтверждающие ID»
  "fragments": [ {"message_id": int, "timestamp": int, "text": str}, ... ]  # §4.5
}
```

### 4.1. Название
`name` = `thread["topic"]` из канонического §95-payload, **verbatim** (уже прошёл лимиты §95: ≤200, без `\n`). Пустая строка невозможна (валидатор L1 отверг бы).

### 4.2. Описание (детерминированное, НЕ генерация)
`description` = компактная агрегация **уже валидированных** `facts[].text` темы в каноническом порядке: `text`-значения дедуплицируются, схлопываются по пробелам, соединяются фиксированным разделителем (`" · "`), обрезаются до `DESCRIPTION_MAX` символов по границе слова с флагом `description_truncated=true` (в `metrics`, не в L2-контент). Если фактов нет — `description=""` (**не выдумывается**). **Инвариант:** `description` строится только из полей L1; никакой LLM/прозы/цитат от сборщика (§96 «не генерировать доказательства»).

### 4.3. Хронология
`chronology` = по каждому `message_id` темы (порядок уже ASC из канонизации L1) пара `{"message_id", "timestamp"}`, где `timestamp` берётся из §92-payload по TG `message_id`. **Компактно** (только id+время, без текста). Отсутствие §92-строки для id → **fail-closed** `invalid`/`missing_source` (хронология обязана быть правдивой; L1 гарантирует `message_ids ⊆ id-space`).

### 4.4. Факты и подтверждающие ID
`facts` — **verbatim** из L1 (`text`, `evidence_message_ids`), без изменения. `evidence_ids` = детерминированный union `evidence_message_ids` всех фактов темы, ASC по §92-порядку. `evidence_ids ⊆ message_ids` темы (гарантия L1); проверяется повторно (defense-in-depth). Пустой `evidence_message_ids` у факта — как в L1 (политика L-R1026S3-2 остаётся зоной S5; S4 не ужесточает и не ослабляет).

### 4.5. Необходимые исходные фрагменты текста (§96, компактность)
`fragments` — из §92-payload (`build_l1_payload`); текст **не выдумывается**. Детерминированный отбор: приоритет 1 — сообщения из `evidence_ids` (подтверждающие), приоритет 2 — остальные `message_ids` темы; внутри приоритета — ASC. Лимиты: `FRAGMENT_MAX_CHARS` (обрезка фрагмента), `MAX_FRAGMENTS_PER_THREAD`, `MAX_FRAGMENTS_TOTAL`. Строки с пустым `text` в `fragments` не попадают (остаются в `chronology`). **Весь §93-набор/сырой лог целиком не передаётся** — только отобранное подмножество. Отсутствие §92-строки → fail-closed `missing_source`.

## 5. ID-пространства и целостность (D5)
- Пакет оперирует **TG `message_id`** (пространство §92/§95). DB `id` — только внутренняя бухгалтерия усечения (`skipped_ids` в логах), **не** публичное поле пакета.
- Каждый `message_id`/`evidence_id`/`fragment.message_id` обязан существовать в §95-payload и в §92-payload; висячие/дублированные/перекрёстные ссылки → `invalid` (код причины). Фабрикация/подмена id запрещены (§96).
- `unassigned_message_ids` — транзит из L1 без изменения; пересечение с темами невозможно (гарантия L1), проверяется.

## 6. Лимиты/бюджет L2-входа (D2)
- **Ключи:** переиспользование существующих `limits.summary_max_context_tokens`/`_chars` через `resolve_chat_limit(token_value, _SUMMARY_CONTEXT_TOKEN_DEFAULT=30000, "SUMMARY_MAX_CONTEXT_CHARS", chars_value, "SUMMARY_FACT_PACKAGE")` (тот же приём, что `resolve_l1_budget`, `summary_l1_clusterizer.py:305-320`). **Δ каталога = 0**, новых env-переменных нет. Per-chat-резолв — S5 (при врезке).
- **Единицы:** токены (приоритет) с chars-fallback — штатная семантика `resolve_chat_limit`; `budget.kind/limit/estimated/fits` в пакете.
- **Приоритет усечения (детерминированный, отбрасываемое — первым):** (1) `fragments` (самые старые первыми; **последние сохраняются** — §93 «не резать последние молча»); (2) `description` (производное → `""`); (3) целые темы (самая старая первой). Факты/evidence **не обрезаются частично** — вместо этого отбрасывается тема целиком.
- **Явность:** любое вытеснение → `status="truncated"` + `skipped_ids` (TG id вытесненных фрагментов) / `skipped_threads` + WARN-лог («не резать молча», §93/§96). Если в бюджет не влезает ни одна тема → `status="empty"` → L2 не вызывается.

## 9. Fail-closed, неполнота, детерминизм (D5)
| Вход `L1Result.status` | Пакет | В L2? |
|---|---|---|
| `ok` | `ok` (или `truncated` при усечении пакета) | да |
| `truncated` | `truncated` + проброс `skipped_ids`/`skipped_tg_ids`/`chunk_count` + WARN | да |
| `empty` | `empty`, `threads=[]` | **нет** (§106) |
| `invalid` | `invalid` + `reason`, `threads=[]` | **нет** (§95) |
| `error` | `error` + `reason`, `threads=[]` | **нет** (§106) |
| нет `usable`/`payload=None` | пакет **не строится**, `not_built`+`reason` | **нет** |

- «Невалидный вход не идёт в L2» (§95/§106); пустой пакет → L2 не вызывается.
- **Детерминизм/канонизация:** фиксированный порядок ключей; ASC `(timestamp,message_id)`; дедуп; двойной прогон байт-идентичен; вход не мутируется.
- **0 LLM-вызовов:** модуль не импортирует `llm_client`; живой путь (`await_count==2`, `steps=[stage1,stage2]`) — вне diff.

## 10. Логи/безопасность (R17, §108/§109)
Аддитивные события `FACT_PACKAGE_START`/`FACT_PACKAGE_COMPLETE`/`FACT_PACKAGE_ERROR` (+WARN-усечение) с полями §109: темы/факты/фрагменты, оценка токенов, длительность, `status`/`reason`, `correlation_id` (формальный `run_id` — S7). **R17:** только числа/коды/id/host — без ключей, текстов сообщений, сырых ответов, промптов. Аддитивные счётчики для S7/S8 (`facts_count`/`fragments_count`/`truncated_count`/`skipped_ids` счётно) — **без узлов ExecutionGraph** (S8) и без второй аналитики.

## 11. Приёмочные сценарии
- **SC-01** §96-полнота: каждая тема несёт name/description/chronology/facts/evidence_ids/fragments; адаптированный пример §95 проходит.
- **SC-02** 0 LLM: сборка не вызывает LLM; `await_count==2` в живом пути; `step="fact_package"` в живом пути отсутствует.
- **SC-03** fail-closed: `empty`/`invalid`/`error` → пакет не идёт в L2; пустой → L2 не вызывается.
- **SC-04** ID-целостность: DB `id`↔TG; evidence ⊆ темы; висячие/фабрикованные id → `invalid`.
- **SC-05** компактность: сырой лог целиком не воспроизводится; фрагменты ⊆ подтверждённым id; бюджет соблюдён.
- **SC-06** усечение: явное (`truncated`+`skipped_ids`+WARN), воспроизводимое; последние фрагменты сохраняются.
- **SC-07** детерминизм: двойной прогон байт-идентичен; вход не мутируется.
- **SC-08** описание/хронология: детерминированы, из реальных полей L1/§92, без генерации; отсутствующие поля не выдумываются.
- **SC-09** транзит `service`: `cover_prompt`/`response_mode` не теряются и не попадают в L2-контент.
- **SC-10** инварианты живого пути: `summary_generator`/XML/публикация/обложка/`web/**` — вне diff; OFF-цепочка байт-в-байт; полный pytest ≥ baseline; JS-маркеры зелёные.
