> **Тип:** backend/LLM/data — сочетание retrieval (lexical/FTS + vector + фильтры + reply-граф + эпизоды), типизированный reranker, embedding fingerprint/поколения, единый `EvidenceBundle`, адаптивный бюджет контекста, singleflight/high-watermark сводок и отключение прежнего ответного кеша. Потребитель контрактов `mca-03` (§96 — `(chat_id, tg_message_id)`/namespace/revision) и `mca-04a` (§98 — SourceRef/EvidenceLink/статусы).
> **ТЗ-источник (IMMUTABLE, НЕ изменяется):** `plans/current_task.md` v1.8, **§11** «MCA-07 — retrieval и единый контекст» (`:383–434`), а именно:
> - **§11.1 «Поиск»** (`:391–399`) — сочетание lexical/FTS + vector + фильтров по времени/участникам + reply-графа + эпизодов; для запроса об истории — сначала эпизоды, при необходимости спускаться к сообщениям; сохранять поиск точной фразы/имени/даты; reranker → **типизированный список ID**; пустой **валидный** список ≠ все кандидаты; ошибка формата/timeout — **отдельный статус с явной политикой fallback**; порядок = оценке; **embedding cache key** = текст + provider/model + dimensions + preprocessing/version (+endpoint/deployment там, где оно меняет модель); один dimension ≠ совместимость; **индексы имеют fingerprint и поколение**.
> - **§11.2 «EvidenceBundle»** (`:401–416`) — обязательные поля логического контракта (trigger/current message/revision; адресат/автор/упоминаемые/неоднозначности; текущая ветка/локальный контекст; релевантные факты/эпизоды с SourceRef и временем; ограничения запроса/неизвестное/противоречия; профиль/интересы/отношения; выбранное намерение/недавние действия; `context_version`/исключённые материалы и причины); **один согласованный bundle** для решения, инструментов, синтеза и формулировки; System2 после tool loop **не** должен получать только исходный вопрос + tool output, теряя адресата/ветку/ограничения; весь архив на каждом этапе не дублируется.
> - **§11.3 «Бюджет контекста»** (`:418–426`) — считать **полный** запрос (system/developer/personality, user context, tools schemas, tool results, output reserve, служебный overhead с учётом реального API); при неизвестном tokenizer — **консервативная оценка с запасом** и логирование метода; объём **адаптивный**; нет универсального обязательного лимита 6000 токенов / 8 фактов; жёсткая граница — окно модели и размер payload; сначала целые смысловые блоки, затем сжатие менее важных; не обрезать отрицание/ID источника/дату так, что меняется смысл; при переполнении — сокращать/суммировать с сохранением источников, дополнительный retrieval либо уточнение; **не отправлять заведомо переполненный запрос**; логировать фактический размер/резерв/исключённые категории/причину.
> - **§11.4 «Сводки и кеш ответов»** (`:428–434`) — сводка per chat: **singleflight/coalescing + high-watermark/CAS**, чтобы поздно завершившийся старый запрос не перезаписал новую версию; обновление источников — отдельной **revision**; для контекстных диалоговых ответов **отключить прежний кеш по одному нормализованному query/chat/user**; **дедупликацию одного Telegram update оставить**; повторное «почему?» под другим родителем обрабатывается заново; «иной ответный кеш» — **не обязательная оптимизация**, но если сохраняется, ключ обязан включать зависимые версии и ссылку на родителя.

## Приёмочные инварианты MCA-07 (нарушение = НЕ принято)

1. **Retrieval — комбинация, не один канал:** lexical/FTS + vector + фильтры по времени/участникам + reply-граф + эпизоды; для истории — сначала эпизоды, затем при необходимости сообщения; точная фраза/имя/дата сохраняются. **MCA07-R1; T-3843, T-3844, T-3845.**
2. **Reranker типизирован:** возвращает типизированный список ID; **валидный пустой список ≠ все кандидаты** (все кандидаты в контекст не возвращаются); ошибка формата/timeout — **отдельный статус** с явной политикой fallback; при заявленном ранжировании порядок соответствует оценке. **MCA07-R2; T-3846.**
3. **Embedding cache key** = текст + provider/model + dimensions + preprocessing/version (+endpoint/deployment там, где оно меняет модель); один dimension **не** доказывает совместимость; индексы имеют **fingerprint и поколение**; смена модели при той же размерности **не** смешивает старые и новые векторы. **MCA07-R3; T-3847.**
4. **EvidenceBundle един и полон** (§11.2): trigger/current revision; адресат/автор/упоминаемые/неоднозначности; ветка/локальный контекст; факты/эпизоды **с SourceRef и временем** (§98); ограничения/неизвестное/противоречия; профиль/интересы/отношения; намерение/недавние действия; `context_version`/исключённые материалы и причины. **Один** bundle используется для решения, инструментов, синтеза и формулировки. **MCA07-R4; T-3848, T-3852.**
5. **System2 после tool loop не теряет контекст:** не получает только исходный вопрос + tool output; адресат/ветка/ограничения сохраняются; весь архив на каждом этапе не дублируется. **MCA07-R4; T-3852.**
6. **Бюджет — полный и адаптивный:** system/developer/personality + user context + tools schemas + tool results + output reserve + overhead с учётом реального API; при неизвестном tokenizer — консервативная оценка с запасом и логирование метода; нет универсального обязательного лимита (6000/8); целые смысловые блоки → затем сжатие менее важных; **отрицание/ID источника/дата не обрезаются так, что меняется смысл**; переполнение → суммирование/доп. retrieval/уточнение; заведомо переполненный запрос не отправляется; логируются фактический размер/резерв/исключённые категории/причина. **MCA07-R5; T-3849.**
7. **Сводки per chat:** singleflight/coalescing + **high-watermark/CAS** — поздно завершившийся старый запрос не перезаписывает новую версию; обновление источников — отдельной **revision**. **MCA07-R6; T-3850.**
8. **Ответный кеш:** для контекстных диалоговых ответов **отключён** прежний кеш по одному нормализованному query/chat/user; **дедупликация одного Telegram update сохранена**; повторное «почему?» под другим родителем обрабатывается заново; «иной ответный кеш» — не обязательная оптимизация (если есть — ключ включает зависимые версии и родителя). **MCA07-R6; T-3851.**
9. **REUSE, не второй контур:** существующие `summary_memory`/`direct_chat_service`/`lore_cache`/`thread_chain`/`lore_stories`/`provenance` переиспользуются; **второй retrieval/EvidenceBundle** запрещён. **GEN-R19; T-3843, T-3844, T-3846, T-3848.**
10. **Аддитивность/идемпотентность DDL (если нужен):** только через реестр `mca-14`; старые записи/ID/таблицы сохранены; nullable = честный unknown; повторный прогон — no-op. **MCA14-R1/R2; T-3842.**
