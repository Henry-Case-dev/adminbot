# F5 — Чек-лист ротации SSH-доступа (для @DevOps, вне репо)

> **Раунд:** 10.16. **Фича:** `security-rotation-finalize-round1016` (T-1661/T-1664).
> **Триггер:** рабочая копия `plans/current_task.md` (`:61-76`) содержит плейнтекст
> SSH-пароль. Пароль **не в git** (см. `plans/reports/round10.16_security_scan.md`),
> но подлежит **ротации/отзыву** как R17-долг.
> **Правило R17:** в отчётах, логах и коммитах — **ни одного секрета**. Только факты:
> «ключ установлен / пароль отозван / доступ подтверждён». Значения ключей/паролей
> не публикуются.

## 0. Порядок (важно!) — сначала ключ, потом отзыв пароля

Строго в этом порядке, чтобы **не потерять доступ** к серверу:

```
1. Сгенерировать ключ  →  2. Установить публичный ключ  →  3. Проверить вход по ключу
→  4. Только теперь отозвать/сменить пароль  →  5. Проверить доступ ещё раз  →  6. Отчёт
```

## 1. Генерация ключа (локально, у @DevOps)

```bash
ssh-keygen -t ed25519 -a 100 -C "adminbot-deploy-<дата>" -f ~/.ssh/adminbot_deploy
# приватный ключ: ~/.ssh/adminbot_deploy   (НЕ в репо, НЕ в чат, НЕ в отчёт)
# публичный:      ~/.ssh/adminbot_deploy.pub
chmod 600 ~/.ssh/adminbot_deploy
```

- Приватный ключ — только в менеджере секретов / локальном `~/.ssh` (никогда в репо).
- `.gitignore` уже исключает `id_ed25519*`, `id_rsa*`, `*.pem` — но ключ и так вне репо.

## 2. Установка публичного ключа на сервер (одноразово, ещё по паролю)

```bash
ssh-copy-id -i ~/.ssh/adminbot_deploy.pub nik@<прод-сервер>
# либо вручную: добавить содержимое .pub в ~/.ssh/authorized_keys на сервере
```

## 3. Проверка входа по ключу (пароль ещё жив)

```bash
ssh -i ~/.ssh/adminbot_deploy -o PasswordAuthentication=no nik@<прод-сервер> 'whoami && hostname'
# ожидаем: nik / <hostname>  — вход прошёл БЕЗ пароля
```

## 4. Отзыв/смена пароля (только после успешного п.3)

Вариант A — сменить пароль на новый сложный (если пароль ещё нужен другим людям):

```bash
ssh -i ~/.ssh/adminbot_deploy nik@<прод-сервер>
passwd nik          # новый сложный пароль, сохранённый в менеджере секретов
```

Вариант B (предпочтительно) — полностью запретить парольный вход:

```bash
sudo sed -i 's/^#\?PasswordAuthentication .*/PasswordAuthentication no/' /etc/ssh/sshd_config
sudo sshd -t && sudo systemctl reload sshd
# в другом окне НЕ закрывая текущую сессию — проверить вход по ключу (п.5)
```

- **Не закрывать** активную сессию, пока вход по ключу не подтверждён в новой сессии.
- При наличии `KbdInteractiveAuthentication` — выставить `no` (иначе пароль принимается косвенно).

## 5. Финальная проверка доступа

```bash
ssh -i ~/.ssh/adminbot_deploy nik@<прод-сервер> 'echo KEY_OK && sudo systemctl status admin_bot --no-pager | head -3'
ssh -o PreferredAuthentications=password -o PubkeyAuthentication=no nik@<прод-сервер> \
    'echo SHOULD_FAIL'   # ожидаем отказ: парольный вход закрыт
```

## 6. Деплой без плейнтекст-пароля (Step 9–10)

```bash
ssh -i ~/.ssh/adminbot_deploy nik@<прод-сервер> \
  'cd /var/www/admin_bot && git pull --ff-only && sudo systemctl restart admin_bot && \
   curl -fsS http://127.0.0.1:8000/api/health'
# ожидаем: git fast-forward, restart OK, /api/health = 200
```

- `.env` при обычном деплое **не трогаем** (только код + `git pull` + `restart`).
- Live-верификация: `/api/health` = **200**, `/api/memory/*` = **401** (не 500).
- `plans/current_task.md` — **личный untracked-файл владельца**, в git не коммитим;
  пароль из рабочей копии удаляется **по согласованию с владельцем** (замена на
  «см. менеджер секретов»).

## 7. Отчёт @DevOps (строго без секретов)

Шаблон:

```
[SSH-ротация round1016] ключ ed25519 установлен и проверен; парольный вход
отключён/пароль сменён; доступ по ключу подтверждён; деплой <commit> — fast-forward;
admin_bot active (running); /api/health 200; /api/memory/* 401.
Секреты в отчёт не включены (R17).
```

## 8. Rollback-окно

- До отзыва пароля любой шаг откатывается: удалить ключ из `authorized_keys` и
  работать по прежнему паролю.
- После отключения `PasswordAuthentication` откат — вернуть `yes` + `reload sshd`
  (нужен уже существующий ключевой доступ, поэтому не отключаем раньше п.5).
