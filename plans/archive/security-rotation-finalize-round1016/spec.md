## 3. Git-гигиена и защита от случайного коммита

- Повторно подтвердить: `git ls-files` и `git log --all -- plans/current_task.md` — пусто.
- Скан истории на секрет (без печати найденного значения):
  - `git log --all -S'GjI3kYf' --oneline` (или иной безопасный маркер из строки пароля) → ожидаем пусто; вывести только факт/счётчик.
  - `git grep -I -n '<маркер>' $(git rev-list --all)` — при необходимости; результат без значения.
- Hardening (лёгкий, без внешних зависимостей): оставить `.gitignore`-запись; при наличии pre-commit — добавить проверку запрещённых путей; не выполнять `git add -f`.
- **Не коммитить** `plans/MEMORY.md` (untracked-изменение) вместе с секретными материалами; сверить `git status` перед коммитом.

## 4. Ротация (вне репо, @DevOps)

1. Сгенерировать SSH-ключ (ed25519) для деплоя; публичную часть положить на сервер (`~/.ssh/authorized_keys`), проверять вход по ключу.
2. После подтверждения ключевого доступа — отозвать/сменить пароль: `passwd nik` (новый сложный) и/или `PasswordAuthentication no` в `sshd_config` + `systemctl reload sshd`.
3. Проверить новый доступ (`ssh -i <key> nik@…`); отчёт **без секретов** (R17): только «ключ установлен/пароль отозван/доступ подтверждён».
4. Деплой-процедура (README) — без плейнтекст-пароля: ключ + `git pull` + `systemctl restart admin_bot`.
