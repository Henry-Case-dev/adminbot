# ADR-1019-2 — Бюджет direct-чата: sentinel «−1 = безлимит», per-chat резолв, изоляция от фон-контура

- **Статус:** Proposed (Step 2 @Architect, раунд 10.19; **итерация 2 — UPD3, 15.09.2026**) → **реализовано (Батч B, @Builder, 15.09.2026) + ревью-фиксы D-1…D-5**, ожидает ревью T-1798. Код: `services/budget_limits.py`, `services/chat_usage.py` (`budget_snapshot`), `services/worker_budget.py` (sentinel + per-chat, AMEND D6), `services/llm_client.py`, `config/settings.py`, `services/param_catalog.py`; тесты `tests/test_budget_unlimited_round1019.py`.
- **Дата:** 2026-09-15
- **Раунд:** 10.19, фича F2 `direct-chat-budget-unlimited` (T-1789) + итерация 2 (T-1853)
- **База:** HEAD `fd6acc7`. **Связано:** F-7 §5.2 (бюджет глобального ключа), F-10 §5.2 (worker budget), ADR-1018-7 (единый резолв настроек), ADR-1013-1 (env-only vs каталог), **ADR-1019-8** (мультичатовость, sentinel-таблица, сид настроек чатов).
- **SUPERSEDE (частично):** **F-15 (раунд 10.3)** в части: «лимиты `limits.chat_global_key_budget_*` — дефолты 25/100k **НЕ меняются**» и «sandbox — штатное поведение при исчерпании». Владелец изменил требование (UPD2 п.1): безлимит по чату + видимые/управляемые бюджеты.**UPD3** дополнительно отменяет идею глобального хардкода безлимита и предыдущие дефолты 300/1,5M (см. D5/D8).
- **AMEND:** дополняется семантика `chat_usage.budget_exceeded`/`key_status`; сохраняется строгий порядок резолва ключа и BYOK-фоллбэк F-15 §3.2. Не supersede F-15 §3.1 (диагностика budget-пути) — она расширяется.

## Context

1. Прод: чат `-1002661910336` получает sandbox-заглушку при `used_calls=25, limit_calls=25` (`reason=budget`), тогда как `used_tokens=699` при `limit_tokens=100000` — исчерпан только лимит вызовов.
2. Владелец в «Сводке» видит лимиты **другого контура** (`worker_budget`, 35/чат) и делает вывод «не превышено» → расхождение восприятия (F3 исправляет отображение).
3. `chat_usage._budget_limit_requests/_tokens` читают **только** `hot.get` (глобальный слой) → per-chat override лимитов **не работал вообще**; «выставить безлимит чату» было негде.
4. F-15 §3.2 зафиксировала порядок `свой → глобал-бюджет → свой-фоллбэк → sandbox` и «дефолты не меняются»; `0 = запрет` — канон F-7.
5. Требование владельца: безлимит **без хардкода** id, отдельный раздел настроек (F3), честные бары «Сводки».
6. Инварианты: R16 (аддитивность), R17 (без секретов), fail-open (PG down → бот жив), порядок роутеров `bot.py`, изоляция контуров direct ↔ фон.

## Decision

### D1. Sentinel-семантика: `0 = запрет`, `<0 = безлимит` (**переиспользует 0, вводит отрицательное**)
Модуль `services/budget_limits.py`: `FORBIDDEN = 0` (сохранён канон F-7/F-15), `UNLIMITED = -1` (любое отрицательное = метрика не ограничена), `budget_state(limit) → 'forbidden'|'unlimited'|'cap'`. «0 = безлимит» **не** используется (обратная совместимость + неоднозначность).

### D2. Per-chat резолв лимитов (обязательный)
`_budget_limit_requests/_budget_limit_tokens` становятся async и принимают `chat_id`; приоритет — **`chat_params.overrides[key]` → `hot.get(key)` (глобальный DB) → env-дефолт** — ровно контракт ADR-1018-7 D1 через `resolve_setting_cached`. Это и есть исправление рассинхрона «ползунки из админки не доходят» для бюджетного контура.

### D3. Безлимит — данные, не код
Механизм включения: запись per-chat override (`chat_params.set_chat_params(chat_id, {"overrides": {…: -1}})`) через `POST /api/config`(+`X-Chat-Id`) или тумблер F3. Хардкод chat_id в коде **запрещён**. Прод-применение для `-1002661910336` — шаг @DevOps/UI.

### D4. Единый снимок + устранение ложного sandbox
`budget_snapshot(pg, chat_id)` возвращает `{exceeded, exceeded_metric, used/limit calls+tokens, unlimited, day}`; `budget_exceeded` — обёртка. **Инвариант:** `exceeded=True` подразумевает определённый `exceeded_metric`; иначе ERROR-лог и `exceeded=False` (**fail-open** — в sandbox без доказанной причины не уходим). `llm_client` формирует `details` из снимка (добавлены `exceeded_metric`, `unlimited`). Порядок резолва и BYOK-фоллбэк F-15 §3.2 сохранены.

### D5. Пересмотр прод-дефолтов (**SUPERSEDE F-15 §6**) — консервативные глобальные + per-chat безлимит
`CHAT_GLOBAL_KEY_BUDGET_REQUESTS` 25 → **100**; `CHAT_GLOBAL_KEY_BUDGET_TOKENS` 100 000 → **500 000**. **UPD3 (итерация 2) SUPERSEDE** ранее предложенных 300/1 500 000: глобальные дефолты — **предохранитель**, безлимит — **только per-chat** (UPD3 п.2). Обоснование: один активный целевой чат получает `−1` данными (сид); остальные чаты защищены умеренным потолком (100 вызовов ≈ 1/10 мин при 16-часовом дне; 500k ≈ 5k×100). Значения применяются через данные (PG) — env-дефолт прод не мигрирует (`ON CONFLICT DO NOTHING`). **Принято в UPD3.**

### D8. Мультичатовая модель и сид настроек чатов (**ADR-1019-8**)
Любой безлимит/политика чата — **per-chat данные**, не смена глобального дефолта и не ветвление по `chat_id` в коде. Целевой чат `-1002661910336` получает `−1` бюджетов через `services/chat_settings_seed.py` + `config/chat_settings_seed.json` (идемпотентный сид). Sentinel-таблица по семействам (бюджет/фон/контекст/retention) — ADR-1019-8 §D2. Изоляция памяти — ADR-1019-8 §D5.

### D6. Изоляция контуров
F2 меняет `chat_usage` (+`budget_limits`/`llm_client` details). `worker_budget` сохраняет **собственные** ключи (`limits.worker_daily_*`) и независимый резолв — правки direct-контура его лимиты не меняют (регресс-тест T-1795).
**AMEND (ревью Батча B, D-1/D-2, 15.09.2026):** `worker_budget` **получает** sentinel `0=запрет`/`<0=безлимит`/`>0=cap` (`budget_limits`) и per-chat резолв (`worker_settings.resolve_setting_cached`, default = `settings.WORKER_DAILY_LLM_*_PER_CHAT` → 60/300 000). Причина: каталог F2 (T-1855) обещает «−1 — безлимит» для фон-ключей, UPD3 п.3 требует безлимит для целевого чата, F3-тумблер пишет `−1` — молчаливая неверная подсказка в UI недопустима. `_metric_limit` стал async; `consume` при `<0` пишет расход и возвращает True (учёт сохраняется).

### D7. Feature flag не вводится
«Безлимит» — персистентные данные чата, не rollout-флаг. Progressive delivery — поэтапно по данным (тестовый чат → остальные). Rollback — `git revert` + снятие override.

### D9. Диагностика снимка и fail-open (ревью Батча B, D-4/D-5)
- `budget_snapshot` во **fail-open** ветке (usage недоступно) сохраняет **вычисленные** `forbidden` и `source=_aggregate_source(None, req, tok)` (не хардкод `False`/`"default"`): `0`-лимит виден независимо от доступности PG, снимок не самопротиворечив. `unlimited=False` (в sandbox без доказанного расхода не уходим).
- `llm_client` берёт `exceeded` **и** `details` из **одного** вызова `budget_snapshot` (ранее — `budget_exceeded` + повторный снимок: 2× резолв лимитов, 2× `used_today`, 2 PG-раундтрипа + TOCTOU).

## Consequences

**Positive**
- Чат больше не уходит в заглушку при живом доступе; владелец управляет лимитом данными/UI.
- `reason=budget` всегда имеет доказанную метрику; ложные ветки диагностируются ERROR-логом.
- Настройки бюджета наконец доходят до воркера (устранён класс дефекта ADR-1018-7 для этого контура).
- Механизм Δ каталога = 0; семантика явная и тестируемая.

**Negative**
- Новый sentinel `−1` требует объяснения оператору (митигируется тумблером F3).
- Лимиты стали async (доп. резолв в горячем пути) — митигируется `resolve_setting_cached` (TTL 120с).
- Повышенные дефолты увеличивают потенциальную стоимость глобального ключа (осознанно; пользователь один, ключ дешёвый).
- Требуется шаг данных @DevOps/UI, иначе безлимит не активируется (env-дефолт прод не меняет).

## Alternatives

- **A1. Отдельный bool-ключ `flags.chat_key_unlimited` (+1 REGISTRY).** Отклонено: дублирует семантику, требует Δ каталога, два источника правды.
- **A2. «0 = безлимит».** Отклонено: ломает канон F-7/F-15 («0 = запрет»), ломает прод-значения и тесты.
- **A3. Хардкод `if chat_id == -1002661910336: unlimited`.** Отклонено владельцем прямо («без хардкода»).
- **A4. Обход бюджета после исчерпания (использовать global всегда).** Отклонено F-15/F-7 (нарушает назначение бюджета); вместо этого — явный безлимит данными.
- **A5. Ретрай бюджета при каждом вызове.** Отклонено: маскирует проблему, лишние запросы.
- **A6. Отдельная таблица per-chat budgets.** Отклонено: `chat_params.overrides` уже является слоем per-chat (ADR-1018-7), DDL не нужен.
- **A7. Поднять только один токен-лимит.** Отклонено: владелец просил «отключить лимиты по чату» — нужна семантика безлимита, а не подгонка числа.
