## 3. Наблюдаемое поведение и отказы

- Карта вызовов показывает **только реально выполненные** этапы прогона; этап без данных → **узла нет** (не подставляется заглушка/фиктивные данные, §24/§25/§30).
- `kind` узла однозначно определяет состав полей: `algorithm` **никогда** не получает LLM-токены/стоимость; `format` показывает состояние форматирования; `publish` не создаётся (GATED).
- Неизвестная стоимость → **«Нет данных»**, никогда выдуманный `$0`; безлимит (`-1`-sentinel) → **«Без лимита»**; «стоимость LLM» и «ресурсы сервера» — разные блоки.
- Связи (`parentIds`) — только подтверждённая линейная последовательность **одного** `run_id`; ветвление без `parent_id` не изобретается; агрегат периода не изображается как точная трассировка.
- Отказ источника (PG down / телеметрия OFF / нет снапшота прогона) → **fail-open**: shape-совместимый пустой граф без ошибок UI; карта показывает «Нет данных».
- Публикационный путь не изменяется и не вызывается.

## 6. D3 — «backend adapter» vs клиентский adapter (ответ (c))

Слой «Backend metrics → Normalized execution graph → UI» (§25) делится строго на три части:

1. **Backend-источник (данные):** аддитивный read-only эндпоинт `GET /api/analytics/execution/latest?run_id=<id>` в существующем роутере `web/api/analytics.py` (global-admin, fail-open). Возвращает нормализованный граф (узлы в каноническом `ExecutionNode`-shape + блок §112-метрик).
2. **Backend-нормализация:** **отдельный** чистый модуль `services/execution_graph_source.py` (NEW) — «raw sources → canonical nodes»; без DDL, без побочных эффектов, тестируется изолированно. **Преобразование API-ответов не размещается внутри SVG/Vue-компонента** (§25).
3. **Клиентский нормализатор:** `web/static/execution_graph.js` получает `fromExecution(payload)` (аддитивно к `fromTrace`/`fromSummary`) и расширенный `STEP_KIND`/`STEP_LABEL`; рендер (`tokenFlowTree` в `web/app.js`) — **view-проекция**, как в F6.

- **Вторая визуализация запрещена:** единственный контур `.token-flow*`/`ExecutionGraph`; `GraphViewer`/`NodeCard`/`DetailPanel` **не переписываются** — допускаются только аддитивные подписи/стили kind-узлов.
- **R16:** «не плодить API» трактуется как запрет лишних поверхностей; **один** аддитивный read-only эндпоинт — минимальная реализация §111 «Расширить backend adapter».
- **Альтернатива (отклонена):** расширять `/analytics/usage/latest` полем `graph` — смешивает семантику «последний вызов любого модуля» и «граф Саммари» (последний `correlation_id` ≠ последний прогон Саммари); отдельный эндпоинт чище и не меняет контракт F6.
- **Альтернатива (отклонена):** переносить всю нормализацию на клиент — тогда filter/format-узлы недоступны (их нет в `/analytics/*`); серверная нормализация использует реальные источники.

## 9. D6 — агрегаты/режимы (ответ (f))

- **Режим «последний вызов»** — конкретная цепочка одного `run_id` (узлы + связи-последовательность).
- **Режим «период»** — агрегат (`/analytics/usage/summary`) с раскрытием; агрегатные узлы `parentIds=[]`, `status='unknown'`; **агрегат не изображается как точная трассировка** (§25).
- Режимы **не смешиваются**; агрегат не берётся из трассировки и наоборот.
- **Нет `parent_id` → нет связи:** ветвление не достраивается; допускается только подтверждённая линейная последовательность одного `run_id` (предыдущий реальный этап); при отсутствии предшествующего этапа — `parentIds=[]`.
- Пусто → «Вызовов ещё не было» / «За период данных нет».

## 14. Приёмочные сценарии (SC)
