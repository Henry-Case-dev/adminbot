## 1. Цель

Старая БД не должна загрязнять новые пайплайны. Пересобирается **только сгенерированный мусор**:
- **Ребилд досье:** `manage.py memory rebuild-dossiers` — **боевая пересборка сразу** (дефолт `apply`, без обязательного dry-run)
  и пересборка профилей через пайплайн F1.
- **Санитария:** мусорные факты без связей вычищаются, убеждения перепроверяются валидатором,
  галлюцинации удаляются.
- **⛔ ЖЁСТКИЙ ИНВАРИАНТ (строка 143):** импортированные сообщения (сырая история чата — `smart_messages`
  и её FTS) **НЕ удаляются ни при каких обстоятельствах**. Только производные (досье-факты/мемы, убеждения,
  парадигмы, галлюцинации).
- **Ручные `persona_dossier_overrides`** — неприкосновенны (строка 142); `--include-overrides` по умолчанию выключен.

## 3. Контракт CLI

```
python manage.py memory rebuild-dossiers [--chat ID] [--all]
        [--include-overrides] [--dry-run]      # --dry-run опционален
        [--db PATH] [--limit N] [--batch N] [--allow-target-chat]

python manage.py memory sanitize-beliefs [--chat ID] [--all]
        [--dry-run] [--db PATH] [--limit N] [--batch N]
        [--allow-target-chat]

python manage.py memory consolidate     [--chat ID] [--dry-run] ...   # F4
```

- **Группа:** `memory` с `dest="memory_command"` (argparse sub-subparsers, по образцу `build_parser`).
- **Дефолт — боевой `apply` (UPD):** команда выполняет реальную пересборку/санитарию сразу. `--apply` как
  обязательный флаг и обязательный dry-run **отменены**. `--dry-run` остаётся **опциональной** диагностикой.
- **`--chat` обязателен** для ребилда/санитарии (без `--all`) — защита от «случайно всё».
- `--all` **исключает** целевой чат `-1002661910336`; для него нужен явный `--chat <id>` + `--allow-target-chat`.
- `--include-overrides` (default OFF) — ручные `persona_dossier_overrides` сохраняются; перезапись — только с флагом.

### 3.1 Жёсткие инварианты и страховочная сетка (UPD)

1. **⛔ Инвариант сырой истории:** ни одна ветка (rebuild/sanitize/consolidate) не выполняет `DELETE`/`UPDATE`
   по `smart_messages` и её FTS-слою, а также по импорт-источникам сырой истории. Мутации ограничены
   allowlist'ом **сгенерированных** производных (`graph_facts`, `edges`, `belief/paradigm`-записи).
   Guard-проверка перед DELETE: таблица ∈ allowlist, иначе операция отменяется (abort).
2. **Ручные `persona_dossier_overrides`** — неприкосновенны; перезапись только явным `--include-overrides`.
3. **Авто-бэкап** (Backup API → `MEMORY_BACKUP_DIR`, `flush+fsync`) — автоматический, синхронный шаг **до**
   любого DELETE (страховка, а не dry-run).
4. **JSONL-архив удаляемых сгенерированных строк** — автоматический синхронный шаг; сверка
   `candidates == archived`, иначе операция отменяется (модель `_archive_imported_history` retention).
5. Живой бот: `initialize_existing()` без DDL/WAL-конфликта (`manage.py:694`).
6. **Никаких авто-кронов и HTTP-триггеров**; только ручной запуск.
7. Схема БД **не меняется** (SQLite v12).

## 4. Алгоритмы

### 4.1 `rebuild-dossiers`
1. **Сброс сгенерированного мусора:** удалить/заархивировать **только** `graph_facts` со `status='chat_meme'`
   **и `status='dossier_portrait'`** (портрет Слоя Б F1 — производная строка `graph_facts`) для чата —
   артефакты старого однопроходного пайплайна и устаревшие персональные портреты.
   **`smart_messages`/импорт-историю не трогаем (инвариант §3.1.1).**
   `persona_dossier_overrides` не трогаем (если не `--include-overrides`).
2. **Пересборка:** прогнать двухслойный пайплайн F1 по окну сообщений заново (per participant),
   записать валидные `chat_memes` **и персональные портреты** (`graph_facts.status='dossier_portrait'`,
   `belief_meta.patterns/themes`, ключ chat+target — см. F1 spec §3.2.1); ручные overrides имеют приоритет
   над сгенерированным портретом.
3. **Идемпотентность:** повторный прогон не плодит дубли (существующие `db.meme_exists`/дедуп F1;
   портрет — идемпотентный `upsert_generated_dossier`).
4. Отчёт: `{chat, scanned, reset, reset_portraits, rebuilt, skipped, reasons}`.

### 4.2 `sanitize-beliefs`
Работает **только со сгенерированными производными**; сырую историю не читает и не мутирует (§3.1.1).
1. **Факты без связей:** `graph_facts`, у которых нет инцидентных `edges` (`edges.fact_id`), исключая
   protected и `kind IN ('belief','paradigm')`; bounded-выборка.
2. **Валидатор убеждений (count-agnostic):** для `belief_meta.type IN ('belief','paradigm')`:
   валидный JSON `belief_meta`, непустой текст, `source_ids`/`evidence` ссылаются на существующие
   `graph_facts.id`. Невалидные → кандидаты на удаление.
3. **Галлюцинации:** `source_ids`, которых нет в БД; `chat_meme.target`, которого нет в ростере участников.
4. Отчёт с причинами по каждому классу (R17: без текстов, только id/класс/count).

## 5. Данные и миграция

- **Схема НЕ меняется** (SQLite остаётся **v12**); только `DELETE`/архивация **сгенерированных** данных.
- **⛔ Сырая история неприкосновенна:** `smart_messages` (+FTS)/импорт-источники не удаляются и не изменяются (§3.1.1).
- Объём БД ~724 МБ: только `LIMIT`/`--limit`-батчи, никакого полного скана в event loop; CLI — офлайн-процесс.
- **Откат:** восстановление из авто-бэкапа + JSONL-архив удалённых **сгенерированных** строк (точечный restore).
- R16/R17: логи — counts/классы; никаких секретов и текстов.

## 6. План тестов

1. **Инвариант сырой истории:** после боевого прогона `rebuild-dossiers`/`sanitize-beliefs` число строк
   `smart_messages` и её FTS не изменилось; SQL-трасса не содержит мутаций `smart_messages`.
2. **Guard allowlist:** попытка DELETE по таблице вне allowlist → abort (тест защитного слоя).
3. Идемпотентность (двойной прогон → 0 изменений на втором).
4. Восстановление из бэкапа + JSONL (точечный restore сгенерированных строк).
5. Guard: целевой чат не затрагивается при `--all`; без `--allow-target-chat` отказ.
6. Ручные `persona_dossier_overrides` не перезаписываются без `--include-overrides`.
7. Валидатор убеждений count-agnostic (синтетические фикстуры 0/N/36+).
8. Регрессии: retention-контур не сломан.
9. **Портрет Слоя Б (UPD раунд 10.21, Issue 1):** боевой `rebuild-dossiers` сбрасывает
   `graph_facts.status='dossier_portrait'` (архив+guard, `reset_portraits` в отчёте), затем пересобирает
   ровно одну строку на участника; ручные overrides при этом сохранены; `--dry-run` считает портреты в `reset`,
   но не удаляет.

## 7. Риски и откат

- **R1 необратимая потеря данных** — боевой прогон без dry-run; страховка: авто-бэкап, JSONL-архив,
  guard целевого чата, allowlist-проверка «только сгенерированные таблицы».
- **R2 факт-ошибка `user_dossier`** — работаем с реальными таблицами (§2).
- **R3 объём/диск** — батчи, офлайн, проверка свободного места перед боевым прогоном.
- **R4 зависимость от F1** — ребилд стартует только после готовности F1.
- **R5 неприкосновенность сырой истории** — инвариант §3.1.1, тесты №1/№2 §6.
- **R6 v12** — DDL нет; FTS/vec-строки удаляются только вместе с **сгенерированными** фактами осознанно (сверка count).
- **Откат:** бэкап; схема не менялась.
