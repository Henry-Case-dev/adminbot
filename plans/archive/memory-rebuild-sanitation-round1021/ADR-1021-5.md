# ADR-1021-5 — Деструктивный CLI `manage.py memory` (rebuild-dossiers / sanitize-beliefs): безопасность

- **Статус:** **Accepted** (по решению владельца, UPD после Human Gate, раунд 10.21)
- **Дата:** 18.09.2026, раунд 10.21
- **Контекст:** F5 `memory-rebuild-sanitation-round1021`, T-1980…T-1989
- **Связано:** ADR-1019-6 (retention), ADR-1021-1 (пайплайн F1), ADR-1021-4 (консолидация)

## 1. Контекст

Нужна процедура пересборки досье и санитарии фактов на БД ~724 МБ / ~2M строк при живом боте.
Команды `manage.py memory` в проекте НЕТ; таблицы `user_dossier` НЕТ. Есть прецедент `manage.py retention`
(снапшот Backup API + архив до DELETE). Из него F5 берёт **обратимость** (бэкап/архив), но **не** обязательный
dry-run и env-подтверждения (UPD разрешил боевую миграцию сразу).

## 2. Решение (UPD: деструктив разрешён без холостых прогонов)

1. Новая argparse-группа `manage.py memory` с подкомандами `rebuild-dossiers`, `sanitize-beliefs`
   (+ `consolidate` из F4).
2. **Политика выполнения (изменена UPD):**
   - **дефолт — боевой `apply`**: команда выполняет реальную пересборку/санитарию **сразу**;
   - **обязательный dry-run ОТМЕНЁН**; двойные env-подтверждения (`MEMORY_REBUILD_ENABLED`,
     `MEMORY_REBUILD_BACKUP_CONFIRMED`) как обязательные **ОТМЕНЕНЫ**; `--dry-run` — опциональная диагностика;
   - **⛔ ЖЁСТКИЙ ИНВАРИАНТ: сырая история не удаляется.** `smart_messages` (+FTS) и импорт-источники
     сырых сообщений не мутируются ни в одной ветке и ни при каких обстоятельствах. Пересобирается/чистится
     только **сгенерированный** мусор (`graph_facts.status='chat_meme'`, убеждения/парадигмы, галлюцинации);
     перед DELETE — guard «таблица ∈ allowlist сгенерированных», иначе abort;
   - **страховочная сетка (не dry-run, тихий автоматический шаг):** авто-бэкап (Backup API + fsync)
     **до** любого DELETE + **JSONL-архив** удаляемых сгенерированных строк со сверкой `candidates == archived`;
   - **guard** целевого чата `-1002661910336`: не входит в `--all`, требует явного `--chat` + `--allow-target-chat`;
   - **никаких авто-кронов и HTTP-триггеров**; только ручной запуск;
   - схема БД НЕ меняется (SQLite v12).
3. **Count-agnostic валидатор убеждений** («36» не хардкодим).
4. **Ручные `persona_dossier_overrides`** сохраняются, если не передан `--include-overrides` (default OFF).

## 3. Обоснование

- Retention (ADR-1019-6) дал рабочий паттерн **обратимости** (снапшот + архив до DELETE). Из него берём
  авто-бэкап и JSONL-архив; обязательный dry-run и тройной env-гейт **не переносим** — владелец разрешил
  деструктивную миграцию на проде сразу (UPD, строка 140).
- Sleep-time compute / offline consolidation: ошибочная запись в память становится «истиной» → перезапись
  должна быть **обратимой и проверяемой** (авто-бэкап/архив/валидатор), что и обеспечивается без dry-run
  (https://arxiv.org/pdf/2504.13171, https://arxiv.org/html/2605.20616).
- Инвариант «сырую историю не трогаем» отделяет необратимо ценное (импорт чата) от восстанавливаемого
  сгенерированного слоя — это главный принцип безопасности F5.

## 4. Альтернативы

| Альтернатива | Вердикт |
|---|---|
| Django-style management command | В проекте argparse (`manage.py:476`); не ломаем стиль. |
| Работа на копии БД с подменой боевой | Долго (724 МБ), риск рассинхрона и простоя. |
| Авто-крон раз в сутки | Деструктивно и непредсказуемо; отклонено. |
| Удалять без архива | Нет обратного пути; отклонено. |
| Обернуть всё в feature-flag | Флаг не защищает от деструктива; защищают CLI-гейты/бэкап. |

## 5. Последствия

- Δ каталога = 0 (env-темы вне каталога; флагов нет).
- Runbook @DevOps (упрощён): (авто)бэкап → боевой `rebuild-dossiers`/`sanitize-beliefs` →
  post-check counts + проверка, что `smart_messages` не изменился → при сбое restore из бэкапа/JSONL.
- R16/R17: вывод — counts/классы, без путей/текстов/секретов.

## 6. Решения Human Gate (UPD)

- **Д13 → да:** деструктивная миграция на проде разрешена (UPD владельца, строка 140).
- **Д14 → живой прогон:** без обязательного снапшот-превью; страховка — авто-бэкап + JSONL до DELETE; WAL на живом боте.
- **Д15 → count-agnostic:** «36 убеждений» не хардкодим, состав мусора — по итогам аудита F4.
- **Д16 → `--include-overrides` default OFF**; ручные правки досье неприкосновенны (строка 142).
- **Главное (строка 143):** сырая история (`smart_messages`/импорт) не удаляется ни при каких обстоятельствах.

## 7. UPD раунд 10.21 (Issue 1 High) — сброс сгенерированных портретов Слоя Б

F1 персистит персональный портрет как производную `graph_facts.status='dossier_portrait'` (F1 spec §3.2.1,
ADR-1021-1 §8). Чтобы `rebuild-dossiers` не оставлял устаревшие портреты после пересборки, шаг сброса
расширяется: помимо `status='chat_meme'` архивируются и удаляются `status='dossier_portrait'` того же чата —
**тем же** контуром безопасности (авто-бэкап, JSONL-архив + сверка `candidates == archived`, guard
`assert_derived_table('graph_facts')`). Новых таблиц/флагов нет (Δ каталога = 0, схема v12).
`sanitize_beliefs` портреты не трогает (классы `orphan_fact`/`invalid_belief`/`hallucination` их не включают).
Отчёт получает счётчик `reset_portraits`; `--dry-run` их только считает. Ручные `persona_dossier_overrides`
не затрагиваются (как и раньше — только под `--include-overrides`).
