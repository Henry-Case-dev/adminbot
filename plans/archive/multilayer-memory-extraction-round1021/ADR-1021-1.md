# ADR-1021-1 — Двухэтапная экстракция памяти: Слой А (Thinker) + Слой Б (Synthesizer)

- **Статус:** **Accepted** (UPD владельца после Human Gate, раунд 10.21)
- **Дата:** 18.09.2026, раунд 10.21
- **Контекст:** F1 `multilayer-memory-extraction-round1021`, T-1943…T-1952
- **Связано:** ADR-1013-3 (канон-миграции), ADR-1020-7 (reasoning/strip), F2 (grounding), F5 (rebuild)

## 1. Контекст

`LoreWorker._classify_dossier` (`services/lore_worker.py:526`) делает **один** LLM-вызов и раскладывает окно
по `real_facts`/`chat_memes`. Из-за отсутствия стадии рефлексии и явного entity resolution в досье попадают
копипасты (Тяньаньмэнь), чужие имена («Кирилл» у Никиты) и шутки («инструкции Васи»). Класса
`PersonalityExtractor` и таблицы `user_dossier` в коде НЕТ (факт-ошибки ТЗ).

## 2. Решение

Ввести **двухслойный пайплайн внутри воркера**:

- **Слой А (Scratchpad/Thinker)** — LLM-вызов #1, temp 0.2. Выдаёт строгий JSON
  `{"candidates":[{target,kind,text,evidence,confidence,reason}],"discarded":[...]}`.
  `kind ∈ {person_fact, meme, quote, copypasta, other_person, noise}`.
  Это «System 2»: он думает и фильтрует, но не вербализует для пользователя.
- **Фильтр** — Python: `kind=person_fact` требует непустой `evidence` (номера строк окна) и имени из ростера.
- **Слой Б (Synthesizer)** — LLM-вызов #2, temp 0.2. Вход — только отфильтрованное; выход —
  `portraits:[{target,portrait,patterns,themes}]`/`memes` **без дословных цитат** (валидатор: verbatim-подстрока
  окна > 6 слов отклоняется). Атрибуция по `target` обязательна: досье персональное (UPD Issue 1).

Запись `chat_memes` в `graph_facts.status='chat_meme'` остаётся прежней; `real_facts` не дублируем.
Запись **портретов** — производные `graph_facts.status='dossier_portrait'` (UPD Issue 1, §8).

## 3. Обоснование (research)

- Mem0/LangGraph: память строится как отдельные узлы извлечения и обновления, а «что достойно памяти»
  решает отдельный классификатор (https://mem0.ai/blog/... , https://arxiv.org/pdf/2504.19413.pdf).
- Talker-Reasoner: развести медленное формирование убеждений и быструю вербализацию
  (https://arxiv.org/pdf/2410.08328v1).
- PLaT: Planner и Decoder как разные модули (https://www.alphaxiv.org/overview/2601.21358).
- MemR3: явный промежуточный state (evidence/gap) — делает процесс объяснимым и тестируемым
  (https://arxiv.org/pdf/2512.20237).

## 4. Рассмотренные альтернативы

| Альтернатива | Почему отклонена |
|---|---|
| Улучшить один промпт `DOSSIER_SYSTEM_PROMPT` | Нет явного entity resolution и нет проверяемого intermediate-артефакта; эффект недоказуем. |
| Отдельный сервис-класс `PersonalityExtractor` (как в ТЗ) | Такого класса нет; вводить параллельный пайплайн = дублирование записи `graph_facts`. |
| Второй проход отдельной «reasoning»-моделью | Провайдер может не отдать `reasoning_content`; жёсткая зависимость от модели недопустима. |
| Писать `real_facts` в новую таблицу | DDL/миграция на БД ~724 МБ; смена контракта досье — вне скоупа. |

## 5. Стоимость и деградация

- **Стоимость ×2** вызова на прогон классификации. Митигация: единый прогноз A+B через
  `worker_budget`/`_budget_ok` (`lore_worker.py:461-467`), кап окна `limits.lore_window_max_chars`,
  аварийный env-kill-switch `MULTILAYER_EXTRACTION_ENABLED` (default **ON**).
- **Кэш:** промежуточный артефакт НЕ кэшируется между прогонами (окно меняется); кэшируем только
  существующий `db.meme_exists` (идемпотентность записи).
- **Fallback Слоя А:** невалидный JSON/ошибка после 1 retry → WARNING + путь 10.20 (single-pass).
- **Детерминизм:** только чистые парсеры/фильтры в Python; LLM-стадии не пишут в БД.

## 6. Последствия

- Пайплайн **включён по умолчанию, без раскатки** (UPD). Новых каталожных флагов нет: **Δ каталога = 0**
  (REGISTRY/Settings/categorized/GROUPS/mapped/TAB_RULES — без изменений).
- Единственный рубильник — **env-only ClassVar** kill-switch `MULTILAYER_EXTRACTION_ENABLED` (default ON,
  вне каталога, прецедент retention-гейтов `settings.py:483-497`).
- Kill-switch OFF-путь обязан быть байт-совместим с 10.20 (регресс-тест на аварийном откате).
- **Д3:** портрет F1 не перезаписывает ручные `persona_dossier_overrides`; обновляются только генерируемые производные.
- R17: логи — `chat_id`, counts, `kind`, длины; без текстов.
- Откат: аварийно — env-kill-switch; полноценно — `git revert` (схема БД v12 не меняется).

## 7. Решения Human Gate (UPD)

- **Д1/Д2 → ON по умолчанию без раскатки** (строка 117): безусловная активация, откат `git revert`.
- **Д3 → ручные overrides неприкосновенны:** портрет не перезаписывает `persona_dossier_overrides`.
- **Д4 → метрика доли `discarded`** сохраняется как наблюдаемость (без гейта-блокировки прогона).

## 8. UPD раунд 10.21 (Issue 1 High) — персистенция портрета Слоя Б

### 8.1 Проблема
`validate_layer_b` (`services/dossier_prompts.py:431`) вычислял `portrait`/`patterns`/`themes` и отдавал их
дальше, но `_classify_dossier_multilayer` писал только `chat_memes`. Портрет **нигде не сохранялся и никем не
читался**; F5 `rebuild_dossier_for_chat` его тоже не персистил. F1 заявлен как «Слой Б — Синтезатор», но
доставлял ноль портрета → требование владельца «Досье содержит психологический портрет и паттерны» не выполнено.

### 8.2 Решение (нулевой DDL)
- **Per-target контракт Слоя Б** (`portraits[]`, §2): без атрибуции персональное досье невозможно.
- **Хранилище:** строка `graph_facts` `status='dossier_portrait'`, `kind='fact'`, `origin='chat_history'`,
  `target_user`=канон-имя, `fact`=портрет (≤600), `weight=0.3`,
  `belief_meta={generated:true,generator:"layer_b",contract_version:1,patterns,themes,updated_at}`.
  Колонка `status` — свободный TEXT без CHECK (прецедент `chat_meme`/`archived_belief`) → **Δ DDL = 0**,
  `user_version` остаётся **12**. Владелец по-прежнему требует «без нового DDL».
- **Изоляция:** статус `≠ 'confirmed'` отсекает строку от FTS-RAG/KNN/`get_persona_card`/`get_persona_names`/
  `get_dream_candidates`/`list_chat_memes`/`_list_orphan_facts` — зеркально мемам.
- **Идемпотентность:** `upsert_generated_dossier` — `SELECT` по (chat,target,status) → FTS-safe `UPDATE` либо
  `insert_graph_fact`; ровно одна строка на участника.
- **Читатели:** `web/api/chat_lore.py::_dossier_payload` (модалка досье) и
  `direct_chat_service.build_persona_card` (`/persona`); UI — `web/index.html`.
- **Merge:** `persona_dossier_overrides` (ключ `user_id`) не перезаписываются; при чтении
  `portrait_source='manual'` при непустой ручной правке, иначе `'generated'`.
- **Удаление при rebuild:** F5 сбрасывает `dossier_portrait` вместе с `chat_meme` (архив/guard/бэкап).

### 8.3 Обоснование
- Модель «второй проход синтеза портрета, хранимый как отдельная производная» согласуется с Mem0
  (extraction → update, отдельный узел памяти) и Talker-Reasoner (Reasoner формирует паттерны, хранит их
  отдельно от вербализации). Persist-контракт на существующей таблице — минимальная стоимость и ноль миграции.

### 8.4 Рассмотренные альтернативы персистенции
| Альтернатива | Почему отклонена |
|---|---|
| Новая таблица `user_dossier` / новые колонки | Запрещено (новый DDL, `user_version` 12). |
| Писать портрет в `persona_dossier_overrides` | Нарушает `manual-overrides-immutable`: затрёт ручные правки. |
| `kind='dossier_portrait'` | CHECK колонки `kind` допускает только `fact`/`belief`; `insert_graph_fact` нормализует → нельзя. |
| Портрет безадресно (один на окно) | Не ложится в персональное досье (кейс «Никита/Кирилл»); не решает Issue 1. |
| `status='confirmed'` с новым `origin` | Утечёт в RAG/карточку как обычный факт; исказит досье. |
| Хранить только в in-memory/логах | Именно текущий баг: нечего читать потребителю. |
