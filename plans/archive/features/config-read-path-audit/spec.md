# Аудит read-путей конфигурации (F-5)

## Контекст и цель

Требование 01.09.2026 (MEMORY.md): все параметры админки должны РЕАЛЬНО влиять на поведение — аудит мест чтения `settings.X` напрямую вместо `hot.get`, верификация через /debug_config. Массовая миграция read-путей выполнена (коммит `6156047`, 02.09). Остаток: точечный аудит прямых чтений, import-time чтения и сквозная верификация.

## Архитектурные привязки

- **84.4** — ConfigCache/hot_config: `hot.get(key, default)` (кэш → PG → дефолт).
- **84.12** — param_catalog (265 записей, кастинг по типу).
- **84.18/84.20** — /debug_config (дамп из RAM, формат `key = value`) — инструмент верификации.

## Границы

T-651/T-652 (унификация кастов `_cast_to_type`/`_coerce`/`_coerce_value` и каст default на cache-miss) живут в **F-1** (`features/post-deploy-admin-minors/`) — здесь только ссылки, задачи НЕ дублируются. Прямые чтения, которые осознанно остаются (дефолт/не-горячие значения), фиксируются пометкой.

## Связи с другими фичами

- F-1 — T-651/T-652 (дом кастов).
- F-2 — /debug_config как инструмент проверки.
- F-4 — баг тумблеров (причина — read-пути).

## Критерии готовности

- Grep-аудит `settings\.` по рантайм-пути завершён: каждое прямое чтение мигрировано ИЛИ осознанно оставлено с пометкой.
- Import-time чтения (декораторы/инициализация, пример alan.py `UserIdFilter(hot.get(...))`) вынесены за cache.init или зафиксирована фолбек-семантика.
- Сквозная проверка: изменение параметра в админке → `/debug_config <ENV_NAME>` показывает новое значение.
- Тесты test_hot_config/test_config_cache/test_hot_migration + полный pytest — 0 failed.
