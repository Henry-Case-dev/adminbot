## Решения

**D1. Один фактчек-контур; envelope — новый DTO, не расширение mca-22.** Единственный resolver/service — существующий `FactCheckService` (`services/factcheck_service.py::check_claim:79`); все входы (команда/reply, tool `fact_check`, авто, ручной UI) проходят один resolver (`services/temporal_factcheck.py` — NEW-модуль моделей, вызываемый единственным сервисом; **не** второй пайплайн, план `:211`). Код-символ — **`TemporalClaimEnvelope`**: grep установил, что `ClaimEnvelope` занят mca-22 (`services/claim_envelope.py`, ADR-1028-6 D4/D5 — конверт атрибуции личных фактов; потребители `canonical_messages`/`quote_resolver`/`mca_retrieval_context`); термин ТЗ «ClaimEnvelope» сохраняется (`:1763`, A72 `:953`, ADR-1028-19 D11). DTO mca-22 не расширяется — разные домены (**CA-20-14**, сверх CA-20-1…13 PM). Поля — ровно §30.1 `:1763`; envelope иммутабелен, один объект идёт через analyst → validator → verbalizer и все fallback (`:1793`, A72).

**D2. Канонические метаданные + серверная валидация scope.** Источники: Origin-блок v32 mca-19 (`origin_type`/`origin_sent_at`, включая `hidden_user`), MessageRef/revision mca-03, MediaAnalysis по замороженному контракту ADR-1028-19 D11 через SourceRef mca-04a; свой vision не запускается, OCR-даты = extracted_claimed (недоверенный канал, `:1778`, CA-20-6). Модель выбирает только target reference текущего чата; сервер проверяет chat scope/доступ и собирает envelope; невалидно → `temporal_envelope_rejected` без выдуманных подстановок (CA-20-7/12). Свободный текст → `free_text` + explicit unknown origin — даты/message не придумываются (`:1765`). Внутренний tool loop фактчекера не вызывает `fact_check` рекурсивно: стадии — data-only без инструментов (mca-18 spec §5 D6) + серверный depth-guard.

**D3. Схема v33: durable run + evidence.** `mca_factcheck_runs` (run_id PK, access_scope, chat/trigger/target, target_revision/content_hash, claim_text/span, source_type CHECK, attribution, origin_type, repost_received_at, original_published_at + precision, claim_period, date_source, date_timezone, date_uncertainty, requested/assessment_mode, analysis_as_of, related_asset_id + related_analysis_revision, factual_verdict CHECK, temporal_status CHECK, evaluated_period, verdict_text/uncertainty, stage_trace, fallback_used, cache_hit, pipeline_version, tz_resolution_version, reason, revision, времена) + `mca_factcheck_evidence` (run_id, claim_part, url, support, source_ref JSON, published_at + published_at_source, retrieved_at, temporal_relevance, relation, source_kind) + 3 индекса. **Δ DDL = v33 (не 0):** A73 требует виджет/trace на реальных запусках — durable записи с периодами, честным provenance и scope-доступом; события mca-13 не годятся (payload-раздувание, R17-риск, нет выборки по scope); JSON-блоб убил бы права/выборку. Аддитивно/идемпотентно через реестр mca-14 + backup-guard; повторный прогон — no-op; PG — **no-op** (`pg_db.py` вне diff, GEN-R4).

**D4. Каскад дат и пять времён.** Раздельно: доставка в чат ≠ дата оригинальной публикации ≠ заявленное время события ≠ дата веб-публикации ≠ время проверки; `forward_origin.date` — дата исходника пересылки, не дата события (`:1771`). Приоритет `date_source`: telegram_origin (все MessageOrigin; hidden_user имеет date) → telegram_message → publication_metadata (`updated_time`/Last-Modified/snippet ≠ publication time без проверки) → extracted_claimed (не повышать над Telegram молча; конфликт показать; EXIF ≠ публикация) → unknown (NULL/интервал/точность; `now` не подставлять) (`:1775–1779`).

**D5. Периоды, относительные даты, TZ.** Период утверждения важнее даты публикации («в 2019…» → 2019); «сегодня/вчера/завтра» — относительно автора фрагмента и его публикации, не пересылки; вложенная цитата — своя дата; неизвестный TZ → интервал пограничных суток; UTC-хранение и TZ чата — разные задачи (`:1781`).

**D6. Четыре режима; ретроспектива помечается.** `contextual` (дефолт) / `current` / `historical_truth` / `knowable_at_time`; явные просьбы разрешаются при сборке envelope («это сейчас правда?» → current; «было ли верно тогда?» → historical_truth; knowable — только явно; дефолт владельца — каталог). historical_truth допускает позднее расследование с явной меткой ретроспективы; смешивать с «что автор знал тогда» запрещено (`:1783`, A71).

**D7. Декомпозиция, search, evidence.** Части с собственными периодами; числа — REUSE `NumericClaim`/`MetricResult` mca-15 (второго числового контура нет, CA-20-3); запросы — сущность+событие+временные ограничения, не только date filter; поисковый инструмент — существующий `execute_web_search` (REUSE, `:1761`). Evidence: URL, support, published_at (+происхождение), retrieved_at, temporal relevance, отношение к части; SourceRef — форма mca-04a (без записи в `mca_evidence_links` — вердикт не личный факт); нет результатов → `insufficient_evidence`; исчезнувший первоисточник → `temporal_source_unavailable` (CA-20-10, no-false-acceptance); URL — через существующий fetch/SafeFetcher mca-02.

**D8. `TemporalVerdict` — раздельные оси.** factual_verdict (supported/refuted/mixed/insufficient_evidence) ≠ temporal_status (current/outdated/old_but_valid/misleading_reuse/unknown) + evaluated_period + assessment_mode + as_of + evidence_refs + uncertainty (`:1791`); один неверный элемент ≠ весь пост ложный (части указываются); в аналитику — объяснимые основания, без скрытой цепочки рассуждений. `misleading_reuse` — только при признаках предъявления старого за новое; пересылка ≠ намерение (CA-20-11).

**D9. Кеш: составной ключ, legacy вне namespace, bypass.** AMEND `handlers/factcheck.py:268` + `services/smart_cache.py:47`: новый slug **`factcheck_temporal`**, ключ — каноническая сериализация scope + canonical claim/span + target revision/content_hash + origin fingerprint + режим+период + tz_resolution_version + MediaAnalysis revision + evidence/pipeline version + freshness bucket (для current) (`:1795`). Legacy slug `factcheck` на ON-пути не читается/не пишется (namespace сменился без удаления несвязанных кешей, `:1797`; OFF-откат продолжает легаси-путь бит-в-бит). Unknown origin → корректный ключ невозможен → **авто-bypass** (вычислять без кеширования вердиктов, reason `temporal_cache_disabled`); кеш поиска/загрузок сохраняется; ручной аварийный OFF — kill-switch. as_of внутри payload — hit не получает сегодняшнюю дату (CA-20-9). Атрибутированный ответ не разделяется между сообщениями при неизвестном происхождении (CA-20-8).

**D10. Freshness — политика поверх кеша, не второй closure.** Buckets volatile (current; короткий TTL) / stable (исторический; длинный TTL, инвалидация при новых материалах/правках через target revision/content_hash в ключе). Механизмы mca-22 (`response_freshness`) и mca-04a (`freshness_status`) не дублируются и не расширяются (CA-20-5); mca-20 не пишет в provenance-status. `TEMPORAL_TZ_RESOLUTION_VERSION="tzr1"` — версия алгоритма TZ/границ суток в ключе и записи; bump выпадает старые вердикты естественно.

**D11. UI/trace — существующие поверхности.** Виджет в «Аналитике» (routes +2: список/детали runs; RBAC — прецедент `/api/random/test`; `ROUTES_SHA256_F11` переутверждение — прецедент mca-19): timeline original/repost/claim/as_of, «почему эта дата» (date_source+uncertainty+каскад), evidence-карточки с периодами, cache hit/version, OCR uncertainty, branches/fallback; просмотр под правами. Настройки — вкладка `mod_factcheck` (дефолт режима, 2 TTL freshness, tool-тумблер); «provider/tool availability» = tool-тумблер (отдельного провайдера у фактчека нет, GEN-R2). Витрина — последнее событие (mca-12); нового раздела нет. Trace — процесс `temporal.factcheck` **v0→v1** (AMEND плейсхолдера `mca_process_registry.py:1134–1140`, прецедент `vision.analyze v0→vision.media v1`), 8 стадий `:1805`, события `factcheck_temporal` (id/коды/refs, R17); widget_id «Временной фактчек» — контракт mca-17c. Дата-ошибка (`temporal_date_extract_failed`) ≠ дата-отсутствие (`temporal_date_unknown`); fallback не меняет historical↔current без явного статуса (`temporal_fallback_mode`).

**D12. Границы.** mca-04a — форма SourceRef, не второй механизм валидности (CA-20-2); mca-15 — числа, статистика ≠ вердикт (CA-20-3); mca-16 — lessons не верифицируются (CA-20-4); mca-19 — контракт D11 потребляется, пиксели не читаются (CA-20-6); mca-22 — closure не дублируется (CA-20-5); mca-18 — сначала вердикт, затем стиль; BehaviorFrame после TemporalVerdict; analyst/validator — data-only (CA-20-13). mca-01 `write_transaction` для v33-записей; mca-13 reason аддитивно; mca-02 SafeFetcher для URL; mca-11 — cache hit 0 токенов, `fact_check` метричный; новый провайдер/аккаунт запрещены (GEN-R2); SQLite+PostgreSQL не меняются, скачивание/транскрибация/выжимка не тронуты (GEN-R18 `:1811`).

## Последствия

- Позитив: старый репост проверяется в своём временном контексте; «тогда было верно» ≠ «фейк»; честный кеш (не text-only), честные даты/неопределённости, честный insufficient_evidence; наблюдаемость (run/evidence/trace) для mca-17c/mca-12/mca-21.
- Негатив/цена: v33 (+2 таблицы, 3 индекса), F8-переиздание (+4/+1), 3 kill-switch, +10 reason, тул 14-й; durable-записи run — рост БД (политика хранения — существующий контур).
- Откат: soft (env) без потери данных; cold revert безопасен (аддитивная схема); legacy-кеш жив для OFF-пути.

R17: секретов в ADR/spec/threat нет; `plans/current_task.md` не изменялся.
