# ADR-1015-3 — Гибридный вызов функций: Fast-Track regex + LLM Tool Calling

- **Статус:** Принято (Step 2 @Architect, 14.09.2026)
- **Раунд:** 10.15, фича F8 `hybrid-tool-calling-round1015` (T-1610)
- **Контекст:** основная LLM чата (DeepSeek) уже умеет tool-calling (эпик 3.3: `llm_client.generate_chat`, `tool_loop`, `tool_router`, `tool_schemas`; инструменты `query_chat_memory`/`dig_into_lore`/`execute_web_search` в `direct_chat`). F6 вводит канонический реестр текстовых команд (Fast-Track, обход LLM). Нужен гибрид: текстовые команды — мгновенно regex-ом; свободная форма («Олег, скачай этот видос пожалуйста») — через инструменты LLM.

## Решение

1. **Fast-Track сохраняется и приоритетен.** Порядок роутеров `bot.py` неизменен (search 0d/youtube 0e/web 0f/checkup 0g до direct_chat 0h) + F6-yield для download (4e). Сообщение вида `префикс + канонический триггер` не доходит до LLM.
2. **Tool Calling — расширение существующего механизма,** а не второй пайплайн: `TOOL_CALLING_TOOLS` +3 инструмента, `ToolContext`/`ToolDeps` расширяются аддитивно, `tool_loop`/`llm_client` не меняются.
3. **Итоговый tool-сет — 7:** существующие 3 + `summarize_video`, `download_media`, `get_bot_health` + `get_recent_history` (F9). Рост выше soft-ориентира «≤6» оправдан покрытием интентов owner-TZ.
4. **Корнер-кейс файлов (ключевое):** `download_media` исполняется на бэкенде и **сам** отправляет MP4 в Telegram; в LLM возвращается **фиктивный** `tool_response {"status":"success","message":"Файл успешно загружен в чат"}`. Успех — только после реальной отправки; при сбое — `status:"error"` (никогда не врём модели).
5. **Лимиты/безопасность:** переиспользуем `TOOL_MAX_ROUNDS=4`/`_TOOL_CALLS_PER_ROUND_MAX=2`; таймауты инструментов — код-константы; R17 (в логи — только имя инструмента/класс ошибки, без URL/текстов).
6. **Гейт скачивания:** `flags.download_enabled` (существующий), новых каталог-ключей нет.

## Альтернативы и отклонения

- **Отдельный LLM-пайплайн для инструментов:** отклонено — дублирование; direct_chat уже имеет tool-loop.
- **Возврат в tool_response описания файла (`file_id`/размер) вместо фикции:** отклонено — модель пытается «печатать» файл; owner-TZ предписывает фиктивный ответ.
- **Отдельный инструмент `get_video_transcript`:** отклонено — объединён с `summarize_video` через `mode` (сокращение tool-сета).
- **Новые каталог-ключи (вкл. инструментов, лимиты):** отклонено — Δ=0; гейты — существующие флаги/код-константы.

## Каталог-Δ

**Δ = 0.** REGISTRY 435 / Settings 406 / categorized 411 / GROUPS 90 / mapped 88 / TAB_RULES 19.

## Последствия

- Ноль регрессий Fast-Track (тест приоритета). Tool-путь деградирует безопасно (provider без tools → обычный ответ).
- Расширяемая база: новый инструмент = схема + метод `dispatch` (+ при необходимости deps).

## Инварианты

Порядок роутеров `bot.py` (только DI-kwargs), `TOOL_MAX_ROUNDS`/`_TOOL_CALLS_PER_ROUND_MAX` не менять, R16/R17, `media/`/`.env` не трогать, каталог Δ=0.
