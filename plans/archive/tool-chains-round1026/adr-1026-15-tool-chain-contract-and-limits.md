## Контекст

§15 задаёт цепочки: «Инструменты должны уметь использовать результаты предыдущих инструментов»; пример — «Найти ссылку в доступном контексте → Вызвать инструмент извлечения статьи → Получить Markdown и метаданные → Передать текст в фактчек → Получить результаты проверки → Подготовить ответ»; «Не требовать, чтобы пользователь повторно присылал ссылку, если она однозначно доступна в контексте»; «Не создавать специальный костыль, который работает только для этой фразы»; «Если инструмент B требует результат инструмента A, сначала выполнить A. Затем передать его результат в B»; «**Не выполнять зависимые инструменты параллельно**»; «Независимые вызовы могут выполняться параллельно, **если существующая архитектура это поддерживает**»; «Использовать существующую архитектуру tool calling»; «Не реализовывать отдельный обработчик для каждой комбинации инструментов. Нужен общий механизм выполнения цепочек».

§16 требует: для каждого инструмента определить название/назначение/аргументы/обязательные поля/тип результата/возможные ошибки/ограничения/стоимость; «Результаты должны быть структурированными. **Не передавать результат одного инструмента следующему исключительно как произвольный неструктурированный текст**»; пример JSON (`status/url/title/markdown/source_id`) — «**Пример, а не обязательная схема. Использовать существующие контракты, если они подходят**»; «Ошибки инструментов должны возвращаться в понятном структурированном формате. **Не превращать каждую ошибку в общий отказ LLM**».

§17 требует не допускать бесконечных циклов, предусмотрев: максимальное количество вызовов; общий тайм-аут; ограничение повторных попыток; защиту от повторного одинакового вызова; ограничение расходов; обработку частичного результата; «Начальные значения подобрать после анализа существующих инструментов. **Не добавлять тяжёлую инфраструктуру**… Для одного чата достаточно понятного и надёжного координатора».

**Фактическое состояние baseline (A0 EVIDENCE).** Цепочки **уже есть**: `services/tool_loop.py::chat_with_tools:89` — многораундовый цикл (`TOOL_MAX_ROUNDS=4:38`, `_TOOL_CALLS_PER_ROUND_MAX=2:39`; assistant `tool_calls:167–171` → роль `tool:184–185` → повтор LLM `:172–190`; plain-fallback `:125–135`; деградация `:191–196`; `ToolLoopResult:48–73` с `tool_trace`/`tool_context`). **Зависимые A→B уже поддержаны** (последовательно). **Параллельности нет** (`asyncio.gather` отсутствует). Диспетчер `tool_router.dispatch:455–480` **всегда возвращает plain-строку** (часть — JSON-строка; ошибки — «ОШИБКА {name}: {Type}»). **GAP §16:** структурного контракта нет — результаты склеиваются в текст `tool_context` и идут в Синтезатор (`direct_chat_service.py:1132–1143`); `tool_trace` — только метаданные. **GAP §15:** сценарий «ссылка→извлечение→фактчек» каноном 10 не закрыт — `web_content_extractor.extract:59` и `factcheck_service.check_claim:77` — **сервисы**, не тулы. **GAP §17:** общего тайм-аута цепочки, дедупа, лимита расходов и явного суммарного лимита — нет (per-tool тайм-ауты в роутере есть: search 25 c, download 180 c, summarize/lore 300 c, history 10 c).

**Открытые вопросы Step 1 (a)–(f)** требуют lasting-решений: (a) механизм контракта §16; (b) значения §17-лимитов; (c) параллельность; (d) расширение канона; (e) границы A3/A4/A7; (f) санкции/deploy/риск.

## Решения

**D1. Контракт §16 — ГИБРИД: модельно-видимый канал сохранён + out-of-band структурный спутник (envelope); reuse `ToolLoopResult`/`tool_trace`.**
- **(1) Модельно-видимый канал без изменений:** `role:"tool"`-content и `tool_context` (grounding для Синтезатора) остаются как есть; новые/JSON-инструменты возвращают JSON-строку (как `dig_into_lore`/`generate_image`).
- **(2) Структурный спутник:** на каждый вызов — запись envelope `{round, tool, args_fingerprint, status(ok|error|skipped), data, error_code, error_type, truncated, metered, duplicate, attempt, out_chars}`, хранимая на `ToolLoopResult` (аддитивный атрибут) и в `ToolContext` (`ctx.tool_results`); envelope **не сериализуется** в модельный ввод.
- **(3) Reuse, не новый контур:** расширяются существующие `ToolLoopResult`/`tool_trace` (аддитивно); новый тип цикла/агент/роутер **не вводится**.
- **Спутник доступен следующему инструменту** через `ToolContext` (паттерн `ctx.lore_story`/`ctx.lore_compiled`) — программный A→B handoff; порядок A→B по-прежнему задаёт модель (выбор инструментов не дублируется).
- **Альтернативы:** (i) «лёгкий envelope **вместо** строки» отклонён — OpenAI-протокол требует строку в `role:"tool"`, замена сломает модельный контур/OFF; (ii) «только reuse `ToolLoopResult`/`tool_trace`» отклонён — текущий `tool_trace` не несёт тип/ошибку/стоимость → §16 не закрывается.

**D2. Структурированные ошибки; ошибка инструмента ≠ общий отказ LLM.**
- Envelope несёт `status:"error"` + `error_code`/`error_type` (R17: только код/класс); модельно-видимый текст остаётся прежним «ОШИБКА {name}: {Type}» (совместимость) либо структурным JSON (новый `fetch_article`).
- Ошибка одного инструмента не прерывает цикл, не превращается в общий отказ LLM и не приводит к «тишине»; fail-safe/деградация существующего контура (`degraded`/`round_limit`/`llm_error`) сохранены.

**D3. §17-лимиты — аддитивные код-константы поверх существующих; один env-only kill-switch.**
- `TOOL_MAX_TOTAL_CALLS = 6` (туже теоретических 4×2=8) — суммарный cap.
- `TOOL_CHAIN_TIMEOUT_SECONDS = 360.0` — общий тайм-аут (мягкий wall-clock, от входа в цикл), проверяется на границах раундов и **перед каждым** диспетчем; **in-flight вызов не отменяется**. **R-1 закрыт (T-3527/@Architect): действующее значение — 360.0 c**, формулировка согласована с `spec.md` §4(b)/§7. Значение = максимальный per-tool таймаут (300 c: `_LORE_TOOL_TIMEOUT`/`_SUMMARIZE_TOOL_TIMEOUT`) + 60 c запас → одиночный тяжёлый инструмент не режется, цепочка из нескольких тяжёлых деградирует. Вариант 300 c отклонён: он равен per-tool-максимуму и мог бы резать одиночный тяжёлый вызов.
- `_TOOL_MAX_SAME_CALL = 2` — одинаковый вызов (имя + канонические аргументы `json.dumps(sort_keys=True)`) исполняется ≤2 раз (попытка + ≤1 повтор); далее — **не диспетчится**, возвращается последний результат (`duplicate=true`); автоматических ретраев нет (каскады сервисов сохраняются).
- `TOOL_CHAIN_MAX_METERED_CALLS = 4` — лимит расходов (metered = search/article/summarize/download/lore/image/transcribe; free = memory/dig/history/health); `worker_budget.image_calls` **не дублируется**.
- Частичный результат: существующие `degraded`/`round_limit`/`llm_error` + аддитивные причины `chain_timeout`/`chain_call_limit`/`chain_cost_limit`; `tool_context` не теряется.
- **Kill-switch `TOOL_CHAIN_LIMITS_ENABLED`** (env-only `ClassVar`, default ON, Δ каталога=0): OFF → лимиты/дедуп не применяются (baseline-поведение цикла).
- **Тяжёлая инфраструктура не добавляется** (только константы + in-memory счётчики прогона).

**D4. Параллельность независимых — санкционирована ПОСЛЕДОВАТЕЛЬНОСТЬ; `asyncio.gather` не вводится; зависимые — всегда последовательно.**
- §15 допускает параллель только «если архитектура это поддерживает». Архитектура **не поддерживает**: `ToolRouter`/`ToolDeps`/`ToolContext` не concurrency-safe (общий мутабельный `ctx`; побочные эффекты и порядок важны — `download_media`/`generate_image` шлют в чат, pending-меню in-memory). Параллелизм потребовал бы менеджмента задач/отмены/частичных сбоев → тяжёлая инфраструктура, прямо не рекомендованная §17.
- Последовательность — **обоснованная норма** (tasks.md инвариант 3), требование не сужено.

**D5. Расширение канона — +1 общий инструмент `fetch_article` (атомарно, reuse `web_content_extractor`); фактчек-инструмент — A7.**
- §15-пример каноном 10 не закрыт; `web_content_extractor.extract:59` — сервис. Добавляется один инструмент `fetch_article`: `url` (optional; при отсутствии — `ctx.resolved_url`); JSON-результат `{status,url,source_id,chars,truncated,markdown[,title]}`. Per-tool `_ARTICLE_TOOL_TIMEOUT = 45.0` (trafilatura 10 c / Tavily 15 c / Exa 15 c + запас). `source_id` — детерминированный короткий хэш нормализованного URL (grounding/дедуп).
- **Атомарность:** схема + регистрация в `TOOL_CALLING_TOOLS` (**в хвост**, ADR-1020-4) + метод роутера + `active_tools` + тесты — одним изменением; `factcheck_tools`=3 без изменений; **не второй контур** (тот же `ToolRouter`/`tool_loop`/`ToolDeps` + аддитивный `extractor`).
- **Kill-switch `ARTICLE_TOOL_ENABLED`** (env-only `ClassVar`, default ON, Δ каталога=0): OFF → инструмент не объявляется (эффективный канон 10).
- **Фактчек-инструмент и «URL+фактчек» (§36–§37) — A7** (граница); A7 **reuse** A2-envelope как вход, без дубля `fetch_article`.

**D6. Контекстный резолв ссылки — общий (`ctx.resolved_url`).**
- Ссылка, однозначно доступная в контексте (текущее сообщение → reply → forward → уже загруженное окно), резолвится **общим** механизмом (reuse `smartmodule_urls`), без новых I/O и без per-phrase костыля.
- При неоднозначности (несколько различных URL в окне и нет явного) — не резолвится; `fetch_article` без `url` возвращает структурный `no_url` (честно), модель может уточнить.
- `fetch_article.url` optional именно для этого сценария.

**D7. Санкции: Δ DDL = 0, Δ каталога = 0, §85-UI — отдельная санкция.**
- Новых таблиц/колонок/индексов нет; состояние лимитов — in-memory на прогон. `param_catalog.py` вне diff; новые kill-switch — env-only `ClassVar` (`TOOL_CHAIN_LIMITS_ENABLED`, `ARTICLE_TOOL_ENABLED`).
- §85-UI (Δ каталога ≠ 0) — вне A2.

**D8. Release policy = EPIC_ONLY (deferred): A2 отдельно не деплоится; bump `APP_VERSION` 2.58.30 → 2.58.31 — в агрегированном релизе Эпика 3.**
- A2 меняет рантайм разделяемого `tool_loop` живого direct-чата → read-only NOT_APPLICABLE неприменим; поэтому вклад фичи **входит в агрегированный pending epic-release Эпика 3** (манифест/порядок/агрегатный Reviewer gate — на границе эпика). Отдельного деплоя фичи после approval **нет** (T-3549 = `DEFERRED_TO_EPIC`). Точную версию подтверждает @DevOps на границе эпика.
- Активация — по факту эпик-деплоя (автоматическая push/ff в рамках агрегата); лимиты/новый инструмент — ON по умолчанию. Hot-OFF — env-only kill-switch'и; cold — annotated-тег **`pre-round1026-a2`** → `e8646af` + `git revert`; канон-откат промптов не требуется. Теги/бэкапы не удаляются (R18).

**D9. Границы волн: A3/A4/A6/A7/A8/A9 не реализуются; §104 не трогать; REUSE ExecutionGraph; handoff A7.**
- A3/A4 (§18–§25), A6 (§32–§35), A7 (§36–§37/§38–§48), A8 (§41/§44), A9 (§49/§51) — вход, не реализация. §104 `generate_image` без изменений. Наблюдаемость — reuse `execution_graph_source`/`analytics.py`/`execution_graph.js` (вторая аналитика не создаётся).
- **Handoff → A7:** фактчек-инструмент (§36–§37) reuse A2-envelope/`ctx`-спутник и общий механизм цепочек.

**D10. Risk-Level: R3.**
- A2 меняет рантайм-семантику **разделяемого** `tool_loop` (blast radius — каждый диалог с инструментами), вводит изменение контракта `dispatch` (envelope) и контроль потока цепочки (лимиты/дедуп/тайм-аут/расходы) + новый инструмент канона. Это соответствует Critical-KG-рискам `Risk-a2-infinite-call-loop`/`Risk-a2-live-chat-regression` и High `Risk-a2-phrase-hack-per-combination`/`Risk-a2-unstructured-handoff`.
- **Усиленные требования (обязательны):** (1) threat/failure-анализ с тестом на каждую угрозу; (2) rollback-доказательства (OFF → байт-в-байт legacy; hot/cold); (3) расширенная adversarial-приёмка (границы 6/360/2/4; soft-timeout; неоднозначная ссылка; OFF; 2-вызовность) + diff-аудит.
- **Понижает до R2:** доказанная полная аддитивность при OFF и отсутствие новых наблюдаемых исходов вне лимитов. **Reviewer может повысить.**

**D11. Наблюдаемость — R17-safe, reuse существующих логов/событий/ExecutionGraph.**
- Логируются только числа/коды/id/`error_type`/имена инструментов/длины; без ключей/промптов/сырых текстов/URL/аргументов. Вторая аналитика/карта не создаётся (граница A9).

**D12. AMEND/REUSE-карта.**
- ADR-1020-7 §1 — **effective AMEND** (аддитивные причины деградации `chain_timeout`/`chain_call_limit`/`chain_cost_limit`; существующие ветки не меняются).
- ADR-1026-13 D3 — **санкция использована** (канон 10→11; durable-аудит — AMEND-запись на merge T-3547; сам durable-аудит в Step 2 не трогается).
- ADR-1026-14 D3 — **граница A2 исполнена** (A2 теперь владеет §15–§17; общий механизм — reuse `tool_loop`).
- ADR-1013-3 — **NOT_APPLICABLE** (промпты не меняются; `PREV_*`/миграции/эталоны не добавляются).
