> - **§27.4 «Состояния, ошибки и честный итог пайплайна»** (`:1400–1410`) — состояния стадии: `queued`, `running`, `waiting_external`, `retry_scheduled`, `succeeded`, `skipped`, `failed`, `cancelled`, `interrupted`; run дополнительно `partial/degraded`; `stalled` — диагностическое (не доказывает исключение, не заменяет outcome); у каждого skip — причина и влияние; требуемые/необязательные стадии и ветви — контрактом pipeline version; успех всех обязательных → `succeeded`; сбой необязательной с работающим fallback → `degraded/partial` с описанием; невыполненная обязательная → `failed/interrupted`; не помечать run success, пока не зафиксирована необходимая запись или остаётся обязательная дочерняя задача; асинхронное продолжение — отдельный linked job с явным pending, а не скрытый успех; ошибка содержит очищенный traceback/cause chain, failed stage, последние успешные stages, попытку, elapsed/deadline, dependency, влияние, fallback, checkpoint и действие восстановления; нулевой результат/валидное молчание ≠ падение; ошибка SQL/парсинга ≠ «нет воспоминаний»; ошибка одной ветви не стирает успех другой; «предполагаемая причина» отдельно от подтверждённой ошибки; после SIGKILL/потери машины может отсутствовать traceback — честный `interrupted`.
> - **§27.5 «Длинные процессы, heartbeat и watchdog»** (`:1412–1424`) — у долгого job: владелец/lease, heartbeat, фактический progress marker, deadline, ожидаемая внешняя операция, checkpoint, `next_retry_at`; heartbeat ≠ progress; лимиты стадий по типу (LLM/видео/архив); ориентиры: heartbeat **15s**, stale **60s**, progress-stall — отдельно по типу стадии относительно ожидаемой длительности/deadline (конфигурируемо; законная длительная транскрибация не объявляется упавшей через минуту); время в очереди и у внешнего провайдера — отдельно от времени исполнения; watchdog проверяет durable state периодически и на старте; при stale lease — подозрение, проверка владельца/состояния, затем `interrupted`/retry по безопасной политике; lease generation/fencing защищает от записи результата старым worker после takeover; heartbeat не продлевает абсолютный deadline без объяснимой смены этапа; детект недоступности — вне основного event loop (существующая проверка здоровья/менеджер процессов); UI при потере backend — `telemetry stale/unknown`, без старого «зелёного»; recovery: прочитать checkpoint, определить подтверждённые записи/side effects, возобновить только безопасные этапы; никаких бесконечных retries; неопределённая доставка/платная операция — `delivery_unknown` до сверки по operation ID, рестарт не даёт права повторить вслепую.
> - **§27.6 «Инциденты и уведомления в миниаппе»** (`:1426–1436`) — список активных инцидентов (стадия, серьёзность, первое/последнее обнаружение, число повторов, затронутые jobs/chats, влияние, последнее восстановление, ссылка на trace); компактный индикатор на витрине + прямой переход; **acknowledged ≠ resolved**; recovered/resolved — только после реальной проверки здоровья/завершения восстановления; история инцидента сохраняется после исчезновения ошибки; группировка повторов provider timeout/DB busy по устойчивому признаку с сохранением отдельных trace и счётчика; успешный fallback снижает влияние, но не скрывает сбой основного пути; новые симптомы не объединять по одинаковому слову timeout; ошибки/stale-переходы доходят до открытого миниаппа ближайшим обновлением (**цель ≤10 s** от обнаружения; SSE/WebSocket при наличии инфраструктуры, иначе инкрементальный polling); при восстановлении соединения — пропущенные события по cursor + сверка; уведомления — **только в миниаппе** (без чата/DM/email/сторонних сервисов); бот не публикует пользователям внутренние stack traces.

## Приёмочные инварианты MCA-17a (нарушение = НЕ принято)

1. **Реестр процессов полон и сверен с кодом:** для каждой фактически активной функции (включая предыдущие эпики 1–3 и закрытые `mca-03`/`02`/`04a`/`07`) — `process_id`, версия, назначение, входы/выходы, стадии/ветвления, триггер/расписание, настройки, источник состояния, операции восстановления, `widget ID`; mapping фактических стадий на события; **новый процесс без наблюдаемости = незавершённая интеграция**; статус `реализовано/выключено/не запускается/не инструментировано` с причиной. **MCA17-R1; T-3864, T-3865.**
2. **Сквозной trace/span-контракт — расширение `mca-13`, не второй store:** `pipeline_run_id`/`pipeline_type`/`version`, `span_id`, `parent_span_id`, `linked_span_ids`, `job_id`, `attempt_id`, `causation_id`, `event_id`, `event_sequence`, `status`, `reason_code`, start/end, `heartbeat_at`, `progress_at`, `deadline_at`, `checkpoint_ref`; correlation проходит через durable queue и восстанавливается при resume. **MCA17-R3; T-3867, T-3868.**
3. **Root job + batch traces:** длительный archive job — это root job + отдельные batch traces, **не** один бесконечный span; внутри batch — диапазон/счётчики + ссылки на отдельные проблемные записи; failures не скрываются за усреднённым «обработано 500». **MCA17-R3; T-3869.**
4. **Parent-child только для реального вложенного выполнения; shared/singleflight — links, а не один ложный владелец; retry — новая попытка в рамках того же логического этапа, не затирание предыдущей ошибки; параллельные ветви — отдельные spans/зависимости.** **MCA17-R3; T-3868, T-3869.**
5. **Время и связь событий:** длительность внутри процесса — монотонными часами; отображение — UTC; связь событий — по ID/sequence, **не только** сравнением timestamp. **MCA17-R3; T-3870.**
6. **Стадийные события вокруг реальных операций** (scheduled/queued → started → ожидаемое действие/объём → завершение внешнего запроса → валидация → фиксация → передача дальше → terminal outcome); никакой генерации вымышленного списка этапов задним числом по общему success. **MCA17-R3; T-3870.**
7. **Состояния стадии/run:** `queued`, `running`, `waiting_external`, `retry_scheduled`, `succeeded`, `skipped`, `failed`, `cancelled`, `interrupted`; run — дополнительно `partial/degraded`; `stalled` — диагностическое, **не** заменяет outcome; у каждого skip — причина и влияние. **MCA17-R4; T-3871.**
8. **Честный итог по контракту pipeline version:** успех всех обязательных стадий → `succeeded`; сбой необязательной с рабочим fallback → `degraded/partial` с описанием; невыполненная обязательная → `failed/interrupted`; run **не** success, пока не зафиксирована необходимая запись/остаётся обязательная дочерняя задача; допустимое асинхронное продолжение — **отдельный linked job** с явным pending, без скрытого успеха. **MCA17-R4; T-3872, T-3873.**
9. **Ошибка информативна и честна:** очищенный traceback/cause chain, failed stage, последние успешные stages, попытка, elapsed/deadline, dependency, влияние, fallback, checkpoint, действие восстановления; «предполагаемая причина» отдельно от подтверждённой; нулевой результат/валидное молчание ≠ падение; ошибка SQL/парсинга ≠ «нет воспоминаний»; ошибка одной ветви не стирает успех другой. **MCA17-R4; T-3873.**
10. **Heartbeat ≠ progress:** у долгого job — владелец/lease, heartbeat, progress marker, deadline, ожидаемая внешняя операция, checkpoint, `next_retry_at`; ориентиры heartbeat **15 s** / stale **60 s**; progress-stall — по типу стадии (LLM/видео/архив) относительно ожидаемой длительности/deadline; конфигурируемо; законная длительная транскрибация не объявляется упавшей через минуту; очередь/внешнее ожидание — отдельно от времени исполнения. **MCA17-R5; T-3875.**
11. **Watchdog и takeover безопасны:** watchdog проверяет durable state периодически и на старте; stale lease → подозрение → проверка владельца/состояния → `interrupted`/retry по безопасной политике; **lease generation/fencing** защищает от записи результата старым worker после takeover (в т.ч. `cancelled`/`failed` — L-MCA01-5); heartbeat не продлевает абсолютный deadline без объяснимой смены этапа; детект недоступности — **вне** основного event loop; UI при потере backend — `telemetry stale/unknown` (старый «зелёный» не сохраняется). **MCA17-R5; T-3876, T-3882.**
12. **Recovery по checkpoint и `delivery_unknown`:** прочитать checkpoint, определить подтверждённые записи/side effects, возобновить только безопасные этапы; без бесконечных retries; неопределённая доставка/платная операция — `delivery_unknown` до сверки по доступному operation ID; рестарт не даёт права повторить её вслепую; опасное задание без обязательного durable checkpoint завершается/приостанавливается явно. **MCA17-R5/R9; T-3877, T-3874.**
13. **Инциденты:** список активных (стадия/серьёзность/первое-последнее/повторы/jobs/chats/влияние/последнее восстановление/trace); группировка по устойчивому признаку с сохранением отдельных trace и счётчика; успешный fallback снижает влияние, но не скрывает сбой основного пути; новые симптомы не объединяются по одному слову timeout; **acknowledged ≠ resolved**; recovered/resolved — только после реальной проверки; история сохраняется после исчезновения ошибки. **MCA17-R6; T-3878.**
14. **Доставка инцидентов:** до открытого миниаппа ≤10 s от обнаружения (SSE/WS при наличии инфраструктуры, иначе инкрементальный polling); восстановление соединения — пропущенные события по **cursor** + сверка состояния; **только миниапп** (без чата/DM/email/сторонних); бот не публикует пользователям внутренние stack traces. **MCA17-R6; T-3879.**

16. **Ретенция/пагинация/индексы/маскировка:** правила ретенции MCA-13 сохранены (14 d подробные / 90 d решения/архив; ручные/происхождение вне ротации); серверная пагинация и индексы по времени/chat/run/status; после истечения подробной ретенции — «детали удалены по сроку хранения», не «этап не выполнялся»; trace/user/message ID — не высококардинальные labels агрегированного metric; ключи/cookies/initData/credentials редактируются до записи во все каналы (включая error cause и экспорт); полный промпт/архив не дублируется; доступ к подробному содержимому — по ролям и chat isolation; скрытые рассуждения модели не запрашиваются. **MCA17-R7, GEN-R14; T-3880, T-3883.**
17. **Диагностические действия (ядро):** cancel/resume/retry только для разрешённых jobs; по правам, с actor/audit event, идемпотентны; «Повторить отображение» — только чтение; повтор внешнего side effect запрещён без безопасной семантики; `delivery_unknown` — доступная сверка вместо слепого retry; интерфейса запуска произвольного кода/SQL нет; runtime fault injection недоступен обычным и не включён в production постоянно; демо-данные — с явной меткой, отдельно от production metrics. **MCA17-R9; T-3874, T-3877, T-3883.**
18. **REUSE, не второй контур:** ExecutionGraph (`RunSnapshotStore`/`record_agentic_event`/`build_graph`/`GET /analytics/execution/latest`/`execution_graph.js`) и `mca_events` — расширяются аддитивно; второй store/вторая аналитика/второй TaskSupervisor/второй write-механизм запрещены; UI не ходит в БД напрямую. **GEN-R19/GEN-R21; T-3865, T-3866, T-3867, T-3880.**
