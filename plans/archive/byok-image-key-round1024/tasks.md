## Цель
Починить сохранение API-ключа генерации изображений в мини-аппе:
- Новый ключ должен уходить **отдельным запросом** на `/api/config/keys/own`, а не в общий `PUT /api/config`.
- Если ключ уже в БД — бэкенд не возвращает его в общих настройках; фронт показывает заглушку `••••••••••••` / «Ключ установлен».
- При включении «Режима GET-запроса» поле ключа **блокируется (disable) и очищается**.

- Фронт-логика сохранения секретов: `web/app.js` (sticky-save/`dirtyKeyItems`, `:1400-1430`, общий save `:2840-2865`).

- [ ] **T-2278** [@DevOps] Деплой + живая приёмка: сохранение ключа работает без ошибки; после перезагрузки — заглушка; GET-режим блокирует поле; отчёт без значений ключа.

## Критерии приёмки
- Новый ключ изображений сохраняется без ошибки через безопасный эндпоинт.
- После перезагрузки поле показывает заглушку, а не пустоту; ключ есть в БД.
- GET-режим блокирует и очищает поле.
- Секрет не появляется в общих настройках, ответах и логах. Тесты/JS-гейт зелёные.

## Риски
- **R1 (Critical):** утечка секрета в git/логи/общие настройки → маскирование + тест «нет plaintext» (T-2273/T-2276/T-2277).
- **R2 (High):** расширение BYOK-whitelist меняет модель прав → AMEND ADR + тесты прав (T-2271).
- **R3 (Medium):** обратная совместимость с уже сохранёнными глобальными настройками → миграции не нужны, но проверить порядок разрешения.
- **R4 (Medium):** очистка поля в GET-режиме может случайно удалить ключ из БД → очистка только UI, без DELETE без явного действия.
