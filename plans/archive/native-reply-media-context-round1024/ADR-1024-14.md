# ADR-1024-14 — Медиа-маркер нативного видео/медиа в контексте реплаев (баг A-1)

- **Статус:** **Accepted** (Step 2 @Architect, 19.09.2026)
- **Фича:** F13 `native-reply-media-context-round1024` (UPD4 баг A-1)
- **Тип:** backend/LLM-контекст (thread_chain / chat_context / direct_chat) + env-only флаг
- **Связано:** ADR-1023-1 (маркировка целевого сообщения, байт-инвариант), ADR-1023-2 (окно фактчека/граф реплаев), ADR-1020-1 (канонический контракт метаданных), ADR-1020-4 / ADR-1016-1 / ADR-1017-2 (инструменты медиа — **AMEND зона F14**)
- **Задачи:** T-2291…T-2298
- **Граница:** F13 = доставка факта медиа в контекст; F14 = инструменты (`services/tool_schemas.py`, `services/tool_router.py`, `handlers/video_download.py`)

## Context

1. **Прод-баг (UPD4, кластер A):** юзер реплаит «Бот что на видео» на нативное TG-видео. Фраза не входит в YouTube-триггеры (`services/command_registry.py:25`) → путь уходит в `direct_chat`. Но контекст реплая **text-only**:
   - `services/thread_chain.py:131-146` — узел с `text=""` не попадает в цепочку (`if text:`);
   - `services/chat_context.py:107-110` — строка с пустым текстом `continue`;
   - `services/direct_chat_service.py:1220-1233` — `<Current_Question>` берёт только `message.text`.
   В итоге LLM не видит ни факта видео, ни способа сослаться на него инструментом.
2. **Медиа уже есть в БД:** `smart_messages.media_type` заполняется observer'ом (`handlers/summary.py:125-143, 193-204`) и отдаётся во всех чтениях (`get_smart_message_by_tg_id`, `get_recent_messages`, `get_messages_around`) — **новых колонок/DDL не требуется**.
3. **Marker-прецедент уже существует:** `services/tool_router.py:1036-1061` (`get_recent_history`) рисует `[медиа: {media_type}]` для пустых строк. F13 расширяет этот диалект, не изобретая второй.
4. **Байт-инвариант 10.23:** ADR-1023-1 (маркировка триггера) и ADR-1023-2 (окно/граф фактчека) прямо требуют **побайтово прежний** вывод рендеров при отсутствии нового сигнала. Любая правка `thread_chain`/`chat_context` обязана это сохранить.
5. **Инструменты пока text/URL-only:** `summarize_video`/`download_media` требуют обязательный `url` (`services/tool_schemas.py:120-172`) — их ревизия **сознательно вне F13** (F14, AMEND ADR-1020-4).

## Decision

### D1. Маркер = тип медиа + внутренний реф (без публичного URL)
- Формат: `[медиа: {media_type}]`, при известном id — `[медиа: {media_type} tg:{id}]` / `[медиа: {media_type} msg:{id}]`.
- `{media_type}` — словарь БД (`video|photo|voice|audio|animation|sticker|document|other`), совпадающий с `_detect_media_type`.
- Реф — **внутренний** (`tg:<tg_message_id>` / `msg:<internal_id>`); публичный URL, `file_id`, токены **не** попадают в контекст (R17).
- Неизвестный/битый `media_type` санитизируется (`[a-z_]`, ≤20) → `other`; инъекция в каноническую строку невозможна.
- Контракт живёт в новом тонком модуле `services/media_marker.py` (`media_marker`, `row_media_marker`, `message_media_type`, `is_media_type`, `media_context_enabled`) — единый источник для F13 и F14.

### D2. `thread_chain` и `chat_context`: не отбрасывать пустую медиа-строку
- В обеих точках при пустом тексте и включённом флаге подставляется маркер **до** прежней проверки на скип. Заголовок строки и `resolve_item_id` (в т.ч. `item_id` как реф) не меняются.
- **Семантика текста сохраняется точно по месту:** `thread_chain` — raw-текст и truthiness (`if text:`), `chat_context` — `strip()` и `if not text`. White-space-only строки ведут себя как раньше.
- **Инвариант:** при отсутствии медиа (все `media_type` пусто/`text`) выбор строк и усечение окна/цепочки **байт-в-байт** прежние; алгоритм keep-end и капы не трогаются.

### D3. `<Current_Question>`: текст + маркеры, маркер не теряется
- `_strip_direct_prefix(message.text or "")` и кап `limits.chat_current_question_max_chars` сохранены.
- Дописываются маркеры нативного медиа самого сообщения и `reply_to_message` (по `message_media_type`). При пустом тексте блок всё равно строится; при непустом — текст усекается до резерва под суффикс, затем суффикс дописывается (маркер гарантированно выживает).
- При отсутствии медиа — ровно `stripped[:cap]`; при пустом тексте без медиа — `""` (прежнее поведение, байт-в-байт).

### D4. Caption-медиа не трогаем в F13
- Маркер добавляется **только** при пустом тексте. Медиа с caption рендерится как раньше — минимальная поверхность изменения и защита байт-эталонов. Расширение на caption-медиа — отдельное решение (при необходимости), вне F13.

### D5. Kill-switch
- `NATIVE_REPLY_MEDIA_CONTEXT_ENABLED` — env-only `ClassVar`, **default ON**, вне каталога. OFF → все три пути дают прежний вывод побайтово. Δ каталога = 0, Δ DDL = 0.

### D6. Граница с F14 (AMEND ADR-1020-4)
- F13 **отдаёт реф в контекст**, но **не меняет** схемы/диспатч инструментов. F14 принимает медиа из реплая/контекста при сохранении `url`-пути, валидирует реальное вложение live-сообщения (`video_note`/не-видео `document` отклоняются) и приводит `tool_router._history_lines` к общему хелперу.
- Известное ограничение: `media_type="video"` не отличает `video` от `video_note`, а `document` — от видео-документа; квалификация — на стороне F14 по live-сообщению.

### D7. Порядок и ступень
- F13 стартует первым (отдаёт контракт T-2291), F14 потребляет. Общие файлы `thread_chain.py` + `chat_context.py` + `direct_chat_service.py` — **эксклюзив F13**. F13 не трогает `tool_schemas.py`/`tool_router.py`/`handlers/**`.

## Consequences

**Positive**
- Модель «видит» нативное видео/медиа в реплае и получает устойчивый внутренний реф для tool-calling → живой сценарий A-1 становится возможным (совместно с F14).
- При отсутствии медиа регресс нулевой: переключатель OFF и байт-эталоны сохраняют прежнее поведение (ADR-1023-1/2).
- Один словарь токенов для БД-контекста и live-сообщений; один marker-хелпер на весь контекст.

**Negative**
- Контекст немного растёт на медиа-строках (участвует в существующем усечении; капы не меняются).
- Caption-медиа в F13 не маркируется — часть кейсов остаётся «слепой» для типа вложения (осознанно).
- Амбивалентность `video`/`video_note`/`document` переносится в F14 (валидация live-вложения).

## Alternatives

- **A1. Хранить `file_id`/mime в `smart_messages` (DDL)** — **отклонено:** Δ DDL, вне инварианта раунда; квалификация доступна по live-сообщению на стороне F14.
- **A2. Рендерить публичный URL на файл** — **отклонено:** R17 (утечка URL/эфемерных ресурсов) и не нужен для факта видимости.
- **A3. Маркер только в `<Current_Question>` (без chain/window)** — **отклонено:** ломает паритет direct/фактчек (F2 использует общий `thread_chain`), не даёт factcheck-окну видеть медиа.
- **A4. Маркировать все медиа-строки, включая caption** — **отклонено в F13:** расширяет поверхность и байт-риск; при необходимости — отдельное решение.
- **A5. Менять схемы инструментов прямо здесь** — **отклонено:** зона F14 (AMEND ADR-1020-4 / ADR-1016-1 / ADR-1017-2), иначе рассинхрон tool-loop.
- **A6. Новый каталоговый ключ/флаг** — **отклонено:** env-only `ClassVar` достаточен, Δ каталога = 0.
- **A7. Включить флаг через hot/per-chat** — **отклонено:** прецедент 10.21–10.23 — env-only рубильники.
