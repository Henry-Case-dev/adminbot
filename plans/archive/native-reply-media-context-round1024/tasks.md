> **Раунд 10.24 (UPD4-A-1)** · Приоритет **P1** · Шаг 1 @PM · Тип: backend контекста (thread_chain/chat_context/direct_chat)
> **ТЗ:** `plans/current_task.md`, секция **UPD4** (строки 274–279). Файл untracked; секреты не цитировать (R17/R18).
> **Baseline:** HEAD `00eab85`; прод `4314ea4`. Отчёт @Memory: `upd4-live-bug-clusters-round1024` (кластер A).
> **Граница с F14:** F13 делает **нативное медиа видимым в контексте** (данные для LLM); F14 даёт **инструментам** возможность его скачать/суммаризовать. F13 НЕ меняет `tool_schemas.py`.
> **UPD5 №3 (строка 403):** «что на видео»/«че за видос» и подобные — запрос на **выжимку**; «транскрипт» — отдельная команда **транскрибации**. Медиа-маркер не теряет намёк на тип запроса (выжимка vs сырой транскрипт); выбор инструмента — зона F19 (`media-transcribe-tool-round1024`).

## Цель
Ситуация: юзер реплаит «Бот что на видео» на **нативное TG-видео** — фразы нет в триггерах, запрос уходит в `direct_chat`, но контекст реплая **text-only** (сообщение с медиа и пустым текстом отбрасывается) → LLM физически «не видит» видео и не может вызвать инструменты. Сделать так, чтобы факт наличия нативного медиа в реплае/цепочке доходил до модели (медиа-маркер), **байт-в-байт не меняя** вывод при отсутствии медиа.

## Что уже есть (координаты)
- Триггеры YouTube не содержат «что на видео»: `services/command_registry.py:25` (youtube: `транскрипт`, `че за видос`, `о чем видео`, `поясни за видос`) → свободная форма уходит в direct_chat.
- Цепочка реплаев скипает пустой текст: `services/thread_chain.py:131-146` (`text = row["text"] or ""`, `if text:` — узел без текста не попадает в `<reply_chains>`).
- Окно контекста скипает пустой текст: `services/chat_context.py:107-110` (`text = (row["text"] or "").strip(); if not text: continue`).
- Current_Question только текст: `services/direct_chat_service.py:1220-1233` (`_strip_direct_prefix(message.text or "")`).
- Нативное медиа на сообщении: `message.video` / `message.document` с mime `video/*` (реплай — `message.reply_to_message`); существующий резолвер — `handlers/youtube.py:296` (`_resolve_video_media`), квалификация документа — `handlers/youtube.py:327`.
- Инструменты требуют обязательный `url`: `services/tool_schemas.py:120-172` (`summarize_video`, `download_media`) — сам контракт инструментов — **зона F14**.
- Рендер строки цепочки — единый `format_context_item`/`format_chain_line` (`services/thread_chain.py:161-177`).

## Задачи
- [x] **T-2291** [@Architect] ADR/spec: контракт **медиа-маркера** в цепочке реплаев и `<Current_Question>` (что именно уходит LLM: тип медиа + внутренняя ссылка/признак, без публичного URL; R17/R16 — опускать отсутствующее). Явно зафиксировать **байт-в-байт** прежний вывод при отсутствии медиа (граница по ADR-1023-1/2). Определить точку связи с инструментами (передаётся F14).
- [x] **T-2292** [@Builder] `services/thread_chain.py:131-146`: не отбрасывать узел с пустым текстом, если на нём есть нативное видео/видео-документ — добавлять компактный маркер через существующий `format_chain_line`/`format_context_item` (kind медиа). **При отсутствии медиа — вывод байт-в-байт прежний.**
- [x] **T-2293** [@Builder] `services/chat_context.py:107-110`: аналогично не скипать строки-медиа — рендерить маркер; **байт-в-байт** при отсутствии медиа (окно/бюджет усечения не меняются).
- [x] **T-2294** [@Builder] `services/direct_chat_service._render_current_question` (`:1220-1233`): учитывать нативное видео на самом сообщении и на `reply_to_message` — маркер не теряется при пустом `message.text`; сохранить срез префикса и кап `limits.chat_current_question_max_chars`.
- [x] **T-2295** [@Builder] Связка контекста с tool-calling: чтобы модель могла сослаться на медиа из маркера — согласовать с F14 формат идентификатора (внутренний реф медиа-узла); в F13 — только отдать реф в контекст (без изменения схем инструментов).
- [x] **T-2296** [@Builder] Тесты: (a) цепочка/окно с нативным видео содержит медиа-маркер; (b) **при отсутствии медиа вывод `thread_chain`/`chat_context` — байт-в-байт** (эталонный тест); (c) `<Current_Question>` не пуст при видео-реплае без текста; (d) медиа-маркер доступен в user-content для tool-loop.
- [ ] **T-2297** [@Reviewer] Ревью: медиа видно модели; байт-эталоны при отсутствии медиа не задеты; нет утечки публичных URL/секретов; маркер не ломает бюджет контекста.
- [ ] **T-2298** [@DevOps] Деплой + живой сценарий: «Бот что на видео» реплаем на нативное TG-видео → бот «видит» медиа и отвечает (через инструмент F14). Отчёт.
- [x] **T-2332** [@Builder] **UPD5 №3:** в медиа-маркере/`<Current_Question>` не терять намёк на тип запроса — «что на видео»/«че за видос» → сигнал **выжимки**, «транскрипт» → сигнал **транскрибации** — чтобы tool-loop (F19) выбрал нужный инструмент (сырой транскрипт vs выжимка). **Байт-в-байт** прежний вывод при отсутствии медиа сохраняется (эталонный тест T-2296(b)). Согласовать формат сигнала с T-2343/T-2348.

## Критерии приёмки
- Реплай-нативное видео присутствует в контексте direct_chat как медиа-маркер (наличие видео, без публичного URL).
- Контекст несёт **сигнал типа запроса** (выжимка vs транскрипт) для tool-loop F19, не меняя байт-эталон при отсутствии медиа.
- При отсутствии медиа `thread_chain`/`chat_context`/`Current_Question` дают **идентичный** прежнему вывод.
- Живой сценарий A-1 воспроизводится: бот больше не «слеп» к видео в реплае.
- Полный pytest — 0 failed; `git diff --check` чист.

## Риски
- **R1 (High):** изменение рендера цепочки/окна ломает байт-эталоны 10.23 F1/F2 → обязательный эталонный тест T-2296(b).
- **R2 (Medium):** маркер раздувает бюджет контекста → компактный формат, участвует в общем усечении.
- **R3 (Medium):** утечка file_id/служебных данных в контекст/логи → только тип медиа + внутренний реф (R17).
- **R4 (Low):** пустая строка-медиа без маркера → тест (c).
