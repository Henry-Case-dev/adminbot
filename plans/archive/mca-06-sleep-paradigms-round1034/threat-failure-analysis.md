## 1. Угрозы и отказы пайплайна

### THR-1 — Ложные парадигмы из вытесненного/некачественного материала (Integrity)
**Механизм:** текущий порядок «get_rag_facts → top_k → возраст-фильтр» (dream_worker.py:1577–1590) вытесняет старые релевантные основания свежими до проверки возраста; RAG возвращает `[]` и при выключенном RAG (:3135), и при ошибке (:3144) — неотличимо от «якорей нет» (R06-B-002). Итог: парадигмы строятся на непрезентативной выборке или честный путь падает в no_anchors без диагноза.
**Митигация:** исторический профиль с возраст/scope-фильтром **ДО** top_k (spec §4.2); три различимых исхода rag_off/ошибка/пусто (§3.2–3.3); FTS-фолбэк без vec-предусловия (§4.5, CA-10). **Остаточный риск:** тематические пакеты могут дать слабую тему → валидатор моста §5.3 отклоняет (insufficient_evidence).

### THR-2 — Подмена даты события датой индексации (Spoofing/Tampering)
**Механизм:** `_anchor_ts` (dream_worker.py:2105–2111) берёт `rag_ts`/`created_at`; после импорта/пересборки `created_at` ≠ дата события (R06-B-003). Подмена «молодого» факта «старым» фиктивно проходит порог 90 дней (:160, :2123–2132) — порог «двух исторических якорей» обходит не-LLM-путём.
**Митигация:** возраст только от проверяемого `message_timestamp` (mca-03 `(chat_id, tg_message_id)`); факт без валидного времени → `missing_timestamp`-счётчик, не проходит порог (spec §4.3, О5); T-4712 обследование/восстановление по оригиналам. **Остаточный риск:** доля фактов без восстановимого времени → честный no_anchors/insufficient_evidence + доля в отчёте (§7.2 п.7).

### THR-3 — Партиальный/кривой LLM-вывод, принятый за результат (Repudiation/Integrity)
**Механизм:** `_deep_llm_once` (dream_worker.py:1747–1757) возвращает content как есть; обрезка, частичный JSON, галлюцинированные индексы якорей. Существующая защита: `parse_bridge_answer` + ровно 1 retry (:1613–1640), индексная валидация якорей (:1655–1656).
**Митигация (сохранить/расширить):** сбой парсинга → статус `error`, никогда не «успешная пустая выдача» (О7, §7.1); валидатор моста §5.3 (субъект/последовательность/противоречие/источник) и валидатор ссылок §5.4 (существование `resolve_source_ref` provenance.py:288 / соответствие / недубльность) — «проверки ID в JSON недостаточно» (:358); якорь без traced-ссылки → honest unknown. **Остаточный риск:** семантически кривой, но парсящийся вывод → ловит только мост-валидатор; приемлемо при обязательном независимом подсчёте (THR-4).

### THR-4 — Инфляция независимости: пересказы и само-подтверждение (Integrity)
**Механизм:** N пересказов одного сообщения считаются N якорями; цикл «вывод бота → пересказ вывода → усиленный вывод» поднимает confidence без новых событий (:351–352). Сегодня `min_anchors=2` (:1616) считает якоря, а не первичные события — два пересказа проходят порог.
**Митигация:** independence-подсчёт по уникальным первичным событиям (§5.1, каноническая идентичность mca-03/SourceRef); bot_self-основания исключаются REUSE `bot_output_ledger.py` (§5.2); порог «двух якорей» сохранён на **независимых** событиях, не снижен (О1, D10). Тесты: «2 пересказа → independence=1», «вывод→пересказ→усиление не растит счётчик».

### THR-5 — LLM-таймаут/зависание ночного прогона (DoS/доступность)
**Механизм:** ночные прогоны всех чатов вызывают LLM последовательно; зависание вызова блокирует тик воркера; существующие лимиты — токен-кап (:1601–1606) и 1 retry, wall-clock deadline на глубокий сон — нет. Summary-Supervisor сюда не распространён (AM-1).
**Митигация:** дисциплина внутри контура воркера (AM-1): таймаут наследуется от роутера воркеров (`_worker_llm` F3/T-1439, LLM_TIMEOUT для не-Summary потребителей — граница AM-3 ADR-1028-8), стадийный heartbeat/progress-stall mca-17a (§8.5) — зависание стадии LLM не объявляется упавшим по общему таймеру, но ограничен progress-stall-порогом; ограниченный backoff после ошибки (§6.2); один чат не блокирует остальные (per-chat квоты §6.1, О3). **Остаточный риск:** повторяющиеся таймауты одного чата → backoff + отчёт (§7.2), ручной прогон для диагностики (§6.3).

### THR-6 — Гонка ручного и планового запуска / двойная запись (Race condition)
**Механизм:** ручной прогон (:1515 `manual=True`) обходит гейты :1519–1546; конкурентный запуск того же чата может продублировать парадигмы или двойным списанием исчерпать бюджет.
**Митигация:** per-chat singleflight + повторная проверка `last_deep_attempt` (database.py:6793) перед стартом; конкурентный запрос → отказ/вливание без дублей (spec §6.3, :379); идемпотентность записи через `_deep_dedup_key` (:2135) + provenance-дедуп (§8.3). Запись — через существующий single-writer механизм mca-01 (`write_transaction`/`@_serialized_write`; сеть/LLM вне транзакции).

### THR-7 — Гонка с episodes/rebuild-контуром (Race/Consistency)
**Механизм:** memory_rebuild/дossier-пересборка и mca-05 recheck меняют/пересоздают основания между выборкой якорей и записью парадигмы; парадигма ссылается на исчезнувшие/пересмотренные опоры.
**Митигация:** существующая защита опор живых beliefs в `memory_rebuild.py` (S10.21-3) сохраняется; ссылки — типизированные SourceRef с ревизией (provenance), исчезновение опоры → честный `unknown`/recheck, не тихая потеря; пересборка досье ставит зависимые парадигмы в ограниченную очередь пересмотра (§8.4, каскад bounded); эпизод-recheck (mca_episodes.py:536) — источник события для пересмотра. **Остаточный риск:** окно между выборкой и записью → фиксируется в отчёте (стадии), пересмотр закрывает.

### THR-8 — Деградация ядра характера (Integrity/автономия)
**Механизм:** ночные ветки сна/traits пишут в persona-область; накопительные дрейфы могут перезаписать настроенное владельцем ядро (:357).
**Митигация:** жёсткая граница AM-3: DreamWorker не имеет write-пути к ядру (тест «путь не существует/блокирован», spec §8.6); интересы/отношения/состояние — derived-слой как сегодня; изменения ядра — зона mca-18 с человеческим контролем. Оценка последствий: нарушение → R3-инцидент с откатом soft-рубильником.

### THR-9 — Случайное исследование как канал отравления (Tampering)
**Механизм:** выбор случайного материала (:356) может маскировать целевой подбор: «рандом» выводит удобные факты, вердикт зависит от выборки.
**Митигация:** `DreamRandomSource` — только выбор материала, seed = `(pipeline_run_id, chat_id)`, выборка в `selection_meta` отчёта (воспроизводимость, аудит); вердикт — только по доказательствам §5.3 (тест «разный материал, одинаковые доказательства → один вердикт»); без доказательств → unchanged/insufficient (spec §8.7); kill-switch `MCA_DREAM_RANDOM_EXPLORE_ENABLED`.

### THR-10 — Квотный шторм / starvation (DoS-доступность)
**Механизм:** глобальный `count_deep_attempts` (database.py:6811, без chat_id) — одна неудача исчерпывает суточную квоту всем чатам (R06-B-004); обратный экстремум — снятие глобального капа даёт ночной шторм LLM/токенов.
**Митигация:** двухуровневая модель (D9, §6.1): per-chat доступность + сохранённый глобальный кап (тест «глобальный лимит по-прежнему работает»); ограниченные ретраи после backoff/настроек/новых данных, циклические ретраи заблокированы (О10); токен-кап через `worker_budget` не дублируется (reuse §3).

### THR-11 — Отчёты/логи как канал утечки (Information Disclosure, R17)
**Механизм:** отчёт прогона (стадии, якоря, причины) может протянуть сырой текст сообщений/персональные данные в durable JSON, UI-логи и «Аналитику».
**Митигация:** R17-sanitize до записи во все каналы; отчёт — ID/счётчики/причины/диапазоны дат, без сырого текста; cap на списки якорей (прецедент `[:20]`×200 симв. в belief_meta, dream_worker.py:2051–2052 — для отчёта ещё строже: только ID); ретенция 14/90 REUSE; UI-эндпоинты — RBAC как существующие `/api/memory/dream*` (`_require_global_admin` memory_agi.py:541).

### THR-12 — Расхождение «запись/счётчик/статус» (Repudiation)
**Механизм:** ошибка записи после инкремента счётчика (:1664–1672) даёт success без записи (:380); счётчики БД при ошибке чтения → нули в API (memory_agi.py:554–564) маскируют сбой.
**Митигация:** итоговый статус выводится из факта записи (`written` только при подтверждённом `fact_id`); ошибка записи → `error`/`unchanged` (T-4728, §8.5); ошибка чтения счётчиков → `counters_error` с диагнозом (§3.4, О2).

### THR-13 — Рост durable-артефактов (DoS-хранилище)
**Механизм:** отчёт на каждый запуск (включая скип-прогоны) × чаты × ночи — неограниченный рост `mca_pipeline_runs`/`report_json`.
**Митигация:** bounded JSON (капы полей); ретенция существующая 14/90 дней (REUSE mca-17a); отчёт не дублирует span-события (стадии — в `mca_events`, отчёт — агрегат); индекс v25 только под реальные запросы (§11.2).

### THR-14 — Регрессия kill-switch (Availability/целостность поведения)
**Механизм:** 7 новых слоёв поверх веток сна; неполный OFF-паритет меняет поведение владельца незаметно ночью.
**Митигация:** каждый слой — отдельный env-only ключ default ON, OFF = бит-в-бит 2.58.47 (§11.1); обязательные OFF-паритет тесты на каждый слой (§12); traits-последовательность при OFF — прежняя (dream_worker.py:1696–1700). Миграция v25 аддитивна — старый код не читает; cold-откат `git revert`.

### THR-15 — Имитация прод-проверки (Process/Trust)
**Механизм:** приёмка «production effective-config + ограниченный прогон» (:381) может быть подменена fixture-прогоном по архиву.
**Митигация:** процессное правило О4: без production-доступа — `NOT_VERIFIED` с причиной в evidence (T-4733), фича не объявляется прод-проверенной; прод-причина гейта подтверждается настройками и журналом конкретного запуска (§3.4).

## 3. Выводы
- Критическая масса рисков закрывается **переупорядочиванием** (фильтр ДО top_k), **честными статусами** (10-матрица) и **типизированным происхождением** обеих групп — без нового инфраструктурного контура (без второго Supervisor/резолвера/run-store).
- Два риска с остаточной вероятностью (THR-3 семантическая кривизна, THR-7 окно гонки) принимаются с компенсацией: мост-валидатор + bounded очередь пересмотра; оба видны в отчёте прогона.
- Новый DDL — аддитивный (v25); деградационные сценарии БД (locked/сбой) ведут к статусам error/`telemetry_degraded`, не к потере данных или ложному успеху.
