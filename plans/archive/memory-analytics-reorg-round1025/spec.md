## 4. Решения D1–D8

### D1. Adapter §22–§25: точка размещения и каноническая модель `ExecutionNode`

**Точка размещения — чистый JS-модуль `web/static/execution_graph.js`** (zero-build, IIFE, подключается существующим способом `<script src>` без inline; CSP-safe). `web/api/analytics.py` **не расширяется** (R16: не плодить API; существующие ответы уже достаточны). Обоснование: §25 запрещает преобразование API-ответа внутри SVG/компонента дерева — adapter обязан лежать **между** API и рендером; клиентская сторона — естественное место, т.к. компонент живёт в `app.js`, а серверный ответ уже плоский и стабильный. Серверная нормализация добавила бы поля/эндпоинты (рост контракта, дублирование агрегатов и трассировки), чего §22/§25 не требуют.

**Публичный контракт модуля (витрина, не каталог):**
- `ExecutionGraph.fromTrace(latestResponse) → { runId, nodes[], edges[], total, empty }` — РЕЖИМ 1.
- `ExecutionGraph.fromSummary(summaryResponse) → { period, aggregate[], totals, empty }` — РЕЖИМ 2.
- `ExecutionGraph.filter({module, model, stage, status})`, `ExecutionGraph.detail(node)`.

**`ExecutionNode` — поля и источники (без вымысла):**

| Поле | Источник | Отсутствует → |
|---|---|---|
| `id` | детерминированно `correlation_id + ':' + index` (порядок `ts ASC, id ASC`) | — |
| `runId` | `latest.correlation_id` | `null` |
| `parentIds` | **только** подтверждённая линейная последовательность того же `correlation_id` по `ts`: `[предыдущий узел]` | `[]` для первого узла и для любого `tool`-узла (в БД нет `parent_id`) |
| `kind` | `step`: `single/stage1/stage2/image` → `llm`; `tool` → `tool`; пусто/иное → `other` | `other` |
| `stageKey` | сырой `step` | `'other'` |
| `stageLabel` | ru-словарь: Слой 1/Слой 2/Один вызов/Изображение/Инструмент/Шаг | `'Шаг'` |
| `moduleId` | `module` | `null` |
| `status` | в данных нет | всегда `'unknown'` (не «success»!) |
| `provider` | в данных нет (source ≠ provider) | `null` |
| `model` | `model` | `null` |
| `inputTokens`/`outputTokens` | `input_tokens`/`output_tokens` (сохранять `tokensEstimated`) | `null`, если поля нет |
| `cost` | `cost_usd` **только** при `price_known=true` | `null` |
| `costCurrency` | фиксировано `'USD'` | `null` при `cost=null` |

| `startedAt` | `ts` шага | `null` |
| `finishedAt` | в данных нет | `null` |
| `metadata` | `{ toolName, source, tokensEstimated, priceKnown }` | `{}` |

`algorithm`/`format`/`publish` — **зарезервированы контрактом и в F6 не эмитятся**: в `llm_usage_events` таких `step` нет (Ф6), значит фиктивные узлы создавать нельзя (§24). Когда Эпик 2 начнёт передавать реальные этапы через тот же контракт (S8), `algorithm`-узел сможет нести только реальные метрики (`metadata.processed`, `metadata.saved`, `durationMs`); **LLM-токены для `algorithm` не подставляются никогда**.

### D2. Два режима §26

Переключатель верхнего уровня «Последний вызов | День | Неделя | Месяц». `Последний вызов` → `fromTrace('/analytics/usage/latest')`; `День/Неделя/Месяц` → `fromSummary('/analytics/usage/summary?period=…')`. Ветки отрисовки **взаимно исключающие**: трассировка никогда не рендерится из агрегатов и наоборот. Деградация: пустой `latest` → «Вызовов ещё не было»; пустой период → «За период данных нет»; неизвестная цена → «Нет данных» (§28). Агрегатные узлы несут `status='unknown'`, `parentIds=[]` — временных/иерархических связей в агрегате не изобретаем.

### D3. Интерактивность §27 и mobile §29

- Desktop: выбор узла открывает **side-panel** справа с реальными полями (этап/модуль/модель/вход/выход/цена/статус; отсутствующие → «Нет данных»).
- Mobile: **bottom-sheet** (отдельный, не навигационный `.more-sheet`); для «Последнего вызова» — вертикальная последовательность этапов, для периода — раскрываемый агрегат. Горизонтальный граф не сжимается до 320 px.
- Фильтры (модуль/модель/этап/период/статус) — **только на «Аналитике»**; превью Статуса фильтров не получает.
- CSS: reuse `.token-flow*` и `tokenSeriesBars`, расширение **аддитивное**; fullscreen/`--shell-h` (§63/§64) не ломаются.

### D4. Честные состояния §28

`fmtCost` сохраняет `$0` **только** для подтверждённого нуля; при `priceKnown=false` рендерится «Нет данных» (устраняет текущее `$0`-по-умолчанию, Ф8). Бюджет `∞` → «Без лимита» без заполненного progress bar. Блоки «Стоимость LLM» (токены/цена из `llm_usage_events`) и «Ресурсы сервера» (CPU/RAM/диск/аптайм из `/api/status`) разделены подписями и источниками; подмена исключается тестом.

### D5. Превью Статуса §21 и граница с F11

F6 поставляет **источник и компонент**: `fromTrace(latest)` → компактный блок (корень + этапы + итог + честная цена), mount в зоне карточки «Аналитика» (Статус-сетка §12–§14). Это **не** «одна строка с токенами»: показываются реальные этапы и цена/«Нет данных». **F11** владеет финальной композицией витрины Статуса (позиция/пропорции/§12-порядок) и может переставить/оформить блок, не меняя его контракт. F6 не дублирует полный набор фильтров §27 в превью.

### D6. Раздел «Память» §52–§58 (presentation-level, Δ каталога = 0) — **AMEND-1 (H1 §52)**

> **Решение (вариант A) от 2026-09-23** по блокеру H1 @Reviewer (`review.md`): `adr-1025-19a-memory-section-52-amend.md`. Код не меняется; закрывается правкой спеки/ADR. Остальные блокеры H2 не покрывает.

§52 перечисляет 5 имён (Досье/Факты/Связи/Лор чатов/Настройки). Честно воспроизводимы **3 карточки верхнего уровня** — `HUBS_V2['#/memory']` (`web/app.js:425-446`), т.к. в коде есть только **3 distinct-рендера**, а F6 не создаёт маршрутов (**R16**, `Δ каталога = 0`): **Настройки памяти** (`memory_rag`, generic config), **Лор чатов** (`chat_lore`, `web/index.html:2871-3238`), **Люди и связи** (`relations`, `:2657-2860`). Карточки-заглушки «Досье»/«Факты» не создаются (§0/§57 — без фикции; §116 — без потери виджетов; §52 «не смешивать просмотр людей с настройками RAG»).

**Карта реализации имён §52 (новых маршрутов НЕТ):**
- **Связи** → «Люди и связи» (`relations`).
- **Лор чатов** → `chat_lore`.
- **Настройки** → «Настройки памяти» (`memory_rag`), 5 подгрупп (ниже).
- **Досье** → per-person модалка «Досье» внутри «Люди и связи» (`openDossier`, `web/index.html:2835`, `web/app.js:4693`; показывает traits/facts/links) + «Живая лента досье»/«Новые факты» (§19) в «Аналитике» (`dossierFeed`, `GET /api/oversight/dossier_feed`, `web/index.html:2238-2287`).
- **Факты** → «Настройки памяти → Граф знаний» (§54, конфигурация извлечения/распада/дедупа фактов) + та же живая лента подтверждённых фактов + виджеты фактов/убеждений (§18).

**Осознанное отклонение от буквального списка §52** (5 записей → 3 карточки + карта выше): dedicated экраны «Досье»/«Факты» вне F6 (presentation-level, R16/Δ каталога=0), кандидат в отдельную фичу при требовании владельца. «Настройки» группируются в 5 подгрупп **в витрине JS** (карта группа→подгруппа, как в F4/F5), без правки `services/param_catalog.py`:
- **Поиск** → `limits.dig_*`, `flags.dig_*` (7);
- **Граф знаний** → `limits.graph_*`, `flags.graph_*` (7);
- **Хранение** → `full_memory_retention_days`, `memory_backup_hour`, `flags.memory_backup_enabled`/`vec_int8_enabled`/`graph_user_quota_enabled`;
- **Ночной синтез** → `deep_sleep_top_k`, `flags.deep_sleep_enabled`/`belief_decay_enabled` **+ остальные реальные параметры синтеза, найденные в коде** (поиск в T-2900);
- **Отношения** → `flags.relations_*`, `limits.relations_*`, `irony_filter_enabled` в подразделе «Память → Люди и связи → Настройки отношений»; алгоритм стадий не меняется.

Ручной лор не удаляется при очистке авто (§58). Умный кэш (§59) остаётся в «ИИ → Умный кэш». Ни один параметр не теряется (§116) — покрывается картой §117(2,3).

### D7. Совместимость и флаги

Контракт `ExecutionNode` расширяемый (§22/§30): неизвестный `stage`/`kind` → `other` + `stageLabel` из payload; GraphViewer/NodeCard/DetailPanel управляются таблицами enum/label с безопасным fallback → новые узлы Эпика 2 принимаются **без рефакторинга**. Инварианты: Δ DDL = 0, Δ каталога = 0, CSP/zero-build, §57–§64 не ломать, F1/F4/F5/F9/ADR-1024-24 не переписывать.

**Флаги.** Новый флаг **не вводится**. Мягкий откат: `TOKEN_FLOW_NODEFLOW_ENABLED=OFF` — рендер возвращается к прежним плоским бейджам (не использует adapter); `TOKEN_ANALYTICS_ENABLED=OFF` — серверный kill-switch (shape-совместимый пустой ответ, «Нет данных»); крайний откат — `git revert`. Обоснование: ТЗ предупреждает не строить сложную систему флагов; новый env-флаг потребовал бы правки `web/api/routes.py::ui_flags` и не добавляет покрытия (ТЗ §116 не требует флага; прецедент ADR-1024-13 использован только для крупных слоёв). Если @Reviewer потребует гранулярный откат — единственная допустимая ручка `UI_EXECUTION_GRAPH_V2` (default ON, аддитивно в `ui_flags`), решение — @Orchestrator.

### D8. Верификация §75/§76/§116

- **Adapter (JS-unit, фикстуры):** однослойный вызов (`single`), двухслойный (`stage1`→`stage2`), ветка `tool`, неизвестный `step` → `other`, отсутствие `parent_id` → `parentIds=[]`, `price_known=false` → `cost=null`+«Нет данных», агрегатный ответ (`by_module`/`series`), неизвестные поля → `null`/`other`.
- **§75:** 4 режима; выбор L1/L2/модели/модуля; неизвестная стоимость; безлимит; отсутствие фиктивных этапов; мобильное представление; отдельно — adapter одно-/двухслойных.
- **§76:** мониторинг интеллекта (убеждения/парадигмы/эволюция/лента досье/сон/бейджи) — **не менять**, только проверка; прокрутка при новых событиях не сбрасывается.
