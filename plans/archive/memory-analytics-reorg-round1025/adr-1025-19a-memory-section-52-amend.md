# ADR-1025-19a — AMEND-1 (H1 §52): раздел «Память» = 3 карточки, а не 5

- **Статус:** Accepted (Step 2 @Architect, 2026-09-23). **Связано:** `adr-1025-19` (D7), `spec.md` D6, `tasks.md` T-2895; блокер H1 `review.md`.
- **Контекст.** §52 перечисляет 5 имён (Досье/Факты/Связи/Лор чатов/Настройки). В коде — 3 distinct-рендера: `memory_rag` (generic config), `chat_lore` (`web/index.html:2871-3238`), `relations` (`:2657-2860`). F6 presentation-level: новых маршрутов нет (R16), `Δ каталога = 0`. «Карточка-заглушка» запрещена (§0/§57, §116), а карта «Факты» → `memory_rag`+`memorySubgroup='graph'` показала бы настройки RAG под именем «Факты» — прямое смешение с §52.

## Решение (вариант A)
Принять **3 карточки верхнего уровня** («Настройки памяти» / «Лор чатов» / «Люди и связи») как честную реализацию §52 и зафиксировать карту:
- **Досье** — per-person модалка «Досье» из «Люди и связи» (`openDossier`, `web/app.js:4693`, `web/index.html:2835`) + «Живая лента досье»/«Новые факты» (§19, `dossierFeed`).
- **Факты** — «Настройки памяти → Граф знаний» (§54) + живая лента фактов + виджеты фактов (§18).
- **Связи**/**Лор чатов**/**Настройки** — существующие рендеры.

## Альтернативы
- **(B) Добавить карточки «Факты»/«Досье» без маршрутов (алиасы/подгруппы).** Отклонено: dedicated memory-рендера нет (нужен новый рендер = вне scope/R16), а алиас «Факты» → настройки «Граф знаний» давал бы вводящий в заблуждение переход (§52/§0/§57).
- **(C) Новые маршруты `#/memory/facts`/`#/memory/dossier`.** Отклонено: R16/`Δ каталога = 0`, вне F6.

## Последствия
Кода не требуется (текущая реализация = 3 карточки); обновляются `spec.md` D6/R-F6-11 и T-2895. Буквальный список §52 из 5 записей не воспроизводится — отклонение зафиксировано; dedicated экраны «Досье»/«Факты» — вне F6, кандидат в отдельную фичу. Инварианты сохранены: R16, `Δ каталога = 0`, §116 (виджеты памяти целы), §52 (люди ≠ RAG).
