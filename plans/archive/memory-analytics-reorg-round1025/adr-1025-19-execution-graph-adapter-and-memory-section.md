# ADR-1025-19 — Adapter ExecutionGraph как клиентский модуль, канонический `ExecutionNode` под реальные данные, presentation-level раздел «Память»

- **Статус:** Proposed → Accepted на Step 2 F6 (23.09.2026); перевод в «Accepted» — после ревью/аудита и merge (Step 7).
- **Дата:** 2026-09-23.
- **Раунд:** 10.25, Эпик 1, **Волна 3**, фича **F6** `memory-analytics-reorg-round1025` (T-2870…T-2920).
- **Связано:** `spec.md` (этой папки); ТЗ §4, §21–§30, §52–§59, §75, §76, §111, §116, §117; `plans/ARCHITECTURE.md` §54 (F1), §57 (F2/hotfix5/F3), §58 (hotfix6), §59 (hotfix7), §60 (F4/ADR-1025-14), §61 (F5/ADR-1025-15), §62–§64 (hotfix8/9/10); `ADR-1024-7` (token nodeflow, ADR-1024-13, ADR-1024-24).
- **Затрагивает:** `web/app.js` (`tokenFlowTree`/`tokenFlowNodes`/`loadTokenAnalytics`/`fmtCost`/oversight-ветка), `web/index.html` (oversight-блок `:1969-2087`, Статус-карточка `:3246-3259`, «Память»), `web/static/app.css` (аддитивно `.token-flow*`), **новый** `web/static/execution_graph.js`, тесты `tests/js/*`, `tests/test_*analytics*`, `config/settings.py` (только `APP_VERSION`), `README.md`.

- **Номер ADR:** `ADR-1025-18` занят hotfix10 → F6 берёт **ADR-1025-19** (единственный свободный следующий).

## Контекст

§22–§25 требуют **расширяемую карту LLM-вызовов** и **отдельный слой** `Backend metrics → Normalized execution graph → UI`, а §23 даёт пример `ExecutionNode`. При этом ExecutionGraph **уже существует** (`web/api/analytics.py`, PG `llm_usage_events`, `tokenFlowTree`/`tokenFlowNodes`/`tokenSeriesBars`/`loadTokenAnalytics`) и **вторую систему визуализации создавать нельзя** (§111/§116).

Проверенные ограничения:

1. **Данные плоские.** `llm_usage_events` содержит `correlation_id, module, step, tool_name, source, chat_id, model, input_tokens, output_tokens, tokens_estimated, cost_usd, price_known` — **нет** `parent_id`, `status`, `duration`, `finished_at` (`services/usage_events.py:32-37`). API `/analytics/usage/latest` отдаёт плоский `steps[]` (`web/api/analytics.py:41-45`).
2. **kind-словарь узок.** Реальные `step`: `single`, `stage1`, `stage2`, `tool`, `image` (Ф6 spec). `algorithm`/`format`/`publish` §24/§111 — **пока не записываются**; в F6 их нет.
3. **Текущий рендер инференсит.** `tokenFlowTree` attaches `tool` к «ближайшему Синтезатору» (`web/app.js:2229-2249`) — это вывод, а §25 запрещает придумывать связи без `parent_id`.
4. **`fmtCost(0) → '$0'`** — не отличает «цена неизвестна» от «реально 0» (§28).
5. **Инварианты:** Δ DDL = 0, Δ каталога = 0, CSP/zero-build, R16 (не плодить API), §57–§64 не ломать.

---

## Решение

### D1. Adapter — **клиентский** чистый JS-модуль `web/static/execution_graph.js`; `web/api/analytics.py` не расширяется

**Решение.** Преобразование живёт **между** API и рендером, на клиенте: IIFE-модуль `window.ExecutionGraph` с функциями `fromTrace(latest)`, `fromSummary(summary)`, `filter(...)`, `detail(node)`. `tokenFlowTree`/`tokenFlowNodes` перестают вычислять узлы сами и рендерят **только нормализованные** узлы. Серверные ответы и эндпоинты **не меняются**.

**Альтернативы.**
- **(a) Расширить `web/api/analytics.py` (серверная нормализация).** Отклонено: (1) §25 — преобразование должно быть **вне** компонента, но не обязано быть на сервере; (2) R16 — новые поля/эндпоинты растили бы контракт без нужды; (3) §26 «не смешивать трассировку и агрегаты» проще удержать одним ответом на режим, чем новым эндпоинтом; (4) серверная правка затронула бы `web/api/**` шире, чем требует F6. **Но:** adapter не запрещено перенести на сервер в Эпике 2 (S8) — контракт `ExecutionNode` к этому готов.
- **(b) Adapter внутри `web/app.js`.** Отклонено как «файл на 10k строк»: отдельный zero-build файл проще тестировать JS-unit и он CSP-safe (внешний `<script src>`), при этом не заводит сборщика.
- **(c) Adapter внутри SVG/Vue-шаблона.** Прямо запрещено §25.

### D2. Канонический `ExecutionNode` — только подтверждаемые поля; `algorithm`/`format`/`publish` зарезервированы, но не эмитятся

**Решение.** Модель из `spec.md` §4 D1 (таблица «поле → источник»). Ключевые правила:
- `runId = correlation_id`; `id = correlation_id + ':' + index` (порядок `ts ASC, id ASC`) — стабильно и без вымысла.
- `parentIds` — **только** реальная линейная последовательность того же `correlation_id` по `ts` (предыдущий узел). Для `tool`-узлов и первого узла — `[]`: `parent_id` в данных нет, связь не изобретается (§25). UI может визуально группировать `tool` внутри вызова **без утверждения родителя** и с нейтральной подписью.
- `status` — всегда `'unknown'` (в данных нет статуса; выдавать `'success'` = вымысел).
- `durationMs`/`finishedAt`/`provider` — `null`.
- `cost`/`costCurrency` — `null`, если `price_known=false` (не `$0`).
- **`kind`**: `single/stage1/stage2/image → llm`; `tool → tool`; иное/пусто → `other`. `algorithm/format/publish` существуют в enum для Эпика 2, но в F6 **не создаются** (данных нет → узлов нет, §24).
- **`algorithm`-метрики**: только реальные (обработано/сохранено/длительность) из payload Эпика 2; **LLM-токены для `algorithm` не подставляются никогда**.

**Альтернативы.** (a) Синтезировать `parentIds` по эвристике «tool → ближайший llm» — отклонено (§25 прямо запрещает). (b) Проставить `status='success'` как «вызов записан» — отклонено (§24: не выдавать вымысел за факт). (c) Копировать TS-пример §23 дословно — отклонено (§23: «адаптировать к существующему стеку»). (d) Добавить `parent_id` в схему — Δ DDL ≠ 0, вне F6.

### D3. Два режима §26 на существующих эндпоинтах; взаимно исключающие ветки

**Решение.** «Последний вызов» → `fromTrace(/usage/latest)`; «День/Неделя/Месяц» → `fromSummary(/usage/summary?period=…)`. Ветки отрисовки не смешиваются: агрегат не рисуется как трассировка, трассировка не берётся из агрегатов. Пусто → «Вызовов ещё не было» / «За период данных нет». Агрегатные узлы: `status='unknown'`, `parentIds=[]`.

**Альтернативы.** (a) Единый «умный» вид, смешивающий оба ответа — отклонено (§26). (b) Новый эндпоинт для трасс — R16, отклонено. (c) Трактовка агрегата как точной трассировки — запрещено §25.

### D4. Интерактивность §27 / mobile §29

**Решение.** Desktop — side-panel; mobile — bottom-sheet (отдельный, не навигационный). Фильтры (модуль/модель/этап/период/статус) — только на «Аналитике»; превью Статуса их не получает. Mobile: вертикальная последовательность / раскрываемый агрегат; горизонтальный граф не сжимается до 320 px. CSS — аддитивное расширение `.token-flow*`; fullscreen/`--shell-h` (§63/§64) сохраняются.

**Альтернативы.** (a) Полный набор фильтров и в превью — запрещено §27. (b) Сжать граф в 320 px — запрещено §29. (c) Новый визуальный компонент — вторая система визуализации, запрещено §111/§116 (reuse существующих классов/структуры).

### D5. Честные состояния §28

**Решение.** `fmtCost` даёт `$0` только при подтверждённом нуле; доля с `price_known=false` → «Нет данных». Бюджет `∞` → «Без лимита», progress bar не заполняется. «Стоимость LLM» и «Ресурсы сервера» — разные блоки с разными источниками и подписями. Тест на отсутствие подмены.

**Альтернативы.** (a) Оставить `$0`-дефолт — прямо запрещено §28. (b) Скрывать неизвестную цену — искажает «расходы»; «Нет данных» честнее.

### D6. Превью Статуса §21 — источник и компонент от F6, композиция от F11

**Решение.** F6 отдаёт `fromTrace(latest)` + компактный блок (корень + этапы + итог + честная цена) и mount в зоне карточки «Аналитика» на Статусе (§12–§14). Превью — **не одна строка с токенами** (§21) и не полный набор фильтров (§27). Финальную композицию/позицию витрины Статуса §11–§20 владеет **F11** (§58.6: heartbeat и §12-порядок уже разграничены); F11 использует контракт превью без рефакторинга.

**Альтернативы.** (a) F6 сам строит витрину Статуса — конфликт с F11 (§11–§21). (b) Превью = одна строка с числом токенов — прямо запрещено §21. (c) Отдать превью целиком F11 — тогда §21 не закрыт в F6; поэтому разделение «данные+компонент (F6) → композиция (F11)».

### D7. «Память» §52–§58 — presentation-level перегруппировка, `Δ каталога = 0`

> **AMEND-1 (H1 §52, 23.09.2026):** карточек — **3**, не 5. См. `adr-1025-19a-memory-section-52-amend.md` (карта «Досье»/«Факты» через существующие поверхности; новых маршрутов нет).

**Решение.** Навигация `#/memory` получает **3 карточки — «Настройки памяти» / «Лор чатов» / «Люди и связи»** (AMEND-1); существующие рендеры `relations` (`web/index.html:2657-2860`) и `chat_lore` (`:2871-3238`) сохраняются, generic `memory_rag` становится «Настройки». Группировка в 5 подгрупп (Поиск / Граф знаний / Хранение / Ночной синтез / Отношения) — **карта группа→подгруппа в витрине JS** (подход F4/F5), `services/param_catalog.py` не правится. Ручной лор не удаляется при очистке авто (§58). §59 smart cache остаётся в «ИИ → Умный кэш». Просмотр людей не смешивается с настройками RAG (§52).

**Альтернативы.** (a) Переклассифицировать группы в каталоге — `Δ каталога ≠ 0`, нарушает §116. (b) Новые страницы/эндпоинты для памяти — R16/Δ DDL. (c) Перенести smart cache в «Память» — §59 явно указывает «ИИ → Умный кэш».

### D8. Совместимость §30/§111 и флаги

**Решение.** Контракт расширяемый: неизвестный `stage`/`kind` → `other` + `stageLabel` из payload; GraphViewer/NodeCard/DetailPanel управляются enum/label-таблицами с fallback → узлы Эпика 2 принимаются без рефакторинга (§30/§111). Новых серверных узлов Эпика 2 в F6 нет.

**Флаги: новый флаг не вводится.** Мягкий откат — `TOKEN_FLOW_NODEFLOW_ENABLED=OFF` (прежние плоские бейджи, adapter не используется), `TOKEN_ANALYTICS_ENABLED=OFF` (серверный kill-switch), крайний — `git revert` + тег `pre-round1025-f6`.

**Альтернативы.** (a) `UI_EXECUTION_GRAPH_V2` (env-only, аддитивно в `ui_flags`). Отклонено как default-решение: требует правки `web/api/routes.py::ui_flags` (вне минимального диффа F6), а §ТЗ предостерегает от сложной системы флагов; покрытие отката уже есть через `TOKEN_FLOW_NODEFLOW_ENABLED`. **Допустимо** как единственная ручка, **если** @Reviewer потребует гранулярный откат — решение за @Orchestrator. (b) Каталоговый ключ-флаг — `Δ каталога ≠ 0`, запрещено. (c) Progressive delivery — не применяется (один прод).

## Последствия

**Плюсы.** Единая честная модель узла; adapter вне компонента (§25); расширяемость под Эпик 2 без рефакторинга; отсутствие второй системы аналитики; `Δ DDL = 0`, `Δ каталога = 0`; отсутствие фиктивных узлов/токенов и `$0`-подмены.

**Минусы/цена.** Текущее поведение `tokenFlowTree` (attaches `tool` к Синтезатору) заменяется честной последовательностью — визуально иначе для tool-ветки (осознанно, §25). Новый статический файл в `web/static/` (zero-build, CSP-safe). `algorithm`/`format`/`publish` в F6 не видны (данных нет) — появятся только с Эпиком 2.

**Затронутые контракты.** UI-контракт карты вызовов (витрина `tokenFlowTree`→`ExecutionGraph`); `fmtCost` семантика нуля; раздел «Память» (навигация/раскладка). Серверные контракты `web/api/analytics.py`, таблицы PG, каталог — **не меняются**.
