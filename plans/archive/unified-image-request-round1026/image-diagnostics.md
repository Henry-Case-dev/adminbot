## 1. Факты (EVIDENCE) — пробы

### 1.1 HY-01 — tool-совместимость провайдера/модели (T-3555)

**Проба:** реальный `chat/completions` c `tools` = канонический набор
`active_tools(image_generation_enabled=True)` через прод-клиент `services.llm_client`
(тот же путь, что `chat_with_tools`), `tool_choice="auto"`, фикс-набор 5 свободных
image-фраз, temperature 0, A/B двух описаний (`TOOL_GENERATE_IMAGE_LEGACY` vs
`TOOL_GENERATE_IMAGE_V21`). Скрипт пробы — вне рабочего дерева (temp); ключ не печатается.

**Результат (10/10 запросов): `LLMServerError`**
- HTTP **500** от `https://apinet.cloud/v1/chat/completions`, тело провайдера:
  `get_channel_failed` — «по модели deepseek-v4-flash в группе default доступный
  канал не существует (retry)» (канал модели не существует).
- Fallback-модель клиента (`api.deepseek.com`) — HTTP **401** (нет отдельного ключа).
- **Контроль (тот же эндпоинт, БЕЗ tools, промпт «ping»)** — **тоже 500** ⇒ отказ
  **не специфика tools**: на env-эндпоинте билдера модель `deepseek-v4-flash`
  недоступна целиком.

**Вывод (честно):**
- Конфигурация env билдера (`.env`) ≠ прод-конфигурация (прод поднимает модель
  из PG-каталога, который отсюда недоступен). Прод активен и обслуживает чат —
  «внешний отказ прод-провайдера» из этих данных **не доказывается**.
- **HY-01 = НЕПОДТВЕРЖДЕНО** (и не опровергнуто). «Отказ модели» **не выдумывается**.
- Это **не** ветка «внешняя причина → остановить C/D/E»: ни один факт не указывает
  на отказ прод-провайдера как на доказанную проблему; известный сбой —
  билд-окружение.

**План проверки владельцем/оператором (1 команда на прод-хосте):** тот же пробный
`chat/completions` c активным прод-набором `tools`. Критерий:
`finish_reason=="tool_calls"` на свободной image-фразе ⇒ поддержка есть (HY-01
опровергнут); иначе — **честная фиксация внешнего ограничения** и (при смене
модели/провайдера) отдельный `ARCHITECT_DECISION_REQUIRED`.

### 1.2 HY-04 — plain-fallback (T-3555)

- **Механизм (код, факт):** `tool_loop.py:288–299` — `LLMError` на
  `round_index==0` → лог `[tools] provider rejected tools — plain answer` →
  plain-генерация без tools (FR-15). Повторно подтверждён чтением текущего кода.
- Факт срабатывания в проде — **не проверяем отсюда** (логи недоступны, §0).
  **HY-04 = НЕПОДТВЕРЖДЕНО / НЕ ОПРОВЕРГНУТО.** План: `grep "provider rejected tools"`
  по journald прод-сервера за окно наблюдения сбоев (владелец).

### 1.3 HY-02 — реальная ошибка генератора (T-3556)

- **Код-факт:** классификация причин различает классы (`timeout/network/
  unauthorized/bad_request/rate_limited/budget/bad_json/too_large/…`):
  лог `[image] generation failed | reason=…` — `image_generation.py:970–986`
  (строки после A3); `[image] attempt failed | attempt=N/M | reason_class=…` —
  `:1078–1088`.
- Прод-логи недоступны (§0) ⇒ **HY-02 = НЕПОДТВЕРЖДЕНО / НЕ ОПРОВЕРГНУТО**
  (нет фактического распределения `reason_class` в проде).
- Гарантия A3 (блок E): реальный `reason` уже доводится в tool-результат
  (`status:"error", reason:…`), синтетический «отказ модели» исключён тестом.
- План проверки владельцем: `journalctl` + grep `\[image\] (generation failed|
  attempt failed)` за окно «сбоев», разбивка по `reason_class`.

### 1.4 HY-03 — состояние рубильников (T-3557)

**EVIDENCE (env-слой, фактическое чтение `.env`+settings, 24.09.2026):**
- `IMAGE_GENERATION_ENABLED=True`, `IMAGE_GENERATION_MODULE_ENABLED=True`,
  `IMAGE_MODEL_COMPAT_ENABLED=True` — модуль изображений **ON**.
- `TOOL_CHAIN_LIMITS_ENABLED=True`, `ARTICLE_TOOL_ENABLED=True` — A2-контур ON.
- LLM: `LLM_MODEL_NAME='deepseek-v4-flash'`, `LLM_BASE_URL='https://apinet.cloud/v1'`
  (ключ присутствует, не печатается).

- **Per-chat слой** (`flags.image_generation_module_enabled` через
  `get_chat_param`) отсюда **не читаем** (PG недоступен). Тем самым перчатка:
  env-слой детерминированно НЕ блокер; per-chat — неизвестен.
- **HY-03 = ЧАСТИЧНО опровергнуто** (env-ON); per-chat — требует чтения на проде
  (план: чтение `flags.image_generation_module_enabled` per-chat из каталога).

### 1.5 HY-06 — форма запроса (T-3557)

- **Механика подтверждена кодом** (независимо от corpus): пре-гейт срабатывает
  ТОЛЬКО на «(бот|bot)[\s,:-—]*(нарисуй|сгенерируй|создай (изображение|картинку|мем|арт))…»
  (`IMAGE_KEYWORD_RE`, `image_generation.py:93–101`); при срабатывании tool-путь
  детерминированно OFF на ход (`image_pre_gate_fired` → `image_enabled=False`,
  `direct_chat_service.py:881/938`; A0 EVIDENCE, повторно подтверждено).
- Свободная форма («нарисуй кота» без «бот») пре-гейтом не ловится → инструмент
  объявляется модели.
- **Привязка к наблюдаемым «сбоям» недоказуема отсюда** (corpus нет).
- **HY-06 = механика ПОДТВЕРЖДЕНА (узкий scope); полная привязка к симптомам —
  по прод-corpus** (план: снятие фактических фраз у оператора / из логов).

### 1.6 HY-05 — влияние описания на выбор модели (T-3557)

- A/B-проба (OLD vs NEW описание) спроектирована и запущена (§1.1), но **не
  дала результат**: все 10 попыток — живой 500-отказ эндпоинта (билд-окружение).
- **HY-05 = НЕПОДТВЕРЖДЕНО / НЕ ОПРОВЕРГНУТО (проба не выполнена).**
- Санкция D4 не зависит от HY-05: текст описания — **требование §21 (6 пунктов
  понимания модели)**, а не «доказанный фикс». Внесён текст, канон 11 сохранён.
  A/B-проба передаётся владельцу вместе с прод-пробой HY-01 (та же команда).

## 2. Сводная таблица вердиктов (вход для AMEND ADR-1026-16, T-3558)

| HY-04 | plain-fallback срабатывает в проде | **НЕПОДТВЕРЖДЕНО / НЕ ОПРОВЕРГНУТО** (механизм кода факт; логов нет) | §1.2 | Grep journald владельцем |

**Итог блока B:** ни одна HY из этого окружения не стала **доказанной причиной**;
ни одна не опровергнута полностью (кроме env-слоя HY-03). Доказанный планировочный
вывод D1 соблюдён: унификация §18/§20 выполняется **всегда** (требование ТЗ);
остальные минимальные фиксы — **страховочные** и не зависят от нераскрытой причины:
(1) авторитетный маркер «уже handled» (D3); (2) fail-closed-валидация + доведение
реального `reason` + возврат в цикл (§21); (3) текст описания по 6 пунктам (D4).
Кандидат «внешняя причина (провайдер/модель)» остаётся **открытой гипотезой**,
проверяется живой прод-пробой проведения владельцем; «отказ модели» никем не
объявлялся.
