# ADR-1026-1 — Алгоритмический префильтр Саммари: каталог `summary.filter.*` и форма алгоритма

- **Статус:** Accepted (Step 2 @Architect, 23.09.2026)
- **Фича:** S1 `summary-filter-round1026` (Эпик 2, этап 0 «подготовка сообщений»)
- **Тип:** backend/алгоритм + Δ каталога (санкционировано) + UI-метаданные
- **Связано:** ADR-1013-3 (промпт-канон), ADR-1022-3/4/5 (ровно 2 LLM-вызова), ADR-1023-1 (маркер /summary), ADR-1025-24 **D4** (не менять публикацию до live-приёмки Эпика 1)
- **Baseline:** HEAD `01f3c57`, `APP_VERSION` 2.58.17, каталог 459/418/434/98/96/21, SQLite `user_version=12`.

## Контекст

ТЗ §80 вводит пайплайн `лог → Алгоритмический фильтр → Восстановление контекста → L1 Кластеризатор → L2 Писатель → формат → публикация`. S1 реализует **первый** шаг — детерминированный префильтр без LLM (§87–§89, §91–§93). Открыты D1–D7 (`tasks.md`). Публикационный путь менять нельзя (ADR-1025-24 D4). Система обязана остаться с **ровно 2 LLM-вызовами** (ADR-1022-4).

## Решения

**D1. `summary.filter.*` → новые параметры каталога (санкция Δ каталога), не env-only.**
§89 требует «тонкую настройку» + подбор порога плотности по реальным логам, а §87 — UI-маршрут «Подготовка сообщений»; T-3139 требует hot-переключения **без рестарта**. Env-only `ClassVar` не даёт ни UI-редактируемости, ни hot-переключения, ни per-chat. Поэтому — существующий каталог (`param_catalog`/`chat_params`, `hot.get`), параллельное хранилище запрещено (§87).
Ключи и дефолты (`{category}.{field_lower}`): `flags.summary_filter_enabled=ON`, `flags.summary_filter_reply_context_enabled=ON`, `limits.summary_filter_min_weight=1`, `limits.summary_filter_min_words_for_bonus=5`, `limits.summary_filter_burst_window_seconds=120`, `limits.summary_filter_min_burst_density=4`, `limits.summary_filter_context_neighbors=1`, `limits.summary_filter_context_max_messages=50`; группы `flags_summary_filter`/`limits_summary_filter` → вкладка `mod_summary`.
**Δ каталога:** REGISTRY 459→467, Settings 418→426, categorized 434→442, GROUPS 98→100, `_TAB_BY_GROUP` 96→98, `TAB_RULES` 21. JS `MODULES` без изменений. per_chat — да (каскад global→chat→дефолт).
Альтернатива (env-only, Δ каталога=0) отклонена: не удовлетворяет §87/§89/T-3139. Альтернатива (новая категория) отклонена: категории фиксированы.

**D2. Δ DDL = 0 подтверждено.** Фильтр — чистая функция в памяти; хранение — существующие `chat_params`/каталог и `smart_messages` (без новых таблиц/колонок), SQLite остаётся `user_version=12`.

**D3. Промпт-каноны не затрагиваются.** §87–§89 — алгоритм; `services/summary_prompts.py` вне диффа; `PREV_*`/`PROMPT_MIGRATIONS`/эталон и ступень ADR-1013-3 не требуются. Если бы потребовались — только `PREV_*`+байт-тесты атомарно.

**D4. Форма алгоритма — детерминированная, максимум 1 балл за критерий.**
- Балл 0..4: (1) `reply_to_id != None` **или** текстовое `@`-упоминание; (2) на сообщение ответили в окне (индекс по **`tg_message_id`**, т.к. `reply_to_id` хранит Telegram id — установлено по `handlers/summary.py:181-183`); (3) всплеск по плотности; (4) слов > `min_words_for_bonus`.
- Всплеск: trailing-окно `[t−W, t]`, «всплеск» при числе сообщений ≥ `min_burst_density` (`==` → да). Дефолт 4 за 120 с ⇒ два соседних сообщения — не всплеск (§88).
- Порог: `kept = {score >= clamp(min_weight,0,4)}`; `==` порога → сохранить. `min_weight>4` клэмп до 4 (не «удалить всё молча»).
- Не-события: сообщения бота/прошлые Саммари (`user_id == bot_id`) → `score=0`, исключены из children/burst (§91).
- Детерминизм: без системных часов, тай-брейк `(timestamp,id)`, вход уже отсортирован.
- Fail-open: исключение → WARNING + нефильтрованное окно; пустой `kept` при непустых `rows` → `kept=rows`; `trigger_message_id` форсированно сохраняется (ADR-1023-1); `dropped` сохраняется для S2.
- «Не теряет важное»: ответ/родитель → балл ≥1; потери обратимы через `dropped`.

**D5. Граница S1 ↔ S3 (§93).** S1 выполняет **механическую** часть: оценка токенов по существующим потолкам, перекрывающиеся фрагменты, дедуп по `id`, сохранение `reply_to_id`/`tg_message_id`. «Объединить темы / устранить **семантические** дубли» — **S3** (L1 LLM, §94–§95). Контракт фрагментов: `FilterResult.fragments` (`Fragment{index,message_ids,overlap_message_ids,reason}`) либо `None`; `kept`/`dropped`/`scores` доступны всегда. S3 потребляет фрагменты/`kept`; S2 — `dropped` + §89-ключи.

**D6. Интеграция/UI/логи.**
- Врезка строго между `get_window_messages` и `xml.build`; фильтруется **только** XML-история L1, все прочие потребители `rows` (RAG/graph/memorize/постфикс) — на исходных `rows` (нет регресса recall). Порядок этапов/публикация не меняются; 0 новых LLM-вызовов.
- Fail-open (см. D4) + OFF = байт-в-байт прежний путь без побочных записей.
- UI: группы на вкладке `mod_summary` через F0 `persistItems` (одна мутация), метаданные в JS `MODULES`, mobile вертикально, CSP/zero-build.
- Логи `FILTER_START/COMPLETE/ERROR` с полями §109; `run_id` = существующий `correlation_id`; метрики — в аддитивную структуру для S8 (узлы `algorithm` эмитит S8). R17/R18.

**D7. Инварианты/тесты/деплой.** Δ DDL=0; Δ каталога = санкция D1; CSP/zero-build; R17/R18; публикация и двухвызовность не тронуты. Тесты — unit-матрица фильтра + регресс Саммари + обновление чисел `test_param_catalog`. **Deploy = VERIFIED (да):** S1 поставляет рантайм `services/**`, `config/settings.py`, `services/param_catalog.py`, `web/app.js` → **bump `APP_VERSION` 2.58.17 → 2.58.18** + README + cache-bust. Гейт S6/S10 (публикация/hybrid) остаётся закрытым до live-приёмки Эпика 1 (ADR-1025-24 D4).

## Последствия

- Δ каталога (≈+8 записей, +2 группы) — первый sanctioned Δ в Эпике 2; Scanner T-3153 сверяет точные числа; тесты-инварианты каталога обновляются.
- Появляется обратимая точка расширения: S2/S3/S8 используют `dropped`/`fragments`/метрики без переделки контура.
- Ограничение: «адресное упоминание» — эвристика по тексту (в строке окна нет поля `mentions`); `reply_to_id` — основной сигнал.
- Публикация, 2 LLM-вызова, промпт-каноны — без изменений.

## Альтернативы (сводно)

- Env-only вместо каталога — отклонено (D1).
- Семантический дедуп/склейка тем в S1 — отклонено (нужен LLM; это S3, D5).
- Всплеск «любое соседство» — отклонено §88 (нужна плотность, D4).
- Фильтрация исходных `rows` для RAG — отклонено (риск падения recall; фильтруем только XML, D6).
- Изменение публикационного пути — запрещено ADR-1025-24 D4.
