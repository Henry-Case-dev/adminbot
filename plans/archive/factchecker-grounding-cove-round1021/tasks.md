## 1. Цель

Прекратить галлюцинации фактчекера: бот выдумывает несуществующие теги вида `[04.2023 | fact:2574]` и несёт
бред, не связанный с базой. Требуется:

- Фактчекер может цитировать **только** те ID и даты, которые **физически присутствуют во входящем контексте**.
- Паттерн **Chain-of-Verification (CoVe)**: сначала выписать найденные факты в скрытый блок размышлений,
  сверить с запросом, затем писать вердикт.

## 2. Решение (Шаг 0) — что уже есть / что новое / факт-ошибки ТЗ

- **Full Tool Access фактчекера реализован в 10.20** (раунд 10.20, фаза E, T-1905…T-1912). Посылку ТЗ «фактчекер без тулов» **не переоткрывать**.
- **Стриппер reasoning-тегов есть:** `services/reply_postprocess.py::strip_reasoning_tags`; интеграция в `services/summary_cleanup.py:8,24-27`.
- **Reasoning-черновик парсится:** `services/llm_client.py:1012-1020` (`reasoning_content`/`reasoning`/`thinking`) — скрытый блок CoVe можно вести через него.
- **Промпт фактчека:** `services/factcheck_prompts.py::FACTCHECK_SYSTEM_PROMPT` (+ слепок раунда 5 для авто-миграции PG, `prompt_migrations.py`).

### 2.2 Что новое (реализовать)
- **Strict grounding**: валидатор цитат — ID/даты только из входного контекста; «фантомные» теги **жёстко вырезаются** (Д6=вырезать).
- **CoVe-блок** в промпте + пост-обработке: `найденные факты → сверка → вердикт`; черновик не уходит пользователю. **Активен по умолчанию** (UPD).
- Запрет выдуманных `[ММ.ГГГГ | fact:ID]`, если ID/месяц отсутствуют в контексте.

### 2.3 ⚠️ Факт-ошибки/уточнения ТЗ
- **`factcheck_service.py` уже имеет Full Tool Access** (10.20) — не «изолировать RAG заново», а **усилить grounding** поверх существующего пути.
- **Канон-конфликт:** текущий `FACTCHECK_SYSTEM_PROMPT` **предписывает** «дай понять, что ты уже проверял эту инфу
  ранее … и тебе не нужно повторять дважды» (`services/factcheck_prompts.py:43,72,104`) — ТЗ это **ЗАПРЕЩАЕТ**
  (см. F3, канон-миграция ADR-1013-3). Правка промпта фактчека — **атомарно** с F3, не отдельным проходом.
- **Точки входа фактчека** для @Architect — уточнить по `services/factcheck_service.py` (вызов `llm.generate(...)`).

## 3.1 Fix-round 10.21 — Issue 3 (Medium): grounding на tool-loop пути

> реально добытые инструментами (`dig_into_lore`), вырезались. Инварианты: R17 (без текстов в логах),
> Δ каталога = 0; phantom-теги по-прежнему вырезаются.

- [x] **T-2014** [@Builder] Накопить выводы инструментов в `chat_with_tools` (`ToolLoopResult.tool_context`,
  аддитивный атрибут, в логи не пишется) и добавить их в множество допустимых grounding-якорей в
  `factcheck_service.check_claim`. *(Реализовано: `services/tool_loop.py` — `tool_context` во всех ветвях
  возврата; `services/factcheck_service.py` — слияние якорей до `cleanup_llm_text`.)*
- [x] **T-2015** [@Builder] Тесты: id из tool-вывода ⇒ тег сохранён; фантомный id ⇒ вырезан; без tool-вызова

- [x] **T-2016** [@Builder] **Fix-round 2 (Low): месяц ↔ ISO-месяц в grounding.** Валидатор сопоставляет
