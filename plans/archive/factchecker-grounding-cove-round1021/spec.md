## 1. Проблема и цель

**Симптом (ТЗ):** фактчекер выдумывает несуществующие теги вида `[04.2023 | fact:2574]` и несёт бред,
не связанный с базой.

**Цель:**
1. **Strict grounding:** цитировать можно **только** те `fact:ID` и даты, которые физически присутствуют
   во входящем контексте.
2. **Chain-of-Verification (CoVe):** сначала выписать найденные факты в скрытый блок размышлений,
   сверить с запросом, затем писать вердикт; черновик НЕ уходит пользователю.

## 3. Целевая архитектура

### 3.1 Детерминированный grounding-валидатор (без LLM)
Новый чистый модуль (напр. `services/grounding_validator.py`):
1. **Сбор допустимого множества** из `user`-контента (`<claim>`, `<chat_context>`, `<search_results>`,
   RAG-блок, lore-вывод): `fact:(\d+)` → `allowed_ids`; `\d{2}\.\d{4}` → `allowed_months`;
   `\d{4}-\d{2}-\d{2}` → `allowed_dates`.
   - **UPD fix-round 2:** месяц `ММ.ГГГГ` и ISO-дата сопоставляются также по нормализованному ключу
     `YYYY-MM` (месяц ↔ ISO-месяц). Иначе легитимный тег `[01.2024 | … | fact:N]` при наличии в контексте
     только ISO-даты `2024-01-01` вырезался бы как фантом. Риск ложного пропуска ограничен рамками одного
     месяца и признан несущественным (теги и так проверяются по `fact:ID`).
2. **Пост-обработка вердикта:** паттерн фантомного тега `\[\s*\d{2}\.\d{4}\s*\|\s*fact:\s*(\d+)\s*\]`:
   - id ∈ `allowed_ids` и месяц ∈ `allowed_months` → тег **сохраняется**;
   - иначе → тег **жёстко вырезается** (Д6=вырезать; без замены на «(без подтверждения)»), инкремент счётчика.
3. «Голые» `fact:ID` вне допустимого множества → id вырезается.
4. Валидатор **никогда не бросает**; логирует только counts (`stripped_phantom`, `kept`) — R17.

> Валидатор встраивается в `check_claim` ПОСЛЕ `cleanup_llm_text` (`:121`), до `strip_lore_html`.
> Он аддитивен и безопасен → **работает всегда**, независимо от флага CoVe.

### 3.2 Chain-of-Verification (one-call, фактор-ревью)
Правка `FACTCHECK_SYSTEM_PROMPT` добавляет обязательный скрытый блок:
```
Перед вердиктом в тегах <reasoning> … </reasoning> (НЕ для пользователя):
  A) выпиши найденные факты ровно в том виде, как они есть в контексте (ID/даты из меток),
  B) сверь каждый с <claim>,
  C) отметь, чего в контексте НЕТ — этого в вердикте быть не должно.
Вердикт — только текст ПОСЛЕ </reasoning>.
```
`strip_reasoning_tags` уже удаляет `<reasoning>` перед отправкой (`cleanup_llm_text`). Стоимость: **+0 LLM-вызовов**
(один и тот же вызов несёт и черновик, и вердикт). Это компромисс: полный factored-CoVe из статьи требует
отдельных вызовов; здесь внешним «verifier» служит детерминированный валидатор §3.1.

### 3.3 Поведение при отсутствии фактов
Если валидных якорей нет вовсе — промпт обязывает не выдумывать теги и честно писать вердикт без ссылок;
валидатор гарантирует, что фантомный тег не уйдёт даже при невыполнении промпта.

## 6. План тестов

1. **Фантомный тег:** вердикт `[04.2023 | fact:2574]` при отсутствии id → тег срезан; при наличии → сохранён.
2. **Ложные срабатывания:** корректный `[04.2024 | Автор: X]` из контекста не портится.
3. **CoVe:** `<reasoning>`-блок срезан (`cleanup_llm_text`), вердикт после `</reasoning>` доставлен.
4. **Нет фактов:** пустые допустимые множества → теги не выдумываются, валидатор не падает.
5. **Регрессии:** Full Tool Access (tool-loop) не сломан; `test_factcheck_prompts.py`, `test_prompt_migrations.py` зелёные.
6. **R17:** лог валидатора без содержимого и значений.

## 7. Риски и откат

- **R1 канон-атомарность** — один коммит с F3: константа + `PREV_*` + `prompt_migrations.py` + `docs/canon/**` + тесты.
- **R2 ложно-негативный grounding** — тесты на реальных форматах меток; при сомнении тег не удаляем, а сохраняем (идём от точного формата и допустимого множества; Д6=вырезать только фантом).
- **R3 «двойная стоимость CoVe»** — фактически +0 вызовов (hidden-блок в том же вызове).
- **R5 пересечение с F1** — Слой Б пользуется тем же инвариантом «только из контекста».
- **Откат:** обратная канон-миграция + `git revert`; валидатор аддитивен.

  https://doi.org/10.18653/v1/2024.findings-acl.212 — draft → verification questions → independent answers →
  verified response; factored-вариант снижает риск копирования галлюцинации (60.8 → 63.7 FactScore;

- **LLM2 (verifier как System 2):** https://ar5iv.labs.arxiv.org/html/2412.20372 — внешний процессный
