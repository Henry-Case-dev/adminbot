# ADR-1011-2 — Embed-фоллбэки как first-class catalog: sanctioned Δ каталога

- **Статус:** Accepted (@Architect, 12.09.2026); требуется явный апрув владельца
  на изменение состава категорий (не счётчиков).
- **Пункт ТЗ:** 2.3 (полноценные инпуты Base URL/Модель/Ключ/Проверить у
  «Фоллбэк 1/2» блока «Эмбеддинги»).

## Контекст (evidence)

- В каталоге у embed-фоллбэков есть **только display-name**:
  `EMBEDDING_FALLBACK_DISPLAY_NAME`, `EMBEDDING_FALLBACK2_DISPLAY_NAME`
  (`services/param_catalog.py:560-563`, группа `models_embeddings`).
- Реальные `EMBEDDING_FALLBACK_BASE_URL / _MODEL / _API_KEY / _API_KEY_2`
  лежат в `_INFRA` (`services/param_catalog.py:429-436`) — `category=None`,
  **не мигрируются, не попадают в `/api/config`, не редактируются из UI**.
- Runtime: `services/llm_client.py:292-303` читает их **напрямую из
  settings** (без `hot.get`), `services/status_service.py:257-278` — тоже.
  Семантика: ОДИН `base_url` + ОДНА `model` + ДВА ключа каскадом
  (`_embed_fallback_api_key`, `_embed_fallback_api_key_2`).
- Значит, «просто нарисовать инпуты» нельзя: без переноса в каталог поля
  не появятся в `configItems`, не сохранятся и будут проигнорированы
  рантаймом (фейковые инпуты).

## Решение (sanctioned Δ каталога БЕЗ роста счётчиков)

Перевести 4 параметра из `_INFRA` (category None) в first-class каталог:

| PG-ключ | Категория/группа | Тип | Secret |
|---|---|---|---|
| `models.embedding_fallback_base_url` | models / `models_embeddings` | str | нет |
| `models.embedding_fallback_model` | models / `models_embeddings` | str | нет |
| `keys.embedding_fallback_api_key` | keys / `keys_llm` | str | **да** |
| `keys.embedding_fallback_api_key_2` | keys / `keys_llm` | str | **да** |

`EMBEDDING_FALLBACK_TIMEOUT_SECONDS` / `_MAX_RETRIES` остаются в `_INFRA`
(технические, владелец их не просил).

**Инварианты НЕ меняются:** REGISTRY **400** / GROUPS **90** / Settings
**372** / mapped **88** / `TAB_RULES` **19** — это перемещение записей между
списками каталога, не добавление. Группы `models_embeddings`/`keys_llm` уже
принадлежат вкладке `llm_providers` (`param_catalog.py:1647-1655`).

**Read-path (обязательно, иначе инпуты бесполезны):**
- `services/llm_client.py:292-299` → `hot.get("models.embedding_fallback_base_url", …)`,
  `hot.get("keys.embedding_fallback_api_key", …)`, `…_api_key_2`, `…_model`.
  Тесты `test_llm_client.py:620-741` без кэша получают прежние kwarg-дефолты
  → паритет.
- `services/status_service.py:257-278` → те же `hot.get`.
- Значение по умолчанию = текущий `settings.EMBEDDING_FALLBACK_*` → поведение
  не меняется.

**Сохранение значений (migration):** non-secret `base_url`/`model` сидятся
автоматически `_seed_settings` (`services/pg_db.py:415-436`) из settings.
Secret-ключи там не сидятся (R17-политика) → **обязательный деплой-шаг**:
идемпотентный `python scripts/migrate_env_to_pg.py --only-category models,keys`
(БЕЗ `--force`; `ON CONFLICT DO NOTHING`), который экспортирует .env-значения
ключей в PG, печатая только `configured`. До этого шага «Проверить» уже
работает через `hot.get`-дефолт на settings.

**Shared base_url/model у Фоллбэк 1/2:** сохраняем текущую семантику —
оба подблока биндят одни `models.embedding_fallback_base_url`/`_model`
(различаются только API-ключом). UI помечает shared-поля подсказкой, чтобы
не было иллюзии независимости. Разделение base/model на два независимых
провайдера — вне скоупа (потребовало бы менять каскад `llm_client`).

## Отклонено

- **Новые параметры `embedding_fallback2_base_url/model`** — меняет рантайм-
  каскад и счётчики; избыточно.
- **Оставить всё как есть (только display-name)** — не выполняет ТЗ 2.3.
- **Показывать инпуты, но не менять read-path** — фейковая функциональность.

## Последствия

- Плюс: embed-фоллбэки полностью редактируемы и тестируемы из UI; текущие
  значения сохранены.
- Минус: `test_migrate_env_to_pg.py:246,256` (13 ключей keys → 15) и
  `test_webapp_round1010_ui.py`/`test_frontend_tab_mapping.py` часть маркеров
  обновляются осознанно; рост счётчиков НОЛЬ.
- Feature flag не требуется (значения те же, rollback = revert + миграция
  аддитивна/идемпотентна).
