# ADR-1016-3 — Версионирование канона «Гайда по фичам» и write-path (PG-only)

> **Статус:** Accepted (Step 2 @Architect, 14.09.2026). **Раунд:** 10.16. **Фича:** F2 `guide-delivery-round1016`.
> **Связано:** §36 `ARCHITECTURE.md` (F7 10.15), `_migrate_info_how_it_works_v1015`, `_seed_intelligence_guide` (F6 10.14).

## 1. Контекст

Канон F7 доставлялся миграцией по **байт-равенству** единственному слепку `PREV_DEFAULT_INFO_TEXT`. Прод-PG содержал дрейфовый текст (не байт-равный слепку) → миграция пропущена, гайд остался старым. Дополнительно `save_text` (`/edit_info`) писал в **git-tracked** `info_text.md`, создавая расхождение с репозиторием и блокируя fast-forward pull.

## 2. Решение

1. **Версия канона:** поле `canon_version` в JSONB `content.info_how_it_works`; код-константа `INFO_CANON_VERSION`. Любая правка `DEFAULT_INFO_TEXT` обязана бампать версию и добавлять прежний текст в реестр слепков.
2. **Нормализованное сопоставление:** `normalize_canon` (EOL + trailing whitespace + strip) против `KNOWN_INFO_SNAPSHOTS`.
3. **Правило авто-обновления:** `stored < CURRENT` И текст ∈ известных слепков → перезапись каноном; неизвестный текст → **одноразовая форс-доставка канона** (ревью-итер. 1, High: владелец разрешил перезаписать текущий прод-текст, чтобы гарантировать доставку без ручного reset), после чего маркер `canon_delivered_version` блокирует повторное затирание — последующие ручные правки не теряются (WARNING + `canon_drift`), для отката — явный force-reset.
4. **Force-reset** — REST под RBAC `edit_info`, с `prev_html`/`prev_updated_at` в значении и аудитом `updated_by` (id, R16).
5. **Write-path PG-only:** `save_text` не пишет `info_text.md`; файл — read-only сид + байт-эталон. Ручная правка сохраняет маркер `canon_delivered_version`.
6. **Прод-деплой/доказательство (гейт T-1641):** после `restart` `ConfigCache.init` либо находит слепок (авто-миграция), либо выполняет одноразовую форс-доставку; @DevOps читает `canon_version==2` и `canon_drift==false` (совпадение `html` с `DEFAULT_INFO_TEXT`).

## 3. Альтернативы

| Вариант | Вердикт |
|---|---|
| Оставить байт-в-байт сравнение | Отклонён: не ловит whitespace/CRLF-дрейф (прод-кейс) |
| Хэш-нормализация без явного реестра | Отклонён: нельзя восстановить `prev_html`/откатиться; реестр строк нужен для бэкапа и деплой-сверки |
| Авто-reset любого неизвестного текста | Отклонён: молча удаляет ручные правки владельца (прямое нарушение требования) |
| Одноразовая форс-доставка канона с маркером `canon_delivered_version` (ревью-итер. 1) | **Принят:** гарантирует доставку текущего прод-текста (владелец разрешил его перезаписать), но не затирает правки, сделанные ПОСЛЕ доставки (маркер версии) |
| Отдельный PG-ключ под бэкап | Отклонён: лишний ключ вне каталога; `prev_html` в значении проще и атомарен |
| Бампать `canon_version` при ручной правке | Отклонён: версия описывает код-канон; ручной текст = drift, не новая версия |
| Исключить `info_text.md` из репо | Отклонён: файл — сид `_seed_info_key` и байт-эталон теста; write-path убран, роль read-only |
| Локальная запись при PG down | Отклонён: расхождение локаль/прод; вместо этого явная ошибка (503/фраза) |

## 4. Последствия

- (+) Канон доезжает в прод; ручные правки не теряются молча; pull не блокируется; идемпотентность и аудит.
- (−) Новый внутренний контракт `canon_version` и обязанность сопровождать правки канона (бамп версии + слепок + байт-тест).
- (−) При PG down `/edit_info` возвращает ошибку (раньше писал файл) — осознанный выбор в пользу консистентности.
- Инварианты: DML-only (DDL нет), каталог-Δ=0, `DEFAULT_INFO_TEXT` байты не меняются, порядок роутеров `bot.py` не тронут.
