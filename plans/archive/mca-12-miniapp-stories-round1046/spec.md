## 1. Витрина «Истории чата» (MCA12-R1; T-5156–T-5160)

Read-side запросы (пагинация/фильтры/агрегаты) — **AMEND репозитория фасада mca-05** (read-only методы поверх v21-таблиц), не второй модель: расширение существующего фасада ≠ новый механизм (CA-12-1).

Read-проекция `mca_events` — не второй канал телеметрии (CA-12-2): прецедент — индикатор инцидентов mca-17a (`oversight.py`, `mca_incidents.compact_indicator`).

**D3. Вставка блока в F11-композицию «Статус»: одна вставка, порядок сохранён, нового маршрута нет.** Позиция — после зоны мониторинга интеллекта (F5 «Мониторинг Интеллекта» ~index.html:5087, F7 «здоровье памяти» ~:5153, «Бюджеты интеллекта» ~:5248) и **до** нижних логов («Доступность ключей» ~:5289, «Сводка логов» — вне `.status-grid`). Блок живёт в существующем `#/` (Статус, F11 ADR-1025-23); верхнеуровневый маршрут `#/stories` не создаётся (GEN-R12). Существующие виджеты и их относительный порядок не меняются, кроме единственной вставки (`:776`). Liquid Glass сохраняется: существующие `data-glass`/палитра #090D17/#151B2A, бирюзовые/фиолетовые акценты, медленный атмосферный градиент; блок — карточка витрины, не админ-таблица (`:774`); адаптив по существующей сетке F11 (12/6/1), не прятать за меню.

**D4. Лента: cursor/dedup/bounded, prepend без сброса scroll, reconnect-сверка (A54).** Обновления — инкрементальный polling существующим механизмом миниаппа (SSE/WS в инфраструктуре нет; прецедент доставки инцидентов mca-17a, §27.6 `:1434` — «инкрементальный polling, при восстановлении — пропущенные по cursor и сверка»). Контракт: курсор = (event_id, ts) монотонный; dedup по `event_id`; новые элементы prepend **без** сброса scroll и **без** перерисовки открытой карточки (`:786`, A26); пауза/продолжение — локальная остановка опроса с честной пометкой «пауза»; reconnect — сверка latest + догрузка gap'а; stale-данные не выглядят healthy (видимый индикатор «данные от…»); bounded history — ретенция mca-13 (90d terminal), вышедшее за ретенцию — честное «история ограничена», не нули. Recheck-события старых историй показывают **обе даты** (дата события / дата обнаружения — поля события mca-05, A11).

**D5. Счётчики и прогресс: SQL-агрегаты существующих полей + статусы существующих процессов.** «Число историй» — count `mca_stories` чата; «новые/дополненные» — из событий ленты за фиксированное окно UI (константа, не настройка); «ожидающие проверки» — state/verification-агрегат; «видимый прогресс архивной обработки и последнее состояние» — read-рендер статусов существующих процессов `episodes.build`/`episodes.backfill` (реестр mca-17a + durable `task_jobs` mca-01). Пустые состояния — отдельные видимые («нет историй», «обработка не запущена», «данные недоступны»), нули только после успешного расчёта; демонстрационные данные — только с явной меткой и отдельно от production (`:786`, §19 `:1474`).

**SC-R1a (→A26):** блок виден на «Статусе» desktop+mobile в заданной позиции (после мониторинга интеллекта, до логов); существующие виджеты не сдвинуты/не сломаны; верхнеуровневого маршрута «Истории» нет.
**SC-R1b (→A26/A54):** новое событие не сбрасывает scroll и не дёргает открытую карточку; reconnect восстанавливает ленту без дублей/потерь, stale ≠ healthy; пауза/продолжение и reduced-motion работают на обоих вьюпортах.

## 2. Таблица и карточка в «Памяти» (MCA12-R2; T-5161–T-5166)

**D6. Таблица — вкладка/подраздел в существующей «Памяти» (F6-хаб `#/memory`), серверная пагинация.** Новый подраздел в существующем меню-хабе «Память» (прецедент lessons-таблицы mca-16 `data-lessons` index.html:1984, `GET /api/memory/lessons` memory_agi.py:1351); **не** новый top-level маршрут. Пагинация — **keyset** по `(chat_id, updated_at, story_id)` (индекс `idx_mca_stories_chat_updated` существует, database.py:775); фильтры — маппинг на существующие колонки v21 без денормализации: название (`title`), участники (`participants_json` — фильтр в пределах чата, JSON-scan по bounded-странице чата), период событий (`event_start_ts/event_end_ts`), дата обнаружения (`discovered_at`), число эпизодов (`mca_story_episode_links` count), состояние (`state`), источники/проверка (`verification`), последняя обработка (`updated_at`); поиск по названию и содержанию — LIKE `title/summary/claims_json` в пределах чата (FTS-таблицы историй нет — полнотекстовый движок не строится). Параметры пагинации/фильтров валидируются **на сервере** (client-side trust запрещён — Scanner T-5173). Если прод-explain покажет деградацию на фильтрах участников/периода — **эскалация санкции индекса через реестр mca-14** (§18 `:866`), тихие миграции запрещены (CA-12-8).

**D7. Карточка — один UI-объект, два входа (витрина и таблица); состав по `:794`.** Краткое содержание, хронология эпизодов (`mca_story_episode_links` + `mca_episodes`), участники с устойчивыми ID (mca-03 identity), утверждения и источники (`claims_json` + SourceRef-форма mca-04a / `record_story_provenance` mca-05 `:2177`), исходный контекст, связанные убеждения/парадигмы (существующие связи mca-06 — read), неизвестное — честно, противоречия (события `contradiction_found`), версии и ручные изменения (`mca_story_versions` + `override_*`-колонки, `created_by`). Открытие из ленты — подробная карточка **на месте** (без навигации, `:784`); переход «открыть таблицу» ведёт на вкладку историй существующей «Памяти», источник перехода сохраняет контекст возврата.

**D8. Действия — только существующие операции фасада mca-05, CAS-защита, семантика stale.** Исправить → `update_story_manual` (CAS `expected_version`, `:770`); merge → `merge_stories` (redirect, `:936`); split → `split_story` (redirect, `:971`); исключить из retrieval → `set_story_excluded(true)` (`:874`); вернуть → `set_story_excluded(false)`; пересобрать → существующий вход `assemble_stories` (`:2041`, после Q2-фикса D9); открыть оригинал → Telegram-ссылка **только** при достаточных валидных метаданных (chat_id/tg_message_id), иначе архивный просмотр; отсутствующий оригинал — явное состояние, не заглушка-«ссылка» (`:796`). Stale update (CAS-конфликт) → HTTP 409 + UI показывает актуальную версию и **не затирает** чужие правки (A13 `:894`). Ручные overrides пайплайн не затирает — гарантировано существующей логикой (override-поля вне сравнения пересборки, `mca_episodes.py:2140–2157`); переживание следующего сна/пересборки — контрактный тест (A13). Каждое действие — существующее событие mca-13/mca-05 + новая версия (`:796–798`); новых reason_code нет (D15/§7.4).

**SC-R2a (→A25):** таблица/карточка другого чата недоступны; неавторизованная мутация отклонена; просмотр/raw-источники/мутации под текущими ролями и chat scope; публичная витрина получает разрешённые краткие данные, не raw-логи.

## 4. Права, приватность, устойчивость (сквозное; R17/CA-12-7)

**D13. RBAC/chat scope/авторизация миниаппа на каждом read/mutation.** Все новые routes — под существующей моделью доступа (web access/deps, прецедент RBAC `/api/random/test` routes.py:2002 и memory-API): read ленты/таблицы/карточки — авторизованный пользователь с доступом к чату; данные чужого чата — отказ (A25); мутации — права редактирования памяти + server-side проверка + CAS. **Публичная витрина — разрешённые краткие данные** (`:798`): агрегаты, названия, статусы, счётчики; raw-сообщения, сырые логи, содержимое источников — только в карточках под действующими правами, никогда в публичных агрегатах.

**D14. R17-миниапп: маскирование и XSS-профиль.** initData/Authorization/cookies/секретные URL-параметры не всплывают в UI-логах и экспорте (§17.3 `:844`); secrets не в localStorage/bundle (прецедент §2 `:596`). Поиск/фильтры — параметризованные запросы, не конкатенация. Полный профиль — `threat-failure-analysis.md` (TH-1…TH-8).

**D15. Наблюдаемость новых отказов — без новых reason_code.** Отказы мутаций выражаются HTTP-семантикой (403/404/409 CAS/409 disabled) и payload-полями честных состояний; лента/счётчики читают существующие события.
