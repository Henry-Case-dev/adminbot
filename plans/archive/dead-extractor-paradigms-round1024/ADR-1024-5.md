# ADR-1024-5 — Живой дебаг «Глубокого сна»: развязка traits от paradigms + Empty State

- **Статус:** **Accepted** (Step 2 @Architect, часть 1/2 раунда 10.24, 19.09.2026). **RE-OPEN фиксов 10.18/10.20.**
- **Фича:** F8 `dead-extractor-paradigms-round1024`
- **Тип:** backend (пайплайн «Глубокого сна») + API-контракт под UI
- **Связано:** ADR-1018-2/-7, 10.20 (RE-OPEN), ADR-1024-1 (трассировка), `round1024-architecture.md` §4
- **Задачи:** T-2244…T-2253

## Context

Колонки «Парадигмы» и «Эволюция характера» пусты на виджете «Мониторинг Интеллекта». Живой анализ кода выявил **конкретную структурную причину** (не «косметика»):

1. **Критично — traits вызываются только после успешной записи парадигм.** В `_run_deep_once` (`services/dream_worker.py:1479-1641`) persona-блок стоит в самом конце (`:1612-1638`), а выше есть **ранние return**, которые его пропускают: `disabled` (`:1489`), `daily_limit` (`:1497`), `cooldown` (`:1507`), `no_memory` (`:1509`), `error` (`:1502/1515/1526`), `no_context` (`:1517`), `no_anchors` (`:1533`, требуется ≥2 исторических якоря — самый частый путь), `budget` (`:1543`), `unchanged` (`:1573`), `error` (`:1547/1564/1570`). Итог: если парадигмы «unchanged»/`no_anchors`, **traits не запускаются вообще**.
2. **traits жёстко требуют self-факты** `origin='bot_self_reply'` (`_run_persona_traits_once:1811-1832`); без них → `status='empty'`, `reason=no_self_facts`. Владелец: не галлюцинировать, но показать **Empty State** с пояснением (UPD3 п.4).
3. **Мастер-гейты по умолчанию OFF**: `DREAM_ENABLED=False` (`config/settings.py:1261`), `DEEP_SLEEP_ENABLED=False` (`:1308`); `PERSONA_ENABLED=True` (`:968`). Если на проде они выключены — весь контур мёртв (это проверяет live-диагностика T-2245).
4. **Ошибки записи глотаются** в мягком виде: `_write_paradigm` (`:1912-1955`) при embed-сбое — WARNING; в цикле `:1588-1595` ошибки `_write_paradigm` → WARNING + `fact_id=None`; `parse_bridge_answer` при невалидном JSON даёт `ValueError` → retry → `error`. Причины не видны сквозным образом.
5. **API** отдаёт парадигмы (`web/api/memory_agi.py:455-497`) и traits (`web/api/routes.py:1610-1638`), но **нет явной причины пустоты** (`no_self_facts`/`persona_disabled`/`master_off`), поэтому UI не может показать грамотный Empty State.

## Decision

### D1. Развязать traits от paradigms (корневой фикс)
- Извлечь persona-блок в отдельный шаг, исполняемый **всегда**, когда Сон вообще допустим (после проверок `disabled`/`daily_limit`/`cooldown`), независимо от исхода paradigm-ветки.
- Конкретно: после прохождения гейтов `manual/disabled/daily_limit/cooldown` (и `persona_enabled`) вызвать `_run_persona_traits_once` **до** любых ранних return ветки парадигм (или в `finally`-подобном шаге); ранние return парадигм сохраняют свой статус, но результат дополняется `traits`.
- `_deep_result(...)` уже несёт `traits` — контракт формы не меняется.
- Kill-switch `DEEP_SLEEP_EXTRACT_FIX_ENABLED` (env-only, default ON); OFF → прежняя последовательность (byte-identical).

### D2. Источники traits — без галлюцинаций
- Приоритет self-фактов `origin='bot_self_reply'` **сохраняется**; при их отсутствии traits **не** генерируются (не подменяем личность общим лором).
- Вместо «пустой ленты» API отдаёт **причину**, UI — Empty State (UPD3 п.4).

### D3. Явный контракт статусов (для API/UI)
- `_run_persona_traits_once` и paradigm-ветка возвращают/пишут статус+причину; `persona_state.last_trait_status` (`bot_persona.record_trait_status`) используется как источник.
- API дополняется аддитивно (R16):
  - `GET /api/memory/deep-sleep` → `paradigms_status`, `paradigms_reason`, `deep_enabled`, `master_enabled`;
  - `GET /api/persona` (или cognition) → `traits_status`, `traits_reason`, `self_facts_count` (число self-фактов за окно), `persona_enabled`.
- Причины: `ok | empty | no_self_facts | persona_disabled | master_off | budget_skip | cooldown | no_anchors | no_context | error | duplicate`.
- UI (Часть 2, web-очередь) рендерит пояснительный текст/тултип: как работает эволюция (self-факты → рефлексия → черты), почему сейчас пусто.

### D4. Гарантия извлечения фактов/парадигм о пользователях
- Парадигмы (о людях/связях) и обычный graph-extract (факты о пользователях) — отдельные контуры: проверить/зафиксировать, что `_write_paradigm` пишет `origin='derived_belief'`, `belief_meta.type='paradigm'`, и что graph-extract (F1) работает.
- Устранить потерю валидных элементов в `parse_bridge_answer` (если часть элементов теряется — не отбрасывать всю пачку) и убедиться, что `_write_paradigm` не глотает ошибки (лог с причиной, F2).

### D5. Сквозная трассировка этапов (совместно с F2)
- На каждом этапе/раннем return — `trace_step(component="dream", step=..., status=..., reason=..., chat_id=...)`: гейты, `candidates` (beliefs/recent/anchors), `historical>=min`, budget, `parse`, `dedup`, `write`, `traits`.
- Без сырых текстов сообщений (R17).

### D6. Live-диагностика перед мутациями
- T-2245 (@DevOps, read-only): проверить `DREAM_ENABLED`/`DEEP_SLEEP_ENABLED`/`persona_enabled`; наличие `origin='bot_self_reply'` в `graph_facts` за окно `_PERSONA_SELF_LOOKBACK_DAYS=30`; непустоту beliefs; прогнать `run_once`/ручной триггер и снять `stats` (paradigms/traits/skipped/ran). **Сначала бэкап** — затем мутации (данные производные).

## Consequences

**Positive**
- Root cause устранён: traits перестают зависеть от результата парадигм.
- Пользователь/владелец видит, **почему** пусто (Empty State), а не «мёртвый экстрактор».
- Причины сбоя каждого этапа видны в логах (F2).
- Δ DDL = 0, Δ каталога = 0.

**Negative**
- traits могут запускаться чаще (при каждом допустимом прогоне Сна) → расход фона; ограничен `_deep_budget_ok` и суточным капом.
- Если мастер-гейты выключены на проде — данных не будет до включения; это теперь **явно** видно (`master_off`), но включение — решение владельца.
- Расширение API-полей требует аккуратного обновления фронта (Часть 2).

## Alternatives

- **A1. Просто «включить флаги» на проде** — **недостаточно**: даже с включёнными флагами traits пропускаются на `no_anchors`/`unchanged` (структурный баг).
- **A2. Ослабить источник traits (убрать требование self-фактов)** — **отклонено владельцем**: не галлюцинировать; вместо этого Empty State.
- **A3. Генерировать self-факты искусственно** — **отклонено**: противоречит «честному карантину self» (ADR-1014-2).
- **A4. Просто заглушка «нет данных»** — **отклонено владельцем**: нужен пояснительный Empty State.
- **A5. Новый DDL-статус-журнал пайплайна** — **отклонено**: Δ DDL; достаточно `persona_state` + лог-события.
