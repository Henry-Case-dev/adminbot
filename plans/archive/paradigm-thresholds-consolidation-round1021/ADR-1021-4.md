# ADR-1021-4 — Аудит порогов Парадигм/Deep Sleep и Memory Consolidation

- **Статус:** **Accepted** (UPD владельца после Human Gate, раунд 10.21)
- **Дата:** 18.09.2026, раунд 10.21
- **Контекст:** F4 `paradigm-thresholds-consolidation-round1021`, T-1971…T-1979
- **Связано:** ADR-1021-5 (CLI/санитария), ADR-1018-2 (пороги сна), ADR-1013-3

## 1. Контекст

Deep Sleep (10.13) и парадигмы реализованы (`dream_worker._run_deep_once`, `_write_paradigm`,
`belief_meta.type='paradigm'`), но мета-слой пуст. Дефолты `DREAM_ENABLED` и `DEEP_SLEEP_ENABLED` — **False**,
`BELIEF_DECAY_ENABLED` — False. Достоверная причина не установлена; ТЗ предлагает «снизить порог», но это
может лечить симптом.

## 2. Решение

1. **Сначала READ-ONLY аудит** (T-1972) — доказать точку обрыва по `memory_dream_log`, `count_paradigms`,
   фактическим значениям флагов. **Никаких правок до отчёта.**
2. **Memory Consolidation** — отдельная идемпотентная функция `consolidate(apply=True)` (bounded-выборка,
   дедуп через `_paradigm_dedup_keys`), вызываемая **только CLI** (F5), не из тика; авто-крона нет.
   Дефолт — боевой прогон; `--dry-run` опционален. Страховка — авто-бэкап + JSONL-архив.
3. **Пороги** меняются по результату аудита; **принудительное снижение разрешено** (Д11=да, значения — из
   отчёта аудита), через идемпотентную PG-миграцию дефолтов (`migrate_dream_thresholds` — прецедент).

## 3. Обоснование (research)

- Sleep-time compute: фоновая консолидация эффективна и снижает test-time compute, но **ошибка фонового
  размышления становится «истиной» в памяти** → обязательны обратимость и проверяемость
  (авто-бэкап + JSONL-архив; опциональный dry-run) (https://arxiv.org/pdf/2504.13171,
  https://www.letta.com/blog/sleep-time-compute/).
- Auto-Dreamer: консолидацию правильно выносить в отдельный офлайн-процесс с provenance и «region rewrite»,
  а не смешивать с онлайн-записью (https://arxiv.org/html/2605.20616).

## 4. Альтернативы

| Альтернатива | Вердикт |
|---|---|
| Сразу снизить пороги (как просит ТЗ) | Может не дать эффекта, если обрыв — на флаге; риск лишнего расхода. Отклонено без аудита. |
| Автоматический крон консолидации | Деструктивно + удорожает; отклонено (CLI-only, как retention). |
| Снять капы TOP_K/MAX_PARADIGMS | Ломает модель стоимости RAG «по всей базе». Отклонено. |
| Новая таблица `paradigms` | Ноль DDL у нас (маркер в `belief_meta`); не нужно. Отклонено. |

## 5. Последствия

- **Δ каталога = 0:** флаг консолидации не вводится; при ветке C меняется только значение существующего
  `limits.deep_sleep_max_paradigms_per_run` (Δ записи = 0).
- Пороги `DREAM_*`/`DEEP_SLEEP_*` мигрируются идемпотентно и обратимо; значения принудительного снижения — из отчёта аудита.
- Наблюдаемость в `memory_health` — аддитивные метрики.

## 6. Решения Human Gate (UPD)

- **Д10 → включение `DREAM_ENABLED`/`DEEP_SLEEP_ENABLED`** — если аудит покажет обрыв на флагах (ветка A).
- **Д11 → да:** принудительное снижение порогов разрешено; точные значения — из отчёта аудита (ветка B).
- **Д12 → флаг `flags.memory_consolidation_enabled` не вводится** (консолидация CLI-only), Δ каталога = 0.
