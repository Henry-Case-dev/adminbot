## Приёмочные инварианты MCA-04a (нарушение = НЕ принято)

1. **SourceRef типизирован** (`store`/`entity_type`/`entity_id`/`chat_id`/`revision`; для оригинала — `tg_message_id`/`dataset_id`); SQLite fact ID, PG row ID и Telegram message ID **не** взаимозаменяемы. **MCA04-R1; T-3821, T-3822.**
2. **EvidenceLink** несёт объект+версию, источник+версию, тип (`derived_from`/`supports`/`contradicts`/`mentions`/`supersedes`), способ, статус проверки, время, версию экстрактора, краткое проверяемое основание. **MCA04-R2; T-3822.**
3. **Статус происхождения** `original/reconstructed_support/tentative/unknown`; конфликтность, актуальность, покрытие — **отдельные поля**; одно утверждение может иметь сохранённый источник и одновременно устареть. **MCA04-R3; T-3827.**
4. **Собственные ответы бота — не независимое подтверждение** фактов о людях; личные предпочтения персонажа маркируются отдельно от фактов. **MCA04-R3; T-3825, T-3826.**
5. **Восстановление:** прямое → точный/смысловой поиск; контекст/reply; проверяются автор/объект/время/отрицание/цитата/шутка/пересказ/актуальность; **вектор — кандидат, не доказательство**; покрытие по **каждому** утверждению; ambiguous → `tentative`; восстановленное подтверждение **не** переименовывается в `original`; неподтверждённое **не** удаляется; ложный `original` не создаётся. **MCA04-R4; T-3828, T-3829.**
6. **Единая семантика личного факта:** разделены `speaker/author`, `subject`, упомянутые и источник; субъект — устойчивый ID в области чата; импорт без TG ID → stable source ID + **unresolved** (без выдуманного Telegram ID); одноимённые не объединяются; упоминание имени — не доказательство. **MCA04-R7; T-3825.**
7. **Self-report допустим** («по собственным словам», одно свидетельство); **третье лицо — атрибутированное утверждение** со статусом, а не безусловная биография. **MCA04-R7; T-3825, T-3826.**
