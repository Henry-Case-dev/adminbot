## 3. Методология доказательств (запрет «grep нашёл»)

Приёмка — только по фактическому рендеру. **Минимальный набор зондов на каждый дефект:**

| Область | Зонд |
|---|---|
| Liquid Glass | `getComputedStyle(el).backdropFilter/backgroundColor` на `.modal-card`, `.card`, `.module-card`, `.prov-block`; проверка `@supports not (backdrop-filter)` фолбэка |
| CSS Grid | `getComputedStyle(container).gridTemplateColumns` → число треков; viewport 1440/1000/999/400 |
| Data binding | `document.querySelector('input[type=password]').value` → маска `••••••••••••` vs `''`; `type` поля |
| Градиент | `getComputedStyle(document.documentElement).getPropertyValue('--grad-speed'/'--grad-d')`; `animationDuration`; reduced-motion/contrast |
| Геометрия | `getBoundingClientRect` на карточках/панелях → пересечения, отрицательные margin, съезды |
| Sticky | зазор `sticky.bottom` vs `scrollport.bottom` (закрыть M-1: 88px) |
| Консоль | `page.on('console')`/`page.on('pageerror')`/`requestfailed` → список ошибок |

Дополнительно: **скриншоты** ключевых экранов. Grep-строки в исходниках как доказательство **запрещены**.
Замеры проводить на **живом локальном сервере фронтенда** со стабами `/api/*`, без реальных секретов.

## 4. Фокус инспекции (по ТЗ)

1. Геометрия/отступы: перекрытия, кривые margin/padding, съезжающие блоки.
2. Liquid Glass: настоящий `backdrop-filter: blur(...)` + корректный `rgba`, фолбэки.
3. CSS Grid: карточки растягиваются по сетке (≥2 трека desktop), не ломая мобильный вид.
4. Data binding: маски `••••••••` для существующих секретов vs пустые поля — во всех модулях.
5. Градиент: ускоренная анимация + оранжевый спектр; `prefers-reduced-motion`/`prefers-contrast` целы.
6. Консоль: JS-ошибки, React-варнинги, упавшие запросы.

## 5. Защита от регресса 5 дефектов UPD3

Авто-проверки (новый `tests/js/round1021_ui_audit_test.js`, реальный Chromium через Playwright):

1. `.modal-card/.card` → `backdropFilter` содержит `blur(16px)`, фон `rgba(20, 25, 30, 0.5)`.
2. `.prov-grid/.module-list/.hub-grid` при 1440px → **≥2 трека**; при ≤479px → 1fr.
3. Поле секрета с настроенным ключом → `value` = маска; ввод реального ключа не сохраняет маску.
4. `--grad-speed` ∈ [5,8]s, `--grad-d` оранжевый (`#FF8A3D`-спектр); reduced-motion → `animation: none`.
5. `<sticky-save>` присутствует в каждой ветке (config/modules/access); зазор sticky ↔ низ ≤ 2px (без 88px).

Плюс инвариант меню: 25 вкладок / 6 NAV_ITEMS / 12 модулей (существующие JS-тесты).

## 6. `UI_AUDIT_REPORT.md` — контракт

Путь: **корень репозитория `UI_AUDIT_REPORT.md`** (артефакт по ТЗ). Структура:
1. Окружение и tooling (какой инструмент сработал: Puppeteer MCP или Playwright + версия Chromium; viewport-матрица).
2. Проверенные экраны (таблица: раздел → статус → дефекты).
3. Дефекты: `ID | severity | точный CSS-селектор | сырой вывод зонда | фикс | статус`.
4. Консоль: ошибки/варнинги/упавшие запросы (без секретов).
5. Скриншоты (маскированные).
6. Закрытые ранее дефекты UPD3 (регресс-чек), включая **M-1 sticky 88px**, и открытые Low/Medium.
7. Ограничения (WebView не проверялся).
8. **Честный статус инструментов:** если Puppeteer и Playwright оба упали — явная запись «визуальный аудит
   не выполнен» + сырые ошибки. Отчёт без реального рендера считается **невалидным** (см. §3, R2).
