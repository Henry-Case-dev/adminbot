# ADR-1025-4 — Уведомления и SaveBar: один итог на операцию, safe area, приоритеты ошибок

- **Статус:** **Accepted** (Step 2 @Architect, 20.09.2026)
- **Фича:** F0 `f0-config-bugfixes-round1025` — F0.4
- **Тип:** UI (web: `app.js`/`index.html`/`app.css`)
- **Связано:** `spec.md` §4; `tasks.md` T-2434…T-2438; F9 `secrets-and-save-states-round1025` (визуальный SaveBar); ADR-1025-2 (saveState)
- **Задачи:** T-2434…T-2438

## Контекст

1. `toast(text, kind)` пушит в `this.toasts` без дедупа/лимита; `id = Date.now()+Math.random()` — коллизии/дубли (`web/app.js:2125-2132`).
2. `.toast-wrap` фиксирован `top:1rem; right:1rem; z-index:60` без safe-area и лимита (`web/static/app.css:562-571`); Telegram safe-area уже применяется в layout (`web/static/app.css:686-689`), но не к тостам.
3. Три противоречивых тоста на одно действие — следствие F0.1 (успех + 409 + «Не сохранено»).
4. Длинные ошибки выводятся целиком в тост (риск stack trace поверх мобильной страницы).
5. `.sticky-save` уже sticky+safe-area (`web/static/app.css:890-906`), но состояние (`stickySaving`/`dirtyCount`/`stickyFailed`) — набор независимых флагов, не единый `saveState`.
6. `.scope-panel` (`app.css:331-332`, z-index 50) — селектор области, который нельзя перекрывать.

## Решение

### D1. Одно итоговое уведомление на операцию
Каждой операции присваивается `operationId`; `notify(operationId, result)` идемпотентен (повторный вызов с тем же id игнорируется). Один тост на операцию:
- `ok` — всё сохранено;
- `warn` — частичный успех: «Сохранено N из M; не сохранено: …»;
- `err` — ничего не сохранено.
Запрещён одновременный «success+error» без частичного результата. При пакетном сохранении — **не** тост на каждое поле.

### D2. Уровни ошибок
- Ошибки отдельных полей — **возле полей** (per-field map, подсветка как `sticky-save__failed`, `app.js:7769-7770`).
- Глобальный тост — только итог операции.
- Длинная ошибка (> порога) → действие **«Подробнее»** (раскрытие в области/модалке), **без** полного stack trace огромным тостом поверх мобильной страницы.

### D3. Тосты: safe area, очередь, приоритет
- `.toast-wrap`: `top/right` через `max(env(safe-area-inset-*), var(--tg-content-safe-area-inset-*), var(--tg-safe-area-inset-*))` (образец `app.css:686-689`).
- Не перекрывать header, навигацию и `.scope-panel`.
- Очередь: одновременно ≤ 3; приоритет `err > warn > ok`; дедуп одинаковых (текст+kind) в окне; стабильный уникальный `id`.
- Mobile-проверка 320/390/768.

### D4. SaveBar
- Единое состояние из ADR-1025-2 (`saveState`), а не набор флагов.
- Sticky + safe-area (уже есть), учёт клавиатуры (visualViewport), доступность последнего поля.
- **Разделение с F9:** серверная логика состояний — F0; визуальный слой — здесь и в F9; блоки не дублировать. F9 читает результат F0 и не переписывает.

### D5. Feature flag
Продуктовый флаг не вводится. Наблюдение — визуальная приёмка на mobile/TMA (T-2438). Откат — `git revert` (точка отката T-2410).

## Последствия

**Positive**
- Исчезает «три сообщения на одно действие»; одно понятное состояние SaveBar.
- Мобильный UI: тосты не перекрывают навигацию/селектор области; длинные ошибки не «заливают» экран.
- Полевые ошибки рядом с полями — пользователь понимает, что именно не сохранилось.

**Negative**
- Замена `toast()` на `notify()` — точечная правка многих вызовов; текущие вызовы могут остаться как внутренний примитив под капотом `notify` (сохраняется обратная совместимость).

## Альтернативы

- **A1. Оставить тост на каждое поле** — **отклонено**: §5 ТЗ прямо запрещает.
- **A2. Модальный диалог ошибки** — **отклонено**: тяжелее для TMA и перекрывает контент.
- **A3. Тост со stack trace** — **отклонено**: §5 ТЗ; риск раскрытия деталей и поломки верстки.
