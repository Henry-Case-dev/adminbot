# ADR-1013-3 — Политика правки промпт-канонов раунда 10.13 (PREV vs PROMPT_MIGRATIONS)

> Статус: **ACCEPTED**. Дата: 13.09.2026. Автор: @Architect (Step 2).
> Касается: F1 (`dream_prompts`), F3 (`dream_prompts`, deep-sleep canon), F8
> (`lore_prompts`, `dossier_prompts`). База: HEAD `ce25dc7`.

## 1. Контекст

Tasks.md F1/F2/F3/F8 требует «правки канона промптов только через `PREV`-слепок +
`services/prompt_migrations.py` (`PROMPT_MIGRATIONS`) + байт-тесты». Фактическая
архитектура (сверено с кодом):

| Канон | Файл | Модульная константа | PG-ключ в `param_catalog._PROMPTS`? |
|---|---|---|---|
| Дистилляция «сна» | `services/dream_prompts.py` | `DREAM_DISTILL_PROMPT` | **нет** (Q10/NFR-6 раунда 9) |
| Авто-лор merge/init | `services/lore_prompts.py` | `LORE_MERGE_SYSTEM_PROMPT`/`LORE_INIT_SYSTEM_PROMPT` | **нет** |
| Промпт извлечения фактов | `services/summary_prompts.py` | `EXTRACT_PROMPT` | да, но `prompt_migrations` **явно исключает** `prompts.extract_system_prompt` |
| Прочие user-facing | ... | ... | да (`_PROMPTS`, 10 шт.) |

`services/prompt_migrations.py` мигрирует **только PG-сид-значения**:
`migrate_prompt_canons(cache)` читает `cache.get("prompts.*")` и заменяет
значение, если оно равно одному из `PREV_*`/`LEGACY`. Для не-PG константы
записи в PG нет — мигрировать нечего.

## 2. Решение

1. **Модульные константы (`dream_prompts`, `lore_prompts`, новый
   `dossier_prompts`) НЕ добавляются в PG-каталог.** Действует прецедент Q10/NFR-6
   раунда 9 («промпты дистилляции/ностальгии — константы модулей, не PG/REGISTRY»).
   Каталог не растёт; owner не редактирует эти каноны из TMA.
2. **Дисциплина правки модульного канона = PREV-слепок + байт-тесты:**
   - сохранить байт-в-байт прежний текст как `PREV_<NAME>` в том же модуле;
   - новый текст — в `<NAME>`;
   - добавить эталонную копию нового текста в байт-тест
     (`_<NAME>_REFERENCE`) + тест `PREV_<NAME> == старый текст`;
   - обновить `plans/docs/canon/backlog.md`/`architecture.md` (эталон = код = тесты).
3. **`PROMPT_MIGRATIONS` не трогается** для этих канонов (записи не создаются).
   Ступень добавляется только если канон **является PG-сидом** (`prompts.*`).
4. Если в будущем owner захочет редактировать канон сна/лора/досье из TMA —
   это отдельное решение: санкционированный Δ каталога (`prompts.*` + Settings +
   `PROMPT_MIGRATIONS`-ступень). В рамках 10.13 — **не делаем**.

## 3. Обоснование

- Минимизация каталог-Δ: 10.13 уже даёт +22 записи (лимиты/флаги/провайдеры);
  добавление 3 промптов дало бы ещё +3 записи и +3 Settings-поля без запроса ТЗ.
- Сохранение прецедента: dream/nostalgia/lore уже модульные; смена прецедента
  требует явного решения владельца (как OD-решения раунда 10.5).
- Байт-тесты уже существуют для всех канонов («эталон = код = тесты»,
  R11-дисциплина §11 ARCHITECTURE) — механизм PREV отработан.

## 4. Последствия

- **Отклонение от формулировки tasks.md** (там упомянут `PROMPT_MIGRATIONS`
  для F1/F8): исполняется PREV+байт-тесты, `PROMPT_MIGRATIONS` — no-op.
  Зафиксировано в spec.md каждой фичи, в tasks.md — не блокер.
- `services/prompt_migrations.py` **не в диффе** раунда 10.13 (кроме случаев,
  если Builder решит вынести канон в PG — тогда нужен Human Gate).
- Риск: owner не сможет подправить канон сна/лора из UI. Приемлемо (модульные
  каноны меняются только через PR — существующее поведение).

## 5. Альтернативы

- **A1. Добавить `prompts.dream_distill_system_prompt`/`prompts.lore_*_system_prompt`/
  `prompts.dossier_system_prompt` в каталог** (+3 REGISTRY, +3 Settings, +1-3
  ступени `PROMPT_MIGRATIONS`, сид из константы). Плюс: UI-редактируемость,
  полная унификация. Минус: рост каталога, смена прецедента Q10 без запроса,
  риск рассинхрона «UI vs константа-дефолт». **Отклонено для 10.13**, кандидат
  в отдельный техдолг при запросе владельца.
- **A2. Ничего не менять в промптах** (только код-рендер). Отклонено: ТЗ §1
  прямо требует группировку по времени/динамику в дистилляции, §2 — иронический
  фильтр в промпт воркера.
