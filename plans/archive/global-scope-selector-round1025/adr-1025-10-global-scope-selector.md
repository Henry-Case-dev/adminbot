## Контекст
Постоянный селектор области §5 вводит три вопросы, которые нельзя решить «очевидным» способом без риска потери данных:
1. Что означает действие «Вернуть глобальное значение» — **сброс к заводскому дефолту** или **снятие per-chat переопределения**?
2. Как переключать область, если у пользователя есть **несохранённые правки** (в т.ч. черновики блоков `llm_providers`, не отражающиеся в `configItems`)?
3. Что делать с **запоздавшими ответами** `loadConfig` при быстрой смене области, и нужно ли отображать состояние «Ожидает применения» (§43)?

Конфигурация — read-through: `GET /api/config` отдаёт **эффективное** значение (`per_chat override → глобал → дефолт`).

## Решение

### D1. «Вернуть глобальное значение» = DELETE override, **НЕ** factory-reset
Действие снимает **только** per-chat переопределение (`overrides.pop(key)` + merge `meta`), возвращая наследование глобального значения; параметр **не** сбрасывается к заводскому дефолту. Эндпоинт — существующий `DELETE /api/config/chat/{key}` (`web/api/routes.py`); `404`, если override нет. Клиент — `resetChatOverride` (`web/app.js:3333`), `encodeURIComponent(item.key)`; подпись «↪ Глобальное» + `aria-label` (мобильный overflow-фикс).
- **Почему не factory-reset:** сброс к дефолту разрушил бы намеренную глобальную конфигурацию и смешал бы понятия «наследовать глобально» и «вернуть заводское» — прямое нарушение §5.

### D2. RBAC снятия override — scope по чату (без эскалации)
Серверный гейт `web/api/routes.py:852-904` использует `access_for(user.id, chat_id)` (`services/roles.py:180-198`) → грант **скоупится по чату**: local-admin чата A не может сбросить override чата B (403). Для групп — `is_global_admin or is_local_admin`; для DM — только `is_dm_owner`. JS-условие показа кнопки приведено к **паритету** `!(isGlobalAdmin || isDmCtx() || isLocalAdminCtx())` (`web/index.html`, 8 мест). R17: лог пишет только `chat=,key=,by=` (без значений); ответ — только своему пользователю.

### D3. Guard несохранённых правок — «полный» (включая черновики блоков)
`hasUnsavedEdits()` (`web/app.js:2481-2516`) обязан видеть **все** источники незакоммиченных правок, а не только `dirtyItems`/`saving`. Покрыто: `stickyDirtyCount`/`dirtyItems`/`dirtyKeyItems`/`saving`; **`blockDrafts`** (вкладка «LLM-провайдеры» — `blockFieldValue` читает `blockDrafts[f.key]`, при этом `configItems` не меняется → без этого guard слеп); API-ключ; `ownKeyDraft`; `personaDraft` (сравнение с baseline `personaMeta.values`); `dossierDraft` (сравнение с `dossierData.manual_traits`, включая очистку до `''`). Guard вызывается **до** сброса черновиков (`setActiveChat` `:2521-2532`; `blockDrafts={}` — только после подтверждения, `:2572`). Это закрыло M-F3-1.
- **Почему confirm, а не авто-сохранение:** неявная запись при переключении области смешала бы scope-и и противоречила бы единому save-path F0 (ADR-1025-2).

### D4. Stale-эпоха — запоздавший ответ не применяется
Каждая загрузка инкрементит `scopeEpoch` (`:2509`); `_scopeGuard` (`:3379`) отбрасывает `loadConfig`-ответ, если эпоха изменилась (loading чужого scope не снимается). При смене scope черновики (`blockDrafts`/`keyDrafts`/`personaDraft`/`configChatUpdatedAt`) и `configItems` **очищаются — перенос запрещён**. Поведение покрыто `tests/js/round1025_scope_selector_test.js`.

### D5. §43 «Ожидает применения» — N/A (явное обоснование)
Отдельного `applied-state`/асинхронного применения с задержкой сервер не имеет (read-through `ConfigCache` + PG/`chat_params`, POST + NOTIFY; `GET /api/config` сразу отдаёт эффективное значение). Показывать «Ожидает применения» нечего — иначе выдуманное состояние (запрещено §43). Трассируемость закрыта **явным N/A**; «фактическое состояние» = эффективное `value` + `configItemNotice` при реальном расхождении (без шума на `per_chat=false`).

- **AMEND ADR-1020-9** — только в части, унаследованной от F2 (значения токенов); механики сохранены.

## Последствия
**Positive:** предсказуемая семантика возврата к глобальному (не сброс); отсутствие потери черновиков при смене области; отсутствие stale-состояния при быстрой смене чата; RBAC без эскалации; чёткое N/A по §43.
**Negative/издержки:** python-тест частично маркерный (поведение покрывает JS-тест; L-F3-2); остаточное F0-окно в `persistItems` (epoch снимается после `await`) — **follow-up F0**, не этот пакет; `configItemNotice`-формулировка по non-per_chat может читаться двояко (L-F3-1).

## Альтернативы
| Альтернатива | Почему отклонена |
|---|---|
| Возврат к **заводскому** дефолту | Уничтожает глобальную конфигурацию; смешивает «наследовать» и «сбросить» (§5) |
| Авто-сохранение черновиков при смене области | Смешение scope; конфликт с единым save-path F0 (ADR-1025-2) |
| Guard только по `dirtyItems` | Слеп к `blockDrafts` (M-F3-1) → тихая потеря правок |
| Показ «Ожидает применения» | Выдуманное состояние — read-through не имеет applied-state (§43) |
| Отмена запросов без эпохи (только по scope-id) | Не ловит одинаковый scope при быстром переключении туда-обратно |
