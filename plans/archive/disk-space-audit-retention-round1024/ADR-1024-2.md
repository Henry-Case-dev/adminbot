# ADR-1024-2 — Retention диска: 1 бэкап БД, неприкосновенная история, 6 мес JSONL, 7 дней логов

- **Статус:** **Accepted** (Step 2 @Architect, часть 1/2 раунда 10.24, 19.09.2026)
- **Фича:** F9 `disk-space-audit-retention-round1024`
- **Тип:** ops/данные (retention-политики + аудит/очистка) + единый источник истины ротации
- **Связано:** `round1024-architecture.md` §3.2; ADR-1024-1 (объём логов); `project.md` (imported-history-immutable)
- **Задачи:** T-2254…T-2263

## Context

1. Диск вырос **10 → 16.4 ГБ (+6.4 ГБ)** для текстового бота (UPD2 п.7). Главный кандидат: **полные safety-бэкапы БД** `memory_rebuild_*.db` (~802 МБ каждый), которые **не покрывались ротацией**: `services/memory_backup.py::_rotate` (`:180-200`) удаляет только `local_database_*.db`/`facts_*.txt`, а `create_safety_backup` (`services/memory_rebuild.py:149-175`) пишет `memory_rebuild_*.db` без ротации. Плюс не-history JSONL (`memory_generated_*.jsonl` — снимки досье) и логи.
2. Владелец (UPD3 п.5): **строго 1 последний бэкап БД** (3 — запрещено); JSONL — 6 месяцев; **архивы/дампы истории сообщений (`.jsonl`) удалять КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** (бесконечное хранение истории); прочие JSONL (снимки досье/телеметрия) — резать; логи — **7 дней**.
3. `imported_history_*.jsonl` — файлы **сырой истории** (создаются `services/memory_maintenance.py:426-…`, docstring `:434-435`: «файл содержит текст переписки»). Техдолг **S10.19-24** предполагал их ротацию — **отменяется политикой владельца** (Won't Fix).
4. `create_safety_backup` создаётся непосредственно перед рискованными операциями пересборки досье — удалять единственный свежий бэкап нельзя (Critical-риск R1 из tasks.md).
5. Retention в `memory_backup` уже есть (hot-config `limits.memory_backup_keep`, код-дефолт 1), но покрывает не все префиксы.

## Decision

### D1. Единый источник истины — `services/disk_retention.py`
- `prune_db_backups(directory, *, keep=1)` — удаляет все `*.db`-бэкапы кроме **одного** новейшего (по имени/дате), покрывая **оба** префикса (`local_database_*`, `memory_rebuild_*`). Вызывается из `memory_backup._rotate` и `memory_rebuild.create_safety_backup` → закрывает корневую причину +6 ГБ.
- `audit(dirs) -> dict`, `plan_cleanup(dirs) -> list`, `apply_cleanup(plan, *, verify=True) -> dict`, `forecast_monthly(dirs) -> dict`.
- Δ DDL = 0, Δ каталога = 0 (env-only ClassVar).

### D2. Таксономия (жёсткая, приоритет — сохранность данных)
| Класс | Шаблоны | Политика |
|---|---|---|
| IMMUTABLE | `imported_history_*.jsonl`, `media/**`, SQLite-БД, `.env` | **никогда не удалять** |
| DB-бэкапы | `local_database_*.db`, `memory_rebuild_*.db` | ровно **1** новейший суммарно |
| facts-export | `facts_*.txt` | 1 (пара к БД) |
| JSONL-ротация | `memory_generated_*.jsonl`, прочие не-history `*.jsonl` | удалять старше **180 дней** |
| Логи | journald | **7 дней** (`SystemMaxUse`/`MaxRetentionSec`) |

### D3. Безопасность удаления (fail-closed)
- Порядок: `снимок (audit) → план → verify (существует валидный свежий бэкап) → удаление → лог «удалено/освобождено»`.
- Без валидного свежего бэкапа удаление **запрещено** (``verify`` fail → abort).
- CLI по умолчанию dry-run; удаление — только с `--apply`.
- Ни один секрет (SSH/ключи) не попадает в отчёт/лог (R17/R18); пути — без секретов.

### D4. Логи — 7 дней
- journald: `SystemMaxUse` + `MaxRetentionSec=7d` (применяет @DevOps на сервере, конфиг-сниппет в отчёте/runbook).
- Приложение: лимит длины тела (ADR-1024-1) снижает объём; собственная файловая ротация не вводится (логи в journald).

### D5. Отчёт владельцу-обязательство (UPD2 п.7.3)
- Обязательный отчёт: (1) причина роста +6 ГБ с атрибуцией по компонентам; (2) что удалено и сколько освобождено; (3) прогноз расхода на месяц. Место — `plans/metrics.md` (по завершении F9) + live-отчёт @DevOps.

## Consequences

**Positive**
- Диск «дышит»: safety-бэкапы больше не накапливаются; не-history JSONL и логи ограничены.
- Сырая история сообщений **неприкосновенна** (инвариант владельца).
- Единый источник ротации исключает расхождение путей (баг +6 ГБ).
- Отчёт даёт владельцу факты.

**Negative**
- Хранится только 1 бэкап БД → окно отката уже (принято владельцем; именно поэтому verify перед удалением).
- `imported_history_*.jsonl` продолжают расти (осознанно, по политике).
- Требуется явный `--apply` и live-аудит (@DevOps).

## Alternatives

- **A1. Хранить 3 бэкапа (прежний Human Gate #5)** — **отклонено владельцем** (UPD3 п.5): запрещено.
- **A2. Ротировать `imported_history_*.jsonl` (техдолг S10.19-24)** — **Won't Fix**: владелец запретил удалять историю.
- **A3. Сжимать архивы истории** — **отклонено**: мутация неприкосновенных файлов; риск потери/несовместимости.
- **A4. Только ручная очистка без политик** — **отклонено**: проблема вернётся.
- **A5. Отдельная DDL-таблица журнала retention** — **отклонено**: Δ DDL; достаточно отчёта/логов.
