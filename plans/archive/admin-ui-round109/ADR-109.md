## ADR-109-1 — Кастомное имя модели хранить как `ParamSpec` (Settings)

**Контекст.** Нужно «Название модели» (кастомное имя) для dashboard и форм провайдеров. Варианты: новый каталог `ParamSpec` vs карта в коде/`bot_settings` ad-hoc.

**Решение.** 7 новых `ParamSpec` (`models.*_display_name`), поля `Settings` (`LLM_DISPLAY_NAME`, …), сид через существующую миграцию. Глобальные (`models.*` вне per-chat).

**Альтернативы.** (a) Карта в `web/app.js` — не видна в `/api/status`, дублирует UI-состояние. (b) PG-only без Settings — требует нового механизма сидинга.

**Последствия.** Settings 364→372, REGISTRY 392→400. Плюс: единый источник (каталог), перчаточный UI, без новой механики.

## ADR-109-3 — Health-проверка: реальный POST вместо `GET /models`, кэш с TTL по результату

**Контекст.** Stale-200 из 60-с кэша и 200 от `/models` при 502/503 от `/chat/completions` дают ложное «здоровье».

**Решение.** Единый `probe_openai(base,key,model,kind)` (`services/llm_probe.py`): `kind="chat"` → минимальный POST `/chat/completions` (1 token); `kind="embeddings"` → `POST /embeddings`; `kind="stt"` → `POST /audio/transcriptions` (multipart с минимальным тихим WAV — Whisper не chat-модель, chat-проб к ней всегда падал и давал ложный `ok=False`). Таймаут 5с; статусы `ok|error|timeout|unreachable|not_configured`. Кэш по `module_id`: 2xx — 60с, ошибки — 10с; stale-ok не отдаётся. `stt_groq` → `kind="stt"`; `stt_openrouter` остаётся `kind="chat"`: его расшифровка идёт через `chat.completions` с `input_audio` (`openrouter_transcriber`), отдельного STT-эндпоинта у него нет.

**Последствия.** Точнее статус; чуть больше трафика к провайдеру (по одному проб-запросу на провайдера при `/api/status`, параллельно `asyncio.gather`). STT-карточка больше не «вечно красная», в историю ключей не пишется ложный `ok=False`. Тесты `test_status_service.py` обновляются (в т.ч. URL/method STT-проба).

## ADR-109-4 — PERMsoc: новый `SLAVIK_ENABLED` для независимого тумблера Славика

**Контекст.** Модуль `slavik` — master-derived (`sub_flag_key=None`), независимого тумблера нет. Требование владельца: у **каждого** owner-блока ровно один реально работающий, не дублирующий тумблер.

**Решение.** Новый флаг `SLAVIK_ENABLED` (default **True**) → `_FLAGS` (`flags_permsoc`) + `PermsocModule("slavik", …, sub_flag_key="flags.slavik_enabled")`; `DEFAULT_SUB_FLAGS[...] = True`. Untouched → поведение байт-в-байт. `kostik`/`alan` остаются master-derived и живут в блоке «Общее».

**Альтернативы.** (a) Использовать мастер как тумблер Славика — дублирует мастер и вводит в заблуждение. (b) Добавить `gates.slavik` — шире и ломает домен гейтов.

**Последствия.** Settings 364→365, REGISTRY 392→393. Router order `bot.py` не меняется (гейт уже стоит). `permsoc_telemetry`/`permsocModuleBadge` обновить.

## ADR-109-5 — «Бюджет фона» переносится в «Сводку»; backend не меняется

**Контекст.** Нули — следствие отсутствия строк `worker_budget` за сутки (воркеры не тикали), усиленное UI-дефектом (перебор всех чатов) и дублированием с `oversight.global_budget`.

**Решение.** Карточка с «Модулей» удаляется; компактная полоса в «Сводке» (источник `worker_budget.get_day_summary` через `loadBudgetInfo`, вызывается из `loadOversight`); per-chat — по-прежнему колонка таблицы. Backend/`worker_budget.py` и endpoint сохраняются. Пустое состояние — «Сегодня расхода ещё не было».

**Последствия.** Убирается дубль, чинится «не тот чат», функционал не теряется. Тесты-маркеры переноса обновить.
