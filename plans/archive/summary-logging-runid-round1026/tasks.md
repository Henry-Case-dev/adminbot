## Приёмочные инварианты S7 (нарушение = НЕ принято; трассировка §ТЗ + ADR-1026-9 + SC спеки)
1. **Единый `run_id` на прогон (ADR D1):** `run_id` = существующий `correlation_id` (UUID4 hex, `usage_events.new_correlation_id()`, `services/usage_events.py:62`); ровно **одна** точка создания — живой путь `summary_generator.py:348`, dry-run `summary_test_run.py:495`; второй идентификатор **не вводится**; все этапы получают его **параметром**. **SC-01/SC-02.**
2. **Аддитивность:** новые события/поля — **аддитивны**; существующий формат логов и `GET /api/status/logs` не ломаются; «OFF байт-в-байт» = неизменность **артефактов/поведения** (возвраты, число/состав LLM-вызовов, публикация, XML, файлы), **аддитивные лог-строки допустимы** (§108 прямо требует «все этапы логируются») — тесты пинят артефакты, не лог-байты (ADR D7). **SC-13.**
3. **R17-safe:** только числа/коды/id/host/HTTP-статус/тип ошибки/причина/попытки; **без** API-ключей, промптов, сырых текстов сообщений, сырых ответов LLM, персонального содержимого досье. Маскировка — существующим `sanitize()` (`services/log_ring.py`). **SC-08/SC-12.**
4. **События §108 (ADR D2):** переиспользовать существующие `FILTER_*`/`RESTORE_*`/`L1_*`/`L2_*`/`TEST_*`; **добавить** `SUMMARY_START`/`SUMMARY_COMPLETE`/`SUMMARY_FAILED`, `FORMAT_START`/`FORMAT_COMPLETE` (+`run_id`/`reason` в существующий `FORMAT_ERROR`), `COVER_START`/`COVER_COMPLETE`/`COVER_ERROR`; имена адаптируются к существующему формату, смысл сохраняется. **`PUBLISH_*` — GATED, НЕ реализовывать** (пометить явно). **SC-02…SC-06, SC-15.**
5. **Детали §109:** по каждому `*_COMPLETE` — оговорённые поля (см. spec §5); при ошибке — `run_id`/этап/модель/провайдер(host)/HTTP-статус/тип/причина/попытки; строка «Ошибка Саммари» без деталей **запрещена**. **SC-03…SC-07.**
6. **Телеметрия (ADR D3):** связь событий с существующим учётом `llm_usage_events` (PG, `module='summary'`, `step ∈ {l1_clusterizer,l2_writer}`) по `run_id`/`correlation_id`; **Δ DDL=0** — новых таблиц/колонок/индексов **нет** (ring-buffer `services/log_ring.py` + файловые логи; retention без изменений; сбор контекста — in-memory/`_filter_metrics`). **SC-11/SC-12.**
7. **§110 log viewer (ADR D4):** используется **существующий** viewer внизу Статуса (`web/app.js:9457–9607`); **клиентский** фильтр-чип «Саммари» (`logLevel→'INFO'` + фильтрация `this.logs` по маркерам `SUMMARY_`/`FILTER_`/`RESTORE_`/`L1_`/`L2_`/`FORMAT_`/`COVER_`/`TEST_`/`run_id=`), **без нового endpoint и без diff `routes.py`** (обоснование «без неоправданного усложнения» — spec §7); раскрытие/копирование (`expanded`/`logText`/`copyLogRow`) сохраняются; при ошибке — понятная формулировка + раскрытие `run_id`/время/модель/причина/подробности. **SC-09/SC-10.**
8. **Fail-closed/покрытие ошибок (ADR D6):** каждый этап имеет `*_ERROR`-ветку + `SUMMARY_FAILED` при провале (вместо `SUMMARY_COMPLETE`); ошибка одного этапа логируется с деталями §109 и не маскируется под успех; недоступность лог-стора — best-effort, пайплайн не прерывается. **SC-07.**
9. **Границы (ADR D2/D5/D6):** ExecutionGraph (§111) — **S8**, узлы S7 не создаёт; публикация (§100–§106) — **S6 GATED**, не вызывается, `PUBLISH_*` отсутствуют в diff; dry-run (§113) — **S9**: 0 публикаций / 0 памяти / 0 `generate_image` сохранены, эмитятся `TEST_*` **без** `SUMMARY_*`/`PUBLISH_*`, тот же `run_id`, второй контур логирования не создаётся. **SC-14/SC-15.**
10. **Инварианты проекта (ADR D7):** **Δ DDL=0**; **Δ каталога=0** (`param_catalog.py` вне diff; новых ключей/env нет; **F8 НЕ переиздаётся — N/A**, ADR-1026-2 не запускается); CSP/zero-build; 0 новых внешних зависимостей; **2-вызовность** (`await_count==2`); §104/обложка/XML вне diff; **R18** (бэкапы/теги не удалять). **SC-12/SC-13.**
