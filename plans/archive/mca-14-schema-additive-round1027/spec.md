## 1. Область и исключения

**Входит:** идемпотентный версионируемый migration-runner (реестр шагов); backup согласованно с SQLite+WAL + проверка места + проверка чтения копии; политика nullable/unknown и сохранения стабильных ID/таблиц; индекс-политика по explain; контракт archive-job (checkpoint/уникальный ключ/resume), разделяемый с `mca-01`; rollback-build/forward-fix контракт; единая kill-switch-политика; **механизм заявки Δ DDL** для всех последующих фич (реестр версий + формат санкции).

**Не входит (границы):** доменные таблицы (SourceRef/Episode/Intent/MediaAsset/и т.д. — волны 1–5 заводят версии v16+ через этот механизм); сам TaskSupervisor (`mca-01`); контракт событий (`mca-13`); PG-схема (`pg_db.py` вне diff — GEN-R4); удаление/переименование старых таблиц (запрещено); восстановление БД как штатный откат (запрещено).

## 3. Наблюдаемое поведение и отказы

- На **свежей** и на **legacy v12** БД `initialize()` приводит `PRAGMA user_version` к целевой версии; повторный запуск — no-op (нулевые изменения, нулевые дубли).
- Перед применением любого нового шага — backup; если места недостаточно или копия не читается — **явная ошибка и отказ применять** (никакого частичного применения).
- Legacy-строки сохраняют `id`; новые `nullable`-поля честно `NULL`/`unknown` (не выдуманный источник).
- Archive-job: при прерывании/рестарте продолжает с последнего подтверждённого checkpoint; повторный старт не создаёт дублей (уникальный ключ).
- Отказ backup/миграции не тушует приём сообщений; ошибка видна в логе (R17-safe) и в терминальном событии MCA-13.

## 4. Интерфейсы и контракты

### 4.1. Migration-runner (D1 ADR-1027-1)
- Реестр шагов: `list[MigrationStep{version:int, name:str, apply: async callable}]`; `_run_migrations()` читает `PRAGMA user_version`, применяет шаги с `version > current` по возрастанию, пишет книгу `schema_migrations(version, name, applied_at, checksum)`, ставит новую `user_version`.
- Legacy-БД (v1…v12 без книги): шаги v1…v12 не исполняются повторно (idempotent guards + `user_version`), книга back-fill одним baseline-рядом; применяется только v13+.
- Идемпотентность двойная: guard раннера (`version >`) **и** self-guard шага (`sqlite_master`/`PRAGMA table_info`).
- Существующие методы `_migrate_*` **переиспользуются** как тела шагов (REUSE), не переписываются.

### 4.2. Backup с WAL + free-space + read-back (D2)
- Механизм — **`VACUUM INTO`** (REUSE `services/memory_backup.py:110`; консистентная копия включая WAL; fallback `sqlite3 .backup` уже есть). Копия одного файла без учёта WAL запрещена.
- **Free-space check** (`shutil.disk_usage`) ≥ размер БД × safety-коэффициент до применения; недостаток → явная ошибка.
- **Read-back:** открыть копию read-only, `PRAGMA integrity_check` == `ok`, сверить `user_version`; провал → отказ.
- Путь/имя копии — не в логи (R17).

### 4.3. Archive-job контракт checkpoint/уникальный ключ (D4)
- Долгая работа разделена: чтение → (LLM) → **короткая запись** под общим write-механизмом `mca-01`; транзакция не держится на весь диапазон.
- Job-поля: dataset/диапазон/курсор/версия/status/heartbeat/attempt/processed; **уникальный ключ** против повторного применения/параллельного старта; checkpoint пишется после фиксации; resume с последнего checkpoint.
- Контракт **разделяется** с `mca-01` (`task_jobs`, поля `coalesce_key`/`generation`/`fencing_token`/`heartbeat_at`) — второй job-механизм не вводится.

### 4.4. Индекс-политика (D5)
- Индекс добавляется только под **реальный** запрос, подтверждённый `EXPLAIN QUERY PLAN`; «все комбинации» запрещены. Каждый индекс фиксируется в `spec.md` фичи-владельца с планом запроса.

### 4.5. Rollback-compat (D6)
- Совместимый откат кода оставляет новые данные (аддитивность). Для несовместимой версии — **исправленный rollback build** или **forward fix**; backup restore — только аварийный сценарий. Манифест rollback-build приложен (T-3758).

## 5. Δ DDL / Δ каталога / kill-switch

- **Δ DDL:** **v13** — `schema_migrations` (см. рамку §1.1). Доменных таблиц нет. PG — no-op.
- **Δ каталога:** **0** (все рубильники/лимиты env-only `ClassVar`); F8 не переиздаётся (ADR-1026-2 NOT_APPLICABLE).
- **Kill-switch:** `MCA_SCHEMA_MIGRATIONS_ENABLED` (env-only `ClassVar`, default ON); OFF → legacy-путь миграций без runner/backup-обвязки (паритет baseline). Существующий `DB_LOCK_RESILIENCE_ENABLED` уважается, не дублируется.

## 6. Приёмочные сценарии (SC)

- **SC-01:** на legacy v12 БД прогон поднимает `user_version` до целевой; `schema_migrations` содержит ряды для v13+; повторный прогон — 0 изменений, 0 дублей.
- **SC-02:** на свежей БД результат тот же; missing-колонки/таблицы создаются идемпотентно.
- **SC-03:** backup создаётся `VACUUM INTO`; при искусственно малом месте — явная ошибка, миграция **не** применена.
- **SC-04:** read-back копии даёт `integrity_check=ok` и совпадающий `user_version`; битая копия → отказ.
- **SC-05:** legacy-строки сохраняют `id`; новые `nullable`-поля = `NULL` (unknown), не выдуманы.
- **SC-06:** для каждого добавленного индекса приложен `EXPLAIN QUERY PLAN` реального запроса; «комбинаторных» индексов нет.
- **SC-07:** archive-job исполняется без транзакции на весь диапазон; прерывание → resume с checkpoint; `EXPLAIN`/лог подтверждают короткую запись.
- **SC-08:** повторный/параллельный старт того же job не создаёт дубль (уникальный ключ).
- **SC-09:** `git revert` к `7165ff7` сохраняет новые данные; несовместимая версия → rollback build/forward fix; backup restore не штатный.
- **SC-10:** у каждой функции волны 0 (и последующих) резолвится kill-switch; OFF даёт паритет baseline; OFF-запись содержит причину/время/план (R17-safe).
- **SC-11:** новая DDL-фича без зарезервированной версии/санкции в рамке не проходит gate; шаг регистрируется, а не правит общую последовательность.
- **SC-12 (A28):** до деплоя в БД сохранены false-настройки; после старта согласованные функции реально включены (недостаточно новых defaults).
- **SC-13:** логи миграций/backup не содержат секретов/полных путей; события — по контракту MCA-13; `R17`-тесты зелёные.

## 7. Зависимости

Нет обязательных предшественников. Потребители: `mca-01` (`task_jobs`), `mca-13` (`mca_events`), все DDL-фичи волн 1–5. Совместно с Wave 0: `mca-13`, `mca-01`. Внешние сервисы не требуются.
