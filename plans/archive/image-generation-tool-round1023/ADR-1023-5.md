# ADR-1023-5 — Генерация изображений: инструмент `generate_image` на провайдере Pollinations (POST/GET), секрет только env/PG

- **Статус:** **Accepted** (Step 2 @Architect, часть 2/3 раунда 10.23, 19.09.2026)
- **Фича:** F5 `image-generation-tool-round1023`
- **Тип:** backend (tool/service) + UI (`web/**`) + PG-сид
- **Связано:** ADR-1020-4 (гейт инструмента по флагу), ADR-1020-7 (деградация tool-loop), ADR-1019-8 (идемпотентные PG-сиды), `round1023-architecture.md` §1/§3.4/§5
- **Задачи:** T-2136…T-2146

## Context

1. ТЗ требует инструмент `generate_image` для Синтезатора прямого чата (ключевики + tool-calling), провайдера Pollinations.ai (`Base URL https://gen.pollinations.ai/v1`, модель `flux`, жёстко `"response_format":"url"`), блок в «Провайдеры» (URL/Модель/API Ключ/чекбокс GET) и тумблер в «Модули».
2. ТЗ задаёт реальный ключ; он **не должен** попасть в git/логи (Critical-риск). Коммитить/цитировать нельзя (R17/R18).
3. Обязательное правило владельца: перед интеграцией сторонних API — веб-ресёрч. Он выполнен (см. References): подтверждены Base URL, OpenAI-compatible endpoint, `response_format:"url"`, GET `/image/{prompt}`, ошибки/`Retry-After`, лимиты Telegram `sendPhoto`.
4. Ключевые технические ограничения: `tool_choice` форсировать нельзя (канон R9/backlog §16); тул-цикл `TOOL_MAX_ROUNDS=4`; бюджет — `worker_budget`; egress — реестр; меню мини-аппа заморожено.

## Decision

### D1. Провайдер и протокол
- База: `https://gen.pollinations.ai/v1`; `POST /v1/images/generations` с `Authorization: Bearer <key>`, JSON `{prompt, model:"flux", n:1, size:"1024x1024", response_format:"url"}`. Жёсткий `response_format:"url"` — требование ТЗ; для owned-модели `flux` поддерживается (community — нет, см. ресёрч). Если шлюз всё же вернёт `b64_json` (игнорируя `response_format`), он принимается как **сознательный defensive-fallback** — контракт основного пути (`data[0].url`) не меняется, генерация не падает (review iter1, Finding 5).
- **GET-режим — строго анонимный** (review iter1, Finding 1): ключ в query НЕ добавляется, даже если он задан; UI блокирует ввод ключа в GET-режиме. Причина — httpx логирует полный URL на INFO, а консольный/journald-обработчик не гарантировал маскировку. Defense-in-depth: `logging.getLogger("httpx").setLevel(WARNING)` + `SecretMaskFilter` (`services/log_ring.py`) на `console_handler` в `bot.py`.
- GET-режим: `GET https://gen.pollinations.ai/image/{quote(prompt)}?model=flux&width=1024&height=1024&seed=<random>` (без ключа — строго анонимный, review iter1 Finding 1). Параметр `seed` — для воспроизводимости/повтора.
- Ошибки: `4xx` не ретраим (кроме `429`), `429/503` — ≤1 ретрай с учётом `Retry-After`; таймаут `IMAGE_REQUEST_TIMEOUT_SECONDS` (env-only, default 90 c).

### D2. Тул-интеграция без форса `tool_choice`
- Явные ключевики — **пре-гейт** (образец `_dig_pre_gate_block`): детект `IMAGE_KEYWORD_RE`, генерация+отправка, инъекция `<image_result>` в Stage-1. Это не форсирует `tool_choice` (канон сохранён) и детерминировано.
- Свободные просьбы — обычный tool-calling: `generate_image(prompt)` 9-м инструментом (первые 8 — байт-в-байт), гейт `active_tools(..., image_generation_enabled)`.
- Инструмент сам отправляет изображение (прецедент `download_media`, который сам отправляет файл) и возвращает модели короткий статус.

### D3. Секрет — только env/PG, байты вместо keyed-URL
- Ключ резолвится `hot.get("keys.image_api_key", settings.IMAGE_API_KEY)`; default пуст; сид-миграция пишет только URL/model/GET-дефолты, **не** ключ.
- **Никогда** не логируется и **никогда** не передаётся в Telegram: байты изображения скачиваются сервером и отправляются как `BufferedInputFile` (multipart). В GET-режиме keyed-URL не покидает сервер.
- Тест «нет plaintext-ключа в репо» + R18-отчёт.

### D4. Бюджет
- Перед платным вызовом: `worker_budget.consume(pg, scope=f"chat:{chat_id}", metric="image_calls")`. `False` → деградация/отмазка. PG down → fail-open `True`.
- Новая метрика `image_calls`; лимит переиспользует существующий per-chat paid-call лимит (`limits.worker_daily_llm_calls_per_chat`) — **без нового каталогового ключа** (Δ каталога ограничен image-группами).

### D5. Каталог (Δ фиксирован)
- +3 группы: `models_images`, `keys_images`, `flags_module_images`.
- +5 ключей: `IMAGE_BASE_URL`, `IMAGE_MODEL`, `IMAGE_GET_MODE`, `IMAGE_API_KEY`, `IMAGE_GENERATION_MODULE_ENABLED`.
- Вкладок не добавляем (`TAB_RULES +0`, `TAB_NAV +0`), меню заморожено.

### D6. Egress
- Новый `telegram_send.send_photo`; точка регистрируется в `SEND_ALLOWLIST` (`services/image_generation.py`: байты без LLM-текста). Подпись не несёт модель-текста.

## Consequences

**Positive**
- Функция генерации изображений встроена в существующий tool-loop без нарушения канона R9/`tool_choice`.
- Секрет не утекает (env/PG, байтовый путь, тест).
- Стоимость контролируется `worker_budget`; сбой не роняет бота.
- Каталог расширен предсказуемо (3 группы/5 ключей), меню не тронуто.

**Negative**
- Неделимая зависимость от внешнего провайдера (доступность/латентность/лимиты) — митигируется таймаутом/фолбэком/флагом.
- GET-режим с `?key=` несёт риск утечки ключа в логи посредника (рекомендация — анонимный GET или POST; вынесено в Human Gate).
- `flux` — не самая дешёвая модель; стоимость зависит от провайдера.
- Дополнительная точка egress и новые каталоговые ключи → пин-тесты.

## Alternatives

- **A1. Форсировать `tool_choice=generate_image` на ключевиках** — **отклонено**: нарушает канон (backlog §16 п.2); вместо этого пре-гейт.
- **A2. Передавать URL провайдера прямо в `sendPhoto`** — **отклонено**: в GET-режиме URL содержит ключ → утечка к Telegram; плюс недетерминированная повторная генерация. Скачиваем байты сами.
- **A3. Хранить ключ в код-константе/миграции** — **отклонено** (Critical-риск, R18).
- **A4. Только tool-calling без ключевиков** — **отклонено** ТЗ (нужны явные ключевики); пре-гейт даёт детерминизм.
- **A5. Новый каталоговый ключ лимита image-вызовов** — **отклонено** ради Δ каталога; переиспользуем существующий per-chat лимит.
- **A6. Отдельная таблица/DDL для изображений** — не нужно (только `bot_settings`).
