# ADR-1017-2 — Запрос качества в tool-пути скачивания (SUPERSEDE ADR-1016-1 §2 п.3/§3)

> **Статус:** Accepted (Step 2 @Architect, 14.09.2026). **Раунд:** 10.17. **Фича:** F2 `tool-download-quality-round1017` (T-1675).
> **Связано:** ADR-1015-3 (tool calling, корнер-кейс файлов), ADR-1016-1 (контракт скачивания).
> **⚠️ SUPERSEDE:** отменяет решение **ADR-1016-1 §2 п.3** и строку таблицы **§3** «Добавить `quality` в JSON-Schema `download_media` — Отклонён». Остальные пункты ADR-1016-1 (контракт `download(url, quality=None, progress_cb=None)`, ветвление direct/платформа по URL, reason-коды R17, bounded probe-fallback) — **в силе**.

## 1. Контекст

UPD3 (стр. 157): прямое `Бот, скачай` работает **с выбором качества**; tool-calling то же видео **не скачивает и даже не спрашивает качество**. ADR-1016-1 сознательно запретил LLM выбирать качество и оставил tool-путь на авто-`max`. Практика показала дефект: авто-`max` (`download(url)` без `probe`) на части роликов не собирается, а UX «молчаливое max» владельца не устраивает — нужно **то же меню качества**, что в Fast-Track.

Требование владельца (UPD3): tool должен **спрашивать** качество. Предложенная механика — бэкенд отправляет клавиатуру качества и возвращает LLM `tool_response` вида «пользователю предложен выбор качества»; callback доделывает скачивание.

## 2. Решение

1. **Меню качества инициирует бэкенд, не LLM.** `_download_media` для платформенного URL делает `probe()` (метаданные + реальные качества) и отправляет в чат инлайн-клавиатуру `tdq:<height>`; в LLM возвращается фиктивный `tool_response {"status":"needs_quality", …}` (модель не «печатает» файл — ADR-1015-3 §4). Скачивание доводит callback `tdq:` в роутере 4e (переиспользует downloader/media-send/прогресс/кулдаун Fast-Track).
2. **`quality` В JSON-Schema `download_media` добавляется** (enum `max`/`2160`/…/`360`, `QUALITY_ENUM`) — **но опционально и только для явного запроса пользователя**. Если LLM передал `quality` (пользователь сказал «скачай в 720p») — скачиваем сразу без меню. Иначе — меню. Это отменяет запрет ADR-1016-1 §2 п.3, сохраняя UX-приоритет меню.
3. **Прямой медиа-URL** (`is_direct_media_url`) скачивается сразу без меню (качество нерелевантно) — как Fast-Track `:284-339`.
4. **Bounded fallback:** провал `probe` для не-direct URL → **одна** попытка `download(url, None)` без меню; провал → честный `status:"error"` (зеркало Fast-Track `_download_without_menu`).
5. **Кулдаун (D279):** touch — только после успешного `probe` (ask-ветка) либо после успешного `download` (немгновенные ветки); callback кулдаун **не трогает**. Провал кулдаун не жжёт.
6. **Pending — in-memory TTL 600 c** (key `(chat_id,user_id)`), ленивая чистка; без PG/DDL. Истечение/нет pending → «меню протухло».
7. **Лимиты tool-loop (4 раунда / 2 вызова) не меняются.** Tool-сет остаётся 7 инструментов.

## 3. Рассмотренные альтернативы

| Вариант | Вердикт |
|---|---|
| Не добавлять `quality` в схему (меню всегда) | **Частично:** базовый флоу — да; но явный запрос «в 720p» в свободной форме остался бы без прямого пути. Добавляем опциональное поле. |
| Отдельный tool `ask_download_quality` + повторный `download_media(url, quality)` | **Отклонён:** +1 инструмент (tool-сет 8), лишний раунд tool-loop, LLM должен удержать URL между раундами — хрупко |
| LLM сам спрашивает текстом, пользователь отвечает числом → `download_media(url, quality)` | **Отклонён:** UX-шум, парсинг свободного ответа, риск неверного качества; owner-TZ требует кнопки |
| Pending в PG (персист между рестартами) | **Отклонён:** рестарт бота редкость, TTL 10 мин; DDL/миграции не нужны (SQLite v9 сохраняется) |
| Скачивать `max` без меню при провале probe | **Отклонён:** маскирует причину; fallback даёт **одну** попытку и честный reason-лог |
| Возврат `file_id`/размера в tool_response вместо фикции | **Отклонён** (ADR-1015-3): модель пытается «печатать» файл |

## 4. Последствия

- (+) Tool-путь даёт тот же UX качества, что Fast-Track; дефект падения закрыт probe-first + явным int-качеством.
- (+) Единый источник enum (`QUALITY_ENUM` ↔ `_ALLOWED_HEIGHTS`) — нет дрейфа.
- (−) Появляется состояние pending (in-memory) и callback `tdq:` в роутере 4e — рост поверхности, покрыт тестами (timeout/busy/stale).
- (−) Возможен «двойной» текст: меню от бэкенда + финальная реплика LLM. Митигация — `tool_response` приказывает модели кратко подтвердить; не блокер.
- Инварианты: лимиты tool-loop, порядок роутеров `bot.py`, каталог-Δ=0, `media/`/`.env`, R16/R17 — без изменений.

## 5. Трассируемость

ADR-1016-1 §2 п.3/§3 — **отменены**. ADR-1016-1 §1 (`download`-контракт), §2.4 (reason-коды), §2.5 (probe-fallback) — **сохранены** и переиспользованы в tool-пути.
