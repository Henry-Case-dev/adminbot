# ADR-1022-8 — Асинхронная пересборка досье из мини-аппа: файловый job-store, кооперативная отмена + rollback из стартового снапшота

- **Статус:** **Accepted** (Step 2b @Architect по решению владельца UPD3 §2, 18.09.2026)
- **Фича:** F8 `dossier-rebuild-async-ui-round1022`
- **Тип:** backend (job-store/API) + frontend `web/**` + data-safety/rollback
- **Связано:** ADR-1022-1 (движок rebuild + confirmed-cleanup), ADR-1021-5 (guard/архив/бэкап), ADR-1020-5 (снапшот), ADR-1013-3, R16/R17, F2 (ступень `web/**`)

## Context

Владелец требует в мини-аппе кнопку **«Пересобрать досье»** (период 30/90/180/Всё время) с
**фоновой задачей**, **прогресс-баром «X/Y чанков»**, **persistence** при reopen и **отменой
с откатом** производных юзера из стартового бэкапа.

Аудит:
- Движок уже есть: `services/memory_rebuild.py:400` + `services/lore_worker.py:691-717`
  (окно `smart_messages` — только чтение). CLI F1 нетронут.
- Паттерн фоновой задачи и статус-эндпоинтов — `web/api/memory_agi.py:323-337` (202/409,
  `asyncio.create_task`) + `:455`/`:530`.
- Паттерн прогресса (мост/троттлинг/fail-open) — `services/progress_reporter.py:92-264`.
- Карточку «Досье» формирует `get_persona_card` (`database.py:4410-4437`): `target_user=name
  AND status='confirmed'` + `dossier_portrait` + edges-links.
- `graph_facts`/`persona_dossier_overrides` — main SQLite (v12), PG-схемы graph_facts нет.

Ограничения: **Δ каталога = 0**; инварианты `imported-history-immutable`/
`manual-overrides-immutable`; одна задача на юзера; переживание reopen (и, по возможности,
рестарта).

## Decision

1. **Job-store — файловый JSON** (`services/dossier_rebuild_jobs.py`, каталог
   `<MEMORY_BACKUP_DIR>/dossier_jobs/`), атомарная запись (`tmp`→`os.replace`+fsync), retention
   (50 job'ов / 7 дней), один писатель (`asyncio.Lock`). **Без DDL** (SQLite остаётся v12).
   *Альтернатива (таблица БД) отклонена:* DDL/миграция ради короткоживущего job-стейта;
   файл проще тестировать и он не трогает схему памяти.
2. **API (4 эндпоинта)** в `web/api/chat_lore.py`: `POST rebuild`, `GET rebuild/{job_id}`,
   `GET rebuild/latest`, `POST rebuild/{job_id}/cancel`; RBAC `_require_chat`; 409 при активном
   job для `(chat_id,user_id)`; fail-open GET.
3. **Движок:** аддитивный `LoreWorker.rebuild_dossier_for_user(..., target_user, chunk_size,
   progress_cb, cancel_cb)` — user-scoped, чанковый, с кооперативной отменой; существующий
   `rebuild_dossier_for_chat` не меняет поведение (CLI F1 совместим).
4. **Прогресс:** `total = ceil(COUNT(окна)/chunk_size)` (дешёвый COUNT); `processed` после
   каждого чанка; троттлинг записи + fail-open (не роняет пересборку).
5. **Стартовый снапшот + rollback:** точечный JSONL производных целевого юзера
   (`confirmed`/`chat_meme`/`dossier_portrait`, `kind='fact'`) на старте (fail-closed без него);
   отмена → архив текущих производных + удаление через guard + восстановление снапшота
   (`INSERT OR REPLACE` по `id` + FTS, vec best-effort); идемпотентно; `overrides`/
   `smart_messages`/beliefs/nodes/edges не трогаются.
6. **Конкурентность:** уникальность per `(chat,user)` + файл-lock per chat против CLI-прогона F1
   (stale-детект по TTL/pid).
7. **Рестарт:** job-store переживает рестарт; **живое исполнение — нет** → non-terminal job'ы
   помечаются `interrupted`, доступен ручной rollback. **Авто-resume не делается**
   (LLM-пересборка небезопасно-возобновляема; полу-записанные производные честнее показать).
8. **Флаг:** `DOSSIER_REBUILD_UI_ENABLED` — env-only `ClassVar`, **default ON**, Δ каталога = 0;
   OFF → эндпоинты 404 + кнопка скрыта.

## Consequences

- Владелец управляет пересборкой из UI; видимый эффект — очистка confirmed-мусора + свежий
  `dossier_portrait`. Стоимость LLM растёт с окном (chunking/bounded).
- Появляется новый контур персистентного job-стейта и rollback-снапшотов (зона сопровождения:
  retention, lock, stale-детект).
- Принят риск R2 (job не переживает краш) — компенсирован `interrupted` + ручным rollback.

## Alternatives

- **In-memory job без persistence** — отклонено: нарушает требование persistence/reopen.
- **Полный DB-бэкап на каждый UI-job (`create_safety_backup`)** — отклонено: ~724 МБ на клик;
  точечный снапшот производных достаточен (сырая история/overrides не мутируются).
- **Kill процесса вместо отката** — отклонено владельцем (нужен rollback).
- **Авто-resume после рестарта** — отклонено: небезопасно/неидемпотентно.
- **Отдельный фронтенд-опрос через WebSocket** — избыточно; polling GET каждые ~2 c достаточен.
- **Новый ключ `param_catalog`** — запрещено (Δ каталога = 0); chunk-size/chunk-window —
  env-константы.

## Cost ×2 / бюджет / латентность

LLM: Layer A × чанков + Layer B (1); bounded `max_msgs`/chunk_size. HTTP не блокируется
(`asyncio.create_task`). Бюджет — существующие лимиты LLM-воркера. Логи — counts/коды (R17).

## Kill-switch / Fallback / Rollback

- **Kill-switch:** `DOSSIER_REBUILD_UI_ENABLED=false`.
- **Fallback:** ошибка снапшота → job `failed` без мутаций; fail-open GET; UI не падает.
- **Rollback:** `rollback_<job_id>.jsonl` (восстановление) + `cancelled_<job_id>.jsonl` (аудит);
  второй рубеж — авто-бэкап F1; код — флаг OFF / `git revert`.

## Canon migration

**Не требуется** (нет промптов/канон-констант; UI/бэкенд-инфраструктура).
