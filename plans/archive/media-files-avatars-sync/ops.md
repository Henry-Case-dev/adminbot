# F6 — операционная процедура: локальное хранилище Bot API и рассинхрон ФС↔БД

> T-1832 (@Builder, раунд 10.19). Без секретов (R17): строка `<bot_id>:<token>`
> и абсолютные пути с токеном здесь НЕ приводятся.

## Где лежат файлы локального Bot API

При `is_local=True` (D262) telegram-bot-api складывает скачанные файлы в
`TELEGRAM_API_FILES_DIR/<bot_id>:<token>/<категория>/file_<id>.<ext>`
(`photos/`, `videos/`, `voice/`, `documents/`, …). Имя каталога — полный токен
(`<bot_id>:<secret>`); **не логировать** и **не коммитить**.

`services/media_download.local_file_path()` разрешает только **относительные**
пути под этим корнем (traversal-guard). Абсолютный путь/выход за корень → файл
читается через `bot.download` (облачный путь).

## Симптом «файл есть в БД, но не находится»

1. Аватары/медиа «отлетают» (`fetch failed`), в логах — относительный
   `photos/file_*.jpg`, которого нет на диске.
2. Причина: локальный Bot API вернул относительный `file_path` ДО того, как
   файл появился на диске (race), либо файл потерян при переезде/чистке.

## Что делать

1. **Диагностика:** `GET /api/status/media-health` → счётчики
   `db_media_rows/text_media_paths/files_on_disk/missing_on_disk/orphan_files`
   и примеры хвостов имён (`sample_missing`). Только числа/хвосты (R17).
   **D-4:** `db_media_rows` достоверен; `text_media_paths`/missing/orphan —
   эвристика по ТЕКСТУ сообщений (`reliable=false`, `basis='text_scan'`), т.к.
   реальные `file_path` в схеме не персистятся. Результат TTL-кэшируется (120с).
2. **Автолечение (штатно):** аватары и медиа уже используют локальный fallback
   (`services/media_download.read_local_file_bytes`, 3 ретрая по 1с); при
   отсутствии файла — `bot.download` (перекачает и закеширует на диск).
3. **Bounded-восстановление:** `services/media_integrity.restore_missing_files`
   **убран из публичного API** (не имел call-site и маппинга `path→file_id`) —
   перенесён в `backlog.md`; включать только при появлении персистентного
   маппинга медиа.
4. **Ручная проверка:** сверить содержимое каталога Bot API с хвостами из
   `sample_missing`; недостающие файлы перекачать повторным обращением (кэш
   аватаров/медиа сам обновит).

## Инварианты

- `media/` и `.env` не трогаются; записи БД **не удаляются** (только
  диагностика).
- Логи: только имя файла/`file_id`/тип исключения/числа; полный путь с токеном —
  никогда (R17).
