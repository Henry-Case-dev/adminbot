# ADR-1024-11 — Реальный data-binding алиасов + живое доказательство (F10)

> **Статус:** proposed → применяется в раунде 10.24.
> **RE-OPEN / AMEND:** 10.22 F2 «Починили рендер JSON-словаря» — отчёт признан **ложным** (UPD2 п.8).
> **Слой:** web (data-binding) + обязательный read-only diagnostic. Δ DDL = 0, Δ каталога = 0.

## Контекст

Поле «Словарь алиасов имён» (`limits.summary_aliases`, `widget=keyvalue`) в TMA
(вкладка «ИИ» → «Имена») у владельца **пустое**, хотя в 10.22 был отчёт «починили
рендер JSON-словаря». Значит, фикс 10.22 был **ложным закрытием**.

Разбор причин (с доказательствами из кода и документации Vue):

1. **Тесты 10.22 не проверяли реальный рендер.** `tests/js/round1022_aliases_test.js`
   вызывал `kv.methods.sync.call(ctx)` вручную — вне реактивного монтирования.
   `tests/test_aliases_render_round1022.py` проверял только `_ensure_keyvalue_object`
   и cache-bust. Ни один тест не монтировал `kv-editor` и не проверял DOM.
2. **Vue 3: `props` — `shallowReactive`, а не `reactive`.** `watch: { 'item.value': … }`
   на prop-объекте не является deep-watch; при замене `this.configItems` в `loadConfig`
   (новый массив/новые объекты) watcher path-bound к старому пути может не сработать.
   Это подтверждено официально: vuejs.org «Watchers» (shallow по умолчанию для
   getter-возвращающего-объект) и vuejs/core #9965 (изменение поведения shallowReactive
   props). Компонент не перемонтируется (нет `:key`) → `created()`-`sync()` выполняется
   один раз со значением, которое могло быть не финальным.
3. **Формы значения/двойное кодирование** — уже обрабатывались backend'ом
   (`_ensure_keyvalue_object`) и `sync()`, поэтому это не единственная причина; но
   без live-фактов нельзя утверждать, что данные вообще не пусты.

Проблема методологическая: **нельзя доказать UI-фикс юнит-тестом функции `sync()`.**
Нужны (а) живое доказательство состояния БД/API и (б) render-тест компонента.

## Решение

### D1. Сначала факты, потом фикс (диагностика обязательна)

Добавляем read-only диагностический шаг (CLI/защищённый вывод), который фиксирует:
global-значение (`bot_settings`), per-chat override, форму и форму ответа
`GET /api/config` (`value`/`global_value`/`widget`/`chat_source`). Значения
обезличиваются (R17). **Restore из бэкапа запрещён.**

Ветвление: данные есть → чиним binding; данных нет → это Empty State/сид, а не
binding-баг (и это фиксируется как факт).

### D2. Надёжная реактивность KV-редактора

- `watch` по самому `item` с `deep: true, immediate: true` (или геттер значения с deep),
  а не по строковому пути prop-а.
- `:key` на компоненте, зависящий от версии значения (`configVersion`/сериализация),
  чтобы reload перемонтировал редактор.
- `sync()` расширяем на массив пар `[[k,v]]`; безопасный fallback остаётся.

### D3. Эффективное значение + источник

Показываем chat override, если он есть, иначе global; добавляем индикатор
«значение чата»/«глобально» через `chat_source`/`global_value`. Это устраняет класс
жалоб «данные есть, а поле пустое из-за слоя overrides».

### D4. Доказательство приёмки

Обязательный **render-тест** компонента (монтирование + проверка DOM) и **живая
TMA-приёмка** на прод-данных (cache-bust). Закрытие — только при наличии D1-фактов
и D4-доказательства.

### D5. Kill-switch

`ALIASES_KEYSVALUE_RENDER_ENABLED` (env-only, default ON) через `ui_flags`.

## Последствия

**Плюсы:** закрывается реальная причина (реактивность prop + отсутствие render-теста),
а не симптом; вводится доказательная дисциплина (факты БД + live), убивающая повтор
ложного отчёта; эффективное значение показывает реальную картину слоёв.
**Минусы/долг:** диагностический шаг — дополнительная работа @Builder; render-тест
требует аккуратной эмуляции DOM (в репо уже есть harness `tests/js/vue_mount_test.js`).
**Инварианты:** read-only диагностика не нарушает `imported-history-immutable`;
секреты не логируются (R17).

## Альтернативы

| Альтернатива | Почему отклонена |
|---|---|
| Просто «ещё раз поправить `sync()`» | не лечит prop-реактивность; риск третьего ложного закрытия |
| Переписать KV-редактор на прямое `v-model` по `item.value` | крупный рефактор; больше риск, чем точечный `watch`+`:key` |
| Проверить только тестом функции (как 10.22) | доказано недостаточно |
| Восстановить из бэкапа «чтобы точно были данные» | прямо запрещено; перезапишет свежие данные |
| Диагностика через запись/мутацию | нарушает read-only/immutability-инварианты |
