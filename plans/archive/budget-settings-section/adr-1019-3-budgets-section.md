# ADR-1019-3 — Раздел «Бюджеты»: отдельная config-вкладка для обоих контуров, per-chat безлимит, честная «Сводка»

- **Статус:** **Accepted / Implemented** (Step 2 @Architect, раунд 10.19; **итерация 2 — UPD3, 15.09.2026**; Step 4 @Builder, 16.09.2026). **Δ каталога санкционирован владельцем (UPD3 п.5)** и реализован: `437/92/407/412/90/20`.
- **Дата:** 2026-09-15
- **Раунд:** 10.19, фича F3 `budget-settings-section` (T-1799) + итерация 2 (T-1853)
- **База:** HEAD `fd6acc7`. **Связано:** F2/ADR-1019-2 (механизм безлимита), **ADR-1019-8** (мультичатовость, sentinel-таблица, сид настроек чатов, Сводка-контракт), ADR-1018-6 (nav-разметка/TAB_RULES), ADR-1018-7 (резолв настроек), F-7 §5.2/F-10 §5.2.
- **AMEND:** расширяет каталог-контракт раунда 10.19 (2 новые группы + новая вкладка + 1 новый ключ); не меняет семантику существующих ключей. **AMEND (итерация 2):** D2/D3/D4/D6/D7 пересмотрены под UPD3 (мультичатовость, retention-поле, guard, консервативные дефолты, расширенный контракт `limits`). **Дополняет** ADR-1018-6 (nav/TAB_RULES-инварианты сохраняются, чисел становится больше).

## Context

1. Владелец (UPD2 п.1): «Настройки по бюджетам в миниаппе я вообще их не вижу, почему их нет? Нужен отдельный раздел в Модулях… проследи, что в Сводке бары показывают актуальную информацию».
2. `limits.chat_global_key_budget_*` лежат в группе `limits_chat` («Прямой чат: контекст», `param_catalog.py:220-221,1232-1240`) — рядом с десятками ключей контекста; `limits.worker_daily_*` — в `limits_worker` на вкладке «Диагностика» (`:1244-1267`). Бюджеты рассеяны и невидимы.
3. «Сводка» (`oversight.py:193-215`) показывает **только worker-контур**; поэтому в момент sandbox-срабатывания (direct-контур) владелец видит «лимиты далеки от исчерпания» — **ложная картина**.
4. Механизм безлимита даёт F2 (sentinel `−1`, per-chat резолв); UI-тумблер без механизма невозможен → жёсткая зависимость F2 → F3.
5. Инварианты: R16 (аддитивность API), R17, пин-тесты каталога, JS-parity `CONFIG_TAB_TITLES ↔ TABS[].label` (ADR-1018-6 D3), `TAB_NAV` исчерпывающ (D2).

## Decision

### D1. Отдельная config-вкладка `mod_budgets` («Бюджеты») в nav «Модули»
`TAB_MOD_BUDGETS = "mod_budgets"`; `CONFIG_TAB_TITLES[TAB_MOD_BUDGETS] = "Бюджеты"`; `TAB_RULES[TAB_MOD_BUDGETS] = ((CATEGORY_LIMITS, frozenset({"limits_chat_key", "limits_chat_context", "limits_worker"})),)`; `TAB_NAV[TAB_MOD_BUDGETS] = NAV_MODULES`. Оба контура + лимит контекста — в одном разделе; `limits_worker` переезжает из «Диагностики».

### D2. Две новые группы — бюджеты ключа и лимит контекста выведены из `limits_chat`
`GroupSpec("limits_chat_key", "limits", "Бюджет ключа чата", "…", 29)` — `CHAT_GLOBAL_KEY_BUDGET_TOKENS/REQUESTS` из `limits_chat`.
`GroupSpec("limits_chat_context", "limits", "Лимит контекста (чат)", "…", 30)` — `CHAT_GLOBAL_CONTEXT_MAX_TOKENS`, `CHAT_THREAD_MAX_TOKENS` из `limits_chat` + `CHAT_CONTEXT_BUDGET_TOKENS` из `limits_chat_budgets` (в группе остаются только доли `CHAT_BUDGET_*_RATIO`). Причина: ключи не находимы в «Прямом чате»; перенос **не** меняет значения/семантику — только группу.

### D3. Каталог-Δ (точный, итерация 2)
`GROUPS 90 → 92` (+`limits_chat_key`, +`limits_chat_context`); `mapped 88 → 90`; `TAB_RULES = CONFIG_TAB_TITLES 19 → 20`; `TAB_NAV 19 → 20`; **`REGISTRY 436 → 437`, `Settings 406 → 407`, `categorized 411 → 412`** (+1 `IMPORT_HISTORY_RETENTION_DAYS`, группа `limits_memory`). Итог: **437/92/407/412/90/20**. Пин-тесты и JS-parity обновляются синхронно (прецедент ADR-1018-6 D3). **Санкция получена (UPD3 п.5).**

### D4. Тумблер «Безлимит по чату» — без новой REGISTRY-записи
Тумблер пишет **существующие** per-chat ключи (механизм F2): direct — `limits.chat_global_key_budget_requests/tokens = −1`; фон — `limits.worker_daily_llm_calls_per_chat`/`_tokens_per_chat = −1`; контекст — `limits.chat_global_context_max_tokens`/`…_thread_…`/`…_context_budget_… = −1`. OFF — возврат прежних чисел (или снятие override). Новых параметров не вводится.

### D5. `worker_budget` — per-chat + sentinel (доведение механизма F2 на фон-контур)
`_metric_limit(scope='chat:<id>', …)` резолвится per-chat через `resolve_setting_cached`; `limit < 0` → безлимит; `limit == 0` → запрет фонового расхода для чата; `scope='global'` — **без изменений** (глобальный предохранитель процесса). Изоляция контуров сохраняется: меняются только per-chat/фон-ветки. `get_usage`/`get_day_summary` аддитивно отдают `unlimited`/`forbidden`/`source`.

### D6. «Сводка» — оба контура + контекст + хранение, аддитивно (R16)
`build_summary` карточка чата: существующий `budget.worker.{calls,tokens}` **сохраняется**; добавляется **новый** ключ `limits` = `{key_budget, worker_budget, context, storage}` (точный контракт — spec F3 §4.2). Метрика: `{used, limit, unlimited, forbidden, source}`; CAP: `{limit, unlimited, source}`; storage: `{import_retention_days, import_forever, source, label}`. Фронт: `unlimited` → «Безлимит (∞)», `forbidden` → «Запрещено», storage → «Импорт: Вечно»/«Импорт: N дней». Существующие поля не удаляются.

### D7. Дефолты (итерация 2 — умеренные, UPD3 п.5)
Direct: **100** вызовов / **500 000** токенов (не 300/1,5M). Фон per-chat: **60** вызовов / **300 000** токенов (не 120/500k). Глобальные фон-лимиты 200/500k — не меняются. Безлимит — **только per-chat** (сид настроек чатов). Обоснование — ADR-1019-8 §D7.

### D8. Человекочитаемое объяснение «фон vs интеллект» — часть раздела
В разделе — блок «Как это работает» (текст из spec §4.5): два контура трат, почему **глобальные значения умеренные**, что значат `0`/`−1`/«безлимит» (по семействам), что происходит при исчерпании, что значит «Импорт: Вечно». Каталог-Δ от текста помощи **не** растёт.

### D9. Feature flag не вводится
Раздел/тумблер — видимость и настройка существующих значений; откат — `git revert` (+ возврат каталога). Progressive delivery — по данным (тестовый чат → прод).

### D10. Целевой чат — эксклюзивные значения **сидом**, не хардкодом (UPD3 п.3)
`-1002661910336`: retention `0` (вечно), бюджеты ключа/чата `−1`, фон `−1`, контекст `−1` (максимум) — через `services/chat_settings_seed.py` + `config/chat_settings_seed.json` (идемпотентно, `bot.py main()`). Id — только в сиде/тестах. Guard: `retention==0` → purge импорта **жёстко запрещён** (`services/retention_policy.py` + allow-list в `purge_imported_history`). Полный механизм — **ADR-1019-8 §D4/D5**.

### D11. Изоляция памяти (UPD3 п.2)
Лимитный/UI-слой F3 строго per-chat (кэш/резолв/запись/Сводка). Аудит памяти (импорт/RAG/кэши/эмбеддинги) и исправления — **F7 §4.6 / ADR-1019-8 §D5-аудит**.

## Consequences

**Positive**
- Владелец видит и управляет обоими контурами; «безлимит» доступен одним тумблером без хардкода.
- «Сводка» перестаёт вводить в заблуждение: direct и фон показаны раздельно.
- Понятное объяснение снижает риск неверных ожиданий («почему бот ушёл в заглушку»).
- Механизм без новым REGISTRY-ключей — минимальный каталог-Δ.

**Negative**
- Каталог-инвариант растёт (+1 группа, +1 вкладка) — требует санкции и синхронного обновления пин-/JS-parity-тестов.
- Тумблер пишет 4 per-chat ключа; частичный сбой (например, фон не обновлён) требует честного отображения состояния (читать фактическое значение, не предположение).
- `worker_budget` меняется в per-chat/фон-ветках — нужен регресс-тест изоляции (что global-лимиты не задеты).
- Расход при повышенных дефолтах выше (осознанно, см. объяснение).

## Alternatives

- **A1. Δ=0: собрать раздел только из `limits_worker` (+ существующая группа `limits_chat`).** Отклонено: `limits_chat` тянет десятки контекстных ключей, раздел «Бюджеты» превращается в «Прямой чат»; direct-контур не выделен.
- **A2. Новый ключ-флаг `flags.chat_key_unlimited` (REGISTRY +1).** Отклонено: дублирует sentinel F2, лишний Δ.
- **A3. Отдельный React/Vue-компонент бюджета.** Отклонено: в проекте generic-рендер каталога; новый компонент = лишний код и риск CSP.
- **A4. Новый API-эндпоинт только для бюджетов.** Отклонено: `build_summary` уже агрегатор; аддитивные поля достаточно (R16).
- **A5. Показывать бюджеты в «Диагностике».** Отклонено владельцем (просил отдельный раздел в «Модулях»).
- **A6. Менять глобальные лимиты фон-контура под безлимит чата.** Отклонено: глобальный предохранитель защищает процесс целиком.
