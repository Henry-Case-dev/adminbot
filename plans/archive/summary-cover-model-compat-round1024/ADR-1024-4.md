# ADR-1024-4 — Универсальный payload изображений (без hardcode-карты) + кнопка «Проверить подключение»

- **Статус:** **Accepted** (Step 2 @Architect, часть 1/2 раунда 10.24, 19.09.2026). **AMEND ADR-1023-5 D1/D5, ADR-1023-6 §2/§3.2.**
- **Фича:** F12 `summary-cover-model-compat-round1024`
- **Тип:** backend (image/summary) + логирование + API теста
- **Связано:** ADR-1023-5 (image-тул/Pollinations), ADR-1023-6 (обложка Article), ADR-1024-1 (лог тела ошибки), `round1024-architecture.md` §3.3/§3.4
- **Задачи:** T-2279…T-2288

## Context

1. Обложка саммари не генерируется для `gptimage`, но работает для `flux`; в Прямом чате «нарисуй» с `gptimage` работает (UPD2 п.10). Причина — жёстко зашитые поля запроса в `services/image_generation.py`: `size:"1024x1024"` (`:62,262`) и `response_format:"url"` (`:263`), которые часть моделей/провайдеров отвергает. Ошибка скрыта «тихим откатом» на текст.
2. Веб-ресёрч (см. §References): у Pollinations `POST /v1/images/generations` **required только `prompt`**; `model/n/size/quality/response_format` опциональны; default `response_format` = **`b64_json`**; **community-модели поддерживают только `b64_json`**, `response_format:"url"` для них → HTTP 400. Сервер эмитит `width/height` только если caller передал `size`. У OpenAI GPT-image моделей `response_format` не поддерживается вообще.
3. `compose_cover_image_prompt` (`services/summary_generator.py:101-105`) конкатенирует `style + cover_prompt` и обрезает жёстким капом `COVER_IMAGE_PROMPT_MAX=300`; при длинном/расположенном в конце стиле инструкция (напр. «PERMsoc») может быть обрезана — UPD2 п.10.1.
4. Владелец (UPD3 п.8): **не делать hardcode-карту `модель→параметры`**; payload строго по OpenAI-стандарту; убрать поля, ломающие совместимость; обложка с любой моделью; **кнопка «Проверить подключение»** с тостом (успех или сырой текст ошибки).
5. Ошибки провайдера сейчас не видны (F2 добавляет тело в лог).

## Decision

### D1. Минимальный универсальный payload (AMEND ADR-1023-5 D1)
- POST-тело: **`{prompt, model, n:1}`** — только стандартные поля. **Убираем `size`, `response_format`, `quality`** из тела полностью (никакой capability-map).
- Ответ принимаем в обоих формах: `data[0].url` (скачиваем) **и** `data[0].b64_json` (декодируем) — уже поддерживается как defensive-fallback (`_generate_post`), теперь это **основной** путь совместимости.
- GET-режим (`_generate_get`) не трогаем по совместимости контракта Pollinations (width/height/seed — параметры GET-эндпоинта); он остаётся альтернативным режимом.
- Kill-switch `IMAGE_MODEL_COMPAT_ENABLED` (env-only, default ON; область — **вся** генерация изображений, т.к. тело POST общее для обложки/tool/пре-гейта — L1 review iter1); OFF → прежнее тело (byte-identical, для отката).
- Δ каталога = 0, Δ DDL = 0.

### D2. Универсальный кап промпта с сохранением стиля (AMEND ADR-1023-6 §2)
- Ввести `SUMMARY_COVER_PROMPT_MAX_CHARS` (env-only, default **1000** — в пределах лимитов моделей) и отдельный `SUMMARY_COVER_STYLE_MAX_CHARS` (default **500**).
- Композиция: **стиль сохраняется целиком** (до своего капа), visual-промпт догоняет до общего капа; при нехватке места режется **visual**, а не стиль (инструкция владельца типа «PERMsoc» должна доходить до модели).
- Лог `style_present`/`style_len`/`visual_len`/`final_len` (R17-safe, без полного текста) — доказательство подмешивания (UPD2 п.10.1).

### D3. Кнопка «Проверить подключение» (probe)
- Новый административный эндпоинт `POST /api/images/test` (RBAC: глобальный админ), тело `{prompt?}` (default тестовый промпт).
- Реализация — `image_generation.probe(...) -> ProbeResult`:
  - `{ok, status_code, reason, body_excerpt, latency_ms, model, mode}`;
  - идёт тем же универсальным путём, что и генерация, но **не отправляет в Telegram** и **не расходует per-chat бюджет** (диагностика админа; rate-limit, напр. ≤1/10с);
  - `body_excerpt` — сырой текст ошибки провайдера, **усечённый и обезвреженный** через `external_log.safe_text` (R17), ключ никогда не возвращается.
- Фронт (Часть 2): кнопка в карточке изображений → тост «успех» или сырой (безопасный) текст ошибки.
- Логирование через F2 (`log_external_api`).

### D4. Наблюдаемость «тихий откат ≠ тишина»
- `summary_generator._deliver_rich`: при `generate_image → None` — `log_external_api`/`trace_step` с реальной причиной (статус/тело/модель), а не только «image unavailable».
- `image_generation.generate()`: тело ошибки провайдера в лог через F2.

## Consequences

**Positive**
- Обложка генерируется с любой OpenAI-совместимой моделью (`gptimage`, `ideogram`, `flux`) без карты возможностей.
- Убран источник 400 (`size`/`response_format`) — устранена модель-зависимость.
- Владелец может сам проверить подключение и увидеть сырую (безопасную) причину в тосте.
- Доказано, доходит ли `prompts.summary_cover_style` до модели (лог + probe).
- Δ DDL = 0, Δ каталога = 0.

**Negative**
- Отказ от `size` → размер задаёт дефолт модели (для обложки приемлемо; единообразие не критично).
- Отказ от `response_format:"url"` → возможна передача base64 (чуть больший payload/декодирование) — уже поддерживается.
- Probe — отдельный админ-эндпоинт (нужен rate-limit/логирование).

## Alternatives

- **A1. Capability-map «модель → параметры»** — **отклонено владельцем** (UPD3 п.8): провайдер может быть любой.
- **A2. Передавать `size` только «поддерживающим» моделям** — **отклонено**: тот же hardcode-подход.
- **A3. Оставить `response_format:"url"`** — **отклонено**: community-модели дают 400; универсальность требует опустить.
- **A4. Усекать стиль вместе с visual (как раньше)** — **отклонено**: инструкция стиля теряется (п.10.1).
- **A5. Тест-кнопка без реального вызова (dry-run)** — **отклонено**: владелец просит сырой текст ошибки реального подключения.
- **A6. Возвращать полный `resp.text` в тост** — **отклонено**: R17; возвращаем усечённый/обезвреженный.
