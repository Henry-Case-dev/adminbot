### 0.1. Факт-расхождения с ТЗ

- ТЗ: «откройте React/Vue компонент, отвечающий за модальное окно «Справка»». **React в проекте
  нет**; контент — **код-канон** `DEFAULT_INFO_TEXT` (Python) + PG `content.info_how_it_works`,
  рендер — Vue-шаблон `web/index.html:2592`. Правка выполняется в `services/info_service.py`,
  синхронизируется в `info_text.md` и PG-миграцией.
- Текущая вёрстка использует `<h1>/<h2>/<h5>/<h4><b><i>` и команды inline. Правила ТЗ (только
  `<h1>`/`<h2>`, команды в `<blockquote>`, без точек/запятых/«или» между примерами) означают
  **полную переписку** текстовых секций, а не правку блока.

### 0.2. Санитайзер

`sanitizeHtml` = `DOMPurify.sanitize(raw)` с дефолтной конфигурацией → `<blockquote>`, `<h1>`,
`<h2>` **разрешены** по умолчанию. Отдельный allowlist, вероятно, **не нужен**; обязательна
проверка реального рендера (blockquote визуально выделен) и CSS `.info-html`.

## 1. Цель

Полностью переписать Справку по строгим правилам вёрстки, объяснить разницу «транскрипт vs
выжимка», удалить п.11 «Безлимиты», добавить блок «Как бот думает (System 2)», бампнуть канон
v3 → v4 со слепком и байт-тестом.

## 2. Архитектура / контент

### 2.1. Правила вёрстки (жёсткие)

1. Между примерами команд — **никаких точек, запятых, союза «или»**.
2. Каждая команда-вызов — в `<blockquote>` (в UI — выделенная цитата/код).
3. Только `<h1>` для главных разделов и `<h2>` для подразделов. Иные теги заголовков (`h3`–`h5`)
   в каноне не использовать.
4. Сохранить дерзкий ироничный стиль канона (прецедент 10.20/БЛОК 8).

### 2.2. Обязательный состав

- **Транскрипт vs выжимка (КРИТИЧНО):**
  - Дословное распознавание: `<blockquote>Бот, транскрипт</blockquote>` — дословный текст
    (голосовые, кружки, видео с YouTube).
  - Смысловая выжимка: `<blockquote>Бот, поясни за видос</blockquote>`
    `<blockquote>Бот, о чем видео</blockquote>` — суммаризация (бот пересказывает суть).
- **Удалить п.11 «Безлимиты»** (`info_service.py:209-214`).
- **Блок «Как бот думает (System 2)»** в «Гайд по возможностям»: кратко и понятно описать новый
  двухэтапный пайплайн (сначала бот разбирается и отсеивает мусор, затем формулирует ответ),
  **без деталей реализации**; упомянуть естественность/отсутствие штампов — **без** деталей
  validator-loop и без преждевременных обещаний (F3–F5 ещё в работе).

### 2.3. Канон-миграция (D224 + ADR-1013-3)

1. Новый `DEFAULT_INFO_TEXT` (v4).
2. `INFO_CANON_VERSION` **3 → 4** (`:225`).
3. Прежний v3-текст → новый слепок `PREV_R1022_DEFAULT_INFO_TEXT` в `KNOWN_INFO_SNAPSHOTS`.
4. Синхронизировать `info_text.md` (корень) — **байт-в-байт** с `DEFAULT_INFO_TEXT`.
5. Идемпотентная PG-миграция `content.info_how_it_works` (известный v3-слепок → v4; неизвестный
   прод-текст → force-delivery с `prev_html`, как в ADR-1016-3).
6. Байт-тест + тест миграции v3→v4.

### 2.4. Рендер/санитайзер

- Проверить `sanitizedInfoHtml` (DOMPurify) на `<blockquote>`/`<h1>`/`<h2>`; при необходимости —
  CSS `.info-html blockquote` (рамка/сдвиг) в `web/index.html`/`app.css`.
- Убедиться, что редактируемый текст превью/санитайз не режет blockquote (R2).

## 3. Контракты

- `DEFAULT_INFO_TEXT` (v4) ↔ `info_text.md` ↔ PG `content.info_how_it_works`: байт-синхрон (D224).
- `/api/info` отдаёт `canon_version=4`, `canon_drift` вычисляется по нормализованному сравнению.
- Структура вкладок/меню **не меняется** (инвариант).

## 4. Feature Flags / Progressive Delivery

- Флагов нет. Δ каталога = **0** (версия канона — не ключ `param_catalog`).
- Ступень: **F2 → F7** (общий `web/**`); текстово — после F6 и ADR F3/F4/F5.

## 5. Kill-switch / fallback / откат

- Kill-switch: `POST /api/info/reset-canon` (RBAC `edit_info`) откатывает к канону.
- Fallback: при ошибке миграции прод-текст не затирается (сохраняется `prev_html`).
- Откат: `git revert` + обратная канон-миграция (вернуть `INFO_CANON_VERSION=3` и v3-текст).

## 6. Стоимость / латентность

Не применимо (контент + миграция PG, одноразово).
