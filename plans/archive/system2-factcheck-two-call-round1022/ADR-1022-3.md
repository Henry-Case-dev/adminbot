# ADR-1022-3 — Фактчек: физический конвейер Аналитик (JSON) → Вербализатор

- **Статус:** **Accepted** — решение владельца UPD3 (18.09.2026); уточнено Step 2b @Architect (18.09.2026)
- **Фича:** F3 `system2-factcheck-two-call-round1022`
- **Тип:** backend/LLM + канон промптов
- **Связано:** ADR-1021-2 (grounding + CoVe), ADR-1021-3 (де-роботизация), ADR-1013-3 (канон-миграции), ADR-1020-7 (strip reasoning), F6 (chokepoint + validator-loop)

## Context

Сейчас фактчек — один вызов с CoVe-черновиком в `<reasoning>` внутри того же промпта
(`factcheck_prompts.py:123-130`, `factcheck_service.py:55-157`). Проблема ТЗ: сырые системные
теги (`fact:12723`) протекают в ответ; `<thought>` внутри одного промпта — костыль. Требуется
физическая изоляция вербализатора от базы/тегов и перевод ID/дат в человеческое время.

Аудит: grounding уже строгий (`collect_allowed_anchors`/`strip_phantom_tags`, S10.21-4/-5),
cleanup — единый (`reply_postprocess.strip_reasoning_tags`), фактчек имеет Full Tool Access
(`factcheck_service.py:98-118`).

## Decision

1. **Два независимых вызова.**
   - **Stage 1 (Аналитик):** вход — `target_text`/`user_hint`/`forward_source`/`chat_context`
     + RAG + выдача поиска + `tool_context` (tool-loop сохраняется как Stage-1). Выход —
     **строгий JSON** (Chain Handoff Spec §2.2 spec). Аналитик переводит `fact:ID`/`ММ.ГГГГ` в
     человеческое время.
   - **Stage 2 (Вербализатор):** вход — **только** валидированный JSON. Ни RAG, ни инструментов,
     ни якорей, ни черновиков. Выход — финальный текст.
2. **Строгий парсер + fallback:** невалидный/усечённый JSON → одиночный путь 10.21 (не
   галлюцинировать). Kill-switch `SYSTEM2_FACTCHECK_ENABLED` (env-only `ClassVar`, default ON,
   Δ каталога = 0).
3. **Grounding переносится, а не удаляется:** `strip_phantom_tags` на выход Stage-1 (до парсинга)
   и на выход Stage-2; якоря — те же доверенные (`<claim>`/`<user_hint>` исключены).
4. **AMENDS 10.21:** `<reasoning>`-CoVe как единственный механизм заменяется физическим
   конвейером; слепки `PREV_*_R1021` сохраняются; канон-миграция атомарна (ADR-1013-3).
5. **Chokepoint F6** остаётся последней egress-сеткой (не замена изоляции).
6. **Validator Loop (UPD3 §3):** Stage-2 вызывается через
   `services/negative_constraints.verbalize_validated` (`max_retries=2`); при клише ответ
   бракуется и перегенерируется тем же Вербализатором; после исчерпания — fallback на 10.21.
   Клише **не** вырезаются кодом (вето владельца); scrubber режет только теги.

## Consequences

- Утечка `fact:\d+`/`msg:\d+` из вербализатора становится архитектурно невозможной (Stage-2
  физически не видит ID); regex-предохранитель — defense-in-depth.
- Стоимость ≈ +1 LLM-вызов на фактчек; латентность растёт.
- Появляется контрактная обязанность: JSON-схема версионируется вместе с каноном.

## Alternatives

- **Оставить один вызов с `<thought>`** — отклонено ТЗ (костыль, утечки).
- **Второй вызов без строгого JSON (передавать «конспект» текстом»)** — отклонено: не
  даёт гарантии отсутствия тегов и не валидируется.
- **Regex-стрип без второго вызова** — отклонено: не устраняет утечку-источник, только маскирует.

## Cost ×2 / бюджет / латентность

+1 вызов (Stage-2); в tool-пути Stage-1 = существующий tool-loop. Бюджет — `limits.factcheck_max_symbols`,
таймауты per-stage. Латентность: +1 round-trip. Решение о приемлемости — Д-6.

## Kill-switch / Fallback / Rollback

- **Kill-switch:** `SYSTEM2_FACTCHECK_ENABLED=false` → одиночный путь 10.21 (байт-в-байт).
- **Fallback:** невалидный JSON / таймаут Stage-1 → 10.21; таймаут Stage-2 → 10.21.
- **Rollback:** флаг OFF / `git revert` + обратная канон-миграция.

## Canon migration

**Обязательна (ADR-1013-3):** `FACTCHECK_ANALYST_*` + `FACTCHECK_VERBALIZER_*` + новые
`PREV_*`-слепки + `PROMPT_MIGRATIONS` + `ROLLBACK_MIGRATIONS` + `plans/docs/canon/**` + тесты —
**одним атомарным коммитом**. `PREV_FACTCHECK_R1021_SYSTEM_PROMPT` сохраняется.

## Human Gate — ЗАКРЫТО владельцем (UPD3)

- **Д-5** → отдельные env-флаги, **default ON**, Δ каталога = 0 (в т.ч. `SYSTEM2_VALIDATOR_LOOP_ENABLED`).
- **Д-6** → ×2 стоимость/латентность **принята**.
- **Д-7** → fallback на 10.21 — **да** (в т.ч. после исчерпания validator-loop).



## Implementation (Шаг 4 @Builder, 18.09.2026)

Реализованы п.1–6 Decision. Stage-1 (Аналитик) сохраняет tool-loop и
grounding-якоря; Stage-2 физически изолирован (только JSON). Невалидный JSON и
исчерпание validator-loop → одиночный путь 10.21. Полный pytest 6876/0.
