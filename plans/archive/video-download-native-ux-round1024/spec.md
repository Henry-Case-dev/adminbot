## 1. Цель

Устранить баг A-3: при провале probe/скачивания нативного реплай-видео пользователь
получает бессмысленную и циничную реакцию — статус «⏳ Скачивание без выбора качества…»
(`handlers/video_download.py:456`) и общий пул `VD_ERROR_PHRASES` («че ты мне суешь? я не
могу это скачать», `tools/video_download_phrases.py:11-15`), **без объяснения причины**.

Дополнительные дефекты UX того же сценария:
1. Меню качества предлагается там, где оно **неприменимо** — у нативного реплай-видео
   файл уже существует, выбирать «качество скачивания» не из чего.
2. При наличии и живого видео, и ссылки (в т.ч. caption-URL реплай-видео) непонятно,
   что именно выбрал бот.

**Что должно стать:**
- провал probe/скачивания по ссылке → **понятная причинная** фраза (проверка бота / возраст /
  недоступность / сервис лёг / файл больше лимита / сервис не ответил), без сырых кодов/URL;
- нативный реплай-видео идёт **без меню качества** и без лживого статуса «Скачивание без
  выбора качества…»; неудача нативного пути → честная фраза «не смог переслать», а не «суешь»;
- при конфликте «видео + ссылка» — **предсказуемый приоритет** (нативное видео, инвариант F14)
  плюс **однострочное пояснение** с подсказкой, как запросить ссылку.

## 3. Требуемое поведение

### 3.1. Понятная причина probe/скачивания по ссылке (T-2308)

1. Ни одна **известная** причина не должна попадать в общий циничный `VD_ERROR_PHRASES`.
   Выбор пула — по таблице:

   | reason / класс | Пул фраз | Смысл для юзера |
   |---|---|---|
   | `probe_bot_check`, `ytdlp_bot_check` | `VD_UNAVAILABLE_PHRASES` | платформа требует проверку/вход в аккаунт |
   | `ytdlp_unavailable`, `ytdlp_drm` | `VD_UNAVAILABLE_PHRASES` | возраст/DRM/недоступность |
   | `cobalt_down` | `VD_SERVICE_DOWN_PHRASES` | сервис качалки лёг |
   | `direct_too_big`, `ytdlp_too_big`, `stream_too_big` | `VD_TOO_BIG_PHRASES` | файл больше лимита Telegram |
   | `probe_timeout`, `probe_failed`, `cobalt_timeout`, `cobalt_error`, `cobalt_unsupported`, `direct_*`, `tunnel_http`, `stream_failed`, `stream_timeout`, `ytdlp_failed`, `ytdlp_postprocess`, `invalid_quality` | `VD_PROBE_FAIL_PHRASES` | не удалось скачать по ссылке: сервис не ответил/ссылка битая |
   | прочее/неизвестное | `VD_ERROR_PHRASES` (residual) | без изменений |

2. Функция выбора (`_probe_error_phrase`/`_fallback_phrases`) реализует эту таблицу; порядок
   проверок: `too_big` → `bot_check`/`unavailable` → `service_down` → probe/link-fail → unknown.
3. Фраза **никогда** не содержит URL, `file_id`, локальных путей, `str(exc)` или raw reason-код
   (R17). В лог уходит только `error=<Class> reason=<code>` (F14).

### 3.2. Меню качества неприменимо к нативному реплай-видео (T-2309)

1. Нативный путь (`_handle_native_media`) **не вызывает** `_send_quality_menu`, не пишет `_PENDING`
   и не доходит до `_download_without_menu` — инвариант F14 native-first.
2. Текст «⏳ Скачивание без выбора качества…» используется **только** URL-fallback-веткой и
   остаётся честным для неё (скачивание внешнего файла без меню). На нативном пути он
   **недостижим** (гарантируется тестом T-2310 a).
3. Статус нативного пути — про **пересылку существующего файла**, без слова «качество»:
   `нативное видео: {mb} МБ, пересылаю...` (как сейчас, `:756-757`).

### 3.3. Конфликт «видео + ссылка» — предсказуемость и объяснение (T-2309)

1. Приоритет — **нативное видео** (не переворачиваем решение F14 ADR-1024-15 §2.2).
2. Если нативный путь выбран, а `_extract_urls` вернул ≥1 ссылку (своё сообщение / caption
   своего или реплай-сообщения) — показывается **однострочное пояснение-приоритет** перед
   статусом пересылки:
   - notice (пример): `беру видео из реплая, ссылку не трогаю (нужна именно ссылка — пришли её без реплая на видео)`;
   - если медиа взято из своего сообщения — формулировка про «видео из сообщения»;
   - **URL не цитируется**, только факт «ссылка есть, но выбрано видео».
3. Реализация без нового состояния: хендлер передаёт в `_handle_native_media` счётчик
   проигнорированных ссылок; notice добавляется в то же статус-сообщение (реплай на триггер).
4. Меню выбора «видео ↔ ссылка» **не вводится** (см. ADR §Альтернативы): низкая частота,
   лишний callback/pending и egress-поверхность; объяснения + подсказки достаточно.

### 3.4. Неудача нативного пути — понятная причина (T-2309)

1. `_handle_native_media` при не-`too_big` ошибке (`fetch_media_to_tmp`/`send_video`) отвечает
   пулом **`VD_NATIVE_FAIL_PHRASES`** («не смог переслать видео из реплая…»), а не циничным
   `VD_ERROR_PHRASES`.
2. Файл > 2 ГБ — по-прежнему `VD_TOO_BIG_PHRASES` (`:752-754`).
3. В лог — только класс исключения (R17), без file_id/temp-путей.

### 3.5. Разделение функций в UX (UPD5) — границы F15

Владелец закрепил разную семантику запросов; F15 **не размывает** её формулировками:

| Запрос пользователя | Функция | Путь | Владелец UX |
|---|---|---|---|
| «скачай / загрузи / стяни» | **скачивание/пересылка файла** | Fast-Track 4e (`handlers/video_download.py`) | **F15** |
| «что на видео» / «че за видос» / «о чем видео» | **выжимка** | 0e YouTube-summary (F16) или инструмент `summarize_video` (F14/F19) | F16/F14/F19 |
| «транскрипт» / «транскрибация» | **сырая транскрибация** (курсив) | 0e transcript (F16) или инструмент `transcribe_video` (F14/F19) | F16/F14/F19 |

- F15 отвечает **только** за UX ветки скачивания (меню качества, probe-причина, конфликт
  «видео + ссылка», неудача нативного fetch). Схемы инструментов и разделение
  `summarize_video`/`transcribe_video` — **F14 (контракт) → F19 (финал)** (ADR-1024-15 §2.3-bis);
  F15 их не трогает.
- **Запрет на смешение лексики:** фразы F15 не должны обещать «выжимку» или «транскрипт» — они
  говорят именно про **скачивание/пересылку** файла («не смог переслать видео», «нет ссылки на
  видео»). Слова «транскрипт»/«выжимка» в пулах F15 не используются, чтобы не конфликтовать с
  командами 0e и выбором инструмента LLM.
- `VD_NATIVE_PRIORITY_NOTICE` (конфликт «видео + ссылка») по-прежнему про выбор **источника
  файла**, а не про summary/transcript; подсказка «пришли ссылку без реплая на видео» остаётся.

## 4. Контракты

### 4.1. Пул фраз — `tools/video_download_phrases.py`

```python
# F14 создаёт; F15 финализирует формулировки (2–3 фразы).
VD_PROBE_FAIL_PHRASES: tuple[str, ...]   # probe_timeout/probe_failed + link-fail
# F15: новый пул — неудача нативного fetch/send (не too_big).
VD_NATIVE_FAIL_PHRASES: tuple[str, ...]  # 2–3 фразы
# F15: новый одиночный текст пояснения при конфликте «видео + ссылка».
VD_NATIVE_PRIORITY_NOTICE: str          # без URL/file_id, строчными, без markdown/эмодзи
```

Стиль-инварианты (как в существующих пулах, `test_smartmodule_phrases.py`): строчные,
без эмодзи, без markdown (`**`, `_`, `` ` ``), без плейсхолдеров, **disjoint** со всеми
существующими пулами (`VD_*`).

### 4.2. Выбор пула — `handlers/video_download.py`

```python
def _probe_error_phrase(reason: str) -> tuple[str, ...]: ...   # таблица §3.1
def _fallback_phrases(exc: Exception) -> tuple[str, ...]: ...  # класс → reason → пул
```

- Сигнатуры не меняются; расширяется только таблица ветвлений.
- `VD_ERROR_PHRASES` остаётся **residual** (неизвестная причина) — контент не трогаем
  (защита от регресса прочих вызовов).

### 4.3. Нативный путь — `handlers/video_download.py`

```python
async def _handle_native_media(
    bot, message, media, *, ignored_urls: int = 0) -> None:
    ...
```

- `ignored_urls` — число проигнорированных http(s)-ссылок (аддитивный keyword-only,
  дефолт 0 → вызовы F14 совместимы байт-в-байт).
- `ignored_urls > 0` и флаг ON → статус: `f"{VD_NATIVE_PRIORITY_NOTICE}\n{базовый_статус}"`.
- Ошибка (не `too_big`): флаг ON → `VD_NATIVE_FAIL_PHRASES`, иначе → `VD_ERROR_PHRASES`.
- Вызывающий код (F14) передаёт `ignored_urls=len(urls)` при native-first.

### 4.4. Флаг — `config/settings.py`

```python
VIDEO_DOWNLOAD_NATIVE_UX_ENABLED: ClassVar[bool] = _env_bool(
    "VIDEO_DOWNLOAD_NATIVE_UX_ENABLED", True)   # env-only, вне param_catalog
```

- Гейтит runtime-ветки F15: notice при конфликте, `VD_NATIVE_FAIL_PHRASES`, финальный
  статус нативного пути.
- Контент пулов — статические константы (не ветвятся флагом); их откат — `git revert`
  атомарного коммита F15 (прецедент bugfix-флагов раунда).
- `OFF` → поведение уровня F14: нативная неудача → `VD_ERROR_PHRASES`, notice не показывается,
  статус прежний.

## 6. Тесты (T-2310 + расширение)

- **(a)** Реплай «скачай» на нативное видео (в т.ч. с caption-URL) → вызван `_handle_native_media`,
  `_send_quality_menu` **не** вызывался, `_PENDING` пуст, в отправленных текстах нет
  «без выбора качества».
- **(b)** Parametrize по причинам (§3.1): каждый reason → ожидаемый пул; **ни один** известный
  reason не даёт `VD_ERROR_PHRASES`; `probe_timeout`/`probe_failed` → `VD_PROBE_FAIL_PHRASES`.
- **(c)** Видео + caption-URL → статус содержит `VD_NATIVE_PRIORITY_NOTICE`; `ignored_urls > 0`;
  текст **не** содержит URL/`http`.
- **(d)** **Канон-пулы:** `VD_PROBE_FAIL_PHRASES`, `VD_NATIVE_FAIL_PHRASES` disjoint между собой
  и со всеми `VD_*`; строчные, без эмодзи/markdown/плейсхолдеров.
- **(e)** Неудача нативного пути (не `too_big`) → `VD_NATIVE_FAIL_PHRASES`, не `VD_ERROR_PHRASES`;
  >2 ГБ → `VD_TOO_BIG_PHRASES`.
- **(f)** Флаг OFF → нативная неудача даёт `VD_ERROR_PHRASES`, notice отсутствует (совместимость с F14).
- **(g)** R17: caplog содержит `error=<Class> reason=<code>`, без URL/`file_id`/temp-путей;
  в исходящих текстах нет URL.
- **(h)** Egress: `handlers/video_download.py` остаётся в `SEND_ALLOWLIST`; `SEND_POINTS` не расширен.
- **(i)** **Разделение функций (UPD5):** ни один текст пулов/notice F15 не содержит подстрок
  «транскрипт»/«выжимк» (не конфликтуют с командами 0e и выбором инструмента F14); F15 не
  импортирует/не трогает `services/tool_schemas.py`/`services/tool_router.py`.
- Полный pytest — 0 failed; `git diff --check` чист; Δ DDL = 0; Δ каталога = 0.

## 8. Критерии приёмки

1. На реплай-видео меню качества **не** предлагается и статус «Скачивание без выбора качества…»
   **не** появляется.
2. При провале probe/скачивания по ссылке пользователь получает **понятную причину** из
   причинного пула; причина фиксируется в логе (класс + safe-reason).
3. При конфликте «видео + caption-URL» поведение предсказуемо (видео из реплая) и объяснено
   однострочным notice с подсказкой; URL в chat не цитируется.
4. Неудача нативного пути объясняется честной фразой (не «че ты мне суешь»).
5. Пулы фраз без пересечений; pytest 0 failed; `git diff --check` чист; **Δ DDL = 0**;
   **Δ каталога = 0**.

## 9. Флаг и раскатка

- **Флаг:** `VIDEO_DOWNLOAD_NATIVE_UX_ENABLED` — env-only `ClassVar` в `config/settings.py`,
  **default ON**, вне `param_catalog`.
- **ON:** новый UX (причинные фразы-ветки, notice конфликта, нативный пул).
- **OFF:** поведение уровня F14 (нативная неудача → `VD_ERROR_PHRASES`, без notice).
- Поэтапная раскатка internal→10%→50%→100% **не требуется** (прецедент 10.21–10.23);
  kill-switch достаточен.
- Флаг **не дублирует** `NATIVE_MEDIA_TOOLS_ENABLED` (F14, маршрутизация): F14 OFF → native-first
  выключен, F15 UX применяется к URL-пути независимо.

## 10. Откат

- Флаг OFF (runtime-ветки F15); либо `git revert` атомарного коммита F15 (возврат формулировок
  пулов/notice).
- **Δ DDL = 0**, Δ каталога = 0; `media/` и `.env` не трогаются; новых миграций/таблиц нет.

## 11. Инварианты (не нарушать)
