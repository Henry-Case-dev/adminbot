# ADR-1024-16 — UX нативного реплай-видео: причинные фразы, неприменимость меню качества, конфликт «видео + ссылка»

> **Статус:** Proposed (Step 2 @Architect, 19.09.2026). **Раунд:** 10.24. **Фича:** F15 `video-download-native-ux-round1024` (T-2307).
> **Тип:** AMEND — UX-контракт ошибок/качества поверх F14 (F14 `ADR-1024-15`).
> **Связано:** ADR-1016-1 (контракт скачивания, probe-fallback), ADR-1017-2 (качество в tool-пути, pending), ADR-1024-15 (приоритет нативного медиа, пул `VD_PROBE_FAIL_PHRASES`), ADR-1015-3 (tool_response — модель не «печатает» файл).
> **Границы:** F14 — маршрутизация/запись причины/пул-механизм; **F15 — только пользовательский UX**. F15 не меняет схемы инструментов и маршрутизацию.
> **R17/R18:** URL/`file_id`/секреты не цитируются; `current_task.md` untracked, не коммитить.

## 1. Контекст

Прод-баг UPD4-A-3: «Бот скачай видос» реплаем на **нативное TG-видео** завершается статусом
«⏳ Скачивание без выбора качества…» (`handlers/video_download.py:456`) и общей циничной фразой
`VD_ERROR_PHRASES` («че ты мне суешь? я не могу это скачать», `tools/video_download_phrases.py:11-15`),
**без объяснения причины**. Replied-видео — уже существующий файл, поэтому:
- меню качества к нему **неприменимо** (скачивать нечего, качество выбирать не из чего);
- формулировка «скачивание без выбора качества» вводит в заблуждение.

Дополнительно (после F14): при приоритете нативного видео над caption-URL
(`ADR-1024-15 §2.2`) пользователь не понимает, что ссылка из caption **осознанно
проигнорирована**, — нужен объясняющий UX, а не «тишина».

Первопричины дефекта и текущее состояние:
1. Провал probe/скачивания по ссылке маскируется общим пулом: `_probe_error_phrase`
   (`handlers/video_download.py:410-421`) для неизвестных причин возвращает `VD_ERROR_PHRASES`,
   а `_fallback_phrases` (`:424-436`) для многих `DownloadError.reason` тоже.
2. Нативный путь при не-`too_big` ошибке отвечает `VD_ERROR_PHRASES` (`:762-767`) — та же
   циничная отмазка.
3. Конфликт «видео + ссылка» не объясняется (F14 выбирает видео, но текстом это не выражено).

F14 (`ADR-1024-15`) вводит native-first маршрутизацию, пул `VD_PROBE_FAIL_PHRASES` (механизм)
и R17-safe запись причины в лог. Остаётся **пользовательский слой**: финализировать
формулировки, закрыть маппинг всех причин, дать нативный UX и пояснить конфликт.

## 2. Решение

### D1. Причинная таксономия «reason → пул» (AMEND ADR-1016-1 §2.4, ADR-1024-15 §2.4)

- Каждая **известная** причина провала probe/скачивания ведёт в смысловой пул:
  - `probe_bot_check`/`ytdlp_bot_check`, `ytdlp_unavailable`, `ytdlp_drm` → `VD_UNAVAILABLE_PHRASES`
    (проверка/вход/возраст/DRM);
  - `cobalt_down` → `VD_SERVICE_DOWN_PHRASES`;
  - `*_too_big` → `VD_TOO_BIG_PHRASES`;
  - `probe_timeout`, `probe_failed`, `cobalt_timeout`, `cobalt_error`, `cobalt_unsupported`,
    `direct_*`, `tunnel_http`, `stream_failed`, `stream_timeout`, `ytdlp_failed`,
    `ytdlp_postprocess`, `invalid_quality` → `VD_PROBE_FAIL_PHRASES` (сервис не ответил / ссылка
    не поддалась разбору).
- `VD_ERROR_PHRASES` становится **residual** только для неизвестных/неожиданных причин; его
  контент **не переписывается** (защита прочих call-site'ов: tool-путь, generic-ветки).
- Причина в чат как код/URL/`str(exc)` **не уходит** никогда (R17); в лог — `error=<Class>
  reason=<code>` (F14).

### D2. Меню качества неприменимо к нативному реплай-видео

- Нативный путь (`_handle_native_media`) не вызывает `_send_quality_menu`, не создаёт `_PENDING`
  и не доходит до `_download_without_menu` — инвариант native-first (F14). F15 это **фиксирует
  тестом**, а не меняет маршрутизацию.
- Текст «⏳ Скачивание без выбора качества…» остаётся только у URL-fallback и честен для него;
  на нативном пути статус — про **пересылку существующего файла** (`нативное видео: {mb} МБ,
  пересылаю...`), без слова «качество».

### D3. Неудача нативного пути → честный пул `VD_NATIVE_FAIL_PHRASES`

- `fetch_media_to_tmp`/`send_video` при не-`too_big` ошибке → новый пул `VD_NATIVE_FAIL_PHRASES`
  («не смог переслать видео из реплая…»), а не `VD_ERROR_PHRASES`.
- `> 2 ГБ` → существующий `VD_TOO_BIG_PHRASES` (без изменений).
- Новый пул — минимальный (2–3 фразы), disjoint со всеми `VD_*`, стиль существующих канонов.

### D4. Конфликт «видео + ссылка»: приоритет видео + объяснение (AMEND ADR-1024-15 §2.2)

- Приоритет **не переворачивается**: нативное видео выигрывает (решение F14).
- Если при выборе нативного пути `_extract_urls` вернул ≥1 ссылку (своё сообщение / caption
  своего или реплай-сообщения) — в то же статус-сообщение добавляется однострочный
  `VD_NATIVE_PRIORITY_NOTICE`: «беру видео из реплая/сообщения, ссылку не трогаю (нужна именно
  ссылка — пришли её без реплая на видео)».
- **URL не цитируется**; сообщается только факт выбора. Нового состояния/callback'а **нет**:
  `_handle_native_media(..., *, ignored_urls=0)` — аддитивный keyword-only параметр.
- Меню выбора «видео ↔ ссылка» **не вводится** (см. §4): низкая частота, лишний callback/pending
  и новая egress-поверхность; приоритет + подсказка достаточны.

### D5. Флаг и совместимость

- `VIDEO_DOWNLOAD_NATIVE_UX_ENABLED` — env-only `ClassVar` в `config/settings.py`,
  **default ON**, вне `param_catalog`. Гейтит runtime-ветки F15 (notice, `VD_NATIVE_FAIL_PHRASES`,
  финальный статус нативного пути). Контент пулов — статические константы; их откат —
  `git revert` атомарного коммита F15.
- Флаг **не дублирует** `NATIVE_MEDIA_TOOLS_ENABLED` (F14-маршрутизация).
- **Δ DDL = 0**; **Δ каталога = 0**; egress-реестр, `.env`, `media/` не трогаются.

## 3. Последствия

**Positive**
- Баг A-3 закрыт: провал объясняется человеческой причиной, а не циничной отмазкой; меню
  качества не вводит в заблуждение; конфликт «видео + ссылка» предсказуем и объяснён.
- Формулировки финализированы и покрыты канон-тестом непересечения пулов.
- Residual-пул `VD_ERROR_PHRASES` сохранён без правки → нет регресса прочих call-site'ов.

**Negative**
- Нативный UX зависит от F14-маршрутизации: при `NATIVE_MEDIA_TOOLS_ENABLED=OFF` симптом A-2
  вернётся (это осознанный backend-рубильник F14, вне F15).
- Появляется новая поверхность формулировок (2 новых текста/пула) — покрыта тестами (d).
- Статические строки пулов не откатываются флагом F15 — только `git revert` (прецедент bugfix).

- Инварианты: порядок роутеров `bot.py`, лимиты tool-loop (4/2), egress-реестры,
  `parse_mode=None`, `imported-history-immutable`, media-политика, Δ DDL=0, Δ каталога=0 —
  без изменений.

## 4. Рассмотренные альтернативы

| Вариант | Вердикт |
|---|---|
| Развернуть приоритет F14: ссылка побеждает видео / спросить пользователя меню-выбором | **Отклонён:** воспроизводит прод-симптом A-2/A-3, противоречит ADR-1024-15 §2.2 |
| Полноценное инлайн-меню «видео из реплая ↔ скачать ссылку» (`vdn:`) | **Отклонён:** новый callback/pending/TTL и egress-поверхность; низкая частота кейса; приоритет+подсказка решают задачу (граница «F15 = UX сообщений») |
| Отдельный пул на каждую причину (bot-check/age/drm/…) | **Отклонён:** размножение пулов; существующие `VD_UNAVAILABLE_PHRASES`/`VD_SERVICE_DOWN_PHRASES`/`VD_TOO_BIG_PHRASES` покрывают смысл (тезис ADR-1016-1 §3 «переиспользуем пулы») |
| Переписать `VD_ERROR_PHRASES` на вежливые формулировки | **Отклонён:** пул используется в tool/иных ветках — риск регресса; вместо этого маршрутизируем известные причины в честные пулы |
| Показать notice отдельным сообщением / в caption видео | **Отклонён:** лишний send-точка/шум; caption — метаданные медиа; заметка в статусе-реплае достаточно |
| Молчаливое видео без notice | **Отклонён:** требование владельца — «осмысленный UX при наличии видео и caption-URL» |
| Хранить выбор «видео/ссылка» в БД | **Отклонён:** Δ DDL, избыточно для UX-подсказки |
| Раньше (в F14) финализировать формулировки | **Отклонён:** границы фич — F14 отдаёт механизм/пул и лог, F15 — тексты/UX (см. задачи T-2303/T-2308) |
