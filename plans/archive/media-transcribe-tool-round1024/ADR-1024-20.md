# ADR-1024-20 — Разделение инструментов по функциям: выжимка (`summarize_video`) vs транскрибация (`transcribe_video`) + команда «транскрипт»

> **Статус:** Proposed (Step 2 @Architect, 20.09.2026, UPD5 №3). **Раунд:** 10.24. **Фича:** F19 `media-transcribe-tool-round1024` (T-2343).
> **Тип:** AMEND — ревизия канона инструментов (**R9: 9 → 10**), контракта `summarize_video` (удаление `mode`) и командного пути «транскрипт» (принудительный повтор ГС/кружка).
> **Связано:** ADR-1020-4 (канон инструментов R9), ADR-1015-3 (tool calling / `summarize_video` с `mode`), ADR-1020-7 (`tool_choice` не форсируется), ADR-1023-5 (`generate_image`, 9-й), **ADR-1024-15** (F14: контракт нативного источника + разделение функций), **ADR-1024-17** (F16: YouTube raw-транскрипт курсивом).
> **Границы:** F13 `native-reply-media-context-round1024` (эмиссия `ToolContext.native_media`), F14 `native-media-tools-round1024` (контракт + `native_media.py`), F16 `youtube-multimodal-download-fallback-round1024` (`handlers/youtube.py`).
> **R17/R18:** URL/`file_id`/секреты в тексте ADR не цитируются; `plans/current_task.md` untracked, в git не коммитится.
> **Спека:** `plans/features/media-transcribe-tool-round1024/spec.md`.

## 1. Контекст

Владелец (UPD5 №3) закрепил семантику функций, которую текущий tool calling не выражает:

- «Что на видео», «че за видос», «о чем видео» и подобные — запрос **выжимки** (саммаризации).
- «транскрипт» — запрос **сырой транскрибации**: принудительно повторить транскрибацию ГС/кружка, если авто не сработало, и то же — для любого видео; для YouTube отдать **голый транскрипт аудио курсивом**, как у ГС/кружков.

Проблемы статус-кво:

1. **Один инструмент на две функции.** `summarize_video` принимает `mode: summary|transcript` (`services/tool_schemas.py:123-147`). LLM выбирает не *функцию*, а параметр, и «что на видео» vs «транскрипт» ведут к одному инструменту — двусмысленность выбора и риск подмены выжимкой сырого текста (или наоборот).
2. **Команда «транскрипт» по ГС/кружку не форсирует повтор.** Триггер `транскрипт` есть в `command_registry.py:25` (группа `youtube`), но текстовая команда реплаем на `voice`/`video_note` проходит youtube 0e (`bot.py:766`) раньше direct_chat 0h (`:779`) и voice_transcription 0i (`:783`); `_classify_video_request` не находит видео-цель (`_resolve_video_media` намеренно **не** квалифицирует voice/video_note) и отдаёт нейтральную фразу. Принудительного повтора нет.
3. **Рассинхрон канона.** Комментарий-счётчик в `tool_schemas.py:241` описывает «7», фактически 9 (техдолг 10.23 **I2**).
4. **Контракт уже зафиксирован, но не реализован.** F14 (`ADR-1024-15` §2.1/§2.3-bis) зафиксировал: `summarize_video` = выжимка (`mode` удалён), `transcribe_video` = сырой текст (10-й), `url` необязателен + `source:["link","reply"]`, `ToolContext.native_media`. Финальную схему/dispatch/команду/счётчик вливает F19 поверх F14 (ступени **F14 → F19**, **F16 → F19**).

Это AMEND трёх канонов (R9, `summarize_video`-контракт, командный путь транскрипта) и требует явного ADR.

## 2. Решение

### 2.1. Канон инструментов R9 — **10** (AMEND ADR-1020-4 п.2.1)

- Порядок первых **9** — байт-в-байт (`query_chat_memory`, `dig_into_lore`, `execute_web_search`, `summarize_video`, `download_media`, `get_bot_health`, `get_recent_history`, `compile_lore_story`, `generate_image`); **10-й — `transcribe_video`** (в конец; канон-дисциплина «новое — в хвост»).
- `TOOL_CALLING_TOOLS` → `len == 10`; комментарий-счётчик в шапке модуля и у списка приводится к фактическому (закрывается техдолг 10.23 **I2**); синхронно актуализируется `plans/docs/canon/architecture.md` (секция `TOOL_SCHEMAS`).
- `active_tools`/`factcheck_tools` не меняют состав по существу: фактчекер видео-инструментов не получает (3 инструмента). `transcribe_video` включается в LLM-список только при флаге (см. §2.4).

### 2.2. Разделение функций: выжимка vs транскрибация (AMEND ADR-1015-3 / ADR-1024-15 §2.3-bis)

Ключ к выбору LLM — **однозначные EN-`description`** (полные схемы — spec §4.1/§4.2):

| Инструмент | Функция | Когда вызывать | Что вернуть |
|---|---|---|---|
| `summarize_video` | **выжимка** (конденсат) | «что на видео», «че за видос», «о чем видео», «перескажи/выжимка» | сжатый пересказ, **не** сырой транскрипт |
| `transcribe_video` | **транскрибация** (сырой текст) | явный «транскрипт»/«транскрибация», повтор транскрибации ГС/кружка/видео | дословный сырой транскрипт, **без** пересказа |

- `summarize_video`: параметр `mode` **удаляется** (инструмент однозначен); описание прямо сообщает, что сырой транскрипт — это другое.
- `transcribe_video`: описание требует вернуть текст **дословно** и запрещает сжимать/пересказывать.
- `tool_choice` **не форсируется** (канон ADR-1020-7 / backlog §16 п.2) — выбор за моделью.
- Источник (`url`/`source`) у обоих инструментов единый (контракт F14 §2.3): `url` необязателен, `source: enum["link","reply"]`; нативный источник резолвится из `ToolContext.native_media`, а не из текстового аргумента модели (file_id не восстановим из БД). Таймауты/лимиты tool-loop не меняются.

### 2.3. Команда «транскрипт»: принудительный повтор ГС/кружка + сырой транскрипт курсивом

- **ГС/кружок:** текстовая команда (`Бот, транскрипт` / `<Имя>, транскрипт`) **реплаем** на `voice`/`video_note` → форсированный повтор STT этого медиа (не полагается на авто-путь observer 0i), ответ — сырой текст **курсивом** в формате D268/D272, реплаем на целевое сообщение.
- **Любое видео:** YouTube-URL → субтитры (raw), при недоступности — download→STT, доставка курсивом; direct/platform → download→STT; нативное видео/документ → download→STT. Без изменений семантики, регресс-инвариант F16.
- **Размещение:** квалификация reply-voice добавляется в `handlers/youtube.py` (`_classify_video_request`, новый `kind="voice"`), т.к. youtube 0e обрабатывает текст **до** direct_chat 0h и voice_transcription 0i. Шаги транскрибации переиспользуются из `handlers/voice_transcription.py` (функция форс-повтора); порядок роутеров `bot.py` **не** сдвигается.
- Триггеры не расширяются — «транскрипт» уже в каноне (`command_registry.py:25`).

### 2.4. Флаг: схема безусловна, рантайм гейтится

- `MEDIA_TRANSCRIBE_TOOL_ENABLED` — env-only `ClassVar`, **default ON**, вне `param_catalog` (Δ каталога = 0).
- **Безусловно:** наличие `TOOL_TRANSCRIBE_VIDEO` и канон `TOOL_CALLING_TOOLS == 10` (JSON-схемы не гейтятся runtime-флагом — прецедент 8→9).
- **Гейтится:** включение `transcribe_video` в `active_tools` (LLM-доступность) и командный форс-повтор ГС/кружка. OFF → LLM видит 9 инструментов, «транскрипт» по ГС даёт прежний нейтральный ответ, авто-транскрибация и видео-команды — как до F19.
- Удаление `mode` у `summarize_video` — часть безусловной ревизии канона (UPD5), не гейтится.

### 2.5. Аддитивное расширение native-резолвера (координация F14 → F19)

- `services/native_media.py` (модуль F14) аддитивно расширяется: `NativeMedia.kind ∈ {"video","document","voice","video_note"}`, `resolve_reply_video` возвращает также voice/video_note.
- `transcribe_video` принимает все виды; `summarize_video`/`download_media` — только video/document (для voice — понятная ошибка, не исключение).
- Существующая квалификация video/document — байт-в-байт; расширение R16-аддитивно.

### 2.6. Egress и формат

- Egress-реестры **не расширяются**: инструмент `transcribe_video` возвращает **строку** (как query-инструменты); доставка курсива — командный путь через уже allowlisted `_send_transcript_reply` и `handlers/voice_transcription.py` (allowlist «ASR-транскрипт»).
- «Курсив» — **локальный** `parse_mode="HTML"`; глобальный `parse_mode=None` plain-каналов не трогается.
- **Δ DDL = 0**; `media/`/`.env` не трогаются.

## 3. Последствия

- (+) LLM выбирает функцию по однозначным EN-`description`; сырой транскрипт и пересказ больше не смешиваются (`mode`-двусмысленность устранена).
- (+) Команда «транскрипт» принудительно повторяет транскрибацию ГС/кружка (закрыт сценарий «авто не сработало») и отдаёт сырой транскрипт курсивом для любого видео, включая YouTube.
- (+) Канон инструментов консистентен (**10**); устаревший комментарий-счётчик устранён (закрыт I2); `docs/canon` синхронизирован.
- (+) Инструмент никогда не бросает; введённая безопасность ошибок/лимитов сохраняется; egress не расширяется.
- (−) Ревизия LLM-facing контракта: `mode` исчезает у `summarize_video` — покрывается канон-тестом; Python-сигнатуры/`active_tools` не затрагиваются.
- (−) Расширение native-резолвера voice/video_note — дополнительный код-контакт с F13/F14; тестируется юнит-инъекцией, поведение video/document байт-в-байт.
- (−) Форс-повтор ГС/кружка — дополнительный расход STT/скачивания по явной команде; ограничено лимитами размера/длительности и явностью команды.
- (−) Появляется зависимость порядка: F19 стартует после F14 и F16 (общие файлы).
- Инварианты: `imported-history-immutable`, egress-реестры, `parse_mode=None`, `R16/17/18`, порядок роутеров `bot.py`, лимиты tool-loop, `Δ DDL=0`, `Δ каталога=0` — без изменений.

## 4. Рассмотренные альтернативы

| Вариант | Вердикт |
|---|---|
| **Один** `summarize_video` с `mode: summary\|transcript` (статус-кво) | **Отклонён:** LLM путает функции по параметру; владелец требует два отдельных инструмента с чёткими определениями (UPD5 №3) |
| `transcribe_video`, отдающий **выжимку** транскрипта | **Отклонён:** транскрибация = дословный сырой текст (как у ГС); пересказ — только `summarize_video` |
| Только команда «транскрипт», без нового инструмента | **Отклонён:** владелец требует разделения и в tool calling — LLM должна сама выбирать сырой транскрипт или выжимку |
| Форс-повтор ГС/кружка реализовать в `handlers/voice_transcription.py` (0i) как отдельный хендлер текста | **Отклонён:** youtube 0e обрабатывает команду раньше direct_chat 0h и voice 0i; перестановка роутеров нарушает инвариант порядка `bot.py` |
| Читать/переиспользовать уже сохранённый авто-транскрипт | **Отклонён:** владелец просит **принудительно повторить**, когда авто не сработало; повтор — всегда свежий STT |
| Гейтить флагом само наличие схемы/канон (OFF → 9) | **Отклонён:** канон/JSON-схемы гейтятся безусловно (прецедент 8→9, ADR-1024-15 §2.1); флаг — kill-switch рантайм-доступности и форс-повтора |
| `summarize_video`, принимающий и voice (выжимка голосового) | **Отклонён:** выжимка голосового не является зафиксированной функцией; voice обслуживает только транскрибация |
| Новый текстовый триггер/синоним для «транскрипт» | **Отклонён:** «транскрипт» уже в каноне `command_registry` (группа `youtube`); новых ключей не вводим (Δ каталога = 0) |
| Прокидывать медиа в инструмент через текстовый внутренний реф/file_id | **Отклонён:** file_id/bytes не восстановимы из БД; источник — только `ToolContext.native_media` (контракт F14/ADR-1024-15 §2.3) |
| Отдавать «транскрипт» через новый egress-путь/`send_points` | **Отклонён:** egress не расширяется; курсив — существующий allowlisted путь |
