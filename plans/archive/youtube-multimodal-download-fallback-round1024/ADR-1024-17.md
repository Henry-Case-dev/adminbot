# ADR-1024-17 — YouTube+summary: файл вместо URL страницы (download → мультимодалка → фолбэк субтитры)

- **Статус:** Proposed (Step 2 @Architect, раунд 10.24 / UPD4 кластер B; **обновлён под UPD5**)
- **Дата:** 19.09.2026
- **Фича:** F16 `youtube-multimodal-download-fallback-round1024` (P0, T-2313…T-2321)
- **Тип решения:** backend видео-пайплайн (роутер 0e) + AMEND архивной границы
- **Связанные ADR:** ADR-1016-1 (download-контракт), ADR-1017-2 (probe/качество), ADR-1020-4 (канон инструментов), ADR-1023-1/2, ADR-1024-1 (R17-safe логирование), **ADR-1024-15 (разделение `summarize_video`/`transcribe_video`)**. Архив: `plans/archive/video-multimodal-pipeline-and-incidents`.
- **UPD5 (закрыто владельцем):** (1) порядок «download → мультимодалка → фолбэк субтитры» **подтверждён**; (2) cookies/POT-provider/resident-proxy на проде **разрешены**; (3) `транскрипт` = сырой транскрипт **курсивом**, выжимка — отдельный путь.

---

## Контекст

В проде запрос «Бот че за видос `https://youtu.be/1TON5W_SNKY…`» отвечал «автор видоса зажал субтитры, пересказывать нечего».

Разбор показал двойную причину:

1. **YouTube-URL-ветка `mode=summary` отправляет в OpenRouter URL страницы, а не файл.** `services/youtube_summarizer_service.py:46-48` (`_canonical_youtube_url` → `https://www.youtube.com/watch?v=<id>`) передаётся в `OpenRouterVideoClient.summarize(video_url=…)` (`:102`, `:115-119`). Мультимодальная модель не может «посмотреть» HTML-страницу YouTube → L1 и L2 структурно обречены на провал → остаётся L3-субтитры. То есть мультимодальный канал для YouTube-URL **никогда не работал**, а лишь тратил 2×120с.
2. **Age-restricted видео даёт PERMANENT-фейл субтитров.** `services/youtube_transcript_engine.py:400-422` классифицирует `AgeRestricted` как `(PERMANENT)`, но итоговый `YouTubeTranscriptUnavailableException` (`:148-154`) смешивает её с обычным «нет субтитров» → хендлер выбирает общий пул 5.6 (`YOUTUBE_ERROR_PHRASES`, `services/smartmodule_phrases.py:62-64`), включая фразу «автор видоса зажал субтитры». Причина age-restricted не доходит до пользователя и до логов как отдельная сущность.

При этом **нативная ветка уже работает**: `handlers/youtube.py:957-968` (native+summary) делает `fetch_media_to_tmp → media_share.publish_media_file → summarize_media_url` (L1/L2 по реальному файлу). Пользователь сам подтвердил: «в ответ на нативное видео телеграма выдала выжимку по видео вполне корректно». Также есть готовая инфра скачивания YouTube: `_download_url` (`:678-686`) → `VideoDownloader.download(url, "360")` → yt-dlp (POT/proxy/cookies через `build_ytdlp_base_opts()`).

**Владелец (UPD4 B):** «он должен был скачать это видео и передать в мультимодальную модель… а вот если выжимка упала, то он должен был фолбекнуться на субтитры».

**Конфликт с архивом:** `plans/archive/video-multimodal-pipeline-and-incidents/spec.md:37` («YouTube-URL-ветка mode=summary — байт-в-байт»), `:52` (FR-B5 «youtube+summary — текущий `summarize_cascade` L1/L2/L3 без изменений»), `:241` («`_parse`-путь целиком байт-в-байт»). Это осознанный AMEND (T-2313), а не неявная правка границы.

## Решение

Для `kind=youtube` + `mode=summary` вводится строгий порядок:

```
A) скачать видео (VideoDownloader.download(url, "360"), бюджет-таймаут)
B) опубликовать файл (media_share) → мультимодалка L1→L2 по /media/-URL (summarize_media_url)
C) при провале/недоступности A или B → субтитровый фолбэк L3 (summarize_cascade)
```

Ключевые архитектурные положения:

1. **Хендлер — оркестратор, сервис — исполнитель.** Композиция «скачать → опубликовать → L1/L2 → субтитры» живёт в `handlers/youtube.py::_process_youtube_summary` и **переиспользует** уже проверенный `_publish_and_cascade` (`:630-662`, тот же путь, что у native/direct/platform). Это следует паттерну рабочей нативной ветки и не размазывает файловый lifecycle (tmp/публикация/TTL/удаление) по сервису.
2. **`summarize_cascade` становится субтитровым фолбэком (L3).** Из `services/youtube_summarizer_service.py` удаляется `_canonical_youtube_url` и попытка L1/L2 по URL страницы; метод делегирует в существующий `summarize(...)`, сохраняя сигнатуру (совместимость `tool_router` и тестов). Мультимодалка по произвольному реальному URL остаётся в `summarize_media_url` (без изменений) и вызывается по опубликованному файлу.
3. **Никакой фабрикации URL.** Сервис больше не изобретает playable-URL из `video_id`; video_url всегда приходит извне (опубликованный файл). Это устраняет класс бага «URL, который выглядит валидным, но не играется».
4. **Честная деградация.** Сбои скачивания/публикации/мультимодалки — тихие (WARNING в лог, R17-safe: класс исключения + reason, без URL); пользователь видит либо выжимку, либо существующие/новые фразы. Промежуточных трейсбеков и фраз на шагах A/B нет.
5. **Age-restricted — первоклассная причина.** `YouTubeTranscriptUnavailableException` получает атрибут `reason` (`age_restricted | transient | unavailable`); хендлер выбирает отдельный пул `YOUTUBE_AGE_RESTRICTED_PHRASES` («возрастной порог/нужна авторизация, субтитры закрыты») вместо ложной «битой ссылки».
6. **Kill-switch + поэтапная раскатка.** `YOUTUBE_MULTIMODAL_DOWNLOAD_ENABLED` (env-only `ClassVar`, default `True`): OFF → шаги A/B пропускаются, сразу субтитровый L3 (деградации нет). `YOUTUBE_MULTIMODAL_DOWNLOAD_CHAT_IDS` — CSV-allowlist для раскатки internal→10%→50%→100% без редеплоя. `YOUTUBE_MULTIMODAL_DOWNLOAD_TIMEOUT_SECONDS` (default 240) ограничивает шаг A.
7. **Ноль инфраструктурной дельты.** `ClassVar`-флаги не входят в `dataclasses.fields(Settings)` → вне `param_catalog` → **Δ каталога = 0**; **Δ DDL = 0**; egress-реестр не расширяется (используются существующие send-точки).
8. **Credentialed-уровень разрешён (UPD5).** Владелец разрешил на проде YouTube **cookies / POT-provider (bgutil) / resident-proxy**. Это делает возрастные/защищённые видео достижимыми и для видеоряда, и для субтитров. Уровень — **опциональный** и гейтится `YOUTUBE_CREDENTIALED_LEVEL_ENABLED` (env-only `ClassVar`, default `True`): ON → `build_ytdlp_base_opts()`/`_transcript_proxy_config()` используют креды, если они есть; OFF → только публичные ресурсы (деградации UX нет — age-restricted даёт честный пул). **Значения (пути cookies, URL POT/proxy) — только `.env`**, в spec/логи/отчёты не попадают (R17/R18); логируется только **presence** (`set|empty`).
9. **Разделение «выжимка vs транскрипт» (UPD5).** `mode=summary` (этот ADR: A→B→C → выжимка) и `mode=transcript` — **разные итоги**: транскрипт отдаёт **голый сырой текст курсивом** (`_send_transcript_reply`, HTML `<i>`, тот же стиль, что у ГС), без саммаризации; выжимка сырой текст не отдаёт. Смешение запрещено. На tool-уровне это два инструмента (`summarize_video`/`transcribe_video`, ADR-1024-15 §2.3-bis); F16 tool-слой не трогает (эксклюзив F14) и лишь гарантирует сырой транскрипт/`reason` от движка.

**Границы неизменности (гарантируются тестами):** `mode=transcript` (**в т.ч. формат — сырой транскрипт курсивом**), native/direct/platform-ветки, «скачай» 4e, `_parse`/D126, cache-key, on_retry-нотификатор, 🗿, пулы 5.5/5.6/5.8, консьюм, кулдаун, порядок роутеров `bot.py`, `parse_mode=None` plain-каналов (кроме локального HTML-курсива transcript-доставки), `imported-history-immutable`.

## Последствия

**Плюсы**
- YouTube+summary получает настоящий видеоряд: мультимодальная модель видит файл, а не страницу.
- Устранён главный «тихий» источник потери 2×120с на L1/L2 по URL страницы.
- Age-restricted перестаёт маскироваться под «нет субтитров» — понятная причина для юзера и для диагностики.
- Максимальное переиспользование (downloader, media_share, summarize_media_url, `_publish_and_cascade`) — низкий риск регресса.
- Мгновенный откат флагом; полный откат — `git revert`.
- **UPD5:** credentialed-уровень легализует age-restricted (при наличии `.env`-кредов); «транскрипт» и «выжимка» разведены — пользователь получает ожидаемое (сырой текст курсивом vs пересказ).

**Минусы / цена**
- Ветка становится дороже и медленнее: скачивание + публикация + L1/L2 до 240с; суммарный бюджет приближается к NFR-4 архива (~5–6 мин в худшем случае). Порядок **подтверждён владельцем (UPD5)**; остаётся технический Open Q по бюджету.
- Возрастает нагрузка на yt-dlp/POT/proxy/cookies и на диск (tmp + `MEDIA_SHARE_DIR`; митигируется `finally`-уборкой и TTL). Креды **разрешены (UPD5)** — уровень опционален и гейтится флагом; значения только `.env`.
- `tools/video_downloader.py` не меняется, поэтому наследуется его модель отмены: `asyncio.wait_for`-таймаут скачивания не убивает yt-dlp-поток немедленно (orphan-поток/файл). Это **уже существующее** свойство (внутренний `_YTDLP_DOWNLOAD_TIMEOUT_SECONDS=900`), F16 лишь делает таймаут короче. Мониторинг каталога — за @DevOps.
- `summarize_cascade` теряет page-URL-ветку; тесты `tests/test_video_cascade.py`, закреплявшие баг, переписываются (покрытие L1/L2 переносится на `summarize_media_url`).
- **Выжимка** через tool-путь `tool_router` для YouTube остаётся субтитровой (эффективно как раньше) — возможный follow-up, вне скоупа F16. **Транскрибация** покрыта `transcribe_video` (F14).

**Влияние на документацию (Step 7)**
- `plans/ARCHITECTURE.md` §13/§15 (стр. 233, 252) — уточнить: сигнатура `summarize_cascade` та же, семантика — L3-only; YouTube+summary = download→file-мультимодалка→субтитры; канон инструментов = **10** (`summarize_video`/`transcribe_video`).
- Архив `video-multimodal-pipeline-and-incidents/spec.md` — пометить AMEND по строкам 37/52/241 (не переписывая сам архив; зафиксировать в `plans/ARCHITECTURE.md` и backlog).

## Альтернативы

1. **Оставить субтитры первым уровнем, видеоряд — фолбэком.**
   - *За:* дешевле и быстрее в типичном случае; субтитры для большинства видео доступны.
   - *Против:* прямо противоречит решению владельца и цели фичи (P0): age-restricted/немые/музыкальные/визуальные ролики как раз теряют смысл без видеоряда; текущий баг именно в приоритете субтитров. Возможный компромисс для Open Q №1 (субтитры параллельно/предварительно при известной доступности), но требует отдельного анализа цены.
2. **Передавать в `summarize_cascade` параметр `media_url` вместо композиции в хендлере.**
   - *За:* одна точка «L1→L2→L3».
   - *Против:* дублирует lifecycle публикации/удаления/таймаутов, который уже инкапсулирован в `_publish_and_cascade`; разносит файловую ответственность между сервисом и хендлером. Отклонено в пользу переиспользования.
3. **Скачивать сервису самостоятельно (Downloader + media_share внутри `YoutubeSummarizerService`).**
   - *Против:* сервис получает зависимости уровня инфраструктуры (tmp-файлы, HMAC-публикация, TTL), ломая разделение слоёв и усложняя тесты. Отклонено.
4. **Отдавать в OpenRouter внешний YouTube-URL напрямую (уже так) / публиковать страницу.**
   - *Против:* это и есть баг; модели отдаётся HTML, а не видео.
5. **Не добавлять новый пул фраз, а дополнить 5.6.**
   - *Против:* смешивает разные причины (нет субтитров vs возрастной порог) и оставляет ложные формулировки; NFR-7 требует непересечения пулов. Отклонено.
6. **`git revert` как единственный механизм.**
   - *Против:* не даёт оперативного kill-switch под нагрузкой; выбран флаг + allowlist.

  Приоритет субтитров первым уровнем не вводится; смена потребовала бы нового AMEND.
