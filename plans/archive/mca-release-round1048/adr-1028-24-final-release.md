## Контекст

§20 `plans/current_task.md:986–1044` писался под «единый production-релиз»; фактически программа доставлена per-feature (CA-11): все фичи в проде, **2.58.66 = origin/master** (`e16be7e`, mca-17c VERIFIED; mca-12 → 2.58.65 `3dfc892`). Базлайн: v33 / каталог 523 / KS 85 / reason 280 / тулы 14 / реестр 47; suite 12338/4 (4 pre-existing identity), js 62/62; routes-пин `8153b8bd…` цел; 9 owner-гейтов PENDING OWNER + T-5217. Единственные не-кодовые оси: игровой stub mca-10c (A36 `:917`) и денежные лимиты OFF (`:1026`). Единственный возможный код-пакет окна — mca-21 (ADR-1028-22 D10: применение канон-доставки в окне mca-release). PM (requirements-map §5) вынес 7 развилок Q1–Q7. Раунд ничего не строит: (a) сверка effective-state по живому прод-runtime, (b) доставка deferred-пакетов, (c) live-sweep-консолидация, (d) проверки на замороженном HEAD, (e) §20.3-сценарии → §21-отчёт → README/commit/push → маркер → PM-close.

## Решения

- **D1 — верификационная природа и границы (CA-REL-1…8).** Раунд не добавляет функциональность и не создаёт вторых механизмов: деплой-способ/секреты/контур effective-проверки/канон-механика — существующие; чужие пакеты (mca-12/17c/19/20/21) и arch-frames других фич не редактируются; `plans/current_task.md` read-only (R17); ASAP 5 не начинается.
- **D2 — effective-state: истина = прод-runtime (`:1004`).** Инвентарь KS/настроек (T-5222) и таблица 21 строки `:1008–1030` (T-5223) — по фактическому runtime/API/витрине/журналам, не по дефолтам кода; каждая строка: санкционированное (ADR фичи) → фактическое → Δ-вердикт. Read-only: 0 переключений; расхождение — с причиной и решением. Квант-честность (`:988`/`:1032`): статус ANU отдельно от настройки quantum; fallback = «незавершён/деградирован», не «работает»; несуществующие credentials не включаются.
- **D3 — намеренно-неактивные оси — артефактами.** Stub mca-10c: код в проде, не зарегистрирован/не активен, пробный вызов → `not_implemented` без side effects (A36; §21 п.6 `:1055`); деньги OFF `:1026` — состояние лимитов из прод-runtime (`:752` — учёт работает). Включение — только санкцией владельца вне раунда.
- **D4 (Q2) — заморозка HEAD.** Единая заморозка **после интеграции пакета mca-21**; полный прогон T-5225 на ней; SHA — в manifest. Расхождение прод-HEAD ↔ HEAD = СТОП + re-сверка (identity-прецедент mca-17c 9/9, пин `8153b8bd…`); чужие коммиты → ff-интеграция `:994` + перезапуск затронутых проверок. Effective-сверки от HEAD не зависят.
- **D5 — pre-release проверки и путь возврата (`:994–997`).** Точная сверка базлайна: 12338/4 (те же identity), js 62/62, F8 523, frontier v33/0 pending, census 85/280/14/523/47; новый red — разбор до продолжения. Backup с **read-back**; путь возврата: KS soft-пути + git revert (2.58.45→2.58.66, перечень в manifest) + команды проверки; тексты — из слепков/backup (поведение не меняют `:1842`).
- **D6 — Δ-инварианты verification-only (CA-REL-6).** Δ DDL = **0** (v33 не растёт; канон-доставка mca-21 — DML, доказательство TH-5: `canon_version`/`canon_drift` post-delivery; при Δ=0 полный migration smoke не нужен — frontier + census). Δ каталога = **0** (523; F8 NOT_APPLICABLE). KS **0** (85; env-оверрайды ожидаемо 0). reason **0** (280). Тулы **0** (14). Процессы/widget-ID **0** (47). Routes **0** (`ROUTES_SHA256_F11` re-pin не требуется). Единственный допустимый код-пакет — mca-21 (`info_service.py` + сид-файлы + канон-тесты; для него инварианты тоже 0).
- **D7 (Q1) — deploy: правило код-дельты.** Evidence mca-21 готова (T-5213–T-5215) → окно исполняет пакет mca-21 = пер-фичевый bump **2.58.66→2.58.67** (CA-11; DEFERRED_TO_RELEASE mca-21 — его окно, не superseded) + канон-доставка = исполнение **T-5216** + TH-5-сверка. mca-21 доставлен ранее → окно без код-действий, **маркер = релизный документ** (`deployment.md` фичи) без бампа. «Пустой» бамп запрещён (версии = код-дельты, прецедент 2.58.56–2.58.66). Evidence нет → окно переносится, маркер не выставляется (CA-REL-1). Факт — `deployment.md`; недоступность — честный «деплой не выполнен: нет …» (`:1044`).
- **D8 — секвенция окна и границы с mca-21.** Префлайт (зелёные блоки A/B + evidence + drift-gate D9 mca-21) → backup → [деплой пакета + identity-сверка] → [канон T-5216 + TH-5] → §20.3 → §21-отчёт + Review + Scanner → live-sweep → маркер (только после зелёных A–E + Approved + Critical/High=0). mca-release не редактирует тексты/версии гайдов и merge-политику drift — окно **исполняет** чужой пакет по правилам ADR-1028-22 D9; 0 дублей T-5216. Деплой — существующий способ/секреты; значения секретов не в командах/логах (`:998`, R17); fail2ban-дисциплина AGENTS.md (один recon ~15 с + один прогон, пауза ≥22 мин, `/healthz`).
- **D9 — §20.3 и телеметрия (`:1038–1042`).** Все проверки — реальные, с артефактами: effective config через runtime/API, direct reply через существующие тестовые команды (0 синтетических сообщений участникам), retrieval, намерение, source link, checkpoint, витрина, video path, журналы. Сбой → фикс + повтор **затронутой** проверки; авария → **один** компонент, точная причина, приём сообщений сохранён. Телеметрия ≥ **15 мин**; jobs running/queued с причиной и рестарт-устойчивостью (`:1060`); deep sleep — контролируемый запуск без дублей. No-false-acceptance: имитация запрещена.
- **D10 (Q5) — отчёт по архиву.** Источник чисел — прод-метрики archive-прохода (runtime/API/журналы): обработано, доля метаданных/источников, скорость, оценка остатка; **снапшот на дату маркера** с пометкой «процесс продолжается»; полный проход 2 млн не требуется (`:1060`).
- **D11 (Q3/Q4) — live-sweep и §21 п.5–6.** Live-sweep: **один сводный чек-лист** (9 гейтов + T-5217) с по-гейтными секциями, сводит PM, живёт в backlog (Round 10.48 → Follow-up-чек-лист); **частичное закрытие допустимо** — каждый гейт независимо живой проверкой владельца; закрытые пункты из backlog удаляются (без resolved-истории), оставшиеся → §21 п.9. Скриншоты — Builder на явно тестовых/обезличенных данных (desktop/mobile + таблица управления + 4 «Аналитика»-экрана); **матрица покрытия = сводка** (47/47 mca-17c + `backlog:335` + T-5204/T-5218 mca-21), вторую матрицу с нуля не строить; trace-примеры по §21 п.6 с реальными event ID + подтверждение stub.
- **D12 (Q6/Q7) — R3 ратификация, пороги, README.** R3 — по роли (RELEASE-точка программы `:215`), содержание verification-only. **Пороги эскалации:** код-Δ вне пакета mca-21, любой Δ-инвариант D6 ≠ 0, расхождение факт↔санкция без решения, имитация живой проверки, секрет в артефакте, fail2ban-нарушение → **СТОП + Step 2** (re-план/amend), тихих расширений нет. README — в PM-close (T-5237, распределение ADR-1028-22 D11): краткая сводка + ссылка на «Справку», без дублей гайдов (CA-21-2), ирония сохранена (`:1847`); коммит на русском по правилам, push ff.

## Последствия

Позитив: финальная точка программы закрывается без единой миграции и без нового кода (кроме возможного пакета mca-21 с нулевыми инвариантами); честный effective-снимок 21/21 по живому проду; owner-гейты консолидированы в один чек-лист без ложного закрытия; маркер привязан к код-дельте, а не к церемонии. Негатив/ограничения: раунд не закрывает живые гейты (остаются за владельцем); окно зависит от контент-фазы mca-21 (неготовность → перенос); при недоступности SSH возможен честный исход «деплой не выполнен». Если верификация вскроет несанкционированную код-дельту или расхождение факт↔санкция — останов и возврат Step 2 (не тихое расширение).
