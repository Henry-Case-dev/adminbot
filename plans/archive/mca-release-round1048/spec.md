## 1. Effective-state сверка §20.2 — истина в прод-runtime (RELEASE-R2; T-5222–T-5224)

**D1. Источник факта — живой прод, не код.** Правило `:1004` («одних новых defaults недостаточно, если старые значения в БД перекрывают их») фиксирует источник истины: фактическое значение настройки/KS читается из прод-runtime/API/БД/журналов. Строка подтверждения «в коде default ON» — не доказательство effective ON. Каждый пункт инвентаря T-5222 — строка «настройка/KS → санкционированное состояние (ADR/санкции своей фичи) → фактическое effective → Δ-вердикт». Сверка — read-only: **0 переключений этим раундом** (CA-REL-4); расхождение факт↔санкция → перечислить с причиной и решением (влить/эскалация @Architect), молчаливых правок нет. **PARALLEL_SAFE** (read-only инвентарь).

**D2. Таблица 21 строка `:1008–1030` — построчно, без «по дефолту».** T-5223 заполняет каждую строку статусом (ON / ON-с-оговоркой / OFF / деградация) + источником проверки (runtime/API/витрина/журналы). Особые строки: архивный проход — running/queued **с причиной**; спонтанность — probability 0.05, один общий выбор на автономную ситуацию; NumericClaim — все пути отправки; банк опыта — candidate не активируется без проверки; 14.6–14.11 — единые координатор/очередь/RandomSource; сон/глубокий сон — существующее расписание сохранено; SelfModel/BehaviorFrame — все пути ответа; MCA-19 — каскад (отдельное подключение → основная модель → effective OFF **с причиной**) + контролируемый backfill; MCA-20 — команда, инструмент и все fallback-пути; аналитика MCA-17 — KS 85 Δ=0, handoff mca-17c `backlog:335`.

**D3. Намеренно-неактивные оси — подтверждение артефактом, не изменение (T-5224).** (а) Игровой stub mca-10c §14.12 `:718–728`: код в проде, не зарегистрирован/не активен (вне SmartModule, без tools/handlers/UI); пробный вызов → `not_implemented`, без сетевых запросов и side effects (A36 `:917`; §21 п.6 `:1055` — «отдельно подтвердить неактивность игрового stub»). (б) Новые денежные ограничения **OFF** `:1026` (учёт расходов работает при отключённых лимитах `:752`): состояние настроек лимитов из прод-runtime. Включение — только явной санкцией владельца вне этого раунда; в отчёте/гайдах — честная пометка, не реклама.

**D4. Квант-честность (`:988`/`:1032`).** Фактический статус ANU проверяется **отдельно** от выбора quantum в настройке: quantum выбран/активирован с реальным ключом ≠ «ANU доступен». Временный fallback виден и не заменяет приёмку подключения; при fallback состояние интеграции — «незавершён/деградирован», формулировка «квантовый режим работает» запрещена; несуществующие credentials не включаются. Остальные функции при fallback работают по явной fallback-политике.

**SC-R2a:** 21/21 строк со статусом и источником; 0 строк, подтверждённых только дефолтом кода.
**SC-R2b:** каждая KS/настройка T-5222 имеет строку с фактическим значением и вердиктом; 0 расхождений без решения; 0 переключений; env-оверрайды ожидаемо 0 (прецедент релиз-маркеров 2.58.56–2.58.66).
**SC-R2c:** stub-вызов и состояние лимитов подтверждены артефактами (вывод вызова + прод-runtime-факт).
