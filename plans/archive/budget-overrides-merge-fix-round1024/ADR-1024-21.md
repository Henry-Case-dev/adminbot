# ADR-1024-21 — Merge per-chat значений в `POST /api/config`: разведение namespace `overrides` (значения) ↔ `perm_overrides` (матрица прав)

- **Статус:** ✅ **ACCEPTED** (Step 2 @Architect, раунд 10.24 / UPD5-critical). Обязывает @Builder.
- **Дата:** 2026-09-20
- **Фича:** F20 `budget-overrides-merge-fix-round1024`
- **Раунд:** 10.24 (UPD5-critical), `plans/current_task.md:404`; backlog §10.24, F20
- **База:** HEAD `00eab85` (прод `4314ea4`)
- **Связано:** ADR-1018-7 (единый резолв настроек `chat → global → default`), ADR-1019-2 (бюджетный sentinel; D4 `budget_snapshot`/BYOK-резолв), ADR-1022-5/1023-3 (`physical-two-call`).
- **AMEND:** **ADR-1019-8** (write-path per-chat `overrides`) и **ADR-1012-1** (per_chat / X-Chat-Id save-путь). **SUPERSEDE: нет.**
- **Приоритет:** P0 / Critical. Δ DDL = 0, Δ каталога = 0, новых флагов нет.

## 1. Context

1. **Симптом:** владелец сохраняет одно значение бюджета в мини-аппе — и бот уходит в фразу-заглушку `content.no_key_reply`. У целевого чата `-1002661910336` исчезают **8 seed-ключей** (`config/chat_settings_seed.json:11-20`, в т.ч. `limits.chat_global_key_budget_requests: -1` = безлимит) → глобальный cap (`services/chat_usage.py:61-65`, 100 вызовов / 500k токенов) → `NoApiKeyForChat('budget')` (`services/llm_client.py:404-420`) → заглушка (`services/direct_chat_service.py:767-781`, `services/sandbox_reply.py:8-11`).
2. **Первопричина:** `web/api/routes.py:482` берёт `chat_overrides = dict(root.get("perm_overrides") or {})` — это **матрица прав**, а не значения. Далее `:523-524` строит `new_overrides = perm_overrides ∪ {сохранённый ключ}` и `:528-529` записывает его в namespace **`overrides`**. Поскольку одиночный save (`web/app.js:4454-4461`) шлёт **один** ключ за POST, namespace `overrides` **целиком** заменяется: все прочие per-chat значения уничтожаются, а значения «загрязняются» ключами матрицы прав.
3. **Эталоны корректного чтения рядом:** GET `routes.py:372-377` и DELETE `routes.py:729` читают `root.get("overrides")`; `perm_overrides` в них используется только для матрицы прав.
4. **Петля «самоизлечения»:** сид (`bot.py:1049-1051`, `services/chat_settings_seed.py:156-179`) возвращает overrides на рестарте, но следующая правка снова стирает → рестарт «лечит», UI «калечит».
5. **Структурный корень:** `services/chat_params.py:330-333` заменяет namespace **целиком** (by design). Следовательно, корректность держится на вызывающем: он обязан merge-ить базу **из своего** namespace. POST смешивал два разных namespace (`overrides` и `perm_overrides`), что и есть дефект.
6. **Инварианты:** R16 (аддитивность API), R17/R18 (секреты/креды), порядок роутеров `bot.py`, `physical-two-call` (LLM-конвейер), Δ DDL = 0, Δ каталога = 0.

## 2. Decision

### D1. База merge значений = `root.get("overrides")`, запись — только в `overrides`
`POST /api/config` (с `X-Chat-Id`) читает namespace **значений** и пишет в него же:
`value_overrides = root["overrides"]` → `new_overrides = value_overrides ∪ patch_overrides` → `set_chat_params({"overrides": new_overrides, "meta": …})`. `perm_overrides` **не** является базой и **не** попадает в запись.

### D2. `perm_overrides` — отдельный namespace (матрица прав, read-only в POST)
`perm_overrides` читается и используется **исключительно** для `effective_matrix`/`can_edit_param` (`routes.py:498-500`). Запись прав чата остаётся в `web/api/access.py:443-447`. Namespace-ы не смешиваются ни в одну сторону.

### D3. Семантика `manual-overrides-immutable`
Ручные per-chat **значения** не могут быть разрушены последующей записью другого значения; единственный путь удаления — `DELETE /api/config/chat/{key}`. Сид уважает ручные правки (кроме `enforce`), как и раньше (ADR-1019-8 D4). Данное правило формулируется явно, чтобы «immutability» не смешивали с матрицей прав.

### D4. Глобальный путь (`per_chat=false`) и optimistic concurrency — без изменений
`_post_config_global` (`routes.py:752+`) и ветка `app.js:4451-4461` (`global:true`, без `X-Chat-Id`) не меняются. `expected_updated_at` → `ChatParamsConflict` → `409 {code:"conflict", current_updated_at}` сохраняется. GET `updated_at`/`chat_updated_at` сохраняется.

### D5. Идемпотентность и «пустой save»
Повторный save того же значения не меняет набор ключей и не пишет history-строку (`old_json == new_json`). Отсутствующий ключ не создаётся. Пустой `items` → `422`. Лог `[api] config chat updated | chat | keys | by` сохраняется (R17-safe). Обновление `updated_at` при повторе допустимо (не регресс).

### D6. Разрыв петли сида
После фикса UI-save больше не стирает seed-ключи → `apply_chat_settings_seed` на рестарте видит равенство значений и делает `skipped` (no-op). Политику сида (`enforce`/`version_bump`/`force`) **не меняем** — это F22-зона.

### D7. Флаг не вводится
Поведенческий фикс корректности; kill-switch — `git revert`. Progressive delivery не требуется; live-проверка на целевом чате.

### D8. Реализация
Единственный обязательный файл — `web/api/routes.py`: разведение переменных на `:482` (`perm_overrides` vs `value_overrides`), подстановка `perm_overrides` в `:498-500`, merge от `value_overrides` на `:523-524`. `web/app.js`, `services/chat_params.py`, `services/chat_settings_seed.py`, `web/api/access.py` — не меняются.

---

### AMEND ADR-1019-8 (D1 — write-path per-chat `overrides`)
**Было (неявно):** per-chat override пишется через `set_chat_params`/`POST /api/config` (+`X-Chat-Id`), namespace-семантика не была специфицирована явно — это позволило ошибочно merge-ить от `perm_overrides`.
**Стало (уточнение, не отмена D1):** write-path per-chat **значений** обязан merge-ить базу `root["overrides"]` и писать только в `overrides`; `perm_overrides` — независимый namespace матрицы прав. D2 (sentinel-таблица), D4 (сид/идемпотентность), D9 (флага нет), D10 (нейтральный сид) — **без изменений**.

### AMEND ADR-1012-1 (D2 — per_chat / X-Chat-Id save-путь)
**Было:** глобальные (`per_chat=false`) ключи сохраняются global-путём; серверный 422/DM read-only сохранены.
**Стало (уточнение, не отмена D2):** per-chat save-путь (`X-Chat-Id`) разделяет namespace: база merge — `overrides` (значения), `perm_overrides` — только для прав. Клиентское поведение (один ключ за POST, `global` для `per_chat=false`) **не меняется**; серверный 422 и DM read-only **сохраняются** без ослабления.

## 3. Consequences

**Positive**
- Одиночный save перестаёт уничтожать прочие per-chat значения; seed-overrides (в т.ч. `-1` = безлимит) выживают после UI-правок; петля «рестарт-лечит / UI-калечит» разорвана.
- Матрица прав и значения окончательно разведены — устраняется целый класс будущих регрессов (не только текущий).
- Дифф минимален (≈3-4 строки в одном файле), риск низкий, откат тривиален.
- Поведение GET/DELETE и обоих путей (`per_chat` true/false) не меняется.

**Negative**
- Корректность по-прежнему держится на дисциплине вызывающего (namespace-merge в `set_chat_params` заменяет целиком, by design) — митигируется регресс-тестами (a)/(b)/(d).
- F20 **не ремонтирует** уже утерянные значения целевого чата — это F22 (строгий порядок F20 → F22, иначе ремонт снова затирается).
- Связанный дефект в `access.py:443-447` (одиночная запись прав может затирать прочие `perm_overrides`) остаётся вне scope — выносится в follow-up.

## 4. Alternatives

- **A1. Опереться на `perm_overrides` и доставать значения из него** — отклонено: namespace-ы семантически разные; смешение и есть баг.
- **A2. Изменить `set_chat_params` на глубокий merge namespace-ов** — отклонено: меняет базовый контракт PG-слоя, blast-radius по всем вызывающим (сид, gates, keys, access), не нужно для фикса.
- **A3. Клиентский фикс (шлём все ключи одним POST)** — отклонено: не устраняет серверный дефект; хрупко (любой внешний/новый вызывающий воспроизведёт баг); одиночный POST — легитимный контракт.
- **A4. Merge отдельным `value_overrides` + `perm_overrides` (принято)** — минимальный, точечный, доказуемый тестами.
- **A5. Ввести feature flag** — отклонено: поведенческий фикс корректности, не rollout; `git revert` достаточно.
