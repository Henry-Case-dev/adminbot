## 1. Цель и контекст

§80/§81 задают целевой пайплайн: фильтр → восстановление → **L1 Кластеризатор** (S3, §94–§95) → **пакет фактов** (S4, §96) → **L2 Писатель** (§97–§99) → **форматирование** (§100–§103/§105) → существующие `generate_image` и `sendRichMessage` (§104). Сейчас Саммари — ровно **2 физических LLM-вызова**: Stage-1 «Редактор» → Stage-2 «Рассказчик» (ADR-1022-4). S5 реализует L2-слой и форматирование так, чтобы после врезки L1+L2 **заменили** Stage-1/Stage-2, сохранив ровно 2 вызова (ADR-1026-5 D1, AMEND ADR-1022-4 effective S5).

Ключевые ограничения: §97 (запрет сленга/беглой речи/бессвязного потока/мемов; умеренная ирония; приоритет точности; **не выдумывать цитаты / не приписывать реплики**), §98 (H1, вступление, абзацы, логичный порядок, необязательное заключение, ≤1 жирный акцент на абзац), §99 (структурированный документ, **не** произвольный HTML; форматтер — код, не LLM), §104 (`generate_image`/обложку/порядок публикации не трогать), §106 (fail-closed), §82 (слот слоя: отдельные провайдер/модель/промпт/параметры/fallback).

## 4. Контракт L2 (D1)

### 4.1. Модуль и интерфейс
`services/summary_l2_writer.py` — изолированный слой: **не** импортирует фильтр/восстановление/генератор саммари и **не** видит сырой лог; единственный вход L1-данных — `FactPackage` (S4). Ровно **1** LLM-вызов.

```
@dataclass(frozen=True)
class L2Result:
    status: str            # "ok" | "empty" | "invalid" | "error"
    document: dict | None  # {"schema_version":1,"title":str,"paragraphs":[{"text":str,"emphasis":str|None}]}
    invalid_reason: str | None   # R17-safe код
    usage: dict | None     # {"input_tokens":int|None,"output_tokens":int|None}
    metrics: dict          # аддитивно (абзацы, длительность, violations-счётчики)
    duration_ms: float

def build_l2_input(package: dict, *, detail: str = "serious") -> str
async def run_l2(llm=None, package=None, *, service=None, correlation_id=None,
                 slot=None, max_paragraphs=None) -> L2Result
def parse_l2_document(raw: str) -> tuple[dict|None, str|None]
def validate_l2_document(document: dict, package: dict) -> tuple[dict|None, dict]
```
- `service` (`cover_prompt`/`response_mode`) в L2-контент **не попадает** (изоляция §96/§104); используется оркестратором для промпта-детали и обложки.
- Вызов — через существующий LLM-контур (прецедент `summary_l1_clusterizer._dedicated_generate`): `module="summary", step="l2_writer"`, token accounting, существующая политика fallback, fail-fast на детерминированных ошибках. Публичный per-call метод клиента (R-R1026S3-1) — не блокер S5.

### 4.2. Вход (§96, компактность)
`build_l2_input` собирает контент-секцию пакета: на тему `name`, `description`, `chronology` (только timestamp/порядок), `facts[].text` + `evidence_message_ids`, отобранные `fragments[].text`. `service`, `budget`, `unassigned_message_ids` в контент не идут. Весь сырой лог повторно не передаётся. Формат — компактные JSON-строки (как §93-упаковка L1), детерминированный порядок.

### 4.3. Выход (§97/§98/§99) и промпт
- Строгий JSON-документ §99: `{"schema_version":1,"title":str,"paragraphs":[{"text":str,"emphasis":str|null}]}`; разбор — существующим `system2_handoff.parse_json_object`; лишние поля/типы → `invalid`.
- Новый канон `SUMMARY_L2_WRITER_SYSTEM_PROMPT` (§97): отдельная роль «писатель статьи»; **без** инструкций на сленг/беглую речь/бессвязный поток/мемы; умеренная ирония допустима, приоритет — точность; §98-структура; короткая памятка разрешённых смысловых элементов (§103 — без копии документации Telegram). Канон **не общий** с L1/Рассказчиком (§81/§85 «один промпт — один источник»).
- `response_mode` не включает legacy-блоки `MODE_CASUAL_*` (они несут «торопливое письмо» — противоречит §97); ON-путь трактует режим как уровень детализации (serious/casual — короче, deep_research — больше абзацев). Legacy-режимные блоки сохраняются для OFF-пути.

### 4.4. Запрет выдуманных цитат и приписанных реплик (инструкции + пост-валидация)
1. **Инструкции (промпт):** прямые цитаты не приводить; реплики пересказывать своими словами; имена/авторство не домысливать.
2. **Пост-валидация (код, `validate_l2_document`):** для каждой кавычковой вставки (`«…»`, `"…"`, `„…"`, `“…”`) нормализованный (casefold+схлопывание пробелов) фрагмент должен быть подстрокой объединения текстов пакета (`facts[].text` ∪ `fragments[].text`).
   - **нет совпадения** → цитата выдумана: снять кавычки (перевести в косвенную речь) + WARN-счётчик; выдуманная цитата **не публикуется как цитата** (§106);
   - **цитата совпала, но рядом атрибуция к именованному участнику** (`Имя: «…»`, `«…», — сказал/написал/заявил <Имя>`) → **fail-closed** `invalid` (`quote_attribution`): в пакете нет карты автор↔текст (изоляция §96), значит L2 не вправе приписывать реплику; повтор невозможен (3-й вызов запрещён) → Саммари не публикуется (§106).
   - Порог: если после нормализации документ теряет структуру/пустой → `invalid`. Результат валидации — R17-safe коды и счётчики в `metrics` (без текстов).

## 5. Форматтер §98/§99/§101/§102/§105 (D2)

### 5.1. Модуль и состав
`services/summary_article_formatter.py` — **чистый детерминированный** (stdlib; без БД/сети/LLM/часов). Композиция §98: `title` (H1) → опциональное вступление → абзацы событий → необязательное заключение. Отдельные типы блоков (intro/conclusion) **не** вводятся: вступление/заключение — обычные абзацы (не усложняем контракт §99). Порядок абзацев — как в документе (логичный порядок — ответственность промпта, T-3319).
```
def format_rich_html(document, *, cover_id=None, sanitize=None) -> str
def format_plain_html(document, *, sanitize=None) -> str
def format_plain_text(document) -> str
def chunk_plain_blocks(document, limit: int = 4096) -> list[str]
```

### 5.2. Rich-путь (§101/§102, основной)
- `cover_id` задан → первым идёт `<img src="tg://photo?id=…">` (существующий `SUMMARY_COVER_MEDIA_ID`/`build_cover_media`, §104 не тронут), затем `<h1>title</h1>` (**настоящий H1**, не жирный), затем `<p>…</p>`.
- Экранирование — **кодом**: `sanitize_outgoing` (существующая обёртка) → затем `html.escape(..., quote=True)` (порядок обязателен: sanitize ДО escape — инвариант 3 `telegram_send`). Спецсимволы `& < >`, кавычки, Unicode, эмодзи, ссылки — покрываются тестами.
- Разрешены только теги `img`/`h1`/`p`/`b`; MarkdownV2 не смешивается.
- Доставка: существующий `sendRichMessage` (`services/telegram_send.send_rich_message`) с **явным** указанием HTML-режима (новый параметр `content_format="html"`; default `"auto"` → текущее поведение байт-в-байт для legacy-вызовов). Причина: авто-детектор `_looks_rich` распознаёт `<h1` как rich-markdown и отправил бы HTML как Markdown — нужен явный маршрут. Механизм публикации не переписывается (§100).

### 5.3. Plain-путь (§105, fallback без обложки)
- ON-путь: `format_plain_html` → `<b>title</b>` + абзацы + совместимые `<b>`-акценты, отправка существующим `sendMessage` через `send_text(..., parse_mode="HTML")`; превышение лимита — `chunk_plain_blocks` по **границам абзацев** (≤4096), без молчаливого обрезания.
- Если HTML-отправка недоступна/падает → финальный даунгрейд `format_plain_text` (низкоуровневый текст без разметки) и прежний поток; текст не теряется.
- **OFF-путь** `_deliver_plain`/`_send_streaming`/`_send_chunked` (R11, `parse_mode=None`) — **вне diff** (байт-в-байт).

### 5.4. Лимиты (каталог/env)
- `title` ≤ 200 символов, одна строка; абзацев ≤ `limits.max_summary_parts` (существующий ключ) и ≤ 498 блоков; суммарный rich ≤ 32000 символов (< Bot API 32 768, 500 блоков); абзац ≤ 900 символов.
- `emphasis` обязан быть дословной подстрокой своего абзаца; иначе снимается; **≤1** акцент на абзац (лишние снимаются до первого/удаляются); отсутствие акцента допустимо.
- Markdown/буллиты/нумерация в тексте абзаца — детерминированно снимаются (R11-совместимость); «не придумывать событие ради заголовка» — промпт (T-3319) + проверка «title непустой, ≤1 строки».

## 7. Врезка, 2-вызовность, fail-closed (D5/D6)

### 7.1. Границы врезки (D5)
- **OFF (default):** `_run` идёт прежней веткой `SYSTEM2_SUMMARY_ENABLED` → `_generate_two_call` (Stage-1 Редактор + Stage-2 Рассказчик); новые модули в живом пути **не импортируются**; поведение **байт-в-байт**; `await_count==2`.
- **ON:** `rows → S1 filter_window + S2 restore_context → §92-payload → run_l1 (1 вызов) → build_fact_package (0) → run_l2 (1 вызов) → formatter (0) → доставка`. Врезка — **после S1/S2** (ADR-1026-7 D5/§80): L1 получает уже отфильтрованный/восстановленный вход, `trigger_message_id` учтён S1, `focus` прокинут в L1 (`focus_block`). Ровно **2 физических LLM-вызова** (L1+L2); 3-й невозможен. ON активируется **только** после live-приёмки Эпика 1 (гейт S6/S10 + ADR-1025-24 D4); в S5 ON проверяется **на моках**.
- Точка врезки: ветка в `_run` за флагом, после S1/S2; ветка OFF не изменяется; `_generate_two_call` сохраняется для OFF/отката.

### 7.2. Fail-closed (§106)
| Событие | Поведение |
|---|---|
| `L1Result` не `usable` (`empty/invalid/error`/нет payload) | L2 **не вызывается**; `L2_SKIPPED` (reason); публикации нет; без повторов |
| `FactPackageResult` не `deliverable` (`empty/invalid/error/not_built`) | L2 **не вызывается**; `L2_SKIPPED`; публикации нет |
| L2 `empty`/`invalid`/`error` (в т.ч. `quote_attribution`) | `L2_ERROR`/`SUMMARY_FAILED`; **без** legacy-фолбэка (это был бы 3-й вызов); пустое/выдуманное не публикуется |
| Текст готов, обложка не создана | публиковать текст plain (§105) |
| Классы ошибок | различать `SUMMARY_GENERATION_FAILED`/`COVER_GENERATION_FAILED`/`RICH_MESSAGE_SEND_FAILED`/`TEXT_FALLBACK_FAILED`; «Ошибка Саммари» без деталей запрещена (§109) |

- **Детерминизм/канонизация:** строгий парсер; фиксированный порядок; вход не мутируется; двойной прогон форматтера байт-идентичен.
- **ID-пространства:** вход L2 — TG `message_id` из пакета (§92/§95/§96); выход документа id не содержит; валидатор вырезает `fact:`/`msg:`/сырые числовые ID из текста.

## 8. Логи/безопасность (R17, §108/§109)
Аддитивные `L2_START`/`L2_COMPLETE`/`L2_ERROR`/`L2_SKIPPED` и `FORMAT_START`/`FORMAT_COMPLETE`/`FORMAT_ERROR`; поля §109: провайдер (host), модель, входные/выходные токены, количество абзацев, длительность; ошибки — этап/модель/провайдер/HTTP-статус/тип/причина/попытки. **R17:** только числа/коды/id/host — без ключей, текстов сообщений, сырых ответов, промптов. `correlation_id` — существующий (формальный `run_id` — S7). Метрики §112/§111 — аддитивные счётчики без узлов ExecutionGraph (S8).

## 11. Приёмочные сценарии
- **SC-01** §99-контракт: документ `{schema_version,title,paragraphs[{text,emphasis}]}`; лишние поля/типы → `invalid`.
- **SC-02** ровно 1 вызов L2; ON-путь — 2 вызова (L1+L2), OFF — 2 (Stage-1+Stage-2); `await_count==2` в обоих.
- **SC-03** §98-структура: один H1; абзацы отдельно; ≤1 `<b>` на абзац; отсутствие акцента допустимо.
- **SC-04** §101/§102: настоящий `<h1>` в rich; `<p>`/`<b>`; экранирование `& < >`, кавычек, Unicode, эмодзи, ссылок; нет неподдерживаемых тегов/MarkdownV2.
- **SC-05** §105 plain: H1 → жирный; абзацы и совместимые акценты; разбивка по границам абзацев; текст не теряется/не обрезается молча.
- **SC-06** §97-запреты: сленг/беглая речь/мемы/бессвязность не проходят (структурные проверки + канон); умеренная ирония не отбраковывается.
- **SC-07** цитаты: выдуманная цитата не публикуется как цитата (нормализация); цитата с именованной атрибуцией → fail-closed.
- **SC-08** §96-изоляция: L2 не видит `service`/сырой лог; `cover_prompt`/`response_mode` транзитят через пакет (§104 не тронут).
- **SC-09** fail-closed: `L1Result`/пакет не `usable` → L2 не вызывается; L2-провал → нет публикации; обложка-провал → публикуется текст; 4 класса ошибок различимы.
- **SC-10** слот §82: env-only `SUMMARY_L2_*`; «не выбрано» → глобальная модель; наследование ≠ аварийное резервирование; per-chat не «протекает».
- **SC-11** канон ADR-1013-3: `PREV_*` + идемпотентная миграция + ROLLBACK + эталон; кастом не перезаписывается; ключ Рассказчика/Редактора не тронуты.
- **SC-12** детерминизм: двойной прогон форматтера байт-идентичен; вход не мутируется.
- **SC-13** R17: логи `L2_*`/`FORMAT_*` без ключей/текстов/промптов/сырых ответов.
- **SC-14** инварианты живого пути (OFF): `summary_generator` OFF-цепочка байт-в-байт, `generate_image`/обложка/XML/`web/**` вне diff, Δ DDL=0, полный pytest ≥ baseline, JS 43/43.
