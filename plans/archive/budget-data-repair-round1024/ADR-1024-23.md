# ADR-1024-23 — Ремонт потерянных per-chat `overrides`: канонический ремонт = plain-сид, read-only аудит истории, разграничение флага контекста и master-тумблера

- **Статус:** ✅ **ACCEPTED** (Step 2 @Architect, раунд 10.24 / UPD5-critical). Обязывает @Builder.
- **Дата:** 2026-09-20
- **Фича:** F22 `budget-data-repair-round1024`
- **Раунд:** 10.24 (UPD5-critical), `plans/current_task.md:404`; backlog §10.24, F22
- **База:** HEAD `a406440` (F20 уже в HEAD `070f31c`; прод `4314ea4`)
- **Связано:** ADR-1018-7 (единый резолв `chat → global → default`), ADR-1019-2 (бюджетный sentinel), ADR-1019-4 (контекстные лимиты), ADR-1024-21 (F20 — фикс merge; **предпосылка**).
- **AMEND:** **ADR-1019-8 D4** (ответственность за per-chat `overrides` и сид). **SUPERSEDE: нет.**
- **Приоритет:** P0 / Critical. **Δ DDL = 0, Δ каталога = 0**, новых флагов нет.

> **Решение владельца (Gate G5 — да):** идемпотентно вернуть 8 стандартных значений из сида (с бесконечными лимитами) + аудит истории правок; JSONL/историю читать read-only, секреты не выводить (R17/R18).

## 1. Context

1. **Симптом:** у целевого чата `-1002661910336` исчезли 8 per-chat значений (`config/chat_settings_seed.json:11-20`, в т.ч. `-1` = безлимит) → глобальный cap → `NoApiKeyForChat('budget')` → фраза-заглушка `content.no_key_reply`. UI-значения бюджетов «сбрасываются и не применяются».
2. **Первопричина стёрта:** merge-баг `POST /api/config` (база merge бралась из `perm_overrides`), устранён в **F20** (`ADR-1024-21`, коммит `070f31c`). F20 **прекращает потерю**, но **не ремонтирует** уже утерянные данные — это F22 (строгий порядок **F20 → F22**).
3. **Механизм восстановления уже существует:** `apply_chat_settings_seed(force=False)` (`services/chat_settings_seed.py:165-172`) добавляет ключ, которого **нет** (`not present`), и не трогает существующий. Поскольку баг стирал namespace `overrides` **целиком**, все 8 seed-ключей стали absent → plain-сид вернёт их без перезаписи чего-либо.
4. **Дефект CLI-пути (находка разведки):** `manage.py::_cmd_apply_chat_overrides:832-846` вызывает `pg.init(seed_settings=False)` **без** `await pg.connect()`; `PgDatabase.init` при `pool is None` молча выходит (`services/pg_db.py:521-528`) → `apply_chat_settings_seed` видит `pool is None` → пустой отчёт → CLI печатает `applied=0 skipped=0 errors=0` и **exit 0**. Т.е. `python manage.py apply-chat-overrides` — **тихий no-op** (подтверждено `plans/metrics.md:299`). Это блокер ремонта через CLI.
5. **История правок:** `chat_lore_history.field IN (…,'chat_params','chat_keys','gates')` (`services/pg_db.py:201-208`), колонки `old_value`/`new_value` (TEXT), куда `set_chat_params` пишет `json.dumps` **всего root** (`services/chat_params.py:347-353`). Значит по строкам можно восстановить таймлайн изменения **набора ключей** `overrides` и найти момент вайпа (и `changed_by`: BIGINT; `NULL` = бот/сид).
6. **Две разные оси бюджетов:**
   - `flags.chat_context_budgets_enabled` (`services/direct_chat_service.py:1139-1162`) — **усечение контекста промпта** в direct-контуре; `scripts/backfill_104_chat_flags.py` ставит `false` целевому (экономия).
   - master-тумблер **F21** `flags.budgets_enabled` — выключает **все** бюджеты (direct key + worker + context).
   Их смешение — источник будущих регрессов; F22 обязан зафиксировать границу.
7. **Инварианты:** `manual-overrides-immutable` (ADR-1024-21 D3), R16 (id — ключ), R17/R18 (секреты), канон write-path `set_chat_params` (NOTIFY/кэш/история), Δ DDL = 0, Δ каталога = 0.

## 2. Decision

### D1. Канонический ремонт = **plain-сид** (`apply_chat_settings_seed(force=False)`), не новая команда
Ремонт потерянных seed-ключей — это **штатный сценарий** `not present` → re-apply, уже реализованный сидом. Отдельная repair-команда не вводится: второй write-path дублировал бы логику и грозил расхождением (риск R4). Единый источник истины — `config/chat_settings_seed.json` + `apply_chat_settings_seed`.

### D2. `--force` — break-glass, а не дефолт
`force=True` перезаписывает **present**-значения и потому нарушает `manual-overrides-immutable`. Дефолт ремонта — **без `--force`**. `--force` применяется только: (а) по **явному гейту владельца**, (б) после read-only аудита, показавшего ключ класса `different`. Без санкции present-значения не перезаписываются.

### D3. Ремонт идемпотентен и бесшумен на повторе
Повторный прогон при наборе == эталон → `patch` пуст → `skipped`: без `set_chat_params`, без `chat_lore_history`, без NOTIFY. Это же разрывает петлю «save → стирание → рестарт-лечение» (F20 устранил стирание; сид на рестарте — no-op).

### D4. Починка CLI `apply-chat-overrides`: `pg.connect()` + fail-loud
`_cmd_apply_chat_overrides` обязан вызывать `await pg.connect()` до `pg.init(...)`; при `pg.pool is None` — stderr и **non-zero exit**. «Нечего делать» и «PG недоступен» различаются. Форма вывода (`applied/skipped/errors` + ключи) сохраняется. Это превращает CLI в реальный ремонтный путь (иначе ремонт только через рестарт бота с авто-сидом).

### D5. Read-only аудит — новая CLI-команда `manage.py audit-chat-overrides`
Только `SELECT`, без write-path/NOTIFY. Собирает: (1) набор `overrides` целевого чата и сверку с эталоном сида (`ok|absent|different`) + `meta.chat_settings_seed_version` + `keys.allow_global` (presence); (2) **JSONL-таймлайн** `chat_lore_history field='chat_params'` с детектором вайпа (`added/dropped`, `changed_by`, `wipe_suspected`); (3) `chat_keys` — **только** `{configured,last4}`; (4) `chat_usage`/`worker_budget`/`bot_settings` — **только числа**; (5) резолв `flags.chat_context_budgets_enabled` (`value,source`). JSONL — в `var/` (gitignored), редактированная сводка — в `plans/reports/`.

### D6. Разграничение `flags.chat_context_budgets_enabled` ↔ master (F21)
Зафиксирована иерархия: **master OFF перекрывает всё**, включая усечение контекста; **master ON не отменяет** `chat_context_budgets_enabled` (усечение контекста продолжает действовать). `scripts/backfill_104_chat_flags.py` остаётся валидным и **не меняется**. F22 **не пишет** ни один из этих флагов: 8 seed-ключей (`-1`) ортогональны обеим осям. Реализация master — F21, вне scope F22.

### D7. Безопасность вывода (R17/R18)
В stdout/JSONL — только имена ключей, счётчики, seed-значения (числа `0/-1`) и `{configured,last4}`. Сырые `key_value`, токены, пароли и полные JSON-дампы `old_value`/`new_value` **не выводятся**. JSONL — в gitignored `var/`.

### D8. Реализация
- `manage.py`: connect-fix в `_cmd_apply_chat_overrides` + новый read-only `_cmd_audit_chat_overrides` и subparser.
- `services/chat_settings_seed.py`, `config/chat_settings_seed.json`, `scripts/backfill_104_chat_flags.py` — **не меняются**.
- Δ DDL = 0, Δ каталога = 0, новых флагов нет.

---

### AMEND ADR-1019-8 D4 (ответственность за per-chat `overrides`)

**Было (D4):** не-ex`enforce`-ключи сида применяются «при отсутствии ключа, при росте `version` сида или `force=True` (уважает ручные правки владельца)». Не было явно сказано, что именно эта ветка (`not present`) является **штатным механизмом ремонта** уже утерянных значений, и что CLI-путь может быть no-op.

**Стало (уточнение, не отмена D4):**
1. **`present=False` → re-apply = канонический ремонт** потерянных seed-ключей. Это целевое, а не побочное использование сида.
2. **`force=True` — исключение (break-glass), а не штатный ремонт.** Он перезаписывает **present**-значения и потому нарушает `manual-overrides-immutable` (ADR-1024-21 D3); применяется только по явному гейту владельца и после read-only аудита (класс `different`).
3. **`version_bump`** остаётся штатным каналом для **будущих** изменений сида (не используется для ремонта текущей потери).
4. **CLI `apply-chat-overrides`** обязан реально подключаться к PG (`pg.connect()`) и падать громко при недоступности; «тихий no-op» признан дефектом (D4).
5. Политика `enforce` (retention применяется всегда, tail-инвариант безопасности данных) — **без изменений**. Идемпотентность «повторный запуск — no-op» — **без изменений**.

## 3. Consequences

**Positive**
- Потерянные 8 значений (в т.ч. `-1` = безлимит) восстанавливаются **идемпотентно**, штатным механизмом сида, без нового write-path.
- `manual-overrides-immutable` соблюдён: plain-сид не трогает ручные правки; `--force` — только по гейту.
- Появляется **воспроизводимый read-only аудит**: видно, что и когда стёрлось, что лежит сейчас, сходится ли с эталоном; утечек секретов нет.
- Устранён скрытый дефект CLI (тихий no-op) — ремонт/сид запускаются из CLI, а не только рестартом.
- Граница «усечение контекста ↔ master-тумблер» зафиксирована — класс будущих регрессов снят.

**Negative / риски**
- Plain-сид **не** исправит ключ, который `present`, но имеет неверное значение — для этого нужен `--force` и Human Gate (осознанный компромисс в пользу immutability).
- Аудит парсит свободный TEXT `old_value`/`new_value` — нужна устойчивость к не-JSON/мусору (`try/except`, не падать).
- Добавляется CLI-команда и тесты — небольшой прирост поверхности, полностью read-only/локальный.

## 4. Alternatives

- **A1. Новая отдельная repair-команда** — отклонено: дублирует write-path сида, риск расхождения (R4); сид уже делает нужное через `not present`.
- **A2. Всегда `apply-chat-overrides --force`** — отклонено: нарушает `manual-overrides-immutable`, затирает намеренный выбор админа.
- **A3. Прямой SQL `UPDATE chat_profiles SET chat_params…`** — отклонено: обходит канон `set_chat_params` (NOTIFY/кэш-инвалидация/history), ломает кэш и аудит.
- **A4. Аудит скриптом `scripts/*.py` без `manage.py`** — допустимо, но предпочтён subcommand `manage.py` (обнаружимость, единый CLI, консистентность с `apply-chat-overrides`). Окончательный выбор локации — за @Builder, контракт из §D5 сохраняется.
- **A5. Не трогать CLI (ремонт только рестартом)** — отклонено: тихий no-op остаётся миной; CLI заявлен как штатный путь (ADR-1019-8 D4) и должен работать.
- **A6. Ввести feature flag** — отклонено: ops/ремонт данных, не rollout; kill-switch — откат.
