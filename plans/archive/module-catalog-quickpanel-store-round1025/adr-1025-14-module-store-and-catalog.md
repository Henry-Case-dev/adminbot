## Контекст

§31 задаёт «Модули» как главный сценарий: открыть → найти → убедиться в области → включить/выключить → получить подтверждение сервера. Тумблер одного модуля виден в **трёх** представлениях (§37: панель быстрого управления, карточка каталога, страница модуля). Текущий код (`web/app.js:4130-4148`) держит состояние в единственном элементе `configItems` — это почти «один источник», но:

1. **Оптимистичная мутация без отката (§41).** `toggleModule` сначала пишет `it.value = !!checked`, затем вызывает `saveConfigItem`; при ошибке значение **остаётся** изменённым — UI показывает успех, которого не было.
2. **Нет scoped-ключа (§38/§42).** Логического ключа `scope_type + scope_id + module_id` нет; при быстрой смене чата результат запроса применяется к «текущему» контексту (`configItems` перезагружаются, а оптимистичное значение живёт в старом/новом элементе без привязки к исходной области).
3. **Три представления — три будущих копии (§37/§40).** Панель быстрого управления §34 добавляет второй визуальный экземпляр; без общего слоя появляются независимые boolean-состояния и риск трёх запросов на одно действие.
4. **§43 требует различать** глобальное значение / локальное переопределение / фактическое состояние и **показывать реальную картину по серверной логике** («Не работает: отключён глобально»), «не предполагая приоритет локального значения без проверки кода». Проверка кода (см. §D3) показывает, что **приоритет локального значения различается по модулям**.
5. **§36 требует** не хранить избранное в конфигурации бота, но допускает UI-хранилище либо фиксированный набор; при этом Δ DDL = 0 — обязательный инвариант.
6. **§44/§33/§34** требуют витринных названий «Сводки чатов»/«Ответы в чате» и поиска по описанию/техническому имени/синонимам при Δ каталога = 0.

Ограничения: Vue 3 **global zero-build**, CSP `script-src 'self'`, **без новых state-библиотек** (§39); канонический write-path F0 (`persistItems`, ADR-1025-2) и scope-контракт F3 (ADR-1025-10) переиспользуются, не переписываются.

## Решение

### D1. `ModuleConfigurationStore` — тонкий слой над существующим `configItems` на реактивности Vue (без новых библиотек)

**Решение.** Store — не отдельная библиотека и не отдельный reactive-объект, а набор **computed/methods/данных на существующем экземпляре Vue** в `web/app.js`. Канонический источник значений — **`configItems`** (наполняется существующим `loadConfig` → `GET /api/config`). Store добавляет только **оверлей операции**: `moduleOptimistic` (значение в полёте), `modulePending` (блокировка), `moduleSaveError` (ошибка по ключу). Копий конфигурации на визуальный экземпляр **нет**.

**Логический ключ (§38):** `scope_type + '/' + (scope_id ?? 'null') + '/' + module_id`, где `module_id` = `m.id` каталога (`mod_summary`), а на провод уходит `m.toggleKey` (`flags.summary_enabled`). Пример: `global/null/mod_summary`, `chat/123/mod_summary`, `chat/456/mod_summary` — три разных контекста.

**API (§39):** `getModuleState(scope, moduleId)`, `setModuleState(scope, moduleId, enabled)`, `refreshModuleState(scope, moduleId)`, `subscribeModuleState(scope, moduleId, cb)`.
- `getModuleState` — чистая производная (overlay → `configItems` → «неизвестно»); реактивна по построению.
- `refreshModuleState` — существующий `loadConfig()` **только для активной области** (данных чужой области в памяти нет); нового API нет.
- `subscribeModuleState` — `this.$watch` на геттер ключа, возвращает функцию отписки; шаблоны подписаны неявно через реактивность Vue. Это адаптация логического контракта §39 к существующей архитектуре («Адаптировать к существующей архитектуре» — прямо разрешено ТЗ).

**Почему не выносим в отдельный модуль/реактивный singleton.** Отдельный объект потребовал бы ручной синхронизации с `configItems` (источник истины, обновляемый `loadConfig`/409-recovery/`setActiveChat`) → появился бы «второй источник правды» — прямое нарушение §37. Реактивность Vue даёт подписку без новых зависимостей.

**Альтернативы.** (a) Pinia/effector/`@vue/reactivity` — отклонено: новая библиотека ради трёх тумблеров (§39 прямо запрещает), CSP/zero-build. (b) Отдельный plain-JS store с собственной подпиской — отклонено: дублирует реактивность Vue и создаёт вторую модель конфигурации.

### D2. Одна мутация на действие; откат — структурный (overlay), а не «перечитывание»

**Решение.** `setModuleState` **не мутирует** `configItems`. Оптимистичное значение живёт **только** в `moduleOptimistic[key]`. Мутация — **ровно один** вызов канонического write-path F0:

```
persistItems([{ key: m.toggleKey, value: !!enabled, per_chat: item.per_chat }], { operationId })
```

Один элемент → одна группа → **один** `POST /api/config` (chat с `X-Chat-Id` либо global — split внутри `persistItems`). Повтор блокируется `modulePending[key]`; вторая линия — in-flight-guard `persistItems` по `m.toggleKey` (`skipped`).

**Откат (§41) — структурный.** Поскольку `configItems` не изменялся, снятие overlay (`delete moduleOptimistic[key]`) автоматически возвращает UI к **подтверждённому сервером** значению. Дополнительный `GET /api/config` для отката не нужен. Ветка 409 переиспользует контракт F0 (`conflicting[]`, один re-read, `stickyConflict`) и **не дублируется**; авто-ретраев нет (успех/409/ошибка — один проход).

**Применение результата — по зафиксированному ключу и эпохе.** `key`, `scopeId`, `epoch = scopeEpoch` снимаются **до** `await`; результат применяется только если `epoch === scopeEpoch` и только к `key`. «Текущий чат на момент ответа» не читается нигде (§42). Известное остаточное окно F0 (`persistItems` снимает epoch после `await`, L-F3-4) F4 **не использует как гарантию** — guard свой.

**Индикатор сохранения** — по `modulePending[key]`.

**Альтернатива «мутировать `it.value` и откатывать при ошибке»** отклонена: требует хранить предыдущее значение и восстанавливать его адресно, легко теряется при параллельных операциях/409-recovery, где `persistItems` сам перечитывает конфиг. Overlay-подход исключает класс ошибок «откатили не то/не туда».

**Альтернатива «после ошибки перечитать конфиг»** отклонена как избыточная (лишний запрос) и как источник ложного состояния при устаревшем ответе; F0 уже делает re-read только в ветке 409.

### D3. Фактическое состояние: три уровня + `runtimeGate` модуля (проверено по коду)

**Решение.** Показываем три уровня: **глобальное значение** (`global_value`), **локальное переопределение** (`chat_source === 'chat'`), **фактическое состояние** (эффективное `value` + runtime-поправка). В JS `MODULES` добавляется метаданные **`runtimeGate: 'global' | 'per_chat'`** (+ `parentGate`) — это витрина, **не каталог** (Δ каталога = 0). При отсутствии метаданных — `'global'` (консервативно: не утверждать действие локального значения без доказательства кодом).

**Аудит по коду (обязательная часть решения, §43 «не предполагать… без проверки кода»):**

| Модуль | Ключ | Runtime-гейт | Доказательство |
|---|---|---|---|
| `mod_summary` | `flags.summary_enabled` | **global** | `bot.py:373` (LLM/сервисы), `:752-786` — регистрация роутеров 0a–0i читает `hot.get` **без чата** |
| `mod_direct` | `flags.direct_chat_botword_enabled` | **global** | `handlers/direct_chat.py:194` `hot.get` |
| `mod_factcheck` | `flags.factcheck_enabled` | **global** | `handlers/factcheck.py:228` `hot.get` (per-chat в этом файле — только глубина цепочки `limits.*`, не мастер-флаг) |
| `mod_search` | `flags.search_enabled` | **global** | `handlers/search.py:117`; `handlers/direct_chat.py:104,124-131` `hot.get` |
| `mod_transcribe` | `flags.enable_voice_transcription` | **global** | `bot.py:534`, `:785` `hot.get` |
| `mod_video_summary` | `flags.video_summary_enabled` | **global** | `handlers/youtube.py:1355`; `handlers/direct_chat.py:105` |
| `mod_media_download` | `flags.download_enabled` | **global** | `bot.py:227,856`; `handlers/video_download.py:258`; `services/media_download.py:198`; `services/tool_router.py:1058` |

**Родительский гейт.** Для восьми модулей с `gate='global'` (summary, direct, factcheck, search, transcribe, video_summary, web, checkup) дополнительный глобальный родитель — `flags.summary_enabled` (регистрация роутеров 0a–0i, `bot.py:752-786`): при глобально выключенном родителе модуль **фактически не работает**, даже если его собственный глобальный флаг включён.

**Подписи для неглобальной области** (helper `moduleRuntimeNotice`, отдельный от `configItemNotice`):

| Условие | Подпись |
|---|---|
| `global_value===false && effective===true && gate==='global'` | **«Не работает: отключён глобально»** + «локальное значение сохранено» |
| то же, `gate==='per_chat'` | «Включено для этой области (глобально выключено)» |
| то же, `gate==='unknown'` | «Локальное значение сохранено; глобально модуль выключен» |
| `effective===false && hasOverride && gate==='global'` | «Отключение для этой области не влияет: модуль управляется глобально» |
| родительский гейт выключен глобально | «Не работает: отключён глобально» |
| иначе | пусто |

**Override не уничтожается:** F4 не вызывает `DELETE /api/config/chat/{key}` из карточек/панели; глобальная запись не трогает локальный слой (серверный `_post_config_global` пишет только global).

**`configItemNotice` не изменяется.** F3-тест (`tests/test_scope_selector_round1025.py:86-89`) фиксирует его точную формулировку для карточек **параметров**; модульные подписи — отдельный helper. Это осознанное сужение: правило F3 «Локально включено, хотя глобально выключено» остаётся верным для параметров, где per-chat приоритет доказан, а модульные карточки получают более точную формулировку по `runtimeGate`.

**§43 «Ожидает применения» — N/A.** Конфигурация read-through (`ConfigCache` + PG/`chat_params`, POST + NOTIFY; `GET /api/config` сразу отдаёт эффективное значение). Отдельного applied-state с задержкой сервер не имеет → показывать нечего (иначе выдуманное состояние). Наследуется из ADR-1025-10/F3.

**Альтернатива «единая формулировка „Локально включено, хотя глобально выключено“ для всех модулей»** отклонена: она молчит о том, что для 9 из 13 модулей локальный override **не влияет** на работу — §43 требует показать реальную картину.

**Альтернатива «серверный признак runtime-скоупа в каталоге»** отклонена: требует нового поля `ParamSpec`/GROUPS → Δ каталога > 0.

### D4. Избранное — `localStorage` (UI-предпочтение), Δ DDL = 0

**Решение.** Избранное хранится в браузере: ключ `adminbot.modules_quickpicks.v1` (+ суффикс `me.id`, если доступен). Значение — JSON-массив `m.id`, валидируемый по `MODULES`; стартовый набор кандидатов §34 (Сводки чатов / Ответы в чате / Проверка фактов / Поиск) применяется, если ключа нет/он битый/`localStorage` недоступен (fail-open). Избранное **не** участвует в `/api/config`; закрепление **не** включает/выключает модуль; состояние модуля всегда серверное (§36).

**Почему `localStorage`.** Прецедент проекта — UI-предпочтения уже живут в браузере (Ф17: `adminbot.active_chat_id`, `adminbot.route`); Δ DDL = 0 сохраняется; серверное per-user хранилище потребовало бы таблицы/миграции/эндпоинта (запрещено инвариантом и §36 «без создания ненужной серверной архитектуры»).

**Альтернативы.** (a) Серверное per-user предпочтение — отклонено (Δ DDL > 0, новый эндпоинт, лишняя архитектура). (b) Только фиксированный набор без закрепления — отклонено: §34 «предпочтительно позволить администратору закреплять модули самостоятельно», а `localStorage` уже есть. (c) `sessionStorage` — отклонено: предпочтение должно переживать перезапуск WebView.

### D5. Поиск: метаданные в JS `MODULES` (Δ каталога = 0); витринные названия — только в JS

**Решение.** В `MODULES` добавляется `keywords: [...]` (синонимы + техническое имя); `subtitle` используется как описание. Поиск идёт по `title` / `subtitle` / `toggleKey` / `keywords`. «Саммари», «сводка», «суммаризация», `summary` находят «Сводки чатов»; «ответы», `direct`, «бот» — «Ответы в чате». Витринные названия: `mod_summary.title = 'Сводки чатов'`, `mod_direct.title = 'Ответы в чате'`; **`id`/`toggleKey`/`tab` не меняются**, `TABS[].label`/`PROVIDER_BLOCKS` не трогаются, старые названия остаются синонимами (поиск и маркер-тесты не ломаются). Отдельной страницы результатов нет (§44).

**Альтернатива «метаданные в `services/param_catalog.py`»** отклонена: Δ каталога > 0; JS-витрина — правильный дом для поисковых синонимов UI.

### D6. Особенности модулей: `noToggle`, uiFlag-гейт, тач-цель, «карточка ≠ тумблер», «Настроить»

**Решение.**
- **`noToggle`** (шаблон `web/index.html:1175`; сейчас не выставлен ни одним модулем): карточка с бейджем «без тумблера», «Настроить» доступно; модуль входит **только в «Всего»**, не входит в Включено/Выключено/Есть проблемы и в панель. Правило проверяется синтетическим модулем.
- **uiFlag-скрытый модуль** (`mod_images`, `visibleModules`, `web/app.js:1466-1474`): при `IMAGE_MODULE_CARD_ENABLED=OFF` исключается из витрины, поиска, панели и **всех** счётчиков; никогда не считается «Выключено».
- **Неизвестное ≠ выключено:** нет элемента `toggleKey`/`value==null` → «неизвестно», исключено из Включено/Выключено, учтено в «Есть проблемы».
- **Тач-цель тумблера ≥44×44 CSS px** (визуальный трек не растёт), **без** уменьшения ради 4 колонок панели.
- **«Карточка ≠ тумблер»:** клик по телу/описанию/иконке не переключает; единственный переключатель — тумблер.
- **«Настроить» (вопрос e):** вводится единый шов `openModuleWorkspace(m)`; в F4 он делегирует в **существующую модалку** `openModuleWindow(m)` (регресс-путь: параметры модуля остаются доступны — §79/§116), кнопка переименовывается в «Настроить». **Новый маршрут/заглушка-страница не создаются** — рабочее пространство §46 и его маршрут принадлежат **F5**; F4-заглушка дала бы пустую страницу и изменила IA/роутинг F1 без функциональности.

**Отклонено:** немедленная регистрация `#/modules/<id>` и «заглушка-маршрут» (буквальная формулировка T-2626). Это **отступление от буквы задачи при сохранении цели**: точка входа есть, доступ к параметрам не потерян, F5 подменяет реализацию шва. Требуется привести формулировку T-2626 в соответствие (см. `spec.md` §12).

### D7. Раскладка: каталог ≤3/2/1, панель ≤4/2/2–1, без горизонтального скролла

**Решение.** Сетка каталога задаётся **изолированными** правилами `.module-list` (container-query-тиры: ≥1024 → 3, 480–1023 → 2, <480 → 1) **после** общего правила `.prov-grid, .module-list, .hub-grid`; сами `.prov-grid`/`.hub-grid` **не изменяются** (вне скоупа F4 и покрыты маркер-тестами). Панель — отдельный контейнер `.module-quick` (≤4/2/2/1 по тем же тирам). Горизонтального скролла страницы нет на 320–1440; `auto-fit` больше не даёт >3 колонок. Маркер-тесты, затрагиваемые сменой сетки, обновляются **атомарно с кодом** (`spec.md` §9.12).

**Альтернатива «общий `max-width` на `.prov-grid`-правиле»** отклонена: расширяет дифф на чужие разделы и гарантированно ломает F1/F2-маркеры без необходимости.

### D8. Инварианты и отсутствие feature-flag

**Решение.** Гейт F4: **Δ DDL = 0**, **Δ каталога = 0** (`services/param_catalog.py` вне диффа; 459/98/96/21/418), CSP/zero-build, **новых state-библиотек нет**, **новых эндпоинтов нет** (R16), R17/R18 (значения/секреты не логируются; `plans/current_task.md` не коммитить), write-path F0 и scope-контракт F3 переиспользуются без изменения, `configItemNotice` не меняется, IA F1/токены F2/shell hotfix6-7/нативные кнопки Telegram не ломаются.

## Последствия

**Positive.**
- Три представления гарантированно согласованы: одна модель (`configItems` + overlay), ноль независимых boolean.
- Откат §41 становится **структурным** свойством (нельзя «забыть откатить»): ошибка/409/частичный успех не оставляют ложного успеха.
- §42 закрыт по построению: применение по зафиксированным `key`+`epoch`, без опоры на «текущий чат».
- §43 показывает **реальную** картину (в т.ч. «Не работает: отключён глобально» там, где код действительно глобально-гейтится), не выдумывая applied-state.
- Δ DDL = 0, Δ каталога = 0, ноль новых API/библиотек → минимальная поверхность для @Scanner.

**Negative / издержки.**
- Появляется **поддерживаемое** соответствие `runtimeGate` ↔ код (13 модулей): при изменении серверного гейта модуля метаданные в JS нужно актуализировать. Митигация: default `'global'` (безопасная сторона), `unknown`-нейтральная подпись, аудит-таблица в этом ADR как референс.
- Избранное привязано к устройству/браузеру (per-`localStorage`), не синхронизируется между устройствами — принято сознательно (§36 допускает; Δ DDL = 0 обязателен).
- Витринные названия «Сводки чатов»/«Ответы в чате» расходятся с `TABS[].label` («Саммаризация»/«Прямые ответы») — расхождение витрины и меток разделов; принято (переименование только витрины, каталог не тронут).
- Сетка каталога меняет маркер-ожидания F1/F2 → требуется атомарное обновление маркеров (список в `spec.md` §9.12) и внимательное ревью.

## Верификация

- **Store/ключи:** `global|null|module`, `chat|123|module`, `chat|456|module` — три разных контекста; `get/set/refresh/subscribe` работают; overlay не мутирует `configItems`; `node --check web/app.js` OK.
- **Одна мутация:** spy-транспорт фиксирует **ровно 1** `POST /api/config` на переключение (в т.ч. при трёх смонтированных представлениях); двойной тап → одна мутация.
- **Откат §41:** ошибка/409 → тумблер возвращается к серверному значению, сообщение понятное, авто-ретраев нет.
- **§42:** ответ чата A, пришедший после перехода в B, не меняет B; stale-ответ отбрасывается по epoch.
- **§43:** три уровня различимы; «Не работает: отключён глобально» только для `gate='global'`/выключенного родителя; override не уничтожается; устаревший `configItemNotice` **не изменён** (F3-тест зелёный).
- **§45:** неизвестное ≠ выключено; `noToggle` — только «Всего»; uiFlag OFF — вне счётчиков.
- **§44:** «Саммари»/«сводка» находят «Сводки чатов»; описания/тех.имя/синонимы; нет отдельной страницы результатов.
- **Инварианты:** Δ DDL = 0 (`user_version=12`), Δ каталога = 0 (459/98/96/21/418), нет новых библиотек/CDN/эндпоинтов, `git diff --check` чист, R17/R18 соблюдены.
- **Регресс:** полный pytest (база 8207/0) + JS 27/27 + новые наборы; 0 новых падений; маркеры сетки обновлены атомарно.
