## 1. Область и исключения

**Входит (что делает A6):**
- **Новый LLM-видимый инструмент `get_user_context`** (имя сохранено из §33 как рабочее; канон-регистрация — **11 → 12** атомарно): LLM запрашивает сведения о **конкретном** человеке **по инициативе LLM**, по требованию, а не через подмешивание полных досье всех пользователей (REQ-A6-01/-02).
- **Purpose-зависимая выдача** (§33: `identity / appearance / speech_style / biography / relationships / general`): каждый сценарий получает **свой набор данных** (REQ-A6-03/-05, §32 `:5079–5089`).
- **Адаптированный контракт** (не слепое копирование §33): `chat_id` берётся из `ToolContext` (как у существующих инструментов), а не параметром модели; `purpose` обязателен; `max_items` опционален (REQ-A6-04/-06).
- **Reuse существующего досье + RAG** без новой БД памяти: `AliasResolver`, `db.get_persona_card` (читатель за `build_persona_card`), `db.get_generated_dossier`, `format_dossier_block`, `summary_memory.search_long_term`/`get_rag_context`/`get_rag_facts`/`vector_search` (REQ-A6-07).
- **Envelope результата из 5 полей §33** (`:5124–5130`): найденные факты + источники + степень подтверждённости (если доступна) + временной контекст + признак отсутствия данных — как **структурированные** поля (JSON-объект результата), попадающие в A2-envelope (`ToolContext.result_for`) для A4 и §35-цепочек (REQ-A6-08).
- **Честность:** неподтверждённое не выдаётся за факт; отсутствие данных — явный флаг, а не домысел; источники/подтверждённость проводятся из существующих носителей (`graph_facts.status`/`weight`/`created_at`/`tg_message_id`/`origin`) (REQ-A6-09).
- **Lazy RAG:** RAG вызывается только когда purpose требует подтверждения/дополнения сообщениями (детерминированная карта), не «всегда» (REQ-A6-10).
- **Капы:** `max_items` + внутренние капы на факты и на срезы сообщений; **никаких «сотен сообщений»**; без крупных кусков личной переписки в результате (REQ-A6-11/-12).
- **Временная стилизация, не подмена личности:** `speech_style` собирает **compact style profile** по существующим данным для передачи Вербализатору; системная личность бота не меняется (REQ-A6-13).
- **Комбинирование с фактчеком через A2-цепочку** (`tool_loop`): память подтверждает **факт высказывания**, фактчек проверяет **содержание**; набор фактчек-инструментов **не расширяется** (§35; REQ-A6-14/-15).
- **Наблюдаемость R17-safe** и **диагностируемость** («почему инструмент не сработал»): лог только `purpose`/`user_id`/`chat_id`/`count`/`latency`/`empty-reason`; понятная причина пустого результата (REQ-A6-17).
- **Env-only kill-switch** `MEMORY_LOOKUP_ENABLED` (default ON; OFF → инструмент не объявляется, остальные 11 — байт-в-байт); **Δ каталога = 0** (REQ-A6-06).

## 3. Наблюдаемое поведение и отказные сценарии (по кластерам REQ)

### 3.1. Контракт инструмента (REQ-A6-01/-04/-06; D2)
- **Имя:** `get_user_context` (рабочее, из §33; snake_case, совместимо с каноном).
- **Адаптированная сигнатура** (адаптация §33 `:5116–5118`):
  - `person` (**required**, string) — имя/алиас/`@username`/числовой id **строкой**; резолвится существующим `AliasResolver` (`canon_name`/`resolve`).
  - `user_id` (**optional**, integer) — альтернативный якорь идентичности, если модель получила id из контекста; при наличии имеет приоритет над `person`.
  - `purpose` (**required**, enum: `identity | appearance | speech_style | biography | relationships | general`).
  - `max_items` (**optional**, integer ≥ 1) — предел числа элементов выдачи (семантика — §3.5).
  - **`chat_id` — НЕ параметр модели:** берётся из `ToolContext` (как у всех существующих инструментов); это и есть адаптация контракта §33.
- **Вызов возможен только по инициативе LLM** внутри существующего `tool_loop` (on-demand); универсального dump-инструмента нет (REQ-A6-01/-02).
- **Невалидные аргументы (§52 п.14):** отсутствие `person` и `user_id`; неизвестный `purpose`; не-строковый `person`; не-int/`<1` `max_items` → структурированный `{"status":"error","error":"invalid_arguments","detail":"<code>"}`; инструмент **не бросает**, остальные инструменты в цепочке продолжают работу; лог — R17-safe.
- **Неизвестный человек** (не резолвится) → это **не** ошибка, а честный результат: `status:"ok"`, `no_data:true`, `empty_reason:"unknown_person"`.
- **Неоднозначное имя** (§53 «путает пользователей с одинаковыми именами»): `person.resolution="ambiguous"`, `no_data:true`, `empty_reason:"ambiguous"`, кандидаты — **только id/ref** (без слияния фактов двух людей и без сырого текста); при неоднозначности факты **не** возвращаются.
- **Kill-switch OFF:** инструмент отсутствует в модельно-видимом наборе (`active_tools`); при вынужденном прямом вызове (тесты) — `{"status":"error","error":"disabled"}`.

### 3.2. Карта purpose → источники (REQ-A6-02/-03/-05/-07/-10/-11; D3)
| purpose | Источники (reuse) | RAG? | Содержание выдачи |
|---|---|---|---|
| `identity` | `AliasResolver` (canon name, aliases) + `db.get_persona_card` (счётчик/факты) | нет | канон-имя, разрешённые алиасы, id (если доступен), краткая сводка «кто это» |
| `appearance` | `graph_facts` (target_user, `status='confirmed'`) **фильтр** по речному лексикону внешности | нет | факты внешности; при отсутствии — `no_data:true`, `empty_reason:"no_storage_for_purpose"`; правила извлечения — **A4** |
| `speech_style` | bounded per-user slice (существующие message/RAG-аксессоры) + `db.get_generated_dossier` (patterns/themes) → **compact style profile** | да (bounded; только для характерных сообщений) | компактный профиль стиля (интонация/паттерны/темы), **не** подмена личности |
| `biography` | `graph_facts` (target_user, confirmed, `weight DESC`) + `db.get_generated_dossier` (portrait) | нет | биографические факты + портрет |
| `relationships` | edges из `db.get_persona_card.links` (`source_name`/`relation_type`/`target_name`; `origin != bot_direct_reply`) | нет | связи с людьми + типы отношений |
| `general` | FTS/vec RAG: `search_long_term` / `vector_search` / `get_rag_context` (+ `get_rag_facts`) | да | релевантные сообщения/факты-подтверждения |

- **Выборочная выдача без universal dump:** результат ограничен запрошенным человеком и purpose; чат-лор/полные досье всех участников **не** подмешиваются (REQ-A6-02; §32 `:5091–5092`).
- **`appearance`:** выделенного хранилища нет; A6 реализует **только generic-фильтр** поверх существующих `graph_facts` с честным `no_data`, когда ничего не найдено. **Извлечение/классификация внешности (в т.ч. из изображений) — A4** (явная граница, U1).
- **`speech_style`:** per-user профиля в готовом виде нет (`_build_style_anchors` — chat-anchored к ответам **бота**, `direct_chat_service.py:2038`); A6 строит **компактный** профиль **на лету** из существующих данных, без нового хранилища и без нового LLM-вызова.

### 3.3. Envelope результата — 5 полей §33 (REQ-A6-08/-09; D4)
Результат инструмента — **JSON-объект** (строка), который A2-механизм (`_classify_output`) разворачивает в `data` envelope; структура (пример, не обязательная схема):
```json
{
  "status": "ok",
  "purpose": "biography",
  "person": {"name": "<canon>", "user_id": 123, "resolution": "resolved"},
  "facts": [
    {"text": "...", "confidence": "confirmed", "weight": 0.72,
     "time": 1700000000, "source_id": "tg:456"}
  ],
  "sources": [
    {"kind": "graph_fact", "ref": "tg:456", "origin": "chat_history", "ts": 1700000000}
  ],
  "confidence": {"available": true, "label": "confirmed", "value": 0.72},
  "time_context": {"from": 1690000000, "to": 1700000000, "label": "2023–2024"},
  "no_data": false,
  "empty_reason": "",
  "truncated": false
}
```
- **5 полей §33 ↔ структура:** `facts` → `facts[]`; `sources` → `sources[]`; степень подтверждённости → `confidence` (+ `facts[].confidence`); временной контекст → `time_context`; признак отсутствия данных → `no_data` + `empty_reason`.
- **Проводка источников/подтверждённости (U3):** источники — `graph_facts.origin` + `tg_message_id` (ID-политика `tg:`, ADR-1020-1) + `created_at`; RAG-хиты — `msg:<id>`/timestamp; edges — `source_name`/`relation_type`/`target_name`. Подтверждённость — `graph_facts.status` + `weight` + `last_confirmed_at` (если доступны); отсутствие носителя → `confidence.available=false`, `label:"unknown"`.
- **Честность (REQ-A6-09):** ни один элемент не помечается `confirmed`, если носитель не подтверждает; отсутствие данных маркируется явно (`no_data:true`), а не «заполняется» домыслами; источники — идентификаторы, не сырые тексты.
- **Никаких больших цитат (REQ-A6-12):** `facts` — краткие факты; сообщения RAG — только короткие подтверждающие фрагменты/ссылки-источники в пределах char-капа; крупные куски личной переписки не копируются.
- **Envelope — носитель результата** для A4 и §35-цепочек (`ToolContext.result_for("get_user_context")`), без изменений A2-контракта.

### 3.4. Lazy RAG (REQ-A6-10; D3)
- RAG (`search_long_term`/`vector_search`/`get_rag_context`/`get_rag_facts`) вызывается **iff** `purpose ∈ {general, speech_style}`; для `speech_style` — только когда bounded-slice не даёт достаточных характерных сообщений.
- Для `identity`/`appearance`/`biography`/`relationships` RAG **не** вызывается (детерминированно, документировано, тестируемо).
- Эмпирический критерий теста: при purpose, не требующем RAG, RAG-методы `deps.memory` не вызываются (spy/mock).

### 3.5. Капы и `max_items` (REQ-A6-11; D5)
- **`max_items`** — предел числа элементов в `facts[]` (и срезов сообщений) для данной выдачи; дефолт per-purpose, hard-ceiling `MEMORY_LOOKUP_MAX_ITEMS_HARD = 20` (clamp).
  - дефолты: `identity=5`, `appearance=10`, `biography=10`, `relationships=10`, `general=8`, `speech_style=5`.
- **Срезы сообщений:** `MEMORY_LOOKUP_MESSAGE_SLICE_MAX = 5` (hard 10), `MEMORY_LOOKUP_SLICE_MAX_CHARS = 240` на фрагмент, `MEMORY_LOOKUP_RESULT_MAX_CHARS = 4000` на результат. «Сотни сообщений» невозможны by design.
- **Взаимодействие с A2-капами:** инструмент — **free/local** (не в `METERED_TOOLS`), т.к. читает только локальные БД; он не расходует `TOOL_CHAIN_MAX_METERED_CALLS`, но подчиняется общим `TOOL_MAX_TOTAL_CALLS=6` и дедупу A2. Капы A6 — аддитивные env-only константы (Δ каталога=0), по прецеденту A2/A5 env-only.

### 3.6. Комбинирование память + фактчек (§35; REQ-A6-14/-15; D6)
- Цепочка исполняется **существующим** A2-механизмом (`chat_with_tools`): модель вызывает `get_user_context(purpose=general)` → получает сообщение/утверждение через envelope → вызывает один из **3** фактчек-инструментов (`dig_into_lore` / `compile_lore_story` / `execute_web_search`).
- **Память ≠ фактчек** (документируется в `description` инструмента и в §35-инварианте): память подтверждает, что утверждение **было высказано**; фактчек проверяет **содержание**. Поиск похожих сообщений памятью не подменяет фактчек.
- **`factcheck_tools` остаётся 3** — новый инструмент в фактчек-набор **не** добавляется; новый фактчек-инструмент не создаётся (граница A7).

### 3.7. Отказные/негативные сценарии (что считается НЕ выполнением)
- Полные досье всех пользователей подмешиваются в запрос; «универсальный dump» → не принято (REQ-A6-02).
- RAG вызывается всегда (в т.ч. для purpose, не требующих сообщений) → не принято (REQ-A6-10).
- Envelope неполон (нет sources/confidence/time/no-data) или отсутствие данных «заполнено» домыслами → не принято (REQ-A6-08/-09).
- Неподтверждённое выдано как `confirmed`; `confidence` отсутствует, но результат подан как установленный факт → не принято (REQ-A6-09).
- В выдаче — сотни сообщений или крупные куски личной переписки → не принято (REQ-A6-11/-12).
- Системная личность бота подменена личностью пользователя → не принято (REQ-A6-13).
- Созданы новая БД/второй резолвер/второй RAG-контур/Δ DDL/Δ каталога → не принято (REQ-A6-07; инварианты 1/12).
- Фактчек подменён памятью или расширен набор фактчек-инструментов → не принято (REQ-A6-15).
- Невалидные аргументы роняют цепочку/другой инструмент; неоднозначное имя молча сливает людей → не принято (§52 п.14; §53; REQ-A6-17).
- R17-нарушение (в логах — текст досье/сообщений/имён) → не принято (REQ-A6-17).
- Канон 11→12 неатомарен или затронул первые 11; регресс существующих инструментов; Δ каталога ≠ 0; пер-фича деплой/тег/bump → не принято (REQ-A6-06/-17; инварианты 11/12/14).

1. **JSON-схема** `TOOL_GET_USER_CONTEXT` в `services/tool_schemas.py` (EN-`description`; параметры `person`/`user_id`/`purpose`/`max_items`; `additionalProperties:false`; `enum` для `purpose`; `minimum:1` для `max_items`).
2. **Хвост канона:** `TOOL_CALLING_TOOLS` — 12-м элементом (первые **11 — байт-в-байт**; «новое — в хвост», ADR-1020-4).
3. **Env-гейт:** `_memory_lookup_enabled()` (прецедент `_article_tool_enabled` `:460–466`), env-only `MEMORY_LOOKUP_ENABLED` (default ON); в `active_tools` добавляется в `disabled`.
4. **Диспетчер:** запись `"get_user_context": self._get_user_context` в `registry` (`tool_router.py:497–523`) + метод (read-only; reuse `deps.db`/`deps.memory`/`deps.aliases`); unknown → существующая ветка; исключение → R17-safe WARNING (класс исключения) — прецедент `:519–523`.

6. **Константа имени** `MEMORY_LOOKUP_TOOL_NAME = "get_user_context"`.
7. **Тесты `len==12`** и ре-пин существующих канон-тестов (~11 файлов) — в том же изменении.
- **Атомарность обязательна:** без любого из пунктов 1–7 — приёмка не проходит.

- **Effective-набор:** `TOOL_CALLING_TOOLS == 12` безусловно; `active_tools()` default (image OFF) = **11** (12 − `generate_image`); при `MEMORY_LOOKUP_ENABLED=OFF` — 11 (как baseline после A2/A3/A5).
- **Промпты:** новый `description` схемы — единственное промпт-соседнее изменение (атомарно в `tool_schemas.py`); системные/воркерные промпты не меняются → ADR-1013-3 = **NOT_APPLICABLE** (прецедент A2).

### 6.2. Envelope над A2 (D4)
- Модельно-видимый канал A2 не меняется: JSON-строка результата → `_classify_output` (`tool_loop.py:143–184`) разворачивает её в `data` envelope (`_make_envelope`), доступную через `ToolContext.result_for("get_user_context")`/`ctx.tool_results`.
- `status:"ok"` для honest-empty (`unknown_person`/`empty`/`ambiguous`/`disabled`-при-прямом-вызове); `status:"error"` — только невалидные аргументы/сбой сервиса. Это сохраняет A2-семантику «ошибка инструмента не роняет цепочку».
- Envelope `data` (факты) — in-memory на прогон, **не** сериализуется в модельный ввод сверх tool-сообщения, **не** логируется/не персистится (R17; прецедент A2-review «`tool_results` нигде не логируется»).

### 6.3. Точка реализации purpose-роутинга (D3)
- Таблица `purpose → источники` реализуется как явный `dict`-маппинг в `_get_user_context` (или небольшом приватном хелпере) — единый switch, без per-combination обработчиков и без дублей. Каждый purpose — детерминированный набор reader'ов; неизвестное значение → `invalid_purpose`.
- **Резолв субъекта:** `deps.aliases` (AliasResolver) либо `build_alias_resolver(chat_id)` (существующий fail-open) — **второй резолвер не создаётся**; `user_id`-ветка — прямая идентификация.

### 6.4. Lazy-RAG decision tree (D3)
```
purpose == general            -> RAG on (search_long_term/vector_search/get_rag_context/get_rag_facts)
purpose == speech_style       -> bounded per-user slice; RAG on только если slice < минимума характерных
иначе                         -> RAG off (identity/appearance/biography/relationships)
```

### 6.6. R17-формат лога (D8)
- Единственный новый лог: `[memory] lookup | purpose=%s | user_id=%s | chat_id=%s | count=%d | latency_ms=%d | empty_reason=%s`.
- **Никогда:** текст досье, текст/цитаты сообщений, имена, промпты, ключи, сырые аргументы. `user_id`/`chat_id` — идентификаторы; `empty_reason` — enum (`""|empty|unknown_person|ambiguous|no_storage_for_purpose|disabled|lookup_failed`).

- **Новая БД памяти запрещена** (§33 `:5120`); второй контур памяти не создаётся.
- **Δ каталога = 0** (U5): новых ParamSpec/GroupSpec нет; kill-switch и капы — env-only/код-константы. Ожидаемые счётчики: **REGISTRY 470 / Settings 427 / categorized 445 / GROUPS 101 / `_TAB_BY_GROUP` 99 / TAB_RULES 21** — без изменений (финал — F8 `--check` при Build).

## 8. Стратегия тестов

- **Юнит-контракт (T-3611/T-3612):** схема `TOOL_GET_USER_CONTEXT` (required/enum/additionalProperties/minimum); декларируемые параметры и адаптация (`chat_id` из контекста); регистрация в хвосте; `active_tools` default и OFF.
- **Матрица purpose (T-3613/T-3619):** каждый из 6 enum → ожидаемые источники/поля (SC-A6-19); неизвестный purpose → `invalid_purpose`; «свой набор данных на сценарий».
- **Lazy RAG on/off (T-3616):** для `general`/`speech_style` RAG вызывается; для остальных — **не** вызывается (spy/mock).
- **Envelope/честность (T-3617/T-3618):** 5 полей всегда; `confidence.available=false`/`label="unknown"` без носителя; ни один `confirmed` без подтверждения; `no_data`/`empty_reason`; отсутствие dump; отсутствие больших цитат.
- **Капы (T-3618):** `max_items` clamp; срезы ≤ cap; «сотни сообщений» невозможны.
- **Резолв/неоднозначность (T-3614):** коллизия одинаковых имён → `ambiguous` без слияния фактов; unknown → honest `no_data`.
- **Невалидные аргументы (§52 п.14, T-3619):** отсутствие `person`/`user_id`, bad enum, bad `max_items` → структурная ошибка, цепочка/другие инструменты не ломаются.

## 13. Risk-Level и усиление

- **Risk-Level: R2.** Обоснование: A6 добавляет **read-only** LLM-инструмент. Нет DDL/каталога/денег/записи в БД/секретов/деструктивных операций; blast radius ограничен контрактом результата, R17-логом и расширением канона; OFF-путь — байт-в-байт для остальных 11. В отличие от A2 (менял разделяемый control-flow `tool_loop` → R3) и A5 (DDL+деньги → R3), A6 **не меняет управляющий поток** и полностью аддитивен/обратим.
- **Что повысит до R3 (Reviewer-триггеры):** появление записи/DDL/каталога; изменение общего control-flow `tool_loop`/A2-envelope; логирование/персистенция envelope `data` (текстов досье); попадание A6 в shared метеринг-бюджет; регресс первых 11 инструментов; отсутствие байт-в-байт OFF-паритета; утечка приватного текста за пределы модельно-видимого tool-канала.
- **Усиленная проверка (соразмерно R2):** adversarial-тесты на честность/`no_data`/неоднозначность/невалидные аргументы/капы; R17-тест логов; lazy-RAG spy-тест; OFF/байт-в-байт-тест первых 11; diff-аудит границ A4/A5/A7/§104/БД/каталога. Отдельный threat-failure-файл (R3-атрибут) **не обязателен** для R2.
