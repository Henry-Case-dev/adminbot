## A. Spec (зеркало дизайна; spec.md отдельным документом — по решению @Architect)

**Дизайн-решения эпика (PM-база по умолчанию для B–I; открытые вопросы Q1–Q9 закрывает @Architect в T-770 и фиксирует ПРАВКОЙ в этом разделе — строки-решения; если правки меняют требования задач B–I — пометкой `(изменено @Architect T-770)` в тексте задачи):**

- **Хранилище — PG (вариант C research §4/§5), 4 НОВЫЕ таблицы** в `pg_db.py DDL_STATEMENTS` (идемпотентно, `CREATE TABLE/INDEX IF NOT EXISTS`): `chat_profiles`, `chat_lore_history`, `chat_links`, `chat_admins`. Для существующих БД миграция = просто CREATE IF NOT EXISTS при очередном `init()` — НИКАКИХ ALTER/rebuild существующих таблиц. Точная схема:
  `chat_profiles (chat_id BIGINT PRIMARY KEY, manual_lore TEXT NOT NULL DEFAULT '', auto_lore TEXT NOT NULL DEFAULT '', auto_enabled BOOLEAN NOT NULL DEFAULT TRUE, auto_period_hours INTEGER NOT NULL DEFAULT 24, auto_window_hours INTEGER NOT NULL DEFAULT 24, is_active BOOLEAN NOT NULL DEFAULT TRUE, updated_at TIMESTAMPTZ NOT NULL DEFAULT now())` — строго по ТЗ владельца, без лишних колонок; `updated_at` обновляется `now()` на КАЖДОЕ изменение строки (оптимистик-метка).
  `chat_lore_history (id BIGSERIAL PRIMARY KEY, chat_id BIGINT NOT NULL, changed_by BIGINT NULL, field TEXT NOT NULL CHECK (field IN ('manual_lore','auto_lore','settings','remap')), old_value TEXT NOT NULL DEFAULT '', new_value TEXT NOT NULL DEFAULT '', created_at TIMESTAMPTZ NOT NULL DEFAULT now())` + `CREATE INDEX ... ON chat_lore_history(chat_id, created_at DESC)`; `changed_by NULL` = бот/воркер (AI); value — сырые тексты, для 'settings' — JSON-строка набора изменяемых полей.
  `chat_links (old_chat_id BIGINT PRIMARY KEY, new_chat_id BIGINT NOT NULL, created_at TIMESTAMPTZ NOT NULL DEFAULT now())`.
  `chat_admins (chat_id BIGINT NOT NULL, telegram_id BIGINT NOT NULL, added_by BIGINT NULL, created_at TIMESTAMPTZ NOT NULL DEFAULT now(), PRIMARY KEY (chat_id, telegram_id))`.
- **Manual/auto-лор НЕЗАВИСИМЫ** (ключевое уточнение ТЗ): ручная правка пишет только `manual_lore`, авто-генерация перезаписывает только `auto_lore` (manual не затирается НИКОГДА); ручная правка НЕ выключает auto (в отличие от research 2.2 «руки человека важнее» — по ТЗ владельца отключается только явным тумблером auto_enabled).
- **NOTIFY/кэш:** на каждое изменение профиля (INSERT/UPDATE chat_profiles) и запись в chat_lore_history — `pg_notify('lore_updated', '<chat_id>')` в той же транзакции; слушатель — ОТДЕЛЬНОЕ asyncpg-соединение (не из пула), колбэк → инвалидация локального RAM-кэша профилей `ChatLoreCache` (load-on-demand из PG, TTL-фолбэк 60 с на случай потери NOTIFY, fail-open при PG-down). Единый кэш шарится между инжектом, API и воркером (DI из bot.py).
- **Optimistic locking:** все изменяющие операции над профилем принимают «ожидаемый `updated_at`» (от клиента) — при рассинхроне специальный конфликт → API 409 + актуальное значение; авто-запись воркера и lifecycle-апсерты НЕ требуют метки (своя логика: воркер сравнивает/перечитает, Q9-сценарии).
- **Инжект в direct_chat (Q1):** из PG-профиля (с резолвом chat_links) склейка `manual_lore` + `auto_lore`; cap-бюджет инжекта — общий ≤ 2000 символов (диапазон ТЗ 1500–2500 фиксирует @Architect): manual приоритетен и НЕ урезается, урезается auto (по границе абзаца/предложения). PG-лор инжектируется ТОЛЬКО если профиль существует в PG (иначе — старый SQLite-путь как сейчас, дублей текста нет); при активном PG-профиле легаси SQLite-чат-факт константы исключается из сборки protected-фактов (текст == `CHAT_LORE_2661910336`) — иначе текст задвоится (Q1 подтверждает механизм). Флаг `flags.lore_inject_enabled` (default true) — off = старое поведение целиком. Fail-open: PG недоступен/ошибка кэша → блок лора пуст, бот жив.
- **Воркер:** метод `generate_for_chat(chat_id, *, manual=False)` + фоновый цикл (AsyncIOScheduler, `IntervalTrigger(hours=1)`, max_instances=1, coalesce=True — прецедент memory_maintenance) по всем `is_active AND auto_enabled` чатам. Условия авто-прогона: профиль существует/is_active; `auto_enabled`; глобальный флаг `flags.lore_auto_enabled` (default true); период — с последнего авто (Q3: `MAX(created_at)` из history WHERE field='auto_lore') прошло ≥ `auto_period_hours`; окно — сообщения `smart_messages` за `auto_window_hours` от now; минимум осмысленных сообщений в окне — `limits.lore_min_messages` (default 15). Каждый прогон — под `pg_advisory_lock(<chat_id>)` (анти-гонка ручного generate и тика; unlock в finally). Источник: окно smart_messages + существующий auto_lore + чат-уровневые protected-факты. Merge-промпт: канон `LORE_MERGE_SYSTEM_PROMPT` в НОВОМ `services/lore_prompts.py` (текст пишет @Architect в C1; макро-правила: сохранить постоянное, перезаписать устаревшее, противоречия разрешить, связный текст 1–3 абзаца, бюджет ≤ `limits.lore_max_tokens` (default 800), русский, в стиле исходных сообщений, БЕЗ кавычек-ёлочек и длинных тире — дисциплина раунда 5). Вызов LLM — `llm_client` (детали в Q4). Запись: только если текст реально изменился (или первого авто нет) — `auto_lore` + история (`changed_by NULL`) + NOTIFY; иначе skip. Ошибки — fail-open WARNING, профиль не трогаем. «Сгенерировать сейчас» из API = тот же метод `manual=True` (без период-флагов; требуется `auto_enabled` профиля и права).
- **«Осмысленное сообщение» (Q5):** PM-база — `text` непуст после strip, длина ≥ 20 символов; медиа-only/стикеры/команды не считаются; пересланные с подписью ≥ 20 символов считаются. Точный фильтр фиксирует @Architect.
- **Lifecycle:** my_chat_member ТОЛЬКО по событиям самого бота (`new_chat_member.user.id == bot.id`): стал участником/админом → upsert профиля `is_active=true` (существующие тексты не трогаются, дефолты-пустые), удалён → `is_active=false`. `migrate_to_chat_id` (Message): `chat_links.add_link(old, new)` + перенос профиля `UPDATE chat_profiles SET chat_id = new WHERE chat_id = old` (если профиль `new` уже существует — не затирать, WARNING, Q9) + история field='remap' (old_value=old, new_value=new) + NOTIFY. Ленивый резолв: `resolve_chat_id(id)` через chat_links (цепочка, защита от циклов/глубины ≤ 5) применяется во ВСЕХ чтениях профиля (инжект F1, API E1, воркер C1).
