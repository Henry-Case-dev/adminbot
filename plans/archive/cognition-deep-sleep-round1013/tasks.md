## 0. Цель

Ежедневный «Глубокий сон» после обычного сна проходит по всей старой базе памяти: находит якоря,
синтезирует «парадигмы» (мета-факты) о развитии ситуаций/людей и подаёт их в чат как фоновый
исторический слой. Плюс — бэкенд-роутер моделей воркеров (историческая память/вехи/лор vs фоновые проверки).

## 1. Требования (дословно из ТЗ §6 + §3 backend)

- [x] Глубокий сон идёт **ежедневно сразу после завершения обычного сна**; в настройках «Сон» — поля
      времени и триггеров («запускать после Сна» / «свой диапазон времени»).
- [x] **Алгоритм «Поиск по якорям»:** результат только что завершившегося обычного сна (свежие убеждения)
      + выжимка активности за 12 часов → векторный RAG-запрос ко **всей** старой базе.
- [x] **Синтез «Мост времени»:** в отдельную LLM (см. п.3) отправляется свежий контекст + найденные
      исторические факты; промпт «найди связь, сформулируй мета-факт (парадигму)».
- [x] Парадигмы сохраняются, выводятся на дашборд и подаются в контекст чата с весом **0.5–0.6**
      как фоновый «исторический слой».
- [x] **Бэкенд-роутер воркеров:** перед вызовом нейросети в фоновых воркерах проверяются выделенные LLM
      (историческая память/вехи/лор; фоновые проверки/оценка важности) с фоллбэком на основную модель.

## 8. Feature flag / progressive delivery

- **Feature flag:** `flags.deep_sleep_enabled` (default **OFF** для бэкенд-фазы).
- **Rollout stages:** `internal` (тестовый чат, ручной `POST /memory/dream/run`) → **10%** → **50%** →
  **100%**; критерии отката: рост бюджета воркеров, ошибки LLM, дубли парадигм, деградация контекста.
- **Rollback:** флаг OFF + `git revert`; данные (парадигмы) — пометка архивом без DDL.
