# ADR-1022-6 — Egress-предохранитель (только теги) + детектор ИИ-клише и Validator Loop вместо `string.replace`

- **Статус:** **Accepted** — решение владельца UPD3 §3 (18.09.2026); оформлено Step 2b @Architect (18.09.2026)
- **Фича:** F6 `telegram-send-regex-guard-round1022`
- **Тип:** backend `services/**` + канон промптов
- **Связано:** ADR-1020-7 §2 (strip reasoning), ADR-1021-3 (negative constraints), ADR-1013-3, F3/F4/F5

## Context

Сейчас reasoning-теги срезаются в `reply_postprocess.strip_reasoning_tags` (единая функция), но:
(1) нет вырезания `fact:\d+`/`msg:\d+`; (2) нет **единого chokepoint отправки** — 19 прямых
`send_message` в 10 файлах + ~57 `edit/send`-вариантов.

Первоначальная идея 10.22 «вырезать клише regex'ом/`string.replace`» **отклонена владельцем**:
хардкод-вырезание ломает грамматику («дыры» в предложениях). UPD3 §3 требует: regex тихо
режет **только технические теги**, а клише — **браковать ответ и возвращать Вербализатору
(max 2 ретрая)**.

## Decision

1. **Regex Scrubber** — новый `services/outgoing_guard.py`: `sanitize_outgoing` =
   `strip_reasoning_tags` → вырезание `\bfact:\d+\b`/`\bmsg:\d+\b`; no-op без паттернов
   (байт-в-байт 10.21); fail-closed; идемпотентно. **Клише не вырезаются.**
2. **Обёртки отправки** — `services/telegram_send.py`: `send_text`/`edit_text_safe`/`send_caption`
   + реестр `SEND_POINTS`; тест покрытия. `GuardedBot` — **не требуется** (остаётся опцией).
3. **Детектор клише + Validator Loop** — новый `services/negative_constraints.py`:
   `FORBIDDEN_CLICHE_PATTERNS` (в коде, не в промпте), `find_forbidden_cliches(text)->codes`
   (R17, fail-open), `verbalize_validated(generate_call, base_messages, max_retries=2)`.
   Список клише объединён (10.21 + UPD2): `as_ai`, `classic_genre`, `summing_up`, `in_conclusion`,
   `hope_helped`, `you_asked_before`, `mirror_no_you`, опц. `bullet_list`.
4. **Петля:** брак → полный перегенерация тем же Вербализатором с `CLICHE_RETRY_SYSTEM_PROMPT`
   («Ты нарушил Negative Constraints… Перепиши ответ полностью, сделав его естественным»);
   **≤2 ретрая** (≤3 вызова Stage-2); при исчерпании — деградация (F3 → 10.21; F4/F5 → лучший
   вариант). Scrubber тегов — на всех путях (последняя сеть).
5. **Канон:** `ANTI_BOT_BLOCK` расширяется (без дословного цитирования клише) + новый
   `CLICHE_RETRY_SYSTEM_PROMPT`; **атомарная канон-миграция** (ADR-1013-3); список клише — в коде.
6. **Флаги:** `TELEGRAM_SEND_GUARD_ENABLED` (scrubber) и `SYSTEM2_VALIDATOR_LOOP_ENABLED`
   (детектор+петля) — env-only `ClassVar`, **default ON**, Δ каталога = 0.
7. Существующие вызовы `strip_reasoning_tags` не удаляются (идемпотентны).

## Consequences

- Ни один ответ не уходит с reasoning/ID-маркерами (архитектурная гарантия egress).
- Клише устраняются семантически (перегенерацией), а не хирургически — без «дыр» в грамматике;
  цена — редкие (+1…+2) LLM-вызовы при срабатывании.
- Появляется реестр точек отправки и тест покрытия — новая зона сопровождения.
- Канон `prompt_style_blocks.py` читают 8 канонов → правка обязана быть атомарной.

## Alternatives

- **`string.replace` клише** — **отклонено владельцем** (ломает грамматику).
- **Regex-вырезание клише** — отклонено по той же причине.
- **Только LLM-инструкция без детектора** — отклонено: нет гарантии, «ответ с клише» уйдёт.
- **Детектор списка клише в `prompt_style_blocks.py`** — отклонено: grep-тест отсутствия тропов
  поймает сам список; список вынесен в код.
- **Безлимитные ретраи** — отклонено: срыв/зацикливание; жёсткий лимит 2 + деградация.
- **`GuardedBot` как единственный механизм** — риск (несколько точек создания `Bot`); опция.

## Cost ×2 / бюджет / латентность

Scrubber — **ноль LLM-вызовов**. Validator-loop — `0` вызовов в норме; `+1…+2` только при
срабатывании клише (bounded). Бюджет существующих пайплайнов не меняется.

## Kill-switch / Fallback / Rollback

- **Kill-switch:** `TELEGRAM_SEND_GUARD_ENABLED=false` (scrubber) и/или
  `SYSTEM2_VALIDATOR_LOOP_ENABLED=false` (loop).
- **Fallback:** scrubber — fail-closed (не отправлять сырьё); loop — fail-open (деградация).
- **Rollback:** флаги OFF / `git revert` + обратная канон-миграция `prompt_style_blocks.py`.

## Canon migration

**Обязательна (ADR-1013-3):** правка `ANTI_BOT_BLOCK` (без цитирования клише) + новый
`CLICHE_RETRY_SYSTEM_PROMPT` → `PREV_*`-слепок + `PROMPT_MIGRATIONS` + `ROLLBACK_MIGRATIONS` +
`plans/docs/canon/**` + тесты. Ступень: **F6 первым** до F3 → F4 → F5.

## Human Gate — ЗАКРЫТО владельцем (UPD3 §3)

- **Д-10** → вето на `string.replace`/regex-вырезание клише; scrubber = только `<thought>`,
  `fact:\d+`, `msg:\d+`; клише = **детектор + петля возврата (≤2)**; `GuardedBot` не требуется.



## Implementation (Шаг 4 @Builder, 18.09.2026)

Все пункты Decision реализованы: scrubber (`outgoing_guard`), обёртки/реестр
(`telegram_send`), детектор+петля (`negative_constraints`), канон-атомарность
(п.7 ANTI_BOT + `PREV_*_R1022` + `prompt_migrations` + canon docs). `GuardedBot`
не вводился (остаётся опцией), существующие вызовы `strip_reasoning_tags`
сохранены. Тесты F6 зелёные; полный pytest 6876/0.
